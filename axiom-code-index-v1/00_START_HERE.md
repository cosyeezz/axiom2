## 实施目标

必须打通：读取证据 → 模型提案 → 程序校验及原子提交 → 从提交记录返回；以及变化失效 → 持久待办 → 稳定时局部维护 → 压缩/恢复后重新交付。通过独立验收后，才退出 AOCI 运行依赖。

## 不可削弱的约束

- 先检查并保留用户现有修改；`ui/` 只读。按当前源码接线，不凭建议文件名假定模块已存在。
- TypeScript/SQLite负责事实、证据身份、失效和事务；模型解释语义，不让模板自动生成架构结论。
- 按主方案第2及16.1节保持依赖方向和状态唯一所有权。IndexService不含管理/关闭；Runner只执行提案尝试，返回已接受草稿的digest；Worker冻结正文是唯一提交来源。查询、概览、交付、重放和导出共用授权读取视图，正式语义走统一提交。pi/SQL句柄不进入纯规则，IPC不传本地signal或函数。
- Index浏览只读已有索引，服务单独绑定工作区/连接/viewId，不借模型工具身份；共用授权读取与证据规则。树是关系投影，flows只表达有依据的条件先后，不能自动补分支或完整控制流。[离线交互样稿](../artifacts/prototypes/index-browser/index.html)使用合成数据，不是生产接入。
- 扩展通过明确的解析、执行、入口或展示适配器接入，复用既有权限/证据/预算/事务；不预建通用插件框架。新增能力必须验证依赖、取消、释放和故障降级。
- 文档规定与当前实现分开；旧索引、摘要和交付收据不能证明当前事实或当前模型上下文。
- 只有本次实际可见的源码/文档证据可以支持提案。版本漂移、歧义、预算不足如实降级。
- 不在模型请求期间持DB事务，不覆盖现有 Tasks 单一回调，不假定已存在统一供应商并发调度器。事实通知可多订阅，索引RPC必须由唯一路由负责执行、关联与收尾；SQLite串行写入不能替代每indexKey的语义作者互斥。
- 新系统与AOCI只允许一个正式语义写入方。AOCI资产导入只作待核验候选；当前项目合同在正式切换前仍有效。
- `rebuild derived` 不删除长期语义、决定、来源或待办；导出、备份、恢复是退出AOCI的必要条件。
- 保存资产不等于允许披露；旧提交重放、导入候选和恢复后的交付都按当前授权过滤，完整私有备份不经普通索引读取或导出返回。
- 新会话和压缩恢复按当前授权、完整当前分支与有效投影重新选择并交付认知正文；核对锚点、调用/结果及压缩前编辑，被省略的新输入仍阻断旧任务焦点。不能以旧DB included标志冒充当前请求已含正文；选择本身不启动模型，缺少可靠线索时退回有界概览。
- 请求发送前持久化用量身份；已知消耗完整去重，缺失计量或价格显示unknown，不填0。没有凭据/预算时完成可运行脚手架并明确未测。
- 评测遵守主方案第15节的实际基线、L1消融和两个冻结节点；pilot与保留集隔离，五个质量判定单元均须通过。不得削弱基线或把精确缓存收益冒充语义复用收益。
