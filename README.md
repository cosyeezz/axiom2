# Axiom2

基于 pi 的本地多工作空间编码 Agent 工作台。已实现主／子 Agent、模型配置与认证桥接、持久化恢复，并提供 Windows 与 macOS 桌面构建产物。**当前为第一阶段候选交付，不宣称全部验收通过**：真实供应商／OAuth、完整视觉对照、完整原生桌面交互和 macOS/Linux 业务端到端验收尚未完成。

实施依据：[产品设计](docs/design.md)；设计采用状态：[UI 设计同步](docs/ui-sync.md)。文档只描述当前内容，变更轨迹由 Git 保存。

## 一行安装与客户端下载

需要先安装 [Node.js 22.19.0+](https://nodejs.org/)；无需 Git、Rust 或单独安装 pi。源码：[cosyeezz/axiom2](https://github.com/cosyeezz/axiom2)，发布与校验文件：[GitHub Releases](https://github.com/cosyeezz/axiom2/releases/latest)。

**Windows PowerShell（一行安装并启动）：**

```powershell
irm https://raw.githubusercontent.com/cosyeezz/axiom2/master/install.ps1 | iex
```

**macOS / Linux（一行安装并启动）：**

```sh
curl -fsSL https://raw.githubusercontent.com/cosyeezz/axiom2/master/install.sh | sh
```

脚本安装最新 Release 中已经编译的 npm 包，再启动服务。也可直接安装：

```sh
npm install -g https://github.com/cosyeezz/axiom2/releases/latest/download/axiom2.tgz
axiom2 start
```

一行安装完成后会启动后台服务并返回终端；再次使用可在 Pake 控制页点击“启动后台服务”，或运行 `axiom2 start`。`axiom2 status` 查看状态，`axiom2 stop` 正常停止服务；直接运行 `axiom2` 仍支持前台运行、Ctrl+C 退出。后台进程不依赖终端或客户端窗口，但不注册登录自启，也不在崩溃后自动重启。`axiom2 --help` 查看帮助，`axiom2 --version` 查看版本。安装路径由 `npm prefix -g` 决定；全局目录无写权限时请使用用户级 Node.js 安装或 npm prefix。

**Pake 自带离线可用的服务控制页。** 服务未启动时仍能打开客户端，点击“启动后台服务”，就绪后点击“打开工作台”；关闭服务前会列出活动会话并要求确认。服务启动期间可查询“正在启动”状态并关闭服务；启动命令等待超时后，仍可刷新状态或执行 `axiom2 stop`，停止成功后不会再次上线。Windows 与 macOS 都使用一个原生窗口：就绪后在当前窗口切到工作台，点击顶部“服务与更新”返回原有控制页。普通切换保留工作台实例、草稿、选区和滚动位置；服务地址变化时重新建立工作台视图，确认后台停止或确认更新后返回控制页。macOS v0.4.4 与当前源码构建的客户端使用波形图标表示连接：绿为已连接，红为已断开，灰为确认中，文字颜色固定。业务订阅报错或服务管理通道暂不可用时，保留当前工作台；连接信息过期时显示确认中。旧后台不支持连接上报时需更新后台才能显示准确状态。关闭窗口会退出桌面客户端，退出后再次打开会恢复控制入口并识别已有后台。Pake 不包含 Node.js、pi 或后端，首次使用仍需安装服务；Windows 需要 WebView2 Runtime，客户端未签名。关闭客户端不会退出后台服务。真实供应商、OAuth 与原生安装交互的验收范围见下文。

**应用内更新：** 在 Pake 控制页的“版本与更新”点击“检查更新”，分别查看客户端、后台服务与最新版本。点击“更新后台服务”并确认后关闭工作台，先下载、校验和准备新版，再停止旧服务、切换程序并验证启动；项目与会话数据保留，正在执行的任务会结束。更新由独立任务执行，关闭、重开客户端仍可查看进度。程序切换或启动失败会尝试恢复旧程序，更新进程异常退出且留下恢复记录时可点击“恢复旧版本”；恢复会核对旧程序版本，备份缺失且安装目录仍是其他版本时保留恢复记录并报错。后台必须安装在标准 npm 包目录且目录可写（一行安装命令符合此方式），源码目录请使用原方式更新。**应用内更新与恢复仅支持一个数据目录独占一个服务安装。多个数据目录共用全局安装不受支持；请为各数据目录使用独立安装目录，或停止所有相关服务后手动更新。** 当前任务锁和服务探测均按数据目录工作，不能检查其他数据目录是否仍在使用同一程序。

Windows 客户端更新使用“下载客户端更新”→“运行安装器”：附件校验通过后才打开 MSI 安装向导并关闭当前客户端，后台继续运行；安装完成后重新打开客户端查看版本。安装器启动不代表安装成功，仍需完成系统向导。**v0.2.x 客户端首次需手动下载新版 MSI／EXE，之后才能使用应用内更新入口。** 首次安装 Node.js 和后台仍使用上方命令。使用 Node 22 时，如果旧客户端仍提示需要 Node 24，请先手动替换新版客户端，再运行后台安装命令；仅更新后台不会替换客户端内嵌的运行时检查。

macOS 客户端使用 ad-hoc 签名，未经过 Apple Developer ID 签名或公证；首次打开如被系统阻止，可在“系统设置 → 隐私与安全性”中确认“仍要打开”。Mac 客户端自身更新需退出客户端后下载新版 DMG 并替换 Applications 中的应用；后台服务可从控制页管理和更新，仍需满足上述独占安装要求。

手动更新／修复：先通过客户端“关闭后台服务”或 `axiom2 stop` 停止旧服务，再运行安装命令。v0.1.x 前台服务需先在原终端按 Ctrl+C 退出。卸载：停止服务后运行 `npm uninstall -g @cosyeezz/axiom2`；会话数据和共享 pi 配置保留，Windows 客户端在系统设置中单独卸载。

## 从源码启动与使用

需要 **Node.js 22.19.0+**、npm。最低版本由现有 pi 依赖要求确定；无需固定到某个补丁版本。CI 分别使用 Node.js 22.19.0 和 24，在 Windows、macOS、Linux 上执行构建、测试与实际发布包检查。

```sh
cd app
npm ci
npm run build
npm start
```

1. 打开 `http://127.0.0.1:4317/`，本机连接无需 token 或登录。服务仅监听回环地址，仍校验 Host／Origin，拒绝跨站请求。
2. 点击「打开文件夹…」，在系统文件夹选择器中选择已有项目，即默认授权并直接打开工作空间、创建会话，无额外确认弹窗；无需手动输入路径。取消选择不会创建工作空间。重新打开 Pake 或新的浏览器窗口会分别恢复服务端记住的侧栏工作空间和最近主会话，并读取已保存草稿；同窗口刷新优先保留自己的会话位置。会话切换不停止后台工作。若提示服务不支持文件夹选择，请重启本地服务并刷新页面（只刷新无法更新已运行的后端）。
3. 在「配置 → 模型服务」点击供应商旁的「+」，在就地菜单中选择 **OAuth 登录**或**自定义接口**。OAuth 在页面内通过下拉框选择 pi 实时返回的受支持供应商，再点「浏览器登录」，无需先保存连接配置，也无需填写密钥、地址和协议；授权状态和手动回填在页面内展示，支持自动回调，成功后自动导入账号。自定义接口填写连接信息和可选 API Key，再使用**配置下方的保存按钮**发布；同一区域只保留保存、取消及图标式重新读取。密钥旁可直接「退出认证」，保留供应商与模型定义；凭据路径位于「凭据存储位置」展开项。模型配置页点击「拉取模型列表」，在下方展开的目录内搜索并勾选模型后「加入配置」，再统一保存；也可手动添加。配置有效不等于远端认证有效。
4. 回到会话确认模型及思考等级，然后发送任务。主会话确认的选择自动保存为默认，新建会话沿用上次选择（跨工作空间、重启后保留），不改变已有会话或子会话的模型；升级时默认值为空会从现存主会话恢复最近保存的选择，无需重新确认。模型不可用时须重新选择。停止直接强制终止拥有的执行，不请求总结或要求 Agent 清理确认，不承诺文件及外部副作用回滚。
5. 主 Agent 可委派子任务；点击任务卡片查看独立子会话、追问、停止、历史结果。关闭弹窗不停止任务。
6. 输入框下方与子代理设置成组的压缩图标用于展开／收起压缩页面，在页内选择模型、开始／再次压缩或取消任务；两个设置面板的底部均避开工具栏图标，点击另一个图标可直接切换。打开页面本身不会发起模型请求。任务先等待安全点保存快照，使用所选模型在后台生成 **pi 原生摘要**，再等待新的安全点校验并自动应用；原始历史与快照后的新增消息保留，失败或冲突时不应用。

开发模式：`npm run dev`。环境变量 `AXIOM_PORT` 默认固定 4317（桌面入口使用此端口，不支持 0）；`AXIOM_DATA_DIR` 指定数据根目录，`AXIOM_PI_DIR` 可指定共享模型／认证目录，默认使用 pi 的 `getAgentDir()`（通常为 `~/.pi/agent`，遵循 `PI_CODING_AGENT_DIR`）。页面入口：`/`、`/settings.html`、`/model-config.html`、`/tools.html`、`/connect.html`。

默认数据目录：Windows `%APPDATA%/Axiom2`；macOS `~/Library/Application Support/Axiom2`；Linux `$XDG_DATA_HOME/Axiom2` 或 `~/.local/share/Axiom2`。`axiom.sqlite` 保存管理数据，`pi/` 保存应用资源／设置，模型配置与认证使用共享 pi 目录，`sessions/` 保存 pi JSONL，`run-models/` 保存主／子执行的临时模型配置快照，`compression-snapshots/` 保存运行中的临时压缩快照及固定配置；模型保存、登录与退出登录会影响终端 pi 的同一配置，请留意供应商级退出提示；旧版应用的 `pi/models.json` 与 `pi/auth.json` 不自动覆盖或合并到共享目录，可通过 `AXIOM_PI_DIR` 显式继续使用。同一数据目录只允许一个服务管理器。执行快照按数据目录隔离，启动时只清理本数据目录的残留，不扫描或清理共享 pi 目录中的运行文件。

退出服务：在客户端点击“关闭后台服务”并确认，或运行 `axiom2 stop`；前台模式也可按 Ctrl+C。退出会结束拥有的执行并保存状态；控制通道暂时失联且记录的进程仍存活时，不确认“已停止”，需等待后续状态或退出超时。PID 仅用于存活探测，不用于强杀；若旧 PID 被复用，确认停止可能延迟或超时。关闭浏览器或桌面窗口仅关闭客户端。数据目录中的 `service.log` 保存后台启动与运行日志，`installation.json` 记录本机 Node.js／CLI 路径，`service-startup.sqlite` 保存启动实例登记以协调并发启停，`service-control.json` 保存本次运行的本机控制通道凭据；启动登记和控制凭据均不要分享。配置目录不承诺磁盘加密或系统密钥库；需要备份时先停止服务，再复制整个数据目录。

## 内置工具与 OpenCLI

打开「配置 → 内置工具」，在 OpenCLI 条目中检查环境和更新。新电脑点击「检查更新」→「安装 OpenCLI」，安装成功后会默认接入官方 `opencli-usage`、`opencli-browser` 两个技能；本机已有 npm 全局安装时，可检查环境后直接「保存接入设置」。页面也支持更新和重新安装。需要本机 npm 可用、官方 npm 仓库可访问且全局安装目录可写；权限不足时使用用户级 Node.js 安装或 npm prefix，再重启后台服务。

扩展提供两种安装方式：「Chrome 应用商店安装」（推荐）打开 [OpenCLI 官方商店页面](https://chromewebstore.google.com/detail/opencli/ildkmabpimmkaediidaifkhjpohdnifk)，在 Chrome 中点击「添加至 Chrome」；「手动下载压缩包」打开 [官方发布页](https://github.com/jackwener/opencli/releases)，下载 `opencli-extension-v{version}.zip` 并解压，在外部 Chrome 的 `chrome://extensions` 中启用开发者模式，再「加载已解压的扩展程序」。两种入口均由本地后台调用系统默认浏览器，桌面客户端与网页版使用同一路径，启动失败显示可重试提示及对应手动访问地址。保持 Chrome 和扩展启用，点击「检测连接」查看官方 `doctor` 报告；诊断命令执行完成不等于浏览器连接成功。可以设置 Chrome Profile ID／别名和前台／后台窗口模式，空 Profile 遵循 OpenCLI 默认选择。Pake WebView 不替代 Chrome 扩展。

Agent 通过现有 shell 工具运行 OpenCLI，不新增命令映射或原生 OpenCLI 工具。常用技能只注入名称、简介与路径，完整指南按需读取；程序和技能来自同一已安装 npm 包。配置可关闭这两个默认技能，不删除用户已有技能目录；子 Agent 仍限只读工具，不加载这两项技能。设置保存在数据目录的 `integrations/opencli.json`，在后续执行加载，不修改终端 pi 设置。

安装／更新使用官方全局 npm 包，并跳过生命周期脚本；会影响本机其他使用同一 OpenCLI 的程序。Axiom 有活动任务或启动准备时拒绝安装，安装期间不接受新的 Agent 执行。页面关闭不取消后台操作；重连可查看结果。关闭后台服务会中止自有安装进程，重启显示中断，不自动重做；npm 全局安装失败不承诺回滚，可重新检查实际安装后重试。Chrome 扩展独立于 npm 包更新：商店安装由 Chrome 管理更新，手动加载版需另行下载并更新。`integrations/opencli-job.json` 保存最近操作状态，配置损坏或技能缺失会报告警告并跳过本轮 OpenCLI 接入，不阻断基础 Agent。

## 已实现能力与边界

### 工作空间、会话与界面

- 悬停说明使用统一深灰浮层，细边框、圆角和柔和阴影；停留片刻显示，支持键盘聚焦、长路径换行、屏幕边缘避让及弹窗内展示，提示文字可选择和复制。外部点击、输入、Esc、页面滚动或窗口失焦时收起。

- 三个独立 React 页面，沿用设计 CSS、SVG、变量与响应式布局；按职责拆分消息、输入、模型、任务和工作空间组件。
- 应用页面及桌面控制页统一隐藏滚动条和轨道，不预留滚动条空槽；聊天、输入框、侧栏、配置面板、弹窗、菜单、表格与长输出仍可使用滚轮、触控及键盘滚动。
- 单击会话／工作空间的垃圾桶或使用键盘删除时，使用统一深色应用内确认弹窗，默认聚焦“取消”，支持 Esc 取消及焦点恢复；双击垃圾桶直接删除，无需确认。鼠标单击等待 500ms 识别双击，按钮或窗口失焦、切换标签页或 Esc 可取消等待；提交期间防止重复请求，失败显示原因并可重试。模型垃圾桶同样支持双击直接移出草稿，正式发布仍需统一保存并确认供应商级影响。系统文件／目录选择窗口不受影响。

- 会话不分页，默认展示 pi 最新压缩边界选中的摘要、保留消息和后续消息。输入框下方批注按钮旁提供 `bi:filetype-raw`“原始会话”开关，默认关闭；开启后按当前分支展示压缩前后对话并隐藏全部压缩卡片，继续接收实时消息；再次点击、切换会话或刷新页面关闭，不持久化开关、不改变模型上下文或输入草稿。历史按需从绑定 JSONL 读取，继续遵守原生重试排除及 `context_edit`，不混入其他分支；长文本复制、工具详情和图片预览仍按消息归属读取。关闭后释放当前视图的历史副本；首次加载期间及读取失败时保留当前对话，失败可重试；后台尚不支持时明确提示重启后台服务后刷新页面；关闭或切换后的迟到响应不恢复旧视图。压缩卡片展示编号、20 字内主题和压缩前后 Token 估算，可展开完整交接摘要。右侧提供到顶、上一屏、下一屏和到底按钮，支持键盘与减少动效。前后端会话展示缓存采用最多 5 个会话的 LRU，淘汰后从绑定 JSONL 重建。客户端保护正在展示的会话，忽略退订后的迟到快照；超过五个同时订阅会话明确拒绝，不静默淘汰活动视图。消息使用会话级集合订阅、首次完整快照及逐消息更新，不受逐条 500 scope 限制。
- 安全 Markdown、代码高亮／复制；显示层兼容 `简化为**“完成”**就够了`、`**验证：**43` 等中文引号／括号开头或收尾标点与相邻文字间无空格的加粗写法，保留会话原文与复制内容，不改写代码块或转义内容（`tests/markdown.test.ts`、`tests/markdown.check.ts` 覆盖）；连续工具、纯思考、子任务调用、完成通知及无独立正文的失败／停止记录合并为默认收起的执行过程卡片，后续恢复调用继续进入同一卡片，错误与停止信息按顺序保留在内部。空白助手占位不分隔连续过程；占位出现真实正文时才恢复正文边界。会话缓存重新加载后仍发布首次调用的合并更新；思考与正文分开显示期间，新调用只由上方过程承接，正文位置不另起卡片。收起固定两行：第一行是左侧状态图标、描述与调用数、最右侧展开箭头，第二行显示当前工具／思考／子 Agent 摘要；展开后隐藏第二行摘要，仅保留标题及内部详情。进行中使用 Iconify `eos-icons:three-dots-loading` 原生绿色三点缩放 SVG 动画（24px、1.5 秒循环、圆心固定），减少动态效果设置下仍保留该执行状态动画；确认完成使用用户提供的 Tabler 官网 `progress-check` 绿色图标（22px、2px 圆角描边、保留原始路径）：从运行切换为完成时，先淡入左侧虚线，再缓慢画出右侧圆弧，最后画出对号，总计约 2 秒，只播放一次并保持完整图标，减少动态效果设置下也保留这次完成反馈；流式更新、展开／收起与加载已完成的历史记录不重播。状态按过程段判断：仅当前末尾段等待所属 Agent 继续执行；末尾刚出现一条普通助手正文时，前一段仍暂时保持进行中，避免正文继续产生调用并合并回来时反复切换。后面出现由独立正文等内容分隔的新过程段、用户消息或压缩后，旧段只按内部事实收尾，无运行项、无未知结果即可完成。独立思考卡片同样仅在末尾等待；当前过程在所属执行仍活跃时保持进行中，包括请求失败后的恢复等待。收尾以最后一条助手消息判断终态，较早错误保留在内部，不覆盖后续成功恢复。历史卡片不被其他新执行重新激活；确有新运行事实合并进已完成卡片时仍恢复进行中。完成动画在当前展示期间最多播放一次，再次完成直接显示静态图标，内部调用同步展示真实状态；工具或子任务的失败、停止仅在内部对应项反馈，不把外层置为失败或停止，只有助手自身执行失败／停止才影响外层终态，缺少结果仍显示未知；子任务仍在运行时外层保持运行态。普通工具以默认收起的独立行展示工具名称、关键路径／命令，右侧仅显示真实可得耗时（未知为“—”），成功绿色、失败红色，不显示状态文字和加减号，单独展开调用后才显示输入参数和执行输出，避免重复摘要。收起外层同时重置内部工具、思考及子任务操作详情，再次展开仍逐层查看。长输入／输出在展开对应调用时自动读取完整记录，失败可重试，收起时卸载详情正文；普通最终回复保持独立可见。流式状态更新不重置手动折叠。会话环境、思考、工具过程、压缩摘要与子任务操作详情展开后，折叠栏随滚动吸顶，离开该块末尾后退出；每次重新展开时，仅外层“执行过程”卡片按状态定位：运行中到内容末尾，已完成及其他非运行状态从开头显示；内部思考、工具与子任务详情始终从开头展开，块内长输出重置到开头，已展开时的流式更新不打断阅读；嵌套标题按实际高度排列，主／子会话独立生效，窄屏和流式更新不会遮住收起入口（`tests/sticky-disclosures.check.ts` 覆盖）。原始 HTML 不执行，危险链接不生成链接，外部图片不自动加载。未知／超长代码块使用纯文本。

### 模型配置与认证

- 会话中切换模型和思考等级在下一次执行生效，正在执行的回复及同次追加消息保持原设置。新设置实际发起模型请求后，对应请求上方显示模型／思考等级的前后变化；只改等级同样提示，首次选择或相同设置不提示。提示随原生会话保存，刷新和重启后可查看；无新用户消息的重试在回复上方提示。
- 可选模型复用 pi 配置与认证；只保存供应商而未单列模型时使用该供应商的原生目录，只有 pi 判定可用的模型才显示。模型收藏持久化；删除模型会清理收藏，临时认证失效不清除收藏。子代理默认模型与思考等级为全局偏好，已有子会话保持独立选择。
- 配置草稿／临时密钥只在页面内存；模型编辑使用两列基本字段、独立的输入能力卡片及全宽思考等级多选。文本默认支持，图片理解可按模型实际能力开启，映射到 pi 的 `input`；目录导入及重读保留输入能力，未编辑的原生能力继续继承目录。模型列表展示文本／图片摘要，列表和目录的思考等级使用逗号分隔，窄屏自动换行。「完成编辑」仅暂存，切换供应商保留有效编辑；配置下方的统一保存包含未收起或隐藏在连接页签后的编辑，无效 ID 返回模型表单、不丢输入。统一校验修订、字段与 pi 能力，写临时文件并原子替换 `models.json`。`none` 映射 `off`，多选能力映射 `thinkingLevelMap`，数值请求体覆盖映射 `samplingParams`；不支持的字段／协议拒绝保存。
- 模型配置页的「拉取模型列表」在当前工具栏下方展开，提供搜索、多选、收起和批量加入草稿；已添加模型不可重复选择，自定义接口协议不匹配时说明原因，OAuth 按各模型的原生协议选择。通过 pi 原生接口刷新供应商目录，保存选择时保留原生能力、上下文和计费信息。缺少认证／在线刷新失败时明确显示本地目录；pi 不支持自动发现的自定义接口仍需手动添加，不提供独立的通用 `/models` 探测。
- API Key 与 OAuth 通过 pi 原生认证接口，凭据写入当前共享 pi 目录的 `auth.json`，不写入 `models.json`。供应商旁的「+」展开 OAuth／自定义接口菜单；OAuth 的供应商下拉、授权状态与回填在页面内显示，不使用新增或 OAuth 登录弹窗。下拉项直接来自后台 pi 支持的 OAuth 供应商，不维护固定名单或名称别名；若后台未返回可用能力，则禁用登录并提示更新或重启后台、重新读取配置。OAuth 连接面板仅展示账号状态、重新登录与移除，不展示密钥、地址或协议输入框。已存账号在默认应用目录和指定共享 pi 目录中均自动导入；新 OAuth 连接保存模型时不生成自定义接口地址或协议覆盖，已有自定义覆盖保留并提示。自定义连接配置显示两个文件的实际路径；配置下方只放保存、取消和 Tabler `refresh` SVG 重新读取按钮，页面状态区显示保存结果，密钥字段显示已保存状态和占位掩码，明文输入仅在成功保存并重读后清空。登录后由新运行时重新读取本地凭据再确认成功。OAuth 收到链接后自动请求打开系统浏览器，可重开或复制链接；按供应商支持使用自动回调、设备码或手动粘贴授权码／完整回调地址，完成后自动刷新认证状态。授权链接／设备码／输入提示只发送给发起连接；取消、断线、超时不自动重启认证。真实 OAuth 流程仍待验收。
- 已保存密钥、请求头值和敏感 URL 不回传；空密钥保留旧认证。自定义接口的「退出认证」立即执行，保留供应商与模型定义，同时清除受管理凭据、供应商／模型请求头覆盖及地址内嵌凭据和参数；有未保存编辑时禁用。活动执行需先确认停止，部分失败或结果不确定后需重新读取。删除模型同样执行供应商级退出并说明影响。环境变量不改写，仍可认证时如实显示。
- 新增 `!` 命令型密钥／请求头须明确授权；单独登录不接受命令型密钥。已存在的未展示字段保留在服务端。供应商级数值覆盖落实到当前模型，重读显示为模型项。
- 编辑入口要求普通 JSON；注释／BOM、损坏文件、重复 ID 拒绝覆盖。配置上限 1 MB，单命令 200 KB。配置和凭据不是跨文件事务；部分失败须重新读取核实，不假称全部回滚。
- 撤销认证前确认影响并终止受影响的活动执行、取消排队子任务及后台压缩，不增加 Agent 清理确认步骤。当前执行使用固定配置快照；模型选择和配置变更作用于后续执行。

### 主／子 Agent 与恢复

- 主／子会话是 pi 的薄封装：冷启动时创建独立 Node.js 工作进程，已有上下文只从绑定 JSONL 恢复；同一会话不并行启动多个执行。成功结束后复用该进程与 AgentSession，空闲保活池按 LRU 最多保留 10 个、15 分钟未使用后释放，不淘汰正在执行的进程；从初始化起超过 15 分钟的进程在空闲时释放，避免连续复用使未跟踪资源无限陈旧。模型选择、模型配置、认证、设置、项目指令／扩展／技能／提示文件或会话文件变化时拒绝复用并重新初始化；缓存进程的固定配置快照缺失、不可读或改变时，同样先释放旧进程，再按绑定 JSONL 和本轮新快照启动。外部资源包和符号链接目标不保证即时刷新，受上述最长复用期限约束。空闲淘汰先请求正常关闭，最多等待两秒后强杀；等待旧进程退出的启动同样属于可取消执行，停止会使其失效并等待退出。停止、撤销认证和服务退出释放对应进程。主 Agent 在 Windows 未指定工具时使用 pi PowerShell；其项目本地扩展、技能和设置等资源默认授权，首次发送初始化时即按 pi 规则加载，不再单独确认项目资源授权。子 Agent 使用下述固定调研与测试能力，不加载外部扩展或提示模板，不解析配置的资源包。上下文、工具、重试、压缩均由 pi 管理。
- 自动重试由 pi 负责，同一过程保持一个 runId；会话环境展示实际设置，侧栏展示运行阶段和重试次数。继承全局／项目设置，原生默认最多重试 3 次、基础等待 2 秒、会话等待上限 60 秒，供应商层默认 0 次；停止退避不会再启动请求。重试与压缩内部事件不单独标记任务完成，最终结算等待原生空闲与工作进程交接。
- 未恢复的输出长度截断显示“输出截断，可继续处理”，执行与消息均记失败；异常中断和用户停止分开处理。失败、停止、中断后可点击输入区“继续处理”，发送一条明确的新用户指令并创建新执行，保留当前草稿。服务端校验原 runId 及活动工作，旧恢复点击不会注入新的运行；子任务继续沿用新追问／新结果语义。回执不确定只查询，不自动再次发送。
- 重试使用 pi 持久化上下文投影，原生排除的失败尝试在实时及重载视图中一致隐藏，原始 JSONL 保留；已有工具结果不删除或自动重放。重试说明不加入提示词，保持公共前缀稳定；关闭额外缓存预热请求。回环验证只证明请求前缀一致，真实缓存命中须看供应商用量。当前未提供无新增用户消息的手动重试，需 SDK 正式 Session 级能力。
- 「会话环境」展示实际资源加载情况，以及当前／最近一次加载的真实 pi「系统提示词」文本，不用资源清单或应用模板代替。新会话首次发送初始化前显示未初始化占位，不预先生成提示词；历史环境快照缺少系统提示词字段时，提示下次执行加载。
- 四个独立工具：`delegate`、`append`、`cancel_task`、`read_result`。界面在执行过程内部统一使用专用卡片，不重复生成普通工具行：委派从创建开始展示子代理协作卡，错误直接显示在卡片内；读取、补充／追问、停止使用紧凑操作卡，默认展示任务描述和操作状态，展开查看本次交付或操作详情。读取绑定原调用的不可变结果；追加受理、停止受理与实际结束分别标记，失败／停止／未知反馈保留。子任务完成通知收入过程卡片，其他通用系统通知独立展示。子代理可做调研、分析、审查及执行测试、构建和静态检查。独立测试优先并行委派，明确工作目录、命令或范围与前置条件，隔离端口、临时目录和输出路径；依赖或共享资源冲突的检查按顺序执行。返回证据、文件位置、修改建议，或实际测试命令、退出码、关键输出、产物路径及未验证项。代码修改由主 Agent 完成；测试期间不修改相关文件，依据变化后重跑受影响检查，已验证且依据未变的检查无需主 Agent 重复执行。子代理不递归委派，只收到明确背景与任务，不复制父代理全部对话。
- 子代理由执行层固定为 pi 内置 `read`、`grep`、`find`、`ls` 和平台命令工具（Windows 为 `powershell`，其他平台为 `bash`）白名单，禁止直接调用 `edit`、`write`、另一平台的命令工具及其他未批准工具，并在工具调用时再次检查；不加载用户／项目／资源包扩展（包括同名工具覆盖），不安装配置的资源包。系统提示词限定命令用途为委派范围内的验证，允许必要测试产物，禁止修改源码、测试代码、配置、锁文件、基准快照及安装依赖。职责补充、项目默认工具配置、直接追问与恢复历史子会话均不能改变白名单与职责要求。主 Agent 权限保持不变；同项目文件仍共享，应用调研建议前主 Agent 应重新核对当前文件。
- 所有子代理设置集中在输入框下方的分支节点图标内：默认模型、思考等级、并发数与工作时限。删除旧默认子模型块和配置页预算块；批注、分支与压缩图标依次成组，同排时靠最右侧，换行后靠左。模型选择即时保存，数值按 Enter／失焦自动保存；全局服务端持久化、跨工作空间／会话／窗口实时同步，刷新与重启保留。默认模型立即用于新委派，不强换正在执行请求的模型或覆盖已有子会话选择。
- 持久化 FIFO 队列，配置仅包含 `concurrency`（默认 4，范围 1–16）和 `workMs`（默认 600000 毫秒，范围 1000–86400000 毫秒）；到期后的无工具总结固定最多 3 分钟。工作时限修改立即应用于排队及工作中的任务，按最近一次工作计时基点重算截止，已超时则进入总结；有效追加受理并持久化后，从当前时间重新计算完整工作预算，新执行读取最新时限。修改偏好不延长已经开始的总结。并发设置立即作用于现有队列，降低上限不强停正在执行的任务。一次委派最多 8 个，每个主会话最多 32 个活动／排队任务，每个子会话最多 32 条未交付输入。
- `append` 新调用统一使用 `steer`（默认）；运行中追加使用 pi 安全边界。停止中仍可追加，要求先保存，旧执行退出并交付取消结果后自动排队续接；再次停止会撤销尚未启动的新要求。结束后追问复用有效保活进程，或打开同一子会话 JSONL，并创建新执行和不可变结果。所有新执行共用 32 项容量检查，按本次入队顺序调度，续接不插队、不等待父代理读完旧结果。输入回执区分排队、worker 接收、已送达、失败和撤销；明确发送失败不会显示排队成功。`cancel_task` 仅接受 `taskId`、可选 `reason`；手动停止直接强制终止拥有的执行，不再发起总结，不要求清理确认。工作预算到期中断当前操作，在同一 `runId` 内禁用全部工具并总结已有证据；界面显示「正在总结」。总结的 3 分钟上限包含等待当前操作退出和模型重试，到期强停并保留已有输出；总结中追加会中断总结、恢复工具并刷新工作时限。Run 不含 `cleanup`。结果保存停止来源、原因、时间和实际执行耗时，预算总结标记 `budgetSummary`，不表示任务全部验收通过；子代理在执行开始时获知预算、截止时间和此前累计耗时。
- 临近预算时由工作进程主动提醒：剩余总预算的 20%（最多提前 60 秒）时，通过 Steering 在下一安全边界注入一次剩余时间告警，要求尽快交付已有结果和未验证项。同一执行的相同截止时间不重复注入；预算调整重算告警点，后续请求排除旧执行／旧截止的告警并刷新有效告警的剩余秒数。长模型请求或工具调用期间提醒需要等待安全边界，不保证到期前一定被模型读到；提醒不延长预算，工作到期转入上述无工具总结；旧执行、旧预算版本的控制消息和定时器不能覆盖刷新后的时限。
- 子任务报告完整保存，`read_result` 支持 `offset/limit`，每页最多 16000 字符；`truncated/nextOffset/totalLength` 明确后续页。界面可继续读取同一份交付，区分最终回复、部分成果和系统执行记录，旧结果不随续接改变。停止保留已落盘产出，不伪造流式丢失内容。
- 通知使用稳定结果标识去重、每次投递独立请求回执；父代理运行中合批 Steering，空闲时按未冻结规则唤起。从实际 JSONL 完整记录增量核实后才确认，确认丢失先对账；文件存在或内存条目不作为新增输入已落盘的证据，停止期间迟到的持久化可修正输入回执。IPC 发送异常记录为结果未确认，不自动重放，不把发送背压当失败。批量通知逐项核实入队结果，确认未入队的项可在后续显式操作中重试，已入队项不重复注入。明确失败不循环唤醒，新主会话输入或重新选择模型后受控重试。实现与验收见[子代理优化方案](docs/subagent-optimization.md)。
- 完成通知内部只带结果标识，父代理显式读取；前端转为带线性图标的简短状态条，区分完成／取消／失败／中断，不展示内部 JSON。思考与工具一样默认显示单行，使用用户提供的大脑 SVG 与 `thinking` 标题；点击展开后首行保留图标与标题，内部正文为灰色斜体，无左侧竖线。生成中显示 `thinking ...`，三个点与执行过程卡片共用 SVG 错峰缩放动效，收起与展开时一致，完成后移除三点；收起时显示灰色斜体 Markdown 单行预览，展开后隐藏预览，减少动态效果设置下仍保留该三点状态动画。纯思考、工具、子任务操作及完成通知按原顺序收入同一过程卡片，思考和通知不计入工具数量；用户消息、普通正文、压缩及独立系统通知形成边界；无独立正文的失败／停止记录和后续恢复调用仍在同一卡片内。独立正文所附思考在紧邻前一张过程卡片时合并到该卡片，正文独立显示在下方，流式输出和刷新后均不重复生成过程卡片；没有相邻过程卡片时仍收在该消息内。已有过程块及内部思考的手动展开状态在流式更新与子任务调用加入时保留（`tests/thread-layout.test.ts`、`tests/thinking-layout.check.ts` 覆盖）。主／子会话消息列表末尾、输入框左上方不显示独立运行状态行。Steering 发送后保留在输入框上方待执行区，实际消费后才进入会话气泡；
- 父会话停止先冻结自动唤醒，再终止父会话和所属活动子任务、取消所属排队任务；子任务停止只作用于自身。窗口重开、服务重启或子会话新追问不解除父会话冻结，明确的新主会话消息才恢复自动处理。
- 绑定的 pi JSONL 是唯一上下文恢复来源；SQLite 保存关系、结果、未发送草稿和带归属的管理回执，不保存另一份对话上下文。重连只读取消息和运行状态；待确认输入按原请求 ID 自动读取既有回执及原始分支中的消费身份，不恢复已隐藏的正文、不重放请求，也不要求人工执行恢复流程。撤回回执丢失时只查询原回执，确认成功后合并恢复草稿且仅恢复一次；无法取得可靠证据时保留未确认状态。待确认输入是独立的用户数据，不随展示 LRU 丢弃；草稿中保留的待确认提交可在刷新时恢复其请求身份，草稿表不充当完整发送队列。重启不重发提示、重新委派或重做文件修改。迟到回执不清空新的内存输入。缺失／损坏的会话文件保留原件并报错，不用空会话冒充恢复。
- 真实 Token、缓存、pi 上下文估算、耗时按会话展示；底部耗时累计当前会话的所有执行，停止／完成／失败后重新发送或重试继续累计，空闲间隔不计时，切换会话与刷新后从服务端记录恢复，主／子会话分别统计。若只更新了页面而后台仍为旧代码，先显示最近一次运行时间，悬停提示在任务结束后重启后台以启用累计计时。上下文圆环与百分比使用同一占比并限制在 0–100%，未知容量显示虚线与“—”。输入框费用可点击，在当前工作台打开费用浮窗，保留原会话草稿；浮窗内容独立滚动，顶部固定紧凑刷新按钮与关闭按钮，支持点击外部或 Esc 收起；刷新时显示图标旋转和“更新中”，完成后恢复。从主／子会话进入均汇总所属主会话和全部子任务，分别列出主 Agent、每个子 Agent、压缩、工具内部模型调用及其他用量，模型行可展开 Token 与分项费用。后台压缩按任务 ID 与已应用记录去重，失败／取消／未应用的可得消费仍计入；新摘要请求逐次保存可得用量，无法确定的部分显示未知。使用历史记录的美元价格，不以当前价格重算；混合用量显示“已知金额 + 未知”，无记录显示“—”。独立订阅在用量变化及重连时更新，浮窗关闭不扫描历史。
- 工具费用支持 pi 原生 `toolResult.usage`；需要模型维度时可通过 `usage` Entry 的 `kind="tool:<工具名>"`、`provider`、`model` 与 `usage` 上报。同一消费只使用一种方式记录一次，未上报的工具内部调用不能自动计入。主／子会话原始历史中的压缩前、重试与分支消费均保留；摘要／工具记录可能包含多次请求。实际扣款以供应商账单为准，不伪造结果、用量或成功。

**安全边界：**工作进程与上下文隔离不是文件系统／命令沙箱。工作空间访问在选择目录打开时默认授权；主 Agent 的项目本地扩展、技能和设置等资源默认授权并按 pi 规则加载，不提供额外授权门禁；子 Agent 按上述工具白名单和资源限制执行。通用 shell 的测试用途与禁止源码修改由系统提示词约束，不是文件系统只读保障；命令、测试产物、会话记录、应用元数据及已授权的命令型认证均可能产生写入。新增命令型密钥／请求头仍须明确授权。获准工具或项目程序可以修改当前用户有权限的文件、执行命令、安装依赖。强制终止／崩溃不证明所有外部副作用结束，也不回滚文件；必要时由用户检查残留程序及外部状态，但不设置 Agent 清理确认门禁，不能按重启前的旧 PID 自动杀进程。

### 后台压缩与安全点应用

- 主／子会话分别管理任务与详情。图标切换压缩页面展开／收起，即使尚无任务或任务已完成／取消也可查看。页内提供开始／再次压缩及运行中的取消按钮；无消息、未选择模型、断线或操作待核实时说明限制，不因历史终态锁死入口。关闭／Escape 只退出查看，不取消后台任务。刚完成且没有新增消息时，按 pi 原生限制提示暂无可再次压缩的内容，不重复请求模型。
- 压缩模型复用统一 `ModelPicker`（供应商、模型、思考等级与收藏），选择作为独立全局偏好保存到服务端；主／子会话、不同窗口共享，刷新和服务重启后保留，不改变聊天模型。尚未保存时默认当前会话模型；已保存模型不可用时明确报错，不静默替换。运行中修改仅影响下一次压缩。
- 压缩页可配置自动压缩开关、Token 阈值和上下文百分比；默认开启，100,000 Token／80%。实际触发值取 `min(Token 阈值, 当前会话模型容量 × 百分比)`，达到即启动后台压缩；主／子会话独立判断，容量未知时使用 Token 阈值，占用未知时不触发。配置按 Enter／失焦自动保存，全局共享并跨重启保留，页面展示当前生效阈值。保存配置后在执行启动或后续成功回合的用量检查时生效，开关关闭不取消已经开始的任务。自动任务使用已选择的压缩模型，详情标记“自动触发”；持续超阈值时不会反复压缩，同一执行中失败／取消不自动重试。Axiom 接管主动阈值压缩，保留按 pi 设置启用的原生溢出恢复。
- 每次触发都创建独立的新压缩任务，仅依据当前会话分支取快照；此前任务的失败、取消、中断不影响新任务，旧任务回执不作用于新任务。运行中的会话以 pi `turn_end`／`agent_before_settle` 为安全边界，空闲会话先等待保活进程及关闭钩子释放所有权再取快照。历史失败、已中止请求及进程中断留下的未配对工具记录属于可摘要历史，不用于判断当前是否正在执行；当前执行中的工具仍须等待安全边界，不在流式中间状态截取。
- 会话运行中先等待 pi `turn_end`／`agent_before_settle` 安全边界保存当前分支快照；空闲时在所有权释放后保存。独立 pi 工作进程只对快照调用原生 `compact(customInstructions)`，附加要求在完整摘要前生成 `<axiom-summary>` 短主题，不另发模型请求；缺少短主题的历史或原生自动压缩摘要显示“上下文已压缩”。不打断当前请求、不成为原会话的第二个写入者。摘要就绪后，运行中的原会话在新的安全边界校验并追加原生 compaction；空闲会话先释放保活进程，再同步校验并追加，后续发送从新上下文初始化。原始 JSONL 历史和快照后新增消息保留，不用快照覆盖原文件；分支、快照前缀或压缩边界发生冲突时拒绝应用。会话在等待期间结束时，任务交接到空闲会话或新执行继续处理，不因进程结束报失败，也不重新生成已有摘要；等待保活进程退出后重新检查所有权。真实快照／应用错误保留脱敏原因，不猜测会话已停止。
- 阶段依次为等待安全点快照（`snapshot`）、后台原生摘要（`summarizing`）、等待新的安全点应用（`applying`）和已应用（`done`）。`completed` 表示已应用，而非仅生成摘要；应用前不会因摘要就绪更新会话占用。详情的压缩后数值是快照估算，不含新增消息。会话当前占用优先使用 pi 原生统计；压缩后尚无新模型用量时，使用 pi `estimateTokens()` 对已应用的当前上下文投影（摘要、保留消息及新增消息）估算，显示 `≈` 与估算说明，下一次有效模型用量到达后恢复原生统计。旧会话已保存的未知占用也从绑定 JSONL 只读补算，不额外请求模型。
- 使用已确认且可用的模型，不自动替代；压缩进程不加载项目扩展、技能、上下文文件或编码工具。每会话最多 1 项、全局最多 4 项，不设置压缩等待或执行时限，取消后等待最多两秒再尝试强制结束工作进程。授权的命令型认证仍属于可执行配置，不是操作系统沙箱。
- 详情展示真实阶段、摘要和 pi 的前后估算；压缩入口、详情状态、当前步骤以及活动子任务的加载图标统一使用 Iconify `eos-icons:bubble-loading` 官方气泡缩放动画，减少动态效果时仍播放。当前步骤保留高亮，完成步骤显示勾选，失败标记保留在对应步骤，终态移除加载动画。压缩摘要卡片采用 Tabler `fold` 原始路径，图标无方块背景，桌面为 32px、窄屏为 28px，上下箭头以 1.8 秒周期向中间虚线靠拢再回位，减少动态效果时仍播放。失败／中断原因独立展示，异常消息经常见凭据模式脱敏和长度限制后保存，刷新仍可查看；缺少原因时明确提示未知，不伪造诊断。摘要展示超过 64,000 字符会明确标记截断，不以截断文本替代原生应用结果。摘要请求的可得用量／费用在应用后计入所属 pi 会话统计，详情仅为该次明细，不与会话统计再次相加。失败、取消、中断或冲突不应用摘要，也不伪装成成功。
- 任务／回执持久化并校验会话归属；完成终态须在压缩工作进程退出且安全点应用成功后发布。重连仅核实、不重发。服务重启时，若原会话已持久化带有该任务 `details.axiomCompressionId` 的原生 compaction，则将任务恢复为已应用（`completed`），覆盖追加成功但确认回执前崩溃的情况；否则将未结束任务标为中断（`interrupted`），不重放应用或自动重新压缩。父会话整体停止同时取消所属压缩；撤销供应商认证须先确认停止受影响任务。临时快照退出后清理，异常残留在下次启动清理。

## 桌面交付

Windows x64 与 macOS 通用版产物通过 [GitHub Releases](https://github.com/cosyeezz/axiom2/releases/latest) 下载；本地构建输出位于：

- `app/Axiom2.msi`：Windows 安装包。
- `app/Axiom2.exe`：Windows 独立可执行文件。
- `app/Axiom2.dmg`：macOS 通用安装镜像，包含 arm64 与 x86_64。

桌面壳包含本地服务控制页及原生启动／停止桥接，不包含 Node.js、pi 或后端。控制页随客户端打包，从本地加载，不会在服务未启动时跳转到连接错误页。控制页与工作台是同一个原生窗口中的两个独立 WebView；工作台就绪后切换显示，上方保留本地“服务与更新”导航，普通切换不重新加载工作台。沿用原有 Web 产品及 Host／Origin／禁止 iframe 的安全限制；管理桥接校验实际调用 WebView 的标签与内置来源，远程工作台不能因共用父窗口而取得原生服务或更新权限。OAuth 通过本地服务打开系统默认浏览器完成 pi 授权，保留复制链接及手动回填入口。Windows 需要 WebView2 Runtime，Windows 客户端未经代码签名；macOS 客户端使用 ad-hoc 签名，未经过 Apple Developer ID 签名或公证。

重新构建需要 Node.js、Rust/Cargo 与目标平台原生构建工具（Windows MSVC、WebView2；macOS Xcode；Linux WebKitGTK 等）；脚本自动在隔离目录安装固定版本 Pake **3.16.2**：

```sh
cd app
npm run package:desktop
```

macOS 通用版需在 Mac 上、从仓库根目录执行：

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
npm --prefix app run package:desktop -- --targets universal
```

也可在 GitHub Actions 的 `Build Axiom2 Desktop` 中选择 `platform=macos`；`source_ref` 可填写发布 tag 或 commit，为空时使用工作流所在版本。macOS 流程校验 DMG、双架构、版本与应用标识、签名完整性及无测试入口，再从镜像复制应用到临时目录，用隔离数据目录启动并检查该进程拥有可见窗口。正式包始终从 `source_ref` 构建；正式包校验完成后，独立测试应用的两份 JavaScript 探针取自工作流修订，日志记录该修订，不改写正式 DMG。流程另构建独立标识的测试应用，由 `scripts/check-desktop-macos.mjs` 在真实 WKWebView 中操作打包控制页，检查单窗口切换、原生命令拒绝、草稿／选区／滚动／焦点、原生缩放、服务启停、窗口关闭及重开后复用后台；CoreGraphics 独立确认工作台显示时只有一个可见应用窗口。只有检查通过才生成交付 artifact；失败时保留的诊断 artifact 不作为发布包。`Publish Axiom2 macOS Desktop` 可将成功构建的 artifact 直接发布到已有 Release：需填写构建 run ID 与对应 tag，发布前复核源码、原生检查和附件摘要，并校验原生证据中的连接桥接、固定状态文字色和波形三状态样式，保留其他产物并补全校验文件。

配置在 `app/desktop/pake.json`。`package:desktop` 使用 `scripts/build-desktop.mjs` 将固定版本的 Pake 模板复制到隔离目录，注入 `app/desktop/axiom_service.rs`、`axiom_views.rs` 与只读连接观测 `axiom_connection.rs` 后构建，桌面版本统一从根 `package.json` 传入，不修改全局 Pake 源文件；直接运行原版 `pake --config` 不包含服务控制桥接。产物／日志不提交 Git。`npm run check:desktop` 使用 Windows EXE、WebView2 和隔离数据目录，通过本机 CDP、Win32 窗口枚举／缩放与原生关闭请求检查离线控制页、单原生窗口双 WebView、切换后的草稿／选区／滚动／焦点保留、远程管理调用拒绝、启动／停止确认与取消、重启、第二次启动聚焦已有窗口、退出后重新打开、服务换端口后的工作台重建及正常／强制退出客户端后服务存活。先在仓库根目录运行 `npm --prefix app run package:desktop -- --targets x64 --test-instance` 构建独立标识的 `Axiom2-ServiceTest.exe`；仅此测试构建带 CDP 和原生自检入口，正式产物不带调试或自检入口，测试不会接管已运行的正式客户端。可用 `AXIOM_DESKTOP_BINARY` 指定测试 EXE。该检查不覆盖 MSI 安装交互、真实 OAuth 或 macOS/Linux 原生运行。

`npm run check:desktop-update`（在 `app/` 执行）使用当前构建脚本生成的测试 EXE 验证应用内更新；设置 `AXIOM_UPDATE_OLD_TARBALL` 指向已发布 v0.2.3 包、`AXIOM_UPDATE_TARBALL` 指向本次构建包。测试隔离安装目录、数据、pi 配置、npm 缓存及端口，仅测试构建允许本地发布源，并将原生安装器启动替换为程序路径与参数记录；假 MSI 用于验证篡改后零次启动、有效文件仅传入固定系统 `msiexec.exe` 及 `/i`、已校验路径，不执行真实安装。清理需确认最近请求的更新任务已终止、所属 worker 和后台进程已退出；读取失败、状态未知、旧任务记录或超时均保留目录并报告，不与更新并发删除夹具。生产客户端的更新来源固定为本仓库 GitHub Release，附件按发布 API 的 SHA-256 和大小校验。更新日志与恢复记录位于数据目录的 `updates/`；旧程序备份和准备目录保留在原包旁。恢复保证限于更新进程异常退出，不保证系统崩溃或掉电后的自动恢复；程序恢复不回滚会话数据或数据库迁移。恢复时使用已验证旧备份中的控制代码确认服务退出，再移动目录；即使候选程序能显示版本却无法加载控制模块，也不依赖候选程序执行恢复控制。恢复时核对旧程序及服务报告的运行版本；旧后台协议不报告版本时，只确认旧程序和服务运行状态。

## 代码与设计维护

- `ui/`：用户原始设计，只读；根目录 ZIP 保持原样，不自动重打包。
- `app/src/client/{pages,chat,models,tasks,workspaces}`：页面组合与各自状态／交互；直接导入，无总文件承载全部界面。
- `app/src/server/agents.ts` 与 `agents/`：命令／模型归属、工作进程生命周期、消息视图独立。
- `app/src/server/compressions.ts` 与 `compression-worker.ts`：快照任务持久化／取消、原生 pi 摘要与安全点应用分开；客户端 `chat/Compression.tsx` 和 `CompressionDetail.tsx` 分管交互与详情。
- `app/src/server/tasks/`：记录、命令、调度与预算、结果交付分别管理；通过现有 Agent 运行核心执行。
- `app/src/server/model-service.ts`、`models/draft.ts`、`auth.ts`：配置发布、字段映射校验与原生认证。
- `app/src/server/storage.ts`：保存应用管理数据。
- `app/src/shared/`：实际共享协议；`app/tests/`：检查；`app/desktop/`：本地服务控制页入口、原生桥接及打包配置。
- `app/` 根目录原有 HTML／图片／检查脚本是保留的原型副本，不是产品入口。

设计更新先独立提交，再按 `docs/ui-sync.md` 的设计提交差异移植至 `app/`，不整目录覆盖已接入功能。采用提交在完整设计验收前不提前提升。源码发布到 `https://github.com/cosyeezz/axiom2`，安装包与桌面二进制通过 Releases 分发，不提交到 Git。

根目录 `package.json` 是分发入口，也是 CLI 与后台运行状态报告的版本来源。推送到 `master` 后，`Validate Axiom2` 在 Windows、macOS、Linux × Node.js 22.19.0／24 的六组验证全部成功后自动发布后台；PR、手动运行 CI、失败或取消的验证不发布。发布前与公开前检查源提交仍是远端 `master`，已经过时的提交跳过。仅本地 `git commit` 不会触发，必须 `git push origin master`，并等待工作流的 `publish` 成功，其他端才能通过“检查更新”发现新版。

自动发布从源码版本及已有正式格式 tag／Release 的最大版本递增补丁号，同步根包、`npm-shrinkwrap.json`（顶层及根包条目）、`app/package.json`、`app/package-lock.json`（顶层及根包条目）和 `app/desktop/pake.json`。这五个文件的版本变更形成源提交的直接子提交，仅由 `v<版本>` tag 引用，不回写 `master`，不会触发递归发布；因此开发分支上的版本可能落后于已安装版本，实际发布源码以 tag 为准。同一源提交重跑复用已保留的 tag／草稿；已公开版本只重新核验附件与公开下载，不重复发布、改写附件或重设 Latest，允许桌面发布追加校验条目。新 push 取消旧 push 的整条 CI／发布流程，避免旧流水线占据等待中的发布位置；历史重跑使用隔离的并发组，不取消当前 master 的流水线。公开前仍检查源 SHA 与最新正式版本。后台任务只在草稿阶段修改附件，macOS 任务只向正式版本追加附件，并独立串行，因此不会抢占后台发布的等待位置。

发布任务在升版后的快照重新构建并运行 `check:package`，保留实际通过安装、升级和恢复检查的 tarball，直接上传为 `axiom2.tgz`；草稿的附件大小与 GitHub API SHA-256 全部匹配后才公开为 Latest；草稿允许本仓库的临时 `untagged-…` 附件地址，公开后必须使用对应版本 tag 的固定下载地址，并验证实际下载字节。GitHub 元数据或下载短暂不同步时有限重试，每次重新读取元数据；持续失败保留错误，不将重跑直接视为验证成功。安装包检查通过 `AXIOM_VERIFIED_PACKAGE_DIR` 可选导出验证过的包及其版本／commit／摘要凭据，常规检查仍只使用临时目录。若上传或校验失败，修复原因后在 Actions 重跑失败的发布 job；不要覆盖已公开版本。更新器只接受高于已安装版本的正式 Release。

后台自动发布不构建桌面客户端。已有客户端继续更新后台；原生壳改动仍需独立构建，手动桌面构建的 `source_ref` 应选择对应发布 tag，确保桌面产物与 Release 源码、版本一致。源码安装仍通过拉取、构建和重启更新，不使用客户端的后台包切换。

根包依赖版本与 `app/package.json` 保持一致；pi 同系列的七个运行包均显式固定为 `1.1.0`，避免子依赖范围升级造成导出接口不兼容；`npm-shrinkwrap.json` 记录并随包携带构建使用的完整依赖树；`npm ci` 自动构建，`npm run check:package` 校验依赖一致性，并在隔离全局目录安装实际 tarball、启动服务、访问页面与脚本资源、检查跨站请求被拒绝，并验证前台／后台启动、相对数据目录、重复启动、正常停止、控制通道认证及不会停止无关监听进程，并分别在 npm 默认提升布局和用户配置嵌套布局时执行真实预备安装、版本切换与启动验证，核对依赖路径、工作进程模块加载及无失效的内部自身命令 shim。更新器固定使用 `--install-strategy=shallow`，将候选包及其完整依赖树一起切换，保留外部全局命令路径。包检查另用真实旧备份恢复控制模块损坏的候选程序，验证恢复后的运行版本、HTTP 与停止。`npm pack --ignore-scripts` 打包已经构建的产物；Release 将 tarball 命名为 `axiom2.tgz`，同一版本的服务与客户端文件共同生成 `SHA256SUMS`。安装脚本只消费 Release，不在用户机器编译前端。GitHub Actions 提供三平台构建／测试以及手动触发 Windows／macOS Pake 构建；测试环境显式安装文件补全所需的 fd，涉及原生路径／会话的夹具使用真实临时目录，兼容 macOS `/var` 别名与 Windows 短路径。CI 构建不替代原生交互验收。
