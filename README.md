# Axiom2

基于 pi 的本地多工作空间编码 Agent 工作台。已实现主／子 Agent、模型配置与认证桥接、持久化恢复，并提供 Windows 与 macOS 桌面构建产物。**当前为第一阶段候选交付，不宣称全部验收通过**：真实供应商／OAuth、完整视觉对照、完整原生桌面交互和 macOS/Linux 业务端到端验收尚未完成。

实施依据：[产品设计](docs/design.md)；设计采用状态：[UI 设计同步](docs/ui-sync.md)。文档只描述当前内容，变更轨迹由 Git 保存。

## 一行安装与客户端下载

需要先安装 [Node.js 22.19.0+](https://nodejs.org/)；无需 Git、Rust 或单独安装 pi。源码：[cosyeezz/axiom2](https://github.com/cosyeezz/axiom2)，发布与校验文件：[GitHub Releases](https://github.com/cosyeezz/axiom2/releases/latest)。

**Windows PowerShell（一行安装并启动）：**

```powershell
irm https://raw.githubusercontent.com/cosyeezz/axiom2/master/install.ps1 | iex
```

**macOS / Linux（一行安装并启动）：**

```sh
curl -fsSL https://raw.githubusercontent.com/cosyeezz/axiom2/master/install.sh | sh
```

脚本安装最新 Release 中已经编译的 npm 包，再启动服务。也可直接安装：

```sh
npm install -g https://github.com/cosyeezz/axiom2/releases/latest/download/axiom2.tgz
axiom2 start
```

一行安装完成后会启动后台服务并返回终端；再次使用可在 Pake 控制页点击“启动后台服务”，或运行 `axiom2 start`。`axiom2 status` 查看状态，`axiom2 stop` 正常停止服务；直接运行 `axiom2` 仍支持前台运行、Ctrl+C 退出。后台进程不依赖终端或客户端窗口，但不注册登录自启，也不在崩溃后自动重启。`axiom2 --help` 查看帮助，`axiom2 --version` 查看版本。安装路径由 `npm prefix -g` 决定；全局目录无写权限时请使用用户级 Node.js 安装或 npm prefix。

| Pake 客户端 | 下载与使用 |
| --- | --- |
| Windows x64 安装包 | [下载 Axiom2.msi](https://github.com/cosyeezz/axiom2/releases/latest/download/Axiom2.msi)，安装后打开 Axiom2 |
| Windows x64 便携版 | [下载 Axiom2.exe](https://github.com/cosyeezz/axiom2/releases/latest/download/Axiom2.exe)，直接运行 |
| SHA-256 校验 | [SHA256SUMS](https://github.com/cosyeezz/axiom2/releases/latest/download/SHA256SUMS) |
| macOS 通用版（Apple 芯片 / Intel） | [下载 Axiom2.dmg](https://github.com/cosyeezz/axiom2/releases/latest/download/Axiom2.dmg)，打开后将 Axiom2 拖入 Applications，再从应用程序打开 |
| Linux | 当前使用浏览器；尚无发布并验收的原生客户端 |

**Pake 自带离线可用的服务控制页。** 服务未启动时仍能打开客户端，点击“启动后台服务”，就绪后点击“打开工作台”；关闭服务前会列出活动会话并要求确认。服务启动期间可查询“正在启动”状态并关闭服务；启动命令等待超时后，仍可刷新状态或执行 `axiom2 stop`，停止成功后不会再次上线。工作台在独立窗口打开；服务地址变化时，重新打开会替换旧地址窗口。后台停止后工作台窗口关闭，可在控制页重新启动。单独关闭工作台会保留控制页；关闭控制页会退出整个桌面客户端，再次启动时恢复控制入口。Pake 不包含 Node.js、pi 或后端，首次使用仍需安装服务；Windows 需要 WebView2 Runtime，客户端未签名。关闭客户端不会退出后台服务。真实供应商、OAuth 与原生安装交互的验收范围见下文。

**应用内更新：** 在 Pake 控制页的“版本与更新”点击“检查更新”，分别查看客户端、后台服务与最新版本。点击“更新后台服务”并确认后关闭工作台，先下载、校验和准备新版，再停止旧服务、切换程序并验证启动；项目与会话数据保留，正在执行的任务会结束。更新由独立任务执行，关闭、重开客户端仍可查看进度。程序切换或启动失败会尝试恢复旧程序，更新进程异常退出且留下恢复记录时可点击“恢复旧版本”；恢复会核对旧程序版本，备份缺失且安装目录仍是其他版本时保留恢复记录并报错。后台必须安装在标准 npm 包目录且目录可写（一行安装命令符合此方式），源码目录请使用原方式更新。**应用内更新与恢复仅支持一个数据目录独占一个服务安装。多个数据目录共用全局安装不受支持；请为各数据目录使用独立安装目录，或停止所有相关服务后手动更新。** 当前任务锁和服务探测均按数据目录工作，不能检查其他数据目录是否仍在使用同一程序。

Windows 客户端更新使用“下载客户端更新”→“运行安装器”：附件校验通过后才打开 MSI 安装向导并关闭当前客户端，后台继续运行；安装完成后重新打开客户端查看版本。安装器启动不代表安装成功，仍需完成系统向导。**v0.2.x 客户端首次需手动下载新版 MSI／EXE，之后才能使用应用内更新入口。** 首次安装 Node.js 和后台仍使用上方命令。

macOS 客户端使用 ad-hoc 签名，未经过 Apple Developer ID 签名或公证；首次打开如被系统阻止，可在“系统设置 → 隐私与安全性”中确认“仍要打开”。Mac 客户端自身更新需退出客户端后下载新版 DMG 并替换 Applications 中的应用；后台服务可从控制页管理和更新，仍需满足上述独占安装要求。

手动更新／修复：先通过客户端“关闭后台服务”或 `axiom2 stop` 停止旧服务，再运行安装命令。v0.1.x 前台服务需先在原终端按 Ctrl+C 退出。卸载：停止服务后运行 `npm uninstall -g @cosyeezz/axiom2`；会话数据和共享 pi 配置保留，Windows 客户端在系统设置中单独卸载。

## 从源码启动与使用

需要 **Node.js 22.19.0+**、npm。最低版本由现有 pi 依赖要求确定；无需固定到某个补丁版本。CI 分别使用 Node.js 22.19.0 和 24，在 Windows、macOS、Linux 上执行构建、测试与实际发布包检查。

```sh
cd app
npm ci
npm run build
npm start
```

1. 打开 `http://127.0.0.1:4317/`，本机连接无需 token 或登录。服务仅监听回环地址，仍校验 Host／Origin，拒绝跨站请求。
2. 点击「打开文件夹…」，在系统文件夹选择器中选择已有项目，即默认授权并直接打开工作空间、创建会话，无额外确认弹窗；无需手动输入路径。取消选择不会创建工作空间。重新打开 Pake 或新的浏览器窗口会恢复服务端记住的上次工作空间，同窗口刷新优先保留自己的会话位置。会话切换不停止后台工作。若提示服务不支持文件夹选择，请重启本地服务并刷新页面（只刷新无法更新已运行的后端）。
3. 在「配置 → 模型服务」添加供应商和模型，使用**顶部保存**统一发布，包括尚未收起的行内编辑。填写 API Key 或使用 pi 支持的认证入口；配置有效不等于远端认证有效。
4. 回到会话确认模型及思考等级，然后发送任务。主会话确认的选择自动保存为默认，新建会话沿用上次选择（跨工作空间、重启后保留），不改变已有会话或子会话的模型；升级时默认值为空会从现存主会话恢复最近保存的选择，无需重新确认。模型不可用时须重新选择。停止直接强制终止拥有的执行，不请求总结或要求 Agent 清理确认，不承诺文件及外部副作用回滚。
5. 主 Agent 可委派子任务；点击任务卡片查看独立子会话、追问、停止、历史结果。关闭弹窗不停止任务。
6. 输入框下方与子代理设置成组的压缩图标始终打开压缩页面，在页内选择模型、开始／再次压缩或取消任务；打开页面本身不会发起模型请求。任务先等待安全点保存快照，使用所选模型在后台生成 **pi 原生摘要**，再等待新的安全点校验并自动应用；原始历史与快照后的新增消息保留，失败或冲突时不应用。

开发模式：`npm run dev`。环境变量 `AXIOM_PORT` 默认固定 4317（桌面入口使用此端口，不支持 0）；`AXIOM_DATA_DIR` 指定数据根目录，`AXIOM_PI_DIR` 可指定共享模型／认证目录，默认使用 pi 的 `getAgentDir()`（通常为 `~/.pi/agent`，遵循 `PI_CODING_AGENT_DIR`）。页面入口：`/`、`/settings.html`、`/model-config.html`、`/connect.html`。

默认数据目录：Windows `%APPDATA%/Axiom2`；macOS `~/Library/Application Support/Axiom2`；Linux `$XDG_DATA_HOME/Axiom2` 或 `~/.local/share/Axiom2`。`axiom.sqlite` 保存管理数据，`pi/` 保存应用资源／设置，模型配置与认证使用共享 pi 目录，`sessions/` 保存 pi JSONL，`run-models/` 保存主／子执行的临时模型配置快照，`compression-snapshots/` 保存运行中的临时压缩快照及固定配置；模型保存、登录与退出登录会影响终端 pi 的同一配置，请留意供应商级退出提示；旧版应用的 `pi/models.json` 与 `pi/auth.json` 不自动覆盖或合并到共享目录，可通过 `AXIOM_PI_DIR` 显式继续使用。同一数据目录只允许一个服务管理器。执行快照按数据目录隔离，启动时只清理本数据目录的残留，不扫描或清理共享 pi 目录中的运行文件。

退出服务：在客户端点击“关闭后台服务”并确认，或运行 `axiom2 stop`；前台模式也可按 Ctrl+C。退出会结束拥有的执行并保存状态；控制通道暂时失联且记录的进程仍存活时，不确认“已停止”，需等待后续状态或退出超时。PID 仅用于存活探测，不用于强杀；若旧 PID 被复用，确认停止可能延迟或超时。关闭浏览器或桌面窗口仅关闭客户端。数据目录中的 `service.log` 保存后台启动与运行日志，`installation.json` 记录本机 Node.js／CLI 路径，`service-startup.sqlite` 保存启动实例登记以协调并发启停，`service-control.json` 保存本次运行的本机控制通道凭据；启动登记和控制凭据均不要分享。配置目录不承诺磁盘加密或系统密钥库；需要备份时先停止服务，再复制整个数据目录。

## 已实现能力与边界

### 工作空间、会话与界面

- 三个独立 React 页面，沿用设计 CSS、SVG、变量与响应式布局；按职责拆分消息、输入、模型、任务和工作空间组件。
- 删除会话、删除工作空间使用统一深色应用内确认弹窗，不再弹出带本机地址的浏览器原生确认框。默认聚焦“取消”，支持 Esc 取消及焦点恢复；确认期间防止重复提交，失败保留弹窗显示原因并允许重试。系统文件／目录选择窗口不受影响。
- 新增工作空间直接打开系统文件夹选择器，选好目录后默认授权并直接打开工作空间、创建会话，不展示额外授权窗口；Windows 使用 Explorer 原生“打开”窗口，macOS 使用 NSOpenPanel，Linux 使用 GTK 3 文件选择器（需要 Python 3、PyGObject、GTK 3 及图形桌面；Debian/Ubuntu 可安装 `python3-gi gir1.2-gtk-3.0`）。所有文件／目录选择共用 `OpenFileDialog`，支持文件、目录、混合模式各自单选／多选；工作空间采用目录单选，主／子会话附件采用混合多选，服务内所有入口共用一个活动窗口。选择器不可用时明确报错，不改为上传文件或手动输入路径。支持工作空间切换、路径复制与系统文件管理器；会话创建、搜索、置顶、重命名、删除、运行／未读状态。置顶会话跨工作空间统一显示，搜索覆盖全部置顶和当前空间会话；点击置顶会话仅打开该会话，保留侧栏工作空间、普通会话列表及搜索内容，不修改最近工作空间偏好；置顶条目下方显示所属工作空间路径，过长时省略并可悬停查看完整路径。会话内容、标题栏路径及操作使用真实归属，新建会话使用侧栏工作空间；刷新分别恢复侧栏空间和打开的会话。状态点位于会话标题前。运行中（含活动子任务）或未读的会话跨工作空间自动进入“置顶”区，排在空闲的手动置顶会话前，同级按最近更新时间倒序。未查看时一直保留；查看后进入 5 分钟冷却，点击、输入和重新查看续期，前台持续查看期间不回队，最后一个查看窗口离开后才开始完整倒计时。到期自动回所属工作空间普通队列，任务继续运行；新的执行或未读结果仍按规则自动置顶。冷却状态由服务端保存，刷新／重启可恢复，多窗口查看共同保留会话。手动置顶不受冷却影响，不改变当前查看对象。双击或聚焦后按 F2 原位编辑标题，Enter／失焦保存，Escape／空白标题取消，输入法组合输入期间 Enter 不提交；不使用省略号管理入口或重命名弹窗。删除按钮直接位于置顶旁，点击或按 Delete 均需确认，删除保留项目文件。
- 运行状态、阅读状态与连接状态独立：侧栏优先显示主执行、重试等待或活动子任务，未读不会盖住“运行中”。结果使用版本化确认，只有页面可见聚焦、滚到消息底部、未被遮挡且当前连接的结果已渲染时才确认；隐藏窗口、滚动旧内容、启动新执行和后台通知都不会直接清空未读。旧窗口的已读回执不能清掉后来产生的结果，旧库自动迁移。
- 工作空间菜单展开后点击外部区域自动收起，外部控件仍正常响应；菜单内部操作与删除确认弹窗不触发外部收起。工作空间列表仅提供置顶／取消置顶和删除按钮，双击名称或聚焦后按 F2 行内重命名，不显示铅笔按钮；沿用会话标题行的灰色悬停／聚焦操作样式；置顶空间优先显示，重命名不改变目录。删除需确认，仅从列表移除，保留项目文件与会话历史；活动 Agent／排队任务或后台压缩会阻止移除，须先停止。重新选择原目录即可恢复原名称、置顶和历史。最近工作空间保存于服务端，跨客户端窗口／服务重启恢复，不因其他窗口切换而干扰当前查看；已移除的空间自动回退到其他有效空间。
- 主会话自动生成短标题：首条输入先作为临时名称，主 Agent 在正常回复开头自报不超过 10 字的标题，不额外发起模型请求。有效标题保存后不再索要；漏报、无效或失败／中断／长度截断的回复不会定案，后续请求继续尝试。手动重命名始终优先，运行中的迟到标题不能覆盖，重启后仍保留；子会话不参与自动命名。标题标签只在助手回复开头识别，流式与历史展示隐藏标签，原始 pi 会话内容不改写。
- 会话行的置顶／删除按钮平时隐藏且不可指针点击，悬停行时显示灰色图标，悬停具体按钮时提亮；键盘聚焦操作按钮时也显示并保留可见焦点。操作区不预留宽度，标题平时使用全部可用空间，仅在操作区显示时收窄并省略长文本，不改变行布局。
- 回复批注入口位于输入框下方、子代理图标左侧，采用 Lucide Message Square Text 图标。点击开启后，可在已结束的助手正文中拖选几个字精确批注；直接点击按句子、单个列表项、表格单元格或代码行引用，局部文字高亮、附近浮层输入，支持编号定位、编辑、删除和统一发送；跨段落／回复的选区提示缩小范围，不替换引用。切换批注模式保留已加载图片和代码状态，输入批注不重新解析会话正文；关闭时收起批注界面，待发送数量仍显示在图标旁。发送附带对应回复与引用原文，运行中进入 Steering，不覆盖输入框草稿；失败自动合并恢复到输入框，不覆盖后续输入或重发；仅重编号实际绑定的附件，引用原文中的字面编号保持不变。合并后超过 12,000 字时保留全文、显示字数并阻止提交，缩短后恢复发送。批注在当前页面按工作空间／会话隔离，切换会话保留，刷新或关闭页面不承诺恢复。单条引用／意见上限为 6,000／2,000 字，整批最多 12,000 字，超限提示调整后再发送。
- 独立作用域订阅；流式更新不重建输入框或模型菜单。中文输入法、选区、父子窗口草稿独立。
- 主／子会话运行中按 Enter 追加到 Steering 队列，在 pi 安全边界送达；Shift+Enter 换行，中文组合输入不发送。输入框上方显示待执行消息，不增加发送追问、撤回或模式按钮，原停止按钮仍用于停止。在输入框内 500ms 内连按两次 Esc，将服务端确认尚未消费的排队输入撤回编辑；不会停止执行、撤回已执行消息或回滚文件。撤回内容与当前输入合并，保留附件并重编号冲突引用；补全窗口优先用 Esc 关闭，长按 Esc 不触发撤回。
- 未发送会话文本及所选附件仅保留在前端内存，切换会话保留，父／子窗口与不同标签页独立；刷新或关闭页面不承诺恢复。不维护服务端会话草稿，不提供草稿恢复或会话请求人工核实入口。已上传附件文件的保留不等于输入可恢复；模型配置草稿仍按自身规则处理。

### 模型配置与认证

- 可选模型复用 pi 配置与认证；只保存供应商而未单列模型时使用该供应商的原生目录，只有 pi 判定可用的模型才显示。模型收藏持久化；删除模型会清理收藏，临时认证失效不清除收藏。子代理默认模型与思考等级为全局偏好，已有子会话保持独立选择。
- 配置草稿／临时密钥只在页面内存；模型编辑使用两列字段及全宽思考等级多选。「完成编辑」仅暂存，切换供应商保留有效编辑；顶部保存包含未收起或隐藏在连接页签后的编辑，无效 ID 返回模型表单、不丢输入。统一校验修订、字段与 pi 能力，写临时文件并原子替换 `models.json`。`none` 映射 `off`，多选能力映射 `thinkingLevelMap`，数值请求体覆盖映射 `samplingParams`；不支持的字段／协议拒绝保存。
- API Key 与 OAuth 通过 pi 原生认证接口，凭据写入当前共享 pi 目录的 `auth.json`，不写入 `models.json`。连接配置显示两个文件的实际路径；顶部显示保存结果，密钥字段显示已保存状态和占位掩码，明文输入仅在成功保存并重读后清空。API Key 保存后由新运行时重新读取本地凭据再确认成功。授权链接／设备码／输入提示只发送给发起连接；取消、断线、超时不自动重启认证。真实 OAuth 流程仍待验收。
- 已保存密钥、请求头值和敏感 URL 不回传；空密钥保留旧认证，清除认证／删除模型使用供应商级退出登录并说明影响，清除受管理的备用认证来源。环境变量不改写，仍可认证时如实显示。
- 新增 `!` 命令型密钥／请求头须明确授权；单独登录不接受命令型密钥。已存在的未展示字段保留在服务端。供应商级数值覆盖落实到当前模型，重读显示为模型项。
- 编辑入口要求普通 JSON；注释／BOM、损坏文件、重复 ID 拒绝覆盖。配置上限 1 MB，单命令 200 KB。配置和凭据不是跨文件事务；部分失败须重新读取核实，不假称全部回滚。
- 撤销认证前确认影响并终止受影响的活动执行、取消排队子任务及后台压缩，不增加 Agent 清理确认步骤。当前执行使用固定配置快照；模型选择和配置变更作用于后续执行。

### 主／子 Agent 与恢复

- 主／子会话是 pi 的薄封装：冷启动时创建独立 Node.js 工作进程，已有上下文只从绑定 JSONL 恢复；同一会话不并行启动多个执行。成功结束后复用该进程与 AgentSession，空闲保活池按 LRU 最多保留 10 个、15 分钟未使用后释放，不淘汰正在执行的进程；从初始化起超过 15 分钟的进程在空闲时释放，避免连续复用使未跟踪资源无限陈旧。模型选择、模型配置、认证、设置、项目指令／扩展／技能／提示文件或会话文件变化时拒绝复用并重新初始化；缓存进程的固定配置快照缺失、不可读或改变时，同样先释放旧进程，再按绑定 JSONL 和本轮新快照启动。外部资源包和符号链接目标不保证即时刷新，受上述最长复用期限约束。空闲淘汰先请求正常关闭，最多等待两秒后强杀；等待旧进程退出的启动同样属于可取消执行，停止会使其失效并等待退出。停止、撤销认证和服务退出释放对应进程。主 Agent 在 Windows 未指定工具时使用 pi PowerShell；其项目本地扩展、技能和设置等资源默认授权，首次发送初始化时即按 pi 规则加载，不再单独确认项目资源授权。子 Agent 使用下述固定只读能力，不加载外部扩展或提示模板，不解析配置的资源包。上下文、工具、重试、压缩均由 pi 管理。
- 自动重试由 pi 负责，同一过程保持一个 runId；会话环境展示实际设置，侧栏展示运行阶段和重试次数。继承全局／项目设置，原生默认最多重试 3 次、基础等待 2 秒、会话等待上限 60 秒，供应商层默认 0 次；停止退避不会再启动请求。重试与压缩内部事件不单独标记任务完成，最终结算等待原生空闲与工作进程交接。
- 未恢复的输出长度截断显示“输出截断，可继续处理”，执行与消息均记失败；异常中断和用户停止分开处理。失败、停止、中断后可点击输入区“继续处理”，发送一条明确的新用户指令并创建新执行，保留当前草稿。服务端校验原 runId 及活动工作，旧恢复点击不会注入新的运行；子任务继续沿用新追问／新结果语义。回执不确定只查询，不自动再次发送。
- 重试使用 pi 持久化上下文投影，原生排除的失败尝试在实时及重载视图中一致隐藏，原始 JSONL 保留；已有工具结果不删除或自动重放。重试说明不加入提示词，保持公共前缀稳定；关闭额外缓存预热请求。回环验证只证明请求前缀一致，真实缓存命中须看供应商用量。当前未提供无新增用户消息的手动重试，需 SDK 正式 Session 级能力。
- 「会话环境」展示实际资源加载情况，以及当前／最近一次加载的真实 pi「系统提示词」文本，不用资源清单或应用模板代替。新会话首次发送初始化前显示未初始化占位，不预先生成提示词；历史环境快照缺少系统提示词字段时，提示下次执行加载。
- 四个独立工具：`delegate`、`append`、`cancel_task`、`read_result`。界面在执行过程内部统一使用专用卡片，不重复生成普通工具行：委派从创建开始展示子代理协作卡，错误直接显示在卡片内；读取、补充／追问、停止使用紧凑操作卡，默认展示任务描述和操作状态，展开查看本次交付或操作详情。读取绑定原调用的不可变结果；追加受理、停止受理与实际结束分别标记，失败／停止／未知反馈保留。子任务完成通知收入过程卡片，其他通用系统通知独立展示。子代理只做调研、分析和审查，返回证据、文件位置、修改建议和未验证项；所有实际修改及命令验证由主 Agent 完成。子代理不递归委派，只收到明确背景与任务，不复制父代理全部对话。
- 子代理由执行层固定为 pi 内置 `read`、`grep`、`find`、`ls` 白名单，禁止 `edit`、`write`、`bash`、`powershell` 及其他工具，并在工具调用时再次检查；不加载用户／项目／资源包扩展（包括同名工具覆盖），不安装配置的资源包。职责补充、项目默认工具配置、直接追问与恢复历史子会话均不能提升权限。主 Agent 权限保持不变；同项目文件仍共享，应用调研建议前主 Agent 应重新核对当前文件。
- 所有子代理设置集中在输入框下方的分支节点图标内：默认模型、思考等级、并发数与工作时限。删除旧默认子模型块和配置页预算块；批注、分支与压缩图标依次成组，同排时靠最右侧，换行后靠左。模型选择即时保存，数值按 Enter／失焦自动保存；全局服务端持久化、跨工作空间／会话／窗口实时同步，刷新与重启保留。默认模型立即用于新委派，不强换正在执行请求的模型或覆盖已有子会话选择。
- 持久化 FIFO 队列，配置仅包含 `concurrency`（默认 4，范围 1–16）和 `workMs`（默认 600000 毫秒，范围 1000–86400000 毫秒），没有收尾、停止总结或清理预算。工作时限修改立即应用于排队及运行中任务，按原启动时间重算截止，已超时则停止；运行中追问不延长，新执行读取最新时限。并发设置立即作用于现有队列，降低上限不强停正在执行的任务。一次委派最多 8 个，每个主会话最多 32 个活动／排队任务，每个子会话最多 32 条未交付输入。
- `append` 保留 `steer`／`followUp`，默认 `steer`；运行中追加使用 pi 安全边界，结束后追问复用有效保活进程，或打开同一子会话 JSONL，并创建新执行和不可变结果。`cancel_task` 仅接受 `taskId`、可选 `reason`；停止和工作预算到期直接强制终止拥有的执行，不再发起总结，不要求清理确认。Run 不含 `cleanup`。停止结果基于已有记录，包含已知产出、未完成／未验证项及副作用，未知项不伪造。
- 完成通知内部只带结果标识，父代理显式读取；前端转为带线性图标的简短状态条，区分完成／取消／失败／中断，不展示内部 JSON。思考内容使用过程卡片内无左侧竖线的独立折叠块、斜体正文；生成中显示三点依次跳动的 `thinking...`，完成后显示 `thought` 并移除三点，尊重减少动态效果。纯思考、工具、子任务操作及完成通知按原顺序收入同一过程卡片，思考和通知不计入工具数量；用户消息、普通正文和错误仍形成边界。独立正文所附思考也收入该消息内的过程卡片。已有过程块及内部思考的手动展开状态在流式更新与子任务调用加入时保留（`tests/thread-layout.test.ts`、`tests/thinking-layout.check.ts` 覆盖）。主／子会话消息列表末尾、输入框左上方不显示独立运行状态行。Steering 发送后保留在输入框上方待执行区，实际消费后才进入会话气泡；
- 父会话停止先冻结自动唤醒，再终止父会话和所属活动子任务、取消所属排队任务；子任务停止只作用于自身。窗口重开、服务重启或子会话新追问不解除父会话冻结，明确的新主会话消息才恢复自动处理。
- 绑定的 pi JSONL 是唯一上下文恢复来源；SQLite 保存关系、结果和带归属的管理回执，不保存会话草稿或另一份上下文。重连只读取消息和运行状态；待确认输入按原请求 ID 自动读取既有回执及原始分支中的消费身份，不恢复已隐藏的正文、不重放请求，也不要求人工执行恢复流程。撤回回执丢失时只查询原回执，确认成功后合并恢复草稿且仅恢复一次；无法取得可靠证据时保留未确认状态。待确认输入是独立的内存用户数据，不随展示 LRU 丢弃；刷新不承诺恢复。重启不重发提示、重新委派或重做文件修改。迟到回执不清空新的内存输入。缺失／损坏的会话文件保留原件并报错，不用空会话冒充恢复。
- 真实 Token、缓存、pi 上下文估算、耗时按会话展示；上下文圆环与百分比使用同一占比并限制在 0–100%，未知容量显示虚线与“—”。无已知价格时费用为“—”。不伪造结果、用量或成功。

**安全边界：**工作进程与上下文隔离不是文件系统／命令沙箱。工作空间访问在选择目录打开时默认授权；主 Agent 的项目本地扩展、技能和设置等资源默认授权并按 pi 规则加载，不提供额外授权门禁；子 Agent 按上述只读白名单和资源限制执行。只读限制针对模型可调用能力，不是操作系统沙箱，也不表示会话记录、应用元数据或已授权的命令型认证零写入。新增命令型密钥／请求头仍须明确授权。获准工具或项目程序可以修改当前用户有权限的文件、执行命令、安装依赖。强制终止／崩溃不证明所有外部副作用结束，也不回滚文件；必要时由用户检查残留程序及外部状态，但不设置 Agent 清理确认门禁，不能按重启前的旧 PID 自动杀进程。

### 后台压缩与安全点应用

- 主／子会话分别管理任务与详情。图标始终打开压缩页面，即使尚无任务或任务已完成／取消也可查看。页内提供开始／再次压缩及运行中的取消按钮；无消息、未选择模型、断线或操作待核实时说明限制，不因历史终态锁死入口。关闭／Escape 只退出查看，不取消后台任务。刚完成且没有新增消息时，按 pi 原生限制提示暂无可再次压缩的内容，不重复请求模型。
- 压缩模型复用统一 `ModelPicker`（供应商、模型、思考等级与收藏），选择作为独立全局偏好保存到服务端；主／子会话、不同窗口共享，刷新和服务重启后保留，不改变聊天模型。尚未保存时默认当前会话模型；已保存模型不可用时明确报错，不静默替换。运行中修改仅影响下一次压缩。
- 压缩页可配置自动压缩开关、Token 阈值和上下文百分比；默认开启，100,000 Token／80%。实际触发值取 `min(Token 阈值, 当前会话模型容量 × 百分比)`，达到即启动后台压缩；主／子会话独立判断，容量未知时使用 Token 阈值，占用未知时不触发。配置按 Enter／失焦自动保存，全局共享并跨重启保留，页面展示当前生效阈值。保存配置后在执行启动或后续成功回合的用量检查时生效，开关关闭不取消已经开始的任务。自动任务使用已选择的压缩模型，详情标记“自动触发”；持续超阈值时不会反复压缩，同一执行中失败／取消不自动重试。Axiom 接管主动阈值压缩，保留按 pi 设置启用的原生溢出恢复。
- 每次触发都创建独立的新压缩任务，仅依据当前会话分支取快照；此前任务的失败、取消、中断不影响新任务，旧任务回执不作用于新任务。运行中的会话以 pi `turn_end`／`agent_before_settle` 为安全边界，空闲会话先等待保活进程及关闭钩子释放所有权再取快照。历史失败、已中止请求及进程中断留下的未配对工具记录属于可摘要历史，不用于判断当前是否正在执行；当前执行中的工具仍须等待安全边界，不在流式中间状态截取。
- 会话运行中先等待 pi `turn_end`／`agent_before_settle` 安全边界保存当前分支快照；空闲时在所有权释放后保存。独立 pi 工作进程只对快照调用原生 `compact(customInstructions)`，附加要求在完整摘要前生成 `<axiom-summary>` 短主题，不另发模型请求；缺少短主题的历史或原生自动压缩摘要显示“上下文已压缩”。不打断当前请求、不成为原会话的第二个写入者。摘要就绪后，运行中的原会话在新的安全边界校验并追加原生 compaction；空闲会话先释放保活进程，再同步校验并追加，后续发送从新上下文初始化。原始 JSONL 历史和快照后新增消息保留，不用快照覆盖原文件；分支、快照前缀或压缩边界发生冲突时拒绝应用。会话在等待期间结束时，任务交接到空闲会话或新执行继续处理，不因进程结束报失败，也不重新生成已有摘要；等待保活进程退出后重新检查所有权。真实快照／应用错误保留脱敏原因，不猜测会话已停止。
- 阶段依次为等待安全点快照（`snapshot`）、后台原生摘要（`summarizing`）、等待新的安全点应用（`applying`）和已应用（`done`）。`completed` 表示已应用，而非仅生成摘要；应用前不会因摘要就绪更新会话占用。详情的压缩后数值是快照估算，不含新增消息。会话当前占用优先使用 pi 原生统计；压缩后尚无新模型用量时，使用 pi `estimateTokens()` 对已应用的当前上下文投影（摘要、保留消息及新增消息）估算，显示 `≈` 与估算说明，下一次有效模型用量到达后恢复原生统计。旧会话已保存的未知占用也从绑定 JSONL 只读补算，不额外请求模型。
- 使用已确认且可用的模型，不自动替代；压缩进程不加载项目扩展、技能、上下文文件或编码工具。每会话最多 1 项、全局最多 4 项，不设置压缩等待或执行时限，取消后等待最多两秒再尝试强制结束工作进程。授权的命令型认证仍属于可执行配置，不是操作系统沙箱。
- 详情展示真实阶段、摘要和 pi 的前后估算；当前步骤显示旋转圆环与高亮，完成步骤显示勾选，失败标记保留在对应步骤，终态停止动画；减少动态效果时使用静态高亮。失败／中断原因独立展示，异常消息经常见凭据模式脱敏和长度限制后保存，刷新仍可查看；缺少原因时明确提示未知，不伪造诊断。摘要展示超过 64,000 字符会明确标记截断，不以截断文本替代原生应用结果。摘要请求的可得用量／费用在应用后计入所属 pi 会话统计，详情仅为该次明细，不与会话统计再次相加。失败、取消、中断或冲突不应用摘要，也不伪装成成功。
- 任务／回执持久化并校验会话归属；完成终态须在压缩工作进程退出且安全点应用成功后发布。重连仅核实、不重发。服务重启时，若原会话已持久化带有该任务 `details.axiomCompressionId` 的原生 compaction，则将任务恢复为已应用（`completed`），覆盖追加成功但确认回执前崩溃的情况；否则将未结束任务标为中断（`interrupted`），不重放应用或自动重新压缩。父会话整体停止同时取消所属压缩；撤销供应商认证须先确认停止受影响任务。临时快照退出后清理，异常残留在下次启动清理。

## 桌面交付

Windows x64 与 macOS 通用版产物通过 [GitHub Releases](https://github.com/cosyeezz/axiom2/releases/latest) 下载；本地构建输出位于：

- `app/Axiom2.msi`：Windows 安装包。
- `app/Axiom2.exe`：Windows 独立可执行文件。
- `app/Axiom2.dmg`：macOS 通用安装镜像，包含 arm64 与 x86_64。

桌面壳包含本地服务控制页及原生启动／停止桥接，不包含 Node.js、pi 或后端。控制页随客户端打包，从本地加载，不会在服务未启动时跳转到连接错误页。工作台在服务就绪后单独打开，沿用原有 Web 产品及 Host／Origin／禁止 iframe 的安全限制；远程工作台不能调用原生服务控制命令。OAuth 提供可复制的授权链接，由系统浏览器完成 pi 授权。Windows 需要 WebView2 Runtime，Windows 客户端未经代码签名；macOS 客户端使用 ad-hoc 签名，未经过 Apple Developer ID 签名或公证。

重新构建需要 Node.js、Rust/Cargo 与目标平台原生构建工具（Windows MSVC、WebView2；macOS Xcode；Linux WebKitGTK 等）；脚本自动在隔离目录安装固定版本 Pake **3.16.2**：

```sh
cd app
npm run package:desktop
```

macOS 通用版需在 Mac 上、从仓库根目录执行：

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
npm --prefix app run package:desktop -- --targets universal
```

也可在 GitHub Actions 的 `Build Axiom2 Desktop` 中选择 `platform=macos`；`source_ref` 可填写发布 tag 或 commit，为空时使用工作流所在版本。macOS 流程校验 DMG、双架构、版本与应用标识、签名完整性及无测试入口，再从镜像复制应用到临时目录，用隔离数据目录启动并检查该进程拥有可见窗口。只有检查通过才生成交付 artifact；失败时保留的诊断 artifact 不作为发布包。`Publish Axiom2 macOS Desktop` 可将成功构建的 artifact 直接发布到已有 Release：需填写构建 run ID 与对应 tag，发布前复核源码、原生检查和附件摘要，保留其他产物并补全校验文件。

配置在 `app/desktop/pake.json`。`package:desktop` 使用 `scripts/build-desktop.mjs` 将固定版本的 Pake 模板复制到隔离目录，注入 `app/desktop/axiom_service.rs` 后构建，桌面版本统一从根 `package.json` 传入，不修改全局 Pake 源文件；直接运行原版 `pake --config` 不包含服务控制桥接。产物／日志不提交 Git。`npm run check:desktop` 使用 Windows EXE、WebView2 和隔离数据目录，通过本机 CDP 与原生窗口关闭请求检查离线控制页、启动／状态／工作台、停止确认与取消、重启、两个窗口的关闭顺序、客户端重新打开、服务换端口后的工作台重建及正常／强制退出客户端后服务存活。先在仓库根目录运行 `npm --prefix app run package:desktop -- --targets x64 --test-instance` 构建独立标识的 `Axiom2-ServiceTest.exe`；仅此测试构建带 CDP 接入，正式产物不带调试入口，测试不会接管已运行的正式客户端。可用 `AXIOM_DESKTOP_BINARY` 指定测试 EXE。该检查不覆盖 MSI 安装交互、真实 OAuth 或 macOS/Linux 原生运行。

`npm run check:desktop-update`（在 `app/` 执行）使用当前构建脚本生成的测试 EXE 验证应用内更新；设置 `AXIOM_UPDATE_OLD_TARBALL` 指向已发布 v0.2.3 包、`AXIOM_UPDATE_TARBALL` 指向本次构建包。测试隔离安装目录、数据、pi 配置、npm 缓存及端口，仅测试构建允许本地发布源，并将原生安装器启动替换为程序路径与参数记录；假 MSI 用于验证篡改后零次启动、有效文件仅传入固定系统 `msiexec.exe` 及 `/i`、已校验路径，不执行真实安装。清理需确认最近请求的更新任务已终止、所属 worker 和后台进程已退出；读取失败、状态未知、旧任务记录或超时均保留目录并报告，不与更新并发删除夹具。生产客户端的更新来源固定为本仓库 GitHub Release，附件按发布 API 的 SHA-256 和大小校验。更新日志与恢复记录位于数据目录的 `updates/`；旧程序备份和准备目录保留在原包旁。恢复保证限于更新进程异常退出，不保证系统崩溃或掉电后的自动恢复；程序恢复不回滚会话数据或数据库迁移。恢复时使用已验证旧备份中的控制代码确认服务退出，再移动目录；即使候选程序能显示版本却无法加载控制模块，也不依赖候选程序执行恢复控制。恢复时核对旧程序及服务报告的运行版本；旧后台协议不报告版本时，只确认旧程序和服务运行状态。

## 代码与设计维护

- `ui/`：用户原始设计，只读；根目录 ZIP 保持原样，不自动重打包。
- `app/src/client/{pages,chat,models,tasks,workspaces}`：页面组合与各自状态／交互；直接导入，无总文件承载全部界面。
- `app/src/server/agents.ts` 与 `agents/`：命令／模型归属、工作进程生命周期、消息视图独立。
- `app/src/server/compressions.ts` 与 `compression-worker.ts`：快照任务持久化／取消、原生 pi 摘要与安全点应用分开；客户端 `chat/Compression.tsx` 和 `CompressionDetail.tsx` 分管交互与详情。
- `app/src/server/tasks/`：记录、命令、调度与预算、结果交付分别管理；通过现有 Agent 运行核心执行。
- `app/src/server/model-service.ts`、`models/draft.ts`、`auth.ts`：配置发布、字段映射校验与原生认证。
- `app/src/server/storage.ts`：保存应用管理数据。
- `app/src/shared/`：实际共享协议；`app/tests/`：检查；`app/desktop/`：本地服务控制页入口、原生桥接及打包配置。
- `app/` 根目录原有 HTML／图片／检查脚本是保留的原型副本，不是产品入口。

设计更新先独立提交，再按 `docs/ui-sync.md` 的设计提交差异移植至 `app/`，不整目录覆盖已接入功能。采用提交在完整设计验收前不提前提升。源码发布到 `https://github.com/cosyeezz/axiom2`，安装包与桌面二进制通过 Releases 分发，不提交到 Git。

根目录 `package.json` 是分发入口，依赖版本与 `app/package.json` 保持一致；pi 同系列的七个运行包均显式固定为 `1.1.0`，避免子依赖范围升级造成导出接口不兼容；`npm-shrinkwrap.json` 记录并随包携带构建使用的完整依赖树；`npm ci` 自动构建，`npm run check:package` 校验依赖一致性，并在隔离全局目录安装实际 tarball、启动服务、访问页面与脚本资源、检查跨站请求被拒绝，并验证前台／后台启动、相对数据目录、重复启动、正常停止、控制通道认证及不会停止无关监听进程，并分别在 npm 默认提升布局和用户配置嵌套布局时执行真实预备安装、版本切换与启动验证，核对依赖路径、工作进程模块加载及无失效的内部自身命令 shim。更新器固定使用 `--install-strategy=shallow`，将候选包及其完整依赖树一起切换，保留外部全局命令路径。包检查另用真实旧备份恢复控制模块损坏的候选程序，验证恢复后的运行版本、HTTP 与停止。`npm pack --ignore-scripts` 打包已经构建的产物；Release 将 tarball 命名为 `axiom2.tgz`，同一版本的服务与客户端文件共同生成 `SHA256SUMS`。安装脚本只消费 Release，不在用户机器编译前端。GitHub Actions 提供三平台构建／测试以及手动触发 Windows／macOS Pake 构建；测试环境显式安装文件补全所需的 fd，涉及原生路径／会话的夹具使用真实临时目录，兼容 macOS `/var` 别名与 Windows 短路径。CI 构建不替代原生交互验收。
