# Axiom2

基于 pi 的本地多工作空间编码 Agent 工作台。已实现主／子 Agent、模型配置与认证桥接、持久化恢复、项目预览及元素评论修改闭环，并提供 Windows 桌面构建产物。**当前为第一阶段候选交付，不宣称全部验收通过**：真实供应商／OAuth、完整视觉对照、原生桌面交互和 macOS/Linux 实机验收尚未完成。

实施依据：[产品设计](docs/design.md)；设计采用状态：[UI 设计同步](docs/ui-sync.md)。文档只描述当前内容，变更轨迹由 Git 保存。

## 启动与使用

需要 **Node.js 24+**、npm；当前实测 Windows x64、Node.js 24.19.0、npm 11.17.0。

```sh
cd app
npm ci
npm run build
npm start
```

1. 打开终端显示的 `http://127.0.0.1:4317/#access=…` **完整链接**。片段令牌交换为 HttpOnly / SameSite cookie 后从地址栏移除，不要分享链接。服务重启后使用新链接。
2. 打开文件夹，填写已有项目的绝对路径并确认授权。会话切换不停止后台工作。
3. 在「配置 → 模型服务」添加供应商和模型，完成行内编辑后使用**顶部保存**。填写 API Key 或使用 pi 支持的认证入口；配置有效不等于远端认证有效。
4. 回到会话确认模型及思考等级，然后发送任务。停止不回滚文件；强制退出或崩溃后须检查残留进程再确认清理。
5. 主 Agent 可委派子任务；点击任务卡片查看独立子会话、追问、停止、历史结果及待核实输入。关闭弹窗不停止任务。
6. 「预览与评论」打开已授权项目的静态目录或显式启动命令；点选元素、输入备注、发送，再显式刷新检查实际修改。

开发模式：`npm run dev`。环境变量 `AXIOM_PORT` 默认 4317，0 为动态端口；`AXIOM_DATA_DIR` 指定数据根目录。页面入口：`/`、`/settings.html`、`/model-config.html`、`/connect.html`。

默认数据目录：Windows `%APPDATA%/Axiom2`；macOS `~/Library/Application Support/Axiom2`；Linux `$XDG_DATA_HOME/Axiom2` 或 `~/.local/share/Axiom2`。`axiom.sqlite` 保存管理数据，`pi/` 保存应用独立配置／认证／资源，`sessions/` 保存 pi JSONL；不修改终端 pi 的默认配置。同一数据目录只允许一个服务管理器。

退出服务：终端按 Ctrl+C，等待任务与预览清理完成。关闭浏览器或桌面窗口仅关闭客户端。配置目录不承诺磁盘加密或系统密钥库；需要备份时先停止服务，再复制整个数据目录。

## 已实现能力与边界

### 工作空间、会话与界面

- 三个独立 React 页面，沿用设计 CSS、SVG、变量与响应式布局；按职责拆分消息、输入、模型、任务、工作空间和预览组件。
- 工作空间路径确认、切换、路径复制与系统文件管理器；会话创建、搜索、置顶、重命名、删除、运行／未读状态。触屏管理按钮、F2／双击重命名、Delete 确认删除均可用。删除保留项目文件。
- 独立作用域订阅；流式更新不重建输入框或模型菜单。中文输入法、选区、父子窗口草稿独立。
- sessionStorage 恢复同标签页草稿；SQLite 保存每个查看实例的副本，「恢复服务端草稿」明确选择后才替换当前输入，不自动发送。
- 安全 Markdown、代码高亮／复制、分页历史、工具输入／输出与长内容展开；原始 HTML 不执行，危险链接不生成链接，外部图片不自动加载。未知／超长代码块使用纯文本。

### 模型配置与认证

- 可选模型是**明确配置与 pi 可用模型的交集**，不自动加入内置模型。模型收藏持久化；删除模型会清理收藏，临时认证失效不清除收藏。主会话可设置默认子模型，已有子会话独立选择。
- 配置草稿／临时密钥只在页面内存；「完成编辑」不发布，顶部保存统一校验修订、字段与 pi 能力，写临时文件并原子替换 `models.json`。`none` 映射 `off`，多选能力映射 `thinkingLevelMap`，数值请求体覆盖映射 `samplingParams`；不支持的字段／协议拒绝保存。
- API Key 与 OAuth 通过 pi 原生认证接口。授权链接／设备码／输入提示只发送给发起连接；取消、断线、超时不自动重启认证。真实 OAuth 流程仍待验收。
- 已保存密钥、请求头值和敏感 URL 不回传；空密钥保留旧认证，清除认证／删除模型使用供应商级退出登录并说明影响，清除受管理的备用认证来源。环境变量不改写，仍可认证时如实显示。
- 新增 `!` 命令型密钥／请求头须明确授权；单独登录不接受命令型密钥。已存在的未展示字段保留在服务端。供应商级数值覆盖落实到当前模型，重读显示为模型项。
- 编辑入口要求普通 JSON；注释／BOM、损坏文件、重复 ID 拒绝覆盖。配置上限 1 MB，单命令 200 KB。配置和凭据不是跨文件事务；部分失败须重新读取核实，不假称全部回滚。
- 撤销认证前确认并停止受影响的活动执行及排队子任务，清理未确认时阻止撤销。当前执行使用固定配置快照；模型选择和配置变更作用于后续执行。

### 主／子 Agent 与恢复

- 每次执行在独立 Node.js 进程创建 pi 会话，明确工作目录、会话文件与模型。Windows 未指定工具时使用 pi PowerShell；实际资源加载情况可查看。上下文、工具、重试、压缩均由 pi 管理。
- 四个独立工具：`delegate`、`append`、`cancel_task`、`read_result`。子代理不递归委派，只收到明确背景与任务，不复制父代理全部对话；同项目共享文件，必须分配不重叠的修改范围。
- 持久化 FIFO 队列，默认并发 4；默认工作 600 秒、收尾 180 秒、停止总结 60 秒、清理等待 10 秒。配置页可调整；预算创建时固定，运行中追问不延长。一次委派最多 8 个，每个主会话最多 32 个活动／排队任务，每个子会话最多 32 条未交付输入。
- 运行中追加使用 pi 安全边界；结束后追问恢复同一子会话并创建新执行和不可变结果。停止总结先终止工作，再禁工具且限时；立即停止不再发起总结。结果包含产出、未完成／未验证项、已知工具事实与清理状态。
- 完成通知只带结果标识，父代理显式读取；父会话停止先冻结自动唤醒，再停止父／子任务。重复受理、窗口重开和服务重启不解除冻结；明确的新工作与自动重放不同。
- JSONL 保存上下文，SQLite 保存关系、结果和带归属的回执；查询不能用其他会话冒领，升级前缺少归属的旧回执只返回待核实状态、不泄露结果。重启不重发提示、重新委派、重做文件修改或自动重启预览。未消费输入保留，受理不明时核实回执；迟到回执不清空新草稿。缺失／损坏的会话文件保留原件，不用空会话冒充恢复。
- 真实 Token、缓存、pi 上下文估算、耗时按会话展示；无已知价格时费用为“—”。不伪造结果、用量或成功。

**安全边界：**工作进程与上下文隔离不是文件系统／命令沙箱。项目目录授权不等于项目本地扩展、技能和设置的执行授权，后者须单独确认。获准工具或项目程序可以修改当前用户有权限的文件、执行命令、安装依赖。强制终止／崩溃不证明所有外部副作用结束；检查后明确确认清理，不能按重启前的旧 PID 自动杀进程。

### 预览与元素评论

- 静态目录必须位于工作空间内，解析符号链接，拒绝隐藏／选定敏感文件和目录列表；最多 4 个活动预览。
- 项目服务模式接收程序、JSON 参数数组、目录和 1024–65535 的空闲端口，`shell:false` 启动并设置 `PORT`。例如程序 `node`，参数 `["node_modules/vite/bin/vite.js","--host","127.0.0.1","--port","5173","--strictPort"]`，端口 `5173`。依赖须提前安装；不自动猜测或安装项目运行环境。
- 每个预览使用随机 `p-<随机值>.localhost` 能力主机名与独立端口，避免应用 `127.0.0.1` cookie 进入预览；校验 Host／Origin，iframe 不获得应用令牌。能力 URL 不应分享；部分浏览器／系统对 `.localhost` 的支持需实机确认。
- 只代理本实例启动的固定回环上游，GET／HEAD，响应上限 10 MB、上游等待 5 秒；不转发 Cookie／Authorization，不代理外部地址、重定向、写请求或 WebSocket/HMR。**修改后使用显式刷新**。上游 CSP 仍有效，不绕过禁止注入的页面。
- 标注校验父窗口、来源、预览绑定与修订，阻止选中点击触发页面操作。过滤表单值、隐藏内容和脚本，仅保留受限定位资料；备注最多 2000 字符、文本摘要 1000、DOM 片段 4000。坐标不是源码位置，没有通用源码映射或截图编辑器。
- 评论通过绑定会话的实际 pi 工具搜索／修改文件；页面资料作为不可信引用。待核实评论不自动重发，刷新后的旧目标必须重新点选，备注保留。
- 项目服务退出／停止后仍保留清理待核实记录，检查记录中的进程及其子进程后才能确认、新开服务预览或删除会话。静态预览不启动项目进程。关闭预览窗口不停止预览；「停止预览」才释放实例。

## Windows 桌面交付

当前生成的 Windows x64 产物位于：

- `app/Axiom2.msi`：安装包。
- `app/Axiom2.exe`：独立可执行文件。

桌面壳是**本地连接入口**，不包含 Node.js、pi 或后端。先按上文安装／启动服务，再在桌面窗口粘贴完整启动链接；不保存令牌、不扫描端口，动态端口也使用启动链接。需要 Windows WebView2 Runtime。未经代码签名／信誉认证，系统可能提示未知发布者；仅运行自己构建或已核对来源的产物。

重新构建需要 Pake **3.16.2**、Rust/Cargo 与目标平台原生构建工具（Windows MSVC、WebView2；macOS Xcode；Linux WebKitGTK 等）：

```sh
npm install -g pake-cli@3.16.2
cd app
npm run package:desktop
```

配置在 `app/desktop/pake.json`；`package:desktop` 输出机器可读构建结果。已成功生成 Windows MSI 和 EXE，产物／日志不提交 Git。`npm run check:desktop` 在已连接且解锁的 Windows 桌面上启动已构建 EXE，通过原生 UI Automation 检查连接、设置导航和关闭客户端后服务存活；可用 `AXIOM_DESKTOP_BINARY` 指定 EXE。本次运行环境为断开的 Windows 会话，原生交互验收未通过，**安装包构建成功不等于安装／桌面功能已验收**。真实 OAuth 系统浏览器跳转及 macOS/Linux 打包／运行也未验收。

## 代码与设计维护

- `ui/`：用户原始设计，只读；根目录 ZIP 保持原样，不自动重打包。
- `app/src/client/{pages,chat,models,tasks,workspaces,preview}`：页面组合与各自状态／交互；直接导入，无总文件承载全部界面。
- `app/src/server/agents.ts` 与 `agents/`：命令／模型归属、工作进程生命周期、消息视图独立。
- `app/src/server/tasks/`：记录、命令、调度与预算、结果交付分别管理；通过现有 Agent 运行核心执行。
- `app/src/server/model-service.ts`、`models/draft.ts`、`auth.ts`：配置发布、字段映射校验与原生认证。
- `app/src/server/preview/`：生命周期、进程、隔离网关、标注与评论；`storage.ts` 保存应用管理数据。
- `app/src/shared/`：实际共享协议；`app/tests/`：检查；`app/desktop/`：桌面连接页及打包配置。
- `app/` 根目录原有 HTML／图片／检查脚本是保留的原型副本，不是产品入口。

设计更新先独立提交，再按 `docs/ui-sync.md` 的设计提交差异移植至 `app/`，不整目录覆盖已接入功能。采用提交在完整设计验收前不提前提升。当前仅使用本地 Git，不创建远端或推送。
