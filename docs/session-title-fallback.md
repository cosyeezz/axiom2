# 会话标题的 30 秒对话兜底

## 触发和资料优先级

- 原检查点保留：每累计 3 次主模型请求、每轮执行正常完成时检查。
- 增加独立定时检查：从该会话首次用户发起的 run 开始计算 30 秒，不从空会话创建时间计算；后续轮次、重试不重新等待 30 秒。
- 开始时间从持久化 runs 读取，排除带内部 origin 的通知、记忆续跑和压缩准备；后台重新启动后，下次 run 可恢复原截止时间。不会在启动时遍历所有闲置会话并补发标题请求。
- 有有效记忆时始终优先使用 `MEMORY.md` 和关联详情，沿用原有资料复核。
- 无有效记忆且已到 30 秒时，使用当前分支的首条有效用户正文和最近最多 6 条有效模型正文。正文可包含模型向用户解释进度的 commentary，也允许当时已输出的流式正文，不必等最终答复。
- 如果尚无有效模型正文（例如只有工具调用或思考），本次不调用标题模型；有效正文随后到达时可补查。正常提前结束的短会话仍保留 30 秒定时器。

## 内容边界

- 用户正文最多 4,000 字符；每条模型正文最多 2,000 字符，最多 6 条，总正文预算最多 16,000 字符（不含 JSON 包装）。
- 仅使用显示投影中的 `.text`；不序列化工具调用参数、工具结果、思考、错误字段。
- 排除 notice、任务通知、压缩消息、内部通知/记忆续跑/压缩准备来源、失败或取消的模型消息以及空白正文。
- 有说明正文的混合“文字 + 工具调用”消息只取文字；纯工具调用不算有效正文。
- 通过原生当前分支的 original 投影读取，保留压缩前的首条用户输入，同时叠加实时正文，不扫描废弃分支。
- 读取记忆失败不视为“没有记忆”，不会静默绕过读取错误使用对话材料。

## 生命周期和并发

- 定时器不占主执行流程，且 `unref`，不单独阻止后台退出。
- 标题请求仍是后台元数据作业，不向主模型上下文追加命名指令或标题结果。
- 定时、结算及正文到达共用单飞；有在途请求时合并后续检查。
- 兜底生成期间若记忆变得有效，拒绝应用旧兜底结果，并补查记忆路径。
- 沿用每 run 最多 3 次真实标题模型调用的预算及 30 秒标题请求截止；空资料检查不消耗调用预算。
- 成功后不再自动改名；手动命名继续受 pending 状态检查和落库 CAS 保护。
- 停止、相关供应商停止、删除、关闭会话标题组件及非成功结算时清理定时器、取消在途任务，并丢弃待补查请求。

## 聊天中的显示边界

- 标题生成卡片不是消息或最终交付，但它的精确消息锚点是一个可见的过程分段边界。
- 卡片出现后，其前面的执行段不再承接后续思考和工具消息；后续过程在卡片下方连续显示，不必等新的模型正文。尚无后续消息时，活动占位也位于卡片下方。
- 分段沿用消息的最后一个可见贡献（思考、正文、调用），不拆同一消息的内容快照；锚点消息自身后续的正文或调用状态更新仍属于原消息。
- 展开的压缩历史采用同一边界，并保留原来的懒读范围；关闭历史时仍把标题卡定位到对应压缩卡之后，不为定位加载原文。
- 不具备精确锚点的旧记录继续按运行轮次定位，不猜测消息内的分段时刻；未知锚点不挂到当前尾部。普通无标题边界的执行过程保持原有连续性。
