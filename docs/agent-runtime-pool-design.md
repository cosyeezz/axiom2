# 代理运行池统一方案

**状态：方案整理，尚未实施。** 本文合并已确认的 Skill、MCP、预热、会话绑定和两级回收规则；配套[池管理 UI 草案](agent-runtime-pool-ui.md)。本轮仅写文档，不修改功能、不运行真实模型/MCP、不部署。文中的建议值和实现建议不冒充用户已确认的配置或现有 SDK 能力。

## 1. 目标与决策边界

让代理创建、启动和切换尽量轻量：工作空间的重资源提前准备；会话按 ID 使用仍绑定的实例；模型知道可用能力，正文按需读取，MCP 在真正使用时由本会话直连。

### 1.1 已确认规则

| 主题 | 统一规则 |
| --- | --- |
| Skill | 全集注册到程序；按 Axiom 或其他明确声明选择注入的名称、描述、路径；正文按需读取 |
| Skill 与 MCP | 不增加两者关联表；真实工具入口已有目标服务归属，不从读 Skill 推测连接意图 |
| MCP | 工作空间共享获准元数据，Pi 会话自持连接；Axiom 管时机，Pi 管协议、发现、注册与执行 |
| 会话复用 | `sessionId → instanceId`；绑定实例尚存且绑定有效就直接使用，不逐轮扫描资源/profile/文件以证明可复用 |
| 资源准备 | 工作空间重准备允许秒级；领取、绑定和轻量注入目标为毫秒级，尚未实测验收 |
| 归还 | 会话不再占用实例，清理会话私有态后将**仍存活的实例**归还池中，不等于销毁 |
| 补热 | 会话领取实例后立即发起新备用实例的预热；重复使用已有绑定不重复补热 |
| 保活计数 | 统计全部存活实例，而非只统计空闲池；超限不强杀在用实例 |
| 两个计时器 | 会话空闲超时先归还；实例在池空闲超时且总数超限才可销毁，两条件为 AND |
| 手动归还 | 安全点停下；同时支持暂停并提供重试、重新领取后自动续跑 |
| 提示词恢复 | 不累计、恢复历史系统提示词版本；重新绑定时按当前资源程序化注入，保留必要业务历史 |

### 1.2 不做与不承诺

- 不增加 MCP 网关、第二个 MCP client、跨会话活连接共享或统一消息转发层。
- 不增加 Skill—MCP 强关联，也不把未展示 Skill 的新自动发现机制作为必需前置。
- 不把预热等同于请求模型、执行 Skill 脚本或连接所有 MCP；冷工具目录沿用获准的显式发现流程。
- 不把会话归还做成“关掉 AgentSession、只留 Node 进程，再完整冷建”而声称完成完整实例复用。
- 不将最大保活数用作最大并发或创建硬上限；不以实例总年龄代替实例池内空闲时间。
- 不承诺任意历史恢复、冷目录发现、MCP 建连、模型首响应都在毫秒内。
- 不直接删除已有历史文件，不修改安装目录中的 Pi，不以临时私有字段替换冒充可交付接入。

## 2. 对象、所有权与计数

| 对象 | 含义与生命周期 |
| --- | --- |
| 业务会话 | 稳定的会话 ID、工作空间、业务历史和任务进度；实例归还后仍存在 |
| 池实例 | 可预热、可绑定、可安全重置后归池的存活执行实例；不是业务会话记录 |
| 工作空间资源快照 | Skill 全集元数据、MCP 获准目录及其他可共享资源；不含活连接、结果和会话权限 |
| 绑定 | 业务会话与实例的一对一占用关系，附可撤销的绑定代次 |
| 一次执行 | 模型/工具运行及其预算、取消、事件归属；结束后可以保留实例绑定 |

工作空间是资源和绑定隔离边界；不同工作空间的实例不能直接换绑并沿用原 cwd/资源。切换 UI 不等于归还或搬迁实例，也不为历史列表中的每个会话创建实例。

**计数口径：**准备中已创建、池中空闲、绑定准备中、已绑定运行/空闲、归还中、刷新/清理隔离中、销毁中，均属于尚未退出的实例。只有物理退出/关闭得到确认后才减总数；排队但尚未创建的准备任务单独显示，不冒充存活实例。状态互斥，分类计数之和等于总数。

**配置作用域建议：**宿主代理池统一配置和统计，按工作空间分区准备/分配，UI 工作空间筛选只影响列表，不改变总数和淘汰阈值。本文的全部实例包含本方案代理池的全部状态；既有记忆、标题、摘要 worker 的物理额度不能悄悄重分类或改限额，适配时须明示其归属和全局占用。这是接入建议，不是声称用户另行确认了后台 worker 的迁移方案。

## 3. 重资源预热与轻量绑定

### 3.1 工作空间准备

1. 在已允许的工作空间准备阶段加载 Skill 全集、有效声明和其他资源；元数据采集可能读取 `SKILL.md` 全文，但不等于把全文发给模型。
2. 读取 MCP 配置和已获准、有效的完整工具目录。不因缺目录、TTL 或展示状态而隐式连服务；完整 schema 留在程序目录，不全量塞入提示词。
3. 预热可分配实例的资源底座；会话私有闭包、授权、记忆路径、输入队列、工具调用和连接不能从上一业务会话继承。
4. 无模型推理、无虚假对话、无 Skill 脚本执行。需要执行可信扩展初始化时，沿用现有信任与副作用边界，不能称为任意代码沙箱。

**补热调度建议：**每次真实领取后立即发起替补预热，包括无备用时按需冷建并完成绑定的领取；并发准备按工作空间合并已有准备意图，正常目标为至少一个可用/准备中的备用。没有备用时按需建实例，不假称冷路径也是毫秒。重复使用已有绑定、打开历史列表、归还、预热完成或销毁本身均不生成新的补热需求。准备失败有界且可见，不因自身失败/完成回调无限重新排队，具体退避参数留实施阶段。初次无实例时由真实工作空间准备/使用需求触发，不为全部历史会话批量预热。

### 3.2 消息直达与首次绑定

```text
业务消息 → 按 sessionId 查绑定
  ├─ 有效绑定、正在执行 → 对应实例原有输入队列
  ├─ 有效绑定、已空闲   → 同一实例启动下一轮
  ├─ 正在归还/重新绑定  → 等待当前生命周期操作结算
  └─ 无绑定/实例已退出  → 领取 → 恢复业务历史 → 注入 → 发布绑定 → 执行
```

- 绑定直达不重新选池实例，不重建资源，不逐轮做 profile/文件/JSONL 复用资格扫描。业务权限、输入合法性、工具执行准入仍保留。
- 分配事务保证同实例不绑定两个会话、同会话不并发领取两份；准备/历史恢复未完成不能发布可执行绑定。
- 恢复旧会话的必要业务上下文，新会话从空业务历史开始。唯一历史写者完成交接后才放行。
- 绑定阶段按当前声明注入系统提示词、Skill 可见目录和获准 MCP 目录/发现投影；不重复全量注册。
- 既有绑定的请求前提示词/工具投影可以轻量更新；这不等于重新扫磁盘或重载全部资源。

## 4. 状态与两级生命周期

### 4.1 实例状态

```text
准备中 → 池中空闲 → 绑定准备中 → 已绑定空闲 ⇄ 运行中
               ↑                         ↓
               └──── 归还清理中 ← 等待安全点

池中空闲 → 销毁中 → 已退出
准备/清理/刷新失败 → 隔离不可分配 → 明确恢复或故障清理
```

`已暂停`、`待重试`、`恢复中`是业务会话/恢复操作状态，不是说该会话归还后仍占有一个暂停实例。实例回池后可以分配给其他会话；原会话再试时不要求领取另一个新进程，也不能要求仍领取原实例。

### 4.2 两种空闲时间

| 配置 | 起点 | 到期行为 |
| --- | --- | --- |
| 会话空闲回收时间 | 绑定会话真正没有执行、输入交付、待处理任务/生命周期工作时 | 申请安全归还，保留业务会话与历史 |
| 实例空闲回收时间 | 实例准备完毕/归还清理完成，进入可分配空闲池时 | 只成为销毁候选；仍须总数超过最大保活数 |

模型在等响应、工具在执行、等待权限/取消结算、正在压缩或重载，不算会话空闲。用户追加输入使会话空闲计时失效；定时器到期与新输入竞争时，使用同一绑定事务决定先后，不能一边执行一边归还。实例重新被领取立即退出空闲候选；重新回池时重新计时，不用创建时间或 UI 打开时间替代。

### 4.3 归还不是销毁

手动归还或会话空闲到期均经过：关闭旧绑定的新执行准入 → 必要时等安全点 → 结算执行/输入/历史写入 → 失效旧绑定代次 → 清除会话私有态 → 确认可安全分配 → 回池。

清理覆盖工具执行、权限/预算闭包、输入与通知、取消源、事件订阅、历史写者、凭据引用及 MCP 连接/调用上下文。MCP 连接即使来自同一服务也不能跨业务会话保留；沿用 Pi 原生关闭协议并等待可归属的收尾证据。保留的是可安全共享的资源准备，不是上一会话的运行态。无法确认清理成功时隔离实例，不能为了凑空闲数放回池。

### 4.4 实例销毁条件

设最大保活数为 `M`，全部尚存活实例数为 `N`，实例在池中的连续空闲时长为 `idleFor`：

```text
N > M
AND 实例仍处于可分配空闲池
AND idleFor >= 实例空闲回收时间
→ 才能因普通保活策略销毁该实例
```

- 超量但未超时：保留；超时但总数不超量：保留；没有符合条件的实例时允许暂时超量。
- 仅淘汰满足条件的空闲实例，建议按最久未用优先；降到上限停止，绝不回收正在执行的实例来凑数。
- 淘汰选择与领取串行仲裁；并发淘汰先预留退役名额，按 `N − 已预留退役数 > M` 决定是否再选，避免多个退出未完成时过量销毁。物理总数展示仍等真实退出才减少。
- 主动关闭后台、撤权、崩溃和不可恢复故障属于独立安全收尾，不伪装为满足普通保活条件；不得据此把所有普通归还改成销毁。
- 已有独立物理资源/故障保护若限制创建，应显示真实“资源受限/等待”，不能拿软保活阈值冒充该硬限制，也不新增隐形无限重试。

## 5. 手动归还、重试与自动续跑

### 5.1 安全点契约

沿用[会话安全点统一契约](session-safe-points.md)，不把 `!isStreaming`、单工具结束、公开 `agent_end` 或任意 IPC 标记当作可归还授权。

1. IPC 只受理模式和意图，标记等待安全点，禁止旧绑定接收新的执行。
2. 在完整工具批次和 Pi 草稿提交之后请求暂停；不能在 finish 钩子里等待自身 abort。
3. 外层等待旧 prompt/取消和 `waitForIdle()` 结算，确认历史提交、唯一写者和输入归属，再进行解绑/清理。
4. 未到安全点不强杀、不虚报成功；工具长期不返回时展示真实等待原因。取消归还、故障终止等操作若以后新增须另列语义，本文不暗添强制按钮。

### 5.2 两种模式

| 模式 | 归还之后 | 后续执行 |
| --- | --- | --- |
| 归还并暂停 | 业务会话显示“已暂停 · 实例已归还”及“重试” | 用户点击后重新领取、恢复业务进度、注入最新资源，再继续未完成任务 |
| 归还并自动续跑 | 操作进入重新领取/恢复中 | 自动重新绑定并继续，失败显示可重试状态，不暗中无限重试 |

两种操作不设未确认的默认模式。无未完成任务的空闲归还不启动模型；UI 不提供会误导为立即推理的“自动续跑”。

### 5.3 输入、恢复与结果不确定

- 建议沿用现有业务输入持久回执：归还请求先关闭旧代际准入；尚未交给 Pi 的输入继续由原业务队列持有，暂停时显示待处理，续跑时在新绑定交付一次。
- 已进入 Pi 的输入/工具调用须先结算或保留明确的不确定状态，不跨实例自动重发。重复点击用相同操作身份返回已有进度，不并发归还或创建两次恢复。
- 重试/自动续跑沿已提交业务历史和安全检查点继续，不伪造一条用户要求；不从头重放所有已完成工具。费用与用量不因恢复重新累计。
- 已发出的副作用不能靠取消回滚。不确定派发须明确告知并阻止自动重放，由用户核对后决定；不宣称严格 at-most-once。既有 Pi/REA 明确恢复例外沿三步 MCP 契约计数披露。
- 用户普通停止、删除会话、撤权或更新的归还操作可以使旧恢复意图失效；迟到回调不能重新启动已停止任务。恢复是同一业务任务的程序化续接，内部 run/lease 可以更新，但关联与计费连续且可追溯。

## 6. 最新资源与不恢复历史提示词

### 6.1 生效路径

**最新**指重新绑定时取得并完整应用的当前资源快照，而不是承诺远端工具目录实时在线。旧绑定内已发出的请求不会被改写；后台代码变更仍须正式构建/部署，资源刷新不重载 worker 模块。

建议把显式归还/重载操作作为本工作空间资源刷新屏障：读取当前系统/追加提示词与项目指令、当前 Skill 声明及有效目录，更新工作空间快照；需要更新底座的空闲实例先刷新再成为可分配状态。与刷新交错的绑定用发布代次事务决定版本：失效则重新准备/等待，不把旧准备结果标为最新。该流程发生在明确的资源变更、归还/重载和重新绑定边界，**不恢复每轮文件/profile 扫描**。

- 其他仍绑定的会话不因本次单会话归还被强制停止；要使用新底座时经自己的重载/归还流程。
- 仅轻量注入变化可在绑定时更新，不重做整个底座；涉及已注册资源变化则完成相应加载，不能仅修改显示的 revision。
- 新快照加载失败保留可诊断旧快照，但本次“使用最新资源”的恢复不得静默退回旧版或假报成功。
- MCP 配置/授权分区变化立即按既有规则失效；工具目录过期/缺失不因此联网，真实 schema 最终 gate 仍按三步方案。

### 6.2 历史边界

保存业务会话、用户/助手消息、工具调用及结果、有效摘要、必要任务进度；不要求持久累计每次系统提示词文本/差异版本，也不把旧提示词恢复成当前指令。下一次请求由程序生成当前唯一生效的提示词和工具投影。

Pi 1.1.0 当前将结构化系统段与工具声明变化写入原生历史，旧纯文本 system 也有原生重放语义；压缩条目还可能保存 `systemMessage` 快照。**不能用简单删除全部 system 消息、只赋值 `agent.state.messages` 或“恢复后再追加新 prompt”冒充实现：**前者可能破坏工具声明/分支/摘要语义，后者可能仍保留旧指令生效；只过滤当前消息而不处理摘要恢复路径同样不足。

实施前须确定受维护的历史投影/恢复载体：保留协议所需的工具声明和配对结果，从模型请求投影中排除旧系统提示词，并由当前资源重建；历史持久层如何不再累计提示词须有明确、可交付的 Pi 支持与兼容迁移设计。现有文件不在本轮删除，诊断只需安全版本/时间等元数据；用户在普通业务消息中写出的指令不属于可任意删除的“系统提示词历史”。

## 7. Skill 与 MCP 方案衔接

- Skill 全量登记与提示词可见投影分离；选择变化不等于重新注册全集。目录存在不提供执行权限，读取正文不激活 MCP。
- MCP 继续按[第一步可控登记](mcp-session-control-step-1.md) → [第二步目录缓存](mcp-tool-catalog-step-2.md) → [第三步首次调用交接](mcp-lazy-first-call-step-3.md)实施和验收。本文不放宽 A/B/C 的身份、schema、取消、代际、REA、秘密保护与完整快照要求。
- 池绑定代次和 MCP 连接绑定对应；业务执行结束可保留同一业务会话连接，**归还到未绑定池时必须撤销连接绑定并收尾**，不能用已结束 run lease 或新会话身份重贴旧回调。
- 当前默认选中服务预连接仍是现状，切默认 lazy 需另行授权与真实范围验证；本文的目标预热零新增连接不冒充产品当前默认已如此。

## 8. UI 配置建议

仅为可修改的初始建议，不是实测最优值，也不沿用旧池 `maxLive/maxIdle/maxLifetime` 的同名语义。

| 配置 | 建议初值 | 界面解释 |
| --- | --- | --- |
| 最大保活个数 | 8 | 全部存活实例的保留目标，不是并发硬上限 |
| 会话空闲回收时间 | 10 分钟 | 会话持续无工作后，实例归还池中 |
| 实例空闲回收时间 | 15 分钟 | 池中闲置达到该时长且总数超限，才销毁实例 |

建议保存正整数个数、正整数分钟；不把 `0` 默默解释为立即销毁/永不回收。配置保存后重新评估计时条件，不重置空闲起点、不打断在用实例。UI 详细布局、示例与可访问性见[配套草案](agent-runtime-pool-ui.md)。

## 9. 实施前置与当前事实

核查依据为安装的 Pi **1.1.0**，非部署产物验收；版本升级须重核公开契约。

| 项目 | 当前事实与实施前置 |
| --- | --- |
| 绑定快路径 | 当前活动 run 可直达，空闲绑定仍经 profile/acquire；目标不是仅删除 hash 字段，须调整生命周期真相源 |
| 完整实例复用 | 当前主 Agent 主要同会话保留，普通预热主要进程就绪；公开 `AgentSessionRuntime` 切会话会替换 AgentSession，不证明存活完整实例可安全重绑 |

| 安全点 | 复用既有可信边界；归还清理与跨实例恢复仍需新工程验证，不借用旧重载测试冒充通过 |
| MCP | 完整快照观察、旧 codemode 契约身份及最终派发保护仍受三步文档的正式依赖约束 |

如果公开 SDK 无法保持已准备资源并安全重置/换绑，需要受维护 Pi 的窄生命周期 API 与固定正式产物；API 名和实现路径待工程验证。**该依赖未解决前不得宣称池方案已实现，更不能降格成仅保留进程后宣称目标达成。**

## 10. 验收计划

以下均为**未来实施后的用例**，本轮没有运行产品测试。单元测试用假时钟/假消息，SDK 集成用正式依赖和内存服务；worker/UI 使用独立临时配置与本地受控 fixture。真实模型/MCP/REA/OAuth、构建覆盖运行产物和部署另行授权。

| ID | 场景 | 必须证明 |
| --- | --- | --- |
| P01 | 工作空间准备与目录展示 | Skill 全集可显式引用，只有声明目录注入；不注入正文/全部 schema；零模型及未获准 MCP 连接 |
| P02 | 同绑定运行/空闲连续输入 | 命中同实例；忙时入原队列、闲时启动；没有逐轮 profile/资源/文件复用资格扫描 |
| P03 | 同会话与不同会话并发领取 | 一个会话不领两份、一个实例不绑两会话；绑定发布前不能执行 |
| P04 | 历史会话与新会话领取 | 前者恢复必要历史，后者空业务历史；池内领取和冷建领取均补热，复用已有绑定不补热 |
| P05 | 补热并发与无新需求 | 替补意图及时、可合并；归还/销毁/预热完成不会无界自激；失败有界且可见 |
| P06 | 会话空闲计时与输入竞争 | 真正空闲才计时；到期先归还不销毁；输入/取消/压缩/权限等待不会被误判 |
| P07 | 实例空闲计时 | 以进入可分配池起算；领取立即失效、归池重新计时，不按实例总年龄 |
| P08 | 总数与销毁 AND 条件 | 所有存活状态均计数；四象限、无合格候选、真实退出后减数、并发退役不超量销毁 |
| P09 | 运行中安全归还 | 整批工具/草稿提交后停止，外层 idle 再清理；单工具结束/假 IPC 不授权，等待期间无新请求 |
| P10 | 暂停与重试 | 归还后不占实例不发请求；按钮恢复未完成任务，无伪造用户输入和已完成工具重放 |
| P11 | 自动续跑与恢复失效 | 领取/注入后继续；普通停止/撤权/删除压过旧恢复意图；失败不无限暗中重试 |
| P12 | 输入回执/事件/用量交接 | 队列有唯一所有者，无跨代际迟到污染、双交付、双写历史或用量重复；未知派发不自动重放 |
| P13 | 实例 A 会话归还后绑定 B | B 无 A 的消息/闭包/权限/凭据/连接/通知/取消影响；安全底座确实保留而非冷建冒充 |
| P14 | 最新资源与并发刷新 | 回池仍存活但重领使用最新资源；旧准备不可发布，刷新失败不静默旧版；其他绑定不被强杀 |
| P15 | 历史系统段/工具/摘要/分支恢复 | 当前请求和摘要恢复路径无旧系统指令，工具声明及结果配对有效；新持久历史不累计提示词版本；旧文件不被无授权删除 |
| P16 | MCP 与 Skill 兼容 | A/B/C 验收保持；元数据共享、连接隔离，REA 来源/策略、发现/权限边界不退化 |
| P17 | 设置保存、降低保活阈值 | 原子保存/非法值拒绝，计时不重置；只回收满足条件的空闲实例，不把阈值变硬并发 |
| P18 | 故障隔离与关闭 | 清理失败不回可分配池；关闭/崩溃等独立故障流程真实收尾；旧通知不复活实例/任务 |
| P19 | 性能与计数证据 | 分开测工作空间准备、绑定注入、历史恢复、MCP 和模型；报告冷/热、样本数、P50/P95和资源残留，不预报通过 |
