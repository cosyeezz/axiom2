# 模型代理

Axiom 在供应商设置中提供三种连接方式：直连、HTTP/HTTPS 代理地址、内置代理线路。默认直连；外部代理地址不需要安装内核。

## 使用

- 已有桌面代理软件：在供应商的「模型代理」中选择「填写代理地址」，填入该软件的 HTTP 或混合端口，例如 `http://127.0.0.1:7890`，然后保存。支持 HTTP/HTTPS 入口及代理账号密码，不接受 SOCKS 地址。
- 使用 Xray 内置线路：打开「内置工具 → 模型代理」，安装 Xray-core，点击「添加线路」。运行内核默认 Xray-core，导入方式选「分享链接或订阅」，粘贴 `vless://`、`vmess://`、`trojan://`、`ss://` 分享链接或订阅地址，再点击「识别节点」。选择节点、确认线路名称后保存并启动，最后回到供应商设置选择「使用内置代理」。支持多行链接、标准及 URL-safe Base64 分享列表，包括 VLESS Reality/Vision。识别不需要安装 mihomo，也可在安装 Xray-core 前进行；启动线路才需要 Xray-core。
- 使用 mihomo 内置线路：安装 mihomo，在「运行内核」中选择 mihomo。除了分享链接和订阅，还支持含 `proxies` 的 Clash YAML/JSON。协议能力由安装的 mihomo 版本决定。
- 二维码：点击「导入二维码图片」选择图片，或将二维码截图粘贴到输入框。图片由随应用打包的 jsQR 在浏览器本地解码，不上传到在线解码或转换服务。解码文本会填入输入框，核对后点击「识别节点」；订阅内容只在点击后从该地址下载。支持 PNG/JPG/WebP 等浏览器可解码图片，最大 10 MB；当前提供图片导入，不提供实时摄像头扫描。
- 高级配置：选择 Xray-core 后，在「导入方式」中选择「高级：Xray outbound JSON」，提供一个可独立运行的 outbound 对象。mihomo 也保留手动填写完整节点名称的入口。

分享协议使用外部组件解析，Axiom 不实现协议字段转换器。Xray 使用本机独立 xray-knife CLI，首次识别时自动从官方准备导入组件；「识别节点」按钮旁显示连接、下载字节数、校验与转换进度，可直接点击「取消识别」，取消后保留输入。mihomo 使用其内核原生解析。识别只读取节点配置，不测试连通性。Xray 启动前还会执行内核原生配置校验；转换成功不保证参数有效或远端可达。每次 Xray 导入最多 2000 条，重复、无效或不支持的条目会跳过并显示数量；重名节点会加序号，无名节点提供默认名称，应核对结果。

每条线路选择一个节点。Xray 保存的是识别时选中节点的 outbound 快照，订阅地址和整份原文不落入线路配置；订阅参数变化后需重新导入保存。mihomo 保留订阅更新能力，更新后选定名称缺失时请求失败。两种内核都不回退直连。Axiom 不导入桌面客户端的脚本、TUN、DNS 或增强配置。

Xray 识别结果中的凭据只留在服务端私有内存，界面只收到节点名称和类型。保存必须匹配本次识别、原始输入和选中节点；修改输入需重新识别，识别结果在 10 分钟后、新一次识别、保存或服务退出时清除。

内核从官方发布页按需下载，校验 SHA-256，通过原生自检后切换到新版本。检查后若已安装版本与最新版本相同，安装按钮显示「已是最新版本」并禁用；重复的同版本安装请求也不会重新下载。已启动的线路随后台服务启动；编辑线路后需重新启动，安装内核更新后也需重启线路。停止或删除正在使用的线路会使对应模型请求失败，不会自动改为直连。删除线路不会代替用户修改供应商的连接设置。

线路配置与凭据保存在 Axiom 本地数据目录，使用私有目录和文件权限；包含凭据的代理 URL、线路原文不会回显到编辑器。粘贴的配置内容及 Xray 订阅下载最多 2 MB，按 UTF-8 字节计算，下载限制同时覆盖解压后的响应。Xray 订阅下载限时 30 秒并限制重定向，转换限时 60 秒；错误不回显原始链接、订阅令牌或组件诊断。编辑时留空可保留原值；切换内核后需重新提供配置。

## Xray 导入组件

使用 [xray-knife v11.4.1 官方发布](https://github.com/lilendian0x00/xray-knife/releases/tag/v11.4.1)的独立程序，支持 macOS/Linux/Windows 的 x64/arm64。固定平台资产和 SHA-256，从官方按需下载约 21–24 MB，缓存于数据目录的 `integrations/model-proxy/importer`，复用前验证缓存和程序。组件通过 stdin 接收单条链接，stdout 返回 Xray JSON；Axiom 只取一个 outbound，不采用附带 inbound/log，不启动该组件的代理或数据库。

xray-knife 自身源码是 MIT，但官方程序含 GPL-3.0-or-later 的 sing-box 等依赖，不能将整个程序标为 MIT。Axiom 不链接其 Go 库，不随应用捆绑、镜像或再分发该程序；用户运行时直接从官方取得。若未来改变分发方式，须重新处理该工具及依赖的许可证义务。版本升级需同步更新六平台校验值并复测协议转换与 Xray 原生校验。

## 网络范围

网络配置按供应商及执行进程隔离，应用于该供应商的模型调用、模型目录读取和登录认证。主会话、子任务、记忆和压缩执行使用对应的供应商出口；更换供应商或线路代次会切换执行环境。宿主进程及其他独立项目的系统代理设置不变。

供应商认证状态与可用模型只读取本地凭据和供应商定义，不发起供应商请求，因此配置页读取在宿主进程内完成而不按供应商启动模型网络进程；同一读取仍会解析该供应商的线路，内置线路已停止时继续给出明确的不可用提示，不会静默改为直连。模型目录拉取、登录和退出等真正发起网络或写入凭据的操作仍在该供应商自己的模型网络进程中完成。

标准入口使用 `HTTP_PROXY` / `HTTPS_PROXY` 与 undici 的公开 dispatcher；保持供应商 SDK 的原生协议，包括其选择的流式或 WebSocket 请求。常驻内核仅监听带随机认证的本机代理端口，不启用系统代理、TUN 或控制器。Xray 识别通过独立 CLI 离线转换，订阅下载使用独立的直接连接 dispatcher。mihomo 识别时启动独立的临时内核，代理入站全部关闭，仅开放带随机认证的 loopback 控制器来枚举节点；完成、取消或退出后停止进程并清理临时文件。

这里按供应商选择出口，没有维护供应商域名白名单。该供应商的认证域名和模型域名共享所选出口。内置内核将本机、私网地址及 `.local` 域名直连，其余通过选中的节点。外部代理模式下，本机地址、`.local` 及配置中明确的私网 IP 入口绕过代理；普通内部 DNS 域名的分流还依赖外部代理软件的规则。

shell 工具与 stdio MCP 通过公开接口恢复宿主原代理环境；HTTP MCP 传输使用独立 dispatcher。以下边界仍保留依赖原生 SDK 的行为：

- HTTP MCP 主动 OAuth 刷新使用全局 fetch，可能使用当前模型进程的出口。
- 自定义扩展在模型进程中直接调用全局 fetch 或自行启动进程，可能使用该进程的网络环境。
- 某些 SDK 的云凭据来源独立于模型请求代理。例如 AWS HTTP 凭据提供器不一定使用模型所选代理；这不阻止选择该供应商。

因此内置线路提供原生内核的代理能力，但不会复刻另一款桌面客户端的完整运行配置。

## 验证范围

回归覆盖官方 Xray/mihomo 内核的本地运行与规则、Xray 分享链接转换与订阅快照、mihomo 原生枚举、导入组件官方下载与损坏缓存修复、二维码图片的本地解码、取消/退出清理、识别结果绑定与失效、配置写入互斥、凭据脱敏、停线失败、供应商进程分流、真实 IPC 登录与取消、工具环境恢复，以及供应商和内置工具页面。

验证使用本机假上游及原生内核，不包含用户真实节点的端到端连通性；Windows/Linux 原生运行需在对应平台验证。供应商 SDK 标准入口探针涵盖 Codex WebSocket、Vertex ADC 和 Bedrock 模型入口，不代表所有云认证来源均已验证。
