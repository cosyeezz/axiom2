# 本地代码只读助手：Windows 部署修复方案

编制日期：2026-10-15（America/Los_Angeles）
状态：执行规格，不是已完成安装或端到端验收的声明。

## 1. 目标、现状与边界

用户当前遇到三个问题：点击无法启动、终端提示命令不存在、不知道助手安装目录。目标是在不改 Axiom 业务代码、不增加读取权限的前提下，修复安装和日常运维体验。

当前 Chat 的 `server_status` 实际调用返回：

```text
invalid_mcp_response
MCP SSE probe returned 404 from openai.org
status_code: 404
```

当前调用所指向的 tunnel ID 为：

```text
tunnel_6ab14f3ae4608191aac6ca8ba9243820
```

该 ID 仅是本次失败请求提供的定位线索，不代表隧道资源仍然存在或账号拥有访问权限。不要输出或依赖错误里的内部网关地址，也不要自行拼接内部 API。

现有插件名为“本地代码只读助手”；历史工作区别名为 `axiom`、`smoke`，本轮未能读取它们。不能从别名推断真实磁盘路径。历史插件引用可作为界面查找线索，但应在本机实际界面复核。

404 无法单独定位本机进程、隧道资源、关联权限或插件绑定中的哪一层有问题。不得直接宣称“服务没启动”“密钥过期”“隧道被删”或“账号额度不足”。

原始准备包的 README/测试报告只代表该包的历史状态，不代表后来实际部署的所有修改。优先调查和复用已有可运行实现，不要用旧包覆盖未知的新版本。

## 2. 单一推荐架构

保留现有只读 MCP 核心与 OpenAI 官方 Secure MCP Tunnel。整改安装、启动与诊断，不另写隧道，不引入 Docker、WSL、额外云主机或第三方公网转发。[S1]

运行关系：

```text
Windows 当前用户登录
  → 一个受管理的计划任务
    → 前台存活的启动包装器
      → 官方 tunnel-client
        → 现有只读 MCP（stdio 子进程）
```

桌面入口只负责控制同一计划任务及展示状态，不能再绕过计划任务创建第二套客户端。

这里的自动启动明确指“登录该 Windows 用户后自动启动”。不承诺关机、休眠或尚未登录时仍可读取文件。用户没有要求登录前提供服务，不为此新增 SYSTEM 服务和服务账号。

### 建议的新安装位置

下列为本次标准化部署拟采用的位置，不是对旧安装位置的猜测：

```text
程序：%LOCALAPPDATA%\Programs\LocalCodeReader\
状态：%LOCALAPPDATA%\LocalCodeReader\
桌面入口：本地代码助手
任务逻辑名：LocalCodeReader（实际任务名按用户 SID 避免多用户冲突）
```

安装程序在目标电脑解析真实绝对路径并写入非敏感安装记录。目录、程序路径与配置必须分离，且均不得落入 MCP 可读工作区。已有规范安装可以保留，不为统一目录无谓迁移；但必须提供统一桌面入口和真实路径记录。

## 3. 阶段一：本机发现，先定位再修复

先证明执行环境就是用户电脑，不是云端容器。检查系统、当前用户上下文及能否访问目标电脑桌面；不要把云端 `/mnt/data` 当用户安装目录。

按以下顺序检查，只读取与本助手有关的元数据：

1. 桌面/开始菜单相关快捷方式的目标程序与工作目录。
2. 与本助手或该隧道明确相关的计划任务、服务和当前进程的可执行文件位置。
3. 用户级安装登记与由上述线索指向的工具目录、配置位置。
4. 当前环境可解析的 Node/tunnel-client 位置，找到后检查文件存在、架构和版本。

不要全盘递归扫描。不要读取浏览器数据库、项目日志、真实 `.env`、凭据文件原文或其他无关数据。进程参数和任务动作可能含密钥，必须在本机过滤后再输出，不得原样导出所有进程命令行。

发现结果必须区分：

- 程序存在但 PATH/快捷方式/工作目录错误；
- 程序或依赖缺失；
- 存在多个互相冲突的启动入口；
- 本机正常但隧道/权限/插件绑定未通过。

没有找到旧安装不意味着文件从未存在。报告本次检查范围；随后在约定目录恢复，不要求用户先提供他已经明确不知道的安装路径。

## 4. 阶段二：补齐部署，而不是重新开发 MCP

### 4.1 程序、依赖与启动入口

优先修复已有安装。确需恢复源码时，使用随包原始 ZIP，并先执行其核心与真实 SDK smoke 测试；旧包没有完整端到端放行记录，不能直接上线。

程序目录中固定保存实际使用的 Node 运行时、官方 tunnel-client、MCP 代码和生产依赖。已有系统 Node 可用于安装阶段检查，但日常运行不得依赖全局 PATH。不要在每次启动时执行 npm install、下载最新版或重新构建。

从官方来源获取适配当前 Windows 架构的受支持客户端，校验发布文件并记录来源、版本和 SHA-256。安装时核对真实 CLI help；不要把文档中某个历史参数视为所有版本都支持。[S2]

Node 应为经核实仍受维护且兼容的版本，不因为旧测试报告就安装过时的测试版本。不在 Axiom 项目执行 npm install/build/test/start，不修改其依赖或配置。

所有运行路径使用安装时确定的绝对路径，显式指定工作目录及配置。针对空格和中文路径实际测试参数传递。缺文件时显示哪一个文件缺失、应执行哪个本机修复操作，不能只输出 command not found。

### 4.2 用户入口

第一版不必开发新桌面应用。交付桌面快捷方式，指向经过真机验收的 `.cmd` 包装入口，菜单至少覆盖“启动、停止、状态、打开安装目录、导出诊断”。可以复用官方本地管理 UI 查看隧道详情，不再建设第二套仪表盘。[S1]

不要要求用户双击 `.ps1`、自己打开终端、设置 PATH 或复制带占位符的命令。包装入口在失败时保留错误窗口并显示错误阶段及脱敏诊断位置，不允许一闪而过。

桌面入口最终控制的是受管理任务；用户关闭菜单或浏览器状态页，不得终止后台读取进程。不要让状态页本身成为后台生命周期的拥有者。

### 4.3 计划任务与单实例

使用同一 Windows 用户身份运行，采用登录触发、允许手动启动、异常退出有限重试、无不必要运行时长上限、不因切换电池而停止，以及 `IgnoreNew` 实例策略。微软 Task Scheduler 已提供这些基本管理设置，不需要另写常驻守护系统。[S3][S4]

建议异常退出按 1 分钟间隔最多自动重试 3 次，再明确显示故障；这是部署参数，不是连通性保证。包装器必须等待客户端结束并正确传递非零退出码，不能异步拉起后立刻以成功退出，导致计划任务误判为完成。

只允许一个使用该 stdio tunnel ID 的活动客户端。官方明确不支持多个 stdio 客户端共享同一 tunnel ID；更换实例前必须等旧实例及其子进程退出。[S2]

在切换到新任务前，识别并停用属于本助手的旧自启动入口，记录原设置；不得结束所有 Node 进程或删除名称类似的无关任务。启停操作验证进程归属，不以孤立 PID 文件作为唯一依据。

网络临时中断由客户端自身连接恢复机制处理；不要因一次 HTTP 错误就重装组件、重建隧道或无限重启。停止操作应停止本助手拥有的完整进程树，不能留下占用同一隧道的孤儿实例。

### 4.4 运行凭据

原包前台脚本在缺少 `CONTROL_PLANE_API_KEY` 时需要交互输入；不能直接用作无人值守入口。

由用户在本机安全录入 runtime key；使用 Windows DPAPI CurrentUser 保护后保存在助手私有目录，设置相应访问权限。启动任务必须使用同一用户，启动时才解密并传给客户端。DPAPI 是本地静态存储保护，不是抵御同用户恶意进程的强沙箱。[S5]

凭据不得进入命令参数、普通配置、快捷方式、聊天、日志、截图或交接文档。自动启动路径不允许弹出隐藏的 Read-Host；凭据缺失或不可解密时应明确进入“需要本机重新配置”状态，而不是无限重试。

仅采用运行所需权限；创建或管理隧道所需的管理权限不得长期交给后台客户端。[S1]

## 5. 阶段三：分层定位 404 与连通性问题

按层验收，记录最后成功层和失败层，不输出一个笼统“已启动”。

| 层 | 需要取得的证据 | 失败后处理 |
|---|---|---|
| 本机文件 | 实际绝对路径、版本、所需文件存在 | 修复入口或补齐组件 |
| MCP 本机协议 | 真实 SDK 初始化、工具发现、合成安全读取 | 修复依赖或实现，不先排查 Chat |
| 隧道客户端 | 当前配置的 doctor 结果、健康/就绪/轮询状态 | 核对本机网络、配置、运行凭据 |
| 平台资源与权限 | 隧道存在、组织/Chat 工作区关联、使用权限 | 修正准确的资源或权限，不盲目重建 |
| Chat 插件绑定 | 当前插件绑定同一有效 tunnel ID | 必要时通过官方界面更新，保留旧资源直到替代验证 |
| 实际工具调用 | Chat 中真实只读调用成功 | 区分握手、会话或工具错误 |

官方客户端提供 `/healthz`、`/readyz`、`/metrics` 和本地 `/ui`，但本机健康或 readiness 成功不能替代一次从 Chat 发起的真实工具调用。[S1][S2]

管理界面只绑定回环地址，使用实际配置/进程给出的端口，不猜固定端口，不开放公网监听。工具发现和调用均依赖客户端持续运行。[S1]

检查平台/插件时复用现有资源；只通过当前官方界面或正式公开工具操作。不得自行请求错误中出现的内部网关地址。若需要换 tunnel ID，必须同步本机与插件绑定，并在新连接真实成功后再处置旧资源。

## 6. 阶段四：最终验收标准

每项标记“通过 / 失败 / 未执行”，未执行不得写成通过。

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A1 | 干净终端环境不含 Node/tunnel-client 的 PATH 项 | 桌面入口仍可启动并显示真实路径 |
| A2 | 通过桌面入口启动，再关闭菜单和浏览器状态页 | 后台继续存活，真实 Chat 读取成功 |
| A3 | 连续点击启动 5 次 | 仅一个目标客户端和其应有 MCP 子进程 |
| A4 | 人工停止本助手后再次启动 | 旧进程树清理完成，新实例可真实读取 |
| A5 | 在已授权测试范围内终止客户端 | 任务按约定恢复；重试耗尽时明确显示失败 |
| A6 | 凭据缺失/无法解密（只用独立测试配置模拟） | 提示需配置，不闪退，不进入无提示重启循环 |
| A7 | 临时断网后恢复，或经用户允许进行休眠恢复 | 恢复后真实调用成功；期间状态准确显示不可用 |
| A8 | 注销再登录或重启后登录 | 无终端、无手动密钥输入即可通过真实读取 |
| A9 | 中文/空格路径 | 程序与配置参数解析正确 |
| A10 | 只读及范围验收 | 只返回已授权工作区；合成禁止路径被拒绝；不改业务文件 |
| A11 | 原始 SDK smoke 与核心回归 | 针对实际安装版本通过，保留脱敏结果 |
| A12 | 查看状态/导出诊断 | 显示最近检查时间、实际版本、失败阶段；不包含密钥和源代码正文 |

重启、注销、断网和休眠会中断用户工作，必须经过必要授权再实际执行。不能为了完成验收擅自重启；未获授权时明确留为未执行。

### Chat 最小只读验收

在新会话或完成连接刷新的会话中，实际执行：

1. `server_status`。
2. `workspace_list`，核对实际返回别名，不直接沿用历史结果。
3. 对存在且已授权的 `axiom` 调用 `workspace_overview`。
4. 搜索最多 5 个 README 候选，读取一个说明 Markdown 最多 20 行。

对外仅报告工作区别名、相对路径、行数、revision 和成功/失败，不复述项目正文。拒绝路径和脱敏测试使用合成 fixture，不读取真实密钥。若当前执行代理没有 Chat 工具调用能力，标记“本机验收完成，Chat 验收未执行”，不得宣称全部完成。

## 7. 最终必须交付给用户的内容

安装完成后在真实用户桌面提供入口，并在私有状态目录生成安装记录：实际程序目录、配置位置、任务名称、运行用户、运行版本、启动方式、检查时间、插件/隧道关联标识及各验收项结果。记录不包含任何密钥。

交付给用户的说明只需解释：桌面入口在哪里、如何判断在线、如何停止、出错后如何打开脱敏诊断。用户不应该再被要求找安装目录或学习 tunnel-client 命令。

如需提供恢复安装包，必须实际包含或可靠安装所需运行组件，并完成目标 Windows 验证。不能将只有源码的 ZIP、未测试脚本或本交接规格称为“成熟一键安装器”。

## 8. 非目标与禁止事项

不改 Axiom 业务功能，不重构只读核心，不扩大目录授权，不把整个用户目录或磁盘加入白名单，不开放匿名公网 MCP，不关闭系统安全策略，不以执行策略绕过掩盖安装问题，不运行项目脚本，不输出秘密，不把 Linux 容器测试冒充 Windows 验收。

不引入新的常驻数据库、监控平台、复杂服务发现或多副本架构。优先复用已有组件与官方诊断能力。
