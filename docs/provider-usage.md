# 模型用量与统计

配置侧栏的 **「模型用量与统计」**（`/model-usage.html`）与「模型服务」同级，不是模型服务中的 tab。模型服务页不再在供应商名称旁显示额度；新增模型供应商菜单继续隐藏 legacy Codex 入口。

页面区分两个不能相互替代的口径：

- **本机用量**：顶部只有「工作空间」「模型供应商」两个主下拉，默认全部未归档工作空间、全部供应商。工作空间在当前数据模型中就是项目目录，没有另造父空间/子项目层级。点击「加载本机统计」、选择工作空间/供应商或提交记录筛选后，展示总 Token、输入、输出、缓存读取、缓存写入五卡，下方为可搜索、按真实日期筛选、分页的调用记录。卡片统计整个筛选集，不是当前页小计。逐条记录来自原始账务，聚合或不可还原记录明确标注，不冒充网络请求次数。
- **官方用量**：选中已接入查询的供应商后按需自动展示紧凑的已用、剩余和有依据的可用金额估计；默认全部供应商不挂载、不遍历查询。普通供应商复用已有受支持认证，Codex 独立授权是特例。不合计不同供应商余额，工作空间和调用记录筛选都不改变官方账号额度。
- 数字不拼接「＋未知」。缺失显示为「—」而不是实测零，Token 不完整与费用未完整计价分别提示；大数字使用紧凑格式，悬浮提示保留可核对的精确值，微小非零费用不四舍五入为零。

## 按需加载

首次进入只读轻量供应商、工作空间和主会话目录，不扫描统计、不读独立账号、不查询官方额度。点击加载或明确操作工作空间、供应商、记录筛选才启动原始记录核对，不要求先另点一次加载。核对按有界批次自动继续，页面隐藏后暂停继续、恢复可见后接着已有游标；不会每次从同一个历史前缀重扫。普通翻页、供应商、搜索和日期筛选复用同一范围快照，只有独立的续扫请求推进来源游标，手动「刷新本机统计」才明确重建。选中已支持查询的供应商即为官方查询意图，只加载当前供应商所选来源。需要独立账号状态时先确认，避免先误查主认证再切换。网络、账号和授权管理内容仍展开「更多管理」才挂载；选中时为判断来源而读取必要的账号状态不等于展开全部管理。

连接是否在线采用 `useConnectionState().connected/generation`，不再比较 `useConnection()` 的诊断文本。某条订阅读取失败不代表 WebSocket 断开；真实断线禁用读写、保留同范围旧数据，重连后重新读取。OAuth 流程仅因真实断线或连接代次改变而失效，不自动重放授权。

## 本地统计

### 分页调用台账

新版页面使用 `app/src/server/model-usage-ledger.ts`，不是把 `Costs.get()` 聚合结果切页冒充请求。流式读取原生 JSONL 的每个 assistant/tool/usage entry、压缩 job 和每条记忆账务，仅保留账务字段，不将消息正文写入索引或返回；压缩数据库仅投影账务字段，不把摘要、输入快照物化到 JS。原生 entry 使用稳定身份，分支继承的相同调用按来源链去重，真正历史分支与重试仍保留；压缩保持 `job.billing → entry.usage → legacy job usage` 优先级，并与已应用 job 去重。账务 `records > 1` 明示聚合。缺原始记录不将累计值虚构成调用。

每个工作空间范围形成有界、只在内存中的派生 SQLite 快照：最多缓存两个范围、每个最多 20,000 行、最长5分钟，所有读取串行。供应商、会话家族、代理类型、搜索、日期、页大小和页码使用同一快照 SQL，`count`、所有匹配记录的 `total` 与当前页共享相同筛选条件。排序为未知时间最后、真实时间倒序、稳定 ID；快照过期或不匹配时回第一页并提示，避免静默错页。快照保留期间不会即时反映新调用、归档或删除，手动刷新重新核对。搜索转义 SQL LIKE 通配符；真实日期范围自然排除“时间未知”的记录，绝不借文件 mtime 或会话更新时间填充。

一次索引最多1000根、20,000派生行、每家族最多512会话；每批以32 MiB文件/投影估算输入、5000条数据库工作记录、软3秒让出，保留来源游标，下批继续而不是重扫。每4根让出事件循环；单条 SQLite 查询和单个有界操作不承诺硬3秒中断。数据库以稳定rowid小批读取，每批最多8行，单来源最多5000条；压缩原行限16 MiB、账务子对象限8 KiB，只读取selection/state/phase/trigger/startedAt/billing/usage，不用未读取的巨大摘要体积耗尽后续家族预算。过大或损坏的单来源诚实提示，不阻断其他来源。

文件只读初始大小，分块最多64 KiB、单行上限1 MiB、单文件上限512 MiB；较大文件可跨多个扫描批次，不再因超过单批32 MiB整文件拒绝。拒绝最终符号链接与硬链接，核对普通文件、有限 session header/cwd 和工作空间真实路径、结束后文件身份/大小/mtime。跨批的当前文件先写入独立暂存表，仅在验证完成后合并到可见索引；变化或失败会丢弃该文件全部暂存行，绝不把未验证前缀显示成已确认消费。不修补、迁移或改写 JSONL。文件校验失败时同步回滚暂存行及已应用压缩去重集合，避免独立数据库 `job.billing` 因失败文件的 checkpoint 而被误跳过。暂停扫描的文件句柄在5分钟过期、范围淘汰或服务关闭时释放。

返回值区分`processedRoots`（已处理家族）、`scannedRoots`（完整核对家族）和`building`（仍可续扫）。构建期间仅展示已验证来源、暂禁翻页；筛选为空显示仍在核对，不暗示全量为零。来源异常或硬上限造成的最终部分结果继续明确标注，不将遗漏视为零；可按单个工作空间核对。

模型名称按精确 `(provider, 本地模型 ID)` 有界只读投影，保留 ID 提示、不沿上游 ID 借名、不按名称合并。价格缺失不污染 Token；已有历史费用保持原值，缺价记录可按下节公开价格参考估算。

### 会话与代理类型筛选

调用记录筛选提供「会话」和「代理类型（全部代理／主代理／子代理）」，与搜索、日期组成交集。会话按主会话家族归组，包含其子代理；选择子代理不会遗漏该子会话的工具、压缩或记忆账务，因为代理身份依据实际`sessionId/rootSessionId`，不是账务类别。顶部五卡、金额、匹配数、参考估算来源和分页使用相同的完整筛选集。修改下方选项只是草稿，外层「筛选」提交才查询并回第一页，概览范围说明只显示已提交值。

切换工作空间同时清除草稿和已提交的会话选择，保留其他已提交条件；切换供应商保留会话并取交集。非法代理类型、失效/删除/归档/跨工作空间会话或子会话ID均明确报错，不静默扩大为全部。目录加载失败不清除已选会话，可以单独重读；手动刷新本机统计同时重读轻目录，以反映其他标签的新建、改名和删除，自动账务续扫不会反复读取目录。连接代次和空间变化后的迟到目录不覆盖当前选项。

`usage.sessions`只读会话/工作空间元数据，不打开历史、不初始化模型运行时，也不触发账务扫描。全空间是一次有界查询，不按项目扇出；最多返回1000个可用主会话并带`truncated`提示，选项带短ID、全空间时附工作空间以区分重名。**会话筛选只过滤工作空间索引，不把扫描下推为单个家族**，防止重新计入分支继承的相同调用。已选的有界主会话候选在同工作空间内按祖先先于分支处理，不因随机UUID排序让孙分支抢走父分支新增的调用。分支仅显示在共同索引中归属它的账务，不表示其历史文件的所有继承记录均为它新产生的消费；重复来源归最先成功提交的来源，复杂分支链不保证总是最早祖先。谱系仅复用已验证且工作空间隔离的来源缓存；单次至多核对64个祖先节点。缺失/非法父节点、环或达到边界仍无法确认来源时，明确标记部分统计，不发布可能重复的原生entry账务；独立可确认的数据库记忆和压缩job账务仍保留，不以中间祖先伪造新计费身份。续扫进度仍描述整个工作空间/全局索引，不是所选会话的扫描进度。

### 字段设置、紧凑列表与日期范围

调用记录右上角「显示字段」提供24个可选字段，按基本信息、Token用量、费用信息分组：调用时间、工作空间/会话、模型/供应商、独立供应商、调用来源、类别、账务类型、来源状态、会话ID、账务条数；普通输入、缓存读取、缓存命中率、缓存写入、输入合计、输出、总Token；消费金额、四类费用分项、其中参考估算、计价状态。来源状态不是HTTP结果，账务条数不是请求次数；本机未保留的请求耗时、首Token延迟、IP/UA等不会照抄sub2api虚构。

默认展示11列，缩小字号、单元格留白和基础列宽，时间拆为日期/时刻两行、模型与供应商合并显示；长内容截断但保留精确值和身份提示。可切换「紧凑/舒适」、显示全部或恢复默认，至少保留一列。统一列定义驱动colgroup、表头与单元格，按字段而非第几列对齐；表宽随选列计算，横滚始终局限于记录容器。显隐与密度使用浏览器版本键`axiom.usage.view.v1`，白名单过滤、去重、损坏/存储禁用安全回退，并同步同源其他标签页。只存显示偏好，不存查询、凭据或账务；调整显示不请求台账、不触发历史扫描。

四类Token沿用Pi归一化的互斥桶：`input`是普通输入，不含`cacheRead/cacheWrite`；输入合计为`input + cacheRead + cacheWrite`，总Token再加`output`。缓存写入即创建输入缓存，不是模型输出。缓存命中率为`cacheRead / 输入合计`，是**输入Token维度**而不是请求命中率；汇总使用Token加权比值，不平均行百分比。仅记录数为正、Token完整且有限非负、分母大于零时计算；缺失、全零输入或溢出显示「—」，实测无缓存读取且分母为正才显示0%。构建中只代表已核对记录。费用分项要求历史分项完整；`estimatedCost`是消费金额中已有的参考估算子集，不能重复相加。金额标题保留精确值、来源、部分计价和非实际扣款说明。

日期范围使用同风格的零依赖单月日历，提供今天、近7天、近30天、本月、全部及清空；起止任一侧可留空，支持YYYY-MM-DD精确输入以跨年跳转。确认日期只更新筛选草稿，点击外层「筛选」才查询，取消不提交。检查非法日期与起止倒置，按**本地日历日**取起日零点、止日次日零点减1ms，不用UTC日期切片或固定24小时推算。方向键逐日/周、Home/End周首尾、PageUp/Down月、Shift+PageUp/Down年、Enter/Space选择；Escape关闭当前层并还焦点，Tab自然离开，外点不抢焦点。弹层复用现有modal-owned portal/top-layer、visualViewport边界及局部滚动，不使用丑陋的原生日期弹窗。

### 缺价记录的公开参考估算

`app/src/server/public-model-pricing.ts` 是通用静态原厂价格表，单位 USD / 百万 Token。更新时同步修改精确模型 ID、价格、官方来源及核实日期，不请求远程价格、不写用户模型配置。当前包含 DeepSeek Flash/Pro、GLM-5.3/5、GPT-5.3-Codex、Claude Sonnet/Opus 4.6、Gemini 2.5 Flash/Pro；精确支持的别名以表为准，只去除已知厂商命名空间，不模糊删除日期或速度后缀。

`usageCost(value, model)` 保留已记录正金额；仅四类 Token 都完整、非全零、每个非零类别都有可信价格时兜底。模型身份缺失、不完整 Kiro 测量、失败请求的未知占位、未知缓存写入价格仍显示未知。输入、输出、缓存读取、缓存写入分别计价，不把缓存当免费，也不重复当作普通输入。Gemini Pro 输入（含缓存）超过 200k 使用公开长上下文档位。

估算写入派生 `knownCost`，同时记录其子集 `estimatedCost`、`estimatedRecords`、`estimateSources`；不能再把估算子额加到总额。`sumCosts`、会话家族、分类、分页台账 SQL 总计均保留估算标记。卡片和金额显示「含估算」，明细给出参考来源和核实日期。对历史缺价记录，这是核实时公开参考价，不代表历史当时单价，也不改写原 JSONL。历史记录中已有的正金额不被当前表覆盖。

官方来源：

- [DeepSeek](https://api-docs.deepseek.com/quick_start/pricing)：Flash `.30 / 1.20 / .006`，Pro `1.32 / 3.96 / .044`（输入/输出/缓存读取，峰时参考；谷时可能减半）。
- [Z.AI](https://docs.z.ai/guides/overview/pricing)：GLM-5.3 `1.4 / 4.4 / .26`；GLM-5 `1 / 3.2 / .2`。
- [OpenAI](https://platform.openai.com/docs/pricing)：GPT-5.3-Codex `1.75 / 14 / .175`，标准 API 参考，不含服务档位倍率。
- [Anthropic](https://platform.claude.com/docs/en/about-claude/pricing)：Sonnet 4.6 `3 / 15 / .3`；Opus 4.6 `5 / 25 / .5`；缓存写入期限未知时不估。
- [Google](https://ai.google.dev/gemini-api/docs/pricing)：Gemini 2.5 Flash `.3 / 2.5 / .03`；Pro `1.25 / 10 / .125`，超过 200k 输入 `2.5 / 15 / .25`。仅标准文本参考，不含缓存存储时长费。

这不是渠道账单：同模型在 jiuliyun、OpenRouter、CodeBuddy、订阅服务上的真实收费可能不同，还可能有峰谷、Batch、优先档位及其他非 Token 费用。不要使用参考表推算官方余额。

### 原生摘要的逐尝试补账

`native-compaction-usage.ts` 为非 Kiro 原生 compaction 观察每次逻辑 stream 调用：失败重试、前半摘要成功后后半失败也保留用量；未回传有效用量的尝试记未知，而非零消费。成功写入 checkpoint 后按单摘要 usage 身份、双摘要精确求和核对覆盖，只补未被 checkpoint 包含的尝试，不同时累加最终摘要和同一批请求。成功核对的新 checkpoint 在 `details.axiomNativeCompaction` 的版本化元数据中保留各请求的模型与用量；缺价时逐请求估价后汇总，不把两次 Gemini 输入合并后误选长上下文档位，也不猜旧 checkpoint 的模型。自定义或混合归属无法核对时明确未知，不猜测额外金额。Kiro 沿用独立测量 guard，后台 scratch 压缩沿用已有逐请求 billing，不重复安装。

补账在 compaction 结束时写入，**不是崩溃原子账本**；进程中途退出可能仍缺记录。`navigateTree` 的分支摘要失败重试不发 compaction 事件，本 guard 不覆盖；provider 传输内部的隐式网络重试、未上报 Token、历史未留存的失败请求和真实订阅扣款也不能从本机记录恢复。不能将本机统计宣称为供应商账单的完整复刻。

### 兼容聚合统计

以下描述保留的 `usage.statistics` 接口；新版调用列表不使用这些聚合行分页。

`app/src/server/model-usage-statistics.ts` 复用 `Costs` 的原生账务解析。按未归档项目中的、未软删除的主会话家族汇总；子 Agent、压缩、工具和记忆记录只计一次，不逐个子会话叠加 `Costs.get()`，也不同时累加报告总计与明细。历史分支与重试仍是已发生用量。

- 使用历史已记录价格，不按当前模型配置重算；仅完整 Token、可精确匹配公开价的缺价记录参考估算并标记。其他未知模型、费用、Token 保留未知。
- `records` 是用量记录数，不是 API 请求次数；部分工具记录本身可能是聚合结果。
- 未保留、已删除、已归档或上游未上报的消费不能据此还原。兼容聚合接口没有逐调用日期筛选；新版台账仅用原始记录中真实存在的时间。
- 支持按项目筛选及手动刷新，连接恢复后重新读取；不随每条消息重新全库统计。一次扫描同时形成供应商 × 调用来源、供应商 × 项目的聚合，切换供应商不重新扫描；不能只过滤模型表而保留全局概览。
- 供应商目录合并实际连接与历史账务中的供应商 ID；自定义连接名称保持独立，同名连接附 ID 区分，不将品牌相同的连接合并。历史无法归属的记录单列「未识别供应商」。
- 模型分布与计费明细使用相同可读名称，仅按 `(provider, 本地模型 ID)` 投影：配置覆盖名称优先，其次自定义定义名称，再取同 ID 的本地目录名称。不沿上游 ID 推测复制模型名称，不按名称合并账务；原始 ID 保留在提示中。未知内部配置显示「未知模型配置」，历史真实模型 ID 无映射时原样保留。名称不进入家族成本缓存，改名后重新读取统计即可生效；两个可选元数据文件各限 4 MiB，最多投影前 1000 行、名称最多 160 字符，损坏、超限或文件软/硬链接别名不隐藏统计。不读取认证来恢复账号范围目录，Kiro/带 `cacheScope` 的缓存名称保守跳过。
- 同筛选请求单飞，不同筛选排队；最多缓存 512 个家族摘要，以非消耗的 `Costs.version()` 校验，不能吞掉现有会话费用视图待接收的更新。
- 统计只读 JSONL。`openTranscript(..., {readOnly:true})` 使用 Pi 公开的 `parseSessionEntries` 和 `SessionManager.inMemory(..., entries)` 在内存迁移；不能调用 `setSessionFile`，因为 Pi 1.1.0 的文件加载器即使在内存 manager 上也会修补末尾换行。

### 兼容聚合接口预算

本节仅描述旧`usage.statistics`聚合接口；新版`usage.ledger`采用前述可续扫批次，不会在单批耗尽后永久固定同一前缀。

默认每轮最多 1000 个根家族、32 MiB 估算输入、5000 条家族数据库预检记录，每家族最多 512 个会话，软时间预算 3 秒。根会话以 `COUNT` 取得总数，实际加载使用 `LIMIT`；进入账务指纹和 JSON 解析前，以数据库 `length(... AS BLOB)`/限量查询和文件元数据预检压缩正文、完整记忆记录、会话与项目元数据、缓存账务及子任务实际使用字段，包括 ID 和标题。仅返回数字尺寸及限长 ID/路径，不把大正文物化到 JS；根列表也限制 ID 和项目名称的物化长度。

数据库估算为账务源的重复读取、会话元数据反复校验及每个历史文件的项目读取预留保守倍数；缓存命中仍计入指纹预算。**拒绝或异常的预检也累计已读取行数/字节**，耗尽全局预算后停止，不能让每个被拒家族重新取得完整额度。达到数据库 `LIMIT` 时保守返回部分统计，不额外读取越过全局上限的哨兵行；跳过的家族仍参与事件循环让步。

这些是资源与**软时间**预算，不保证单个 SQLite 查询或文件解析可被严格在 3 秒内中断。超过预算、源记录异常、扫描中数据变化时显示部分统计、已扫描/总家族数及警告，不能把未扫描部分当作零。可按项目缩小范围。项目筛选列表最多返回前 1000 个未归档项目，超出时说明；不因此把全项目累计口径改为仅这 1000 个项目。

## 官方查询与认证管理

`ModelService.usageProviders()` 只读配置与凭据元数据，不初始化 SDK 模型目录、不解析命令型密钥、不刷新或迁移凭据。目录只下发连接 ID、名称、配置状态、查询能力及版本摘要；不返回模型数组、文件路径、密钥、请求头或凭据。配置状态仅代表本地已存配置，不保证令牌有效或具有额度权限。

普通连接通过 `ModelService.usage()` 使用本连接的只读认证和隔离网络。尚无适配器或不支持当前认证类型时，明确显示「暂未接入」，不强迫用户额外登录。已有 OpenAI 连接可以在「更多管理」中切换模型认证与独立 Codex 查询来源；即使主连接是未支持官方查询的 API key，也不隐藏已经配置的独立 Codex 账号；若已保存独立 Codex 授权，默认使用它，并明确标注来源，不声称其额度自动对应当前本机模型记录。没有 OpenAI 连接时保留独立 Codex 查询入口。

已连接状态只展示认证来源、官方返回值、更新时间与刷新，网络/账号管理收进「更多管理」。未连接或过期才显示必要的授权操作。筛选、表格与官方查询的迟到响应按连接、账号版本和代际隔离；切换项目清除旧范围统计，刷新失败可以保留同范围的上次结果并标记。

调用表采用可配置列与容器内横向滚动，长名称截断并保留完整提示，数值紧凑显示及列内裁剪，不令页面横溢或侵入相邻列。切换工作空间、供应商或记录筛选时回到记录标识列。两个主下拉和认证来源使用原有 Select 的视口约束弹层、portal/top-layer、键盘与焦点管理；窄屏主下拉堆叠，分页触点至少44px。独立授权状态读取失败不冒称未授权，可在「更多管理」重读。

## 独立 Codex 用量账号

`app/src/server/usage-accounts.ts` 为用量账号创建独立 `ModelService` 和 `Logins` 实例：

- 固定私有目录 `<应用数据根>/model-usage/pi`，独立 `auth.json`、`models.json` 和 `models-store.json`。不临时改进程级 `AXIOM_PI_DIR`，不借用主模型服务凭据。
- 模型网络 worker 接收实例自己的目录、配置及代理。查询与授权均使用这里保存的网络设置；代理失败不能静默直连，也不改变主进程代理环境。
- 状态只返回配置版本、凭据代际摘要、是否配置/过期及脱敏代理，不返回令牌或账号 ID。额度不进入模型编辑草稿、模型目录或任务认证快照。
- 复用原有浏览器授权、设备码/手动回填、取消、断连和受理回执机制，但命令及事件 scope 独立，事件只发给发起连接。与模型服务 OAuth 双向互斥，避免两个流程争用原生回调端口，不取消已有授权。
- 每次操作前双向检查目录和凭据文件的路径别名；拒绝用量侧 symlink/hardlink 以及主文件反向指向用量文件（包括目标尚不存在）的情况。只检查主文件元数据，不读取主凭据内容。坏目录不应阻止整个应用启动，但该账号操作会安全失败。
- 退出需复核配置版本与凭据代际，只删除本机的独立用量凭据，不退出模型服务、不停止任务，也不撤销上游授权。重新授权/退出/网络版本变化会重建额度组件，不保留另一代账号的旧额度。

实际授权必须由用户自行在浏览器完成。独立 Codex 登录成功仍不保证上游额度接口接受该授权；查询不会自动 refresh 或改写 OAuth。过期时提示在此处手动重新授权。

## 只读额度适配

- `app/src/shared/provider-usage.ts`：通用只读 DTO，窗口百分比、点数十进制字符串、次数和具备契约的绝对 Token 额度是独立指标。`null` 是未知，不是零；无限独立表达。当前 OpenAI 适配只返回前三类，不产生推算的绝对 Token。
- `app/src/server/provider-usage.ts`：后端适配器注册表、服务端刷新期限、缓存与单飞。当前支持 `openai`/`openai-codex`；普通 OpenAI OAuth 复用模型服务认证，Codex 走隔离用量账号。API key 或其他未接入的连接不冒称可查询额度。仍不暴露旧 `configuration.usage` 命令或 `ProviderDraft.auth.usageSupported`。
- `app/src/server/providers/openai-usage.ts`：已知 direct grant 本地返回限制；legacy/未分类 OAuth 只调用两个 GET：`https://chatgpt.com/backend-api/wham/usage` 和 `https://chatgpt.com/backend-api/wham/rate-limit-reset-credits`。
- `app/src/client/models/ProviderUsage.tsx`：选中已接入供应商后按需挂载的紧凑指标渲染，按服务端 `nextRefreshAt` 设置自动刷新；可见视图到期读取，隐藏时不查询，恢复可见后最多补读一次，不补历史轮次。进入/重连是普通缓存读取，只有手动按钮传 `refresh:true`；不解释供应商私有字段。`refreshable:false` 或 `unsupported` 时停止轮询并禁用刷新，管理链接只接受无嵌入凭据的 HTTPS。

官方用量首次无缓存或自动期限已到时才只读获取；每次尝试完成后，生成 **30 分钟＋随机 0～10 分钟** 的下一期限，期间只读本地缓存。失败也推进同样期限，同一认证的旧成功结果保留原更新时间并明确标为旧数据，避免 15 秒重试风暴。手动刷新绕过自动期限，但保留至少 5 秒去抖；尝试后重置下一自动期限。同一后端实例内按身份单飞，多标签页/重挂载不重抽期限。

`provider-usage-cache.ts` 将脱敏 DTO、身份摘要、尝试时间及期限持久化到 `<应用数据根>/model-usage-cache/<目录身份摘要>/<供应商摘要>.json`，不写认证或模型配置，不存令牌、账号 ID、代理秘密或上游原始数据。主/独立认证目录分别命名空间，条目继续按供应商、凭据、保存配置和代理运行态校验。重启恢复原期限，逾期只补当前一次；不会在无人观看时后台遍历所有供应商。目录/文件采用私有权限、原子替换，缓存读取有 256 KiB、结构与时间校验，并拒绝缓存软/硬链接和目录别名。缓存不可用时降级内存，不影响只读查询。链接校验不承诺抵御同 UID 恶意进程并发替换父目录；当前也不宣称多个并行后台进程共享根目录时存在跨进程查询锁。

每次读缓存及异步上游结果返回前均复核认证、自然过期及 direct 限制；失效不显示旧数字，不将单纯身份摘要相等误认为令牌仍有效。调用经供应商隔离的 `modelNetwork` worker，不修改主进程全局代理。

额度查询通过 Pi 的 `readStoredCredential` 只读自身凭据，不调用 `getAuth`/`prepareAuth`，不刷新、不推理、不消费。固定官方目标、禁止重定向、限制响应大小与总时限。卡 ID、账户 ID、令牌和原始上游错误正文均不下发；只保留白名单错误诊断，区分过期、401/403、429、服务错误、响应无效、网络失败和超时。401/403 不擅自等同于“需要重登”，也不证明整个套餐已耗尽。

未来供应商的字段解析应留在后端适配器，前端沿用通用指标 DTO。默认复用已有模型认证的只读查询，不执行认证准备或写入；确需新的独立账号类型时仍须显式扩展授权白名单，不把 Codex 的独立登录要求套给所有供应商。

### 可用金额估计

窗口同时展示已用与剩余百分比。**OpenAI 当前只有窗口百分比、点数和次数，没有已核实的绝对剩余 Token 或点数到美元/Token的换算契约**，因此显示“暂不能估算”，不能把点数直接当美元，不能用全部设备/不同窗口的本机 Token 去反推官方上限。

通用 `tokens` 指标只有适配器确有绝对额度契约时才可返回，包含精确本地模型 ID、已用/剩余 Token 和可选 Token 类别。此时才读取 `usage.pricing` 的当前本地配置单价：按每百万 Token 计算。类别明确时使用对应单价；未知配比时必须拥有完整四项价格，展示最小到最大参考区间。缺价、错模型、阶梯价或剩余未知都不估算；不沿上游模型 ID 借价。估值明确不是上游美元余额，与历史已记费用分离。本地价格读取有界只读，不初始化 SDK、不解析密钥、不拉远程模型目录，也不返回完整编辑配置。当前数值估算分支仅有隔离 fixture 验证，不能称真实 OpenAI 已有可估余额。

### 应用级 WS 接口

以下命令拒绝顶层 `workspaceId`/`sessionId`，不允许客户端指定认证文件路径：

- `usage.statistics`：点击加载后请求，可用 `params.workspaceId` 筛选项目；返回全局及供应商维度的 Token、来源、项目与模型汇总，模型行可含轻量可读 `name`。
- `usage.ledger`：按需构建或读取逐来源账务快照；`params` 可含 `workspaceId/providerId/rootSessionId/agentRole/query/from/to/page/pageSize/snapshot/refresh/continue`。`providerId` 缺省是全选、null是未知；`pageSize` 最大100。`continue:true`推进已有有界扫描；不是记录页码，也不等于`refresh:true`重建。返回匹配总数、全筛选总计和当前页，附快照、真实时间、`building/processedRoots/scannedRoots/totalRoots`及警告。新批次发布新快照，旧页回第一页。
- `usage.workspaces`：轻量未归档空间 ID/名称，最多1000，不扫描历史。
- `usage.sessions`：可选`params.workspaceId`，返回`{sessions:[{id,title,workspaceId,workspaceName}],truncated}`；排除已删除、归档空间及任务子会话，最多1000，元数据只读。`usage.ledger`的`rootSessionId`选择该主会话归属账务，`agentRole`只能是`main/subagent`，缺省全部。
- `usage.pricing`：给定 `params.providerId` 的有界当前本地模型单价，不改变历史费用。
- `usage.providers`：轻量只读连接目录与查询能力。
- `usage.account.get`、`usage.account.proxy`、`usage.account.logout`：独立状态、查询网络和退出；写操作校验版本，使用幂等受理回执。
- `usage.auth.start/open/answer/cancel`：仅 `openai-codex` 的 OAuth；事件 scope 为 `usage:authentication`。
- `usage.provider`：按 `params.providerId` 只读查询；`openai-codex` 使用独立账号，其他供应商由模型服务的适配器与已有认证处理；请求断连可停止该视图等待；服务级单飞上游尝试独立存活，最多 10 秒，避免某个标签断开影响其他查看者。退出命令仍只允许独立 Codex，不会退出主模型认证。
- `usage:account` scope：仅发布账号状态失效通知，不广播凭据。
- 自动来源在独立账号状态未确认时不回退主认证；用户明确选择“模型服务认证”后可使用该连接，不因独立账号状态读取失败而阻断。
- `usage:providers` scope：配置更新的轻量失效版本；统计页只订阅此版本，不为监听变更下载完整 `configuration.available`。

## direct 授权限制与历史 401

早期供应商内嵌展示的只读诊断曾从运行实例确认 OpenAI 聚合查询出现 HTTP 401。它仅证明至少一个 GET 被拒绝，不证明两个 GET 都是 401，不确定拒绝的具体原因，也不是当前独立页面已经部署或实际授权成功的证据。

新版 `openai` OAuth 与 legacy `openai-codex` grant 不相同。对照 sub2api `ba81c7fd758e425d67f856d601147ef0c5263d3f`：

- Pi 1.1.0 `openai-chatgpt.js` 使用动态 client、`/api/accounts/authorize`、`/api/accounts/oauth/token`，指定 `resource=https://api.openai.com/v1`，scope 包含 `resource.invoke chatgpt.tokens.use.direct`。
- sub2api `backend/internal/pkg/openai/oauth.go` 使用 Codex 固定 client、`/oauth/authorize`、`/oauth/token` 和 `openid profile email offline_access`，不指定上述 resource，与 legacy Codex 流程相近。
- sub2api 使用该账号 access token 查询相同两个 wham 地址；其 code exchange 是授权码兑换，不是 direct → wham token exchange。补请求头/TLS 指纹不能被当作授权转换的证据。

官方 [Token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference) 指明 direct token 的 audience，并要求认证 metadata 视为 opaque；[Tracking usage](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions#tracking-usage) 指引链接到 [ChatGPT 用量页](https://chatgpt.com/settings/usage)，没有提供点数/重置次数查询契约。目前未找到已核实的 direct → wham 转换，不等于证明官方内部绝无接口。

后端只在存储的 `scopes` 显式包含 `chatgpt.tokens.use.direct` 时本地返回 `refreshable:false` 与官方 HTTPS 管理链接，清除旧缓存，不读 opaque metadata、不启动 worker、不请求 wham。不能只凭 provider 名称猜 grant 类型。legacy/未分类凭据仍尝试只读查询；可用账号 ID 时条件添加 `chatgpt-account-id`，缺少时不本地提前拒绝，由上游判断。

## 重置与消费边界

用户允许后续提供手动重置入口，本轮没有实现 consume、重置或充值按钮。查询只有 GET，不自动消耗可用次数；不能把本地冷却重置、充值或授权重新登录当作官方重置。

后续消费实现必须另行完成明确确认、幂等与互斥、防重复提交、账号/版本复核，并区分“已消费但刷新失败”与“未发送”。查询失败、次数未知或旧数据不能作为可消费依据；不能自动重试消费。本代理测试不得点击真实重置或发真实 consume。
