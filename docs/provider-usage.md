# 模型用量与统计

配置侧栏的 **「模型用量与统计」**（`/model-usage.html`）与「模型服务」同级，不是模型服务中的 tab。模型服务页不再在供应商名称旁显示额度；新增 OAuth 的默认「OpenAI」使用原生 Codex 授权（内部 ID 为 `openai-codex`），不再提供第二个 direct OAuth 新增入口；已有 direct/API Key、自定义连接保留。

页面以四个标签区分数据范围：

- **用量概览**：总 Token、本机费用（USD）、缓存命中率、账务记录四项指标，以及日期趋势、模型 Top 5、工作空间／供应商分布。图表可切换 Token／费用；Token 四类构成折叠展示。
- **调用明细**：逐条账务、字段与密度设置、分页。与概览共用同一筛选集和快照，切换两者不重新读取；图表和指标不是当前页小计。
- **请求监控**：当前后台的供应商并发、峰值、RPM，供应商选择独立；离开标签即停止轮询，保留上次展示，不触发账务或官方额度查询。
- **官方额度**：选择供应商后按需查询紧凑的已用、剩余和有依据的可用金额估计；未选择时不遍历账号。所有供应商（包括 OpenAI/Codex）复用所选主模型连接的已有认证和代理，没有独立用量登录。范围与本机历史筛选无关。

概览和明细上方始终提供同一组五项条件：**日期、工作空间、会话、类型、供应商**。类型为下拉，菜单仅含主代理／子代理／压缩，初始未选择即不限定；统一「应用」「重置」，所有条件均为草稿，变更工作空间只立即重读轻目录并清除草稿会话。搜索集中在同一筛选面板，明细内部不再另设筛选。

页面仅保留数据、单位、已应用范围及含估算／部分数据／未计价等必要状态，不展示统计口径、扫描机制或解释性长文。实现细节保留在本文档中。工作空间仍为项目目录，没有新造父子项目层级。
- 数字不拼接「＋未知」。缺失显示为「—」而不是实测零，Token 不完整与费用未完整计价分别提示；大数字使用紧凑格式，悬浮提示保留可核对的精确值，微小非零费用不四舍五入为零。

## 按需加载

没有近期查询意图时，首次进入只读轻量供应商、工作空间和主会话目录，不请求历史报告、不启动认证、不查询官方额度。历史统计由后台独立子进程维护，是否打开页面不决定它是否运行。点击加载、应用或重置只读取已准备的报告；新筛选或页码尚无报告时注册有界后台视图并显示准备中，不在请求处理中扫描或聚合。修改草稿不提交查询。页面隐藏或切离历史标签只停止页面轮询，不暂停后台核对；手动「刷新本机统计」也是异步更新意图，不等待扫描完成。

在「官方额度」中选中供应商才是官方查询意图，历史筛选供应商不触发额度读取。只查询所选主模型连接，没有第二来源、独立账号状态、代理或登录管理；认证和代理统一在「模型服务设置」维护。

首屏目录和已请求的历史结果就绪后，延后200ms依次预加载请求监控、官方额度的代码，并最多预读一次本机内存中的 `usage.requests`；不挂载授权、不提前查询官方上游，也不在非活动标签轮询。Tab悬停/聚焦可提前加载对应代码。请求监控复用同文档上次结果，1秒内的预读可直接接续轮询；旧连接代次、隐藏或失败数据仍标记陈旧并重读。目录等到当前订阅的首次失效快照后只读一次，避免初始订阅导致重复请求。

已加载页面在同一浏览器标签内短期重进时，`sessionStorage` 的 `axiom.usage.page.v1` 仅保留5分钟内的草稿/已应用条件、页码与快照令牌（有界8K字符），不持久化账务、账号或凭据；重新建立授权连接后立即重新验证此前查询，不强制重建账本。第一次点击「加载」复用持久化报告，只有已加载后的「刷新」提交后台重新核对意图（合并并受冷却约束）。切离再返回历史标签直接沿用当前结果，不因切Tab重查；真正筛选、翻页、重连仍重新读取。

连接是否在线采用 `useConnectionState().connected/generation`，不再比较 `useConnection()` 的诊断文本。某条订阅读取失败不代表 WebSocket 断开；真实断线禁用读写、保留同范围旧数据，重连后重新读取。OAuth 流程仅因真实断线或连接代次改变而失效，不自动重放授权。

## 本地统计

### 分页调用台账

生产路由使用 `app/src/server/usage-sidecar.ts` 管理独立低优先级子进程，`usage-sidecar-engine.ts` 复用 `model-usage-ledger.ts` 的账源验证与解析，不是把 `Costs.get()` 聚合结果切页冒充请求。流式读取原生 JSONL 的每个 assistant/tool/usage entry、压缩 job 和每条记忆账务，仅保留账务字段，不将消息正文写入索引或返回；压缩数据库仅投影账务字段，不把摘要、输入快照物化到 JS。原生 entry 使用稳定身份，分支继承的相同调用按来源链去重，真正历史分支与重试仍保留；压缩保持 `job.billing → entry.usage → legacy job usage` 优先级，并与已应用 job 去重。账务 `records > 1` 明示聚合。缺原始记录不将累计值虚构成调用。

`<应用数据根>/cache/usage/v1.sqlite` 保存可重建的派生账务代次、原子发布的范围 head 和已物化报告，不含原生正文或认证。默认独立准备全局概览，最多维护两个近期范围，每范围最多20,000条账务；发生变化时完整安全重核相应范围，而不是把压缩修正、删除和谱系变化误当成只能追加的新行。暂存以100行小事务写入，完整验证后短事务切换head；旧报告保持同代自洽，新代就绪后逐视图替换，重启可在首次重新核对之前读取此前完整报告。

供应商、会话家族、代理类型、搜索、日期、页大小、页码及图表时区组成报告键。`count`、所有匹配记录的 `total`、图表与当前页使用同一已验证代次和筛选；页面请求只读已物化body，未命中注册后台任务，不回退现场SQL聚合。最多32份视图，单body限1MiB、总body限16MiB；单个超限或失败视图独立退避，不阻塞同范围其他报告。排序为未知时间最后、真实时间倒序、稳定ID；跨代旧页令牌回第一页。搜索转义SQL LIKE通配符；真实日期范围自然排除“时间未知”的记录，绝不借文件mtime或会话更新时间填充。

读取报告前仍复核工作空间、根和已入账会话的删除／归档／归属元数据；不符合时隐藏旧报告，等待新代，不能靠持久缓存继续展示已不可见来源。发布前资格检查与manifest在同一短源只读事务中完成，该事务不做文件I/O、暂停或派生写入。账务源以只读SQLite连接打开，绝不在worker构造会迁移或写源库的Store；派生writer拒绝已发现的缓存目录符号链接及DB/WAL/SHM软硬链接别名。损坏或不可用的派生库目前仅安全降级并重试，不自动删除源库或承诺自动修复磁盘损坏。

一次索引最多1000根、20,000派生行、每家族最多512会话；后台每片源读取采用256KiB文件／投影估算输入、250条数据库工作记录、软15ms预算，片间默认休眠50ms并保留游标。worker账务JSON和搜索索引预算32MiB，派生暂存账务也有32MiB限制，达到上限明确发布部分数据。数据库以稳定rowid小批读取，每批最多8行，单来源最多5000条；压缩原行限16MiB、账务子对象限8KiB，只读取selection/state/phase/trigger/startedAt/billing/usage，不用未读取的巨大摘要体积耗尽后续家族预算。过大或损坏的单来源诚实提示，不阻断其他来源。

启动后默认延迟1秒开始，10秒观察一次源data_version与有界轮转文件元数据（每轮最多128个），30秒最短重建间隔合并变化，最迟5分钟再次核对；这是允许延迟的派生统计，不是逐消息实时账本。worker尽力设置nice19，V8堆上限256MiB，SQLite缓存4MiB、禁mmap、派生页数上限49,152（默认4KiB页约192MiB），自动checkpoint与8MiB的checkpoint后WAL保留目标。V8堆不是总RSS，WAL保留目标不是活动WAL硬上限，进程隔离也不能消除物理CPU／磁盘竞争；单条SQL、图表聚合及JSON序列化仍是不能抢占的有界同步操作，不承诺硬15ms时限。

主进程不增添模型调用、消息保存或压缩完成的统计hook、写表或等待，也不需要这些路径通知；仅独立观察已有落盘来源。IPC真正未应答请求最多16个，调用500ms超时显示准备中但保留wire槽位，10秒健康超时终止worker，退出后指数退避重启；关闭也有界。故障不触发主进程同步扫描fallback。不可见孤立暂存数据在后台按500行清理，不以启动整表删除阻塞ready。

文件只读初始大小，分块最多64 KiB、单行上限1 MiB、单文件上限512 MiB；较大文件可跨多个扫描批次，不再因超过单批32 MiB整文件拒绝。拒绝最终符号链接与硬链接，核对普通文件、有限 session header/cwd 和工作空间真实路径、结束后文件身份/大小/mtime。跨批的当前文件先写入独立暂存表，仅在验证完成后合并到可见索引；变化或失败会丢弃该文件全部暂存行，绝不把未验证前缀显示成已确认消费。不修补、迁移或改写 JSONL。文件校验失败时同步回滚暂存行及已应用压缩去重集合，避免独立数据库 `job.billing` 因失败文件的 checkpoint 而被误跳过。暂停扫描的文件句柄在5分钟过期、范围淘汰或服务关闭时释放。

`processedRoots`／`scannedRoots`／`totalRoots`描述已发布代次的核对范围；`background.state`区分preparing、updating、ready、error。首次未准备报告以“—”而非零显示；有旧完整报告时可以保留并明确后台更新中。`updatedAt`及`verifiedThrough`保守取本次核对开始时间，`publishedAt`另记发布时间，查询本身不抬高水位。可见历史页准备中每1秒、ready/error每5秒读一次缓存，隐藏和切离历史标签停止页面轮询。来源异常、跨分支同一原生调用的不同账务版本或资源上限继续明确标注partial，不能当作已确认完整账单；冲突版本保留既有计入归属，不静默挑选金额，缺原生ID的line回退不拿来推断跨分支冲突。

模型名称按精确 `(provider, 本地模型 ID)` 有界只读投影，保留 ID 提示、不沿上游 ID 借名、不按名称合并。价格缺失不污染 Token；已有历史费用保持原值，缺价记录可按下节公开价格参考估算。

### 图表聚合

图表、过滤汇总及分页报告由后台物化并持久保存，前台请求不重做聚合。内部builder每个发布快照仍有最多8组、序列化合计1MiB的LRU汇总缓存，供后台复用；完整筛选（显式未知供应商与不筛选区分）及规范时区决定`count/total/analytics`。响应反序列化隔离变异，供应商目录按代次复用，分页索引与未知时间最后的排序表达式一致。首次完整扫描、新筛选和新页报告准备仍与记录量有关，可以延迟，不承诺冷历史扫描为毫秒级。

`usage.ledger` 的 `analytics:true` 是可选扩展，不另建扫描器；服务端在与当前页/总计完全相同的已验证快照和 SQL 条件下迭代全体匹配账务。图表不使用 `usage.statistics` 的较窄筛选能力，也不在客户端对当前页作图。

`usage-analytics.ts` 以浏览器 IANA 时区的真实日历日期汇总，DST 不以固定24小时推算；明确的日期端点补空日，开放端点依观察日期确定。最多60桶，长历史自动合并连续日历日，不截断较旧数据。没有真实时间的记录放在 `undated`，仍纳入总计和排名。趋势可展开精确数字表，未知/部分计价与估算状态保留。

模型用 `(provider,model)`、工作空间用ID、供应商用ID/null分组，名称相同也不合并。三个维度各自返回 Token 与已知费用的 Top 5，加独立「其他」余项保留全量总额；不是同一份Token排名改显示费用。金额聚合沿用浮点数，与SQLite求和允许末位舍入差，不改写原账务。缺价不影响Token，参考估算是knownCost子集，不重复相加。

### 会话与类型筛选

「会话」「类型」与日期、空间、供应商、搜索组成交集。会话按主会话家族归组，包含其子代理；主／子代理依据实际`sessionId/rootSessionId`筛选，包含各自的工具、压缩、记忆账务；「压缩」单独选择两者的压缩类别。四项指标、图表、金额、匹配数、参考估算来源和分页使用同一完整筛选集。所有选项都是草稿，「应用」提交才查询并回第一页，范围摘要只显示已提交值。

变更工作空间清除草稿会话，应用后才清除已提交会话，其他条件保留；变更供应商保留会话，应用后取交集。非法代理类型、失效/删除/归档/跨工作空间会话或子会话ID均明确报错，不静默扩大为全部。目录加载失败不清除已选会话，可以单独重读；手动刷新本机统计同时重读轻目录，以反映其他标签的新建、改名和删除，自动账务续扫不会反复读取目录。连接代次和空间变化后的迟到目录不覆盖当前选项。

`usage.sessions`只读会话/工作空间元数据，不打开历史、不初始化模型运行时，也不触发账务扫描。全空间是一次有界查询，不按项目扇出；最多返回1000个可用主会话并带`truncated`提示，选项显示会话名称，不拼接ID或工作空间。**会话筛选只过滤工作空间索引，不把扫描下推为单个家族**，防止重新计入分支继承的相同调用。已选的有界主会话候选在同工作空间内按祖先先于分支处理，不因随机UUID排序让孙分支抢走父分支新增的调用。分支仅显示在共同索引中归属它的账务，不表示其历史文件的所有继承记录均为它新产生的消费；重复来源归最先成功提交的来源，复杂分支链不保证总是最早祖先。谱系仅复用已验证且工作空间隔离的来源缓存；单次至多核对64个祖先节点。缺失/非法父节点、环或达到边界仍无法确认来源时，明确标记部分统计，不发布可能重复的原生entry账务；独立可确认的数据库记忆和压缩job账务仍保留，不以中间祖先伪造新计费身份。续扫进度仍描述整个工作空间/全局索引，不是所选会话的扫描进度。

### 字段设置、紧凑列表与日期范围

调用记录右上角「显示字段」提供24个可选字段，按基本信息、Token用量、费用信息分组：调用时间、工作空间/会话、模型/供应商、独立供应商、调用来源、类别、账务类型、来源状态、会话ID、账务条数；普通输入、缓存读取、缓存命中率、缓存写入、输入合计、输出、总Token；消费金额、四类费用分项、其中参考估算、计价状态。来源状态不是HTTP结果，账务条数不是请求次数；本机未保留的请求耗时、首Token延迟、IP/UA等不会照抄sub2api虚构。

默认展示11列，缩小字号、单元格留白和基础列宽，时间拆为日期/时刻两行、模型与供应商合并显示；长内容截断但保留精确值和身份提示。可切换「紧凑/舒适」、显示全部或恢复默认，至少保留一列。统一列定义驱动colgroup、表头与单元格，按字段而非第几列对齐；表宽随选列计算，横滚始终局限于记录容器。显隐与密度使用浏览器版本键`axiom.usage.view.v1`，白名单过滤、去重、损坏/存储禁用安全回退，并同步同源其他标签页。只存显示偏好，不存查询、凭据或账务；调整显示不请求台账、不触发历史扫描。

四类Token沿用Pi归一化的互斥桶：`input`是普通输入，不含`cacheRead/cacheWrite`；输入合计为`input + cacheRead + cacheWrite`，总Token再加`output`。缓存写入即创建输入缓存，不是模型输出。缓存命中率为`cacheRead / 输入合计`，是**输入Token维度**而不是请求命中率；汇总使用Token加权比值，不平均行百分比。仅记录数为正、Token完整且有限非负、分母大于零时计算；缺失、全零输入或溢出显示「—」，实测无缓存读取且分母为正才显示0%。构建中只代表已核对记录。费用分项要求历史分项完整；`estimatedCost`是消费金额中已有的参考估算子集，不能重复相加。金额标题保留精确值、来源、部分计价和非实际扣款说明。

日期范围使用同风格的零依赖单月日历，提供今天、近7天、近30天、本月、全部及清空；起止任一侧可留空，支持YYYY-MM-DD精确输入以跨年跳转。确认日期只更新筛选草稿，点击外层「应用」才查询，取消不提交。检查非法日期与起止倒置，按**本地日历日**取起日零点、止日次日零点减1ms，不用UTC日期切片或固定24小时推算。方向键逐日/周、Home/End周首尾、PageUp/Down月、Shift+PageUp/Down年、Enter/Space选择；Escape关闭当前层并还焦点，Tab自然离开，外点不抢焦点。弹层复用现有modal-owned portal/top-layer、visualViewport边界及局部滚动，不使用丑陋的原生日期弹窗。

### 缺价记录的公开参考估算

`app/src/server/public-model-pricing.ts` 是通用静态原厂价格表，单位 USD / 百万 Token。更新时同步修改精确模型 ID、价格、官方来源及核实日期，不请求远程价格、不写用户模型配置。当前包含 DeepSeek Flash/Pro、GLM-5.3/5、GPT-5.3-Codex、Claude Sonnet/Opus 4.6、Gemini 2.5 Flash/Pro；精确支持的别名以表为准，只去除已知厂商命名空间，不模糊删除日期或速度后缀。

`usageCost(value, model)` 保留已记录正金额；仅四类 Token 都完整、非全零、每个非零类别都有可信价格时兜底。模型身份缺失、不完整 Kiro 测量、失败请求的未知占位、未知缓存写入价格仍显示未知。输入、输出、缓存读取、缓存写入分别计价，不把缓存当免费，也不重复当作普通输入。Gemini Pro 输入（含缓存）超过 200k 使用公开长上下文档位。

估算写入派生 `knownCost`，同时记录其子集 `estimatedCost`、`estimatedRecords`、`estimateSources`；不能再把估算子额加到总额。`sumCosts`、会话家族、分类、分页台账 SQL 总计均保留估算标记。卡片和金额显示「含估算」，明细给出参考来源和核实日期。对历史缺价记录，这是核实时公开参考价，不代表历史当时单价，也不改写原 JSONL。历史记录中已有的正金额不被当前表覆盖。

### 原生摘要的逐尝试补账

`native-compaction-usage.ts` 为非 Kiro 原生 compaction 观察每次逻辑 stream 调用：失败重试、前半摘要成功后后半失败也保留用量；未回传有效用量的尝试记未知，而非零消费。成功写入 checkpoint 后按单摘要 usage 身份、双摘要精确求和核对覆盖，只补未被 checkpoint 包含的尝试，不同时累加最终摘要和同一批请求。成功核对的新 checkpoint 在 `details.axiomNativeCompaction` 的版本化元数据中保留各请求的模型与用量；缺价时逐请求估价后汇总，不把两次 Gemini 输入合并后误选长上下文档位，也不猜旧 checkpoint 的模型。自定义或混合归属无法核对时明确未知，不猜测额外金额。Kiro 沿用独立测量 guard，后台 scratch 压缩沿用已有逐请求 billing，不重复安装。

补账在 compaction 结束时写入，**不是崩溃原子账本**；进程中途退出可能仍缺记录。`navigateTree` 的分支摘要失败重试不发 compaction 事件，本 guard 不覆盖；provider 传输内部的隐式网络重试、未上报 Token、历史未留存的失败请求和真实订阅扣款也不能从本机记录恢复。不能将本机统计宣称为供应商账单的完整复刻。

### 兼容聚合统计

生产 `usage.statistics` 接口也只读sidecar物化的同代汇总，未准备返回background状态，不在主进程现场遍历Costs；新版调用列表不使用这些聚合行分页。以下条目和下一节预算仅记录保留的旧 `app/src/server/model-usage-statistics.ts` 类与兼容单测，不再描述生产路由。名称更新随后台重新发布，不承诺查询即刷新。

旧类复用 `Costs` 的原生账务解析。按未归档项目中的、未软删除的主会话家族汇总；子 Agent、压缩、工具和记忆记录只计一次，不逐个子会话叠加 `Costs.get()`，也不同时累加报告总计与明细。历史分支与重试仍是已发生用量。

- 使用历史已记录价格，不按当前模型配置重算；仅完整 Token、可精确匹配公开价的缺价记录参考估算并标记。其他未知模型、费用、Token 保留未知。
- `records` 是用量记录数，不是 API 请求次数；部分工具记录本身可能是聚合结果。
- 未保留、已删除、已归档或上游未上报的消费不能据此还原。兼容聚合接口没有逐调用日期筛选；新版台账仅用原始记录中真实存在的时间。
- 支持按项目筛选及手动刷新，连接恢复后重新读取；不随每条消息重新全库统计。一次扫描同时形成供应商 × 调用来源、供应商 × 项目的聚合，切换供应商不重新扫描；不能只过滤模型表而保留全局概览。
- 供应商目录合并实际连接与历史账务中的供应商 ID；自定义连接名称保持独立，同名连接附 ID 区分，不将品牌相同的连接合并。历史无法归属的记录单列「未识别供应商」。
- 模型分布与计费明细使用相同可读名称，仅按 `(provider, 本地模型 ID)` 投影：配置覆盖名称优先，其次自定义定义名称，再取同 ID 的本地目录名称。不沿上游 ID 推测复制模型名称，不按名称合并账务；原始 ID 保留在提示中。未知内部配置显示「未知模型配置」，历史真实模型 ID 无映射时原样保留。名称不进入家族成本缓存，改名后重新读取统计即可生效；两个可选元数据文件各限 4 MiB，最多投影前 1000 行、名称最多 160 字符，损坏、超限或文件软/硬链接别名不隐藏统计。不读取认证来恢复账号范围目录，Kiro/带 `cacheScope` 的缓存名称保守跳过。
- 同筛选请求单飞，不同筛选排队；最多缓存 512 个家族摘要，以非消耗的 `Costs.version()` 校验，不能吞掉现有会话费用视图待接收的更新。
- 统计只读 JSONL。`openTranscript(..., {readOnly:true})` 使用 Pi 公开的 `parseSessionEntries` 和 `SessionManager.inMemory(..., entries)` 在内存迁移；不能调用 `setSessionFile`，因为 Pi 1.1.0 的文件加载器即使在内存 manager 上也会修补末尾换行。

### 兼容聚合接口预算

本节仅描述旧聚合类的历史预算与单测；生产`usage.statistics`和`usage.ledger`均由前述持久旁路提供，不在页面请求中运行此扫描器。

默认每轮最多 1000 个根家族、32 MiB 估算输入、5000 条家族数据库预检记录，每家族最多 512 个会话，软时间预算 3 秒。根会话以 `COUNT` 取得总数，实际加载使用 `LIMIT`；进入账务指纹和 JSON 解析前，以数据库 `length(... AS BLOB)`/限量查询和文件元数据预检压缩正文、完整记忆记录、会话与项目元数据、缓存账务及子任务实际使用字段，包括 ID 和标题。仅返回数字尺寸及限长 ID/路径，不把大正文物化到 JS；根列表也限制 ID 和项目名称的物化长度。

数据库估算为账务源的重复读取、会话元数据反复校验及每个历史文件的项目读取预留保守倍数；缓存命中仍计入指纹预算。**拒绝或异常的预检也累计已读取行数/字节**，耗尽全局预算后停止，不能让每个被拒家族重新取得完整额度。达到数据库 `LIMIT` 时保守返回部分统计，不额外读取越过全局上限的哨兵行；跳过的家族仍参与事件循环让步。

这些是资源与**软时间**预算，不保证单个 SQLite 查询或文件解析可被严格在 3 秒内中断。超过预算、源记录异常、扫描中数据变化时返回部分统计、已扫描/总家族数及警告；界面只保留必要的部分数据状态，不能把未扫描部分当作零。可按项目缩小范围。项目筛选列表最多返回前 1000 个未归档项目，超出时说明；不因此把全项目累计口径改为仅这 1000 个项目。

## 官方查询与认证管理

`ModelService.usageProviders()` 只读配置与凭据元数据，不初始化 SDK 模型目录、不解析命令型密钥、不刷新或迁移凭据。目录只下发连接 ID、名称、配置状态、查询能力及版本摘要；不返回模型数组、文件路径、密钥、请求头或凭据。配置状态仅代表本地已存配置，不保证令牌有效或具有额度权限。

所有连接通过 `ModelService.usage()` 使用本连接的只读认证和隔离网络。`openai-codex` 与其他供应商同路由，不再创建第二个 `ModelService`/`Logins`。尚无适配器或不支持当前认证类型时明确说明，不强迫用户额外登录，也不伪造虚拟 Codex 账号入口。

页面只展示同模型服务的认证来源、官方返回值、更新时间与刷新；缺失或过期授权均引导「模型服务设置」。筛选、表格与官方查询的迟到响应按连接、凭据和配置版本隔离；切换项目清除旧范围统计，刷新失败可以保留同身份的上次结果并标记。

调用表采用可配置列与容器内横向滚动，长名称截断并保留完整提示，数值紧凑显示及列内裁剪，不令页面横溢或侵入相邻列。切换工作空间、供应商或记录筛选时回到记录标识列。筛选使用原有 Select 的视口约束弹层、portal/top-layer、键盘与焦点管理。按扣除侧栏与留白后的内容宽度使用 container query：大于1060px五条件一行，481～1060px日期独行＋空间会话两列＋类型供应商两列，480px及以下单列；所有字段最小宽度为零、长选值截断，按钮独立位于末尾，表格只在局部横滚。窄屏触点至少44px。

## 统一 OpenAI 连接

根与应用的 Pi 依赖统一为 1.4.0。`app/src/server/providers/openai.ts` 复用 Pi 的原生 Codex OAuth、目录与推理实现，仅将展示名改为 OpenAI。模型目录、调用、压缩、记忆和额度共用主模型连接的 `openai-codex` 凭据与代理；不会复制/转换已有 `openai` direct grant、API Key 或历史用量账号的令牌。

所有运行时的 Codex Responses 调用统一设置 `transport: "websocket-cached"`，包括原始与 simple stream，以复用 WS 和符合条件的会话增量。Pi 仍可在输出开始前因传输失败安全降级 SSE；业务拒绝、取消与已经开始输出的请求不透明重放。这不是严格 WS-only，也不代表已验证真实握手或加速幅度。

独立用量账号实现与 RPC 已退役；旧 `<应用数据根>/model-usage/pi` 文件不读取、不迁移、不删除。用户若只有旧 direct/独立授权，应在模型服务设置中新建 OpenAI OAuth；实际授权仍由用户自行完成。已有 Codex 主模型凭据可继续使用，登录成功不等于真实模型或额度接口已验证。额度查询保持只读，不另行 refresh 或改写 OAuth；自然过期后在模型服务设置处理。

## 只读额度适配

- `app/src/shared/provider-usage.ts`：通用只读 DTO，窗口百分比、点数十进制字符串、次数和具备契约的绝对 Token 额度是独立指标。`null` 是未知，不是零；无限独立表达。当前 OpenAI 适配只返回前三类，不产生推算的绝对 Token。
- `app/src/server/provider-usage.ts`：后端适配器注册表、服务端刷新期限、缓存与单飞。当前支持 `openai`/`openai-codex`；均复用对应主模型服务认证和代理。API key 或其他未接入的连接不冒称可查询额度。仍不暴露旧 `configuration.usage` 命令或 `ProviderDraft.auth.usageSupported`。
- `app/src/server/providers/openai-usage.ts`：已知 direct grant 本地返回限制；legacy/未分类 OAuth 只调用两个 GET：`https://chatgpt.com/backend-api/wham/usage` 和 `https://chatgpt.com/backend-api/wham/rate-limit-reset-credits`。
- `app/src/client/models/ProviderUsage.tsx`：选中已接入供应商后按需挂载的紧凑指标渲染，按服务端 `nextRefreshAt` 设置自动刷新；可见视图到期读取，隐藏时不查询，恢复可见后最多补读一次，不补历史轮次。进入/重连是普通缓存读取，只有手动按钮传 `refresh:true`；不解释供应商私有字段。`refreshable:false` 或 `unsupported` 时停止轮询并禁用刷新，管理链接只接受无嵌入凭据的 HTTPS。

官方用量首次无缓存或自动期限已到时才只读获取；每次尝试完成后，生成 **30 分钟＋随机 0～10 分钟** 的下一期限，期间只读本地缓存。失败也推进同样期限，同一认证的旧成功结果保留原更新时间并明确标为旧数据，避免 15 秒重试风暴。手动刷新绕过自动期限，但保留至少 5 秒去抖；尝试后重置下一自动期限。同一后端实例内按身份单飞，多标签页/重挂载不重抽期限。

`provider-usage-cache.ts` 将脱敏 DTO、身份摘要、尝试时间及期限持久化到 `<应用数据根>/model-usage-cache/<目录身份摘要>/<供应商摘要>.json`，不写认证或模型配置，不存令牌、账号 ID、代理秘密或上游原始数据。缓存按主模型认证目录命名空间，并按供应商、凭据、保存配置和代理运行态校验；不再读取旧独立目录的缓存。重启恢复原期限，逾期只补当前一次；不会在无人观看时后台遍历所有供应商。目录/文件采用私有权限、原子替换，缓存读取有 256 KiB、结构与时间校验，并拒绝缓存软/硬链接和目录别名。缓存不可用时降级内存，不影响只读查询。链接校验不承诺抵御同 UID 恶意进程并发替换父目录；当前也不宣称多个并行后台进程共享根目录时存在跨进程查询锁。

每次读缓存及异步上游结果返回前均复核认证、自然过期及 direct 限制；失效不显示旧数字，不将单纯身份摘要相等误认为令牌仍有效。调用经供应商隔离的 `modelNetwork` worker，不修改主进程全局代理。

额度查询通过 Pi 的 `readStoredCredential` 只读自身凭据，不调用 `getAuth`/`prepareAuth`，不刷新、不推理、不消费。固定官方目标、禁止重定向、限制响应大小与总时限。卡 ID、账户 ID、令牌和原始上游错误正文均不下发；只保留白名单错误诊断，区分过期、401/403、429、服务错误、响应无效、网络失败和超时。401/403 不擅自等同于“需要重登”，也不证明整个套餐已耗尽。

未来供应商的字段解析应留在后端适配器，前端沿用通用指标 DTO，并复用已有主模型认证的只读查询，不新增第二套登录、认证准备或写入。

### 可用金额估计

窗口同时展示已用与剩余百分比。**OpenAI 当前只有窗口百分比、点数和次数，没有已核实的绝对剩余 Token 或点数到美元/Token 的换算契约**，因此仍不能给出官方美元余额，不能把点数直接当美元，也不能虚构绝对 Token 上限。页面另外提供下述明确标记的“本机样本估算”，不再将“无法精确兑换”解释为一概不允许参考外推。

通用 `tokens` 指标只有适配器确有绝对额度契约时才可返回，包含精确本地模型 ID、已用/剩余 Token 和可选 Token 类别。此时才读取 `usage.pricing` 的当前本地配置单价：按每百万 Token 计算。类别明确时使用对应单价；未知配比时必须拥有完整四项价格，展示最小到最大参考区间。缺价、错模型、阶梯价或剩余未知都不估算；不沿上游模型 ID 借价。估值明确不是上游美元余额，与历史已记费用分离。本地价格读取有界只读，不初始化 SDK、不解析密钥、不拉远程模型目录，也不返回完整编辑配置。当前数值估算分支仅有隔离 fixture 验证，不能称真实 OpenAI 已有可估余额。

### OpenAI 满额度金额外推

在“官方额度”明确选中 OpenAI 模型连接时，在其剩余用量区域展示 **预估总可用金额（USD · 本机样本估算）**。主／次窗口（通常为5小时／7天）各自展示100%总金额和剩余金额，**各窗口是同一订阅的不同限制，不可相加**。Spark 等额外窗口没有已核实的模型归属映射，不参与此估算；只读取当前主连接同 provider ID 的历史，不合并 `openai` 与 `openai-codex` 台账。

实现位于 `app/src/shared/quota-estimate.ts` 和 `app/src/client/models/ProviderQuotaEstimate.tsx`：

- 用官方窗口的 `resetsAt − windowSeconds × 1000` 推导采样起点，以官方响应的 `updatedAt` 为截止，不将缓存之后新产生的本机费用除以旧百分比。起点仍依赖固定窗口假设，不是新的官方计费契约。
- 以所选 OpenAI 供应商的完整本机账务总计为样本，复用 `usage.ledger` 的 `providerId/from/to/pageSize:1`，不继承历史页工作空间、会话、类型、日期或搜索筛选，也不拿当前页小计外推。跨工作空间的同供应商记录只计一次，既有台账去重、价格来源和费用规则不变。
- 样本金额 `C = total.knownCost`，官方已用 `p%`：**100%总金额 = C ÷ (p / 100)**；**剩余金额 = 总金额 × (1 − p / 100)**。`knownCost` 已包含 `estimatedCost` 子集，不再重复相加。沿用历史已记价格及已有公开参考估价，不按当前配置重算历史，不声称它是订阅实际扣款。
- 只对 ready、非旧数据、尚未重置且窗口／采样时间合法的指标计算。`p=0/null`、无正金额样本、扫描未完成／部分、存在未计价或不完整 Token、非有限数均显示“—”及原因；有效100%已用样本才显示剩余0。低于5%的样本标记低比例，极小正金额用科学计数法保留。
- 悬浮可核对精确采样时间、账务条数、样本金额及公式。可见提示“按本机记录外推，非官方余额”；主认证不能证明历史未换号，其他设备消费、百分比舍入及模型组合变化也都会造成误差，不能将此结果称为严格上下界或官方套餐价值。
- OpenAI/Codex 的本机样本与官方查询均来自当前选择的主 provider。共用当前凭据不能证明历史未换号，也不能归并其他设备消费；因此保留明确的历史换号与设备覆盖警告，不追认旧账务的账号身份。
- 仅合法窗口才按需读取本机样本，共享持久旁路台账；先等待后台building/updating，再检查保守水位。若水位早于官方采样截止则仅提交一次后台重核意图，仍旧则不外推，主／次窗口不各自强刷。准备中每1秒读缓存，最多64次或60秒后停止并提示重试（无background的兼容fixture仍沿用100ms）；隐藏、离开标签或切换连接停止后续读取，迟到结果不能覆盖新连接。官方重置时即撤去旧金额。手动刷新为整组窗口提交一次本机重核，即使官方缓存采样未改变；官方查询的30～40分钟节流及主凭据/缓存隔离协议不变。派生金额不写官方缓存、认证或原生历史。

这是一种依赖本机覆盖率和账号一致假设的外推工具，而不是从单价与百分比本身就能精确还原的官方余额。没有可用样本或官方授权不能查询时，不伪造数字。

### 应用级 WS 接口

以下命令拒绝顶层 `workspaceId`/`sessionId`，不允许客户端指定认证文件路径：

- `usage.statistics`：读取已物化兼容汇总，可用`params.workspaceId`筛选项目；返回全局及供应商维度的Token、来源、项目与模型汇总，模型行可含轻量可读`name`，另有background状态；不调用旧主进程scanner。
- `usage.ledger`：只读已物化账务报告；`params`可含`workspaceId/providerId/rootSessionId/requestType/agentRole/query/from/to/page/pageSize/snapshot/refresh/continue/analytics/timeZone`。`providerId`缺省是全选、null是未知，`pageSize`最大100。`continue:true`兼容旧调用方但不驱动扫描；`refresh:true`仅标记后台异步重核。未命中的合法报告注册有界后台任务并返回preparing；返回匹配总数、完整筛选总计和当前页，附快照、保守水位、范围计数、partial警告与background状态。`analytics:true`包含相同筛选完整集趋势与分布，`timeZone`为经过校验的IANA时区（缺省UTC）。后台完整发布新代，跨代旧页回第一页。
- `usage.workspaces`：轻量未归档空间 ID/名称，最多1000，不扫描历史。
- `usage.sessions`：可选`params.workspaceId`，返回`{sessions:[{id,title,workspaceId,workspaceName}],truncated}`；排除已删除、归档空间及任务子会话，最多1000，元数据只读。`usage.ledger`的`rootSessionId`选择该主会话归属账务，`requestType`可为`main/subagent/compression`，兼容的`agentRole`只能是`main/subagent`，缺省均不限制。
- `usage.pricing`：给定 `params.providerId` 的有界当前本地模型单价，不改变历史费用。
- `usage.providers`：轻量只读连接目录与查询能力。
- `usage.provider`：必须指定 `params.providerId`，一律由主 `ModelService.usage()` 只读查询，包含 `openai-codex`；请求断连可停止该视图等待；服务级单飞上游尝试独立存活，最多 10 秒，避免某个标签断开影响其他查看者。
- 已删除 `usage.account.*`、`usage.auth.*` 路由及 `usage:account`、`usage:authentication` scope；旧客户端请求会被拒绝，不会隐式登录、访问或删除旧凭据。
- `usage:providers` scope：配置更新的轻量失效版本；统计页只订阅此版本，不为监听变更下载完整 `configuration.available`。

## direct 授权限制与历史 401

早期供应商内嵌展示的只读诊断曾从运行实例确认 OpenAI 聚合查询出现 HTTP 401。它仅证明至少一个 GET 被拒绝，不证明两个 GET 都是 401，不确定拒绝的具体原因，也不是当前独立页面已经部署或实际授权成功的证据。

新版 `openai` OAuth 与 legacy `openai-codex` grant 不相同。对照 sub2api `ba81c7fd758e425d67f856d601147ef0c5263d3f`：

- Pi 1.1.0 `openai-chatgpt.js` 使用动态 client、`/api/accounts/authorize`、`/api/accounts/oauth/token`，指定 `resource=https://api.openai.com/v1`，scope 包含 `resource.invoke chatgpt.tokens.use.direct`。
- sub2api `backend/internal/pkg/openai/oauth.go` 使用 Codex 固定 client、`/oauth/authorize`、`/oauth/token` 和 `openid profile email offline_access`，不指定上述 resource，与 legacy Codex 流程相近。
- sub2api 使用该账号 access token 查询相同两个 wham 地址；其 code exchange 是授权码兑换，不是 direct → wham token exchange。补请求头/TLS 指纹不能被当作授权转换的证据。

官方 [Token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference) 指明 direct token 的 audience，并要求认证 metadata 视为 opaque；[Tracking usage](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions#tracking-usage) 指引链接到 [ChatGPT 用量页](https://chatgpt.com/settings/usage)，没有提供点数/重置次数查询契约。目前未找到已核实的 direct → wham 转换，不等于证明官方内部绝无接口。

后端只在存储的 `scopes` 显式包含 `chatgpt.tokens.use.direct` 时本地返回 `refreshable:false` 与官方 HTTPS 管理链接，清除旧缓存，不读 opaque metadata、不启动 worker、不请求 wham。不能只凭 provider 名称猜 grant 类型。legacy/未分类凭据仍尝试只读查询；可用账号 ID 时条件添加 `chatgpt-account-id`，缺少时不本地提前拒绝，由上游判断。

## 重置与消费边界

用户允许后续提供手动重置入口，本轮没有实现 consume、重置或充值按钮。查询只有 GET，不自动消耗可用次数；不能把本地冷却重置、充值或授权重新登录当作官方重置。

后续消费实现必须另行完成明确确认、幂等与互斥、防重复提交、账号/版本复核，并区分“已消费但刷新失败”与“未发送”。查询失败、次数未知或旧数据不能作为可消费依据；不能自动重试消费。本代理测试不得点击真实重置或发真实 consume。
