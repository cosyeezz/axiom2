# 会话渐进式记忆与全局查询方案

状态：会话记忆、同步查询、后台整理和浏览界面已实现。查询与整理已接入统一 pi 执行池，每次新建独立内存会话与权限闭包；固定环境可跨任务复用，生产性能与容量验证见 [执行池说明](pi-execution-pool.md)。本文描述当前实现及约束，记忆功能验证范围与未验证项见第 11.3 节。

本文作为 [产品设计](design.md) 的专项方案。现有 pi 会话、压缩、主／子 Agent 与工作空间隔离仍遵循产品设计；会话删除、记忆加载和执行方式的说明与产品设计及 README 同步维护。

## 1. 目标与基本原则

长时间执行和多轮上下文压缩可能丢失目标、约束、决定及执行细节。本方案通过持久资料和渐进读取，帮助当前会话恢复工作，也让其他会话查询已有经验。

整体机制：

1. 主会话通过系统提示词了解记忆文件能力，用现有文件工具维护简要入口与详细资料；入口包含简要过程，每次压缩后主动重新读取。
2. 后台定时整理这些资料，检查相关记忆中的冲突，按证据修正或删除具体条目，并生成独立的全局摘要索引。
3. 主 Agent 根据记忆查询工具的能力描述，自行决定何时调用同步查询工具。
4. 工具内部使用独立 pi Agent，按需读取摘要、详细资料和引用文件，整理后返回；资料不足时明确说明。
5. 每次查询或整理借用统一池的独占租约，使用全新的内存会话、loader、settings 和工具闭包；清理确认后归还可复用环境。
6. 在输入框下左侧用量区提供上下文与本会话记忆合并入口，右侧工具区提供全局记忆入口；任务进度在合并入口展开后显示。

基本原则：

- **可选辅助**：记忆初始化、读取、扫描或查询失败不阻断会话创建、消息发送或恢复；读不到、归属不匹配时返回空记忆，不弹出读取错误。发送不等待记忆扫描。写入、纠正及本地打开仍校验归属、路径与修订，失败不得伪装成功。
- **事实与来源优先**：根据会话中的实际陈述、操作和结果记录，不捏造，不凭模型主观判断裁定对错；允许依据用户明确纠正和可核实证据修正或删除记忆。
- **简要不等于遗漏**：入口压缩表达，必要细节保存在专题资料中，重要事实应有可追踪的阅读路径。
- **渐进加载**：先读入口或摘要，涉及细节再读资料；详细资料应能独立解释背景，信息不足时保留未知。
- **职责独立**：程序只初始化会话记忆入口 MEMORY.md，主会话按需要创建分类目录与资料并通过现有文件工具维护；后台核实当前事实并清理冲突，查询 Agent 保持只读。
- **历史保留**：压缩和会话列表删除不删除原始对话及会话文件绑定；原始对话不进入本记忆机制的查询或冲突核实流程。
- **上下文隔离**：每次记忆执行使用独立租约和会话，查询消息、权限归属和执行状态不能串入下一次查询。
- **现状如实表达**：正在进行、尚未验证、资料过期、召回截断和查询未完成都须明确标记。

## 2. 系统组成与职责

| 部分 | 职责 | 写入范围 |
| --- | --- | --- |
| 主会话 Agent | 用现有文件工具维护目标、约束、进度、简要过程、结论、专题详情与文件引用 | 所属会话的记忆目录 |
| 记忆目录与变更管理 | 初始化 MEMORY.md、保存归属及文件绑定、监听变化并更新修订与展示 | 入口模板及所属元数据 |
| 后台整理任务 | 定时检查记忆冲突，核实当前事实后修正或删除条目，直接处理用户明确否定，生成摘要和检索信息 | 对应会话记忆条目、相关入口和引用、全局摘要索引；不改原始对话 |
| pi 查询 Agent | 检索摘要、阅读详细资料与引用文件，整理查询结果 | 不写会话记忆和项目文件 |
| 记忆执行器 | 从统一池借用固定能力实例，联合限制并发与等待，逐租约绑定并校验清理 | 运行管理状态及真实用量 |

原始 pi JSONL 继续用于真实对话的持久化与恢复。程序保留会话 ID 到实际对话文件的绑定，模型不维护这份绑定。记忆是补充资料，不替代 JSONL，也不通过另一份对话副本重建 pi 会话。

本方案中的查询 Agent 是同步工具内部的专用执行者，不改变现有 delegate、append、cancel_task、read_result 四个独立工具的契约，不递归委派。

## 3. 会话记忆目录与入口

### 3.1 统一存储

资料保存在 Axiom 应用数据目录，不写入用户项目的设计源目录：

```text
memory/
  sessions/
    <sessionId>/
      MEMORY.md                # 程序初始化的会话入口
      references/              # 模型按需创建：详细过程、调查、方案与验证文档
      scripts/                 # 模型按需创建：可复用脚本
      artifacts/               # 模型按需创建：报告、截图、导出文件等产物
```

后台摘要与检索索引保存在应用 SQLite 的 `memory_sources` 中，与文件修订绑定；不额外生成一套磁盘 catalog。应用数据根在存储入口解析并固定为真实路径，兼容 macOS 系统目录别名和 Windows 短路径；根以下的记忆目录与文件仍拒绝符号链接、目录联接及硬链接。初始化逐级校验目录后创建下一层，拒绝链接时不向其目标创建入口或后代目录。

每个主会话拥有独立目录，并保存与工作空间的稳定归属。程序在创建主会话时只初始化 MEMORY.md 模板及其必要父目录，不预建 references/、scripts/、artifacts/ 或其他资料文件；恢复会话或重复初始化不得覆盖已有内容。上述分类目录与文件由模型按需要创建，不生成空目录。后台索引由整理任务生成，不属于主会话资料预建范围。创建入口失败按无记忆继续创建会话；提供的入口路径只表示所属记忆位置，不保证文件存在或可读。

模型使用现有 read、edit、write 等文件工具维护文档、脚本和相对引用，不另设专用记忆更新工具。程序监听实际文件变化，更新修订信息、TodoList 并标记待整理资料；不按两次保存之间的消息范围自动推定事实来源。目录归属和实际对话文件绑定由程序维护，路径示意不代替归属校验。

详细资料不限制文档个数，按自然主题拆分，可使用相对路径引用所属目录下的其他文档、脚本和产物。引用项目中的当前文件与保留的历史产物时须明确区别，避免把变化后的文件当成历史快照。

### 3.2 MEMORY.md 内容

| 内容 | 记录重点 |
| --- | --- |
| 目标与范围 | 用户最终要达成什么、验收条件、尚未明确的范围 |
| 要求与约束 | 用户明确要求、限制、偏好、纠正及已授权事项的适用范围 |
| 任务进度 | 整体状态、整体进度估计、当前进展、任务标题及已完成／进行中／未开始／阻塞状态，供 TodoList 展示 |
| 简要过程 | 关键尝试、重要发现与转折、做到哪里；具体过程链接到详细文件 |
| 结论与决定 | 会话形成的结论、采用的方案与原因 |
| 验证情况 | 实际检查内容、结果、尚未验证事项 |
| 下一步与接续位置 | 下一步、待处理问题、进行中的子任务与结果位置 |
| 资料导航 | 按详细资料、脚本、产物分类，记录主题、相对路径、简要用途和何时需要阅读 |

程序按上表生成固定栏目，供模型填写及界面直接解析；初始内容仅表示“尚未填写”或“尚未记录”，整体进度为“待评估”，不填入虚构目标、任务或默认百分比。空清单不代表工作已完成；初始模板也不发起模型请求。

入口应简洁但全面。不能只列文件名，也不能省略重要要求后没有任何详情入口。入口优先保留当前目标、有效约束、正在进行的工作、简要过程和接续位置；用简短描述说明关键尝试及其结果、重要转折与当前停点，具体过程移入专题文件并保留链接。进度表达当前状态，简要过程解释如何到达这个状态。

入口通常保持约 1,000 字，全文最多 2,000 字，包含正文与资料导航。超出时由模型将细节移入分类文件，保留关键状态、简要过程和引用；程序不直接截断文件。详细文件不设统一字数上限，按主题拆分，数量不设固定上限；单次读取预算、分页及总体查询预算另行配置，不能每轮加载全部文件。

整体进度由主 Agent 结合已完成工作与剩余工作量估计，记录为“整体进度：约 50%”等，以 10% 为步进。只有任务确认完成才记为 100%；仍有待完成工作或必要验证时最多约 90%。本次授权工作与必要验证完成后，应在最终回复前同步状态及 100%，不能仅因等待用户查看而保留 90%。范围扩大、发现新问题或任务重新打开时，状态、进度及下一步随之更新，允许下调百分比。整体进度是明确标注的估计，不等于任务项数量的完成比例。

### 3.3 可独立理解的详细资料

详细资料应讲清问题背景、适用条件、已知事实、关键尝试与实际观察、采用或放弃方案的原因、实施与验证情况、尚未确认内容，让其他会话无需阅读原始聊天即可理解和使用。入口中的简要过程链接到对应专题，具体过程在专题中按必要顺序说明，不只保留最终结论。

过程记录以理解决定、接续工作和避免重复踩坑为目的，不逐轮抄写对话或保存每次工具调用。真实发生且有参考价值的失败尝试应说明当时条件、结果及适用范围；已排除的推测明确标注为已排除，不混同于事实。进行中的资料保留当前停点和下一步，完成后在同一主题文件中整理关键过程与结果。

每份资料按自然主题维护，已有对应主题时局部更新。文档、脚本和产物通过相对路径引用；项目文件、报告或子任务交付已经承载详情时，可以直接引用实际位置，必要背景仍在记忆中说明。不要求主会话标注逐条消息身份或维护精确对话来源。

例如，关于会话恢复的专题可以说明问题出现条件、用户要求、所选方案、改动位置、当时检查结果和未验证场景，并链接已保存的报告。示例中的验证必须以实际执行为依据，缺少报告或依据时明确说明。

脚本应记录用途、适用条件、是否实际执行以及当时结果。脚本存在不等于执行成功；查询 Agent 阅读脚本内容，不自动执行脚本。

## 4. 会话记忆维护与恢复

### 4.1 内容维护与所有权

主会话在首次接到明确任务时读取入口并填写真实目标、约束、任务清单与初始进度，在重要进展、范围变化或用户纠正后局部更新，最终回复前同步本次结果、验证及下一步；授权工作与必要验证全部完成时写已完成及100%，不因等待用户查看而保留90%。除此之外由模型判断值得记录的内容，不按固定轮次或工具次数刷写。同一主题复用已有文档，不反复重写整份记忆。系统提示词说明这些维护时机、分类规则、字数上限、进度估计及恢复要求；固定栏目和字段格式由模板承载。

子任务结果通过现有交付机制返回主会话，由主会话阅读后把可复用的结论、背景和未完成项纳入记忆。子 Agent 不共同写主会话记忆目录；已有报告或产物可以直接引用，不要求额外整理子会话消息关系。

用户也可以修改记忆。Agent 编辑前读取当前文件并优先使用精确局部修改；用户编辑入口与后台提交校验读取版本，冲突时重新读取并合并，不用旧副本覆盖新内容。文件变化检测与并发保护沿用通用文件操作边界，不增加模型需要填写的专用维护协议。

其他会话默认只读来源资料。发现不同结论时，在本会话记录新事实并关联旧来源，不直接改写其他会话的记忆。后台整理任务依第 6 节处理已核实冲突或用户明确否定，是跨会话清理来源记忆的限定入口，同样须校验归属与修订。

### 4.2 内容演进

所有内容依据最新事实和状态变化同步更新；任务状态、整体进度估计、关键结论与下一步须保持一致，不能保留互相矛盾的当前状态。入口始终表达当前有效状态；重要的目标变化、被替代方案及其原因保存在详细资料中，必要时引用相关文件或产物。重复内容可以整理，已有事实依据不能因缩短入口而消失。已核实不符合事实或用户明确否定的记忆条目按第 6 节修正或删除；真实历史不因现状变化而自动删除。

专题拆分、移动、合并或条目清理时，同步维护入口和引用。记忆对象使用稳定标识与修订信息，使摘要可以检测来源变化；不能让旧摘要静默指向无关的新内容，或让已删除条目继续从旧摘要中召回。

### 4.3 系统提示词与压缩后重读

主会话系统提示词告知记忆文件能力与内容规则，不讲解如何调用文件工具：

> 记忆是可选辅助资料。入口缺失、无法读取或归属不匹配时按空记忆继续当前任务，不报错、不等待修复或中断主流程，不声称已恢复未读到的背景。本会话的记忆入口为 `<路径>/MEMORY.md`，用于维护目标、约束、任务状态、进度、简要过程、关键结论和下一步。首次接到明确任务时读取入口并填写真实目标、约束、任务清单与初始进度；重要进展、范围变化或用户纠正后及时局部更新；最终回复前同步本次结果、验证、任务状态及下一步，授权工作与必要验证全部完成时写已完成及100%，不要仅因等待用户查看而保留90%。所有内容应依据最新事实和状态变化更新，保持一致，明确区分已完成、进行中、计划和未确认事项。入口保持简要，通常约 1,000 字，最多 2,000 字（含资料导航）；详细内容移入分类文件，入口保留关键状态、简要过程和引用。详细文档放入 `references/`，可复用脚本放入 `scripts/`，报告、截图等产物放入 `artifacts/`；程序只创建 MEMORY.md，其余目录和文件由你按需创建，并在入口分类引用、简述用途。在入口记录整体进度估计，以 10% 为步进，并随最新任务状态调整；只有任务确认完成时才记为 100%。每次上下文压缩后，先重新读取入口，再继续工作。

程序提供所属会话的入口路径，不承诺文件可读。用户的新要求优先于旧记录；文件读取失败按空记忆继续，不假定已恢复全部背景。系统提示词不规定维护频率，也不要求模型逐条标注消息来源。

记忆正文由主 Agent 主动读取，不在每次模型请求前自动注入最新文件全文。自身记忆的直接读取不调用 memory_query，也不启动独立查询 Agent。

程序根据真实压缩应用事件提供“需重新读取本会话记忆”的状态提示，使系统规则能在下一次继续执行时生效；后台压缩尚在生成或等待应用时不提前要求恢复。覆盖后台、手动及原生恢复中实际应用的压缩；重读通过实际工具调用完成，不能将提示已送达视为文件已读取。读取失败记录独立的不可用尝试标记，同一压缩不重复提示，不把失败标为读取成功，也不阻断后续工作。

后台压缩基于较早快照生成的摘要不得覆盖执行期间更新的记忆。原生压缩与会话记忆保持独立；原始 JSONL 的恢复规则不变。

### 4.4 本会话任务进度入口

上下文与本会话记忆合用输入框下左侧用量区起始按钮，全局记忆 SVG 按钮紧接压缩图标，不新增独立底栏或文字行。合并图形为20px细实线灰环，橙色弧长表示真实上下文使用量；内部三条细横线在有效任务进度达到三分之一、三分之二和100%时依次点亮，未知或矛盾时全部保持灰色。所有视口入口只显示图标，百分比、Token和任务估计集中到详情；任务完成只点亮内部三条，不改变外环。普通记忆图标统一16px、1px非缩放描边，数据图形1.3单位描边，内部横线0.65px；亮色为暖琥珀色 `#fcbc7c`。44px点击区域单排，保留左指标／右工具分组，组内间距0、组间弹性留白且最小8px，容纳不下时工具栏内部横向滚动。点击合并图标展开上下文数据与 TodoList，再按需查看完整记忆。视觉沿用 [设计交接](../ui/DESIGN-HANDOFF.md) 指定入口的字体、颜色与图标语义；左侧统计浮层最大520px、窄屏两侧留12px，完整记忆使用贴顶贴右抽屉、最大520px且窄屏满宽，不修改 ui/ 原始设计源。

TodoList 是当前查看主会话 MEMORY.md 的展示投影，不另建独立任务状态，不从聊天文本或 Agent 是否运行推断完成情况，也不启动模型生成展示内容。

| 展示位置 | 内容与行为 |
| --- | --- |
| 收起入口 | 细实线灰环上以橙色弧长表示上下文占用，内部三条细横线表示任务三等分进度，三条全亮仅表示已完成；不显示数字，未知保留灰环，准确比例及超限量留在详情；悬停说明上下文与任务状态 |
| 展开区 | 上下文 Token／容量、估算口径及超限量；记忆目标、整体状态与模型估计进度（未完成标“约”）、独立的已完成数量、任务清单、当前进展、下一步和“查看完整记忆”入口；点击外部、关闭按钮或 Escape 收起 |
| 本会话记忆详情 | 点击“查看完整记忆”后展示完整 MEMORY.md，包括简要过程及分类资料导航；不切换聊天会话 |
| 详细资料 | 显示文档名称和简要用途，点击阅读对应文档 |
| 脚本 | 显示脚本名称和用途，点击查看内容，不自动执行 |
| 产物 | 显示报告、截图等文件，按支持能力预览或打开 |

展开区内的任务进度条与百分比直接读取主Agent写入的整体进度估计，以10%为步进；界面小于100时保留“约”，100%仅用于明确完成。记忆文件仍保留估计口径及有效性校验。完成任务数量独立计数，不直接换算为工作量百分比。没有清单时不显示完成数量；已记录任务但无法解析有效估计时显示“进度待评估”，不填充虚假进度条。百分比超出范围、不符合步进或与完成状态矛盾时标为待核对，不由界面猜测修正；范围扩大或发现新问题后允许随记忆更新下调。

2,000 字限制针对记忆入口文件，不要求全文显示在 TodoList。具体过程留在记忆详情及引用文件中；分类下没有资料时不显示该分类，不为缺失目录报错。尚未记录任务时图标悬停说明“暂无记录”，展开说明“还没有任务记录”，不重复显示多个未知状态。文档查看、编辑和保存遵循归属与修订校验规则；任务状态图标用于展示，不直接通过勾选改变执行事实。

仅订阅当前查看会话的记忆修订，文件更新后局部刷新，不重建聊天区，不干扰输入、选区与展开状态。切换会话后切换数据归属并忽略旧响应；初始化或读取失败显示空态，不启动模型生成占位内容，存在未保存编辑时不得以后台更新覆盖。任务入口始终对应当前会话，右侧全局记忆入口用于跨会话浏览。

## 5. 会话文件绑定与保留

程序保存 workspaceId、sessionId、记忆目录与 pi 实际对话文件的绑定关系，使用真实路径，不根据会话 ID 猜测文件名。这是会话管理元数据，不要求模型写入 MEMORY.md，也不自动推定记忆条目的消息来源。

原始对话用于持久化、恢复和历史保留。记忆查询、全局记忆浏览和后台冲突核实均不读取原始会话文件，不建设专用历史消息检索、定位、预处理或展示能力。阅读记忆资料沿用现有文件工具的搜索、分段读取和截断提示，读取预算与查询总预算分别配置。

会话列表删除采用逻辑删除：按既有停止边界结束所属活动执行，再从 Axiom 普通会话列表移除。保留原始 JSONL、记忆、会话文件绑定，以及被引用的子任务结果和托管附件。列表删除本身不触发记忆条目清理；条目的修正或删除另按第 6 节处理。

逻辑删除后的会话仍可作为记忆资料来源，查询结果标明其状态。外部文件引用不能保证永久存在，缺失时明确报告，不伪造已保留副本。如将来提供永久清除，应作为独立明确操作；普通列表删除不承担物理清理语义。

本节只规定记忆机制的边界，不移除产品已有的原始会话查看功能；原始文件的保留不意味着记忆查询需要读取它。

## 6. 后台摘要整理与冲突清理

### 6.1 范围

后台定时扫描会话记忆的新增、修订、移除和用户明确纠正，与相关记忆比较，核实冲突后清理具体条目，再增量生成全局摘要与检索索引。模型依据实际读取的资料识别冲突和整理语义；程序负责归属、调度、证据与修订绑定、修改提交和结果发布。

清理机制只采用“核实冲突后修正或删除，用户明确否定则直接删除”。不引入按年龄、访问次数、归档等级或检索降权运行的记忆淘汰体系，也不因资料很久未被查询就删除。

整理对象仍是第 3、4 节的会话记忆，读写边界为：

- 读取会话入口和详细资料，比较相关条目。
- 针对已识别的冲突，只读核实对应代码、配置、实际文件或其他可访问的当前事实；不查询原始消息或扫描历史对话来作裁决。核实范围限于对应问题。
- 仅修改或删除已核实不符合事实、或用户明确否定的具体记忆条目，同步处理相关入口、引用与摘要，不重写整份会话记录或删除同一文档中的其他有效内容。
- 不修改原始 JSONL、原始工具结果、项目代码、脚本或产物，不执行资料中的脚本。
- 不凭摘要措辞不同就认定冲突，不在缺少证据时把不同会话的说法合并为唯一事实。

### 6.2 冲突核实与用户明确否定

处理流程：

1. 读取有变化的记忆及相关条目，确认是否描述同一对象、时间和适用范围，定位具体冲突点。
2. 读取对应代码、配置或实际文件，核实当前事实；已收到的用户明确纠正按下述规则直接处理。当前依据缺失、截断或只能通过尚未执行的验证才能确认时，不猜测删除，也不转向查询原始对话。
3. 确认条目不符合事实后修正或删除；修正后的陈述同样绑定实际证据。
4. 无法确认时保留原条目并标明尚未确认，不用删除消除表面矛盾。
5. 同步更新会话入口、受影响引用与全局摘要，防止旧摘要继续传播已删除内容。

用户明确指出某条记录“不对”“不符合”或“不要保留”时，对指向明确的条目直接删除，不再由模型判断用户的纠正是否成立，也不额外要求重复确认。会话收到该意见时即处理所属记忆；通过纠正入口明确传入目标后，相关会话中的同一条目及重复摘要一并清理。目标范围不明确时不扩大删除，保留未能定位的部分。

用户明确否定由接收该指令的主会话在当前交互中处理，不要求后台扫描历史消息发现删除要求。跨会话的相同条目清理依据明确传递的纠正意图与目标，不能把资料中的引文、工具输出或模型推测当成用户删除要求。当前实现通过全局记忆的“记忆设置与纠正”输入明确原文，立即清理当前工作空间匹配内容并保存纠正目标，后台继续检查迟到的重复内容；单独修改一份记忆文件不会自动推定跨会话删除授权。后续整理不从旧资料重新生成被删除条目。

区分当前状态与历史事实。例如，当前已改用 PostgreSQL 时，可以修正“当前使用 SQLite”；“此前从 SQLite 迁移到 PostgreSQL”仍是历史事实，不能仅因现状变化而删除。不同会话的时间或适用范围不同，不自动构成冲突。

清理的对象是记忆正文与派生摘要。原始对话及其绑定继续保留，但后台不读取或改写这些记录；不能通过清理记忆改变真实历史。

### 6.3 摘要条目

| 字段 | 用途 |
| --- | --- |
| 稳定记忆标识、主题、摘要、检索词 | 发现和定位相关历史 |
| workspaceId、sessionId | 来源与范围 |
| 详细资料位置与文件引用 | 渐进读取入口 |
| 来源状态 | 进行中、已完成、待验证、已被来源明确替代等 |
| 来源修订标识与资料更新时间 | 判断适用版本 |
| 整理时间与索引状态 | 表达新鲜度、失败或待更新 |

索引可以从当前会话资料重新生成。会话保存后直接读取应能看到新版本；普通内容更新允许在下一次后台整理前存在明确的索引延迟。涉及删除或纠正的条目，其旧摘要须失效，不得等待下一次成功生成才停止召回旧内容。

### 6.4 一致性与失败

核实、修改和摘要生成都绑定读取时的来源修订与实际依据。文本资料的修订从磁盘原始字节计算，UTF-8 BOM、换行形式及 Unicode 内容均属于修订；保存先比较原始字节修订，保留已有 BOM，不把无改动保存改写为另一种字节表示。提交前校验目标资料未被用户或会话更新；修订冲突时重新读取并核对适用范围，不能用旧证据覆盖新内容。每次只提交已核实的对应条目，不覆盖整份文档中的无关修改。

整理的读证据必须从偏移量零开始、在同一修订中连续覆盖到末页。尾页、缺页或读取中途修订改变都不是完整证据，不能用于发布摘要或编辑资料；完整长文的编辑使用累计的已读正文，不回退到只读首屏。

摘要发布前复核修改后的来源。来源变化时不得将旧结果标为最新；未受删除或纠正影响的上次成功摘要可以保留并标明待更新，受影响部分必须失效。摘要生成失败不回填已删除条目，不能用旧摘要恢复来源记忆。

资料读取失败不等于资料删除，模型请求失败不等于没有记忆；核实失败则保留条目并报告未确认。修改失败不能发布声称清理成功的摘要或结果。

后台任务不重叠修改同一来源资料或同一批索引，退出时释放拥有的执行资源。整理模型、周期、并发与预算需要独立配置，模型用量纳入实际记账，不宣称整理免费。

全局统一存储，默认按当前工作空间检索；冲突核实与清理遵守同一归属边界，跨工作空间操作必须显式指定范围，并经过实际授权校验。

## 7. 同步记忆查询工具

### 7.1 对外契约

向主 Agent 提供一个同步工具，暂名 `memory_query`，输入问题与允许的查询范围。工具描述明确告知它能查找记忆中记录的历史工作、决定、问题处理与验证情况，按需阅读详细文档和引用文件，返回事实整理、资料来源和未确认项；不提供原始对话查询。模型依据当前需要自行决定何时调用，不规定每次任务开始、每轮对话或压缩后强制查询全局记忆。

调用方等待一次调用的结果，不通过 delegate 创建异步子任务，也不另行领取查询结果。全局记忆查询的自主调用与第 4.3 节规定的本会话压缩后重读分别处理；后者是主会话必须遵循的恢复规则。

同步指工具等待语义，服务内部采用异步执行，不阻塞其他会话或服务事件循环。主／子运行结算、根会话恢复或错误恢复只定向刷新其实际归属来源；无法确定单一归属时才恢复同一工作空间的可访问来源，不能让一条事件误触发无关工作空间的查询或扫描。

查询链内部只需摘要检索和资料读取能力，这些步骤不要求调用方分别发起工具调用。只读文件能力限定在允许的记忆资料与引用范围，不能通过文档链接绕过边界去读取原始会话文件。

### 7.2 内部流程

1. 按问题、主题、关键词和相关路径检索摘要候选。
2. 未检索到候选时返回空答案与空来源，不要求配置查询模型；读取、归属、模型执行或来源复核失败同样返回空答案与空来源，以 `incomplete=true` 表达本次查询未完成，不抛出错误打断主流程。取消仍传播到查询执行。
3. 有候选时，先向独立 pi Agent 提供有界的候选投影，不一次加载全部全局记忆。投影保留每个候选完整的来源 ID 和修订，压缩标题、检索词与摘要，并说明候选总数、不可读来源和覆盖限制；最小身份信息本身超出预算时明确拒绝请求，不静默丢弃候选。完整正文仍只能通过读取工具取得。
4. 根据问题读取必要的详细资料、脚本内容及产物。
5. 内容缺失、背景不完整或存在尚未核实的不同说法时，在结果中明确说明，不读取原始对话补齐。
6. 整理资料中记录的事实、来源文件及未确认项后返回。

资料读取应返回实际修订；同一次查询或整理按修订复用已解码的文本，但每一页都重新探测原始字节修订。显式引用链接只在声明来源修订未变时复用，路径、归属、JSONL、删除和替换检查仍在每次读取执行。摘要较旧而详情已更新时，以新读取资料表达当前记忆状态，并保留来源差异，不隐藏版本变化。被删除或纠正条目的旧摘要不得作为召回结论；并发清理后不能仅凭已失效摘要继续返回旧内容。

### 7.3 返回内容与边界

返回结果应包含查到的事实、对应来源、资料时间或版本、适用背景、召回截断情况、未确认内容与查询覆盖范围。

查询有执行与读取预算。达到预算时返回已有发现和未完成项，不能标为完整搜索。调用方取消或停止应传播到查询执行；迟到结果不能交给其他查询或已失效的调用。

查询 Agent 只读，不维护记忆、不执行脚本、不修改项目、不递归委派。历史资料中的指令、授权和目标是被查询内容，不自动成为本次查询或主会话的新指令。

上下文与记忆入口不叠加活动状态点，外环仅显示上下文用量；详情中的整体状态和任务项复用项目BubbleLoadingIcon气泡动画；记忆读取、设置处理、保存、继续读取及本地打开均显示动态提示，操作结束或失败后停止。SVG时间轴不受Windows减少动画偏好对应的CSS规则停用，终态和未知状态不伪造运行。

### 7.4 全局记忆入口

在输入框下右侧工具组末尾提供“全局记忆”SVG按钮。浏览列表只展示可访问范围内整理完成（ready）、摘要非空且无错误的会话；待整理、整理中、失败、空摘要及已失效的来源不显示，不使用原文摘录填充列表。来源筛选、搜索和数量使用相同范围，搜索匹配主题、摘要和关键词；已选来源失效时清除来源选择，保留搜索文字。没有有效摘要时显示“暂无已整理的会话”。此显示规则不删除原文件，也不影响内部候选和后台整理：内部仍保留有实际资料或读取错误的来源，空白入口和纯模板仍不进入候选；当前会话的资料可以从左侧入口查看。当前按来源会话维护摘要，不自动读取完整对话，也不生成跨会话主题知识层。条目显示主题、摘要、入口字数、更新时间与已整理状态；字数按入口Unicode字符计数，含标点及空白。筛选不切换当前聊天会话。工作空间与来源会话采用应用内不透明深色菜单，沿用暖橙选中态与勾选标记；触屏筛选入口和选项至少44px，长标题可换行，长列表内部滚动，菜单在视口内上下避让且不受侧页裁切。方向键、Home／End及文字前缀可定位，Enter／空格确认，Tab或外部点击收起；Escape先收起筛选菜单，组合输入不触发关闭。选择后保持筛选入口焦点，切换记忆工作空间后也恢复该入口。

点击条目进入来源会话记忆，顶部可展开“关联文件”和“引用文件”，再点击阅读详细资料、脚本源码或产物；返回按钮固定在展开面板左下角，沿用项目轻量按钮、左箭头、44px热区及正文水平内边距，逐层回退到来源记忆和记录列表，保留列表筛选与阅读位置，不新增原始消息定位或对话回查入口。文档显示实际读取字数，分页未完成标“已读取”，编辑时显示草稿字数。Markdown／文本资料提供“打开本地文件”：`memory.open` 重新校验工作空间、会话、真实路径、引用权限和文档读取修订，打开磁盘版本，不隐式保存草稿；只允许 `.md/.txt`，脚本和可执行文件不交给系统执行。Windows 使用系统记事本，macOS 使用文本打开方式，Linux 使用系统关联并拒绝带执行位的文件；成功回执仅表示已提交打开请求，不代表窗口已可见。逻辑删除的会话仍可作为记忆资料来源，明确显示状态；被清理的记忆条目和失效摘要不得继续作为有效结果展示。

打开入口、浏览摘要、筛选和读取资料直接访问已保存的数据，不调用 memory_query、不启动查询 Agent，也不自动触发后台摘要整理。用户浏览与模型的语义记忆查询使用相同来源，但分别通过直接读取和同步查询工具完成。

全局视图独立订阅索引更新，详细资料按需读取。服务在没有记忆或目录订阅者时仍完成扫描、缓存与持久索引更新，但不构造目录发布负载或发送无人接收的推送；订阅建立时读取当前快照，因此不会遗漏这段期间的状态。列表区分加载、没有已整理会话及筛选无匹配，目录读取失败按空列表展示；摘要因来源或依据变化失效时立即移除，重新整理完成后再显示。正在阅读的资料和编辑草稿保留，不因来源从列表移除而强制退出。关闭视图停止相关展示订阅，更新不重建聊天输入或任务进度展示。

全局浏览与记忆详情复用压缩／子 Agent 的右侧非模态抽屉：贴视口顶边与右边，最大520px、窄屏满宽，固定标题与底部返回区、正文独立滚动，下边缘停在当前入口工具栏上方8px；左侧统计详情仍使用锚定浮层。面板非模态，点击外部空白、再次点击入口、关闭或 Escape 收起；从面板内向外拖动不触发关闭。存在未保存编辑时，关闭、逐层返回及切换其他底栏详情均先提供继续编辑或明确放弃；确认前保持记忆面板可见，继续编辑保留草稿，明确放弃后再打开目标详情；修订冲突可读取最新版本，对照并合并后保存。文档链接提取与Unicode字数按正文缓存，无关状态变化不重复解析。不改 ui/ 原始设计源。

## 8. pi 执行池与租约隔离

查询和后台整理通过 `MemoryRunner` 的 `execute`、`stopProviders`、`close` 接口执行，当前实现为 `PooledMemoryRunner`，`ColdMemoryRunner` 保留为兼容导出别名。它与 Agent、压缩共用服务级 `ExecutionPool`；每次调用创建 `SessionManager.inMemory()`、固定空资源 loader、内存 settings、订阅及读取工具闭包，仅注册 `memory_read`，不加载项目指令、技能、扩展或普通 shell 工具。D 模式允许保留经过配置校验的 ModelRuntime；C 与 managed 模式使用单次记忆实例。

读取请求通过 IPC 返回服务端，由本次调用绑定的读取闭包校验工作空间、候选会话、文件路径、引用、修订和预算。进程只得到校验后的资料；图片读取只传存在提示，不生成或传递会被丢弃的 data URI。执行结束前，worker 对本次实际读取的每份资料发起仅修订 IPC 校验；任一修订变化即作废结果。每次执行的消息、工具闭包、订阅、权限和取消状态均独立。

同时执行数量与等待队列有界，记忆业务许可与物理池名额同时领取，超时包括排队和执行；真实活跃父租约的同步查询可以使用受全局上限约束的叶子预留。取消向所属租约发送停止信号并退役实例，宽限后强制结束；实际进程关闭前仍占物理名额。成功结果必须等待当前租约的清理确认，失败或退出异常不发布成功结果；收到的实际用量持续记入原调用，不能因取消删除消费。

租约身份由 instanceId、generation 和 leaseId 共同限定。准备期间配置变更拒绝执行，旧事件和读取回复不能影响新绑定。固定运行环境可在校验后保留，不能保留上一查询的消息、权限闭包或已消费 loader。预热、空闲回收和关闭遵循 [执行池说明](pi-execution-pool.md)。

## 9. 事实、来源与可信边界

会话记忆、后台摘要和查询结果统一遵循以下表达规则：

| 来源事实 | 允许表达 | 不允许扩大为 |
| --- | --- | --- |
| 用户说已经修复 | 用户表示已修复 | 当前代码已确认无问题 |
| Agent 报告测试通过，没有关联输出 | Agent 报告通过，未关联验证输出 | 已核实所有检查通过 |
| 工具当次退出码为 0 | 该命令当次退出码为 0，附实际输出来源 | 整个系统正确 |
| 不同会话出现不同结论 | 比较时间与适用范围，核实前并列来源，核实后仅修正或删除对应条目 | 无依据地选一个作为真相 |
| 用户明确否定具体记忆 | 删除指向明确的条目及重复摘要，保留纠正来源 | 擅自扩大范围或再次裁定是否接受纠正 |
| 未检索到资料 | 本次检索未找到，附范围 | 从未发生 |
| 召回内容截断 | 明确被省略内容及无法确认项 | 根据缺失部分猜测结论 |

不裁定对错指不凭模型主观判断裁决，不妨碍依据用户明确纠正和可核实证据修正或删除记忆。应区分用户陈述、Agent 判断、工具观测和未经验证的计划；无法核实的部分继续保留并标明不确定。

旧记忆只表示其中记录的当时情况，不能因存在这份文档就认定事实已经核实，也不能直接证明当前代码、环境或测试仍然如此。后台清理针对已识别冲突只读核对当前事实，不查询原始消息；需要执行测试或其他操作才能确认时，由执行任务的主 Agent 验证，后台不擅自运行。不得把“现在不成立”等同于“过去没有发生”。

## 10. 当前实施参数与边界

- 固定入口栏目与任务状态、整体进度估计按第 4 节解析；首次明确任务、重要进展及最终回复前的维护要求随真实入口路径进入主会话系统提示。记忆目录变化触发按会话合并的后台扫描，外部引用每 60 秒作兜底复核；目录遍历、读取和哈希在专用工作线程执行，主线程只提交同代次的快照、摘要失效和订阅更新。保存、主会话运行结算和会话删除仅定向标记实际归属来源，子会话结算不加入主会话记忆扫描队列；扫描按来源隔离异常，失效后台来源不会影响其他来源；消息发送不等待记忆扫描。快照、界面读取和订阅遇到不可用来源返回空态，记忆查询失败返回空答案并标记未完成，不改变全局连接状态。内部资料核验和主动写入仍严格校验归属，避免空态降级绕过读取边界或覆盖文件。改名只更新 catalog 标题投影，已读和置顶不触发记忆目录扫描；旧扫描结果不能覆盖较新的修订。文本修订使用原始磁盘字节，保存时校验修订、文件身份及链接边界。来源或实际引用依据变化立即使派生摘要失效。
- 上下文与会话记忆合并入口放在输入框下左侧用量区，细实线外环以橙色弧长表示上下文占比，内部三条细横线表示任务三等分进度，所有数值留在详情；全局记忆 SVG 入口放在连续工具组末尾，不新增独立工具行。左侧任务详情使用锚定浮层；完整记忆与压缩／子 Agent 设置使用贴顶贴右的非模态抽屉，最大520px、窄屏满宽、底部避让工具栏8px；搜索、双列来源筛选及分隔列表依次组织，设置入口位于列表标题旁。列表→来源记忆→关联文件逐层展示，固定底部返回入口，未保存编辑保护同时覆盖关闭、返回和切换其他底栏详情。编辑绑定文件修订，订阅不覆盖草稿，冲突时可读取最新内容后合并。有效原型未提供专门记忆界面，新增布局沿用当前主题与交互语义，尚无逐像素设计等价依据。
- 查询／整理模型可分别选择，也可在各自菜单选择“使用来源会话模型”恢复继承；两项独立保存，未设置时使用来源会话模型。真实用量与未知消费进入所属主会话费用。
- 记忆业务默认总并发 12，最多排队 32，同时受统一池物理额度约束；超时 120 秒（含等待），读取预算 120,000 字符，候选最多 24 个，候选投影最多 16,000 字符，16 轮工具交互，答案最多 32,000 字符。
- 后台整理默认每 5 分钟唤醒一次，不重叠；每次最多推进 4 个可整理来源，先选择较少尝试且较早更新的来源，未建缓存来源只做定向扫描。服务启动等待完整周期，未填写的入口模板不发起请求，失败来源轮转，已发布摘要保留实际读取依据用于后续失效检查；整理完成后的后验只刷新当前来源和模型实际读取的证据来源，不扩张为全局扫描。
- 每次文本文件读取上限 4 MiB，对外按最多 16,000 字符分页；资料没有创作字数上限，超出读取预算对外按空资料处理，内部保留失败状态，不截断原文件冒充完整结果。界面编辑上限 180 KB，后台只对同修订、从零连续读至末页的局部条目提出修改。图片预览支持 PNG／JPEG／GIF／WebP，最多 5 MiB；查询 Agent 当前只获得图片存在提示，不声称已经识别图像内容。
- 单次来源扫描最多 2,000 个文件、4,000 个目录；超预算对外按空记忆处理，内部保留失败状态。扫描只读，不重建缺失入口；监视目录消失时停止对应监视器，避免 Windows 重复事件造成扫描无法结束，后续低频校验仍可读取恢复的资料。大于 4 MiB 的产物按文件元数据判断变化，不全文加载；大型仓库与长时间负载尚未验证。
- 普通会话删除使用 `deletedAt` 逻辑标记，保留 JSONL、实际文件绑定、主会话记忆、子任务交付及托管附件授权。普通执行边界排除已删除会话，专用记忆读取边界允许查询其保留资料。
- 稳定来源身份为主会话 ID，SQLite 保存摘要、修订、偏好、纠正目标和实际用量。明确纠正由界面传入原文，清理同一工作空间匹配条目及重复摘要；历史文档不能充当当前删除授权。

进程池的预热、保留数、容量和回收参数统一由执行池管理。文件读取不建设独立原始消息索引或专用历史调用读取协议。

### 11.2 验收条件

以下是验收目标，不能据本清单推定所有场景已通过；实际检查结果见本文验证说明。

- 程序只初始化 MEMORY.md 及必要父目录，不预建分类目录和其他资料文件；模型按需创建 references/、scripts/、artifacts/ 并在入口分类引用。恢复和重复初始化不覆盖内容；文件变更被监听，不要求额外维护协议或自动关联消息范围。
- 主会话系统提示词告知记忆能力、实际入口、最新状态转移、分类规则、字数上限与进度估计，不讲解文件工具操作步骤，模型自行决定维护时机；每次压缩实际应用后，通过真实读取工具取得最新 MEMORY.md，详细资料按需读取，不自动把全文注入每轮请求。
- MEMORY.md 通常约 1,000 字、全文最多 2,000 字（含资料导航）；超出时模型转移详情并保留关键状态与引用，程序不截断。详细文件按主题拆分，不设统一字数上限。
- memory_query 的工具描述说明能力和来源边界，由模型自行选择调用时机；本会话压缩后重读不隐式调用全局查询。
- 上下文与会话记忆合并入口只显示细实线外环、真实占比橙弧和任务进度三条细横线，位于左侧用量区起始位置；全局记忆图标位于连续工具组末尾，不新增独立底栏。展开显示上下文准确数值、目标、状态、有效估计百分比、任务清单、当前进展、下一步与“查看完整记忆”；详情展示入口及分类引用，无资料时隐藏分类，脚本只查看。布局、视觉、响应式及交互状态符合有效 UI 设计，不额外调用模型。
- 整体进度来自MEMORY.md中模型按10%步进记录的估计，文件保留估计口径，界面小于100时保留“约”，只有确认完成才为100%；未记录时显示“进度待评估”，无效或矛盾值标为待核对，不由界面猜测。完成项数量单独展示；范围变化允许下调，任务状态、百分比与下一步保持一致。
- 全局记忆图标展示可访问范围的全局记忆，支持摘要、详细资料和文件引用查看；打开与浏览不启动模型或后台整理，不增加原始消息查询入口。
- 两处展示独立订阅、按需读取，更新不干扰聊天输入、选区或未保存编辑；旧响应不串到其他会话，已删除条目不从旧摘要继续展示。
- 主会话和用户并发修改不会静默覆盖；其他会话和子 Agent 不能误写来源记忆。
- MEMORY.md 包含简要过程与对应详细文件链接；详细记忆包含必要背景、关键尝试、实际观察、方案取舍、验证结果与未确认项，可以独立理解和接续；文档、脚本和产物引用有效，陈述与验证结果不混淆，不要求逐轮复制聊天或工具调用。
- 会话逻辑删除后保留原始 JSONL 及程序维护的文件绑定；记忆查询与冲突清理不访问原始对话，不建立原始消息索引。
- 后台核实当前事实后只修正或删除对应记忆条目，用户明确否定则直接删除并清理重复摘要；不查询原始消息，不重写整份记忆，不修改原始对话、脚本、产物或项目代码。
- 无法核实、证据截断、时间或适用范围不同不会触发猜测删除；现状变化不删除真实历史，不按年龄、访问次数或归档等级淘汰记忆。
- 修改前校验来源修订，用户或会话的新修改不被覆盖；删除后相关旧摘要失效，摘要生成失败或迟到结果不会恢复已删除内容。
- 来源变化、读取失败和生成失败不会发布虚假的最新摘要；对外读取返回空内容，查询未完成用 `incomplete` 标记，修改失败不误报清理成功。
- 一次同步查询完成候选判断、必要资料阅读和事实整理；没有可用结果时返回空答案与空来源，未查完以 `incomplete` 区分，取消仍可传播，不读取原始对话补齐缺失。
- 每次查询使用新的内存会话、资源加载器和工具闭包，无上一查询的消息、队列、权限或回调；下一次执行校验当前配置与独占租约。
- 总并发、有界排队、超时、取消和退出清理符合约定；清理确认前不得再次借出，退出中实例仍占物理名额。
- 查询只读，脚本只阅读，历史指令不改变当前权限；模型用量和整理失败如实记录。
- README 与产品设计只在能力实际完成后标为可用；未验证的性能和场景继续明确列出。
