# 会话渐进式记忆与全局查询方案

状态：当前维护规范以[标题路径详情完整提示词](memory-title-details-system-prompt.md)为准。`MEMORY.md` 仅含六态嵌套标题，详情按完整祖先链存为 `details/<祖先标题>/<当前标题>.md`；程序隐式关联，模型使用原生 read/write/edit，无编号详情工具。既有标题及父级不可改名、删除或移动，取消保留分支。只有详情文件真实存在，标题才可点并显示文档图标。独立会话标题仍≤13字，不是任务标题的长度上限；详情浏览分页不受180KB编辑预算限制，编辑仍有该预算。见[独立标题与任务树](session-title-and-task-tree.md)。本文以下旧固定栏目、RULES、百分比、脚注与编号设计及旧验收仅供历史追溯，不代表当前契约；不提供旧编号兼容或迁移，也不删除历史文件。

记忆整理与查询现已改为**已完成目的入队、50条或30分钟互斥批量语义分类、多叉索引树，以及直接 `memory_query({ question })` 查询**；同文件最近最多4个其他一级目的标题/状态仅作冻结语境。最新机制见[目的索引与工具查询](memory-tree-query.md)，联动和验证见[流程覆盖](memory-refactor/purpose-flow-coverage.md)及[实施记录](memory-refactor/purpose-implementation.md)。该实现替代本文旧标题/摘要索引、四字段Topic树、pi查询Agent、手工整理、整会话完成门禁和立即逐文件整理；[此前第一阶段](memory-refactor/01-index-validity.md)保留历史。常驻目录是一级纯关键字分支快照，查询每次使用最新发布索引，成功压缩后程序注入最新目录。历史经验使用前仍须核对当前条件。本文其余文件管理、来源归属、资料保留及待办接续约束继续适用；下方旧设计和验收仅作历史，冲突时以当前机制为准。统一执行池见[执行池说明](pi-execution-pool.md)。

本文作为 [产品设计](design.md) 的专项方案。现有 pi 会话、压缩、主／子 Agent 与工作空间隔离仍遵循产品设计；会话删除、记忆加载和执行方式的说明与产品设计及 README 同步维护。

## 1. 目标与基本原则

长时间执行和多轮上下文压缩可能丢失目标、约束、决定及执行细节。本方案通过持久资料和渐进读取，帮助当前会话恢复工作，也让其他会话查询已有经验。

整体机制：

1. 主会话通过系统提示词了解记忆文件能力，用现有文件工具维护简要入口与详细资料；入口包含简要过程，每次压缩后主动重新读取。
2. 后台按周期检查，只为连续30分钟未变更的会话记忆生成不超过30字的工作标题与不超过200字的独立摘要，概括用途、关键经历和结果，并关联原记忆文件；用户可主动立即整理已保存的来源，绕过周期与稳定等待。
3. 主 Agent 根据记忆查询工具的能力描述，自行决定何时调用同步查询工具。
4. 工具内部使用一个独立 pi Agent，先查看当前工作空间全部有效标题，再按相关性逐层读取摘要、原记忆和必要引用详情；标题目录为空或不可读直接返回空。
5. 每次查询或整理借用统一池的独占租约，使用全新的内存会话、loader、settings 和工具闭包；清理确认后归还可复用环境。
6. 在输入框下左侧用量区提供上下文与本会话记忆合并入口，右侧工具区提供全局记忆入口；任务进度在合并入口展开后显示。

基本原则：

- **可选辅助**：记忆初始化、读取、扫描或查询失败不阻断会话创建、消息发送或恢复；读不到、归属不匹配时返回不含内容的记忆载荷，并用短原因区分缺失、暂不可用、等待纠正、修订冲突与读取失败，不弹出读取错误。合法空模板仍是正常空态。发送不等待记忆扫描。写入、纠正及本地打开仍校验归属、路径与修订，失败不得伪装成功。
- **事实与来源优先**：根据会话中的实际陈述、操作和结果记录，不捏造，不凭模型主观判断裁定对错；允许依据用户明确纠正和可核实证据修正或删除记忆。
- **简要不等于遗漏**：入口压缩表达，必要细节保存在专题资料中，重要事实应有可追踪的阅读路径。
- **渐进加载**：跨会话查询按标题、摘要、入口、详情逐层展开，本会话接续直接读取入口；详细资料应能独立解释背景，信息不足时保留未知。
- **职责独立**：程序初始化共享 RULES.md 和会话入口 MEMORY.md，主会话按需要创建分类目录与资料并通过现有文件工具维护；后台只为已保存资料生成导航摘要，查询 Agent 保持只读，原记忆由主会话和用户维护。
- **历史保留**：压缩和会话列表删除不删除原始对话及会话文件绑定；原始对话不进入本记忆机制的摘要整理或查询流程。
- **上下文隔离**：每次记忆执行使用独立租约和会话，查询消息、权限归属和执行状态不能串入下一次查询。
- **现状如实表达**：正在进行、尚未验证、资料过期、召回截断和查询未完成都须明确标记。

## 2. 系统组成与职责

| 部分 | 职责 | 写入范围 |
| --- | --- | --- |
| 主会话 Agent | 用现有文件工具维护目标、约束、进度、简要过程、结论、专题详情与文件引用 | 所属会话的记忆目录 |
| 记忆目录与变更管理 | 初始化 MEMORY.md、保存归属及文件绑定、监听变化并更新修订与展示 | 入口模板及所属元数据 |
| 摘要整理任务 | 后台周期检查稳定来源，或按用户请求立即整理，生成30字以内标题及200字以内的任务、问题、成果与状态摘要 | 全局摘要索引及整理状态，不修改来源文件 |
| 显式纠正入口 | 按用户明确指定的原文清理同一工作空间的匹配条目，并阻止迟到的重复内容被召回 | 匹配记忆条目及其索引，不改原始对话 |
| pi 查询 Agent | 从全部标题开始，按需读取摘要、原记忆与详情，整理查询结果 | 不写会话记忆和项目文件 |
| 记忆执行器 | 从统一池借用固定能力实例，联合限制并发与等待，逐租约绑定并校验清理 | 运行管理状态及真实用量 |

原始 pi JSONL 继续用于真实对话的持久化与恢复。程序保留会话 ID 到实际对话文件的绑定，模型不维护这份绑定。记忆是补充资料，不替代 JSONL，也不通过另一份对话副本重建 pi 会话。

本方案中的查询 Agent 是同步工具内部的专用执行者，不改变现有 delegate、append、cancel_task、read_result 四个独立工具的契约，不递归委派。

## 3. 会话记忆目录与入口

### 3.1 统一存储

默认安装将资料保存在用户主目录的短路径，不写入项目设计源：

```text
~/.axiom/memory/
  RULES.md                     # 共享的文件组织与格式规则
  <sessionId>/
    MEMORY.md                  # 程序初始化的会话入口
    references/                # 模型按需创建：详细过程、调查、方案与验证文档
    scripts/                   # 模型按需创建：可复用脚本
    artifacts/                 # 模型按需创建：报告、截图、导出文件等产物
```

服务启动时在应用数据目录独占锁内，将旧 `memory/sessions/<sessionId>/` 逐会话复制到新目录，校验源文件在迁移期间未变化，改写不超过 4 MiB 的 UTF-8 Markdown／文本文件中的旧记忆绝对路径，保留二进制产物与原目录作为恢复副本。完成全部复制后，原子提交应用数据目录中的 `memory-location.json`，绑定所属数据根和目标位置。重启使用已提交的位置，不用恢复副本复活已删除的入口。已有目标内容不同时不覆盖，遇到链接、特殊文件或复制失败时保留旧位置供当前服务使用，下次启动重试。已提交绑定损坏或目标目录缺失时，保留绑定并暂用旧目录，不阻断服务启动；旧目录只是恢复副本，可能不含迁移后的更新。通过 `AXIOM_DATA_DIR` 或启动参数指定的非默认数据根仍使用自身的 `memory/sessions/`，规则文件同放于该目录。复制来的绑定不匹配新数据根时被忽略，避免不同实例共享记忆。

当前 SQLite 的 `memory_sources` 保存来源、修订和扫描状态；`memory_purposes` 保存目的身份、冻结语境及排队状态，`memory_purpose_indexes` 保存事务发布索引。旧摘要字段、`memory_organizations`及旧四字段表只保留磁盘历史，不参与扫描依赖核验、整理或查询，也不迁移/清空。不额外生成一套磁盘 catalog。应用数据根在存储入口解析并固定为真实路径，兼容 macOS 系统目录别名和 Windows 短路径；根以下的记忆目录与文件仍拒绝符号链接、目录联接及硬链接。初始化逐级校验目录后创建下一层，仅创建缺失的目录；已有的 Windows 盘符根目录同样只校验，不重复创建。拒绝链接时不向其目标创建入口或后代目录。

每个主会话拥有独立目录，并保存与工作空间的稳定归属。程序初始化共享 RULES.md，并在创建主会话时初始化 MEMORY.md 模板及其必要父目录，不预建 references/、scripts/、artifacts/ 或其他会话资料；恢复会话或重复初始化不得覆盖已有内容。上述分类目录与文件由模型按需要创建，不生成空目录。后台索引由整理任务生成，不属于主会话资料预建范围。创建入口失败按无记忆继续创建会话；提供的入口路径只表示所属记忆位置，不保证文件存在或可读。

模型使用现有 read、edit、write 等文件工具维护文档、脚本和相对引用，不另设专用记忆更新工具。程序监听实际文件变化，更新修订信息、TodoList 并标记待整理资料；不按两次保存之间的消息范围自动推定事实来源。目录归属和实际对话文件绑定由程序维护，路径示意不代替归属校验。

详细资料不限制文档个数，按自然主题拆分，可使用相对路径引用所属目录下的其他文档、脚本和产物。引用项目中的当前文件与保留的历史产物时须明确区别，避免把变化后的文件当成历史快照。

### 3.2 MEMORY.md 内容

| 内容 | 记录重点 |
| --- | --- |
| 目标与范围 | 用户最终要达成什么、验收条件、尚未明确的范围 |
| 要求与约束 | 用户明确要求、限制、偏好、纠正及已授权事项的适用范围 |
| 任务进度 | 整体状态、整体进度估计、当前进展、任务标题及已完成／进行中／未开始／阻塞状态，供 TodoList 展示 |
| 简要过程 | 关键尝试、重要发现与转折、做到哪里；具体过程链接到详细文件 |
| 结论与决定 | 会话形成的结论、采用的方案与原因 |
| 验证情况 | 实际检查内容、结果、尚未验证事项 |
| 下一步与接续位置 | 下一步、待处理问题、进行中的子任务与结果位置 |
| 资料导航 | 按详细资料、脚本、产物分类，记录主题、相对路径、简要用途和何时需要阅读 |

程序按上表生成固定栏目，供模型填写及界面直接解析；主 Agent 必须保留“目标与范围”和“任务进度”栏目，每个明确的真实任务在任务进度中单独使用已完成／进行中／未开始／阻塞状态，不能用部署摘要、验证证据链接或普通正文代替任务清单。读取侧兼容已有入口的“目标与状态”“当前目标与状态”“目标与约束”等目标栏目、分号分隔的显式状态字段，以及任务栏目中的标准 Markdown `- [x]`／`- [ ]` checkbox；只把任务栏目的显式 checkbox 解析为 Todo，不从正文、普通项目符号或链接推断任务。初始内容仅表示“尚未填写”或“尚未记录”，整体进度为“待评估”，不填入虚构目标、任务或默认百分比。空清单不代表工作已完成；初始模板也不发起模型请求。

正文用文字说明目标、要求、事实、决定和结果，详细地址集中在文末脚注中。例如正文写 `验证已完成。[^report]`，文末定义 `[^report]: [验证报告](references/report.md)`。脚注定义须使用 Markdown 链接才能成为可导航的文件引用，纯路径文字不授予读取权限。界面按引用顺序编号，支持跳转至定义及返回实际点击的引用，未引用的定义列在末尾，重复定义只采用第一条。TodoList 与摘要排除脚注定义和标记，引用内容不会生成任务或覆盖进度字段。未加载定义的分页内容保留字面标记，继续读取后再解析；代码和转义文本不产生引用。

入口应简洁但全面。不能只列文件名，也不能省略重要要求后没有任何详情入口。入口优先保留当前目标、有效约束、正在进行的工作、简要过程和接续位置；用简短描述说明关键尝试及其结果、重要转折与当前停点，具体过程移入专题文件并保留链接。进度表达当前状态，简要过程解释如何到达这个状态。

入口通常保持约 1,000 字，全文最多 2,000 字，包含正文与资料导航。超出时由模型将细节移入分类文件，保留关键状态、简要过程和引用；程序不直接截断文件。详细文件不设统一字数上限，按主题拆分，数量不设固定上限；单页读取有上限，查询按需继续分页，累计读取预算仅用于整理，不能每轮加载全部文件。

整体进度由主 Agent 结合已完成工作与剩余工作量估计，记录为“整体进度：约 50%”等，以 10% 为步进。只有任务确认完成才记为 100%；仍有待完成工作或必要验证时最多约 90%。本次授权工作与必要验证完成后，应在最终回复前同步状态及 100%，不能仅因等待用户查看而保留 90%。范围扩大、发现新问题或任务重新打开时，状态、进度及下一步随之更新，允许下调百分比。整体进度是明确标注的估计，不等于任务项数量的完成比例。

### 3.3 可独立理解的详细资料

详细资料应讲清问题背景、适用条件、已知事实、关键尝试与实际观察、采用或放弃方案的原因、实施与验证情况、尚未确认内容，让其他会话无需阅读原始聊天即可理解和使用。入口中的简要过程链接到对应专题，具体过程在专题中按必要顺序说明，不只保留最终结论。

过程记录以理解决定、接续工作和避免重复踩坑为目的，不逐轮抄写对话或保存每次工具调用。真实发生且有参考价值的失败尝试应说明当时条件、结果及适用范围；已排除的推测明确标注为已排除，不混同于事实。进行中的资料保留当前停点和下一步，完成后在同一主题文件中整理关键过程与结果。

每份资料按自然主题维护，已有对应主题时局部更新。文档、脚本和产物通过相对路径引用；项目文件、报告或子任务交付已经承载详情时，可以直接引用实际位置，必要背景仍在记忆中说明。不要求主会话标注逐条消息身份或维护精确对话来源。

例如，关于会话恢复的专题可以说明问题出现条件、用户要求、所选方案、改动位置、当时检查结果和未验证场景，并链接已保存的报告。示例中的验证必须以实际执行为依据，缺少报告或依据时明确说明。

脚本应记录用途、适用条件、是否实际执行以及当时结果。脚本存在不等于执行成功；查询 Agent 阅读脚本内容，不自动执行脚本。

## 4. 会话记忆维护与恢复

### 4.1 内容维护与所有权

主会话主动维护重要信息、决定和操作结果。每次收到用户的新输入，包括运行中追加要求，先检查其中需要保留的信息，并及时更新记忆。执行中有信息新增或变化时，根据遗忘后是否会造成误判、重复操作或重新调查判断保留价值，及时更新会影响后续行动的要求、发现、决定和结果。最终回复前核对记忆是否反映当前任务实际状态。接续任务、上下文压缩后或背景不清时查阅本会话记忆，相关工作有需要时查询全局经验，已有信息充分时不重复查阅。系统提示词只说明维护责任、信息取舍与读写时机，共享 RULES.md 承载目录分工、字数上限、必要栏目、任务与进度格式及脚注写法，模板提供初始栏目。

子任务结果通过现有交付机制返回主会话，由主会话阅读后把可复用的结论、背景和未完成项纳入记忆。子 Agent 不共同写主会话记忆目录；已有报告或产物可以直接引用，不要求额外整理子会话消息关系。

用户也可以修改记忆。Agent 编辑前读取当前文件并优先使用精确局部修改；用户编辑入口与后台提交校验读取版本，冲突时重新读取并合并，不用旧副本覆盖新内容。文件变化检测与并发保护沿用通用文件操作边界，不增加模型需要填写的专用维护协议。

其他会话默认只读来源资料。发现不同结论时，在本会话记录新事实并关联旧来源，不直接改写其他会话的记忆。显式纠正入口依第 6 节处理用户指定原文的跨会话清理，校验归属与修订；后台摘要模型没有来源写入权限。

### 4.2 内容演进

所有内容依据最新事实和状态变化同步更新；任务状态、整体进度估计、关键结论与下一步须保持一致，不能保留互相矛盾的当前状态。入口始终表达当前有效状态；重要的目标变化、被替代方案及其原因保存在详细资料中，必要时引用相关文件或产物。重复内容可以整理，已有事实依据不能因缩短入口而消失。已核实不符合事实的条目由主会话修正，用户明确否定的内容按第 6 节清理；真实历史不因现状变化而自动删除。

专题拆分、移动、合并或条目清理时，同步维护入口和引用。记忆对象使用稳定标识与修订信息，使摘要可以检测来源变化；不能让旧摘要静默指向无关的新内容，或让已删除条目继续从旧摘要中召回。

### 4.3 系统提示词与压缩后重读

主会话系统提示词如下，实际入口与共享规则路径由程序填入：

> 你需要主动维护会话记忆文件 `<路径>/MEMORY.md`，用于保留本会话的重要信息、决定和操作结果，帮助后续工作保持连贯，避免遗漏与重复。同时作为全局记忆的一部分，供其他会话复用相关信息与经验。
>
> 每次收到用户的新输入，包括运行中追加要求，先检查其中需要保留的信息，并及时更新记忆。执行中有信息新增或变化时，考虑：如果之后忘记它，是否会导致误判、重复操作或重新调查？有保留价值就及时更新记忆，尤其是会影响后续行动的要求、发现、决定和操作结果。最终回复前，核对记忆是否反映了当前任务的实际状态与结果。
>
> 接续任务、上下文压缩后或当前背景不清时，查阅本会话记忆。着手相关工作前，考虑全局记忆中是否有可借鉴的经验、决定或结果，有需要再查。已有信息充分时不重复查阅。
>
> 记忆文件的组织与格式遵循 `<路径>/RULES.md`。首次维护前先读取，当前上下文缺少这些规则时重新查阅。记忆不可用时继续任务，不假称已读取或保存。
>
> 交付前必须检查并更新本会话 MEMORY.md，确保任务清单、整体状态、整体进度与实际结果一致，逐项确认当前任务是否仍有未完成项。不得仅凭记忆中的“已完成”标记判断任务完成。
>
> 当前任务范围内仍有已获授权且可继续推进的未完成项时，应继续处理。记忆更新、阶段汇报或写下“下一步”不能代替实际执行。构建或测试失败时，先核对当前错误并继续处理授权范围内可修复的问题，不能仅因报错位于本轮未修改的文件就判定阻塞；涉及并行修改时保留他人改动并核对最新状态。只有确实缺少用户输入、授权或外部条件，且没有可继续推进的工作时，才说明具体阻塞原因和所需条件后结束，不宣称完成。只有当前任务范围及必要验证全部完成，才能标为已完成和100%。一轮回复结束不等于整体完成，完成后继续新工作时恢复相应状态并更新记忆。
>
> 交付内容先说明核心结果和关键变化，再补充必要细节。保持简洁，避免重复说明、过程流水账和无关展开；不为追求简短而省略影响结论的重要限制。

程序提供所属会话的入口路径，不承诺文件可读。用户的新要求优先于旧记录，文件读取失败按空记忆继续，不假定已恢复全部背景。共享规则只承载组织与格式，信息取舍及读写时机不在其中重复。

记忆正文由主 Agent 主动读取，不在每次模型请求前自动注入最新文件全文。自身记忆的直接读取不调用 memory_query，也不启动独立查询 Agent。

程序根据真实压缩应用事件提供“需重新读取本会话记忆”的状态提示，使系统规则能在下一次继续执行时生效；后台压缩尚在生成或等待应用时不提前要求恢复。覆盖后台、手动及原生恢复中实际应用的压缩；重读通过实际工具调用完成，不能将提示已送达视为文件已读取。读取失败记录独立的不可用尝试标记，同一压缩不重复提示，不把失败标为读取成功，也不阻断后续工作。

后台压缩基于较早快照生成的摘要不得覆盖执行期间更新的记忆。原生压缩与会话记忆保持独立；原始 JSONL 的恢复规则不变。

### 4.4 本会话任务进度入口

上下文与本会话记忆合用输入框下左侧用量区起始按钮，全局记忆 SVG 按钮紧接压缩图标，不新增独立底栏或文字行。合并图形为20px细实线灰环，20单位画布中底环与占用弧共用圆心和半径，橙色弧按实际占用角度直接绘制；内部三行“对钩＋横线”保持4px等距和相同像素相位，在有效任务进度达到三分之一、三分之二和100%时依次点亮为橙色，未知或矛盾时全部保持灰色。所有视口入口只显示图标，百分比、Token和任务估计集中到详情；任务完成只点亮内部三条，不改变外环。底栏轮廓统一1.2px非缩放描边，内部对钩与横线1px；亮色为暖琥珀色 `#fcbc7c`。44px点击区域单排，保留左指标／右工具分组，组内间距0、组间弹性留白且最小8px，容纳不下时工具栏内部横向滚动。点击合并图标展开上下文数据与 TodoList，再按需查看完整记忆。视觉沿用 [设计交接](../ui/DESIGN-HANDOFF.md) 指定入口的字体、颜色与图标语义；左侧统计浮层最大520px、窄屏两侧留12px，完整记忆使用贴顶贴右抽屉、最大520px且窄屏满宽，不修改 ui/ 原始设计源。

TodoList 是当前查看主会话 MEMORY.md 的展示投影，不另建独立任务状态，不从聊天文本或 Agent 是否运行推断完成情况，也不启动模型生成展示内容。

| 展示位置 | 内容与行为 |
| --- | --- |
| 收起入口 | 细实线灰环上以橙色弧长表示上下文占用，内部三条细横线表示任务三等分进度，三条全亮仅表示已完成；不显示数字，未知保留灰环，准确比例及超限量留在详情；悬停说明上下文与任务状态 |
| 展开区 | 上下文 Token／容量、估算口径及超限量；记忆目标、整体状态与模型估计进度（未完成标“约”）、独立的已完成数量、任务清单、当前进展、下一步和“查看完整记忆”入口；没有显式任务时说明尚未记录任务清单，不虚构完成数量或任务；不可用状态不展示旧任务；点击外部、关闭按钮或 Escape 收起 |
| 本会话记忆详情 | 点击“查看完整记忆”后展示完整 MEMORY.md，包括简要过程及分类资料导航；“立即整理”根据此来源已保存内容生成摘要，编辑或存在草稿时须先保存或取消编辑；不切换聊天会话 |
| 详细资料 | 显示文档名称和简要用途，点击阅读对应文档 |
| 脚本 | 显示脚本名称和用途，点击查看内容，不自动执行 |
| 产物 | 显示报告、截图等文件，按支持能力预览或打开 |

展开区内的任务进度条与百分比直接读取主Agent写入的整体进度估计，以10%为步进；0%至90%接受 `30%` 与 `约30%` 两种记录，界面统一显示“约30%”，100%仅接受明确完成时不带“约”的记录。记忆文件仍保留估计口径及有效性校验。完成任务数量独立计数，不直接换算为工作量百分比。没有清单时不显示完成数量；已记录任务但无法解析有效估计时显示“进度待评估”，不填充虚假进度条。百分比超出范围、不符合步进或与完成状态矛盾时标为待核对，不由界面猜测修正；范围扩大或发现新问题后允许随记忆更新下调。

2,000 字限制针对记忆入口文件，入口正文只在完整记忆详情中显示，不在 TodoList 首层重复预览。具体过程留在记忆详情及引用文件中；分类下没有资料时不显示该分类，不为缺失目录报错。目标或状态已记录但任务清单缺失时明确显示“尚未记录任务清单”，不把普通正文或链接转成 Todo；连目标和状态也未记录时图标悬停说明“暂无记录”，展开说明“还没有任务记录”。文档查看、编辑和保存遵循归属与修订校验规则；任务状态图标用于展示，不直接通过勾选改变执行事实。

仅订阅当前查看会话的记忆修订，文件更新后局部刷新，不重建聊天区，不干扰输入、选区与展开状态。切换会话后切换数据归属并忽略旧响应；初始化或读取失败显示空态并以简短状态区分缺失、暂不可用、等待纠正、超时、修订冲突与读取失败，不启动模型生成占位内容，存在未保存编辑时不得以后台更新覆盖。任务入口始终对应当前会话，右侧全局记忆入口用于跨会话浏览。

### 4.5 自然结束后的待办接续

主会话一次执行正常完成、没有失败或特殊结算原因后，程序定向扫描最新会话记忆。只有任务栏目仍明确记录“未开始”或“进行中”的可执行事项，且整体状态（包括括注及后续说明）、当前进展和下一步未声明阻塞、等待用户、停止或完成冲突时，才允许自动接续。缺失、不可用、待纠正或已删除的来源不触发执行。普通文件变更、浏览、摘要生成及服务启动不触发接续，历史会话不在重启后自动重放。

接续与30分钟摘要整理完全分离，不依赖摘要或等待整理周期。程序复用原 pi 会话和统一执行池，以隐藏的宿主消息提醒主 Agent 重新读取记忆、结合当前对话确认实际待办并继续已授权工作，不新增用户消息，不消费草稿，不把记忆视为新授权。只有确实缺少必要的用户输入、确认、授权或外部条件，且没有可继续推进的工作时，主 Agent 才记录具体阻塞原因和所需条件后停止；可在现有授权和工具条件下排查修复的构建或测试错误应继续处理。文件及外部操作的完成情况须重新核对，不能因任务仍未勾选就重复执行。

检查、最终提交、工作进程准备完成及模型执行许可前均校验原执行或其本次接续、最新记忆修订、归属、授权、删除状态及停止边界。手动停止或首次提交的新用户输入取消旧检查与尚未开始模型请求的自动准备；同时到达的新输入共享一次停止操作并依次进入会话队列，后续手动停止仍使此前等待的输入失效。重复请求只返回原回执，不取消接续或清空防循环记录。存在活动子任务、排队输入、待处理结果通知或父会话冻结时不抢先启动；正在运行的压缩结束后重新校验再继续。失败、取消、中断、未回复结算及预算总结不属于自然完成。

同一执行只检查一次，同一轮自动接续链中的未完成任务标题和状态保持不变时停止继续，备注或产物变化不能绕过。每轮最多自动启动3次，新用户操作可开始新一轮。无资格的子会话不分配接续链，记忆缺失等未发生启动的检查结束后释放名额。自动请求使用原执行派生的幂等标识，启动结果不确定时保留已有回执，不自动重发。程序不因达到上限而把任务标成完成，也不替代模型维护真实状态。

## 5. 会话文件绑定与保留

程序保存 workspaceId、sessionId、记忆目录与 pi 实际对话文件的绑定关系，使用真实路径，不根据会话 ID 猜测文件名。这是会话管理元数据，不要求模型写入 MEMORY.md，也不自动推定记忆条目的消息来源。

原始对话用于持久化、恢复和历史保留。记忆查询、全局记忆浏览和后台摘要整理均不读取原始会话文件，不建设专用历史消息检索、定位、预处理或展示能力。阅读记忆资料沿用现有文件工具的搜索、分段读取和截断提示，查询仅保留单页上限，整理另设累计读取预算。

会话列表删除采用逻辑删除：按既有停止边界结束所属活动执行，再从 Axiom 普通会话列表移除。保留原始 JSONL、记忆、会话文件绑定，以及被引用的子任务结果和托管附件。列表删除本身不触发记忆条目清理；条目的修正或删除另按第 6 节处理。

逻辑删除后的会话仍可作为记忆资料来源，查询结果标明其状态。外部文件引用不能保证永久存在，缺失时明确报告，不伪造已保留副本。如将来提供永久清除，应作为独立明确操作；普通列表删除不承担物理清理语义。

本节只规定记忆机制的边界，不移除产品已有的原始会话查看功能；原始文件的保留不意味着记忆查询需要读取它。

## 6. 摘要整理、原文纠正与清理

### 6.1 范围与调度

文件监听与扫描及时更新来源修订和展示，来源一旦变化即清空旧摘要并标记待整理。后台模型整理由周期检查触发，默认每5分钟检查一次。入口、专题、脚本或产物的来源修订连续30分钟未变化才具备整理资格，任何新修订重新计时。普通重扫、会话改名与查询不重新计时，稳定起点持久化并在服务重启后继续使用。停服期间变更在重新扫描时重新计时。不另以主会话或子任务的运行状态作为门槛。

后台模型完整读取当前来源 MEMORY.md，按需读取同目录专题，只生成不超过30字的单行工作标题和不超过200字的自然语言摘要，说明做了什么、解决了什么问题、取得的结果和当前状态，只保留影响理解的重要决定或不确定性。主题和摘要按任务目的与成果概括，不包含路径、文件名、代码名称、命令、内部标识等实现细节，不罗列尝试或实施步骤，不使用链接、脚注和代码块。具体过程保留在关联原记忆中。摘要与来源会话、文件入口和修订绑定，服务于全局查看及查询定位，不代替原资料。

后台不读取其他会话、项目当前文件或原始对话，不核实跨来源冲突，不修改原记忆、脚本或产物，也不执行资料中的指令。原文的补充和事实修正由主会话与用户完成。每批最多推进4个来源，运行中出现的新修订留待后续周期，不在当前批结束后立即续排。不会因记忆很久未被查询、年龄或访问次数而删除资料。

### 6.2 用户明确否定

用户明确指出某条记录“不对”“不符合”或“不要保留”时，对指向明确的条目直接删除，不再由模型判断用户的纠正是否成立，也不额外要求重复确认。会话收到该意见时即处理所属记忆；通过纠正入口明确传入目标后，相关会话中的同一条目及重复摘要一并清理。目标范围不明确时不扩大删除，保留未能定位的部分。

用户明确否定由接收该指令的主会话在当前交互中处理，不要求后台扫描历史消息发现删除要求。跨会话的相同条目清理依据明确传递的纠正意图与目标，不能把资料中的引文、工具输出或模型推测当成用户删除要求。当前实现通过全局记忆的“记忆设置与纠正”输入明确原文，立即清理当前工作空间匹配内容并保存纠正目标，后台继续检查迟到的重复内容；单独修改一份记忆文件不会自动推定跨会话删除授权。后续整理不从旧资料重新生成被删除条目。

区分当前状态与历史事实。例如，当前已改用 PostgreSQL 时，可以修正“当前使用 SQLite”；“此前从 SQLite 迁移到 PostgreSQL”仍是历史事实，不能仅因现状变化而删除。不同会话的时间或适用范围不同，不自动构成冲突。

清理的对象是记忆正文与派生摘要。原始对话及其绑定继续保留，程序不读取或改写这些记录；不能通过清理记忆改变真实历史。

### 6.3 摘要条目

| 字段 | 用途 |
| --- | --- |
| 稳定记忆标识、工作标题、摘要 | 标题作为第一层目录，最多30个Unicode码点；摘要作为第二层导航，最多200个Unicode码点，均含标点与空白 |
| workspaceId、sessionId | 来源与范围 |
| 详细资料位置与文件引用 | 渐进读取入口 |
| 来源状态 | 进行中、已完成、待验证、已被来源明确替代等 |
| 来源修订标识与资料更新时间 | 判断适用版本 |
| 整理时间与索引状态 | 表达新鲜度、失败或待更新 |

索引可以从当前会话资料重新生成。来源变化后直接读取能看到新版本，旧摘要立即失效，等待稳定窗口与后续整理周期。已有超过200字、标题为空／多行／超过30字或不属于当前规范版本的条目不展示、不参与查询，下一次扫描将其标为待整理，保留未变化来源的稳定计时，在正常周期按当前规范重新生成，不截断或改写旧摘要代替模型概括。规范版本是内部索引元数据，不作为来源内容或界面文案。

### 6.4 一致性与失败

摘要生成、用户保存与显式纠正均绑定读取时的来源修订。文本资料的修订从磁盘原始字节计算，UTF-8 BOM、换行形式及 Unicode 内容均属于修订；保存先比较原始字节修订，保留已有 BOM，不把无改动保存改写为另一种字节表示。提交前校验目标资料未被用户或会话更新，不能用旧副本覆盖新内容。显式纠正只清理对应条目，不覆盖整份文档中的无关修改。

标题与摘要由同次整理生成并共同校验，任一不合格均不发布，也不截断代替模型概括。整理的读证据必须从偏移量零开始、在同一修订中连续覆盖到末页。尾页、缺页或读取中途修订改变都不是完整证据，不能用于发布摘要。后台模型即使返回编辑建议，也不会修改来源文件。

摘要发布前重扫当前来源并复核实际读取的资料，来源变化或读取未完成则不发布结果。生成失败保留原记忆并报告错误，后续周期可以重试；来源变化后不保留旧摘要作为有效内容，也不从旧摘要恢复来源记忆。

资料读取失败不等于资料删除，模型请求失败不等于没有记忆。未整理、失败及失效来源不进入标题目录，原文仍可通过会话记忆入口直接查看。查询不主动补整理或统计未覆盖来源。

后台整理批次不重叠，退出时释放拥有的执行资源。整理模型、周期、并发与预算可以配置，模型用量纳入实际记账。

全局统一存储，默认按当前工作空间查询；摘要整理、查询与显式纠正都校验归属。

### 6.5 手动整理与仅清摘要

MEMORY.md 原文操作栏提供“立即整理”，强制重新概括该来源当前已保存的记忆，即使已有有效摘要也可重新生成。全局摘要列表提供“整理工作空间”，处理所选工作空间全部待整理来源，跳过有效摘要和空入口，搜索与来源筛选只影响显示。两者均绕过后台周期、30分钟稳定等待和后台每批4项限制，复用相同的只读权限、完整读取、预算、模型选择、用量记账与发布前修订核验。来源变化时拒绝旧结果，不用摘要覆盖原文；每个来源失败后继续处理其他来源，结果区分成功、失败与跳过。

手动与后台共用一个整理执行槽。请求短暂等待受理回执，模型执行由服务拥有，关闭面板、刷新或连接断开不会取消已受理任务。独立订阅 `memory-organization:<workspaceId>` 保存并显示最新手动任务的运行、完成、部分失败、失败、取消或中断状态，以及处理数量。按钮防止重复提交，运行中可取消；取消后已知用量仍保留，晚到结果不能发布。包括取消和失败在内的手动任务结算后，后台等待完整配置间隔再检查，不在下一次调度立即重试。服务关闭等待清理，重启将残留运行任务标记中断，不自动恢复模型调用。

| 命令 | 范围与回执 |
| --- | --- |
| `memory.organize` | 必带 workspaceId，可带 sessionId 限定来源；返回任务ID及初始 running 状态，表示已受理，不表示摘要完成 |
| `memory.organize.get` | 读取指定工作空间最近手动任务；无记录返回 null |
| `memory.organize.cancel` | 必带工作空间及 `params.id`，核对归属后取消对应任务，终态通过状态订阅读取 |
| `memory.summaries.clear` | 必带工作空间及 `params.confirmed=true`，返回本次实际清除的非空摘要数 cleared 和更新来源数 updated |

受理、取消与清摘要按 requestId 和完整请求内容保存幂等回执。同请求重放只返回原回执，不再生成摘要或删除后来新生成的结果；同标识不同参数拒绝。不确定请求不自动重发，可读取最新任务状态核实。

仅清摘要在服务事务内移除指定工作空间的生成主题、摘要、规范版本、关键词、依赖与生成时间，将可读来源标回待整理。保留来源原文、来源修订与稳定计时、读取错误、模型设置、纠正目标、用量和其他工作空间；不注册原文纠正目标。清理前取消涉及该空间的在途整理，并使扫描代次失效，晚到的成功或失败不能恢复已清结果。全部工作空间的清理需逐空间调用并核对实际回执，不通过直接写数据库或原文纠正命令代替。

单来源按钮仅在 MEMORY.md 入口显示，加载、不可用、保存或编辑期间禁用，不隐式保存草稿。整理状态独立于资料读写和设置状态，搜索、筛选、返回与关闭仍可使用；错误收敛敏感信息，重试重新发起整理。切换来源或空间时不把旧响应显示到新归属，重新打开从服务状态恢复。

## 7. 同步记忆查询工具

### 7.1 对外契约

向主 Agent 提供一个同步工具，暂名 `memory_query`，输入问题与允许的查询范围。工具描述明确告知它能查找记忆中记录的历史工作、决定、问题处理与验证情况，按需阅读详细文档和引用文件，返回事实整理、资料来源和未确认项；不提供原始对话查询。模型依据当前需要自行决定何时调用，不规定每次任务开始、每轮对话或压缩后强制查询全局记忆。

调用方等待一次调用的结果，不通过 delegate 创建异步子任务，也不另行领取查询结果。全局记忆查询的自主调用与第 4.3 节规定的本会话压缩后重读分别处理；后者是主会话必须遵循的恢复规则。

同步指工具等待语义，服务内部采用异步执行，不阻塞其他会话或服务事件循环。主／子运行结算、根会话恢复或错误恢复只定向刷新其实际归属来源；无法确定单一归属时才恢复同一工作空间的可访问来源，不能让一条事件误触发无关工作空间的查询或扫描。

查询链内部使用同一个 Agent 完成标题判断、摘要筛选和资料读取，这些步骤不要求调用方分别发起工具调用。只读文件能力限定在允许的记忆资料与引用范围，不能通过文档链接绕过边界去读取原始会话文件。

### 7.2 内部流程

1. 从持久目录取得当前工作空间全部有效工作标题：状态为 ready，符合当前规范版本，标题非空、单行且不超过30字，摘要非空且不超过200字，无错误或不可用标记。正文冷缓存不影响入选，不按关键词或固定数量预筛。
2. 第一层目录为空或不可读时直接返回空答案和空来源，不启动模型，不扫描来源补齐目录。初始提示只含问题、读取说明与全部 `{sessionId, title}`，不携带摘要或正文。
3. 一个只读 pi Agent 看标题判断相关性，通过同一个 `memory_read` 读取相关来源的虚拟 `SUMMARY.md`。该入口提供已保存的标题、摘要及 `MEMORY.md` 路径，不创建磁盘文件。
4. Agent 阅读摘要后决定是否读取该来源 `MEMORY.md`，再按文中引用读取必要详情。标题与摘要只用于导航，事实依据实际读到的正文。找不到相关资料时返回空。
5. 内容缺失、背景不完整或存在尚未核实的不同说法时，在结果中明确说明，不读取原始对话补齐。没有实际文档读取时不返回事实答案。
6. 返回实际读过的来源及文档修订，虚拟摘要不计入正文证据。查询不重扫候选目录、复核全部摘要或重新哈希全部已读文件；读取、归属或执行失败返回空答案及空来源并标记未完成，取消传播到调用方。

每次真实文档读取仍校验当前归属、真实路径、显式引用与文件修订，同次查询重复读取同一文档时发现修订不同会作废结果。文本缓存只在修订相同时复用，原始会话文件与越权路径不可读取。结果所列修订表示实际读取时的版本，不保证回答返回瞬间文件仍未变化。后台扫描继续独立使旧索引失效，不由查询触发全空间扫描。

### 7.3 返回内容与边界

返回结果包含查到的事实、实际读取来源、文档路径与修订，以及必要背景和未确认内容。只读过标题或摘要的来源不列入正文证据。无相关结果返回空；读取不可用、超时、修订冲突或读取失败时使用相应短原因，取消仍向调用方传播。`incomplete` 表示本次执行是否未完成，不再表示全空间待整理来源的覆盖统计。

查询不设累计读取字符或模型交互轮数预算，保留通用执行时限、单页读取限制、模型输出边界和取消。调用方取消或停止应传播到查询执行，迟到结果不能交给其他查询或已失效的调用。

查询 Agent 只读，不维护记忆、不执行脚本、不修改项目、不递归委派。历史资料中的指令、授权和目标是被查询内容，不自动成为本次查询或主会话的新指令。

上下文与记忆入口不叠加活动状态点，外环仅显示上下文用量；详情中的整体状态和任务项复用项目BubbleLoadingIcon气泡动画；记忆读取、设置处理、保存、继续读取及本地打开均显示动态提示，操作结束或失败后停止。SVG时间轴不受Windows减少动画偏好对应的CSS规则停用，终态和未知状态不伪造运行。

### 7.4 全局记忆入口

在输入框下右侧工具组末尾提供“全局记忆”SVG按钮。浏览列表只展示可访问范围内整理完成（ready）、标题单行且不超过30字、摘要非空且不超过200字、符合当前规范且无错误或不可用状态的会话；待整理、整理中、失败、空摘要及已失效的来源不显示，不使用原文摘录填充列表。列表标题与空态显示待整理、整理中、出错的计数；出错状态在同一区域按来源会话列出经过敏感信息收敛的具体原因，并以有界区域承载长列表，但不新增这些来源的摘要卡片，也不把旧摘要展示成当前内容。搜索同时匹配当前可见的失败来源与原因；已选来源失效时清除来源选择，保留搜索文字。没有有效摘要时显示“暂无已整理的摘要”。此显示规则不删除原文件，也不影响内部候选和后台整理：内部仍保留有实际资料或读取错误的来源，空白入口和纯模板仍不进入候选；当前会话的资料可以从左侧入口查看。当前按来源会话维护摘要，不自动读取完整对话，也不生成跨会话主题知识层。条目显示主题、摘要、入口字数、更新时间与已整理状态；字数按入口Unicode字符计数，含标点及空白。筛选不切换当前聊天会话。工作空间与来源会话采用应用内不透明深色菜单，沿用暖橙选中态与勾选标记；触屏筛选入口和选项至少44px，长标题可换行，长列表内部滚动，菜单在视口内上下避让且不受侧页裁切。方向键、Home／End及文字前缀可定位，Enter／空格确认，Tab或外部点击收起；Escape先收起筛选菜单，组合输入不触发关闭。选择后保持筛选入口焦点，切换记忆工作空间后也恢复该入口。

摘要完整展示并自然换行，不按行数截断。点击摘要只展开“关联记忆”，再点击其中的来源会话进入原文。摘要使用模型生成的主题，来源入口和原文详情保留原会话标题，搜索兼顾两者。当前每份摘要关联一份来源记忆，展开与来源按钮均支持键盘操作，来源按钮至少44px热区。原文顶部可展开“关联文件”和“引用文件”，再点击阅读详细资料、脚本源码或产物；返回按钮固定在展开面板左下角，沿用项目轻量按钮、左箭头、44px热区及正文水平内边距，逐层回退到来源记忆和摘要列表，保留筛选、摘要展开状态与阅读位置，不新增原始消息定位或对话回查入口。文档显示实际读取字数与 UTF-8 字节预算，分页合并、编辑预警、保存校验统一使用180 KB UTF-8上限；超限时保留草稿且不提交。Markdown／文本资料提供“打开本地文件”：`memory.open` 重新校验工作空间、会话、真实路径、引用权限和文档读取修订，打开磁盘版本，不隐式保存草稿；只允许 `.md/.txt`，脚本和可执行文件不交给系统执行。Windows 使用系统记事本，macOS 使用文本打开方式，Linux 使用系统关联并拒绝带执行位的文件；成功回执仅表示已提交打开请求，不代表窗口已可见。逻辑删除的会话仍可作为记忆资料来源，明确显示状态；被清理的记忆条目和失效摘要不得继续作为有效结果展示。

打开入口、浏览摘要、筛选和读取资料直接访问已保存的数据，不调用 memory_query、不启动查询 Agent，也不自动触发后台摘要整理。用户浏览与模型的语义记忆查询使用相同来源，但分别通过直接读取和同步查询工具完成。

全局视图独立订阅索引更新，详细资料按需读取。服务在没有记忆或目录订阅者时仍完成扫描、缓存与持久索引更新，但不构造目录发布负载或发送无人接收的推送；订阅建立时读取当前快照，因此不会遗漏这段期间的状态。列表区分加载、没有已整理摘要及筛选无匹配，目录读取失败按空列表展示；摘要因来源或依据变化失效时立即移除，重新整理完成后再显示。正在阅读的资料和编辑草稿保留，不因来源从列表移除而强制退出。关闭视图停止相关展示订阅，更新不重建聊天输入或任务进度展示。

全局浏览与记忆详情复用压缩／子 Agent 的右侧非模态抽屉：贴视口顶边与右边，最大520px、窄屏满宽，固定标题与底部返回区、正文独立滚动，下边缘停在当前入口工具栏上方8px；左侧统计详情仍使用锚定浮层。面板非模态，点击外部空白、再次点击入口、关闭或 Escape 收起；从面板内向外拖动不触发关闭。存在未保存编辑时，关闭、逐层返回及切换其他底栏详情均先提供继续编辑或明确放弃；确认前保持记忆面板可见，继续编辑保留草稿，明确放弃后再打开目标详情；修订冲突可读取最新版本，对照并合并后保存。文档链接提取与Unicode字数按正文缓存，无关状态变化不重复解析。不改 ui/ 原始设计源。

## 8. pi 执行池与租约隔离

查询和后台整理通过 `MemoryRunner` 的 `execute`、`stopProviders`、`close` 接口执行，当前实现为 `PooledMemoryRunner`，`ColdMemoryRunner` 保留为兼容导出别名。它与 Agent、压缩共用服务级 `ExecutionPool`；每次调用创建 `SessionManager.inMemory()`、固定空资源 loader、内存 settings、订阅及读取工具闭包，仅注册 `memory_read`，不加载项目指令、技能、扩展或普通 shell 工具。D 模式允许保留经过配置校验的 ModelRuntime；C 与 managed 模式使用单次记忆实例。

读取请求通过 IPC 返回服务端，由本次调用绑定的读取闭包校验工作空间、候选会话、文件路径、引用和修订，累计读取预算仅用于整理。进程只得到校验后的资料；图片读取只传存在提示，不生成或传递会被丢弃的 data URI。整理结束前，worker 对本次实际读取的每份资料发起仅修订 IPC 校验；任一修订变化即作废整理结果。查询不执行这项后验核验。每次执行的消息、工具闭包、订阅、权限和取消状态均独立。

同时执行数量与等待队列有界，记忆业务许可与物理池名额同时领取，超时包括排队和执行；真实活跃父租约的同步查询可以使用受全局上限约束的叶子预留。取消向所属租约发送停止信号并退役实例，宽限后强制结束；实际进程关闭前仍占物理名额。成功结果必须等待当前租约的清理确认，失败或退出异常不发布成功结果；收到的实际用量持续记入原调用，不能因取消删除消费。

租约身份由 instanceId、generation 和 leaseId 共同限定。准备期间配置变更拒绝执行，旧事件和读取回复不能影响新绑定。固定运行环境可在校验后保留，不能保留上一查询的消息、权限闭包或已消费 loader。预热、空闲回收和关闭遵循 [执行池说明](pi-execution-pool.md)。

## 9. 事实、来源与可信边界

会话记忆、后台摘要和查询结果统一遵循以下表达规则：

| 来源事实 | 允许表达 | 不允许扩大为 |
| --- | --- | --- |
| 用户说已经修复 | 用户表示已修复 | 当前代码已确认无问题 |
| Agent 报告测试通过，没有关联输出 | Agent 报告通过，未关联验证输出 | 已核实所有检查通过 |
| 工具当次退出码为 0 | 该命令当次退出码为 0，附实际输出来源 | 整个系统正确 |
| 不同会话出现不同结论 | 比较时间与适用范围，核实前并列来源，核实后仅修正或删除对应条目 | 无依据地选一个作为真相 |
| 用户明确否定具体记忆 | 删除指向明确的条目及重复摘要，保留纠正来源 | 擅自扩大范围或再次裁定是否接受纠正 |
| 未检索到资料 | 本次检索未找到，附范围 | 从未发生 |
| 召回内容截断 | 明确被省略内容及无法确认项 | 根据缺失部分猜测结论 |

不裁定对错指不凭模型主观判断裁决，不妨碍依据用户明确纠正和可核实证据修正或删除记忆。应区分用户陈述、Agent 判断、工具观测和未经验证的计划；无法核实的部分继续保留并标明不确定。

旧记忆只表示其中记录的当时情况，不能因存在这份文档就认定事实已经核实，也不能直接证明当前代码、环境或测试仍然如此。原记忆中的事实核实由执行任务的主 Agent 完成，后台摘要只概括已保存记忆，不查询原始消息或擅自执行验证。不得把“现在不成立”等同于“过去没有发生”。

## 10. 当前实施参数与边界

- 固定入口栏目与任务状态、整体进度估计按第 4 节解析；首次明确任务、关键事实或方向变化及最终回复前的维护检查随真实入口路径进入主会话系统提示。记忆目录变化触发按会话合并的后台扫描，外部引用每 60 秒作兜底复核；目录遍历、读取、哈希及稳定来源的摘要依赖核验在专用工作线程执行，主线程先逐项校验工作空间、会话归属和显式链接授权，再只提交同代次的快照、摘要失效和订阅更新。同轮相同真实路径的依赖只读一次原始字节，但每条依赖都必须匹配其会话、路径和修订。保存、主会话运行结算和会话删除仅定向标记实际归属来源，子会话结算不加入主会话记忆扫描队列；扫描按来源隔离异常，失效后台来源不会影响其他来源；消息发送不等待记忆扫描。快照、界面读取和订阅遇到不可用来源返回带短原因的空态，记忆查询失败返回空答案并标记未完成，不改变全局连接状态。内部资料核验和主动写入仍严格校验归属，避免空态降级绕过读取边界或覆盖文件。改名更新 catalog 主题与来源标题投影，已读和置顶不触发记忆目录扫描；旧扫描结果不能覆盖较新的修订。文本修订使用原始磁盘字节，保存时校验修订、文件身份及链接边界。来源或实际引用依据变化立即使派生摘要失效。
- 上下文与会话记忆合并入口放在输入框下左侧用量区，细实线外环以橙色弧长表示上下文占比，内部三条细横线表示任务三等分进度，上下文数值与任务投影留在详情；全局记忆 SVG 入口放在连续工具组末尾，不新增独立工具行。左侧任务详情使用锚定浮层；完整记忆与压缩／子 Agent 设置使用贴顶贴右的非模态抽屉，最大520px、窄屏满宽、底部避让工具栏8px；搜索、双列来源筛选及分隔列表依次组织，设置入口位于列表标题旁，整理失败在标题状态区按来源显示具体原因。摘要→展开关联记忆→来源原文→关联文件逐层展示，固定底部返回入口，未保存编辑保护同时覆盖关闭、返回和切换其他底栏详情。编辑绑定文件修订，订阅不覆盖草稿，冲突时可读取最新内容后合并。有效原型未提供专门记忆界面，新增布局沿用当前主题与交互语义，尚无逐像素设计等价依据。
- 查询／整理模型可分别选择，也可在各自菜单选择“使用来源会话模型”恢复继承；两项独立保存，未设置时使用来源会话模型。真实用量与未知消费进入所属主会话费用。
- 记忆业务默认总并发 12，最多排队 32，同时受统一池物理额度约束。查询与整理默认执行时限300秒（含排队）；整理另有累计读取240,000字符（UTF-16代码单元）和32轮模型交互限制。全局设置可保存时限（1–3,600秒）、整理读取量（16,000–1,000,000）及整理轮数（1–128），按 Enter／失焦生效，无需重启，已启动执行保持原设置，旧配置保留原值。查询不继承整理读取量与轮数，也不把全部标题计入累计读取预算。整理文件导航最多16,000字符，只截取完整文件条目并报告遗漏数量；整理提示先占用读取额度，再以余额读取正文，未完整读完不发布标题摘要。读取失败与整理预算不足分别提示，失败来源在后续周期重试。答案最多32,000字符，模型自身输出限制仍独立生效。
- 后台整理默认每5分钟检查一次，只提交连续30分钟未发生来源修订变化的记忆；稳定起点持久化，普通扫描不重置，重启后继续使用。文件变化只更新展示并使旧摘要失效，不即时启动模型，批次结束后不立即续排。每次最多推进4个可整理来源，优先较少尝试且较早更新的已建档来源，未知来源轮转定向扫描最多4个。未填写模板不发起模型请求，失败来源公平轮转。提交模型前与发布摘要前均重扫当前来源；模型只读取本来源，后验不扩张为全局扫描。
- 每次文本文件读取上限 4 MiB，对外按最多 16,000 字符分页；资料没有创作字数上限，超出读取预算对外按空资料处理，内部保留失败状态，不截断原文件冒充完整结果。界面编辑、分页合并与服务端保存统一使用180,000 UTF-8字节上限，超限提示并保留草稿；后台摘要要求同修订、从零连续读至末页的读取证据，不修改来源。图片预览支持 PNG／JPEG／GIF／WebP，最多 5 MiB；查询 Agent 当前只获得图片存在提示，不声称已经识别图像内容。
- 单次来源扫描最多 2,000 个文件、4,000 个目录；超预算对外按空记忆处理，内部保留失败状态。扫描只读，不重建缺失入口；监视目录消失时停止对应监视器，避免 Windows 重复事件造成扫描无法结束，后续低频校验仍可读取恢复的资料。大于 4 MiB 的产物按文件元数据判断变化，不全文加载；大型仓库与长时间负载尚未验证。
- 普通会话删除使用 `deletedAt` 逻辑标记，保留 JSONL、实际文件绑定、主会话记忆、子任务交付及托管附件授权。普通执行边界排除已删除会话，专用记忆读取边界允许查询其保留资料。
- 稳定来源身份为主会话 ID，SQLite 保存摘要、修订、偏好、纠正目标和实际用量。明确纠正由界面传入原文，清理同一工作空间匹配条目及重复摘要；历史文档不能充当当前删除授权。

进程池的预热、保留数、容量和回收参数统一由执行池管理。文件读取不建设独立原始消息索引或专用历史调用读取协议。

## 11. 建议实施顺序与验收

### 11.1 实施顺序

1. 实现 MEMORY.md 模板初始化、归属与文件绑定、现有文件工具维护及模型按需创建分类资料、变更监听与压缩后主动重读。
2. 实现会话逻辑删除与原始文件保留。
3. 实现稳定30分钟后周期生成30字标题与200字摘要、用户明确否定的条目清理及标题目录逐级查询。
4. 实现能力描述清晰、由模型自主调用的同步 memory_query，以及逐租约隔离的专用 pi 查询能力。
5. 在既有工具组接入本会话任务进度与全局记忆两个图标，复用同一资料来源并独立订阅。
6. 实现自然结束后定向检查最新待办并在原授权内接续，验证等待、停止、并发输入、准备与许可阶段竞态和防重复边界。
7. 接入单来源立即整理、工作空间待整理和仅清派生摘要接口，验证受理幂等、状态恢复、取消、清理晚到回写及草稿保护。
8. 验证压缩后重读、跨会话查阅、两处展示入口、并发修改、取消和重启场景，再同步产品文档与实际状态。

### 11.2 验收条件

以下是验收目标，不能据本清单推定所有场景已通过；实际检查结果见本文验证说明。

- 程序初始化共享 RULES.md 与各主会话 MEMORY.md 及必要父目录，不预建会话分类目录和其他资料文件；模型按需创建 references/、scripts/、artifacts/ 并在入口通过脚注引用。恢复和重复初始化不覆盖内容；文件变更被监听，不要求额外维护协议或自动关联消息范围。
- 主会话系统提示词说明维护责任、实际入口、信息取舍与读写时机，文件组织与格式由共享规则承载。每次压缩实际应用后，通过真实读取工具取得最新 MEMORY.md，详细资料按需读取，不自动把全文注入每轮请求。
- MEMORY.md 通常约 1,000 字、全文最多 2,000 字（含资料导航）；超出时模型转移详情并保留关键状态与引用，程序不截断。详细文件按主题拆分，不设统一字数上限。
- memory_query 的工具描述说明能力和来源边界，由模型自行选择调用时机；本会话压缩后重读不隐式调用全局查询。
- 上下文与会话记忆合并入口只显示细实线外环、真实占比橙弧和三行带对钩的任务进度标记，位于左侧用量区起始位置；全局记忆图标位于连续工具组末尾，不新增独立底栏。展开显示上下文准确数值、目标、状态、有效估计百分比、任务清单、当前进展、下一步与“查看完整记忆”；旧栏目只按明确兼容字段投影，不在首层展示原始正文，不可用状态不展示旧任务。详情展示入口及分类引用，无资料时隐藏分类，脚本只查看。布局、视觉、响应式及交互状态符合有效 UI 设计，不额外调用模型。
- 整体进度来自MEMORY.md中模型按10%步进记录的估计，文件保留估计口径，界面小于100时保留“约”，只有确认完成才为100%；未记录时显示“进度待评估”，无效或矛盾值标为待核对，不由界面猜测。完成项数量单独展示；范围变化允许下调，任务状态、百分比与下一步保持一致。
- 全局记忆图标展示可访问范围的全局记忆，支持摘要、详细资料和文件引用查看；打开与浏览不启动模型或后台整理，不增加原始消息查询入口。
- 两处展示独立订阅、按需读取，更新不干扰聊天输入、选区或未保存编辑；旧响应不串到其他会话，已删除条目不从旧摘要继续展示。
- 主会话和用户并发修改不会静默覆盖；其他会话和子 Agent 不能误写来源记忆。
- MEMORY.md 包含简要过程与对应详细文件链接；详细记忆包含必要背景、关键尝试、实际观察、方案取舍、验证结果与未确认项，可以独立理解和接续；文档、脚本和产物引用有效，陈述与验证结果不混淆，不要求逐轮复制聊天或工具调用。
- 会话逻辑删除后保留原始 JSONL 及程序维护的文件绑定；记忆查询与显式纠正不访问原始对话，不建立原始消息索引。
- 后台仅为连续30分钟未变化的来源生成不超过30字的工作标题和不超过200字的任务自然语言摘要，描述工作、问题、结果和当前状态，排除路径与实施细节，关联原入口与修订；任何来源变化重新计时，普通扫描与重启不重置未变化来源。模型不修改原文，用户明确指定原文时保留单独的纠正清理入口。
- 用户可立即整理当前来源或所选空间全部待整理来源，绕过稳定等待且不修改原文；受理与完成明确区分，重放无副作用，取消后不立即自动重试，刷新恢复状态，重启标记中断。仅清摘要保留原文、配置、纠正、用量和来源时间，清理后晚到结果不能恢复。
- 原始记忆的事实核实和修改由主会话与用户完成，后台不因证据不足或不同说法猜测删除，不按年龄或访问次数淘汰资料。
- 修改前校验来源修订，用户或会话的新修改不被覆盖；删除后相关旧摘要失效，摘要生成失败或迟到结果不会恢复已删除内容。
- 来源变化、读取失败和生成失败不会发布虚假的最新摘要；对外读取返回空内容，查询未完成用 `incomplete` 标记，修改失败不误报清理成功。查询记录实际读取时的修订，不在返回前重扫候选或已读资料；并发只读查询不会因扫描代次互相作废。
- 一次同步查询中的一个 Agent 先查看全部有效标题，再按相关性读取摘要、原记忆与必要详情；目录为空或不可读直接返回空，不设累计读取和交互轮数预算。只有标题或摘要读取时不返回事实答案，取消仍可传播，不读取原始对话补齐缺失。
- 每次查询使用新的内存会话、资源加载器和工具闭包，无上一查询的消息、队列、权限或回调；下一次执行校验当前配置与独占租约。
- 总并发、有界排队、超时、取消和退出清理符合约定；清理确认前不得再次借出，退出中实例仍占物理名额。
- 查询只读，脚本只阅读，历史指令不改变当前权限；模型用量和整理失败如实记录。
- 主会话自然完成后读取最新待办，只有无阻塞、等待用户或停止条件的明确未完成任务才自动接续，准备和模型许可前再次复核修订、归属与业务资格。接续沿用原会话和统一执行池，不新增用户消息或扩大授权。新输入优先且重复请求无副作用，并发新输入互不误取消，后续显式停止仍可阻止它们。相同任务状态不重复启动，每轮最多3次，重启不扫描或重放历史任务。
- README 与产品设计只在能力实际完成后标为可用；未验证的性能和场景继续明确列出。
