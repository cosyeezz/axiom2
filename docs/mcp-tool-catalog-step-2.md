# MCP 按需接入 · 第二步：工作空间工具目录缓存

**状态：设计定稿，尚未实施到产品。** 本轮交付方案与验收标准，不修改功能代码、不连接真实 MCP/模型、不安装依赖、不部署。实施前须完成并核验[第一步：会话内可控登记](mcp-session-control-step-1.md)；第一步文档或此前可行性脚本通过，不等于第一步工程验收完成。

## 1. 目标与边界

第一步解决“连接可控”，第二步解决“发现不必连接”：把 Pi 已真实发现的工具元数据保存成工作空间级目录，让其他获准会话离线读取，而不是为了知道有哪些工具再次建连。

- **共享元数据，不共享活连接。** MCP 连接继续归属 Pi 会话；Axiom 不增加 MCP 客户端、统一网关、请求转发或跨会话连接池。
- **目录不是执行注册表。** 缓存命中不代表服务在线、工具 callable 或启动已获授权；目录不得作为调用实参校验的最终依据。
- **读取无副作用，刷新须授权。** 枚举目录不执行命令、不联网、不激活 MCP；冷缓存也不例外。
- **默认兼容。** 产品预连接策略暂不改变。零连接断言针对空初始激活的测试宿主与目录读取路径，不冒充当前整个产品启动已零连接。

### 本步交付

工作空间目录存储、可信服务/配置/权限分区、会话只读投影、显式发现/刷新、完整快照提交、失效/恢复与自动化验收。

### 本步不做

缓存 stub、自动首次调用、把缓存工具注册进 Pi、修改原生 codemode/tool_search 搜索源或系统提示词、全量 schema 注入模型、Skill B、执行池 hash 调整、空闲回收、新前端面板、用户插件系统或懒连接默认上线。模型可用的透明发现/调用闭环属于第三步；第二步只交付内部可消费的离线目录接口。

## 2. 当前依据与必须补齐的能力

依据当前 Pi **1.1.0** 及 Axiom 源码，实施前重核版本与并行变更：

- [capability-resources.ts](../app/src/server/capability-resources.ts) 的 `discoverCapabilities()` 只读取服务配置和 Skill 元数据，不连接服务；它列出的是 **MCP 服务**，不是服务内的工具 schema。
- [capabilities.ts](../app/src/server/capabilities.ts) 保存的 `session_capabilities.catalog` 是会话能力选择快照。不得把它改造成全局工具目录，也不得用新缓存覆盖现有选择、legacy 会话或 reload 语义。
- [storage.ts](../app/src/server/storage.ts) 已使用宿主 SQLite，适合承担共享目录的事务与版本仲裁；worker 不另开一套散落 JSON 缓存。
- [execution-protocol.ts](../app/src/server/execution-protocol.ts) 有 instance/generation/lease 归属约束。元数据由实际发现的 worker 提交，父宿主验证归属后落库；此内部消息只传目录，不传 MCP 调用或连接句柄，不是转发网关。

### 2.1 不把逐工具注册误当完整快照

Pi 1.1.0 的 `registerTool` 包装能观察单个真实定义，但无法独立证明“本服务这一轮完整发现结束”：零工具时没有工具回调，旧工具隐藏也可能再次注册，逐条写入还会留下半份目录。`mcp_servers_change` 处理结束同样不能证明发现成功。

**定稿决策：完整快照观察是本步必要依赖。** 为原生 MCP factory 规划一个窄的、只读的“工具目录快照已完整应用”回调（具体 API 名在实施时确定，不是现有 Pi API）。要求：

1. 由 Pi 自己完成握手、分页发现、工具命名/冲突处理、schema 转换和原生注册；每次完整发现成功后输出一次快照，空列表也输出；发现失败不伪装为空目录。
2. 快照含服务关联标识、该连接内递增的发现序号，以及原始工具名到实际 Pi 注册名的映射和规范化元数据；不暴露 client、执行闭包、transport、完整配置或认证材料。
3. 与当前连接/第一步 generation 绑定；发现序号在该轮发现开始时分配，不按完成顺序倒贴。后续 `list_changed`、重连与曝光变化的完整更新也走同一路径；资源工具重复注册不冒充新目录。另提供窄的刷新失败/目录失效通知，以便宿主标 stale；不暴露底层错误秘密。撤销或 shutdown 后不发布成功快照。
4. 回调只复制数据，宿主异步入库；宿主回调抛错或缓存写入失败不能破坏已完成的原生注册/调用。注册中途失败不提交“完整成功”。
5. 原生过滤、REA policy 包装和服务来源契约保持；只能缓存该会话被允许发现的定义，不把原生归一化前的原始 schema 冒充实际 Pi 参数 schema。

当前 `McpExtensionOptions` 没有此完整快照回调。应在受维护的 Pi 源码及正式依赖产物中补充公开观察能力并固定版本，不直接修改 node_modules，不深导入内部 runtime，不通过解析 transport 消息重做 MCP 发现。若暂时无法取得可交付的依赖版本，此部分是明确阻塞，不能用静默计时窗口、解析 label/name 或部分目录冒充完成；纯存储测试仍可先推进。

## 3. 数据与身份契约

### 3.1 一份完整服务快照

以下是拟议内部数据契约，实施时可调整类型名，不得削弱语义：

| 字段 | 语义 |
| --- | --- |
| `formatVersion` / `producerVersion` | 缓存格式与 Pi/宿主投影规则版本；不兼容时拒绝复用 |
| `workspaceId` / `workspacePathKey` | 宿主可信工作空间身份与规范路径绑定；相同路径的新工作空间不自动继承旧 ID 数据 |
| `serviceId` | 来源、scope、精确服务名及内置身份构成的可信标识；不只按名称，不能让同名配置冒充内置 REA |
| `configRevision` / `visibilityPartition` | 影响目录的配置指纹与授权/身份分区；另用单调配置/授权 epoch 防 A→B→A 复活，由宿主生成，不只信 worker 自报 |
| `snapshotRevision` / `refreshEpoch` | 落库版本与宿主分配的尝试序号；防旧结果覆盖新版本 |
| `discoveredAt` / `expiresAt` / `contentDigest` | 宿主时间、有效期、规范化目录摘要；时间不是并发仲裁依据 |
| `tools[]` | 每项含原始工具名、实际 Pi 工具名、描述、规范化参数 schema；如存在则含规范化输出 schema、namespace 和受支持 annotations |

只持久化 JSON 元数据，不保存 execute/render 函数、调用结果、资源正文、资源工具目录、完整服务 instructions、command/args/env/headers、URL 凭据或 OAuth token。`namespace` 严格投影为 `{ name, description? }`，发送、存储和读取均排除 `namespace.instructions`，不能整对象复制。工具原生名称映射为本次发现的记录，不保证其他会话有相同冲突环境时仍同名；第三步须再次核对真实注册名，不凭缓存名称直接转交。

快照内部可保留用于过滤的 exposure 元数据；对会话返回时按当前策略重新投影。`hidden` 项不进入消费视图；direct 的目录存在不等于当前 active/callable。annotations 仅为服务声明的提示，不构成权限证据。

### 3.2 配置指纹与权限分区

- 配置身份覆盖有效合并来源、工作目录、command/args 或 HTTP 端点、env/headers/auth 配置、工具曝光规则，以及已知会影响目录的内置组件版本/策略版本。超时等纯生命周期参数不必导致工具目录失效，但规则须固定并测试。
- 不把原始秘密存入缓存或普通摘要。敏感配置需要参与身份时，使用宿主私有密钥 HMAC；密钥受本地私有权限保护，轮换/缺失使旧身份失效。HMAC 和私有身份字段不返回模型或公开错误。
- **计算身份不能启动进程或网络。** 不为求 hash 执行 `!command`，不为鉴权分区刷新 OAuth、不重复插值内置 REA 字面 env。可使用已有可信配置/凭据版本及已知环境依赖的本地摘要。
- 同工作空间、同可信服务/配置、同认证主体及可见工具策略的会话才可命中同一分区。凭据主体/授权范围变化使旧分区失效；单纯会话取消不改变共享目录身份。
- 若动态命令、隐式继承环境或 OAuth 状态缺少可验证身份版本，**保守降级为不可跨会话复用的分区**，返回需要显式发现；不谎称只按 mcp.json hash 就能安全复用。支持稳定复用的普通静态配置必须通过跨会话命中验收。
- 工作空间目录每次读取都验证当前 owner、工作空间授权、会话服务选择与工具过滤；提交时再次验证发现者归属、配置版本和可见分区。不允许发现者用更宽权限写入更窄权限分区。

描述/schema 也是不可信服务内容，可能夹带秘密或指令。本步不自动注入模型；worker 投影后、发送前执行字段白名单、大小限制及本连接已知凭据值检查，命中秘密时整份候选不发送，只发送脱敏拒绝状态；父宿主入库前再次校验。测试直接捕获本步目录 IPC 载荷，并扫描缓存和新增诊断，不能只检查数据库。不能承诺识别任意未知秘密，也不能靠通用正则证明内容绝对无敏感信息。

## 4. 读取、发现与刷新流程

### 4.1 只读目录接口

内部 `readCatalog(scope)`（拟议名称）只访问本地可信配置/授权和缓存，输出按会话投影的 `fresh` / `stale` / `missing` 状态、版本、时间及目录。未授权或已移除服务不返回其工具/私有历史，也不能借错误泄漏该服务是否曾被其他会话使用。

`fresh` 表示身份匹配且未过期的历史发现，**不是实时在线保证**。`stale` 仅可向仍获授权且身份未变化的内部诊断读取返回，并明确不能当当前目录；默认消费接口只提供 fresh 工具，stale/missing 的当前工具集为空。身份不符、格式损坏或服务已删除按 missing/不可用处理，不把旧 schema 继续投影。

读取不得调用第一步激活入口，不触发后台刷新、!command、网络或进程；缓存再冷也不例外。不注册任何可执行占位工具，不改变原生 tool_search/codemode 的行为。

### 4.2 冷缓存的显式发现

1. 调用者指定当前会话已获准的服务身份，不可传入任意 URL/command。
2. 宿主验证授权/配置/分区，分配 `refreshEpoch`，通过第一步控制器激活对应服务；不连接其他未请求服务。
3. 等待完整快照信号，而不是等待“至少一个目标工具”；成功发现零工具是合法空快照，失败/超时不是空快照。
4. 宿主校验来源、generation、epoch、schema/大小限制与当前身份，在一个事务内替换该分区快照；等待提交确认后才报告“目录刷新成功”。
5. 连接继续由第一步会话生命周期管理；本步不新增扫描 worker、临时共享客户端或自动 idle 回收，也不因目录写完就关闭其他调用正在使用的连接。

完整发现与提交确认使用单独的、宿主可配置的总期限，覆盖激活、完整列表和提交确认，不借用第一步的单目标工具就绪期限；具体默认值在实施时按宿主策略确定，测试使用短期限和假时钟。宿主负责期限与票据终态：未提交时超时则使本次票据失效、结算等待者并清理计时器，迟到结果拒绝，不自动重试。若事务已提交但确认消息丢失，按本地提交回执查询该 ticket 的结果；确认前返回“结果待确认”，不谎称回滚或重新连接发现。

### 4.3 已连接服务的刷新

- Pi 自然接收的完整工具列表更新可生成新候选，删除工具通过整份替换体现，不做只增不减的合并。
- 需要强制重新发现时，使用第一步“旧代际收尾后显式重激活”的路径。仅当该服务没有业务调用、没有等待中的调用且控制器可独占生命周期时允许；整个收尾/重激活期间阻止新调用进入。忙时返回明确的 busy，不打断在途调用，不建立第二条扫描连接。
- 同会话同服务的并发显式刷新合并为一次尝试，等待者分别取消；一个等待者取消不终止其他人需要的连接、不失效票据或改变目录 freshness。最后一个等待者退出后，已获准尝试仍由控制器管理至成功或期限终止，可正常提交；不因无人等待而另启发现。只有整个尝试终止/取消才失效票据；授权撤销/会话关闭同样使该来源候选失效。
- 跨会话**只做提交仲裁，不合并活连接**。不同会话显式刷新可能各有自己的连接；不承诺跨会话只握手一次。

## 5. 持久化、并发与失效

### 5.1 宿主 SQLite 单写入路径

新增独立工作空间工具快照表及尝试版本表，由现有 Store 所在宿主维护。快照按工作空间/服务/配置/可见分区唯一，完整 JSON 与元数据在一个事务中原子替换；尝试版本允许没有成功快照，失败状态不得覆盖上次成功内容或冒充有效空目录。

worker 经现有内部消息通道提交数据，附带发现开始时捕获的连接绑定身份与第一步 generation；不得在迟到回调里重新贴当前 lease。**连接绑定身份不等于 run lease**：后者只证明一次业务执行，前者须由父宿主新增可撤销准入记录，绑定实例、Pi 会话、工作空间、服务及配置/授权代际。启动登记和显式激活均先取得这种归属；有业务操作时另核验其 run lease，不能只靠现有 `LeaseRef` 证明连接持续有效。

合法 idle 保留连接与下一 run 可沿用同一连接绑定，自然目录更新不依赖一个已经结束的 run lease；换绑、reload、服务撤销、会话关闭、撤权或宿主重启使相关准入失效，新连接重新准入。父宿主每次校验准入仍当前且会话仍绑定原工作空间。此为拟新增内部元数据归属契约，不新增用户 HTTP/WebSocket 控制接口。

针对一个缓存键，宿主在发现前分配持久单调递增 epoch 和本次宿主实例 ticket，只有最新获准尝试的结果可提交；自然更新须沿用仍有效的连接准入 ticket，不在迟到回调时重新申请票据。新连接默认预连接产生的目录也先取得准入，不因它不是显式刷新而绕过仲裁。同一来源 epoch 内检查在发现开始时分配的原生序号，防止交错快照倒序。宿主重启使所有旧实例票据失效，worker 必须重新取得准入。

新尝试失败时，旧迟到成功也不得冒充新尝试成功；上次已提交快照可保留但按失效规则输出。配置/授权采用单调 epoch，覆盖同一 lease 内 reload、配置 A→B→A 和撤权后重新授权；内容 hash 相同不恢复旧票据。成功、失败与失效消息都携带开始时捕获的连接绑定、ticket、配置/授权 epoch 与发现序号，在同一事务仲裁路径验证；新失败阻止旧成功恢复 fresh，新成功也不受旧失败污染。

非发现事件不伪造发现序号：普通连接断开仅更新本代际连接诊断，不因离线自动否认仍未过期的历史目录，且旧连接断开不得覆盖新连接诊断。宿主执行的撤权/删除/配置替换则直接用当前授权/配置 epoch 失效视图与票据，不依赖 worker 通知。权限/配置变更与提交必须在事务内复核，不能只做事务外检查。

### 5.2 有效期与刷新失败

本步定默认有效期 **24 小时**，作为可调整的宿主参数；测试用假时钟，不等待真实时间。TTL 到期只变 stale，**绝不触发建连**。工具列表在 TTL 内仍可能远端变化，目录不作实时承诺。

显式刷新开始即把对应当前消费视图标为待刷新/不可 fresh；整个尝试失败、超时或终止后，历史快照保留为 stale，不自动延长有效期。单等待者退出不属于尝试终止，其余等待者仍可收到 fresh；全部退出但尝试继续时也允许成功提交。已有连接未经请求的自然更新失败若没有完整成功快照，也不得清空目录；记录脱敏诊断并保守标 stale。刷新成功清除该尝试错误。成功、失败、失效和取消通知均须校验相同 ticket/epoch/发现序号，旧失败不得把新成功降为 stale；已提交但确认丢失按提交回执处理，不归类为发现失败。

配置身份变更、认证分区变化、格式/生产者规则不兼容、服务移除、工作空间取消授权立即使对应视图不可命中。取消授权期间迟到提交拒绝；工作空间删除时清理关联行。普通会话关闭不删除其他会话仍可合法复用的已提交目录。

### 5.3 损坏、规模和写入失败

读取时校验格式、字段类型、名称唯一性、规范化 JSON schema 结构和 contentDigest；不执行 schema 中的代码、不远程解析 `$ref`。不支持的格式/损坏视为 missing 并返回脱敏诊断，不能中断整个会话或激活服务补救。

初始保护限额：每服务最多 **1,000** 个工具，单工具 JSON 最多 **256 KiB**，完整快照最多 **2 MiB**（均以 UTF-8 序列化字节计），JSON 嵌套深度最多 **64**；父进程在入库前再次验证，消息入口也限制大小。超限整份候选拒绝，不截断 schema 或保存前 N 个后标为完整。限额可由宿主统一调整，测试必须覆盖边界。

磁盘/事务写入失败不改动原生工具可用性，也不报告目录已持久化；上次快照保持完整。数据库无法读取时目录返回明确不可用，原生已连接服务不因此停用。工作空间删除时清理、配置新版本提交成功后回收同服务失效旧版本；读取不做联网维护，不增加后台 MCP 保活任务。

## 7. 验收标准

### 7.1 测试层级与计数边界

1. **纯目录/存储测试**：临时 SQLite、假时钟、合成快照；禁网络/子进程，不读取用户配置、凭据或生产数据库。
2. **真实 Pi 集成**：真实 AgentSession、正式快照钩子与原生客户端，内存假传输提供服务；直接走工具/生命周期管线，不请求模型。记录 transport start/close、initialize、tools/list、tools/call；列出父宿主存储提交/拒绝计数。
3. **Axiom worker 回归**：受控回环 HTTP 模型 fixture 与模拟 stdio 可使用，单独说明会有本地请求/子进程；不冒称零请求测试。构建如有需要在隔离副本完成，不覆盖当前 dist，不重启正式后台。

### 7.2 必须通过的用例

| ID | 场景 | 验收断言 |
| --- | --- | --- |
| B01 | 缓存存在，空激活宿主创建两个获准会话读取 | 两会话看到相同有效目录；新增 start/initialize/list/call 均为 0；不安装缓存执行工具 |
| B02 | 无缓存或损坏缓存读取 | 返回 missing，不联网/执行命令/激活；故障不影响其他缓存键或原生已连接服务 |
| B03 | 显式冷发现成功（单页 fixture） | 仅目标服务激活；一次 initialize/list；完整提交确认后 fresh，tools/call 为 0；重启目录存储后仍可离线读取 |
| B04 | 成功零工具与发现失败 | 前者提交合法空快照；后者有界失败，不提交空快照，不冒充成功 |
| B05 | 同服务多工具逐条注册及发现中断 | 完成前无半份 fresh 目录；中断无部分提交；完整成功一次替换 |
| B06 | 工具新增/删除/碰撞名/隐藏更新 | 整份替换，移除项不残留；保留 Pi 实际名称与原名映射，不按 label 拆分猜测；hidden 不进入消费视图 |
| B07 | 配置、来源、组件版本及工作空间身份变化 | 影响目录的变更产生隔离身份；同名服务/内置 REA 不串用；删除后同路径新工作空间不继承 |
| B08 | 同工作空间不同授权、身份或工具过滤 | 未选中/未授权/不同认证分区不泄漏目录；宽权限发现不能填充窄权限键；每次读取/提交复核 |
| B09 | 凭据/环境依赖变化及动态命令 | 有可信版本则正确失效；无法判定则不跨会话复用；求身份时零进程/网络，不执行 !command，不重新解析 REA 字面 env |
| B10 | 同会话 10 路显式刷新与等待者取消 | 合并一次发现；单个取消不失效票据，其他等待者获 fresh；全部退出后尝试仍可完成提交；无业务调用，无等待器泄漏 |
| B11 | 跨会话交错、同来源倒序、ABA 与宿主重启 | 新 epoch/序号胜出；新尝试失败不使旧票据复活；同 lease reload、配置 A→B→A、撤权再授权及宿主重启均拒旧票据；自然更新不重新贴票据，不合并两会话连接 |
| B12 | 刷新期间撤销/reload/shutdown/换绑 | 旧归属/代际成功及失败消息均拒绝；无重新贴租约；计时器/等待器清理；旧连接断开不影响新连接诊断或目录；已提交共享目录按规则保留或失效 |
| B13 | TTL、显式刷新失败、整个尝试终止 | 假时钟越界后 stale；失败/终止不延长 TTL，默认消费工具集为空、历史诊断有标记；旧失败/失效通知不改变新 fresh；无隐式重连 |
| B14 | 忙服务强制刷新与其他服务失败 | 忙时拒绝、不打断业务调用；空闲独占收尾后再激活；一服务失败不阻塞另一服务提交 |
| B15 | 写入中断、事务回滚、重启、格式不兼容 | 旧快照完整或新快照完整，无半行；错误有界；格式不兼容按 missing，不破坏原生调用 |
| B16 | 秘密与不可信元数据 | 已知秘密注入描述/schema 时 worker 发送前整份拒绝；捕获目录 IPC、缓存与新增诊断验证；父端复验；嵌套 namespace.instructions 哨兵被排除；无闭包/transport 持久化或 schema 代码/远程 ref 执行 |
| B17 | 规模上限、深度与畸形候选 | 边界内成功、越界整份拒绝；父端复验，不静默截断/标完整，不造成消息/持久化无界增长 |
| B18 | 工作空间撤权/删除及服务移除 | 读取立即失效、迟到提交拒绝；删除清理关联行；会话关闭不误删他人合法快照 |
| B19 | 默认行为及第一步回归 | 预连接/曝光/allowlist/REA policy 和来源契约/legacy/无效配置 reload 基线不退化；目录不成为授权或 callable 证据 |
| B20 | Pi 完整快照钩子契约 | 成功/零工具/列表更新/重连/曝光更新有完整信号；失败有脱敏通知而非空成功；中途注册失败无成功信号；资源重复登记不冒充发现；序号按开始分配、旧代际不发；观察异常/入库失败不破坏原生执行 |
| B21 | 多页发现及后页失败 | 完整遍历后仅提交一次整批目录，list 次数等于 fixture 页数；后页失败不提交部分目录、不清空旧快照 |
| B22 | 发现挂起、提交确认超时与确认丢失 | 宿主期限内有界结算并清理等待器；未提交票据超时失效、迟到候选拒绝；已提交但确认丢失由本地回执查明，不报假回滚、不再建连；失败通知不得跨代际污染 |
| B23 | 连接跨 run 与 idle 自然更新 | 旧 run lease 已结束仍可凭有效连接绑定提交自然更新；下一 run 不重贴旧回调身份、不新增连接；换绑/reload 后旧绑定消息拒绝；普通断开不伪造目录发现失败 |

### 7.4 完成判定

同时满足以下条件才算第二步完成：

- 第一阶段 A01–A15 已有通过证据；本步 B01–B23 均有正式自动化断言和通过证据，类型检查及必要兼容回归通过。
- 使用可交付的 Pi 快照观察能力接通真实 Axiom worker 与宿主存储，不仅是合成数据或临时脚本。
- 同工作空间的两个稳定同分区会话可离线复用目录，读取路径零新增连接；不同分区严格隔离。
- 冷缓存、零工具、过期、权限/配置变化、并发迟到、写入失败和退出清理均覆盖，没有隐式刷新和半份有效目录。
- 验收报告记录命令/退出码、依赖版本、发现/调用/关闭/提交计数、临时资源清理和未覆盖范围。真实 HTTP/stdio/OAuth/REA 未测时明确列出，不能用内存 fixture 代替真实服务结论。
- 默认连接策略未切换；没有注册缓存 stub、修改模型工具声明或新增跨会话活连接共享。

完成后第三步才接“从缓存发现目标 → 调用时按需激活 → 核对真实工具/schema → 原生调用”，并另行验收后决定何时关闭默认预连接。第二步完成不等于整体懒加载已上线。
