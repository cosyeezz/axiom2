# 下载与维护任务

Axiom 的维护任务用于应用管理的下载、检查、安装、验证和清理。任务及必要反馈显示在所属组件卡或资源页面，不再提供独立的“下载与维护”任务中心或任务记录入口。后台、浏览器和桌面标识说明操作实际发生的位置；远程工作台不会因此获得桌面安装权限。

## 连接页维护布局

“版本与更新”继续管理后台服务、终端 Pi 和桌面客户端；应用内 Pi 作为后台服务的环境依赖展示。“维护工具”中的“组件管理”和“环境与安装”复用 `ComponentCard`、`ComponentAction`、`ComponentConfirmation`，不再各自实现另一套卸载行和确认按钮。Pi、后台服务、下载归档及工具清理的确认在所属卡内展开，取消不提交维护请求；需关闭会话或保存工作的操作仍须单独勾选。

默认优先显示连接操作、三项组件名称、当前与最新版本、可用更新摘要；后台卡的“应用内 Pi 与安装设置”、终端 Pi 和客户端的“说明与安装设置”默认收起，按需展开说明、依赖环境与新任务的默认时限。折叠使用可键盘操作的原生展开控件，不卸载内容，也不触发安装或更新。“组件管理”和“环境与安装”在没有需要处理的状态时保持收起。

任务进度、失败和未决结果、恢复／核实入口、内联操作确认始终放在次要信息折叠区之外；收起说明不会隐藏这些反馈，轮询也不会反复打开说明区。取消和延长时限仍属于原任务，不转移到默认安装设置中。

上方连接区保留原标题和说明、设备／地址／端口选择、连接按钮、本机服务状态及启动／关闭确认。原有顶部安装提示、错误与文件下载反馈也保留；“环境与安装”中的所属程序卡承接完整任务、取消和延长时限等维护控制，不在顶部重复生成任务控制。安装进行中、当前安装失败或结果待核实时自动展开准备区。已结束的普通进度面板会收起，但中断、未知结果、恢复证据与手动核实入口仍保留。卸载后组件行消失时，工具卡的结果核实反馈继续可见。

本机服务读取失败时显示待核实，不沿用旧状态宣称已运行或未安装；顶部仍可只读校验，并暂停依赖该状态的维护操作。已打开的后台卸载确认也会禁用，撤销旧确认的提交授权并清除同意；在途预览一旦跨越状态未知，也不能因服务恢复或响应晚到重新授权。恢复状态后须重新预览移除范围并确认，不影响原任务的观察与核实。工具清理只有收到原生层在执行器启动前给出的明确拒绝证据，才会记录为可关闭的“请求未受理”；普通连接错误、超时或已受理任务的核实失败仍保留身份与未知状态，不自动重放清理。

布局复用不改变桌面 IPC、执行器或维护授权：原预览 token、版本和清理范围 revision、单次提交锁、任务编号、取消与延长能力、响应超时不重放等约束保持。Windows 的后台自动卸载限制、下载归档限制及 RTK 离线只读限制也不会因为换卡片而放开。

## 查看进度

下载阶段显示实际收到的字节、响应提供的总量，以及根据接收字节计算的速度。下载源没有提供可信长度时，不显示百分比。压缩包校验、安装器运行和程序自检分别显示阶段与耗时；安装器控制台没有输出不代表下载速度为零。

下载完成后，还可能需要校验、解压、安装和验证。只有整个任务完成才显示完成。版本检查结果、已安装版本和候选版本分别表示不同事实；安装候选验证失败时，不会把它报告为已成功接入。

当前任务的编号和时间预算可以展开查看。刷新页面或连接恢复后，应用读取任务状态，不会自动重复安装。后台重启后，原来进行中的任务标为中断，需要到所属组件页面核实实际安装结果。

旧的“安装任务记录”和“更新任务记录”入口已移除，但本机维护历史并未删除。应用通过本机桌面权限只读历史，不依赖远程后台连接；所属组件卡仍显示其他进行中、中断或结果待核实的尝试。已结束任务保留最近 100 条；进行中、中断和结果待核实的记录持续保留。重新读取证据不会重试安装或自动解除占用。当前任务的取消和延长操作仍绑定原任务编号，已结束记录不能重新获得控制能力。

部分历史记录损坏时，所属维护区域显示一条读取警告，仍保留已读到的未决证据，原记录不会被删除。当前安装记录损坏时，不复用旧快照宣称成功；顶层索引损坏也不会挡住其他有效历史。读取失败时保留已有信息，并停用不能安全使用的控制按钮，直到重新核实。桌面更新历史超过单次读取上限时明确报错，原始本机记录继续保留。

## 时间预算

| 预算 | 默认值 | 用途 |
| --- | --- | --- |
| 等待响应头 | 30 秒 | HTTP 请求发出后等待服务器开始响应 |
| 下载无数据等待 | 60 秒 | 已开始响应的下载连续没有收到数据 |
| 安装阶段 | 10 分钟 | 安装器或安装步骤的执行时限 |
| 任务总时限 | 20 分钟 | 整个已开始执行的维护任务 |

预算接受 1 秒至 24 小时之间的整数毫秒。运行中的任务只能延长预算；延长不重置已经消耗的时间。排队等待不占用执行预算。某项操作缺少可控制的执行机制时，界面不会提供虚假的取消或延长能力。

预算编辑器提供三种模板，选择后仍须保存：

| 模板 | 响应头 | 无数据等待 | 安装阶段 | 总时限 |
| --- | --- | --- | --- | --- |
| 标准 | 30 秒 | 60 秒 | 10 分钟 | 20 分钟 |
| 慢网络 | 60 秒 | 180 秒 | 20 分钟 | 60 分钟 |
| 大文件 | 30 秒 | 90 秒 | 60 分钟 | 120 分钟 |

修改数值后显示为自定义配置。默认设置仅供新任务使用，不会改写旧任务；为运行中任务套用模板时，每项预算至少保持当前值。保存失败会保留草稿，便于重试。

npm 下载由 npm 自身执行，应用通过安装阶段和总预算控制其进程。应用不会把 npm 控制台的沉默解释为某个 HTTP 请求的响应头或下载空闲超时。桌面 Pi 的安装位置检查与版本验证也使用当前任务的取消信号和总预算；延长预算会作用于正在执行的检查。

系统安装器接管 Node.js 或 Tailscale 安装后，应用继续观察安装阶段和总时限，并允许延长等待期限。此时不能通过取消父进程来声称系统安装已经停止。超时后显示“结果待核实”，保留安装占用并等待安装器退出；迟到的成功返回不会覆盖超时记录。观察进程意外退出时也保留占用。请核实系统安装器、重启要求和实际安装版本，确认安装器全部退出后再使用解除占用入口。

## 失败、重试与取消

应用管理的无请求体 GET/HEAD 请求，在收到响应前出现可重试的网络错误，或者返回 408、429、502、503、504 时，最多重试两次。重试遵守服务器的 `Retry-After` 和剩余总预算，可以取消。等待重试时会显示重试状态。

应用不自动重放安装、卸载或其他有副作用的操作。已经开始读取的响应体中断后，不会悄悄继续安装；再次下载通常需要从头开始，不承诺断点续传。

取消表示请求执行器停止并清理。任务在安装器及必要清理结束后才返回终态。如果无法确认进程已退出，任务保留“状态待核实”，不会被普通取消状态覆盖；相关归属记录和文件保留，后续冲突操作会被阻止。取消、超时和输出超限是不同原因；如果操作已经修改了文件，取消不意味着自动回滚。请按任务提示核实当前安装状态。

任务历史保存失败时，应用会明确报告记录未能保存。后台历史中只有部分记录损坏时，仍显示有效记录，同时暂停新的维护写入，保留原文件供核实；不会把损坏内容当作空记录覆盖，也不会据此重放安装。

错误诊断在展示前会隐藏可识别的凭据。日志超过保留上限后，第一行可能已经失去用于识别凭据的前缀，此时会舍弃该不完整行，保留后续完整行和错误原因；如果整段日志没有换行，界面可能只显示错误原因。原始日志的有界读取与结构化输出上限不因此改变。

OpenCLI 和 REA 的维护命令（包括组件检测、MCP 连接验证）、RTK 命令、代理内核安装与订阅临时检查、pi 资源包和资源页的独立 npm 安装统一接入后台维护进程组件。组件登记 PID 与归属记录，在发送操作前完成登记；正常完成、失败、取消、超时和后台正常关闭均通过同一停止入口清理。文件释放与配置提交仍等待清理确认；组件不按进程名称全局杀 Node，也不停止正式运行的代理线路。

macOS 使用独立进程组和 PID 管理：记录工作进程与观察到的子进程，先请求终止，再强杀仍存活的进程，并核实退出。记录还保存启动时间，用于降低 PID 复用误认的风险；这不是安全沙箱，`ps` 启动时间有精度限制。普通子进程继承进程组；被观察到的脱组子进程也会清理，但不承诺捕获在两次扫描之间完成脱组、改父进程的守护进程。宿主被强杀或系统异常时不保证绝无残留。重启后，仅在原宿主、进程组及已登记成员均已退出时允许回收记录；损坏或身份不全的记录仍需核实。macOS 不再因缺少 Linux/Windows 监督器而整体禁用托管安装和程序检查，具体工具仍受其 Node 版本、上游安装包、权限及网络条件限制。

Windows 保留 Job Object；Linux 保留随应用分发的原生监督器，等待整个 PID 命名空间退出后确认清理。Linux 需要支持用户命名空间、PID 命名空间和 pidfd，并允许当前用户使用这些能力。缺少原生组件或受到系统策略限制时，操作会明确失败，不会临时下载编译器或安装系统依赖。

宿主退出与清理确认不是同一件事。平台执行器确认清理后，应用才能解除对应占用；无法确认的中断保留待核实记录。进程被同时冻结或阻塞于不可中断的内核 I/O 时，不能承诺在固定时间内完成清理。

桌面当前更新任务显示“状态待核实”时，可以使用“核实中断任务”。核实会检查原父进程、所有已登记安装命令与后台启动请求的退出凭据。原进程仍在运行、凭据缺失或身份不一致时，继续保留占用与安装文件。旧记录不会因为升级了应用就自动获得退出证明。

核实通过后，先持久保存“已中断”，再按原身份释放安装锁与占用。若释放后的记录提交失败，普通更新仍被阻止，可以再次核实原任务；重试不会删除其他任务后来取得的新锁。此操作不重新执行安装，也不代表安装成功或已回滚。

后台启动请求退出仍可能留下正在运行的服务。存在尚未解决的服务事务时，核实会保留恢复记录，并要求先恢复旧版本；恢复失败后仍保留此限制，直到实际服务恢复得到验证。


## 安装位置与卸载范围

OpenCLI 和 REA 的安装命令退出后，任务仍需完成候选验证、配置提交和终态保存。整个过程保持同一工具的维护占用；目录身份和命令归属记录持续保留。中断后，来源页面提供“核实中断任务”，核对原操作编号及退出凭据后才允许新操作。核实保留候选文件和现有配置，不代表安装成功或回滚完成。未登记的进程、被替换的目录或归属记录会继续阻止清理。

OpenCLI 使用 Axiom 私有的版本目录，验证候选程序和技能后切换配置。旧 Agent 可能继续使用旧目录，因此旧目录不会在切换时立即删除。外部安装的 OpenCLI 只接入本应用；卸载外部程序应使用原安装管理器。

RTK 自动清理旧版本也会留下维护任务记录；进程退出尚未确认时保留候选文件。OpenCLI 和 REA 批量卸载中途失败时，已删除目录的原身份会保留到全部待删除引用提交完成，避免重试时误删同名的新目录。卸载意图另存于维护归属记录中，配置替换后的同步失败也会保留“清理残留文件”入口；重试继续核对原目录身份，最初已不存在的目录若重新出现则拒绝清理。配置提交会先同步文件，再发布替换；支持目录同步的平台还会同步目录。安装配置已发布但后续同步失败时，任务仍报告失败，并保留配置已引用的候选文件。这不构成所有文件系统和断电条件下的持久化保证。

RTK、REA 及其引擎、代理内核的托管清理会核对安装归属、目录和占用情况。原有绝对路径不能单独证明文件属于 Axiom。共享的外部工具、用户设置、订阅、节点及绑定不会因为删除一个托管程序而被作为程序文件清理。

Xray-core 安装时会一并从官方准备并校验分享链接识别程序 xray-knife，两者都成功后才提交内核安装记录。安装失败或取消时保留原安装记录，回收未提交的新内核；可复用的识别程序缓存归入 Xray 的清理范围。同版本 Xray-core 支持重新安装以补齐旧安装或修复文件。识别只使用已安装程序，缺失或损坏时提示重新安装 Xray-core，不在识别期间下载安装。卸载 Xray-core 同时清理识别程序、下载包及历史版本，保留线路、订阅和绑定；旧版识别程序残留也统一从 Xray 入口清理。安装、识别与卸载共用代理维护流程，不提供独立组件入口。macOS、Windows 和 Linux 均可进入维护流程，具体架构仍需上游提供兼容文件。正式线路使用独立的长期 PID 托管，不与临时维护进程混用。

资源包的发现和 Agent 加载只读取已安装资源。缺失或版本不匹配的远程 npm/Git 包需要在资源页显式安装，不会由加载过程隐式联网补装。

独立资源可以同时维护。安装过程中可以切换资源类型、作用范围和列表，继续编辑其他资源；任务按各自编号保留结果，较早任务完成时不会覆盖后来打开的表单。同一 npm 安装目录共享依赖树，因此互斥；不同 Git 仓库和独立安装的技能、MCP 可以并行。同一资源、路径、技能实际名称或 MCP 名称发生冲突时，应用会说明需要等待对应任务。技能移动期间会保留原范围和目标范围的名称占用；一个安装包中的多个技能分别检查名称。技能移动失败时只恢复本次修改的配置条目，保留其他已完成的安装。恢复配置失败时，保留仍可能被引用的文件和备份，提示核实其位置。后台重启会逐项标记中断的资源任务，不会重放操作。

资源页保存失败会保留编辑草稿，保存成功后重新读取实际内容。应用进程中的 Pi 1.1.0 设置存储使用版本绑定的兼容层：即使设置文件尚不存在，也先取得文件锁，再读取和合并。配置发现可以只读访问链接路径；通过目录、文件或硬链接别名写入会被拒绝。外部未加载兼容层的旧 SDK 进程不在此并发保证范围内。

资源页的独立 npm 安装在执行前保存安装记录。进程退出无法确认时，目录和记录持续保留；资源页提示保留位置，并阻止同资源的重复安装、更新或清理。安装日志采用有界截尾，较多日志不会被当作结构化结果超限而中止安装。

安装进程清理完成后，配置提交、回滚和任务终态仍可能尚未保存。此时继续保留待处理记录，不能仅凭进程退出删除目录或开放重试。恢复时核对目录身份与当前所有范围的引用，先保存中断结果，再结束父事务；其他任务已经保存的结果不会被旧内存快照覆盖。卸载预检与实际撤销引用使用同一范围和匹配规则，拒绝删除仍被引用的目录时，保留原配置和偏好。

卸载 pi 资源包时，先记录清理意图并撤销此范围的包声明，再调用包管理器清理托管文件。失败或取消后，资源页保留“继续清理”入口；刷新或重启不会自动重放卸载。清理完成前，同一包不能重新安装或更新。本地来源只撤销引用，源文件保留；托管目录仍被其他资源引用时会阻止清理。

本地 MCP 模板使用显式的 Node.js 脚本入口。需要下载 npm 依赖时，通过 npm 包字段发起受控安装；自定义外部命令仍按该命令自身的行为执行。

MCP 配置删除默认保留 OAuth 凭据。需要同时清理凭据时，在删除确认中明确选择对应选项；其他连接仍共享的凭据继续保留。

浏览器扩展由 Chrome 的扩展管理界面安装、更新和移除。打开官方页面不代表扩展已经安装或连接成功；回到 Axiom 执行连接检测，以实际结果为准。OpenCLI 的版本不代表浏览器扩展版本；没有可靠检测依据时，已安装和可用的扩展版本均显示未核实。

任务错误会区分网络、HTTP、各阶段超时、取消以及清理未确认，并显示发生阶段。下载源和网络路线只展示执行器实际提供的信息；没有提供时明确显示未提供，不根据配置猜测流量是否经过某条代理线路。
