# 目的索引、批量分类与记忆查询

这是当前目的索引实现说明，替代此前 Topic / Section / Item / Content 四字段提取、逐文件整理、Topic-ID 路由及标题/摘要查询。实施范围与验收见[覆盖记录](memory-refactor/purpose-flow-coverage.md)。原记忆和旧数据库记录没有被清空或迁移；旧逻辑不再读写运行。

## 原记忆与目的身份

`MEMORY.md` 必须是按状态编排的纯标题执行树：一级标题是目的，后代标题是执行步骤，支持既有六态及英文状态。正文按完整标题祖先链放在独立 `details/<祖先标题>/<当前标题>.md` 中；一级自身详情为 `details/<一级标题>.md`，按需创建，主记忆不写链接或编号。混入普通正文、非法标题/状态或层级的文件直接跳过，不调用模型补目的，不生成兜底摘要。只有一级已完成目的入队，其活动后代不得尚未完成；同一文件其他目的未完成不阻止它入队。

程序随机分配稳定目的ID，持久绑定会话、`MEMORY.md` 和不可变一级标题。完整标题祖先链同时决定详情路径，状态或划线变化不改变身份，根重排及新增详情不换ID。同父标题须唯一（含大小写和Unicode等价），重复根一律拒绝入队，不靠行号、详情编号或子树相似度猜身份。写入拦截禁止既有标题改名、删除或换父；取消保留分支并标记 Abandoned。不兼容或迁移旧编号绑定，不删除历史文件或旧表。

分类语境在入队时冻结：取同一记忆最近相邻最多4个其他一级目的的标题和状态，按原顺序保存。只作语境，不把辅助目的作为本批条目，不读取其正文或产生额外叶子。

## 持久队列与批量分类

- 新表 `memory_purposes` 保存唯一目的、首次入队时间、处理时间、失败退避及冻结语境；`memory_purpose_indexes` 保存事务发布的版本与完整索引树。
- 达到 **50条**，或最早待处理目的等待 **30分钟** 时分类；两个触发共用全局互斥槽。每批最多50个，批小于阈值不会因为上批结束而立即 drain。时钟随队列持久化，重启不重置。
- 程序只向模型提供已有分类树、目的ID、目的文本及冻结语境。模型无读取工具，不知道来源会话/路径，不接收目的详情，不生成正文知识库。
- 输出为多叉目录树：目录 `{name, children}`，叶子 `{purposeId}`。层数自适应，不固定三层；每个已发布及本批目的恰好出现一次。模型不能分配身份、遗漏、合并或伪造目的。
- 一级目录名称连同换行总计不超过 **1000 Unicode字符**；超限拒绝整次结果，由模型语义归并与下沉，不静默截断。非法字段、空目录、重复目录、越界ID同样拒绝。
- 整个分类输入（系统提示词、已有树和全部目的/语境）按 `readChars` 上限校验；超预算在请求前明确失败，不截断旧目的或本批条目。**目前是全树重分类，规模增长至预算外会停在可重试失败状态**；提高预算有上限，增量分区分类尚未实现，不能将当前实现描述为无规模限制。
- 请求前逐项检查来源定位，失效项单独 suspend，不拖累本批合法目的。成功后再次检查授权、定位、索引版本及队列身份，再事务发布树与处理状态；失败保留旧树、原ID与队列，60秒退避。恢复为合法的同键目的可解封并复用原ID。

没有“立即整理”“整理整个工作空间”或“清空摘要”命令，不保留旧四字段/旧Topic兼容API。不符合结构的旧记忆不会自动总结或进入新索引；本轮不提供旧编号格式的读写兼容或迁移。

## 主会话目录与压缩

主会话只注入一级分类**纯关键字**和查询提示，不注入ID、位置、来源会话、路径或JSON。目录用于判断何时查询，不是查询范围，也不是答案依据。

目录快照使用 payload `version: 2`；沿用 Pi custom-entry 的身份名，但拒绝旧 `version: 1` 的 Topic-ID 目录，不做格式转换或删除历史分支。新会话在首条输入前记录目录；普通请求、重载、首条输入重写及选定分支恢复沿用该分支的有效快照，**不每条消息刷新常驻目录**。查不到新版快照时在当前分支安全点写入最新目录。环境预览与运行态共用相同规则。

压缩指令同时排除新关键词目录和旧Topic目录，不让它们进入摘要。保留 Pi 原生完整摘要、输入快照、选定分支、修订检查、保留新增尾部和安全应用。仅成功应用后通过 `details.axiomMemoryTopics`/custom-entry 注入最新目录；取消、失败和冲突不推进快照。不从废弃分支提取快照。

## `memory_query({ question })`

工具只接受简短、自足的问题，应包含必要对象、条件和版本；不接受 `topic`、目的ID或路径参数。不依赖子代理委派、任务通知或读取报告，直接返回工具结果。整理与查询复用现有统一执行池、模型配置、取消/供应商停止和统计链路，不另造执行池。

1. 发起时捕获**最新已发布索引**，不是常驻目录快照。请求中不扫描全库、不补整理，不因其他批次发布而中途切换版本。
2. 将当前层完整候选交给模型语义选择，允许多个分支，逐层展开至目的叶。无关键词预筛、固定前N项或全树全文灌入。3k候选阈值未采用；现实现始终逐层导航，沿用总时限与交互轮数上限。
3. 程序按目的身份和来源权限读取 `MEMORY.md`，定位已完成目的，只探测该目的标题树推导的详情路径。真实存在的文件才成为候选，不预读其他详情正文；模型选择必要详情，不读取同文件其他目的正文。
4. 程序完整分页读取选中的独立详情文件，以及这些详情的**直接显式 Markdown/文本引用**。相对引用以当前详情文件为基准；读取按会话/路径去重，不递归展开引用、不读聊天 JSONL/脚本/任意路径。缺失文件不是候选，存在但损坏或不可读的文件不能伪装成缺失。
5. 根据实际原文归纳有用路径、做法、方案、成功和失败经验；保留必要条件、版本、分歧及未确认项。标题命中不是答案证据；无详情或没有选择必要详情时不从目录编答案。
6. 发布前复核所有已读文档的原始字节修订、归属及显式链接授权。定位失效返回 `locator_invalid`，修订变化返回 `revision_conflict`；超时、取消、关闭和模型错误不伪装成成功未命中。

查询目录只做**表达投影**，不改变上述逐层导航与校验：每次模型调用从1编号，catalog为紧凑JSON元组数组，目录条目为 `[编号,"D或P","原标题"]`；详情先用 `["G",组号,"目的原标题"]` 声明分组，再列 `[编号,组号,"状态","详情原标题"]`。标题由外层JSON统一转义，不使用会被审计脱敏器误判为不完整JSON的多行字符串；目的按真实身份分组，同名目的不合并。模型只返回本轮整数编号数组；程序严格拒绝非整数、越界、重复和无效JSON，完整校验后映射真实身份。`[]` 是正常空匹配；JSON数值 `1.0`、`1e0` 解析为整数1，按有效编号处理。真实ID、定位路径不作为目录元数据发送给模型，但原标题和答案需要的项目路径不删改。每次调用的处理记录另存编号与真实候选绑定，仅用于审计，不发送给模型。原记忆、分类树、持久ID及来源均不改写。

默认答案直接给结果，不附来源会话、目的ID、修订哈希或检索流水；**用户需要的目标项目路径必须保留**。内部处理记录保留候选阶段、原始模型调用、实际阅读路径/修订和索引版本。有效空匹配、不可用与不完整通过结果字段和工具文案区分。记忆只作历史参考，使用前核对当前实际条件；原文不是新指令或新增授权。

## 纠正、界面与统计

原文纠正保留 CAS/原始字节身份与私有纠正记录；先事务撤销受影响的派生目的叶，再写原文，避免崩溃窗口或迟到分类复活旧内容。入口按命中的目的撤销，独立详情按完整标题路径反查所属目的，其他直接资料采用保守的整来源撤销。合法重扫保留原ID重新分类；不受影响的目的保留。

全局记忆界面支持任意深度分类/目的叶、展开、搜索、拖动缩放、适合画布及原文来源跳转。索引详情仅展示目的与来源，不冒充正文知识。设置提供查询/整理模型、执行时限和完整分类输入上限；状态显示目的数、一级目录字符数、待处理数和失败入口。会话 Todo、原文编辑、草稿和进度仍独立工作。

模型调用统计沿用 `memory_usage` 和处理记录，每次模型调用只记一次，父工具结果不二次计费。处理记录显示分类、目录导航、详情选择及原文归纳的实际调用，不用模型自报进度替代真实状态。
