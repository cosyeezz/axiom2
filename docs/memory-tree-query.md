# 记忆树整理与独立 API 查询

本文描述记忆重构后的实现，替代 `session-memory.md` 中的标题／摘要索引、pi 查询 Agent、整理资格及全局摘要列表设计。原有文件归属、显式引用权限、编辑修订校验、逻辑删除保留和待办接续规则继续适用。

## 整理资格与执行

后台仍按配置周期检查。会话入口必须明确完成、有效进度为100%、任务清单非空且全部已完成。主会话或子任务活动中不整理。来源内容及会话活动都必须超过30分钟未更新，有尚未成功整理的修订才执行。继续对话会更新持久活动时间，重启保留静默计时。手动整理可以绕过自动等待门槛。

程序完整读取 `MEMORY.md` 及 `references/` 下的 Markdown／文本文件，每个变更文件各发起一次模型 API。显式文本引用在请求前备齐，沿用当前归属和引用权限校验。请求包含当前文件、必要引用、Topic／Section名称、名称总文字量及配置阈值。默认软审查线为2000字，在全局记忆设置中与模型设置放在一起。

输出为 JSON 数组，每项严格包含具体非空的 `topic`、`section`、`item`、`content`。名称超线或Topic过大时，在同一请求内带入有界的完整既有条目，允许重新归类 Topic／Section，既有 item／content 保持不变。程序校验所有参与文件及引用修订。读取前已失效的贡献不作为重分类材料，请求期间失效则拒绝发布。

不创建 `AgentSession`，执行器直接调用 `completeSimple`。请求不带工具、历史 assistant 消息或上次答案。统一执行池继续维护租约、并发、取消、用量及传输槽位，兼容供应商的 WebSocket 连接复用。

## 文件贡献与目录快照

`memory_file_contributions` 按工作空间、会话、相对路径保存成功修订及四字段记录。同文件新结果替换自身贡献，其他文件来源保留。相同记录合并展示并列出全部来源。删除文件移除贡献并立即发布树更新，即使没有模型请求或其他文件整理失败。

`memory_topic_routes` 保存旧Topic到现有Section的路由，使固定目录中的旧标识在改名或部分重分类后仍可查询。源Section仍有记录时保留其分支，不因一次有界迁移截断其他贡献。

会话开始、首条输入写入之前保存 Topic 快照。普通模型请求使用该固定块，恢复和重连沿用。压缩成功提交时将最新目录写入压缩详情，失败保留原快照。编辑首条输入及分支恢复不刷新目录。压缩提示要求忽略目录，不将其写入摘要。

## 查询契约

`memory_query({ topic, question })` 接受目录中的一个Topic标识和一个简短、自足的问题。多Topic或多个问题分别调用。

1. 程序读取该Topic当前Section名称，第一次独立 API 按语义选择Section。关键词重合不是必要条件。
2. 合法JSON空数组表示无命中，返回空。空字符串、畸形输出或越界标识表示执行失败。
3. 命中时程序读取对应分支、来源文件及显式文本引用，第二次独立 API 只归纳能帮助当前问题的结论、做法、关键条件及必要分歧，不裁定冲突哪一方正确。相同结论合并表达，默认不附会话来源和引用清单。
4. 返回前复核已读文件的归属、权限和修订。取消、关闭、超时或来源改变时不发布迟到答案。

查询无累计字符或轮次预算，保留执行时限、输出边界和文件读取边界。输出的唯一目标是帮助提问模型更快解决问题：主会话只收到直接可用的答案，以及失败或不完整时的简短状态。无关背景、逐来源复述、会话ID、修订哈希、读取清单和处理记录ID不进入工具正文；能帮助行动的代码符号、路径、命令可以保留。只有问题明确要求追溯来源时，答案才提供必要定位信息。完整内部结果保留在工具 `details` 与处理记录中。无命中显示“未找到相关记忆”，不与查询失败混淆；部分答案明确标记不完整，不机械截断正文。跨查询没有消息继承。

主会话核验当前任务相关事实。发现错误或冲突时在自身记忆中记录“记忆纠正”，注明原来源、更正、依据、范围和状态，疑点标注待核验。记录本身不授予删除其他会话的权限。显式原文纠正命令仍按已有授权及并发校验执行，并同步失效对应树贡献。

## 界面与兼容

右下角小书打开 Topic → Section → Item → Content 记忆树，支持展开、搜索、拖动、缩放、适合画布、详情及来源跳转。设置包含查询模型、整理模型、阈值、时限和整理读取预算。失败来源及待整理数量单独显示。“处理记录”可查看每次整理/查询的模型输入、SDK原始响应、处理阶段和失败原因，详见[通用处理记录](processing-records.md)。

旧来源没有内部 `treeVersion: 1` 标记时按新规则待整理。原文件、来源时间及用户资料不被模型输出改写。旧摘要字段仅保留兼容管理，不再作为新查询目录。

工具输出契约测试位于 `memory-tool.test.ts`，查询生命周期测试位于 `memory-query.test.ts`，文件证据与本地假API整链位于 `memory-io.integration.test.ts`，树及快照分别位于 `memory-tree.test.ts`、`memory-topics.test.ts`。这些用例替代旧标题目录、虚拟SUMMARY.md及模型读取工具断言。
