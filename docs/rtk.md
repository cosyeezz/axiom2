# RTK 内置输出过滤

在「内置工具 → RTK」检查更新并安装官方 Apache-2.0 `rtk-oss`，再启用过滤。默认关闭，默认等级为均衡。安装、重新安装和更新都不会自动启用；更新由用户触发，不自动降级。安装前可以先调整过滤设置；未保存的设置不会阻止安装，安装完成后仍保留这些输入，点击「保存过滤设置」才会生效。

RTK 对已经成功执行的 shell 工具文本做有损摘要，不改变命令，不绕过权限，也不重新执行失败的命令。主代理和子代理使用同一设置，可以单独关闭子代理过滤。设置保存后适用于已打开会话的后续工具结果；处理中若配置版本变化，丢弃该次过滤结果并保留原输出。

## 等级与适用范围

| 等级 | 可识别范围 | 最小输入 | 最低净缩减 |
| --- | --- | --- | --- |
| 保守 | Cargo / pytest / CTest / Vitest 测试，Go JSON 测试，Prettier 检查 | 2 KiB | 20% |
| 均衡 | 加入 Git 简短状态与文件路径列表 | 1 KiB | 10% |
| 强力 | 加入带路径、行号的搜索结果及标准 Git diff | 512 B | 5% |

门槛以 UTF-8 字节计算，净缩减包含附加的原文回查提示。识别同时检查命令和输出格式；同名命令并不保证会过滤。`python -m` 只识别 pytest；`npx`、`pnpm exec`、`yarn exec`、`bun x` 只识别 Vitest/Prettier，`uv run` 只识别 pytest（含 Python 模块形式）。任意项目脚本（如 `pnpm run fd`）不按脚本名称推断工具。参数解析区分选项、选项值和 `--` 后的位置参数；`rg -- --files` 不当作文件列表。文件列表只接受已知保持路径输出的参数，执行命令的 `fd -x/-X`、`find -exec/-execdir` 等会保留原文。Git 词级差异、二进制补丁和非标准输出参数也保留原文。Windows 的 `find.exe` 是内容搜索工具，按不支持处理；文件列表可使用 `rg --files` 或受支持的 `fd` 参数。

Read、MCP、嵌套工具调用、失败命令、SDK 已截断的输出、混合图片结果、未知结构化契约、超过 1 MiB 的文本，以及不支持的测试格式（例如 TAP）不处理。复合 shell 命令、管道和重定向通常不处理；允许简单的 `cd … &&` 前缀。引号内的字面量按参数解析，例如 `rg -n 'foo|bar'`、`rg -n '\bfoo$'` 和 `rg --files --glob='*.ts'`；双引号内的变量展开、命令替换和转义仍保留原文。无法过滤或净收益不足时，仍使用原结果。

## 原文与隐私

只有先成功保存原文，才会把工具文本替换成摘要，并附绝对路径供模型或用户回查。原文是 Axiom 收到的工具文本；已被上游截断的结果不宣称保存了完整进程输出。结构化输出和退出状态保持原值，因此程序调用接口仍可使用原数据。

数据位于 Axiom 数据目录的 `integrations/rtk/`：

- `config.json`：开关、等级、子代理设置、配置修订号和活动安装。
- `versions/`：独立安装的程序与许可证，不改系统 PATH 或全局 RTK。
- `job.json`：最近一次检查、安装或自检状态。
- `effects.sqlite`：效果记录，不含命令正文、参数或输出。
- `originals/`：有损过滤前的工具文本，可能包含项目敏感信息。目录和文件在 POSIX 下分别以 `0700`、`0600` 创建。

原文保留 7 天、最多 200 条；效果记录保留 30 天、最多 5,000 条。启动、定时维护和相关数据读写会清理过期数据。关闭过滤停止产生新的效果记录和原文，已有记录继续按期限清理。界面可分别清空统计或原文；删除原文后，旧聊天中的回查路径会失效。清理不删除聊天记录本身。

过滤通过本机 `rtk pipe` 的 stdin 执行，不向下载服务发送工具内容。子进程禁用 RTK 遥测、recall 和 tee，并将上游数据库路径隔离到 RTK 数据目录。安装与检查更新需要访问 GitHub；这些配置不等同于网络隔离沙箱。

## 安装与故障处理

检查更新使用 GitHub 稳定版元数据，只接受预期的官方 OSS 资产及校验文件。下载限制域名、重定向、时间和大小；核对官方 SHA-256 后，仅提取预期程序和 LICENSE，再验证版本、UTF-8 stdin 透传及文件列表缩减能力。通过后原子切换活动版本。校验、自检、取消或配置冲突均不切换当前安装。服务退出中断的任务不会自动重试，重启后需重新检查。

运行时过滤有超时和输出上限；程序缺失、异常退出、取消、无效 UTF-8 或原文保存失败时保留原结果。自检可验证安装健康，但自检样本的收益不代表实际任务收益。

启动和每小时维护会清理旧安装目录：保留活动版本、最近一个非活动版本，以及修改时间不足 24 小时的目录。短期宽限避免影响正在安装的版本；清理只针对符合托管命名规则的目录，不跟随符号链接。

平台映射包括 macOS arm64/x64、Linux arm64/x64 和 Windows x64；当前真实官方包验收在 macOS arm64 上进行，其余平台尚无实机验收结论。

## 如何读效果数据

「净缩减」是观察到的工具文本输入字节减去返回文本字节；失败、未支持和低于门槛等旁路记录前后相等。平均耗时包含分类和过滤等待，属于后处理观察值。统计不覆盖停用期间或未接入的工具。

这里没有 tokenizer 计数，也没有模型请求缓存、推理、计费或完整进程输出数据，不能将百分比解释为 token 或账单同比下降。JSON 导出包含所选 1/7/30 天窗口的汇总与最近 50 条明细，受 5,000 条滚动保留上限影响。

## 验证入口

在 `app/` 目录执行：

```sh
npx tsc --noEmit
npx tsx --test tests/rtk.test.ts tests/rtk-worker.test.ts
npm run build
npx tsx tests/rtk.check.ts
npx tsx tests/builtin-tools.check.ts
```

浏览器测试可用 `AXIOM_TEST_BROWSER` 指定本机 Chromium/Chrome 程序。单元测试使用注入的发布包和执行器；worker 测试使用真实 SDK 与本地模型协议 fixture，验证主代理、`noExtensions` 子代理以及权限钩子。真实官方发布包的安装与过滤验收证据另存于 `app/test-results/`，不会作为全局安装。
