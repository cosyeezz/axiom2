# 多账号管理整页视觉重构

> **历史方案，已被用户拒收。** 下列竞品研究与离线测试结果留作记录，不代表真实视觉效果已获认可。实际 direct 不可查询态漏测，旧结构仍像空报表。当前重新设计见[真实状态优先方案](model-accounts-redesign-v2.md)。

## 1. 目标与边界

本次重构覆盖**整个多账号管理页面**，不只是卡片：顶部布局、搜索筛选、供应商分组、普通/订阅账号卡、空态和详情均采用一致的信息层级。删去功能复述、长篇介绍及重复导航，保留干净、可操作的页面结构。

调研方法是实际访问公开官网，读取页面/DOM 样式并人工检查截图；不登录其他网站、不读取真实账号、不操作订阅或支付。组件示例、营销产品示意与登录后的真实后台明确区分。借鉴组织原则，不引入竞品组件库、品牌色或营销装饰。

实现限定在账号页面、账号展示包装、页面专属 CSS；共享额度组件增加可选展示插槽与默认关闭的 `summaryFirst` 排列选项，公共默认顺序、进度方向及请求行为不变。账号页补强重读失败时的确认反馈，但不改认证、服务端、切换协议、额度查询/缓存、可见性轮询或金额算法。不重启实际后台；验证使用本地临时服务、合成凭据和离线数据。此处增量边界相对本轮视觉重构起点，不能把 Git HEAD 中前一阶段的累积功能变更归入本轮。

## 2. 官网研究

### 2.1 Vercel Geist：信息纪律与最低足够层级

来源：[Entity](https://vercel.com/geist/entity)、[Materials](https://vercel.com/geist/materials)、[Context Card](https://vercel.com/geist/context-card)、[Progress](https://vercel.com/geist/progress)、[Gauge](https://vercel.com/geist/gauge)。

原始 `/geist/card` 已跳转到 introduction，**不是取得了独立 Card 规范**。本次使用实际可访问的上述官方组件文档。

- Entity 的左身份/右动作、主标识14px/20px且600字重、16px内边距/组间距，使条目不用大面积背景也能被快速识别。右侧只保留一两个控件，低频信息按需查看。
- Materials 强调使用足够区分背景的最低表面层级：常驻卡与浮层不应同样隆重。不在一个元素上叠加多套阴影和边框。
- Context Card 是 hover/focus 补充信息，不适合作为整个账号管理的唯一承载。
- Gauge 适合明确分母的配额，Progress 更偏向任务进度。Axiom保留有文字方向的细配额条，而不是机械套圆环；没有分母不画比例。

**采用**：紧凑标题/动作、身份主次层级、最低足够表面、完整但低频的详情、状态文字冗余。**不采用**：文档目录/装饰网格、hover 才能操作、为统一外形隐藏信息，或把“当前”“授权健康”“额度充足”混成一枚绿点。

### 2.2 Stripe Billing：金融信息的语义精度

来源：[Billing](https://stripe.com/billing)、[英文实际页面](https://stripe.com/en-sg/billing)、[usage-based billing](https://docs.stripe.com/billing/subscriptions/usage-based)、[billing credits](https://docs.stripe.com/billing/subscriptions/usage-based/billing-credits)。

Billing 是**公开营销页中的产品示意**，不是登录后的控制台。实际用量卡宽350px、padding16px、圆角6px、淡色1px边，指标名12px、数字14px；方案、结算周期、计价单位各占不同层级。叠卡和图表服务营销，不是Axiom的布局依据。

- “过去30天用量”“按月结算”“每千单位价格”分别表达统计时间窗、账期和单价，不能揉成一个含糊数字。
- Ledger balance、available balance、credit grant及到期生命周期并非同一概念。
- 营销条形没有可核验分母，不从其长度猜测剩余比例。

**采用**：指标+数字+单位+时间范围、已用/剩余明确、到期与重置区分、旧值与失败分开。**不采用**：紫色营销视觉、模拟价格/增长、叠卡遮挡、将点数换美元、将无归属本机账单当账号余额。

### 2.3 Raycast Pro：暗色的亮度分层

来源：[Raycast Pro](https://www.raycast.com/pro)，公开功能营销页。

“Stay in sync.”实际功能卡在1003px视口下约940×285px，12px圆角、白色6%细边，padding30px24px、gap30px。标题白、解释灰、表面亮度仅微升；宽卡与双列卡根据内容安排。

**采用**：中性暗表面、细边框、清楚的组间留白、标题与解释层级、内容决定高度。**不采用**：hero巨幅留白、功能插画、紫蓝光效、图像占卡片一半。管理工具需要尽快到达真实账号，而不是讲产品故事。

### 2.4 Clerk Pricing：头部、主数值和内容分层

来源：[Clerk Pricing](https://clerk.com/pricing)，公开定价营销页。

Pro卡头实测334×225px左右，20px内边距、8px圆角、白8%内ring与很轻的表面渐变；名称18px600。名称→主价格→周期→动作集中在头部，功能列表与其分层。

**采用**：身份/指标/动作各自有位置，主数值显著高于标签，低对比表面与边线表达精致。**不采用**：长功能清单、推荐/促销标记、蓝紫品牌色和发光轮廓。“当前账号”不等于推荐套餐。

### 2.5 shadcn/ui：公开工具页示例的结构

来源：[Dashboard example](https://ui.shadcn.com/examples/dashboard)。这是**公开交互组件示例**，不是某公司的真实业务后台。

示例是侧栏+紧凑内容顶栏+指标网格+主体数据区，标签弱、数值强，状态badge小而明确。实际Card为14px圆角、1px中性边、白底、24px组间距。

**采用**：工具页层级、搜索贴近内容、标题和唯一主要动作、强数值弱标签。**不采用**：其库或全局主题，也不添加模拟总收入/增长曲线/健康评分。Axiom没有可归账号的账本，不能用假统计填页面。

### 2.6 Linear：低噪边界不是低对比文字

来源：[Features](https://linear.app/features)，公开功能营销页，实访HTTP 200。Planning卡实测背景`rgb(15,16,17)`、16px圆角、padding32px24px，分类13px、主要描述20px；两者约510字重，通过尺寸和字色而非大色块分级。目标anchor本身computed border为0，不能将视觉边缘武断记作1px border。

**采用**：低饱和中性表面、少量状态色、清楚主次、弱分组。**不采用**：64px hero、叙事bento、光效/大插图和整卡切换；账号需要稳定等权扫描，并包含多个独立操作。

### 2.7 Supabase：比较轴与量纲

来源：[Pricing](https://supabase.com/pricing)，公开定价页，实访HTTP 200。套餐名22px、主价格46px，单位较小；白/近白表面、细分隔，各列比较轴一致。390px实访为单列，不压缩成长身份挤不下的两列。

**采用**：数值与单位分层、稳定比较轴、移动端单列。**不采用**：品牌绿色、Most Popular推荐突出、营销长权益清单和巨大主数值。账号“当前”不是推荐购买，不创造跨供应商总余额。

### 2.8 Resend：定价模块与公开工具页图

来源：[Pricing](https://resend.com/pricing)、[官网首页](https://resend.com/)，均实访HTTP 200。Pricing卡价格36px、细分隔将额度/权益/动作分层；仅借模块节奏，不抄76.8px serif标题、估价滑块或纯黑主题。

官网“Everything in your control”有`Resend Dashboard - Overview`产品图（已滚入确认图片完整加载），可见窄侧栏、简短Metrics标题、右侧次操作、等权指标卡、标签左值右的明细。它是**官方静态公开示例，不是本次登录或后台交互验证**，不能由图推断筛选/sticky行为。

**采用**：导航/标题/操作/内容网格各司其职，弱标签强数值，明细对齐。**不采用**：其业务指标、假统计和大图表；不把营销页图当运行行为证据。

## 3. Axiom现状与问题

- 顶部先解释展示资格，再展开登录与指标长文，底部还重复模型服务/统计导航；真正账号内容被推后。
- 普通与丰富订阅卡共用约220px槽位。订阅卡在桌面比手机更窄，多个指标挤成细长信息墙。
- 名称、身份、区域、主数值和解释多为10–12px，重点不突出；缺少识别身份的视觉锚点。
- 更新时间/刷新与详情/切换分成两个工具区，图标目标过小。
- 账号账本不可归属，却为每个窗口重复“金额—”和同一句理由，增加高度但没有新信息。
- 原页面若干共享额度class样式未限定页面，存在影响会话详情的风险。

## 4. 整页信息架构

```text
共享设置导航 / 多账号管理

多账号管理                           [刷新列表] [＋ 添加账号]
[搜索账号、邮箱或区域……………………]   [全部供应商 ▾]     N 个账号

供应商名称  N
[账号卡] [账号卡] [账号卡]

另一供应商  N
[普通卡] [普通卡] …
```

- 保持共享侧栏和面包屑，不改变其他设置页面的几何。
- 正文不放hero、副标题介绍、登录教学、凭据宣传、重复页脚导航或大块空统计。
- 主操作只有“添加账号”；“刷新列表”是次级操作，**不改成刷新所有额度**。
- 搜索、供应商筛选、结果数组成同一工具栏。无结果提供清除筛选，首次空态只保留一条资格说明及模型服务入口。
- 供应商标题只含名称和数量；不重复provider ID和说明段。资格仍在完整账号集上计算，搜索不改变资格。
- 成功反馈简短；错误、断线与旧数据仍明确可见，不能为干净而隐藏异常。切换提交后若权威列表重读失败，旧标识改为“上次选择”，禁止继续切换并提示刷新；已打开的确认框也禁用提交，成功重读后恢复，不把旧卡片假称为已确认状态。

## 5. 账号卡规格与落地选择

### 统一骨架

1. **身份头**：无需外网资源的本地字母标识、账号名、文字“当前”；区域/Auth为次级元信息，真实邮箱或账号ID保持可达。
2. **内容区**：普通卡紧凑显示明确额度状态；订阅卡显示完整套餐/点数/独立窗口/重置次数和日期。
3. **底部操作**：更新时间、刷新、详情、切换放在一个工具区，允许窄屏或放大时自然换行；整卡不是按钮。
4. **详情**：保留认证来源、企业Start URL、区域、流程、有效期和授权信息；额度来源/点数不换美元的解释按需查看，不常驻抢主视觉。

### 普通与订阅分流

- 普通卡采用紧凑列宽与自然高度，保留旧fixture的20%–35%面积密度约束；不套固定高度，也不放无意义头像大留白。
- 数据丰富的订阅组使用更宽的独立列槽位，不把普通卡全部放大。指标分组可扫读，而非每行都是相同字号。
- 点数与次数为摘要项；账号显式开启 `summaryFirst`，复制并稳定前置这些指标，DOM 阅读顺序与视觉一致，公共额度及会话详情默认不变。所有窗口仍分别呈现。主值保留原字符串精度；窗口明确“剩余”，辅助已用、重置和可用性保留。
- 不用统一高度、max-height、line-clamp或折叠整个额度面板来藏指标。只有已有的重置券日期明细使用原生details。
- “预计可用金额 —”和“本机账单未按账号归属，无法估计此账号金额。”只出现一次，不重复每个空窗口；不读取ledger，不推算美元。

### 视觉

- 使用系统dark `#08090a / #191a1b`与暖橙`#f0995b`，light暖白`#f7f6f3`/白面及`#a94f1d`；不改全站token。
- 8px常驻卡圆角、12px面板节奏；中性细边框，无重阴影、光晕、左粗条。当前使用完整细边框和小文字标记。
- 页面标题约22px，账号名14px，主要指标16–18px，次要文字优先12px。使用系统字体、tabular数字，不制造过多字号。
- 图标中性灰，hover/focus提亮；禁用规则沿用系统。暗色靠亮度，不靠投影；亮色靠白面和柔和分隔。
- 新CSS全部按`.model-accounts-workspace`或`.model-account-card`限定，portal详情使用唯一dialog class；不改变官方额度/金额页/会话详情。

### 响应式与可访问性

- 网格使用auto-fill，筛选只剩一张卡时不拉宽；align-items:start避免普通卡被同排长卡撑高。
- 窄屏采用内容优先的列数，不为了两列把操作和长身份挤到不可读。本次明确从旧的窄屏普通两列调整为内容优先auto-fill：普通最小240px、订阅最小320px，因此320/390px均单列；保留桌面普通密度，补临界600/680与放大实测。
- 字体和几何经现有displayTypography统一缩放；自定义尺寸变量显式乘`--display-font-scale`，防漏缩或双缩。
- 触屏及窄屏可点击目标至少44px（放大时可增长），桌面 fine-pointer 目标至少24px；键盘focus-visible明确，状态不只靠颜色。320px、200% 应用字号下进一步收紧添加按钮的横向留白，让刷新与添加同排，不缩小文字或触控目标。
- 普通文字对比度至少4.5:1；完整身份可通过title/详情访问，其他指标不截断；页面和卡片均无横向溢出。

## 6. 业务与安全不变量

- 不改变每provider独立active、账号auth/cache隔离、切换确认及写后权威重读。运行任务固定captured binding。
- 普通provider至少两个Auth；单OpenAI OAuth豁免；无type不计数。先判资格后搜索。
- 每卡只挂载一份额度组件；屏外按需、隐藏暂停、恢复补读、abort/迟到保护不变。默认60秒加抖动，同时尊重服务端更近的刷新时间。
- 0、unknown、不限额分开；unknown不画0进度。OpenAI显示剩余，公共组件默认仍已用。
- 所有主/附加窗口、点数原值、重置次数/日期/完整券明细保留，live套餐与邮箱优先级不变。
- 不真实OAuth/额度/付费模型调用，不读/回传真实secret，不新增认证刷新，不消费券，不把点数/%或混合本机账单换成账号USD。
