# 模型请求覆盖

供应商设置和模型编辑中的“请求头覆盖”“请求体覆盖”均支持常用候选与自由输入。点击输入框右侧箭头查看候选；直接输入时会筛选候选。方向键选择，Enter 确认，Escape 关闭；候选不限制可输入的字段或值。

## 请求头

请求头名称和值均按文本处理。常用名称包括 `Authorization`、`Content-Type`、`Accept`、`OpenAI-Project` 等；部分字段同时提供常用值。

已保存的请求头值不回传到界面，显示“已保存，留空保留”。展开候选或重新选择相同名称不会修改原值；输入新值或更改名称会替换原配置。模型请求头优先于供应商请求头。

## 请求体

字段名支持自由输入，值可选择“文本”或“数字”：

- 文本原样发送，无需添加 JSON 引号。例如 `service_tier` → 文本 → `fast`；文本 `001` 保持为字符串，空字符串和前后空格也会保留。
- 数字发送为 JSON 数值。例如 `temperature` → 数字 → `0.5`。常用采样字段默认选择数字，继续检查有限数、范围和整数要求。
- 自定义字段默认选择文本，可手动切换为数字。

`service_tier` 提供 `default`、`auto`、`fast`、`ultrafast`、`priority` 和 `flex` 候选，也可填写渠道支持的其他文本。字段直接覆盖请求体的顶层属性，带点的字段名不会展开为嵌套对象。最终接受哪些字段和值由所用接口决定。

当前请求体覆盖支持 `openai-completions`、`openai-responses`、`azure-openai-responses` 和 `openai-codex-responses`（OpenAI / Codex 授权，例如用 `service_tier` 开启 fast 模式）。界面编辑字符串和数字；配置中已有的布尔、对象、数组等其他值保留在服务端。删除界面中的覆盖项后，其已保存值也会移除。

供应商请求体覆盖在保存时批量应用到当前模型，模型同名覆盖优先。重新读取后，可在各模型中查看已应用的结果；供应商区域不是独立持久的继承层。

同一供应商可以添加多个相同模型 ID 的配置，例如分别命名为普通版、Fast、Ultrafast，并给各项设置不同的 `service_tier`。模型 ID 填接口实际使用的名称；应用自动维护各项独立的配置标识，保存和重读后仍分别保留参数。无需为了区分档位手动改模型 ID 或增加 `model` 覆盖。

如果已有配置使用本地别名，并通过请求体 `model` 指定原生模型，新建 OAuth 别名时会按同一供应商目录中的目标模型继承接口协议与能力。已有配置保留其协议；若更换的目标使用不同协议，保存时会提示新建目标模型配置。无法识别目标时会提示修正模型 ID，不会用其他模型的协议代替。

本功能负责请求参数配置，不改变服务档位计费逻辑。

## 验证

在 `app` 目录运行：

```sh
./node_modules/.bin/tsx --import ./tests/vite-assets.mjs --test tests/model-overrides.test.ts
./node_modules/.bin/tsx tests/model-overrides.check.ts
```

测试使用临时配置及本地 HTTP 模拟服务；浏览器检查覆盖候选、自由输入、键盘、窄屏、触屏、保存回显和删除。
