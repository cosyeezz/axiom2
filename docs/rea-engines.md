# REA 分析引擎与配套组件

入口：配置 → 内置工具 → REA → 分析引擎与配套组件。

页面只展示当前版本、推荐版本（Hopper 为官方版本）、状态与必要操作，使用默认安装位置。加载与刷新只读取配置、文件及常用路径，不安装组件、不预热。每个组件的“检查更新”检测该组件的本地安装，并查找匹配当前 REA 的发行版本；会运行 Java 属性／模块、WABT 版本或 REA 的无目标 doctor 检查，不会启动 GUI、打开分析目标或枚举设备。检测通过表示环境具备条件，不保证目标分析、许可或桥接成功。

## 系统选择

以 **运行 Axiom 后台的系统与 Node CPU 架构** 为准，不以浏览器、手机或远程客户端的系统为准。页面展示后台平台，组件安装到后台电脑的默认位置。使用转译版 Node 时会按其架构选择组件，请保持 Node 与预期分析架构一致。

| 组件 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| JDK 21 | x64／arm64 托管下载 | x64／arm64 托管下载 | x64／arm64 托管下载 |
| Ghidra | x64／arm64 托管安装，自动构建本机 native；需要 JDK 21+ 和 Xcode 命令行工具 | x64 托管下载；REA 原生控制模块与本地 NTFS 限制仍适用 | x64 托管下载；arm64 下载 ZIP 后自行构建 native |
| Hopper | 下载官方试用 DMG，提供“安装 Hopper”入口打开系统安装窗口；不验证许可 | REA 不支持 | 接入已有启动程序；按发行版从官网选择 x64 安装包 |
| JADX Headless MCP | x64／arm64 托管 JAR | x64 托管 JAR；arm64 不支持当前 REA 契约 | x64／arm64 托管 JAR |
| WABT | arm64 托管下载；无对应 x64 官方包 | x64 托管下载；无对应 arm64 官方包 | x64／arm64 托管下载 |

支持表表示实现的平台分支和上游发行范围，**不等同于 Windows／Linux 实机验收**。其他架构明确不支持，不静默换用另一系统或架构的包。Ghidra 在 Windows/Linux x64 使用预编译 native，macOS 在托管候选目录中构建 native；Linux arm64 仍需按官方说明自行构建。Hopper 应用安装及许可由用户在系统窗口完成；没有匹配下载包的平台只提供本地检测和官方安装指引。

## 版本与配置

当前托管安装及 Ghidra／JADX doctor 适配契约验证于 `rea-agents@6.7.0` 与 `rea-agents@6.8.0`；两版的桥接文件分别来自各自 REA 包。更新到未适配版本时拒绝自动安装，不默认沿用旧契约。Node/npm 同样按目标版本准备组件私有环境，不要求升级后台 Node；版本范围、隔离边界和上游文件摘要见[内置组件的独立运行环境](builtin-component-environments.md)。JDK 取 Adoptium 21 最新修订，Ghidra 验证 12.1.4、接受 12.1.x，JADX Headless MCP 固定 0.7.1，WABT 固定 1.0.42。普通 jadx CLI 不能代替此 JAR。“检查更新”寻找符合这份契约的版本，不追随任意上游最新版。Hopper 未有 REA 固定版本范围，因此展示本地与官方发行版本，不宣称许可、升级资格或实际桥接兼容。

JDK／Ghidra／macOS Hopper 优先读取安装内的版本元数据。托管组件保存发行版本，旧安装从来源记录恢复，刷新和重启不丢失版本显示。WABT 的显式检测核对三个程序的输出。JADX doctor 只检查环境和桥接结构，不能据此推断版本；显式检测额外校验 JAR 的官方 SHA-256，只有匹配固定发行包时才确认 0.7.1，其余保持版本未核实，不能被来源元数据覆盖。

托管安装自动选择 Axiom 独立目录，页面不再提供路径输入。已有配置与环境变量仍可用于发现外部组件，且只注入 REA MCP 与检测子进程，不修改系统 Java、全局 PATH、其他 MCP 或终端 pi 设置，不运行 `rea setup`。已有会话须重新加载技能与 MCP。显式检测使用 `integrations/rea/environment/engines/<组件>/` 中独立的配置、缓存、npm 配置和临时目录；Ghidra 构建另用候选目录内的环境与 Gradle 用户目录。REA doctor 和 Ghidra 构建预检保留当前 REA 版本绑定的私有 Node PATH，合并调用环境后仍清除 Node／Java／Python 等启动注入变量。各引擎共享 REA 的版本级 Node，不为每个引擎复制一套 Node；Hopper 应用及许可仍由系统管理，检测只检查启动程序，不自动启动 GUI。这是运行状态隔离，不是文件系统或安全沙箱，仍保留 HOME、系统命令和凭据访问。

手动安装 Ghidra 时，默认发现 `~/Applications/ghidra_12.1.4_PUBLIC`，以及 macOS 的 `/Applications/ghidra_12.1.4_PUBLIC` 或 Linux 的 `/opt/ghidra_12.1.4_PUBLIC`。Hopper 发现系统或用户 Applications 目录中的应用。非默认位置仍可通过后台环境变量指定：`JAVA_HOME`、`GHIDRA_INSTALL_DIR`、`HOPPER_LAUNCHER_PATH`、`REA_JADX_MCP_JAR`、`REA_WABT_BIN_DIRECTORY`。

JDK 检测要求17+且有 `jdk.compiler`，推荐21；Ghidra 按自身声明的 Java 上下界验证。WABT 要求 `wasm-validate`、`wasm-objdump`、`wasm2wat` 均为1.0.42。Windows 自动使用 `.exe`，Ghidra 的 `.bat` 与 native 文件检测由上游 doctor 负责。

旧路径配置接口保留组件级 revision 冲突保护：其他组件维护不会使本组件确认失效；同一组件或 REA 安装发生变化时要求重新检查。

## 下载、更新与安装

组件卡片复用内置工具的 `BackendMaintenance`，所有检查、下载和托管安装进入同一“下载与维护”任务中心，沿用进度、网络预算、取消和任务记录。先“检查更新”，再确认明确版本。确认结果同时绑定本组件修订、REA 安装和发行包；这些内容变化、再次检查此组件或后台重启后，旧确认不能用于下载，须重新检查。其他组件完成维护不会使确认失效。JDK 在检查后不会因上游发行变化而下载另一个修订。

不同组件可同时检查、下载和更新。例如 Ghidra 下载期间，Hopper 仍可检查更新并开始下载，JADX 等其他卡片也保持可操作。各卡片独立显示进度、结果与错误，取消只作用于选中的任务。同一组件防止重复提交；REA 本体维护、全量组件检测和托管组件卸载与其他 REA 维护互斥，避免切换或删除正在使用的程序和依赖。并发完成时只合并各自的配置字段，不覆盖其他组件刚保存的结果。

Java 路径切换会使 Ghidra／JADX 的旧环境检测结果失效，但保留已确认的发行包。安装过程中使用最新 Java 路径验证；若验证期间路径又发生变化，会重新验证，通过后才切换组件路径。多次连续变化导致无法稳定验证时，保留原路径并提示重新检查。

当前版本等价于推荐版本时显示“已是推荐版本”，隐藏重复安装按钮。例如 JDK 的 `21.0.13+9-LTS` 与发行元数据的 `21.0.13+9.0.LTS` 视为同一版本。后端即使再次收到安装请求，也会先重新检测本地组件，通过后直接复用，不重复下载。检测失败时仍允许修复；目标较新时显示“更新”，目标较低时明确显示“切换推荐版”。外部安装切换到托管版只在验证通过后生效，外部文件保留。

已检查的推荐版本随组件任务记录保留，刷新和重启后继续显示；后台重启不会恢复旧下载确认 token 或旧环境检测通过状态。

macOS Ghidra 和 Hopper 的“下载安装包”只保存校验后的文件，不修改引擎路径。完成后显示“已下载 · 待安装”，提供“安装 Ghidra”或“安装 Hopper”及“查看安装包”，不再要求重复下载。文件保存在 `integrations/rea/downloads/<组件>-<UUID>/`，记录在刷新和重启后保留。再次检查或收到重复下载请求时，复核发行来源、版本、格式、大小与摘要，并确认校验前后的文件身份一致后复用；文件丢失或损坏时恢复下载入口，旧文件保留。

安装已有包需重新确认缓存版本和组件修订，后台重启后也可操作，不依赖旧下载 token。页面的推荐版本变化后，打开中的缓存安装确认失效。Ghidra 后端还会核对当前推荐版本，禁止静默换装其他版本；校验失败也不会把“安装缓存包”变成重新下载。

- **Ghidra**：点击“安装 Ghidra”后，复制并重新校验已有 ZIP，解压至托管目录、构建本机组件，环境检测通过后接入 REA。未下载时也可直接确认下载安装。需要与后台 CPU 架构一致的完整 64 位 JDK 21+；缺少时先安装上方的 JDK。缺少 Xcode Command Line Tools 时会提示在后台 Mac 运行 `xcode-select --install`，完成后可继续使用原 ZIP。Axiom 按发行包中的 wrapper 版本准备官方 Gradle（当前固定 Ghidra 包为 9.7.1），核对 SHA-256 后使用独立 Gradle 用户目录和 `--offline buildNatives` 构建；不要求用户另装 Gradle。五个 native 产物均检查执行权限和架构，再运行 REA doctor。手动安装可参阅[官方构建说明](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.4_build/GhidraDocs/GettingStarted.md#building-native-components)。
- **Hopper**：点击“安装 Hopper”，确认后在后台 Mac 打开已校验 DMG 的私有副本。页面显示“待完成系统安装”；用户按[官方安装说明](https://www.hopperapp.com/download.html)将应用放入 Applications，完成首次启动及许可确认，再点击检查更新。打开安装窗口不等于安装完成，不新增 Axiom 托管组件记录。已发现同版本应用时显示“已安装 · 待许可验证”。下载的是试用包；现有许可证是否有升级资格由 Hopper 确认。后台须运行在已登录桌面的 Mac 上，远程浏览器不会在本机启动安装器。

## 托管安装与恢复

用户确认下载后，官方 HTTPS 下载经过每跳地址白名单、大小／超时限制及文件校验。JDK 校验值来自 Adoptium 元数据，WABT 来自固定发行校验文件，JADX、Ghidra 使用固定版本 SHA-256。Hopper 官方提供 SHA-1 和文件长度，只用于下载完整性检查；应用签名由系统安装流程核实。连接失败或响应体中断（例如底层 `terminated`）显示可重试的网络错误，不直接暴露底层错误文本；不把响应体中途失败静默重放为新下载，失败未发布的文件会清理，已完成的旧包保持不变。

新文件写入 `integrations/rea/engines/<组件>-<UUID>/`，保留来源元数据与归档内许可。ZIP／tar.gz 使用解析库逐项验证并自行落盘，拒绝目录穿越、Windows 保留名、特殊文件、大小写冲突及超限展开；tar 内安全的普通文件链接最后复制为文件，不创建系统链接。安装后检测通过且本组件及 REA 安装修订未改变，才原子切换路径。取消、失败或冲突清理本次准备目录，原路径保持不变；旧成功目录保留给在途会话，不自动删除用户文件。

检测子进程不使用 shell；POSIX 超时／取消终止独立进程组。Windows x64/arm64 使用独立 Node 监督进程，在启动检测程序前通过 Koffi 加入 kill-on-close Job Object；初始化失败不启动检测，监督进程退出或被强杀时终止该 Job 的普通后代进程，不依赖仍存活的父 PID。它不是安全沙箱，宿主 Job 策略可能阻止嵌套；经外部服务创建的进程不在此保证内。

操作按组件分别保存任务和进程归属，复用统一维护、取消与进度记录；下载目录和 Hopper 安装入口也纳入维护归属及目录身份检查。组件在同一后台内并行执行，跨后台进程的 REA 写入仍互斥。关闭页面不会取消操作；刷新会恢复所有任务的状态，重启将各项未完成记录标为中断，不自动续装。可在对应卡片核实中断任务；旧版遗留的全局维护记录须先核实结束，才允许组件并行维护。取消或失败清理本次未发布下载，原安装路径、已完成下载和其他组件任务保留。Hopper 交给系统后的私有副本保留在 downloads 中，避免系统异步读取时被删除；此时取消只结束后台任务，安装窗口可能已打开，需在后台 Mac 核实。旧成功版本、下载包及已交付系统的安装副本不自动回收，托管组件卸载不删除这些文件。

## 验证范围

专项测试覆盖平台资产映射、Windows 路径、ZIP／tar 解包与路径逃逸、SHA-256／Hopper SHA-1 和长度、确认版本绑定与失效、等价 JDK 免下载、重复下载复用、推荐版本与本地版本重启恢复、损坏／丢失安装包、修订冲突、取消保留旧包、MCP 环境隔离、“刷新不探测”、Ghidra／JADX scoped doctor 报告契约，以及父先退出时的后代清理。并发专项覆盖多组件同时安装／下载、反序完成后的配置合并、单项失败与取消隔离、Java 切换后的重新验证、多个中断任务恢复、跨进程准入及子进程归属隔离。全局卸载额外核对组件安装时保存的目录身份，拒绝同路径替换目录。

新增安装专项覆盖 JDK 版本／模块／位数／架构、缺少 CLT、官方 Gradle 地址与摘要、离线构建参数、五个 native 产物检查、真实 macOS `lipo` 参数解析与失败诊断、REA 私有 Node PATH 和引擎子进程注入清理、缓存 ZIP 安装不重复下载、构建失败和取消回滚、重启无 token 的缓存安装、推荐版本漂移，以及 Hopper 私有副本校验和开窗成功／失败／取消不改变引擎配置。

Windows Job 初始化顺序与失败关闭有 API 替身测试；真实 Win32 API、嵌套 Job 策略和 Windows 清理行为仍需原生系统验证。浏览器专项覆盖默认位置、紧凑卡片、已满足版本不再提供重复下载、缓存 Ghidra 安装按钮、Hopper 待完成系统安装状态、推荐版本变化使旧确认失效、Ghidra 或 Hopper 先下载时另一组件与 JADX 仍可操作、双下载与独立取消、刷新不重复任务、无关组件检查后确认仍有效、独立错误反馈及响应式布局。测试使用隔离目录和发行／构建／安装器替身，不真实安装大型引擎或打开系统 DMG；真实 Ghidra 编译、LaunchServices 窗口、商业许可、实际目标分析及 Windows／Linux 原生系统闭环仍未验收。

更新此功能时需同时加载新的前端与后台。仅覆盖构建文件、刷新页面不会替换后台进程已加载的服务；旧后台的全局组件任务会继续禁用其他组件，也不认识新增安装入口。待现有任务结束后重启后台，使组件级并行与下载后安装流程生效。
