# 服务重启后的自动续跑

本能力针对**由服务中断或工作进程意外断开的 Agent 主会话及子任务**，不等同于浏览器断线重连，也不适用于安装、卸载、后台压缩等独立操作。

## 触发与调度

- 服务启动在归档活动执行前，事务保存 `service_recoveries` 恢复意图；正常退出也在停止 Agent 之前保存。
- 服务就绪即开始恢复。每轮先恢复全部子代理，再恢复主代理（含父结果通知）；同类按原恢复记录顺序。全局一次只接续一个会话，接续启动受理或本次准备失败返回后，完整等待 3 秒再处理下一个。
- “接续完成”指恢复启动已受理，不是模型任务执行结束。已经接续且仍在运行的会话不占恢复槽；不设恢复批次数、总活动会话数、父会话等待子任务完成等额外调度条件。子代理恢复直接通过此队列启动，不再等待普通任务并发容量或普通准备 FIFO；普通新任务仍使用原并发设置。调度时刷新子代理优先顺序，新出现的子代理中断也先于尚未接续的主代理。
- 不增加恢复专用容量限制；仍沿用服务共用物理执行池的资源上限。池满时恢复申请立即返回未启动，保留意图并按同一 3 秒节奏轮转重试（含父结果通知），不占住唯一接续槽，也不停止其他活动执行或谎报已接续。
- 工作进程意外退出（`WORKER_INTERRUPTED`／启动交接不确定的 `UNCERTAIN`）结算时在同一事务保存恢复意图，避免 run 已终结但意图尚未登记的崩溃空窗，并由同一队列续接；IPC 断开先回收旧进程，确认退出后才可启动替代执行。普通模型错误仍由 Pi 原生重试处理，不通过宿主重发请求。
- 每个会话只保存一个当前恢复意图。新执行、子任务归属、输入交接与旧意图移除在同一数据库事务完成，避免重复重启重复投递旧意图。通知异步收尾只能清除自身原意图，不能删除新执行刚捕获的停机恢复记录；停机取消尚未完成的启动准备时，原意图保留 pending，供下次启动继续。
- 恢复新建 run 并记录 `resumedFromRunId`，不改写旧执行已结束的事实，也不新增一条“继续”的用户消息。

## 子任务与父会话

- 运行中的子任务从绑定的 Pi JSONL 续接；排队且从未交给工作进程的输入可以恢复，图片与技能引用随原输入身份保留。
- 运行中的子任务尚未交接的追加要求也会保留，排在续接控制条目之后；不是只恢复任务最初的正文。
- 子任务保留原队列顺序及工作／总结截止时间，重复重启不赠送新的时间预算。
- 父会话在本轮子任务接续启动之后恢复，不等待子任务执行结束；个别子任务准备失败不传播成父会话永久阻塞。最后一个子任务已完成、但结果通知尚未确认时，也会保存恢复意图；先核对 JSONL 通知标记，再投递尚未消费的结果。

## 安全边界

- 用户已停止、正在停止、普通失败或已完成的执行不会被当作中断执行重新拉起。确认退出供应商时也撤销尚未接续的主／子会话恢复意图，重新登录不会复活已确认停止的工作。父会话仍在等待子任务的正常结果通知不属于重跑已完成的子任务。
- 已删除会话、归档工作空间、文件访问未授权等情况仍阻止执行并保留原因；这些是授权与归属边界，不是恢复并发限制；文件授权恢复后，无需再次重启即可继续尝试。
- 启动准备失败但尚无新持久 run 接管时，保留 `pending` 和具体错误，先给本轮其他会话一次恢复机会，再在下一轮重试，不设次数上限。已有新持久 run 的操作不会因回执不确定而由宿主重复派发。启动时重试旧版本留下的 `blocked` 意图，但仍重新验证当前归属、授权及原 run。读取或发布异常不会使整个恢复计时链永久停止。
- 已交接但无法确认是否消费的追加输入保持 unknown，不自动再发。工具结果缺失时只补充“结果未知”的协议记录，不由宿主重放可能已执行的写入或 Shell 操作。
- 客户端重连只恢复订阅，不重发用户命令；WebSocket 打开后 10 秒仍无合法 hello／快照／回执时主动关闭并继续重连，避免永久停在“确认中”。服务端从当前意图与绑定 JSONL 续接，不从旧请求回执重建用户要求。
- 旧版本已经终结、没有恢复意图的历史中断不批量拉起。损坏或缺失的会话记录不静默替换成新对话；父通知因文件不可读而无法启动时保留可重试意图、具体错误及未消费结果，不静默丢弃恢复入口。
