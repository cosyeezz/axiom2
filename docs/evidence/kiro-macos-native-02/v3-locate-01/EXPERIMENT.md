# V3 配置离线定位门禁

问题：在已绑定的官方Mac Kiro CLI2.35.1产物中，能否定位用户所述“开启V3”提示或设置定义？用户称Kira client，准确产品/提示原文/开关状态均未知，不能先验认为就是当前CLI。

可反驳假设：V3提示对应这份产物的明确可识别setting；静态提示+key/默认值定义只能形成候选，不能证明本机或用户所见客户端的有效状态。

仅只读 `/Applications/Kiro CLI.app/Contents/MacOS/kiro-cli-chat` 的已知ARM64 `__TEXT,__cstring`和`__TEXT,__const`，沿用冻结Mach-O section元数据，先核完整file SHA；一次有界literal扫描找`v3`，只保留ASCII上下文候选和地址，不解码/反编译/执行。独立审查bundle公开dashboard/manifest资源作为另一范围，无命中不证明其他产品没有设置。

预算：本轮binary扫描1次，CPU120秒/墙钟180秒/地址空间2GiB，上述静态section总计约114MiB；候选上限256项、每项最大480B上下文，公开资源独立审查2分钟/20MiB，不启动Ghidra/LLDB或旧失败runner。无模型请求/目标执行、无网络/凭据/Keychain/用户配置存储读取、无配置或安全策略修改；不找泛V3全盘/进程。

成功判据：身份/section边界一致、非空候选与截断状态明确；若有明确提示/key，记录原始byte/VA和限定解释。只有拿到准确提示/产品/有效状态才可关闭V3对请求一致性的门禁；没有这三项就保存静态结果，等待必要输入，不擅自开关。

失败后：保存错误与部分证据，不复用此namespace取绿。若本产物无能唯一匹配的提示，停止这条定位，不为了猜用户产品扫描其他安装。后续只在已知候选上做新增假设的最小定位。
