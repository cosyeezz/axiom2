# Snapshot consumer — design only, not a terminal attestation

Lifecycle note: this is the original design-stage specification, not current execution status. HTTP02 and the subsequent pure parser tests have ended. The independent [implementation](snapshot_consumer.py) and [Snapshot01 validation with protocol deviations](SNAPSHOT01-VALIDATION.md) now exist; the original no-implementation/proposed-verification wording below records the design stage. No claim of owner terminal or live request is added.

Purpose: independently reject malformed or insufficient `end-string-observer-1` output before it can be cited as even partial API evidence. Existing fake04 consumer does not support this schema. This new component must be pure/no IO/no HTTP/no credential lookup. Do not modify observer/helper while HTTP02 is running. This document is not an implemented parser or permission to launch real requests.

## Boundary and outputs

Input is a bounded serialized snapshot, **not** a trusted arbitrary JS object. Use bytes/strictUTF8 (or primitive text with independently checked bound), <=16KiB, JSON maximum nesting16, <=4records. Reject duplicate decoded keys including escaped duplicates, nonfinite, all floating-point numeric tokens, bool-as-int, multiple roots, trailing nonwhitespace, malformed UTF8/JSON and unknown/missing keys. Never re-emit raw input, error messages/stack/decoder context, arbitrary keys or value hashes. The parser's error must be only a fixed bounded reason. Do not store an exception object, even `raise from None` retains Python context unless handled locally.

Return a newly built fixed result, e.g. schema `end-string-snapshot-check-1`, result `invalid|schema-valid`, reason from a closed enum, `endStringShapeCandidate` boolean and <=4 safe ordinal/class summaries. Every result carries completeness/receipt/naturalInstallation/valueEquality flags false. Validating provenance-free JSON never proves that instrumentation ran. A schema-valid unsupported/fault snapshot is evidence of a limitation, not an execution success. The helper's supplied-value comparison is a different schema and must be rejected here.

## Exact producer schema

Root keys exactly schema,state,fault,calls,pending,coverage,requestCompletenessProved,wireReceiptProved,naturalInstallationProved,records. Schema literal `end-string-observer-1`, coverage literal `partial-api-only`, proof flags exactly false. State one of not-installed,active,closed,conflict. Fault one of none,late-call,unsupported-receiver,record-cap,reentrant-request,repeated-end,scan-cap,original-threw,observer-fault,call-cap,restore-conflict,close-pending,install-refused,install-failed. Counters exact integers calls0..128,pending0..calls; records length0..4 and <=calls. Ordinals contiguous1..N, not arbitrary IDs. Empty records never qualify as candidate.

Each record exactly ordinal,endSeen,endReturned,body,header; booleans exacttype. endReturned implies endSeen. Body closed enum no-end,write-seen,reentrant,repeated-end,unsupported-arity,no-primitive-string,unsupported-encoding,string-cap,scan-cap,primitive-utf8-argument,original-threw. Do not overstate relationships on faulty snapshots: sticky failure may coexist with a later end return, a write-after-end may change body to write-seen, and endSeen=true is not endReturned=true. Only assert relationships directly supported by the frozen source, retaining failure snapshots as schema-valid where appropriate.

Header exactly schema,coverage,reason,method,httpVersion,endpoint,queryPresent,authorization,otherHeadersPresent,valueEqualityProved,wireReceiptProved. Schema literal real-http-header-shape-1; proof flagsfalse. Coverage unknown|format-only. Unknown reason one of invalid-bound,unsupported-input-type,header-cap,unsupported-text,header-grammar,header-count-cap,header-line-cap,projection-failed; all method/httpVersion/endpoint unknown, queryPresent/otherHeadersPresent null and authorization fully unknown (present/duplicate null, remaining strings unknown). format-only requires reason bounded-header-cache, method GET|POST|HEAD|PUT|PATCH|DELETE|OPTIONS|CONNECT|TRACE|other, httpVersion1.0|1.1, endpoint unknown|generate-assistant-response|create-response and exactboolean queryPresent/otherHeadersPresent. Known endpoint requires POST and queryPresentfalse. Unknown endpoint does not imply unknown method or malformed request.

Authorization exactly present,duplicate,scheme,form,tokenShape,scope. Scope always unknown. For format-only: absent => presentfalse,duplicatefalse,scheme/form/tokenShape allabsent. Duplicate => presenttrue,duplicatetrue,scheme/form/tokenShape unknown. Single nonBearer => presenttrue,duplicatefalse,schemeother,form/tokenShapeunknown. Single Bearer => presenttrue,duplicatefalse,schemebearer; formunrecognized/tokenShapeunknown OR formnonempty-ascii/tokenShapeopaque|three-segment. No decoded claims/scopes/strings exported. Three-segment is syntax only, not a verified JWT or scope authority.

## Candidate qualification (not acceptance of actual requests)

A schema-valid snapshot is a partial end-string/header-shape candidate only if stateclosed, faultnone, pending0, nonempty records, calls==record count, and every record has endSeen/endReturnedtrue, bodyprimitive-utf8-argument and headercoverageformat-only. Do not require a known target for generic localfixture qualification; selection of the actual official API is a separate input-bound policy, not guessed from an unknown target. Missing/duplicate/nonBearer authorization remains reported shape, not authentication success. The candidate has no payload, so cannot substantiate even one full payload comparison.

Zeroobservations, active/not-installed/conflict, any fault, pending>0, extra calls, unsupportedbody/header or cap cannot qualify. Keep schema validity separate from candidate qualification so honest failures are inspectable without manufacturing success. `closed` alone is not an owner terminal: a saved wrapper can be called after the snapshot and set late-call. The snapshot itself cannot prove this never happened.

## External terminal requirements and limits

An eventual owner must independently bind reviewed public source/runtime/installation case and held process, get actual exit and true EOF within declared deadline, and collect a final safe state after the relevant last possible call. Merely reading a closed snapshot before process exit and later seeing exit0 is insufficient if that snapshot could become stale. Do not combine a producer-supplied exit/EOF flag with itself as authority. Current wrapper has no terminal handshake/finalization event and no paired RAM channel; neither is supplied by this parser design. Do not resume complete-descendant/M3 research to implement a snapshot checker.

Even a properly collected no-fault terminal would prove only the declared partial observation boundary; captured method aliases/customtransport/H2/embeddedNode/naturalprototype applicability remain independent. Actual request body/auth equality, actual outbound and server receipt need their own supported comparisons. All original privacy limits and user request-only scope remain.

## Proposed separate verification

Before execution define one pure parser test case with ownTEMP, no Node/HTTP/official/state and independent Python JSON vectors. Cover exactvalid/noncandidate variants; every enum/type/key; encoded duplicates/NaN/infinity/floats/bools/depth16vs17/bytecap; record ordinal/count/call/pending relations; header/auth cross-products; malicious unknown values never echoed. Validate selected unchanged observer snapshots through data-only artifacts, not rerun unit56 or HTTPfixtures. A matched valid parser result is not a live request. This design currently has **no implementation, test IDs or PASS claims**.
