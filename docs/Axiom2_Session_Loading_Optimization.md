# Axiom2 会话加载与切换优化

## 1. 范围与约束

本文件定义 B01–B04、P01–P10 的实施边界和验收依据。本轮实现与自动回归已完成；实机性能验证的剩余边界见第 5 节。所有夹具使用临时数据，不读取用户真实会话。

保留当前布局、文案、输入习惯、会话归属、阅读确认和原生上下文语义，不修改 `ui/`。切换会话只改变查看对象，不停止后台执行；跨空间置顶不切换侧栏工作空间。草稿、附件、中文输入、选区、菜单、焦点和滚动遵循原规则。

默认历史继续使用 pi 当前压缩边界的摘要、保留消息和后续消息。RAW 是当前活动分支跨压缩的可见历史，仍尊重原生上下文编辑、失败尝试排除和私有记录过滤，不是 JSONL 所有分支及图片字节的直接展示。保持首次完整条目可用、长字段按需展开；消息列表不分页，不引入尾部先显示、视口虚拟化、整会话 DOM 保活或新的性能模式。普通工具输入预览最多512字符、输出与思考预览最多320字符，独立工具摘要根据完整原文生成路径／命令的短摘要、行号与数量；字段详情通过 `message.part` 展开时一次读取完整字段，不分页、不提供继续加载。

## 2. 问题与实现边界

| 编号 | 当前实现与验收目标 |
| --- | --- |
| B01 同序号重连 | `transport.ts` 区分数据版本与连接交付代际。同服务、同序号的新连接交付复用数据身份并更新同步证据；低序号、旧 socket 和同代重复不能冒充新鲜数据。 |
| B02 RAW 刷新失败 | `OriginalStore` 分离最后成功快照和请求状态。失败、刷新及重试保留已成功的 RAW 节点；有效空数组也是成功。首次失败保留默认历史。 |
| B03 归档单独编辑 | `ThreadIndex.contextRevision` 在权威重建时推进，RAW 失效不依赖默认 ID／分组变化；旧后台缺字段时保持兼容。全文详情也按重建代际失效，包括只修改截断部分的同 ID 内容。 |
| B04 未加载误判空 | 普通历史同时收到 messages 和 thread 后才能显示真实空会话提示，读取错误不冒充空历史。 |
| P01 文件头全读 | `transcriptHeader` 使用文件描述符读取至首行，块大小 1 KiB、上限 64 KiB，finally 关闭。正文交给 pi；校验 cwd、文件类型与读取前后文件身份。 |
| P02 RAW 请求叠加 | 每个查看实例最多一个 RAW 读取在途，期间只保留最新需求；拒绝过期提交，关闭释放实例并取消待执行读取。取消及超时不重放 Agent 操作。 |
| P03 订阅平方记账 | 使用会话级非空 scope 引用计数进行 O(1) 固定判断；每个消费者独立幂等解绑，远端仍合并为消息集合订阅。 |
| P04 隐藏过程重复工作 | 事实按组批量初始化；消息／工具变化在 microtask 合并受影响条目。折叠时不挂载思考与普通工具详情；助手正文固定在过程之外，作为分组边界；真实任务卡和通知继续提供原有已读证据。 |
| P05 后台与显示缓存耦合 | 未观察且无显示缓存的后台 delta 不加载整份历史；运行事实独立保存。完整磁盘记录确认后才释放终态 delta，显示 LRU 仍最多五会话。 |
| P06 重复派生与发布 | 同投影复用线程分组，文本增量不失效布局；无接收者时不生成纯显示快照。不可变事件共享序列化结果，完整客户端集合先提交再通知。注意力、自动置顶、结果版本与费用失效继续执行。 |
| P07 归档全文重复投影 | 同一事件循环批次按文件身份、纳秒时间、大小和历史代际复用原始投影，下轮清理；不永久缓存 SessionManager。详情依赖内容字段与历史代际，不依赖包装对象身份。 |
| P08 队列真实计量 | 计算排队及在途 UTF-8 载荷字节，普通帧预算 4 MiB，可同时容纳受控的一份合法大帧。只读大响应在物化前准入；可靠回执、终态与完整快照保持屏障。 |
| P09 查询与侧栏派生 | 单会话 presence 查询只取目标摘要；任务输入、结果、耗时按父会话批量查询后组装。热点 prepared statements 最多128条；增加 runs／tasks／task_results 所需索引。侧栏按快照 memo 派生并稳定行回调。 |
| P10 对象与解析重复 | RAW 按 ID 订阅并复用等价消息与分组；任务索引按 TaskList 身份构建一次，消费者只选择相关任务。Markdown AST／高亮 token 使用有界纯解析缓存；吸顶样式仅在值变化时写入。 |

## 3. 所有者、失效与资源边界

| 资源 | 所有者与边界 | 失效／释放 |
| --- | --- | --- |
| 默认显示投影 | 前后端五会话 LRU；客户端保护挂载目标 | 权威集合、上下文重建、删除及非活动 LRU 淘汰 |
| RAW 归档 | 单个查看实例的 OriginalStore | 关闭、导航、卸载；旧请求不得恢复新实例 |
| RAW 请求 | 每实例单在途＋一个最新期望版本 | 完成、错误、取消；失败不无限重试 |
| 运行消息 | 后端 transient，与显示缓存分离 | 完整 JSONL 持久化确认或权威重建／结算 |
| 原始投影复用 | 同轮读取、最多五会话、估算文本预算32 MiB，超大项不保留 | 文件身份／源版本变化、历史重建及下一轮事件循环 |
| 纯解析缓存 | 普通五会话、RAW 各自实例；每缓存128项、估算2 MiB | 内容／解析配置变更、LRU、RAW关闭；超大项不保留 |
| 字段详情读取 | 归属、字段修订、历史与连接代际绑定的共享只读请求；完成缓存最多24项、合计2,000,000字符预算，单项超过500,000字符不保留 | 最后一个消费者退出取消在途读取；30秒有效期在访问时清理；字段修订变化后整段重读；正文增量不使未变化的思考或参数失效 |
| 发送载荷 | 每连接普通预算 B=4 MiB，加最多一份大帧 H；等待读取和延迟集合各最多16个描述符 | 发送 callback、关闭；取消／退订释放未执行读取，旧订阅意图不能交付新视图 |

B＋H 是载荷预算，不是与最大合法消息大小无关的固定堆／RSS 上限。原生正文投影和 JSON 序列化仍同步执行，无法通过 AbortSignal 中途抢占；取消保证涵盖尚未执行的读取和不再补读。原始投影复用是同轮共享，不承诺跨事件轮缓存命中。

完整集合在发送边界才物化，消息与已订阅线程索引使用同一版本一次提交；客户端集合水位拒绝不晚于该集合的旧消息增量，防止被删除的 ID 复活。已准入的读取响应先于后续延迟集合交付并释放准入，避免相互等待；失败订阅按当前意图身份清理，不消耗有效订阅配额。待处理重订与成功订阅的交付身份分离：重复订阅失败、取消或连续替换不能丢弃已有订阅排队中的集合更新，只有显式退订结束旧交付身份。

解析缓存只保存纯 AST／token，不保存 React 节点、scope 回调、DOM、图片字节或授权结果。代码高亮保留20,000字符限制与未知语言纯文本降级。文件头优化不表示 pi 正文恢复不再全读。

RAW 可读与可确认已读是不同状态。过期 RAW 可以继续显示，但最新 revision 成功且连接消息、线程、Agent 均同步前不能确认；窗口可见聚焦、底部无遮挡、任务通知／卡片真实渲染等原有条件保持不变。

## 5. 当前验证状态与未确认项

当前原目录 `npm run build` 通过，包含客户端类型检查、186模块生产构建和服务端编译。字段懒加载相关8个测试文件26项通过；字段独立修订与短文本冲突断言补齐后，`lazy-details.test.ts` 的4项复验通过。工具过程、全文、模型菜单、文件预览、费用、任务卡、会话记忆和记忆异常空态8个浏览器脚本通过；模型菜单使用最新生产构建，完整记忆覆盖13组视口。全文及任务卡复验同时确认无控制台警告／错误；只读终审未发现新的确定阻断缺陷。

全量103个 `*.test.ts` 文件的435项测试按四个不重叠分片执行，清单核对无遗漏；分片结果434过、1项删除后状态断言失败，按逻辑删除契约修正后，压缩文件3项复验通过。最终订阅生命周期修复后，受影响的12个文件73项回归全部通过，最终只读审查未发现确定的阻断问题。

七项浏览器检查全部通过：原始会话、压缩已读、工具过程、过程连续性、历史侧栏、会话体验与薄客户端。原始会话及压缩已读使用最新生产构建；覆盖成功 RAW 的刷新失败／重试节点保留、同 ID 截断尾部编辑后的全文失效、主子隔离、草稿、模拟 IME、焦点和响应式布局。原始会话覆盖五个视口，工具过程覆盖六种宽度；代表性截图另作人工抽查，未进行全页面像素对照。

侧栏焦点检查在恢复桌面宽度并完成响应式状态提交后关闭弹窗。快速跨断点缩放与弹窗关闭同时发生时，原有的一次性焦点恢复可能撞上侧栏 `inert` 状态；该边界不由本次行 memo 引起，本次未修改通用弹窗焦点策略。

结构采样在 Windows、Node v24.19.0 的 tsx 环境执行，每组预热3次、正式采样30次。P50／P95分别取排序后的第15／29个样本；数据保存在 `app/test-results/session-loading/structural-performance.json`，均为毫秒。

| 规模 | 订阅／解绑 P50／P95 | 批量事实 P50／P95 | result lookup次数 |
| --- | --- | --- | --- |
| 100 | 0.46／0.88 | 0.22／0.37 | 100 |
| 1,000 | 4.50／5.57 | 2.12／3.01 | 1,000 |
| 5,000 | 24.15／28.24 | 9.29／14.41 | 5,000 |

每次预热和采样都断言 result lookup 次数等于调用数。另有结构回归验证10／50／200 MiB夹具的文件头均只读取1 KiB、六个后台会话60次更新不发生显示历史冷读。有限规模采样不证明整个应用的复杂度，也不替代旧版对比。

结构性计数与浏览器功能通过不等于速度提升百分比。尚未提供目标 Windows/Pake WebView 下30次样本的 T_select、T_visual、T_fresh、T_input 分位数、真实慢网络峰值 RSS 或长时内存回收报告；不宣称达到300ms／100ms或提升30%。若后续性能记录仍显示正文投影为瓶颈，再讨论有明确快照边界的异步读取，不能为追求计时而省略历史。
