# 独立标题与任务树

当前实现的专项说明；测试结果见文末。此轮不要求旧记忆格式迁移或兼容，不重写既有对话历史。

## 独立会话标题

实现入口：[session-titles.ts](../app/src/server/session-titles.ts)，由 [Agents](../app/src/server/agents.ts) 协调生命周期。

- 首次输入的60字符临时标题保留；正式标题由独立模型请求生成，长度≤13个Unicode码点。
- 每3次主模型 `provider_request` 边界检查一次，成功结算补查。计数针对请求边界，包含重试请求，不保证每次请求都已成功返回。
- 前提：主会话、标题仍pending、有有效记忆、没有标题请求在途。预建空文件、纯注释、空占位模板不会触发。
- 采用当前主会话的模型选择，不新增设置。复用无工具的独立API执行通道，只发送系统指令和一条材料消息；不发送主会话历史、工具或工具结果。
- 初次输入包含 `MEMORY.md` 完整正文与其中编号关联的详情，每段使用 `references/details.md#detail:N` 读取；不遍历无关编号和外部链接。分页读完后核对文件修订，最多128000字符；材料缺失、修订变化、超预算均跳过，不把截断资料当完整输入。
- 材料只作为数据，不能执行其中指令。只接收单行纯标题；不完整或超长结果不会发布。
- 每轮最多3次尝试，后续新运行恢复重试；标题请求含排队30秒时限。空材料不消耗尝试次数。
- 成功即持久化定案，不再生成。数据库CAS保证手动命名优先；停止、删除、供应商停用和关闭使相应在途结果失效。
- 不向主上下文追加标题生成指令、结果或结束提醒，不再采纳主代理输出中的标题标签。既有历史不重写，展示层仍保留既有标签过滤。
- 用量记在 `memory_usage` 的 `title` 类型，账单显示“会话标题”，不冒充记忆查询或整理。

## 六态任务树

任务以带状态的Markdown标题按层级展示，状态文字和图标同时保留；已放弃分支继承划线，等待分支不误显示为活跃执行。失败不算已完成，也不误归为已放弃。

图标选自Lucide官网，复用现有 [SVG sprite](../app/src/client/icons.svg)，不引入新图标依赖：

| 状态 | 图标 |
| --- | --- |
| 未开始 | [circle](https://lucide.dev/icons/circle) |
| 进行中 | [circle-dot](https://lucide.dev/icons/circle-dot) |
| 已完成 | [circle-check](https://lucide.dev/icons/circle-check) |
| 等待 | [clock](https://lucide.dev/icons/clock) |
| 已放弃 | [circle-slash](https://lucide.dev/icons/circle-slash) |
| 失败 | [circle-x](https://lucide.dev/icons/circle-x) |

进行中采用静态状态图标，而不是误表示网络加载；实际读取详情时才显示加载反馈。

## 原位单详情展开

实现：[MemoryOutlineView.tsx](../app/src/client/memory/MemoryOutlineView.tsx)。沿用项目原生 `details/summary` 交互：

1. 有详情的任务整行可点击，键盘Enter/Space可切换；无详情行不伪装可展开。
2. 首次展开才读取该行第一个编号。若一行关联多个编号，提供编号选择，每次只挂载、请求和显示选中编号。
3. 服务端先选择该编号段，再对所选段分页；客户端从不请求裸 `references/details.md`，不加载其他编号，失败也不回退整文件。
4. 长详情的“继续读取”保留同一个 `#detail:N`；不同修订不可拼接，冲突清空旧正文并提示重读。
5. 收起、切编号、切会话或修订变化后，旧读取结果不会写入新视图；收起卸载正文。
6. 子任务列表放在详情折叠区外，折叠详情不隐藏子任务。窄屏标题换行、缩进减小，保留焦点样式。
7. 内联详情只读，不出现编辑、整文件展开或本地打开操作；完整记忆浏览入口保持独立。

## 验证

本轮专项验证通过，不代表全仓测试全绿：

- `npm run build`：退出码0；包含前后端TypeScript检查和Vite构建，仅有大chunk提示。
- 9份专项测试共77项通过：标题状态、解析、详情边界、runner、整理、接续及费用。
- `title-generation.test.ts`、`agent.test.ts` 两项真实worker回环集成通过：每3次检查、结算补查、无主历史污染、无工具、13字符、关联详情隔离、手动优先，以及主代理生命周期。
- `memory-chapters.check.ts` 浏览器专项通过：六态图标，1440/390/320宽度，Enter/Space，懒加载、单编号切换、同编号分页、整支划线和原文保留。
- `git diff --check` 通过。

验证中移除了旧标题确认调用残留，更新了旧提示词断言，并将历史污染检查改为检查消息类型，避免临时路径误命中。标题回环夹具采用已完成任务，防止无关的待办自动接续改变请求序号；接续逻辑另有专项覆盖。

所有模型交互仅使用本地回环夹具，环境与数据目录隔离。未调用真实模型、未改正式数据、未提交或部署。
