# 子代理机制优化方案

状态：已实施，定向验收通过。本文统一记录本次目标、接口、实施范围与验收；产品当前行为同步维护于 design.md 和 README.md。

## 目标与不变量

保留 delegate、append、cancel_task、read_result 四个独立工具。子代理负责调研与执行测试，代码修改由主代理负责；工具白名单、资源限制和命令使用约束以 `docs/design.md` 第 7 节为准，不得递归委派。taskId 是任务链，sessionId 是固定子会话，每次执行独立 runId，每份交付独立 resultId。同一子会话仅一个执行者。旧执行回调、计时器和结果不能修改新执行。结果先持久化再通知；结果可读不依赖通知确认。服务重启不自动执行任务或重放不确定输入。父会话停止冻结自动唤醒，子会话新要求不解除冻结。

## 追加与停止后续接

新增子任务追加仅使用 steer（Steering），在 pi 安全边界送达；历史 followUp 记录保留。排队和初始化阶段可追加。停止中也立即受理新要求，记录所等待的旧 runId；旧执行退出并保存取消结果后进入 FIFO 调度，新执行处理新要求，无需父代理先确认旧通知。强制终止不可撤销，不复活旧进程。停止中再次停止撤销尚未启动的续接输入。运行／初始化中的有效追加受理并持久化后刷新工作时限，总结中追加恢复工作且保持同一 runId；新执行使用最新预算。

输入回执按 inputId 保存 queued、accepted、delivered、failed、cancelled 状态及原因；IPC 明确失败不得返回 queued。初始输入与追加输入均以实际 JSONL 完整记录确认送达，不用文件存在或 SDK 内存条目代替写入证据。确认丢失时，结算／取消按 JSONL 身份对账；即使队列正文已清除，同一任务与执行的落盘证据也可将 failed/cancelled 修正为 delivered，独立停止事实继续保留。异步失败可在原操作卡片看到，不能仅有任务级错误。对投递不确定输入不自动重放。停止后新要求与旧执行输入分离；只在接收和调度资格确定后消费输入。

## 容量、公平性与内存

新委派、终态追加、停止后续接、显式重试共用容量入口。父会话最多 32 个活动／排队任务，子会话最多 32 条待处理输入，全局运行容量遵守 concurrency。停止中的旧执行占用位置，待续接链不重复计数。每次入队保存独立序号，不按原任务创建时间插队。校验与入队原子提交。

按 inputId 统一清理 handed、failedInputs、drafts、nativePending：送达、失败、撤回、取消、结算均覆盖。旧执行结算不清理下一执行的新输入。

## 结果

完整报告不可变保存；read_result 仅接收 taskId/resultId，一次返回指定结果全文，可重复读取，不接收分页参数或返回续读字段。每项交付正文不超过2000字属于提示词软上限；超过上限和历史长报告仍正常返回，不截断、拒绝、转成文件引用或额外压缩总结。reportKind 分别标记正常最终回复、已落盘部分输出和系统事实；取消不额外调用模型总结。未完成项不能用模板替代实际报告。历史结果不重写、不推测旧截断尾部。

## 通知

结果身份 resultId 与投递尝试 attemptId 分离。每次重试使用新 requestId，不能复用失败的 notify-resultId 回执。通知状态区分 pending、inflight、delivered、failed、unknown；记录尝试时间、关联结果和错误。

明确未启动可在新的显式操作／配置恢复后受控重试，禁止失败后立即循环唤醒。不确定发送先按父会话 JSONL 对账。父执行失败不直接等于通知失败；已落盘通知应确认。冻结父会话只保存结果，不启动模型。

运行中通知使用 Steering，相邻结果合批，仍携带每项 taskId/runId/resultId/status。按 resultId 在入队和持久化边界去重。批次逐项提交，失败时核对完整原生队列、内存消息与会话条目；确认未入队才释放该项去重标记，已入队保留，不确定项保持 unknown，不连带判定同批其他项失败。原生队列读取复用版本校验适配器，不能把只包含下一安全边界的 peek 当作完整队列。正常运行按文件字节游标增量读取完整 JSONL 行并确认，部分尾行等待后续写入，读取／解析失败不推进游标；文件身份、长度及游标前缀校验发现历史重写时重新核对。启动读取一次既有记录，错误恢复可扫描历史。通知送达不等于父代理已完成结果处理，不承诺下游外部操作恰好一次。idle 到 active 的竞态必须保持系统通知身份，不变成缺少结果标识的普通用户提示。

## 预算与停止事实

仅保留 workMs/concurrency 配置。停止来源结构化保存 user、agent、budget、parent、shutdown、provider；记录原因与时间，不能全部记 USER_STOPPED。子执行开始时获知实际预算、截止时间和任务链此前累计耗时，服务端独立计时仍为最终约束。剩余总预算的 20%（最多提前 60 秒）时，工作进程通过 Steering 注入一次剩余时间告警，提醒交付已有证据和未验证项；同一执行相同截止时间不重复注入，初始化跨过告警点时在执行开始补送，已到期则不补发。模型重试不重置当前截止时间；追加从受理时间重算完整工作预算，预算热更新按最近工作基点重算截止与告警点。首次请求顺序为系统提示词、预算、任务；后续预算更新、提醒和总结通知仅在尾部追加，保留已发送前缀。新预算明确覆盖旧截止时间，历史倒计时保留生成时的快照，不重新计算或删除。追加要求与当时预算一同提交，显示与编辑使用单独保存的原正文。告警等待下一安全边界，不中断长模型请求或工具调用，不延长预算；停止或结束清除定时器。

工作到期后，在同一 worker／runId 内中断当前操作，待原操作退出后清空活动工具并请求总结，工具调用边界同时拒绝所有调用。服务端在阶段切换前设置固定 180000 毫秒硬截止，等待中断和模型重试均计入；总结超时走预算强停，人工停止仍直接强停。总结中追加中断总结、恢复白名单并处理新要求，持久化工作／总结截止及预算版本阻止旧控制消息和定时器覆盖新工作。总结正常完成只保存一次结果，`budgetSummary` 与未验证项明确区分总结交付和任务验收。界面沿用活动状态样式显示「正在总结」。

## 实施范围

- 存储与共享类型：输入回执、入队序号、停止事实、通知尝试、结果身份、结构化任务背景与初始输入标识及旧库迁移。
- tasks/records、scheduler、delivery、commands：原子入队、续接、回执、清理、结果保存、通知恢复。
- agents、agents/runs、agent-worker：通知身份、批量去重、增量确认、停止来源、运行预算上下文。
- 任务工具与客户端：四工具 schema 精简、steer 契约、异步输入状态、完整结果与部分成果标记、任务说明卡和取消原因展示。
- README 与 design：只描述实施后的有效行为。
