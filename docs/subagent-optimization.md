# 子代理机制优化方案

状态：已实施，定向验收通过。本文统一记录本次目标、接口、实施范围与验收；产品当前行为同步维护于 design.md 和 README.md。

## 目标与不变量

保留 delegate、append、cancel_task、read_result 四个独立工具。子代理只读、不得递归委派。taskId 是任务链，sessionId 是固定子会话，每次执行独立 runId，每份交付独立 resultId。同一子会话仅一个执行者。旧执行回调、计时器和结果不能修改新执行。结果先持久化再通知；结果可读不依赖通知确认。服务重启不自动执行任务或重放不确定输入。父会话停止冻结自动唤醒，子会话新要求不解除冻结。

## 追加与停止后续接

新增子任务追加仅使用 steer（Steering），在 pi 安全边界送达；历史 followUp 记录保留。排队和初始化阶段可追加。停止中也立即受理新要求，记录所等待的旧 runId；旧执行退出并保存取消结果后进入 FIFO 调度，新执行处理新要求，无需父代理先确认旧通知。强制终止不可撤销，不复活旧进程。停止中再次停止撤销尚未启动的续接输入。运行中追加不续预算，新执行使用最新预算。

输入回执按 inputId 保存 queued、accepted、delivered、failed、cancelled 状态及原因；IPC 明确失败不得返回 queued。初始输入与追加输入均以实际 JSONL 完整记录确认送达，不用文件存在或 SDK 内存条目代替写入证据。确认丢失时，结算／取消按 JSONL 身份对账；即使队列正文已清除，同一任务与执行的落盘证据也可将 failed/cancelled 修正为 delivered，独立停止事实继续保留。异步失败可在原操作卡片看到，不能仅有任务级错误。对投递不确定输入不自动重放。停止后新要求与旧执行输入分离；只在接收和调度资格确定后消费输入。

## 容量、公平性与内存

新委派、终态追加、停止后续接、显式重试共用容量入口。父会话最多 32 个活动／排队任务，子会话最多 32 条待处理输入，全局运行容量遵守 concurrency。停止中的旧执行占用位置，待续接链不重复计数。每次入队保存独立序号，不按原任务创建时间插队。校验与入队原子提交。

按 inputId 统一清理 handed、failedInputs、drafts、nativePending：送达、失败、撤回、取消、结算均覆盖。旧执行结算不清理下一执行的新输入。

## 结果

完整报告不可变保存；read_result 支持 offset/limit，单次默认最多 16000 字符，返回 totalLength、truncated、nextOffset、reportKind。分页始终读取同一 resultId。正常最终回复、已落盘部分输出和系统事实报告分别标记；取消不额外调用模型总结。未完成项不能用模板替代实际报告。历史结果不重写、不推测旧截断尾部。

## 通知

结果身份 resultId 与投递尝试 attemptId 分离。每次重试使用新 requestId，不能复用失败的 notify-resultId 回执。通知状态区分 pending、inflight、delivered、failed、unknown；记录尝试时间、关联结果和错误。

明确未启动可在新的显式操作／配置恢复后受控重试，禁止失败后立即循环唤醒。不确定发送先按父会话 JSONL 对账。父执行失败不直接等于通知失败；已落盘通知应确认。冻结父会话只保存结果，不启动模型。

运行中通知使用 Steering，相邻结果合批，仍携带每项 taskId/runId/resultId/status。按 resultId 在入队和持久化边界去重。批次逐项提交，失败时核对完整原生队列、内存消息与会话条目；确认未入队才释放该项去重标记，已入队保留，不确定项保持 unknown，不连带判定同批其他项失败。原生队列读取复用版本校验适配器，不能把只包含下一安全边界的 peek 当作完整队列。正常运行按文件字节游标增量读取完整 JSONL 行并确认，部分尾行等待后续写入，读取／解析失败不推进游标；文件身份、长度及游标前缀校验发现历史重写时重新核对。启动读取一次既有记录，错误恢复可扫描历史。通知送达不等于父代理已完成结果处理，不承诺下游外部操作恰好一次。idle 到 active 的竞态必须保持系统通知身份，不变成缺少结果标识的普通用户提示。

## 预算与停止事实

仅保留 workMs/concurrency 配置。停止来源结构化保存 user、agent、budget、parent、shutdown、provider；记录原因与时间，不能全部记 USER_STOPPED。子执行获知实际预算、截止时间和任务链此前累计耗时，服务端独立计时仍为最终约束。追加、模型重试不重置当前截止时间；预算热更新按原启动时间重算。

## 实施范围

- 存储与共享类型：输入回执、入队序号、停止事实、通知尝试、结果分页字段及旧库迁移。
- tasks/records、scheduler、delivery、commands：原子入队、续接、回执、清理、结果保存、通知恢复。
- agents、agents/runs、agent-worker：通知身份、批量去重、增量确认、停止来源、运行预算上下文。
- 任务工具与客户端：steer 契约、异步输入状态、结果分页与部分成果标记；保留当前布局。
- README 与 design：只描述实施后的有效行为。
