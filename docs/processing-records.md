# 通用处理记录

记忆页和后台压缩页提供“处理记录”入口。页面按当前工作空间列出记忆整理、记忆查询和上下文压缩；支持类型、状态、时间、会话与文字筛选，每页50条。记录每4秒更新，浏览、筛选和刷新只读取记录，不会调用模型。返回记忆树保留原来的搜索、展开和缩放状态。

## 一次处理与模型请求

一次处理是一条主记录，保存来源会话、起止时间、阶段、状态及失败原因。内部可以有多次模型请求，每次分别记录模型、调用准备时间、进入模型调用的时间、输入、SDK原始响应、用量及请求结果。

例如模型返回“我会完整读取会话记忆”时，请求可以成功，但整理会在“解析输出：MEMORY.md”失败。详情同时保留成功请求的原始响应与处理阶段错误，便于区分供应商请求、解析、来源校验、发布或摘要应用问题。进入模型调用的时间只表示代码已调用供应商接口，不表示远端已收到请求。

整理在读取前创建记录，读取失败、模型未配置、预算不足或排队失败也可查看。查询的Section匹配与答案归纳属于同一条记录；查询结果附带`processingId`。压缩记录沿用任务ID，自动压缩启动失败也复用同一ID。

## 状态与历史信息

处理状态包含进行中、取消中、成功、失败、已取消、已中断和结果已失效。压缩取消尚未获得安全点确认时继续显示“取消中”及具体说明。后续确认已应用时以真实应用结果为准。迟到的原始响应与用量可补入记录，但不会把已取消的请求改成成功。

服务启动将未结束的处理标为中断，不自动重发请求。已有压缩任务可转换成历史记录，仅展示原来保存的起止时间、最终阶段和结果，不补造逐阶段时间。旧记忆整理错误通过来源错误入口展示，无法恢复过去未保存的输入、输出、具体失败文件或准确失败时间。

## 存储与访问

`processing_records`保存在应用SQLite数据库，按工作空间和来源会话校验访问。列表采用游标分页；详情按记录编号读取。删除来源或改变归属后，原工作空间无法继续读取该来源记录。

输入、响应和结果逐项最多保存2,000,000字符，超过时明确标记截断。常见凭据字段、Bearer令牌及API密钥脱敏，仍可能包含业务资料；脱敏不替代工作空间访问权限。记录保存SDK响应对象，不是原始HTTP报文。旧请求未保存的信息不会伪造补齐。

## 验证入口

- `app/tests/processing-records.test.ts`：记录生命周期、隔离与分页、脱敏、迟到响应、重启、解析失败和两阶段查询。
- `app/tests/processing-records.check.ts`：记忆/压缩入口、历史错误、详情响应、筛选分页、返回状态、四种宽度及浏览不发起模型请求。

测试使用隔离数据目录和本地假模型，不需要真实供应商调用。实际构建与验证结果应以执行日志为准。
