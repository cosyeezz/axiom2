# 通用组件能力、状态与维护契约（定稿）

**状态：已合并用户认可的能力方案、其它本地会话的强化维护定义，以及六类最终图标；按本文实施。** 实施验收另记，不将设计要求冒称已通过测试。此前方案原文保留在[强化前快照](../artifacts/component-maintenance-implementation/capability-state-logic.before-strengthening.md)。

## 1. 适用范围与优先级

适用于 OpenCLI、REA 主程序及独立引擎、RTK、Xray/mihomo，以及后续声明遵循通用规范的接入组件。桌面安装／更新监督器的恢复协议不属于本次强制维护规则；不顺手取消其恢复能力。

较新的明确要求覆盖旧方案中的冲突条款：

- **安装**：直接解析可安装的最新版本，不要求先点检查；现场查询失败时可回退已有真实候选。失败后强制清理该组件，再安装一次；最多重试一次，主动取消不触发清理重试。
- **更新**：采用同一强制安装流程，允许降级。已知目标较低时名称明确为“切换至推荐／最新版”，不能伪装成版本上升；未知目标不能凭不相等声称有更新。
- **卸载**：客户端确认后强制清理该组件的托管程序／对应私有环境和安装记录。旧 revision、检查结果、中断历史、安全点或 Agent 状态不再作为前置门禁。不要求先做卸载范围扫描。
- **抢占**：核心维护按钮在任务运行中仍可触发，由执行器取消原维护操作；同目录写入者在最多 15 秒后仍未退出时可如实返回 BUSY，不能让两个维护写入者并写。
- **历史**：接入组件不持久化中断／待核实状态，不用旧历史阻塞下一次操作。不离线排队或自动重放维护。

执行规范源见 [component-maintenance.ts](../app/src/server/integrations/component-maintenance.ts) 文件头。以上不是删除任意外部路径、修改系统安装或承诺强杀所有资源使用者的授权。固定组件容器、包完整性、实际系统权限及真实失败仍要如实处理。

## 2. 组件声明能力，通用层计算动作

```text
组件适配器：真实支持的能力 + 独立事实 + 既有执行命令
                           ↓
            shared 纯动作规则（不按组件 ID 特判）
                           ↓
             同一种递归组件卡 + 可访问动作
```

适配器声明安装途径、维护范围、版本来源、各动作支持／适用性和真实依赖。通用卡不推断组件名称，也不把父子视觉嵌套当作所有权。

事实维度必须分开：

| 维度 | 要记录／展示的事实 |
|---|---|
| 安装 | 未知、确定未安装、已安装、不完整；真实路径，不能以无版本推断未安装 |
| 执行端与维护范围 | 托管、外部／系统管理、随父维护；外部发现不等于接管 |
| 本地版本 | 来自本地安装的版本，不能用远端候选填当前 |
| 运行验证 | 未验证、通过、不兼容、失败、部分验证；版本一致不等于运行／许可验证通过 |
| 远端候选 | 未查、查询中、真实候选、具体失败；最新与推荐分开 |
| 缓存 | 无、下载中、登记包、经校验可用、失效；登记／版本匹配本身不是完整性证明 |
| 任务 | 本次排队／运行／取消中／成功／失败／取消；接入组件不保留跨重启中断账本 |
| 真实暂阻塞 | 连接不可用、请求正在发送、安装器／缓存清理资源占用、真实宿主前提 |

随父发布的 Node/npm 仍可用递归子卡展示，但只提供实际可用的父检查入口，不能虚构独立更新或卸载。

## 3. 支持、适用、暂时可用分开判断

| 结论 | 展示和交互 |
|---|---|
| 适配器明确不支持／尚不能确认能力 | 隐藏假的动作；重要限制在卡内说明实际途径 |
| 支持但确无意义的附加动作 | 隐藏，例如没有登记包时不显示清包、没有有效包时不显示缓存安装 |
| 已支持核心安装／更新／重装／修复／卸载 | 保留入口，不因未查版本、相同版本、无版本字段、旧状态或运行任务禁用 |
| 暂因真实前提无法执行 | 保留可聚焦灰色入口，键盘／触屏能读到具体原因；点击不发送、不假报成功 |
| 当前连接断开／正在提交请求 | 保留能力和已知事实，说明重连／等待后重试；不离线排队、不自动重放 |

**例外必须明确：核心卸载不是“版本字段不存在就无意义”。** 即使没版本，也可能要清理损坏安装或残留；托管范围的卸载入口仍保留。Hopper 等系统外部应用只有真实卸载说明，不能伪造托管删除。

旧的“disabled 一律隐藏”不再适用。支持、适用性由模型决定；暂阻塞由 `aria-disabled`、可读原因与禁止发送共同表达。保留既有 fine-pointer 灰色悬停／聚焦三态、触屏常显、子卡不点亮父卡以及键盘焦点回收。

## 4. 动作矩阵与命名

| 安装与候选事实 | 主要维护动作 |
|---|---|
| 未安装／安装尚未核实 | 安装；执行时自己解析目标，不要求预先查询 |
| 已装、候选未查或无法比较 | 重新安装；不凭未知候选称“更新” |
| 已装、同版 | 重新安装；不得因为同版隐藏维护入口 |
| 已装、已知更高候选 | 更新；实际执行仍现场解析，不将页面旧候选当绑定承诺 |
| 已装、已知更低候选 | 切换至推荐／最新版，说明可能降级 |
| 不完整／损坏且声明支持重装修复 | 修复（重新安装）；明确策略，不伪称无损修补 |
| 可下载但只能手工安装 | 下载安装包，以及实际安装说明；下载成功不叫已安装 |
| 已登记可用 Ghidra 缓存 | 使用缓存安装；执行端重新检查完整性及版本，不绕过校验 |
| 已登记 Hopper 安装映像 | 打开系统安装器；执行端校验后请求打开，之后仍待用户完成系统安装 |
| 外部安装 | 本地／环境检查和真实原安装方式说明；不删除外部应用 |
| 随父环境 | 从父组件检查／维护；不提供假的独立卸载 |

“检查安装”“检查环境”“查询版本”是三个能力。现有命令若组合了本地与远端检查，说明真实行为，不靠换名假装已拆开。未安装不应无故取消远端查询；真实宿主契约限制要给原因。

修复必须由适配器声明真实策略与范围。健康同版的全量安装称“重装”，而不是自动叫“修复”。若引擎重装，必须跳过“同版本直接复用”的优化；缓存安装／普通安装可以保留各自真实复用策略。

## 5. 任务与真实后置条件

- 请求受理不是任务成功；成功后重新读取实际安装、路径和版本。下载不写已安装版本，打开安装器不写安装成功。
- 强制安装失败可能已经删除旧安装，**不承诺失败保留原版或自动回滚**。重装确认必须披露失败清理重试及可能降级；最终失败保留真实错误与当前事实。
- 取消只表示本次请求取消，不承诺旧版本不变；发布后故障不能误报为尚未切换。资源／权限／进程退出失败如实报告。
- 当前失败可在当前卡显示；不恢复接入组件的跨重启中断／待核实阻塞。也不影响桌面监督器自己的恢复语义。
- 真实资源冲突由执行器处理，不能因父子展示关系禁用全部组件。非核心的下载安装包、缓存清理、打开安装器仍可因真实冲突暂阻塞并说明原因。

## 6. 清包与卸载不能合并

| | 清理安装包 | 强制卸载组件 |
|---|---|---|
| 对象 | 已登记下载缓存 | 对应组件容器内的托管程序／私有环境与安装记录 |
| 安装事实 | 不改变 | 完成后重新核实 |
| 关键范围 | 保留程序、设置、未登记文件、系统安装器副本 | 依组件说明保留设置／用户数据／外部应用；REA 主程序不连带独立引擎 |
| 确认协议 | 继续沿用登记包范围、revision 与执行端完整性校验 | 客户端确认即可，不恢复旧 revision／owner journal 前置门禁 |
| 失败 | 明确范围变化或不能校验原因 | 报真实删除错误，可再点重试，不假报清空 |

RTK 统计／原文清理、MCP 凭据清理等属于独立数据动作，不因强制卸载就自动扩大删除范围。

## 7. 信息展示与六个最终图标

- 头部保持双字标签 **当前／推荐／最新**，只显示有证据的具体版本。候选未查就不显示“尚未检查／待检查”；已装无版本可显示“已安装”，未读安装事实不伪装未安装。
- 不重复“已是推荐版”，不反复展示健康“未检测”。真实失败、不兼容、权限或宿主限制保留；查询失败不能覆盖本地当前版本。
- 已有静态主版本约束不冒充可安装的完整修订。Hopper 版本匹配不能冒称已验证许可或桥接。

用户最终选型见 [确认清单](component-action-icon-selections.json)。新增六个语义键独立于原安装／更新／重装／卸载图标：

| 下载安装包 | D-23 | `hugeicons:package-receive-01` |

## 8. 实施验收边界

1. shared 纯模型覆盖安装事实、候选比较、能力／适用性、连接、发送中、任务运行、缓存和父维护；无组件 ID 特判。
2. 各托管程序和 REA 引擎接线；运行中仍能触发核心维护；无前置 check/revision 门禁复活。
3. 相同版本重装、较低目标切换、显式重装修复与附加缓存／安装器动作命名一致，不虚构能力。
4. 断线和暂阻塞保留键盘／触屏入口、说明原因且不发送；不支持／无意义动作才隐藏。
5. 清包独立确认，外部安装和随父运行时不递归越权删除；确认准确披露强制维护范围与失败后果。
6. 隔离测试和浏览器 fixture 验证，零真实维护请求；保留原递归布局、边框、26／24px 类型图标、16px 组内参照和双字标签。
7. 本轮只实现代码、前端产物与隔离验证；不实际安装／卸载用户组件，不重启后台，不替换桌面应用或发布安装包。
