# 多账号管理重新设计：真实状态优先

> 历史v4：下文折叠身份、查询原因和金额说明的设计已被用户后续「账号信息直接展示、明确启用、减少折叠」要求替代。当前实现与新验收见[账号信息直显与启用](model-accounts-inline.md)。本文旧设计、结果及截图保留溯源，不代表当前界面。

用户拒收上一轮实际效果。本次不是继续微调旧卡片，也不把此前112组离线矩阵当作视觉验收。旧八平台研究保留在[研究文档](model-account-card-design.md)，这里只采用信息纪律，不再按供应商身份预设“必有额度报表”。

## 验收基线

实际截图：单个原有 OpenAI OAuth 账号，当前使用，额度返回 `unavailable`、`metrics: []`、`refreshable: false`，有官方用量入口。旧卡片约400×304，出现订阅报表标题、两段否定说明、金额空指标、多道分隔线及重复的当前/使用中，主要操作反而次要。

新设计第一眼须回答：哪个账号、是否当前、能否查额度、下一步做什么。不可查询不等于认证失效或额度为零。不能靠空指标、灰色禁用按钮、无意义头像或假汇总填空间。

## 整页与账号结构

- 保留系统侧栏与面包屑；短页名和结果数、添加主操作、刷新列表。页面标题与内容边界清楚，不增加hero或教学段落。
- 完整合格集合多账号时才显示搜索；多供应商才显示供应商选择。正在筛选时持续保留控件，不能因结果减少而消失。资格仍先于筛选计算。
- 供应商轻分组、紧凑账号网格。普通最小240px、扩展组320px；单搜索结果不拉宽，内容自然增高，不让同排卡片被拉齐。单账号不因为“管理”两字展示整套空筛选。
- 身份头移除无意义首字头像；名称/真实身份优先，区域仅确有值才显示。当前状态只出现一次；详情使用可见文字，非当前才出现切换按钮。身份与账号操作在头部，不再和额度刷新混成一排图标。
- 暖橙用于当前小标识与真正可执行入口；卡边保持柔和，避免强橙轮廓强调一张无数据面板。

## 按真实数据组织

| 状态 | 展示与操作 |
| --- | --- |
| 初次加载 | 简洁查询中状态，不模拟余额/进度 |
| 不支持或授权不可查询 | 无报表标题、无空指标、无额度刷新；简洁状态和官方入口，完整原因通过明确的查询说明展开 |
| 首次查询失败 | 显式失败消息和可用重试，不当成不支持，也不展示0 |
| 已有额度 | 实际指标才有额度标题；点数/次数摘要、独立窗口、比例与方向、完整重置/到期内容 |
| 刷新失败有缓存 | 保留原数值，明确旧数据/更新时间/失败原因；刷新可重试 |

金额归属限制保留且只一次：已有指标时，`预计可用金额 —`、`本机账单未按账号归属，无法估计此账号金额。` 作为轻量说明；没有指标时，通过明确的「金额估算说明」键盘可展开入口查看完整原文，不在默认卡面继续常驻第二组空指标。不读ledger、不把点数或百分比换美元。

账号身份只保留一条主线：官方查询邮箱优先，其次授权邮箱，再次账号 ID；套餐同样优先官方值。邮箱不同时显式提示「身份来源 · 与授权邮箱不同」，可展开查阅两种来源及令牌声明的非验证性质。长身份/套餐在主行省略，可由明确入口展开完整原值；额度、数量、比例、日期与错误不裁剪。

共享 ProviderUsage 仅提供账号展示选项；默认公共视图不变。每卡只有一个查询实例，查询/缓存/hidden/IntersectionObserver/abort/迟到/60秒抖动及服务端更近deadline不改。不改认证、后台、凭据、运行任务绑定。

## 本轮验收方式

1. 把与实际截图对应的 direct 响应作为独立场景：单账号完整页面与混排均审图，深浅/桌面/手机/大字；不能用 ready-null 或 API Key unsupported 冒充。
2. 加入真正RPC拒绝的首次失败、ready后刷新失败、恢复；检查不支持时无刷新/无轮询，官网链接安全，完整原因可键盘展开。
3. 保留112组几何/对比/触控/焦点检查与原业务、安全、完整额度回归，保留普通卡20–35%密度断言。不把这些数值当视觉评价的替代。
4. 主Agent看完整首屏及关键长图；另由只读审查核实际效果。任何真实场景仍像占位报表都不以“测试通过”交付。
5. 不真实OAuth/上游额度/付费调用；未经授权不重启实际后台。构建与离线预览不冒充已部署。

## 实景审查的修正记录

第二轮两矩阵在75%字号发现「查询说明」触控宽度41.73px，未达到44px；已修实际最小宽度，不放宽断言。人工查看完整页面又发现供应商选择框占满整行，现约200px与搜索同排。只读视觉审查进一步指出双邮箱来源不清、无数据卡仍有空金额摘要，现采用单一主身份、完整来源展开和无数据金额说明展开。

320px/200%元素截图曾被内部滚动容器裁切，不能拿黑块截图证明内容完整。新验证同时保留原视口截图与滚动可达断言；补充整卡图保持宽度/字号、明确增加截图高度后恢复，不修改生产滚动样式。
