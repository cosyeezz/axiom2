# 配置页加载与缓存边界

配置页继续使用整页导航，以隔离各页样式。性能优化不依赖把配置表单写入浏览器缓存。

## 加载策略

- 全站字号反馈使用独立轻量组件，不能静态引用显示设置编辑器或在线字体目录。
- 在线字体目录仅在打开字体库后按需 `fetch` 内容哈希 JSON；显示页的基本字体选择与本地导入不等待在线目录。使用数据请求而不是动态模块导入，避免浏览器缓存失败模块导致“重试”无效。读取失败显示重试入口，不能让整个配置页白屏；关闭后不显示目录错误，重开可重新请求。
- 非连接页在页面模块加载期间开始建立服务连接。订阅仍由页面挂载驱动，已连接时立即订阅、未连接时在连接建立后补订阅。
- 页面模块加载后，公共控件、图标、移动布局和主题覆盖样式通过一个有序 `@import` 样式入口加载，保留原层叠顺序，减少四次串行资源往返。
- 模型列表面板首次切入后才挂载；切回连接配置时不卸载已访问面板，避免丢失模型编辑与目录选择状态。

## 缓存一致性

- 正式构建中 `/assets/` 下含内容哈希的 JS/CSS/字体/图片及内置字体目录 JSON（仅 `font-catalog-<hash>.json`）使用 `private, max-age=31536000, immutable`。缓存仅限浏览器，不允许共享代理缓存。
- HTML 页面入口、API、无哈希文件和错误响应仍使用 `no-store`。新构建改变内容即改变 URL；下一次导航获取新的 HTML，并加载对应的新资源，不会复用旧 URL 下的不同内容。
- 配置内容、认证结果和未保存草稿不新增持久缓存；配置仍从服务端读取，保留现有 WebSocket 快照、重连订阅和保存修订校验。用户临时输入的密钥不写入本轮新增的任何缓存。
- 上述保证是“不因新增缓存读到旧配置”，不是新增所有已打开表单的实时自动更新：现有模型编辑器首次连接读取配置，远端修改后重新进入或刷新会重读；订阅 revision 变化尚不会自动重读并覆盖编辑表单，直接修改后台文件也不保证即时广播。本轮不改变这些既有行为，不自动丢弃用户草稿。
- 这不是页面热更新机制：已经打开的页面不会自动替换正在执行的 JS；部署后需要刷新。服务端代码变更仍需正常部署/重启才能生效。部署时应保留仍可能被已打开页面引用的旧哈希资源，避免延迟导入遭遇 404；若旧资源已被清理，需刷新页面获得新版入口。

不要仅以 `models.json` 的 revision 缓存完整编辑数据：认证文件和模型目录也会影响结果，且读取可能执行旧凭据迁移。若后续增加配置数据缓存，必须另行设计覆盖这些来源的失效版本、并发读取去重和草稿保护。

## 验证结果

隔离生产构建、Chrome 手机视口 390×844、每页三次冷载对照：

| 页面 | 优化前初载 JS（解压后字节） | 优化后 |
| --- | ---: | ---: |
| 配置概览 | 1,173,281 | 388,453 |
| 模型配置 | 1,194,665 | 414,084 |

两页初载均不请求字体目录；再次整页导航的 JS/CSS 网络传输为零。新 HTML 发现新 hash 并下载新资源，未变更资源仍命中缓存。此数据不代表真实手机或远程网络的耗时改善比例，资源测量使用隔离静态服务，不调用正式后台。

回归覆盖：200 行模型首次访问挂载与未保存草稿保留、字体目录按需加载及复用、503 后重试、404 后关闭重开、请求迟到不重新打开弹窗、字体导入/离线恢复/跨窗口同步，以及显示设置 Chromium 与原生 WebKit 滑块检查。生产 fixture 额外验证提前连接、刷新读取新配置及目录故障恢复；静态缓存通过直连/网关检查，新增 JSON 白名单通过 70 项直接 HTTP 断言。类型检查、字体目录/缓存单测和隔离构建均通过。未部署、未重启正式服务，未进行真实手机/Tailscale 验收。
