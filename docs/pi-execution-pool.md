状态：统一物理池已接入 Agent、记忆查询／整理和压缩摘要。有界异步读取候选已在隔离工作树通过243项回归、构建和SDK回环检查，并完成三批亲和与资源规模冻结测量。多资源准备成本明显下降，但亲和仍超出初始目标；容量校准和最终验收尚未完成。实施契约见 [实施方案](Axiom2-pi-execution-pool-implementation.md)，业务边界见 [产品设计](design.md) 和 [会话记忆](session-memory.md)。

## 1. 当前复用范围

| 路径 | 可以保留 | 每次执行仍需建立 |
| --- | --- | --- |
| 主／子 Agent | 同会话的进程和 AgentSession；未绑定进程可以预热模块 | 独占租约、本轮回调与预算、当前配置和文件修订校验 |
| 固定记忆 D 模式 | 进程和验证过的 ModelRuntime，可跨查询／整理复用 | 内存 session、空资源 loader、settings、工具闭包、读取权限、订阅和预算 |
| 固定记忆 C／managed 模式 | 未绑定进程可以在 C 模式预热 | 运行环境与绑定；任务后退出 |
| 压缩摘要 | 未绑定进程可以在 C／D 模式预热 | 当前快照的单次 session；摘要结束后退出 |

主 Agent 不跨真实会话复用已消费的扩展环境。不能证明资源身份的主／子环境采用 single-use，禁后台预热。固定记忆仍按 cwd 分组，不临时更改进程工作目录。压缩只写自己的快照，不取得原会话 JSONL 写入权。

预热只启动 Node、导入模块，或为固定记忆准备模型运行环境，不创建虚假对话、不发模型请求、不执行项目工具。完整项目资源和扩展仍在真实绑定时加载。近期实际需求触发少量补充；只有成功授予真实租约才刷新 profile 的需求时间。距最近需求达到空闲TTL后，下次预热检查会释放该记录并停止后台补充，预热、归还和进程退出不延长需求窗口。活动租约持有独立引用，不因需求记录过期而被停止。打开历史列表不会为每条会话启动 worker。预热目标是全局数量，已有其他 profile 的未绑定实例也会占用目标；它未被回收前，新 profile 可能仍冷启动。

## 2. 模块职责

| 模块 | 当前职责 |
| --- | --- |
| `execution-profile.ts` | 有效环境 hash、真实 SDK 版本、配置与资源修订、模型快照引用 |
| `execution-protocol.ts` | 实例／代次／租约信封、事件发送与身份验证 |
| `execution-pool.ts` | 唯一物理额度、创建预留、准入、亲和、预热、回收与真实退出 |

| `compressions.ts` | 快照、摘要校验、结果持久化及应用安全点 |
| 三类 worker | 各自准备、绑定、执行和清理；保留原有工具与权限边界 |

业务管理器保留原来的队列和状态；池只负责资源分配，不引入第二套任务调度器或用户清理确认流程。

## 3. 环境与模型快照

`profileHash` 使用稳定对象键顺序和 SHA-256，包含 worker 构建、实际 pi 包版本、Node 版本、入口、复用能力、真实 cwd、模型目录、启动环境、模型／认证修订及有效资源。Agent 还包含选择和子任务角色；固定记忆的查询／整理类型、请求身份及模型选择是绑定参数，不因每次调用不同而破坏兼容性。

配置 JSON 的 profile 身份按内容规范化，单纯格式变化不改变 hash；文件监听采用保守失效，格式重写仍可能触发空闲实例退役。普通业务文件不参与初始化资源身份。准备阶段持续复核模型、认证、设置与快照；Agent 在建立环境身份、发送绑定输入前、真实绑定完成后完整扫描资源；最后一次复核实际租约环境，匹配后才发送执行许可。发送前检查保留了对可信扩展初始化／回调的拒绝边界。生产 Agent 明确声明绑定门控，因此准入与 ready 中间检查不重复遍历资源目录；未声明门控的直接池调用仍执行完整 ready 校验。正常 prompt 收到匹配租约的执行许可后才进入首次推理；可信扩展可主动发起模型轮次，不能将该门控宣称为任意扩展代码的执行沙箱。绑定许可等待可取消、断连拒绝且有30秒上限。协调器明确拒绝许可时，Agent 与压缩 worker 保留绑定失败，即使紧随的退役 shutdown 在 Promise 恢复前到达；先发生的停止仍按取消处理。路径使用实际文件系统路径，不统一转小写。会话 JSONL 的工作目录归属使用原生 realpath 解析 Windows 8.3 短名和系统路径别名，仍拒绝不同目录及读取期间被替换的会话文件。初始化资源读取内容摘要；当前异步候选沿用相同的有序字节摘要，每批最多8个文件、进程内最多8个异步读取同时执行，不跨校验边界缓存内容。读取绑定实际打开的文件，核对前后身份与修订，并限制在原大小加一个字节；读取完成后同步复核已观察的文件、枚举目录和缺失路径。只选择固定子项的父目录核对目录身份，各子项独立复核，避免无关临时文件改变父目录时间戳而误拒。该机制不提供文件系统原子快照。等待期间配置变化、取消和租约替换均须在校验返回后重新核对；关闭等待已发起的系统I/O返回并完成收尾。外部 packages/extensions/skills/prompts、符号链接、超出验证预算等无法证明的环境禁止复用与预热。

监听 `models.json`、`auth.json`、`models-store.json` 只提供失效信号，借用和执行边界仍复核内容。配置与记忆目录的监视器注册前使用原生真实路径，避免 Windows 短名触发 libuv 原生断言；保留事件投递、关闭与已有错误恢复机制。旧配置实例不改 hash 冒充新环境，撤权继续按业务规则停止活动执行。

模型快照由环境引用计数持有，位于服务数据目录的 `execution-models/`，不随创建它的首个 Run 结束而删除。文件缺失或损坏时，新建独立路径的快照并使旧环境失效；旧引用释放不能删掉新的注册项。最后引用释放时的文件删除失败不阻断进程关闭通知和停止等待，遗留文件由下次服务启动重试清理。只在服务数据目录锁保护下清理遗留快照，不清理共享 pi 配置目录。

## 4. 生命周期与所有权

```text
创建预留 → preparing → available → leased → cleaning → available
               │           │          │          │
               └───────────┴──────────┴──────────┘
                                      ↓
                                  retiring → exiting → exited
```

创建预留计入总容量，未 fork 时可以撤销；`ensureReady()` 单飞，取消后的旧调用不能重新 fork。准备有独立超时，失败有界退避。任务结果、IPC closed 或退出请求都不能释放物理名额，只有实际 OS close 才移除实例。

池退役时通常发送包含 instanceId／generation／profileHash 的实例级 shutdown；绑定校验拒绝且执行许可已排入发送时，只撤销复用资格并等待 worker 自行报告失败、完成清理和退出，不再并发发送 shutdown，以免把绑定失败改成用户取消或抢先关闭 IPC。该路径仍保留原有强杀期限与真实 close 等待。Agent worker 接受匹配实例的退役，即使新租约尚未送入旧亲和 worker，也能正常清理。每次借用生成 `LeaseRef(instanceId, generation, leaseId)`。异步工具、事件、结果及用量捕获原租约；旧回调和旧取消不能作用于新租约。成功归还需要同租约 cleaned／idle 确认；Agent 收到有效 idle 后，以准备超时作为独立资源验证期限（默认30秒），替换等待清理的2秒期限，重复 idle 不延长期限；失败、状态不明和强制取消退役。强杀在发起操作系统终止前同步撤销复用资格，迟到 idle 不能重新归池，物理名额仍等待实际 close。归池参数读取或异步归还失败不跳过已持久终态的唯一通知与业务退出兑现。取消后已知消费仍归原执行。

同会话绑定一直是唯一 JSONL 所有者，直到合法复用或真实退出。恢复 JSONL 时，工作目录别名通过与工作空间登记一致的原生真实路径解析核验，兼容 Windows 大小写／短路径及 macOS 系统目录别名，不对大小写敏感的目录统一折叠，仍拒绝不同真实目录。文件改写、压缩应用、删除和文件修订变化必须完成所有权交接；single-use 实例退出中也保留原会话所有权，后继不得抢先写入。

服务关闭停止准入、取消资源等待与 pending start，等待启动收尾、租约和拥有进程退出，再释放环境引用。重启不自动重放不确定输入。

## 5. 准入、预算和回收

Agent 启动分为配置准备、锁外等待资源、锁内最终复核与激活 Run、锁外 worker 准备。池等待不占模型配置串行锁、不提前创建执行 Run；子任务工作预算从最终 Run 激活开始，之后的冷准备仍计入预算。等待中的请求可停止，`active()` 包含启动等待，`executing()` 只表示已激活执行。停止与供应商撤销等待准备阶段收尾；尚未进入配置锁的准备可直接取消，之后不会执行其回调，避免撤权 writer 等待同锁请求形成死锁。已进入的准备仍须完成清理。提交前执行环境准备失败持久化为明确失败；提交／IPC 已尝试的未知结果保留原分类，快照清理异常不覆盖该回执。

记忆的业务许可和物理名额同时领取，后台整理不能占住许可后无限等进程。同步记忆查询只有提供仍活跃的父租约才能使用叶子预留；预留也计入全局上限。记忆总截止时间包含排队、准备和执行，不在借到实例后重新计时。

压缩只在生成摘要期间持有租约，进程关闭后可继续等待原会话的摘要应用安全点，不为等待应用长期占资源。

空闲回收遵循数量上限、TTL 与最大寿命；普通 LRU 不淘汰活动执行。不兼容空闲占满时立即按需退役一个实例，等待实际 close 后再创建，不等完整 TTL。同一目录不同有效 profile 可合法并存。

当前源码候选参数为物理上限24、空闲保留4、未绑定预热目标1、叶子预留1、同时预热1、空闲与最长寿命15分钟、资源等待上限256、准备超时30秒。这些尚待生产数据校准；没有实现基于 RSS 的动态准入，物理进程数限制不能称为内存硬上限。

## 6. 模式与可复现测量

内部环境变量 `AXIOM_EXECUTION_MODE` 支持 `managed`、`C`、`D`：managed 关闭后台预热与新增跨绑定；C 预热进程；D 对固定记忆增加 runtime 预热与跨绑定。目前源码默认 D，发布默认值仍待测量确认。

A 原实现与 B 低成本优化保留为独立生产构建，不能用当前代码切 flag 冒充旧实现。C／D 使用同一稳定构建的内部模式。基准只通过本地 HTTP mock 调用真实生产 worker 与 SDK，不访问付费供应商。

```powershell
cd app
npm run build
node scripts/bench-execution-pool.mjs --build=dist --label=D --mode=D --samples=100 --hits=200 --batches=3 --output=test-results/execution-pool/D.json
```

脚本记录构建及探针摘要、机器、Node、原始样本、阶段、失败样本、资源和汇总；可用 `--scenarios=agent-cold,agent-affinity,agent-process,agent-rotation,memory,compression` 选择路径。`agent-rotation` 按六会话偏斜轮转访问，用于比较空闲保留容量；它不在默认场景中。`--max-live`、`--max-idle`、`--ready`、`--max-prewarming`、`--idle-ttl` 和 `--max-lifetime` 通过冻结构建的池构造器校验，报告保存实际参数及脚本摘要；自定义 label 应同时显式指定 `--mode`。预热成本计入采样窗口。`agent-process` 为同 profile 不同会话路径；受控采样在连续样本间等待准备完成。

`--idle-window` 延长最后一次业务请求后的静默观察窗口（默认1000ms），记录带单调时钟时间的池数量曲线与最近一次准入时间，供TTL／最长寿命回访检查；观察结束后才关闭服务。真正的固定到达节奏使用 `scripts/bench-execution-arrival.mjs --mode=D --scenario=memory --samples=100 --interval=250`，不等待上一次执行结束或池准备；记录计划到达、实际到达偏差与全部成功／失败。普通串行脚本的 `--arrival` 仅为最小请求间隔，不能作为开放负载的固定到达证明。

`scripts/bench-execution-scale.mjs` 使用约0.5／5／50 MiB历史与50／500／2,000个技能资源，记录实际JSONL字节／行数、资源字节、加载数量及失败样本，作为小样本趋势检查。`scripts/summarize-execution-pool.mjs` 汇总冻结产物，分别列出总体、实际命中、固定到达和资源成本；主矩阵完成前明确标为阶段性报告。

本地准备口径为父进程 `mock_received`，provider hook 为辅助观测，不能混合比较。Agent 首输出是服务端消息事件；记忆和压缩采用 `result_returned`，不称为流式首 token。命中类别按请求入口前的就绪状态区分 affinity/environment/process/preparation_inflight/cold，不能直接把 `lease.source` 当命中率。

RSS 合计包含共享页，250ms采样峰值不等于精确瞬时峰值；Node active handles 不等于 OS 句柄。worker 探针每100ms采样，CPU统计包含探针自身开销，约1秒的空闲CPU窗口尤其不能当作未插桩产品的精确成本。正常场景失败不能从统计中删除后宣布通过。
