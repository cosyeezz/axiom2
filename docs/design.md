# Axiom2 第一阶段产品设计

本文是第一阶段的实施与验收依据，描述产品应具备的能力，不表示功能已经实现。功能、接口与约束调整时直接更新对应正文，保持一份当前有效的设计。

## 1. 产品目标

Axiom2 是基于 pi 的本地编码 Agent 工作台。用户可以管理多个工作空间和会话，与主 Agent 对话、委派子 Agent、查看工具执行。

第一阶段完成以下闭环：

1. 打开项目目录，建立工作空间。
2. 配置模型与认证，在会话中选择可用模型。
3. 主 Agent 使用 pi 读取、修改文件和执行命令，实时展示过程。
4. 主 Agent 委派子任务；用户和主 Agent 均可追问、停止子代理。
5. 切换工作空间、切换会话、刷新页面和重连时，保持正确的数据归属。
6. 在浏览器与 Pake 桌面壳使用同一套产品。

### 1.1 实施原则

- **设计准确复刻**：以 `ui/` 的页面与交付说明为视觉和交互依据，不另行设计一套界面。
- **设计源只读**：开发不修改、格式化、移动或删除 `ui/`；产品实现在 `app/`。
- **pi 是运行核心**：模型调用、认证、会话上下文、基础工具、重试与压缩使用 pi 的公开能力。
- **独立工具**：委派、追问、取消、读取结果分别注册，不使用 Ask/Let 或统一 action 工具包装。
- **服务端隔离**：工作空间、会话、子任务、执行的归属由服务端校验，不能只依赖前端筛选。
- **独立刷新**：对话输出不能打断输入、模型选择、菜单操作或其他会话查看。
- **事实优先**：不使用模拟任务、虚构工具、虚假成功状态或伪造用量填充产品。
- **可恢复不等于自动重做**：重连与重启不得重复发送请求、重复委派或自动重放文件修改。

### 1.2 第一阶段范围

| 模块 | 交付内容 |
| --- | --- |
| 工作空间 | 选择本地项目目录、切换、重命名、置顶、移出列表、恢复上次使用空间、展示与复制路径、打开系统文件管理器 |
| 会话 | 创建、恢复、切换、自动短标题、手动重命名、删除、搜索、置顶、草稿、未读与运行状态 |
| 主 Agent | pi 会话、流式回答、工具过程、多文件／文件夹附件、图片、@ 原生文件补全、强制停止与无新增消息续接 |
| 后台压缩 | pi 独立快照原生摘要、安全点自动应用、主／子会话独立状态与详情、取消／重试 |
| 子 Agent | 异步委派、独立上下文、实时详情、追问、取消、预算、结果回传 |
| 模型服务 | pi 配置文件管理、API Key/OAuth 认证、模型覆盖、可用列表、删除与退出登录 |
| 配置概览 | 实际模型配置摘要、配置与凭据存储说明 |
| 持久化 | pi 会话文件、SQLite 管理数据、断线恢复 |
| 平台 | Windows、macOS、Linux 的本地服务与浏览器使用，Pake 桌面接入 |

不纳入第一阶段：多人账户系统、云端调度、递归 Agent 网络、自动长期记忆维护、复杂目标工作流、自建模型网关、独立压缩引擎、拖拽页面编辑器、属性编辑面板、多人评论与移动端原生应用。已安装的 pi 扩展与技能按 pi 规则加载，不另外开发插件市场。

## 2. 页面与设计契约

### 2.1 页面映射

| 产品表面 | 设计来源 | 实现要求 |
| --- | --- | --- |
| 工作台 | `ui/coding-agent-v2-before-subagent-modal-v2.html` | 工作空间侧栏、会话列表、消息区、输入区、模型菜单、用量栏 |
| 配置概览 | `ui/settings.html` | 单独页面，展示实际配置摘要和存储范围 |
| 模型服务 | `ui/model-config.html` | 单独页面，供应商列表、连接配置、模型配置、覆盖项、统一保存 |
| 子代理会话 | 工作台中的子代理弹窗 | 保持弹窗外观，使用独立会话实例与状态 |
| 后台压缩 | 输入框下方工具栏的压缩入口及详情侧页 | 图标始终打开页面，页内开始／再次压缩、取消及统一模型选择；任务按主／子会话独立，压缩模型全局记忆 |

页面入口以 `ui/DESIGN-HANDOFF.md`、`ui/DESIGN-MANIFEST.json` 和实际页面互链核对，不能仅凭文件名称选择。辅助 HTML、截图和检查脚本用作设计参照，不据此自动增加产品导航入口。互链与交互检查脚本指向不同页面时，先核对目标交互，不擅自丢弃其中的设计要求；待核对项集中记录在 `docs/ui-sync.md`。

### 2.2 复刻要求

- 保留颜色、字体、字重、间距、边框、圆角、阴影、图标、尺寸、布局、滚动区域和动效时长。
- 从设计中的 CSS 提取变量，不引入组件库默认主题替换原样式。
- 保留悬停、焦点、禁用、空态、错误、加载、选中、折叠、弹窗和确认取消行为。
- 普通用户消息与用户发送的 Steering／追加消息（包括历史记录）统一采用用户气泡，系统通知不作为用户消息；气泡采用低饱和绿色背景与细边框，保持原有靠右布局、圆角与正文颜色；图片附件采用独立浅蓝色图标＋编号标签，与绿色气泡和正文区分，不改变全局强调色。
- 页面分别实现，组件可以复用，但不能将全部页面合并为一个巨大组件。
- 数据接入后用真实内容替换演示数据；“本地演示”“尚未连接”等说明按实际能力改成准确的状态文案，不改变原有信息层级。
- 输入框支持中文输入法；组合输入期间 Enter 不发送。Enter 发送、Shift+Enter 换行与设计保持一致。
- 弹窗有可访问名称、键盘关闭和焦点恢复；菜单与按钮保留键盘导航、标签和可见焦点。
- 产品确认操作使用沿用设计变量的应用内弹窗，不使用浏览器原生 `alert`／`confirm`／`prompt`。删除会话和删除工作空间保留完整影响说明，删除时展示目标名称；默认聚焦“取消”，Esc 取消，确认前不发送命令。提交期间避免重复操作，失败在弹窗内展示原因并允许重试；文件／目录选择仍使用系统选择器。
- 图像、SVG 与 Markdown 渲染保留必要许可证，过滤不可信 HTML 和危险链接。
- 删除图标统一使用用户指定的 28×28 viewBox 垃圾桶 SVG，通过公共 `DeleteIcon` 组件复用，保持 `currentColor` 填充且不叠加描边；覆盖会话、工作空间、模型、配置覆盖项及附件移除。可用按钮悬停或键盘聚焦时图标变为深红色 `#991b1b`。

视觉验收覆盖：360×800、390×844、430×932、600×960、820×1180、1024×768、1366×768、1440×900、1920×1080。页面不得出现无意的横向溢出；代码块等内容可以在自身区域横向滚动。

### 2.3 工作台行为

- 置顶会话跨工作空间统一显示，不按空间分组；普通会话列表限定当前工作空间。搜索覆盖全部置顶会话及当前空间的普通会话。点击置顶会话只切换当前打开的会话，保留侧栏选中的工作空间、普通会话列表和搜索内容；置顶条目下方显示所属工作空间路径，过长时省略并可悬停查看完整路径。会话标题栏路径、消息、输入、重命名、取消置顶和删除仍使用会话的实际归属；新建会话使用侧栏选中的工作空间。刷新分别恢复侧栏空间与打开的会话，跨空间查看不修改最近工作空间偏好；会话退出置顶区后仍保持打开，删除后回退到侧栏空间的可用会话。
- 运行中（主执行启动／运行／停止中或仍有活动子任务）和未读会话跨工作空间自动进入顶部“置顶”区，自动置顶排在空闲的手动置顶会话前；同级按最近更新时间倒序，每个会话只显示一次。未查看的自动置顶会话不开始冷却，保持在置顶区。查看后采用 5 分钟冷却回队：读取后仍保留置顶，点击、输入或重新查看续期；当前会话在可见且聚焦的窗口中打开时持续视为正在查看，最后一个前台查看窗口切换会话、失焦、隐藏或断连后才开始完整的 5 分钟倒计时。到期后回到所属工作空间普通队列，运行继续、状态点保留；同一次持续运行不因快照更新立即再次置顶，新执行或新的未读结果仍按自动置顶规则处理。手动置顶标记独立且不受冷却影响。冷却状态保存在服务端，页面刷新／服务重启后恢复；查看状态按连接独立登记，不切换其他窗口；查看保护使用实际连接状态和连接代次，订阅错误提示不会解除前台保护，重连后只恢复当前查看目标，不重发 Agent 操作。普通区仅显示当前工作空间的其余会话。状态更新不切换当前会话；行内重命名或删除确认期间暂缓该行跨组移动，操作结束后应用最新分组。
- 左侧会话标题列表隐藏滚动条，内容溢出时仍支持滚轮、触控和键盘焦点导航滚动。
- 会话列表的运行／未读状态点放在会话标题前，使用 12px 图标框、6px 实心圆点，保留现有状态色。
- 主会话首次发送时以用户输入的前 60 个字符作为临时标题，折叠空白并去掉图片占位符；纯图片输入使用图片占位名称。标题未定案且未手动命名时，通过 pi `context` 钩子向每次模型请求副本注入自报标题指令，不修改用户原文、系统提示词或持久化上下文，也不另发模型请求。只采纳主代理成功回复开头独立 `<title>…</title>` 中不超过 10 个 Unicode 字符的非空短标题；失败、中断、长度截断、代码及正文 HTML 不作为标题来源。漏报或无效时后续请求继续索要，成功后持久化定案并停止索要。手动重命名具有最高优先级，数据库条件更新阻止迟到模型结果覆盖；子会话不参与。旧库已有非默认名称保留，不自动重命名。流式／历史展示一致隐藏开头标题标签与正在输出的标签片段，不改写 pi 原始回复。标题变更通过会话局部订阅同步到列表、置顶区和当前标题，不打断输入或切换查看对象。
- 会话行通常为切换会话的按钮；双击或聚焦后按 F2 原位切换为标题输入框，不使用省略号管理入口或重命名弹窗。Enter／失焦保存，Escape／空白标题取消；输入法组合输入期间 Enter 不提交。
- 删除按钮直接位于置顶按钮旁，操作区相对整行垂直居中。两者平时隐藏且不可指针点击，悬停会话行时显示灰色图标；悬停或键盘聚焦置顶按钮时提亮，删除图标变为深红色 `#991b1b`，键盘操作保留可见焦点。操作区绝对定位，平时不预留文字宽度；显示时标题与状态文字收窄并省略长文本，避免遮挡且不改变行布局。
- 工作空间切换只改变查看对象，不停止后台 Agent。菜单展开后点击外部区域自动收起，点击菜单内部或删除确认弹窗不触发外部收起，也不阻止外部控件响应本次点击。工作空间列表沿用会话行的灰色悬停操作区及整行垂直居中布局，仅提供置顶／取消置顶和删除按钮，不显示铅笔重命名按钮；双击名称或聚焦后按 F2 在行内重命名，支持 Enter／失焦保存、Escape／空白取消及输入法组合输入保护。置顶空间优先显示，改名不改变目录路径。
- 删除工作空间需要确认，语义是从列表移除，不删除项目目录或会话历史；隐藏空间的会话不再出现在跨空间置顶列表。存在活动执行、排队任务或后台压缩时拒绝移除并提示先停止。重新选择同一目录即可恢复原工作空间标识、名称、置顶和历史。
- 服务端持久化最近使用的工作空间。新打开浏览器查看实例或 Pake 窗口时自动恢复该空间，不要求重新选择目录；同窗口刷新优先保留本窗口的有效会话位置。其他窗口更新最近使用偏好不能切换当前窗口。当前空间已移除时选择剩余有效空间，无空间则展示空态；恢复只切换查看，不启动任务。
- 新建会话即取得稳定标识，附件读取与前端内存输入状态不依赖“当前选中会话”。
- 标题前用状态图标展示与本地服务的实际连接：已连接使用实心链环图标，未连接或连接失败使用实心断链图标，两种图标均水平放置，保留成功／警告状态色；悬停及辅助技术可读取状态；已连接不代表模型供应商调用已验证。
- 主会话空闲而子任务仍运行时，侧栏仍展示活跃任务状态。
- 子任务活动状态图标持续转圈，仅旋转内部圆弧，不旋转底色或状态文字；退出活动状态后停止。系统开启减少动态效果时保留该执行反馈，放慢为 2.8 秒一圈（默认 1.4 秒）。
- 未读状态与运行状态分开保存，不通过最后一句回复文本推测状态。侧栏使用活动优先规则：停止中、初始化、主执行（含重试／压缩恢复）、活动子任务优先于未读；有活动且未读时保留未读事实并在辅助说明中显示。主执行结束但子任务仍排队或运行，不显示整个会话已结束。连接中断保留上次已知状态，标记待同步。
- 结果使用 `resultVersion/readVersion`，`unread = resultVersion > readVersion`。主执行终态与子任务不可变结果分别按 runId/resultId 幂等计数；流式输出、重试倒计时不生成终态未读。`session.read({throughVersion})` 只单调确认已展示版本，旧窗口的确认不能清掉新结果。客户端须在可见、聚焦、消息区滚到底且未被遮挡、当前连接的消息及运行状态已同步、对应任务卡或通知已渲染时确认；恢复可见、聚焦和重连后重新判断。打开会话只影响置顶冷却，新输入、后台通知唤醒及模型读取结果不代表用户已读。
- 删除会话需要确认；先强制终止拥有的活动 Agent 执行，不增加 Agent 清理确认步骤，不因清理待核实记录阻塞删除。
- 删除会话不删除项目目录或 Agent 已经产生的项目文件。
- 会话初始化信息展示实际模型、工作目录与加载成功的能力；加载失败显示原因，不列出虚构工具。「会话环境」展示当前／最近一次加载的真实 pi「系统提示词」文本，不以资源清单、应用模板或推测内容代替。新会话首次发送初始化前显示未初始化占位，不伪造提示词；历史环境快照兼容缺失 `environment.systemPrompt` 字段，提示下次执行加载。
- 输入框下方工具栏按“批注、子代理、压缩”顺序成组显示，批注开关使用 Lucide 官方 Message Square Text SVG，18px 显示尺寸与 2px 圆角描边，保留来源与许可证。默认关闭；开启后以细节为批注范围：拖选只引用选中的字符，点击正文定位当前句，列表限定单个条目、表格限定单元格、代码限定单行；仅高亮对应文字，不整块染色，附近显示批注浮层，添加批注按钮使用用户提供的对话气泡加号 SVG，去掉透明占位路径的描边与按钮底框，紧跟当前段落、列表项、单元格或代码行的文字末尾定位，随换行与尺寸变化更新位置；已保存的意见以行旁编号定位，支持编辑与删除；跨越不同正文块或回复的选区明确提示缩小范围，不替换成其他引用。切换开关保留正文、图片与代码组件状态，不重复加载图片；编辑批注文字只更新编辑器，不重新解析会话正文；不要求逐段批准，也不建立审批或解决状态。流式正文、思考和工具过程不作为批注目标。
- 批注与正在编辑的意见按查看实例、工作空间、会话保留在前端内存；关闭模式只隐藏相关界面，切换会话后可继续，刷新／关闭页面不承诺恢复。底部提供待发送数量、查看全部与统一发送；每条提交携带回复标识、内容块位置、不可变引用原文与意见，引用按数据说明。发送沿用普通消息／运行中 Steering 受理与失败恢复，不覆盖普通输入草稿或携带其中附件；明确失败自动合并恢复到输入框，未知状态不自动重发。恢复仅对实际绑定附件或图片的冲突编号重编号，引用原文中未绑定的 `[fileN]`／`[imagN]`／`[folderN]` 保留字面值。单条引用最多 6,000 字、意见 2,000 字，整批沿用消息 12,000 字上限，超限明确提示，不截断或拆分发送；失败／撤回恢复与当前输入合并后若超限，保留完整内容并显示字数，禁止通过发送按钮或 Enter 再次提交，缩短后恢复发送；停止执行和原生重试不受输入长度影响。来源因压缩离开展示区后仍可在列表编辑和发送保存的引用。
- 主／子输入框占位文案为 `Ask axiom…`，不因此改变中文输入与组合输入行为。运行中的圆形停止按钮保持原尺寸与底色，内部方块为 10×10 px、深红色 `#991b1b`，悬停时保留方块颜色。
- 上下文占用使用从顶部顺时针填充的圆环，与百分比共用有效 Token／容量计算，限制在 0–100%。未知容量显示虚线与“—”，不显示虚假进度；使用可访问进度条语义，未知时不提供数值。

新增工作空间直接由本地服务打开系统文件夹选择器，不要求手动输入路径。选好目录后默认授予项目访问权限，直接登记／恢复工作空间并创建会话，不再展示路径确认或授权弹窗；取消选择不创建工作空间或会话。选择及打开期间避免重复提交，失败显示明确错误并允许重试；旧服务返回空白 404／405 时提示重启本地服务，不直接显示 JSON 解析异常。浏览器文件选择 API 不能可靠提供服务端项目绝对路径，不能用上传文件替代工作空间目录选择。所有系统文件／目录选择复用统一打开组件：`kind=file|folder|mixed`、`multiple`、标题与初始目录；工作空间用目录单选，主／子附件用混合多选。Windows 使用 Explorer `IFileOpenDialog`，macOS 使用 `NSOpenPanel`，Linux 使用 GTK 3 文件选择器（Python 3／PyGObject）；无图形桌面或缺少依赖时明确说明。浏览器与 Pake 共用本地服务，不各建实现。各用途共用一个活动窗口，取消／超时／退出后等待拥有的宿主进程退出才释放位置；服务端统一复核真实绝对路径、文件／目录类型、数量和重复项，工作空间授权及附件归属仍按各自用途校验。

## 3. 系统结构

```text
浏览器 / Pake
       │ HTTP：页面、附件、资源
       │ WebSocket：命令、回执、状态、输出
       ▼
Axiom 服务
  ├─ 工作空间与会话归属校验
  ├─ Agent 进程管理、任务调度、结果通知
  ├─ pi 模型配置与认证管理
  ├─ SQLite、会话索引与附件
  └─ 独立 Agent 工作进程
        ├─ 一个 pi SDK 会话
        ├─ 对应工作目录与明确的会话文件
        ├─ pi 基础工具和默认授权加载的项目扩展
        └─ 主 Agent 的四个子任务工具
```

### 3.1 技术选型

- 前端：React、TypeScript、Vite。
- 服务：Node.js、TypeScript、WebSocket。
- Agent：独立 Node.js 子进程承载 pi SDK，会话通过公开 API 创建和操作。
- 存储：SQLite 管理应用数据，pi JSONL 保存对话上下文。
- 桌面：Pake 作为同一 Web 产品的外壳，不另建一套桌面业务代码。
- 依赖锁定到实际验证过的组合；升级依赖需要重新执行模型、会话、工具和取消验收。

不同时维护另一套 Agent 运行后端，不解析终端输出模拟事件，也不修改 pi 依赖源码。

### 3.2 职责边界

| 部分 | 负责 | 不负责 |
| --- | --- | --- |
| 前端 | 页面、交互、草稿、局部订阅与展示 | 直接读取凭据、调用供应商 API、决定任务归属 |
| Axiom 服务 | 管理数据、进程、命令校验、结果通知、配置发布 | 重写模型协议、推理循环和上下文压缩 |
| Agent 工作进程 | pi 会话、工具执行、事件转换 | 操作其他会话状态、直接管理应用数据库 |
| pi 模型运行时 | 模型目录、协议适配、认证与模型请求 | Axiom 页面和任务列表 |

会话与子代理是 pi 的薄封装：发送请求优先复用归属、配置与持久文件仍一致的保活 pi 工作进程，冷启动才按绑定 JSONL 打开已有会话或创建首次会话；同一真实会话同一时间只允许一个活动工作进程和一个执行者。pi 绑定的 JSONL 是唯一上下文恢复来源，不用 SQLite 请求记录、草稿或另一份对话副本重建上下文。后台压缩允许另一个只处理独立快照的进程，不成为原会话的第二个写入者。不同会话可以并行。同一应用数据目录只允许一个服务进程持有管理锁，进程退出时锁由系统释放。成功执行结束后进程进入独立空闲 LRU，最多 10 个，15 分钟未使用淘汰，初始化满 15 分钟的进程也在空闲时释放，防止持续复用无限延长外部资源陈旧窗口；运行中的进程不参与空闲淘汰。失败、停止、撤权、关闭与不兼容配置淘汰进程。恢复必须指定对应会话文件，不使用“最近会话”推断归属。

## 4. 标识、配置范围与隔离

### 4.1 标识定义

| 标识 | 含义 |
| --- | --- |
| `workspaceId` | 已确认项目目录的稳定标识 |
| `sessionId` | 一个主会话或子会话 |
| `parentSessionId` | 子会话所属的主会话 |
| `taskId` | 一条可持续追问的子任务链，关联固定子会话 |
| `runId` | 一次执行；继续追问创建新的执行标识 |
| `resultId` | 一次执行的最终结果标识，结果发布后不可变 |
| `requestId` | 一次用户操作的幂等标识，重传必须复用 |

工具调用中的父会话和工作空间从注册工具时绑定的运行环境获取，不允许模型通过参数冒充其他会话。

### 4.2 配置范围

- 应用级：模型供应商与认证、子代理默认模型及思考等级、子任务并发和工作时限、模型收藏、新主会话默认模型及思考等级、连接设置。
- 工作空间级：规范化目录、显示名称、项目授权、置顶、移出列表状态、会话集合；最近使用的工作空间标识作为应用级持久化查看偏好。
- 会话级：模型选择、思考等级、会话文件、运行状态。
- 查看实例级：当前选中的工作空间和会话、菜单打开状态、焦点、滚动与折叠状态。
- 会话未发送输入：文本及所选附件仅由前端内存按查看实例、工作空间和会话维护，切换会话保留，父／子窗口及不同标签页互不覆盖；刷新或关闭页面不承诺恢复。不维护服务端会话草稿，不提供草稿恢复或会话请求人工核实界面。上传附件文件的存储不构成草稿恢复。模型配置草稿仍按自身契约处理。

应用级模型服务可以共享，但 Agent 上下文、当前模型选择和消息队列不能跨会话共享。不同标签页的导航不互相切换。

### 4.3 服务端约束

- 目录经规范化与实际路径解析后登记，处理符号链接及平台路径大小写规则。
- 请求执行前校验工作空间、会话、子任务和执行的完整关系。
- 配置、任务状态与事件更新校验当前执行标识，丢弃不匹配的迟到回调。
- 消息、附件读取和模型确认均使用操作发起时的归属，不在完成时读取当前 UI 选择。
- 进程管理器只停止自己创建并记录的进程，不按模糊进程名批量终止。

上下文隔离不是文件系统沙箱。用户选择目录打开工作空间时默认授予编码工具项目访问权限，不额外弹窗确认。不同工作空间不会由 Axiom 误路由，但任意命令仍可能访问授权用户能访问的其他路径。

同一工作空间的 Agent 共享文件；子代理仅只读调研，所有修改及命令验证由主代理执行。主代理应用子代理建议前应重新读取当前文件，避免调研期间文件变化导致建议过时。多个主会话仍可能并行修改；原文不匹配的编辑必须失败并重新读取，不能宣称存在完整文件事务或自动回滚。

## 5. 模型配置与认证

### 5.1 唯一运行配置来源

Axiom2 默认复用终端 pi 的模型配置、模型目录缓存和认证存储（通过 getAgentDir()，可用 AXIOM_PI_DIR 覆盖），显式向各运行时传入文件路径。保存和退出登录也会影响终端 pi；应用设置、资源和会话仍独立。旧独立模型／认证文件不自动覆盖共享配置。

- `models.json`：pi 模型、供应商及覆盖配置。
- `auth.json`：由 pi 原生认证接口管理。
- `settings.json`：需要的 pi 原生设置。
- SQLite 不存第二套模型定义或明文凭据；模型收藏仅保存模型标识。

界面是这些能力的编辑入口，不建立自己的供应商 SDK、模型 HTTP 客户端或 OAuth 交换流程。

### 5.2 模型服务页面

保留供应商列表、搜索、连接配置与模型配置页签、行内编辑、覆盖项编辑、未保存标记、顶部保存与放弃修改。

- 采用顶部统一保存的页面中，“完成编辑”仅暂存并结束行内编辑，顶部“保存”才发布配置。顶部保存必须包含尚未收起、或被连接页签隐藏的行内编辑；无效／重复 ID 保留输入并返回模型表单，不能漏存。完成、保存、切换供应商复用同一草稿合并规则。
- 模型 ID 与显示名称使用两列布局，窄屏按设计折为单列；思考等级多选占满行宽，维持选中、悬停、键盘焦点与可访问分组说明。
- 模型名称与 ID 分别提供复制动作，复制完整原值而非截断文本；显示成功／失败反馈，窄屏与键盘操作可用。复制不修改配置。
- 切换供应商先合并有效行内编辑并保留其他供应商草稿；无效编辑阻止切换。离开模型服务页、刷新或关闭页面直接进行，不弹出页面离开确认或浏览器未保存提示；未保存草稿和临时密钥不自动保存，返回时读取已发布配置。主动放弃编辑仍明确确认。
- 密钥字段支持替换与显式清除；掩码和空白占位不能被误保存为新密钥。保存并重读成功后清空临时明文输入，以占位掩码和“已保存到本地”状态表达持久化结果；OAuth 凭据单独说明。顶部保存区域持续展示结果，错误不能只放在页尾；失败保留草稿。连接页展示当前 `models.json` 与 `auth.json` 的实际路径，避免与旧独立目录混淆。
- 保存成功不等于远端认证或模型请求成功；分别展示配置有效性、认证状态与运行错误。
- 预置供应商信息只能作为待填写模板，不自动变成可选模型。内置模型应保留 pi 原生能力与计费元数据，不能因加入配置列表被无关的自定义默认值覆盖。
- 单独认证入口须先保存或放弃配置草稿。认证归发起连接所有，其他连接不能回答或取消；断线、显式取消或超时终止流程，不自动重新登录。仅展示完成步骤所需的授权链接、设备码与输入提示，不广播供应商任意进度／错误文本或保存认证输入。

### 5.3 UI 到 pi 的字段映射

| 界面内容 | 处理规则 |
| --- | --- |
| 供应商与模型 ID | 使用 pi 支持的 provider/model 标识；避免使用显示名称作为关联键 |
| 接口地址、协议 | 映射 pi 的 `baseUrl` 与支持的 API 类型 |
| 模型名称与能力 | 使用 pi 的 `name`、`input`、`reasoning` 等支持字段 |
| 思考等级 | 配置页可多选模型支持的等级，会话菜单单选本次使用的等级；通过 pi 支持的模型配置表达，不直接写入原型自定义字段 |
| 请求头覆盖 | 使用 pi 支持的 headers 配置，校验非法字符和重复键；敏感值脱敏 |
| 请求体覆盖 | 仅映射当前 pi 支持的覆盖字段和协议能力，例如受支持协议的 `samplingParams` |
| 供应商级通用请求体项 | 仅在 pi 能表达时保存；需要落实到各模型时使用 pi 支持的模型字段，不自建请求拦截层 |
| 模型级覆盖 | 在 pi 支持的规则内优先；不支持的字段应报错或禁用，不能保存后静默忽略 |

保留设计中的编辑布局，但不能为匹配示例文案伪造 pi 不支持的运行能力。等级配置以 pi 的 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` 为边界；界面的 `none` 需要转换为适用的 pi 语义。使用受支持的 `thinkingLevelMap` 表达限制，不把多选结果直接作为一次请求的思考等级。空选或禁用思考须通过模型能力校验；不能让不允许关闭思考的模型产生虚假 off 选项。界面中的“自动”“开关”等选项也必须映射到实际能力，否则禁用并说明原因。

### 5.4 保存与生效

1. 前端提交配置草稿和读取时的配置修订标识。
2. 服务端检查修订标识、字段、重复 ID、URL、覆盖值与 pi 配置合法性。
3. 同一应用配置写入串行执行，避免多个页面互相覆盖。
4. 模型配置在同目录写入临时文件，验证后原子替换目标文件；保存前失败保留原文件。
5. 凭据保存调用 pi 原生认证能力，不自行拼接或覆盖凭据文件；API Key 登录完成后，以新运行时重新读取本地凭据，确认对应供应商存在 API Key 凭据后才报告成功。
6. 刷新 pi 目录，计算可选模型，向会话和配置页发布更新。
7. 所有步骤完成才显示成功；分别报告配置写入、凭据变更或目录刷新失败。

配置文件与凭据文件不是跨文件事务。凭据已经改变但目录刷新失败时，应报告实际状态并重试同步，不盲目重做登录，也不假称全部回滚。配置发布／认证启动等外部操作先持久化请求哈希和受理状态，结果仅保存脱敏字段；重启时未确认完成的操作标为待核实，不自动重做。部分失败或回执不确定时暂停再次发布，显式重新读取并对账后才允许继续。读取到损坏配置时不得用空配置覆盖。

配置更新不得重建正在输入的表单。活动运行继续使用已经确认的模型配置；涉及认证撤销或删除的操作按删除流程处理。空闲时通过 pi 公开接口刷新、重设模型或重建同一持久化会话，不能仅刷新界面目录却继续使用过期运行对象。

### 5.5 会话模型菜单

```text
可选模型 =（明确配置的模型 + 未单列模型的供应商目录 + 已登录供应商目录）∩ pi 判定可用的模型
```

- 配置但没有所需认证的不显示；pi 已登录供应商可直接使用。
- 仅配置供应商时使用其 pi 原生目录，不要求重复逐个添加内置模型；收藏不能绕过认证。
- 删除模型后清除相关收藏，不自动选择其他模型替代。
- 列表为空时禁止发起模型请求，引导进入模型配置。
- 服务端执行同样的允许范围校验，不能通过直接请求绕过菜单限制。
- 能列出不代表远端密钥一定有效；实际调用失败如实展示。
- 菜单沿用工作台深色视觉变量，模型名称与供应商分行显示，长名称允许换行；选中标记和收藏操作保持独立。搜索无匹配时显示明确空态，模型服务入口固定在底部。
- 思考等级使用面板内平铺的单选项，不使用原生下拉菜单；仅展示当前模型支持的等级，支持键盘焦点与方向键切换，窄屏自动换行。底部明确显示“取消／确认”，提交中显示“保存中…”并禁止重复确认；取消或 Escape 关闭后恢复入口焦点。

未打开工作空间时提供打开入口，不展示无法确认的模型菜单；已打开空间但未选会话时，确认模型先创建有稳定标识的会话，再保存选择。取消菜单不创建会话。

菜单选择为本地草稿，确认后等待服务端回执。主会话确认成功时，同时将供应商、模型 ID 与思考等级保存为应用级默认值，无需另行保存；新建主会话在创建时复制上次确认的选择，跨工作空间和服务重启后仍生效。默认值仅保存选择标识，不保存第二套模型定义，不覆盖已有会话。升级时若默认值为空，从现存主会话恢复最近确认的选择（优先按成功回执顺序，旧数据无回执时按选择记录顺序），排除子会话，不按消息或重命名更新的会话时间推断；已有默认值不覆盖。未保存过选择时保持未选模型。默认模型不可用时保留原选择，发送前要求重新选择，不自动替换。取消菜单或确认失败不改变默认值；子会话选择及默认子模型设置不改变应用级默认值。

运行期间允许选择下一次执行的模型；当前执行不因菜单选择被中断或半途更换模型。显示当前执行模型与已确认的后续选择。

子代理默认模型与思考等级为应用级全局偏好；未单设时在创建子代理时继承主会话选择。选择后自动保存，所有工作空间、会话及窗口共享，刷新和服务重启后保留；立即用于之后的新委派，不中断当前模型请求，不覆盖已有子会话的独立选择。升级时一次性迁移旧会话记录中最后存储的非空默认子模型；明确清除为继承后不会重新迁移。

全部子代理设置集中在输入框下方工具栏的分支节点图标内，删除原独立默认子模型块及配置概览的预算块。批注、子代理、压缩图标按此顺序且不拆组；可容纳时与用量图标同排并靠最右侧，容纳不下则整组换行靠左。设置浮层提供模型／思考等级、并发数和工作时限；数值输入完成后按 Enter 或失焦自动保存，错误明确显示且不写入无效值。通过 `task-preferences` 独立订阅同步全局设置，`task.preferences.get/save` 读取／局部更新 `{selection,budgets}`；局部更新不会覆盖其他窗口未修改的字段。

### 5.6 删除与退出登录

**删除模型或供应商必须执行 pi 的供应商级退出登录流程，不能只删除前端列表。**

- 模型编辑中的删除先进入草稿，保存并确认影响后执行；供应商删除使用独立确认操作。
- pi 的退出登录作用于供应商，不是单个模型。删除一个模型时，确认框必须说明同供应商其他模型也可能需要重新认证。
- 该供应商存在活动执行、排队子任务或后台压缩时，先说明影响，经用户确认后终止受影响的执行并取消排队任务；不能在拥有的执行仍活动时宣称删除完成，也不增加 Agent 清理确认步骤。所有类型先检查确认条件，不得先停止其中一种再要求确认其他类型。
- 先阻止受影响供应商的新请求，再调用 pi `ModelRuntime.logout()`，移除运行时认证覆盖及受管理的备用认证来源，移除目标模型／供应商配置并刷新目录。
- 删除单个模型可以保留同供应商其他模型的定义，但不能偷偷保留或重新注入刚退出的凭据。
- 外部环境变量等不由 Axiom 改写；如果它们仍能提供认证，应如实显示认证来源。已删除模型仍由明确配置范围排除，不能重新出现。
- 会话记录保留原模型标识用于查看，但发送前必须重新选择可用模型。
- 失败时保留错误和可重试入口，不将部分完成显示为完全成功。

### 5.7 凭据安全

- 密钥和 OAuth 令牌只进入服务端 pi 认证存储，不写浏览器持久存储、SQLite 消息、日志或附件。
- 前端仅展示是否已配置、认证方式和必要的脱敏信息；不回传已保存明文密钥。
- URL、请求头和配置错误信息均执行敏感数据脱敏。
- pi 支持的命令型密钥及请求头解析属于可执行配置，新增时须在发布入口明确授权；单独登录提示不直接接受命令型密钥。不能自动执行从不可信项目或页面导入的命令。
- 不承诺应用自带系统密钥库或磁盘加密；配置目录使用当前用户权限保护。

## 6. 主 Agent

- 每个主会话绑定自己的 pi JSONL、工作目录和模型选择；发送请求复用有效保活进程，冷启动时已有上下文只从绑定 JSONL 恢复。运行中的输入使用 pi 原生消息机制，不自建上下文恢复层。空闲复用前校验模型选择、冻结模型配置、认证与设置文件和会话文件身份；同时复核缓存进程的配置快照仍可读且与保活时一致，缺失或改变时先关闭旧进程，再使用本轮新快照和绑定 JSONL 启动。其余身份不一致同样先关闭旧进程再启动。IPC 按 runId 隔离；启动等待发送回调（最多 10 秒），回调成功仅表示传输受理，不表示消息已消费，`send()` 返回 false 仅表示背压。调用发送前的准备失败保留脱敏原因并返回确定未发送；调用发送后的同步／异步异常、确认前退出或确认超时按结果不确定处理，不自动重发，等待拥有进程退出并且只结算一次。复用前完成配置校验及新快照清理，失败时保留旧进程的池归属，不产生失管所有者。执行结束与进程退出分离，仅在工作进程确认空闲后结算并释放执行名额。等待旧进程退出的启动在首次等待前登记 pending，计入 active／stop，停止使启动 epoch 失效并等待收尾；命令入队前捕获 epoch，防止越过配置锁期间的停止。已落盘的本轮终态才触发结算回调，存储失败不保活、不发送成功型回调。空闲淘汰先发 shutdown，两秒未退出再强杀。常规指令、扩展、技能、提示文件身份变化禁复用；外部包与符号链接目标允许冻结到最长复用期限，资源检查超限或不可读时保守冷启动。
- 用户提交立即生成前端内存气泡并清空对应输入，显示发送／受理／失败／不确定状态；接收层按请求／输入标识消除占位，不依赖消息组件挂载、不以文本匹配，追加撤回按确认 ID 移除。待确认输入及撤回 ID 保留在独立内存中，不随展示缓存淘汰。当前会话定期只读核实：agent.inputs 每次最多 128 个 ID，验证归属，仅查询完整原生分支的消费身份和已保存回执，不返回压缩前正文；request.get 核实原撤回回执，确认成功才合并恢复草稿且至多一次，未知不重做。确认发送失败时自动移除占位并将原文、附件合并回发起会话的输入框，同时显示具体原因；无需点击恢复按钮，不覆盖继续输入或其他会话，重复回执不得重复回填，已消费输入不得回填。断线或超时显示正在确认发送结果并只读核实；断线不自动重发。
- 前后端展示消息缓存均按会话采用最多 5 个的 LRU。客户端淘汰无订阅会话，活动视图受到保护，已退订迟到快照不入缓存；同时展示超过五个会话明确报错。每会话一个 messages 集合订阅，首次完整快照、后续逐消息更新，压缩／结算发送替换快照删除失效 ID；客户端内部仍按消息 ID 独立通知组件，订阅错误不可静默吞掉。展示从 pi `buildSessionProjection().entries` 选择当前压缩边界并应用原生 `context_edit`，重试排除的失败尝试不进入当前视图；实时重建与重新打开保持一致。不分页、不提供历史游标或 thread.history；只显示最新压缩摘要及保留、后续消息，原始 JSONL 不删除。压缩卡片采用紧凑图标、分支内编号与 30 字内压缩短摘要、前后 Token 估算和展开箭头的分层布局，窄屏时估算换行；完整摘要按需展开并使用与聊天一致的 Markdown 渲染，支持标题、列表、强调、引用、表格与代码块，加载完整文本后保持相同排版。仅在展示时移除摘要中独立成行的 `<axiom-summary>` 内部短摘要标签（包括 pi 分段交接内的标签），保留代码示例中的字面量，不改写原生摘要；短摘要仅从独立 HTML 标签行提取，忽略行内引用、代码块和纯标点占位符，多段摘要优先采用最后一个有效短摘要；缺少短摘要时显示“上下文已压缩”。侧边窄浮动栏提供到顶部、上一屏、下一屏、到底部，屏滚按可视高度 85%，禁用不可滚动方向，支持键盘、窄屏和减少动效。
- 主／子输入框统一：空闲时 Enter 发送，运行时 Enter 将新输入追加到原生 Steering 队列，Shift+Enter 换行，组合输入及文件补全期间不误发送。沿用原停止按钮，不增加追问、模式切换或撤回按钮；待执行队列以紧凑文本显示在输入框上方。
- Steering 发送后先在输入框上方待执行区展示，不立即产生会话气泡；发送中、已受理及状态未确认均留在待执行区，确认失败时自动回填输入框并移除占位。只有 pi 安全边界实际消费消息后，才通过正式消息投影进入会话，消费身份去重；普通空闲首发保留即时反馈。
- 助手原生思考和开头 `<thinking>…</thinking>` 块统一收入执行过程卡片，内部使用独立折叠思考块，不显示左侧竖线。标题使用斜体与 Lucide Brain 大脑图标（24×24 viewBox、2px 描边，沿用 14px 显示尺寸）：实际思考生成时仅显示动态三个点，不显示 `thinking` 或“正在思考”文案，三个点在固定宽度内依次跳动；执行过程收起时的思考摘要使用相同三点动画；进入正文／工具调用或结束后显示 `thought`，移除三点并停止动画；展开正文斜体且统一使用正常字重（400），Markdown 强调、标题、表头和代码高亮也不加粗，代码保留等宽正体。流式更新不重置展开状态，减少动态效果时静止；用户消息、正文引用和代码示例中的标签不转换，原生会话不改写。
- 输入框聚焦时 500ms 内连按两次 Esc，撤回服务端确认尚未消费的可编辑输入，恢复原文及附件到该会话输入框；单按、长按及组合输入不触发。文件补全的 Esc 关闭优先，不计入双击。撤回不停止 Agent、不改写已进入上下文的历史、不回滚文件、不移除内部子任务完成通知。以工作进程真实队列为准处理与消费的竞态；迟到回执仍归发起会话，恢复时合并最新输入且重编号冲突的附件引用，不覆盖继续输入的文字。
- 主代理基础工具使用 pi 的 read、edit、write 和适用平台的命令工具。主代理的项目本地扩展、技能和设置等资源默认授权，首次发送初始化时即按 pi 规则加载；不提供额外的项目资源授权按钮、确认弹窗或 `agent.trust` 命令。子代理只使用第 7 节规定的只读工具与受限资源。
- 主／子输入框左侧「+」直接打开本地附件选择窗口，不显示文件／图片／文件夹选项菜单。同一窗口支持文件、图片与文件夹混合多选；Windows／Linux 混合模式在原生窗口内提供“选择所选项目”和“选择当前文件夹”，原“打开”保留文件打开与目录导航；macOS 使用 NSOpenPanel 的文件／目录混选。保留各系统原生导航、搜索和键盘操作，不自制文件列表。服务端取得真实绝对路径，选择前后校验工作空间授权及会话归属。取消不修改输入，选择期间防止重复打开；“+”在原 44×44 px 位置切换为取消图标，保留“取消选择”可访问名称，选择状态放在输入框上方；不在窄图标列追加文字按钮，不改变输入框的宽高。设置独立等待上限，断线／超时／退出关闭拥有的选择器。Windows 服务接受请求前准备 STA 无控制台原生宿主，点击时直接启动已准备程序，不启动 PowerShell 或重复编译；编译器使用系统绝对路径，产物在服务私有临时目录，正常退出删除。以操作系统窗口实际可见性测量打开等待，不以控件初始化或进程启动代替。
- 每份草稿最多 50 个附件。文件、图片、文件夹均向 Agent 提供路径，不内嵌文本内容，不自动读取图片，不递归展开或上传文件夹；空文件夹也可引用，不改变工作空间。选择窗口以当前工作空间为起点，显式选择可引用当前用户有权访问的其他本地路径；这不是文件系统沙箱。
- 在光标／选区插入 `[fileN]`、`[imagN]`、`[folderN]` 占位符，上方标签显示编号与名称、悬停显示路径，可逐项移除。移除同时清除该编号的正文引用，不重排其他编号；手动删除占位符不自动删除附件。异步选择或读取不能覆盖后续输入或其他会话，选择期间不发送半成品。路径映射只在后台作为引用数据提供给模型，不能提升为系统指令；实时及历史消息正文隐藏生成的映射说明，保留用户正文与占位符。路径图片不等同于已发送视觉内容，模型须按需调用工具读取，不能宣称已理解图片或其他格式，也不因引用图片路径而要求视觉模型。
- 主／子输入框仍可粘贴截图；剪贴板没有原始路径，单张最多 10 MiB，以原始字节保存到应用数据目录的工作空间／会话限定附件目录后建立 `[imagN]` 路径引用。服务端随机生成存储名，原名称不能控制磁盘路径。待发送图片标签可点击或经键盘打开预览，支持关闭按钮、Escape、遮罩关闭及触发焦点恢复，不改变或发送草稿；切换会话或移除附件关闭对应预览。预览按需读取本会话上传目录内的图片，或本次服务运行中由原生选择器明确登记给该会话的图片路径；拒绝任意路径、越界符号链接、非图片和超过 10 MiB 的文件，不在普通消息订阅中广播字节。已发送消息中的图片使用紧凑浅蓝色图标＋编号按钮（如 `imag1`），多个附件可换行，点击热区至少 44 px，悬停显示编号与名称，点击或经键盘打开同一预览窗口；不展示大尺寸元数据卡片，不自动加载缩略图。实时与历史路径图片沿用上述授权限制，外部选择路径的授权不跨服务重启，读取失败在预览中明确显示；旧原生图片按工作空间、会话、消息与图片编号从绑定记录读取，字节不进入持久回执。预览不发送消息，关闭后恢复触发焦点，切换会话关闭预览，迟到响应不重新打开窗口。普通文本粘贴保持原行为；失败回滚本次占位符，不发送半成品。移除引用不会删除原文件或已上传副本，副本当前无自动回收。未发送输入仅保留在前端内存，切换会话保留，刷新不承诺恢复。
- 助手回复的复制入口位于正文右上角，采用 16 px 图标与 44×44 px 点击区域，不再显示底部独立按钮行。桌面默认隐藏，悬停该条回复或键盘聚焦时显示；触屏／粗指针设备常显。正文右侧固定预留空间，流式时也保持相同宽度，显示／隐藏和复制反馈不推动正文。仅在原有可复制条件下显示（非过程块、非流式且正文非空）；成功后显示勾号约 1.5 秒再恢复，失败显示可重试提示，状态供屏幕阅读器播报。复制保留完整 Markdown 原文，截断消息按归属获取全文；用户消息和工具过程不新增复制入口。
- 助手回复中的 Markdown 图片引用支持本地绝对路径（Windows 盘符或 POSIX 路径），接近可视区域时按需显示缩略图，点击／键盘打开现有放大预览；关闭后恢复焦点，引用或会话切换时卸载预览、忽略迟到结果。服务端只从绑定会话的助手消息解析真实图片 token，并在读取前后核验归属与引用；客户端不能提交任意未引用路径，用户正文、代码示例、普通链接、HTML 不形成读取授权。沿用 PNG/JPEG/GIF/WebP、10 MiB、文件签名与符号链接／硬链接检查；不加载远程、UNC、设备路径、SVG 或 data URL，不把图片字节写入消息快照或持久回执。历史消息在文件仍存在且授权有效时可读取；缺失、损坏、超限显示原因及显式重试。引用不会复制源文件，临时目录被清理后图片可能失效。
- 输入 `@` 调用 pi 的原生文件补全提供器，以绑定工作空间为起点；保留 pi 的路径、引号与目录补全规则。↑↓ 导航、Enter／Tab 插入、Escape 关闭，补全窗口打开或加载中 Enter 不发送；中文组合输入不干扰。缺少 fd／fdfind 显示可恢复错误，不自动下载或运行项目内同名程序。搜索只读、不启动 Agent、不产生执行回执；选择结果插入路径引用，由 Agent 按需读取。
- 会话内容中的展开块（会话环境、思考、工具过程、压缩摘要、子任务操作与原始记录）在滚动时将标题／折叠栏吸附于所属滚动区域顶部，滚过该块末尾后自然退出，返回原位置时恢复正常布局；仅展开期间吸顶。每次从收起切换到展开时，从该块内容开头开始阅读，重置块内输出区域的纵向与横向滚动位置，不恢复上次阅读位置；展开动作优先于会话自动跟随底部。已经展开后的流式更新不重置用户阅读位置。嵌套展开时按外层标题的实际高度依次排列，窄屏换行和流式更新后自动调整，不互相遮挡，始终可用鼠标或键盘收起。标题采用不透明背景，吸顶时距所属滚动区域顶部保留 8px 间距并显示完整上边框与顶部圆角，避免贴边裁切观感；嵌套标题共用该顶部间距，不逐层叠加。主／子会话各自独立，不覆盖输入区、导航或其他窗口；子窗口的执行与交付区域同样在自身滚动区域内吸顶。
- 仅展示 pi／模型实际提供的思考内容，不生成补充的“思考过程”。
- 连续工具调用、纯思考、子任务调用及子任务完成通知合并为一个默认收起的执行过程卡片；纯思考没有相邻工具时也使用过程卡片。工具结果归回对应调用，不另起消息。用户消息、普通助手正文、压缩卡及失败／停止消息是分组边界；独立正文所附思考与调用仍收在该消息内的过程卡片。`delegate`、`read_result`、`append`、`cancel_task`（包括 `functions.` 前缀）在过程内部保留专用卡片，参与外层调用数和当前操作摘要，不重复生成普通工具行；思考与通知不计入工具数。内部保持调用顺序、子会话入口、不可变结果详情和错误反馈。组以首条消息稳定 ID 标识，流式更新不重置手动展开状态。收起固定两行：第一行左侧为状态图标、中间为“执行过程”及调用数、最右侧为展开箭头；第二行独占一行按消息及调用顺序显示最近的工具、思考或子 Agent 摘要，不因旧结果迟到而回退。展开后隐藏第二行摘要，标题及内部详情不重复展示当前操作。状态图标使用 Phosphor 官方 Planet／Seal Check SVG，22px 显示尺寸，保留来源与 MIT 许可；运行时为绿色轨道图标与柔和呼吸光晕，确认完成后为绿色花瓣徽章勾选。工具调用、子任务及子任务通知的失败或停止仅在内部对应项展示，不将外层过程卡片置为失败或停止；外层失败与停止由助手消息自身的执行状态决定，未知状态单独标识，不把缺少结果当成成功。子任务仍在运行时外层保持运行态，减少动态效果时静止。新调用到来时，摘要在固定高度的一行中向上滚动切换，旧项滚出、新项滚入，不循环播放旧调用；减少动态效果时直接切换。工具使用与 Axiom 一致的文件、编辑、写入、终端、搜索、网页、子任务线性图标，搭配英文工具名称（如 `read`、`edit`、`write`、`bash`）及关键路径／命令、行号或替换数量；名称去除 `functions.` 前缀，不翻译成操作描述，读取图片仍显示 `read`。`powershell` 在摘要与工具行中以 `bash` 名称展示，仅作为显示别名，不改变底层执行工具；原始详情保留真实工具名。摘要与展开行中的工具名称和图标统一使用与路径／命令一致的白色前景（`--fg-2`），包括未知扩展工具；不再按工具种类区分颜色。路径、命令与结果预览保持原有文本颜色。子任务专用卡片使用 Lucide 官方 SVG：委派为 Network 分支节点、读取为 Inbox 收件盒、补充／追问为 Message Square Plus、停止为 Circle Stop；统一 24×24 viewBox、1.75px 圆角描边和 18px 显示尺寸，保留来源与许可证。子任务专用卡片的工具标题与图标同样使用白色前景，思考块标题与大脑图标使用相同前景色。助手自身执行失败时保留过程块边框提示；单次工具失败仅保留对应工具行的错误摘要，右侧耗时通过颜色表达结果，状态文字仅供悬停与辅助技术读取，不将无结果误报为成功。主／子会话消息列表末尾、输入框左上方不显示独立运行状态行。工具行与子任务卡片的运行指示使用绿色呼吸光晕，减少动态效果时保留静态绿色状态。展开过程后显示思考、子任务卡片、任务通知和各次普通工具调用的折叠行；普通工具行含图标、名称、关键路径／命令与错误摘要；右侧只显示实际可得耗时（未知为“—”），成功为绿色、失败为红色，不显示状态文字、呼吸指示或加减号；每次调用默认收起，单独展开后才显示完整原始参数与执行输出，展开行不重复路径／命令摘要。收起外层过程块时同时重置内部工具、思考与子任务操作详情的展开状态，再次展开外层仍只展开当前一层。长输入与输出在展开对应调用时按归属自动读取完整记录，加载中与失败状态明确显示，失败可重试；长正文可在内容区滚动查看。收起时卸载详情正文，迟到读取结果不得更新已卸载或其他会话的视图；流式增量不重置手动展开状态。消息索引附带稳定消息 ID、思考片段归属与去重标记组成的分组结构，不携带正文，只在消息加入或分组类型改变时更新，正文与工具结果通过会话级集合接收，在客户端按消息 ID 独立订阅。
- 模型请求失败时，主／子会话消息和执行状态展示 pi 返回的具体错误消息，保留可得的状态码与供应商原因；初始化、工作进程启动或执行异常同样保留具体原因；启动异常在执行记录、子任务状态与不可变结果中一致保存，不以笼统启动失败文案覆盖。错误消息统一经常见凭据模式脱敏并限制为 2,000 字符，截断明确标记，不传递完整异常对象或堆栈。实时消息与历史读取使用同一规则，执行原因持久化；仅在没有具体消息时说明“未收到具体错误原因”，不猜测认证、额度或网络故障。
- 使用 pi 原生重试与压缩，不叠加另一套自动重试或自动续跑循环。自动重试保持同一 runId，传递运行阶段及重试序列、次数／上限、预计等待时间、脱敏原因和成功／耗尽／取消状态；次数以连续失败序列为单位。继承 pi 全局／项目设置，会话环境展示实际生效设置；默认最多重试 3 次、基础退避 2 秒、会话等待上限 60 秒，供应商层默认不额外重试。`agent_end`、重试成功或压缩结束均不能单独结算执行，须等顶层调用返回、原生空闲及工作进程空闲／退出交接。
- 最终状态只判断本次执行消息；未恢复的 `length` 为 `failed/OUTPUT_TRUNCATED`，展示“输出截断，可继续处理”；没有停止意图的异常中止为 interrupted，缺少最终回复／工具阶段未结束不能兜底成功。扩展自行处理且未启动模型的输入可记录 `HANDLED_WITHOUT_REPLY`。错误持久化脱敏原因码与说明，只有成功且原生已空闲的进程进入保活池。
- 普通重试不改系统提示、工具定义及历史公共前缀，不将重试说明写入上下文；失败尝试由 pi 持久排除，已有工具结果保留。`cacheWarming=off`，不额外请求模型维持缓存；真实缓存命中以供应商用量为准，相同前缀不保证命中。
- 后续发送复用有效保活会话，或直接打开绑定的 pi JSONL 并处理新消息。失败、停止或中断后，发送按钮旁提供回转箭头 SVG 重试入口（19px 图标、44×44px 点击区域、灰色常态、悬停提亮，保留“重试”可访问名称与提示），不显示独立文字按钮或说明行。点击调用 `agent.resume({expectedRunId})`，创建新 runId 并关联 `resumedFromRunId`，不增加用户消息、不提交或改动草稿。使用 pi 公开 `sendCustomMessage({content:[],display:false},{triggerTurn:true})` 启动原生 Session 生命周期，`context` 钩子在请求前排除内部 `axiom-resume` 标记，并通过 `appendContextEdit`／`refreshContext` 持久排除以保证重载一致；不调用私有方法、不修改依赖、不绕过原生重试／队列／结算。仅排除末尾尚未完成的失败／截断回复，直接从原用户请求或已保存工具结果继续；工具结果缺失时补充明确的“中断、结果未知”错误结果完成协议配对，应用不重放工具、不伪造成功。缺少可续接上下文时明确拒绝，用户可正常输入新要求。服务端校验 expectedRunId、终态和无活动主／子任务，旧恢复意图遇到新执行时拒绝；子任务重试作为独立控制项进入现有并发队列，遵守停止／预算／只读权限并生成新不可变结果。回执不确定只读取原请求 ID，不自动重发。
- 每次执行可使用只读配置快照，保活期间保留所绑定快照，进程退出清除；不在前端或 SQLite 复制模型定义及凭据。项目资源默认授权加载不替代工作空间访问授权或新增命令型密钥／请求头的授权。
- 停止直接强制终止应用拥有的执行，不发起模型总结，不要求清理确认，也不承诺文件或外部副作用回滚。主会话停止时先冻结自动结果唤醒，再终止该会话及所属活动子任务、取消所属排队任务；只停止子任务时不影响父会话或兄弟任务。明确的新主会话消息或手动重试才恢复父会话自动处理；等待配置锁的旧提示和迟到受理不能越过停止边界、启动工作或解除冻结。
- 切换查看对象、关闭子会话弹窗或进入配置页不属于停止操作。

耗时由服务端记录起止时间，前端只负责展示计时。主／子会话底部当前执行耗时按秒（s）、分钟（m）、小时（h）、天（d）逐级进位，最大单位为天；从实际达到的最大单位连续显示到秒，保留各级余数与零值，例如 110 秒显示 `1m50s`，3601 秒显示 `1h0m1s`，93784 秒显示 `1d2h3m4s`。仅舍去不足一秒的小数，不提前进位，未知显示“—”。Token、缓存、费用与上下文占用使用真实可得数据；估算明确标注，未知显示“—”，不能显示为零费用或零用量。统计口径区分当前执行、当前会话与包含子代理的汇总，不重复计费。

### 6.1 后台压缩快照与安全点应用

- 入口沿用工作台上下文图标，点击始终打开压缩页面，不直接启动模型请求。无任务显示准备状态；页内提供开始／再次压缩、运行中的取消及 `ModelPicker` 统一模型选择组件（搜索、收藏、供应商、模型、思考等级）。完成、取消、失败后仍可从页面再次开始；刚完成且没有新增消息时按 pi 原生限制明确提示暂无可再次压缩的内容，不重复模型请求。空会话允许打开和设置模型，但不能开始压缩。每个主／子会话的任务、详情、操作回执独立，更新不重建对话、输入或模型菜单。
- 压缩模型作为独立全局偏好保存在服务端，主／子会话及各窗口共享，刷新和重启后恢复；选择不修改聊天模型。尚未设置时使用当前会话模型，已保存选择失效时明确报错，不静默换回聊天模型。每次任务冻结其启动选择；运行中修改全局模型仅用于后续任务。
- 压缩页面提供全局自动压缩开关、Token 阈值与上下文百分比（整数 1–100）；默认开启，100,000 Token／80%。当当前上下文占用达到 `min(Token 阈值, ceil(当前会话模型上下文容量 × 百分比 / 100))` 时启动后台快照压缩；容量未知时仅用 Token 阈值，占用未知时不触发，不使用累计计费用量或摘要模型容量。主／子会话独立判断，启动与成功 `turn_end` 的新用量事件读取最新配置；页面打开、刷新、订阅、服务重启与保存配置本身不触发请求。数值按 Enter／失焦局部保存，跨窗口同步且保留正在编辑的字段。关闭自动开关不取消已开始的任务。
- 自动压缩复用同一原生快照任务、独立压缩模型、并发上限及安全点应用流程，详情标明自动触发。每次执行在持续超阈值期间只尝试一次；成功后观察到占用回落阈值以下才能再次触发，失败／取消不在同一执行中自动重试，新的执行可重新判断。达到并发上限时跳过本次检查，不建立自动重试计时器或隐式任务队列；后续用量事件可再判断。等待模型配置锁期间复核阈值、开关、执行归属与停止边界；停止或退出后不得复活旧启动。Axiom 接管 pi 的主动 `threshold` 压缩，并忽略被拦截检查的压缩进度事件，避免无实际压缩时显示压缩中／收尾；保留原生手动压缩及按 pi 设置启用的 `overflow` 恢复，不重写摘要协议。
- 启动时校验工作空间／会话、已保存消息、明确且可用的模型／思考等级及配置修订；不自动换模型。每次触发创建独立任务，以当前会话分支重新取快照；此前压缩失败、取消、中断不作为新任务的前置状态，迟到回执仅能作用于其所属任务。运行中的会话等待 pi `turn_end`／`agent_before_settle` 安全边界，再复制当前分支与会话头为临时快照；空闲会话先等待保活进程及关闭钩子释放所有权，重新检查是否出现新执行后同步保存快照。不在任意流式中间状态截取上下文，快照之后的消息不纳入摘要输入。历史失败、已中止请求及进程中断留下的未配对工具记录可被摘要，不以全历史工具配对判断当前安全点；应用仍禁止将原本成对的工具调用与结果切开。
- 独立进程调用 pi `AgentSession.compact(customInstructions)`，同次请求额外生成 `<axiom-summary>` 30 字内中文压缩短摘要，与会话标题的 `<title>` 提示词及生成流程独立；保留原生完整交接摘要结构，不增加短摘要生成请求，只写临时快照；针对 pi 1.1.0 分段压缩未传递 `customInstructions` 的路径，在专用压缩会话的 `streamFunction` 中向每个原生摘要请求附加相同指令，确保历史摘要与当前段摘要都收到要求，不追加会话消息。不对正在工作的原会话调用手动压缩、不打断当前请求。后台取得原生 compaction 结果后，等待原会话新的 `turn_end`／`agent_before_settle` 安全边界，由拥有该会话的工作进程校验并追加原生 compaction、更新内存上下文；空闲会话先释放保活进程，再在互斥保护下同步校验并追加；等待退出后重新检查会话是否已有执行，不另启模型请求，也不形成第二个会话写入者。快照或应用请求遇到执行结束时交接给协调器，在释放所有权后继续处理，不将正常结束视为失败，不重新生成已有摘要；启动期间尚无 IPC 所有者的请求在工作进程就绪后送达。
- 应用前校验真实会话绑定、快照前缀、分支及压缩边界仍兼容；只允许保留快照后的合法追加消息。分支切换、历史改写、其他压缩或缺失保留边界等冲突必须拒绝应用，不自动重新生成摘要或覆盖新内容。追加原生 compaction，不以临时快照替换整个原 JSONL；原始历史与快照后新增消息均保留。失败、取消、中断或冲突不应用摘要，不宣称回滚会话中的其他工作。
- 压缩进程关闭扩展、技能、提示模板、主题、上下文文件与全部编码工具；使用冻结的模型配置与 pi 认证，不建立第二套压缩协议或模型客户端。已有获准命令型认证仍可执行，独立进程不是操作系统沙箱。
- 每会话最多一项，全局最多四项，不隐式排队；不设置压缩等待或执行时限，取消调用原生中止，等待最多两秒后尝试强制结束拥有的工作进程。父会话整体停止覆盖其自身及所属子会话的压缩，等待配置锁的旧启动不得越过停止边界。供应商撤销和服务退出也处理在飞压缩。
- 状态为 `running / completed / cancelled / failed / interrupted`；阶段为 `snapshot / summarizing / applying / done`，分别呈现等待安全点快照、后台生成原生摘要、等待新的安全点应用和已应用，不用假进度定时器。处理阶段仅当前运行步骤显示旋转圆环与高亮，完成步骤显示勾选；失败标记停留在对应步骤，后续步骤仍为等待，终态停止动画。减少动态效果时保留静态高亮。等待应用时仍为 `running`；只有原生结果成功应用且压缩进程退出，才发布 `completed`／`done` 并记录应用时间（`appliedAt`）。其他终态也须释放压缩进程后发布，避免显示可重试却仍占用旧进程。
- 详情以独立提示区展示失败／中断原因；工作进程保留异常消息，经常见凭据模式脱敏与长度限制后传递、持久化并订阅更新，不传递完整异常对象或堆栈。模型配置、供应商请求、快照／应用及进程异常不得统一吞成笼统失败；无法取得具体原因时明确说明未知，不猜测。历史任务缺少原因时同样使用未知提示，失败后允许显式重试，不自动重发。
- 详情展示会话、服务端耗时、pi 压缩前后估算、Markdown 摘要及该次摘要用量／费用；摘要复用会话压缩卡片的安全渲染与排版，原始 HTML 不执行；未知数据不伪装为零。摘要展示上限 64,000 字符，超过明确标记截断；展示截断不影响完整原生结果的应用。摘要生成不代表已经应用，压缩后快照估算不包含后续新增消息，会话圆环优先取 pi 原生上下文统计；压缩后尚无有效模型用量时，以 pi `estimateTokens()` 对当前已提交的上下文投影逐消息估算，包含摘要、保留消息和快照后新增消息，不使用保留助手消息中的压缩前 usage 或详情快照数值。Token 前显示 `≈`，提示说明待模型用量校准；有效原生统计恢复后移除该标记。旧会话持久化的未知占用可从绑定 JSONL 只读补算，无容量仍显示未知。此当前上下文估算同时供 Axiom 自动阈值判断，不改变计费或 pi 的摘要算法；详情中的压缩快照估算不用于自动触发。摘要 usage 在应用后计入所属 pi 会话统计；详情只是该次明细，不再次与主／子会话统计相加。
- `compression.preferences.get/save` 管理全局 `{selection,auto:{enabled,tokens,percent}}`，模型选择和自动配置均支持局部更新，省略字段保留最新值；`compression-preferences` 独立订阅同步设置；`compression.get/start/cancel` 均绑定工作空间／会话，取消还校验压缩任务 ID；`compression:<workspaceId>:<sessionId>` 独立订阅。启动／取消先记录持久回执，前端发送前保存请求标识，重连只查询、不重发。
- 任务与结果持久化，临时快照／配置退出后删除；异常残留启动时清理。重启将未结束任务标为中断，不启动模型请求。关闭详情／子窗口不取消任务；点击详情面板左侧的外部区域收起详情，面板内点击或从面板内拖动到外部不收起；Escape 只关闭最上层压缩详情并恢复焦点。

## 7. 子 Agent 与独立工具

### 7.1 工具契约

四个工具直接注册到主 pi 会话，工具描述和参数一次可见。

| 工具 | 参数 | 行为与返回 |
| --- | --- | --- |
| `delegate` | `context`、`tasks: [{task, systemPrompt?}]` | 异步创建子任务，返回 `taskIds`、排队／启动状态与预算，不等待任务结果 |
| `append` | `taskId`、`text`、`mode: steer \| followUp` | 补充或追问，返回已接受／已排队状态 |
| `cancel_task` | `taskId`、`reason?` | 强制停止指定子任务，不发起总结，返回停止回执；最终交付经完成通知读取 |
| `read_result` | `taskId`、`resultId` | 读取通知对应的不可变结果；不作为进度查询工具 |

- `context`、任务内容、追问文本必须非空，所有参数限制长度和数量并执行服务端校验。
- `systemPrompt` 只补充职责，不提升权限，不覆盖系统安全规则或预算。
- `append` 默认 `steer`，保留 `followUp`；`cancel_task` 不接受模式参数。
- 结果使用结构化字段与文本内容，错误必须标记为错误，不仅返回含“失败”的普通字符串。
- 委派幂等键包含父会话、执行和工具调用 ID，同一调用重传返回同一组任务标识。
- 取消与追加对同一个任务串行更新，其他任务不被无关操作阻塞。
- 子代理不注册委派工具，不递归派生子代理。

### 7.2 委派与上下文

- 每个子任务必须有明确目标、范围、必要资料和交付要求。
- 子代理不自动复制整个主会话；只接收明确传入的背景、任务及其获准的项目上下文。
- 子代理仅用于调研、分析与审查，交付文件路径、相关位置、证据、修改建议和未验证项，不执行修改；所有实际编码、文件变更及需执行命令的验证交给主代理。
- 工作进程以固定白名单只启用 pi 内置 `read`、`grep`、`find`、`ls`，并在工具调用边界再次检查。禁止 `edit`、`write`、`bash`、`powershell`、递归委派和其他未批准工具，不能仅依靠提示词或删除写入工具名称。
- 子代理不加载用户、项目或资源包中的可执行扩展，防止同名只读工具覆盖、扩展命令或动态工具绕过；不加载提示模板，配置资源包从子代理的内存设置快照中移除，避免发现资源时安装依赖。保留项目上下文和可读技能，文本指令不能提高权限。主代理资源和修改能力不变。
- 首次委派、steer／followUp、用户直接追问、结束后恢复绑定 JSONL 均应用同一只读策略，职责补充、历史消息和项目默认工具配置不能覆盖。限制的是模型可调用能力，不是 OS 沙箱；应用仍持久化会话／元数据，已授权的命令型认证仍有自身执行副作用。
- 任务记录先持久化再启动进程，卡片关联触发委派的消息或工具调用。
- 默认最多并行运行 4 个子代理，超出进入服务端 FIFO 队列；并发可配置为 1–16。一次委派 1–8 个，每个父会话最多 32 个活动／排队任务，每个子会话最多 32 条未交付输入；并发委派在异步校验后重新检查限额。
- 排队取消与启动前失败也产生不可变终态报告，不为获取报告而启动工作进程。
- 主代理可以继续独立工作或结束当前回复，子任务完成后由服务发送通知，不轮询等待。

### 7.3 追问行为

| 子任务状态 | 处理 |
| --- | --- |
| 排队／启动中 | 保存追加内容，在安全时机交给该子会话 |
| 执行中 | `steer` 经 pi 的安全边界送达；`followUp` 排到当前工作结束后 |
| 停止中 | 不与正在终止的执行并行启动；待其结束后再发送新追问 |
| 已完成／失败／已停止／中断 | 打开绑定的同一 pi JSONL，创建新 `runId`，只处理新要求，不经过人工恢复或清理确认 |

持续运行期间的追加不延长执行预算。执行结束后的追问产生新执行与新结果，保留原结果可读。

用户整体停止主会话后，未消费的队列不会自行启动。用户明确向子会话发送新追问可以启动该子会话，但不解除父会话的自动通知冻结。

### 7.4 生命周期与预算

```text
queued → starting → running → completed
                       ├──→ failed
                       └──→ stopping → cancelled
```

- 配置仅包含工作时限 `workMs` 和并发上限 `concurrency`，不设置收尾、停止总结或清理预算，也没有 `wrapping`、`summarizing` 或 `cleanup` 阶段。
- `workMs` 默认 600000 毫秒，范围 1000–86400000 毫秒；`concurrency` 默认 4，范围 1–16。分支图标内统一设置且自动全局记忆。工作时限更新立即应用于排队及运行中任务，按原执行启动时间重算截止，已超时则停止；结束后追问的新执行使用最新时限。并发上限立即影响现有队列，提高时填补空位，降低时不强停已运行任务。
- 时间由服务端独立计时，排队时间不计入工作预算；刷新、重连、模型重试和追加消息不重置预算。
- UI 停止、主代理取消和工作预算到期调用同一强制终止机制，记录来源与原因。终止应用拥有的工作进程及可管理的子进程，不再发起模型请求；取消排队任务不启动 pi。
- 停止结果只基于已经保存的输出和可得执行事实，不为补齐报告调用模型，不将取消标成正常完成。
- 重复取消幂等，已结束任务保持原结果，不生成重复交付。
- Run 不含 `cleanup` 状态或字段，不提供 Agent 清理确认界面；强制终止不证明所有外部副作用结束，也不回滚项目文件。
- 服务重启时仍在执行的任务标记为 `interrupted`，不自动重放请求或工具操作；后续新消息直接使用绑定的 JSONL。

### 7.5 结果与通知

1. 执行结束后保存结果、执行状态和待通知信息。
2. 完成通知内部仅携带对应 `taskId`、`runId`、`resultId` 与结果状态。前端实时与历史投影统一为轻量系统状态条，不显示原始 JSON 或内部标识：完成为「子代理已完成」、取消为「子代理已取消」、失败为「子代理执行失败」、中断为「子代理执行中断」；未知／旧格式保留中性文案，不误报成功。正常通知（完成、主动取消及未知状态提示）采用 Tabler Message Forward 图标，失败／中断采用 Tabler Message Report 图标；均为 24×24 viewBox、2px 描边、圆角线帽与连接，16px 显示尺寸，不加圆形外框。所有通知的文字与图标统一使用灰色（`--muted`），显示时末尾统一为一个中文全角感叹号 `！`。图标与 12px 文字的首行垂直居中，文字行高 18px，图文间距 6px，上下内边距 2px、外边距 4px／10px，保留渐隐细线；后续新增通知复用公共 `NotificationIcon` 组件。200ms 淡入，减少动态效果时禁用动画；不使用用户气泡或弹窗，不改变原始上下文及投递确认。
3. 父会话运行中，经 pi 的消息机制在安全边界送达；父会话空闲且未被用户停止时，可以唤起一次结果处理。
4. 父会话已停止时只更新任务卡片，通知保留待处理，不自动发起模型请求。
5. 消息进入可恢复的父会话记录后才确认投递，不能以写入内存队列作为送达依据。
6. 主 Agent 使用 `read_result` 获取结果；相同结果重复读取无副作用。

采用可重投递与幂等去重，不宣称跨 SQLite 与 pi 会话文件存在天然的恰好一次事务。故障恢复根据结果标识和通知消息标识对账，避免丢通知或重复唤醒。

结果包含成功／失败／停止事实、已有产出、未完成或未验证项、已知副作用；未知项明确标注。停止报告仅整理已有记录，不另行请求模型总结，不意味着项目文件或外部副作用回滚。

### 7.6 子会话界面

- 委派从工具调用出现时即显示「子代理协作」卡片，以调用 ID 稳定关联；任务记录尚未生成时展示任务描述与创建状态，任务描述默认最多两行、完整内容可在详情／子会话查看，成功后在原卡片接入真实任务。整次委派失败在组内显示错误原因，具体任务错误放在对应行；调用停止或缺少回执明确标记，不推断成功。委派卡片标题不显示“独立 pi 会话”提示和详情下拉入口，不重复出现通用工具卡；点击任务行进入子会话。
- `read_result`、`append`、`cancel_task` 使用统一的紧凑操作卡：轻边框、现有圆角与统一的 Lucide 线性图标、任务描述、省略长标题、状态和展开入口，窄屏标题与描述分行。分别显示「子任务结果」「补充任务／追加追问」「停止子任务」；读取成功为「已读取」，追加成功为「已受理」，停止按回执区分「停止已受理」「已停止」「任务已结束」。失败原因默认可见，停止／未知状态不隐藏；这些是操作状态，不等同于子任务执行成功或结果已核验。
- 读取详情只展示该次调用绑定的不可变结果，不切换到最新交付；按原始参数核对任务和结果 ID，以 Markdown 展示报告与未完成项。长返回在展开时经 `message.get` 按归属读取完整记录，失败允许重新加载，不重放工具操作。追加正文与停止原因按需展开，原始工具名、ID、输入和输出收在二级详情；收起时不挂载完整结果。可从详情打开关联子会话。子任务通知收入过程卡片，其他通用系统通知保持独立。

- 点击任务卡片打开独立子会话窗口，保留父对话挂载与阅读位置。
- 不将主对话 DOM 移进弹窗，不复用全局 active 作为两个窗口的数据来源。
- 子窗口拥有独立消息订阅、草稿、附件、模型选择、滚动和工具折叠状态。
- 用户可在窗口中追问或停止；按钮与 Agent 工具调用同一任务服务，不经过模型转发。
- 关闭窗口只停止查看，不停止任务。
- 多次追问仍在同一任务卡片下展示，执行与结果分别可辨认。不增加暂存输入恢复、请求人工核实、停止总结或清理确认入口。

## 8. 持久化与故障恢复

### 8.1 存储职责

| 存储 | 内容 |
| --- | --- |
| pi JSONL | 主／子会话消息、工具结果、模型变更及 pi 管理的上下文状态 |
| SQLite | 工作空间、会话索引、任务关系、执行记录、结果交付、压缩状态与摘要预览、请求回执、界面偏好；不存会话草稿或另一份上下文 |
| pi 配置目录 | 模型定义、认证、原生设置与其自身缓存 |
| 应用资源目录 | 上传附件等受控文件 |
| 浏览器查看状态 | 当前查看对象、临时菜单与焦点；未发送会话文本及附件只在前端内存，不承诺刷新恢复；不存凭据或运行事实 |

不把完整对话再复制进 SQLite。结果报告是任务交付对象，不是另一份全部消息记录。

### 8.2 最小数据关系

- `workspaces`：稳定 ID、规范化目录、显示名称、项目授权、置顶、移出列表状态；工作空间查看偏好单独保存最近使用的有效空间标识。
- `sessions`：工作空间、角色、父会话、pi 会话文件、标题及命名状态（待生成／已生成／手动）、模型选择、手动置顶、结果／已读版本与派生未读状态、自动置顶冷却期限（未开始／冷却中／已回队）。
- `session_results`：按会话和结果来源去重的版本事件，执行结算与结果版本在同一事务中写入；不保存第二份消息正文。旧未读迁移为结果版本 1／已读版本 0，已读迁移为相等版本。
- `tasks`：父会话、子会话、委派锚点、任务描述、当前执行标识。
- `runs`：所属会话／任务、状态、阶段、重试元数据、原因码、续接来源、工作预算、起止时间、停止信息；无 `cleanup` 字段。
- `task_results`：唯一结果 ID、唯一执行关联、最终报告、通知状态与确认消息标识。
- `compressions`：唯一任务 ID、所属会话、请求标识、状态／阶段、起止及应用时间、快照消息数、前后估算、模型标识与摘要展示；会话删除级联清理。
- `compression_preferences`：应用级单条压缩模型选择（供应商、模型、思考等级）及自动配置 JSON（开关、Token 数、百分比）；旧表新增 `auto` 列，缺失值使用默认自动配置；独立于聊天模型默认值，不随会话删除而清除。
- `task_settings`／`task_model_preferences`：应用级单条子代理预算和默认模型选择；独立于主会话模型及会话删除，修改通过独立订阅同步。
- `requests`：操作 ID、归属、输入摘要哈希、受理状态与响应，用于安全重传。
- 界面偏好：保存各自归属和修改序号；不建立会话 `drafts` 存储。

具体建表可合并不必要的实体，但必须保留外键约束、执行归属检查和结果去重约束。应用数据库由服务进程管理，Agent 不直接写管理表。

### 8.3 恢复规则

- 会话上下文只从绑定的 pi JSONL 读取；请求回执用于归属校验与去重，不作为输入恢复或上下文重建来源。断线、刷新或重启不自动重发用户请求，不提供会话请求人工核实恢复流程。当前页面中迟到回执只能清除与已提交内容仍一致的目标输入。
- 服务启动只恢复索引与状态，按需要加载 pi 会话；不为查看列表启动全部 Agent。
- 缺失或损坏的会话文件显示错误，保留任务记录，不创建空会话冒充恢复成功。
- 已保存的最终消息与任务结果不因浏览器断线丢失。
- 进程崩溃时尚未持久化的流式尾部不伪装成完整结果；对应执行明确标记中断。服务重启将活动执行原子结算为 interrupted 并生成一次结果版本，重复重启不重复通知，不自动恢复模型请求。
- SQLite 写入失败时停止确认新变更并显示错误，不能继续返回成功。

应用数据放在系统用户数据目录，不写入项目仓库。主／子执行的冻结模型配置保存在该数据根下的 `run-models/`，由同一数据目录的服务锁保护；启动清理只处理本目录的残留快照，不清理共享 pi 配置目录或其他数据根的运行文件。Windows 使用 `%APPDATA%/Axiom2`，macOS 使用 `~/Library/Application Support/Axiom2`，Linux 使用 `$XDG_DATA_HOME/Axiom2` 或 `~/.local/share/Axiom2`。允许通过明确启动配置指定数据根目录。

## 9. 通信与局部刷新

### 9.1 命令和事件

命令至少包含 `requestId`、操作类型、目标标识与参数；非应用级操作携带 `workspaceId` 和 `sessionId`。服务从实际数据关系确认归属，不能将传入标签直接作为授权。

会话事件形状：

```json
{
  "type": "message.delta",
  "workspaceId": "workspace-id",
  "sessionId": "session-id",
  "runId": "run-id",
  "seq": 42,
  "data": { "messageId": "message-id", "delta": "text" }
}
```

- 子会话消息使用子 `sessionId`，同时携带 `parentSessionId` 与 `taskId`；父列表的任务摘要只更新父会话的任务区域。
- 应用级模型配置事件使用独立配置修订标识，不伪造会话归属。
- 消息和工具使用稳定 ID，不用数组索引或时间戳作为唯一身份。
- 命令回执区分“已受理”与“执行完成”，错误包含机器可判定类型和脱敏说明。
- 同一 `requestId` 的不同参数直接拒绝，不能将其视为新请求。回执查询校验原请求的工作空间／会话归属；旧数据缺少归属时拒绝返回内容，不泄露回执或允许自动重做，不据此增加会话请求核实界面。

### 9.2 断线重连

- 单连接承载多个按作用域订阅的事件；不同浏览器标签页各有自己的查看订阅。
- 事件序号在明确的流标识内递增；服务重启更换流标识，客户端不能混用重启前后的序号。
- 重连提交已确认序号，有缓存时补发；缓存不足时获取对应会话快照与游标，再接增量。
- 快照与增量有同一游标边界，防止快照覆盖较新的消息。
- 快照包含当前流式消息、最终消息索引、任务状态与配置修订标识。
- 切换会话后到达的快照只写原作用域；过期加载请求不抢占当前页面。
- 慢客户端允许合并文本增量，不能丢失最终消息、工具结束、取消结果或请求回执。
- 断线后重新订阅会话消息和状态，不自动重发 prompt，也不恢复未发送输入或要求人工核实会话请求。模型配置和后台压缩的专用回执按各自契约处理。

### 9.3 渲染边界

| 区域 | 订阅内容 |
| --- | --- |
| 工作空间与会话侧栏 | 当前工作空间的会话摘要，以及独立订阅的跨空间置顶摘要；均包含运行／未读状态 |
| 消息列表 | 指定会话当前压缩上下文的完整消息 ID 与分组，无分页 |
| 单条消息 | 该消息的内容与工具增量 |
| 输入区 | 该查看实例、该会话的草稿及发送状态 |
| 模型菜单 | 可用目录、当前选择与本地选择草稿 |
| 子任务卡片 | 对应任务状态、进度与结果摘要 |
| 子会话窗口 | 对应子会话的数据 |
| 压缩入口与详情 | 对应会话的压缩任务及操作状态，不订阅其他会话 |

- 应用根布局不订阅流式正文。
- 增量按帧合并，仅更新受影响消息；已完成消息的 Markdown 和代码高亮不重复解析。
- 会话 Markdown 在显示层兼容中文收尾标点与后续文字间无空格的双星号加粗（如 `**验证：**43`）；不改写存储或复制原文，代码块、行内代码及转义继续按字面处理，原始 HTML 与危险链接仍不可执行。
- 长历史按需加载，长工具结果按需展开，不一次性渲染全部内容。
- 复用组件不等于复用状态，父／子会话不能共享草稿、滚动或模型菜单状态。
- 流式输出时保持输入法、焦点、选区、菜单打开状态与用户手动滚动位置。

## 10. 本地服务与桌面运行

- 第一阶段定位为本机单用户，服务默认仅监听回环地址，不默认暴露到局域网。
- 管理 HTTP 与 WebSocket 均需要本地访问校验和来源校验，防止其他网页借用本地服务执行命令。
- 工作空间访问在选择目录打开时默认授权；Agent 项目资源默认授权并按 pi 规则加载，不因非交互运行等待额外确认。新增命令型密钥／请求头的授权仍须显式处理。
- 服务进程集中管理工作进程、数据库连接和退出流程。
- 关闭浏览器标签页或 Pake 窗口只关闭客户端，后台服务和任务继续；用户明确退出服务时显示活动任务并进行停止与持久化。
- Pake 不自带 Node.js 或 pi。先安装 Node.js 24+，使用根目录 `install.ps1`／`install.sh` 安装 GitHub Release 的预编译 npm 包并启动后台服务，或从源码构建。`axiom2 start / status / stop` 管理后台进程，直接运行 `axiom2` 支持前台模式；不注册登录自启或崩溃自动重启。桌面控制页随客户端打包，即使服务离线仍可打开，提供启动、刷新状态、打开工作台及关闭服务；关闭前展示活动会话并确认，正常退出后保留数据。工作台仅在服务就绪后打开独立窗口，服务退出后关闭工作台、保留控制页；关闭客户端不会停止服务。
- 桌面原生命令只接受固定动作，并验证调用窗口为内置控制页；通过安装记录找到 Node.js 与 CLI，以固定参数直接执行，不执行网页传入的 shell 命令、路径或 PID。CLI 使用独立回环控制端口及每次启动随机凭据，拒绝浏览器 Origin、错误 Host 和未授权请求；正常退出经现有服务关闭流程，不按残留 PID 强杀进程。安装记录和控制凭据保存在用户数据目录，后台日志写入 `service.log`。业务服务保留原有回环绑定、Host／Origin 校验和禁止 iframe；远程工作台没有原生服务控制权限。
- OAuth 提供可复制链接，由用户在系统浏览器打开，不在桌面壳内导航授权。Windows MSI／EXE 与服务 tarball 通过 GitHub Releases 提供下载和 SHA-256 校验，源码不包含二进制与用户运行数据。桌面构建从固定 Pake 版本创建隔离模板，注入原生桥接，不修改全局安装的 Pake 源文件。
- 安装包构建、原生窗口交互、真实 OAuth 系统浏览器跳转及目标系统进程管理分别验收，不相互替代。Windows 原生 UI 自动检查需要已连接、解锁的桌面会话。
- Windows 的命令工具按实际环境选择并检查依赖；启动参数使用数组传递，不拼接未经校验的 shell 字符串。
- 跨平台验收在实际目标系统执行，不以路径判断单元测试代替桌面启动和进程停止验证。

## 11. 开发顺序与阶段门槛

### 步骤一：运行基础与设计落地

- 建立前后端构建、服务启动、WebSocket 和 SQLite。
- 提取设计样式，建立工作台、配置概览、模型服务三个独立页面。
- 建立工作空间／会话标识与局部订阅，不保留全局整体重绘入口。
- 验证 pi SDK 创建会话、注册独立工具、消息事件、停止和模型认证接口。

门槛：页面布局可对照，连接与空态真实；无模型时不能意外发起请求；设计源未改变。

### 步骤二：模型与主会话闭环

- 完成模型配置覆盖、pi 登录／退出登录、目录筛选、模型选择。
- 完成真实主 Agent、附件、工具输出、停止、持久化恢复。
- 完成会话列表交互、工作空间隔离和用量展示。

门槛：从打开目录到实际修改文件可完成；配置删除不会残留可选项；双会话同时运行不串数据。

### 步骤三：子 Agent 闭环

- 注册四个工具，完成任务队列、独立子会话、预算、取消与追问。
- 完成结果落库、通知、读取、去重与停止后的冻结。
- 完成子任务卡片及独立子会话窗口。

门槛：多个子任务并行、单独取消、结束后追问、父会话停止和故障恢复均符合契约。

### 步骤四：产品验收与交付

- 完成响应式、键盘操作、视觉对照、长对话与流式交互测试。
- 验证断线重连、服务重启、配置冲突、磁盘失败及拥有进程的终止；Agent 停止不要求人工清理确认。
- 完成浏览器与 Pake 运行验证及跨平台安装启动说明。

门槛：全部第一阶段验收项通过，无模拟数据冒充实际能力，无未说明的支持范围。

## 12. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| UI-01 | 页面复刻 | 三个页面与子会话窗口符合设计几何、样式和交互状态；规定视口无意外溢出 |
| UI-02 | 连续输出期间操作 | 输入、中文输入法、模型搜索、菜单、切换会话和滚动均不被流式刷新打断 |

| ISO-02 | 多标签页与父子窗口 | 查看状态相互独立；关闭窗口不取消任务 |
| MOD-01 | 空配置和新增模型 | 空列表禁止发送；保存并完成所需认证后才出现在会话菜单 |
| MOD-02 | 删除模型／供应商 | 执行 pi 退出登录、提示供应商级影响、移除目标配置与收藏；环境变量不能使删除项重现 |

| MOD-04 | 行内编辑统一保存 | 完成／切换只暂存，顶部保存包含隐藏编辑；无效项保留可修正，草稿不漏存 |
| AGT-01 | 主 Agent | 发送启动单 pi 工作进程，真实工具过程可见；强制停止后新消息使用绑定 JSONL，不经过恢复或清理确认 |
| CMP-01 | 后台压缩 | 安全点保存快照、后台真实 pi 摘要、新的安全点自动应用；主／子归属不串，原始历史与新增消息保留，冲突／失败不应用；取消、重试、停止与撤销有界，重启不重放 |
| CMP-02 | 压缩与用量界面 | 圆环边界／未知态准确；四阶段如实展示，completed 仅指已应用，摘要 usage 应用后计入会话且详情不重复相加；入口仅打开页面、完成／取消后可再次启动、统一模型选择与全局持久化、焦点恢复、减少动画及九视口布局符合设计 |
| SUB-01 | 委派与读取 | 多个只读调研子任务立即返回标识，完成后通知并读取正确结果，无进度轮询；初次与恢复执行仅有只读白名单，伪造写入／shell 调用失败，配置与扩展不能提升权限，主代理保留修改能力 |
| SUB-02 | 追问续接 | 运行中追加及结束后追问符合 pi 队列语义；新执行不覆盖原结果 |
| SUB-03 | 取消与预算 | 单独取消只停止自身；`workMs` 到期强制终止，不发起总结或要求清理确认；仅配置 `workMs`／`concurrency`；重复取消无重复结果，不伪称回滚 |
| SUB-04 | 父会话停止 | 子任务终态可见，自动唤醒冻结；打开窗口和发送子会话消息不擅自恢复父代理 |
| REC-01 | 断线重连 | 快照与增量不重复、不回退，不重复发送用户请求或重复启动子代理 |
| REC-02 | 服务中断 | 从绑定 JSONL 读取消息并展示持久化结果；在飞执行标为中断，缺失文件不静默重做；未发送输入仅内存、切换保留、刷新不承诺恢复 |
| SEC-01 | 凭据与授权 | 浏览器存储、日志和事件不泄露凭据；工作空间访问在打开时默认授权，保留新增命令型密钥／请求头授权；Agent 项目资源默认授权加载 |
| PLAT-01 | 平台交付 | 目标系统可启动服务和桌面壳，目录路径正确，Agent 停止只作用于拥有的进程，无人工清理确认，不承诺外部副作用回滚 |
