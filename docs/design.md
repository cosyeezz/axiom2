# Axiom2 第一阶段产品设计

本文是第一阶段的实施与验收依据，描述产品应具备的能力，不表示功能已经实现。功能、接口与约束调整时直接更新对应正文，保持一份当前有效的设计。

## 1. 产品目标

Axiom2 是基于 pi 的本地编码 Agent 工作台。用户可以管理多个工作空间和会话，与主 Agent 对话、委派子 Agent、查看工具执行。

第一阶段完成以下闭环：

1. 打开项目目录，建立工作空间。
2. 配置模型与认证，在会话中选择可用模型。
3. 主 Agent 使用 pi 读取、修改文件和执行命令，实时展示过程。
4. 主 Agent 委派子任务；用户和主 Agent 均可追问、停止子代理。
5. 切换工作空间、切换会话、刷新页面和重连时，保持正确的数据归属。
6. 在浏览器与 Pake 桌面壳使用同一套产品。

### 1.1 实施原则

- **设计准确复刻**：以 `ui/` 的页面与交付说明为视觉和交互依据，不另行设计一套界面。
- **设计源只读**：开发不修改、格式化、移动或删除 `ui/`；产品实现在 `app/`。
- **pi 是运行核心**：模型调用、认证、会话上下文、基础工具、重试与压缩使用 pi 的公开能力。
- **独立工具**：委派、追问、取消、读取结果分别注册，不使用 Ask/Let 或统一 action 工具包装。
- **服务端隔离**：工作空间、会话、子任务、执行的归属由服务端校验，不能只依赖前端筛选。
- **独立刷新**：对话输出不能打断输入、模型选择、菜单操作或其他会话查看。
- **事实优先**：不使用模拟任务、虚构工具、虚假成功状态或伪造用量填充产品。
- **可恢复不等于自动重做**：重连与重启不得重复发送请求、重复委派或自动重放文件修改。

### 1.2 第一阶段范围

| 模块 | 交付内容 |
| --- | --- |
| 工作空间 | 选择本地项目目录、切换、重命名、置顶、移出列表、恢复上次使用空间、展示与复制路径、打开系统文件管理器 |
| 会话 | 创建、恢复、切换、自动短标题、手动重命名、删除、搜索、置顶、草稿、未读与运行状态 |
| 主 Agent | pi 会话、流式回答、工具过程、多文件／文件夹附件、图片、@ 原生文件补全、强制停止与无新增消息续接 |
| 后台压缩 | pi 独立快照原生摘要、安全点自动应用、主／子会话独立状态与详情、取消／重试 |
| 子 Agent | 异步委派、独立上下文、实时详情、追问、取消、预算、结果回传 |
| 模型服务 | pi 配置文件管理、API Key/OAuth 认证、模型覆盖、可用列表、删除与退出登录 |
| 配置概览 | 实际模型配置摘要、配置与凭据存储说明；加载与静态缓存边界见[配置页加载说明](settings-loading.md) |
| 持久化 | pi 会话文件、SQLite 管理数据、断线恢复 |
| 平台 | Windows、macOS、Linux 的本地服务与浏览器使用，Pake 桌面接入 |

不纳入第一阶段：多人账户系统、云端调度、递归 Agent 网络、复杂目标工作流、自建模型网关、独立压缩引擎、拖拽页面编辑器、属性编辑面板、多人评论与移动端原生应用。已安装的 pi 扩展与技能按 pi 规则加载，不另外开发插件市场。

### 1.3 原生仓库索引后续阶段

原生仓库认知与代码定位属于已授权实施的后续功能阶段，以 `axiom-code-index-v1/IMPLEMENTATION_PLAN.md` 为唯一专项方案。它在独立工作区索引中维护符号、实现、功能、模块与有来源的知识；不改变第 7 节规定的子代理调研与测试工具边界。主 Agent 接入 `locate_code` 与只读 `repo_overview`；专用 pi locator 使用独立内存会话和 index_query/code_evidence/index_submit 三工具，不能编辑文件、加载项目扩展或递归委派。程序负责授权、机械失效、证据与原子提交，模型负责基于已读取证据提出语义更新。

Index 浏览与批注沿用现有工作台视觉和输入协议，真实浏览不发模型请求；批注发送交由主 Agent 核验和修改。持久索引默认关闭，正式启用及 AOCI 退出受专项方案独立验收门槛约束。此段规定目标和边界，不代表产品接入或验收已经完成。

## 2. 页面与设计契约

### 2.1 页面映射

| 产品表面 | 设计来源 | 实现要求 |

页面入口以 `ui/DESIGN-HANDOFF.md`、`ui/DESIGN-MANIFEST.json` 和实际页面互链核对，不能仅凭文件名称选择。辅助 HTML、截图和检查脚本用作设计参照，不据此自动增加产品导航入口。互链与交互检查脚本指向不同页面时，先核对目标交互，不擅自丢弃其中的设计要求；待核对项集中记录在 `docs/ui-sync.md`。

### 2.2 复刻要求

- 品牌标识采用透明背景的金色展翼，唯一源为 `app/assets/axiom-icon.svg`；按可见轮廓等比放大居中，只保留安全边距。工作台侧栏不展示品牌区，顶部为同一行的新建会话与收起按钮；桌面独立连接／控制页、网页标签／主屏幕、Windows／macOS 打包源及 Android 启动／连接页使用同一图形与渐变；进入工作台后桌面顶栏不重复展示品牌。各端资源由同源生成，品牌图案不套用功能图标的描边或着色规则，不改写 `ui/` 原始设计。

- 保留颜色、字体、字重、间距、边框、圆角、阴影、图标、尺寸、布局、滚动区域和动效时长。文字对比度按最终合成背景测量，普通文字至少4.5:1，大字至少3:1；禁用控件、装饰分隔线及用户指定状态图标分别记录。辅助文字使用可读灰色，公共危险／失败图标与错误文字采用低饱和灰玫瑰红 `#d99595`（`--danger-icon`／`--danger-text`），警告色采用柔和琥珀色 `#c5aa78`（`--warn`）。危险按钮填充采用砖红色 `#a85656`（`--danger`），危险按钮悬停为深砖红色 `#934949`（`--danger-hover`）并保留白字；停止方块使用随主题切换的 `--danger-icon`，背景透明，不叠加光晕；暖橙强调色与指定动效保持。
- 应用支持白天／黑夜两套主题，默认黑夜，选择保存在当前设备。桌面顶栏的太阳／月亮 SVG 按钮位于“服务与更新”左侧，连接页页头同步提供入口。“显示与阅读”在字体上方提供白天／黑夜主题选择，网页与桌面共用主题状态、即时应用并持久化；恢复默认包含恢复黑夜主题。白天采用暖白背景、深灰文字与深暖橙强调色；菜单、弹窗、提示、代码、错误及选中／悬停／焦点状态均随主题变化，已打开的浮层无需重开。共用主题规则最后加载；桌面控制页与经来源校验的工作台设置页通过原生桥接双向同步主题，刷新、切换服务地址和进入其他页面保持选择。下述固定深色配色描述适用于黑夜主题，白天使用对应语义变量。
- 公共线性图标按实际可见轮廓收紧 viewBox，保留描边安全边界并等比居中，避免源 SVG 留白造成同尺寸不同视觉大小；公共静态描边采用非缩放描边，默认 1.5px，不因裁切放大而变粗。工作台、设置／模型、记忆、任务、文件预览与远程文件选择复用该规范；填充图标、批注及指定状态动效保留专用绘制规则。图形尺寸与交互热区分开：底栏普通图标统一16px，数据图形20px，工具栏静态线条采用1.2px非缩放描边，可点击入口至少44×44px，间距由控件布局负责。
- 所有应用页面与桌面控制页统一隐藏横向和纵向滚动条及其轨道，不为滚动条预留空槽；覆盖聊天、侧栏、输入框、设置面板、弹窗、下拉菜单、表格和长输出。内容溢出时保留原滚动区域及滚轮、触控、键盘滚动能力。
- 从设计中的 CSS 提取变量，不引入组件库默认主题替换原样式。工作台响应式规则限定在聊天与工作台容器内，配置概览、模型服务和工具页保留共享配置布局，不互相覆盖顶栏间距和内容网格。输入区按实际可用宽度调整模型选择与发送按钮的排列，长模型名省略，保留文字输入空间；短窗口下限制输入区高度并保留内部滚动，长草稿不挤空消息区域。
- 显示与阅读保留阅读偏好和当前效果预览；字体选择保留默认／系统／衬线／等宽预设，通过“浏览字体库”进入原生模态窗口。参考 Penpot 的紧凑搜索与字形样张、Gutenberg 的独立字体管理，以及 Google Fonts 的语言／风格筛选和自定义试阅。桌面左侧是搜索、语言／风格筛选及60项分页列表，右侧是相邻详情、可编辑样张、字号与下载／使用操作；手机全屏列表→详情→返回，保留查询和位置，Esc关闭后回焦点。目录固定1,942个免费字体家族（26款标注支持中文），记录完整TTF／OTF路径、大小、许可和版本；列表可见名称及未下载字体的详情均请求Google CSS2 text字形子集，只有显式下载才取完整字库；列表失败回退可读名称，详情失败提示重试而不隐式全量下载。详情文字发送至Google Fonts，界面明确提示；编辑300ms防抖、输入法组字暂停请求、空文本不请求，独立预览家族不参与完整字体缓存或保存。支持导入TTF／OTF／WOFF／WOFF2，30 MB上限；IndexedDB保存字节，启动时恢复FontFace，代码保持原等宽字体。预览临时加载，不加入字体库或改变当前选择；下载只保存，显式点击“使用字体”才应用，导入也不自动应用。完整下载提供进度、取消、180秒超时和重试；详情子集20秒超时、字形512KiB上限，切换候选、手机返回列表及关闭时取消预览并回收字形；事务提交前取消导入不保存。移除当前字体恢复默认，恢复默认保留字体库，同源窗口同步。手机输入区固定40px高、14px字号、22px行高，模型浮层保留页面倍率。不修改 `ui/`。来源、参考链接和验证边界见 [字体库说明](font-library.md)。
- 附件文字镜像与原生输入框使用相同字体、换行规则及双向滚动位置，手机单行输入不被镜像改成多行。文件补全、任务进度浮层及聊天模型菜单按入口与可视视口定位，避开输入区和工具栏滚动裁切；子会话浮层保留对应弹窗归属，支持触控选择与键盘操作。模型菜单限制在可视高度内，设置侧页中的模型菜单保持内联并随正文滚动。聊天模型菜单采用紧凑搜索、48px 双行模型项和紧凑操作区，桌面最大宽384px、高560px（仍受可用视口限制）；桌面长名称省略但完整名称／供应商／ID保留在焦点与悬停提示中，触屏名称与供应商完整换行。模型名称基准字号12px、供应商10px；思考等级基准10px并按容器宽度收敛，固定一排七个等宽位置，不足七档时保留末尾空位，不把未支持的等级变成选项；窄屏不再切为三列，完整等级文字不裁切；模型列表优先占用剩余空间并独立滚动，触屏控件保留44px高度。运行提示简述下次执行生效、当前追加不变，点击或键盘展开可读取当前执行的供应商／ID／等级。
- 保留悬停、焦点、禁用、空态、错误、加载、选中、折叠、弹窗和确认取消行为。列表与卡片的选中态采用背景、文字或完整细边框区分，不额外添加左侧强调条、加粗边线或单侧内阴影。
- 悬停说明统一使用应用内深灰提示，采用低对比度 1px 边框、8px 圆角、柔和阴影与 12px 浅灰文字，不使用系统原生 `title` 提示。鼠标停留 450ms 后展示，键盘聚焦时可读取；支持长路径换行、视口边缘避让和弹窗内显示，移入提示可继续阅读、选择和复制文字；键盘焦点仍在触发控件上时，无关鼠标移动不关闭提示。外部点击、输入、Escape、页面滚动或窗口失焦时收起，不改变布局或抢占焦点。
- 普通用户消息与用户发送的 Steering／追加消息（包括历史记录）统一采用用户气泡，系统通知不作为用户消息；气泡采用低饱和绿色背景与细边框，保持原有靠右布局、圆角与正文颜色；图片附件采用独立浅蓝色图标＋编号标签，与绿色气泡和正文区分，不改变全局强调色。
- 页面分别实现，组件可以复用，但不能将全部页面合并为一个巨大组件。
- 数据接入后用真实内容替换演示数据；“本地演示”“尚未连接”等说明按实际能力改成准确的状态文案，不改变原有信息层级。
- 输入框支持中文输入法；组合输入期间 Enter 不发送。Enter 发送、Shift+Enter 换行与设计保持一致。
- 弹窗有可访问名称、键盘关闭和焦点恢复；菜单与按钮保留键盘导航、标签和可见焦点。
- 配置表单的单选下拉（资源作用范围／安装方式／包内技能、OAuth 供应商、接口协议、请求体字段、认证选项及浏览器窗口模式）使用应用内菜单，与输入框对齐，优先下方展开，空间不足时向上避让。菜单限定在可见视口内并独立滚动，长选项换行；弹窗内菜单保留弹窗归属且不被祖先裁切。方向键、Home／End、文字匹配移动候选，Enter／空格确认，Escape 取消；Tab、外部点击及窗口失焦收起；页面滚动时菜单继续跟随入口，入口完全滚出视口或被滚动容器裁切后收起，取消不改变已选值。
- 产品确认操作使用沿用设计变量的应用内弹窗，不使用浏览器原生 `alert`／`confirm`／`prompt`。单击会话／工作空间的垃圾桶或使用键盘删除时，展示目标名称及完整影响说明，默认聚焦“取消”，Esc 取消，确认前不发送命令；双击垃圾桶直接删除，无需确认。鼠标单击等待 500ms 识别双击，双击取消待打开的弹窗，按钮／窗口失焦、页面隐藏、Esc 或卸载取消等待；键盘激活直接打开确认框。提交期间避免重复操作；确认删除失败在弹窗内展示原因，双击删除失败使用页面错误提示并允许重试。文件／目录选择仍使用系统选择器。
- 图像、SVG 与 Markdown 渲染保留必要许可证，过滤不可信 HTML 和危险链接。
- 纯图标操作统一使用独立中性灰色，悬停或键盘聚焦具体按钮时提亮并显示浅灰底，键盘操作保留可见焦点；禁用按钮不提亮。复制、编辑、关闭、置顶、刷新、附件移除和工具栏入口共用此规则，收藏、复制结果等状态保留各自语义色；输入框底栏整排图标（含进度、低缓存、压缩运行／失败、选中及展开）统一使用系统灰色 `#8a8f98`，悬停／键盘聚焦提亮，状态通过比例、形状、动画及选中背景区分；上下文占比弧与内部任务已达阶段保持橙色，不随按钮灰度或悬停规则丢失；缓存图标仅闪电部分例外，读取占比大于90%为绿色，大于70%且不超过90%为橙色，70%及以下为告警红，未知保持灰色，悬停／聚焦时闪电保留语义色。发送／停止主按钮及图片内容保留专用样式。模型列表进入行或键盘聚焦行内操作时显示灰色图标，正在编辑的模型行保持浅灰底与可见操作，图标显隐不挤动文字和行布局；触屏／粗指针下模型、会话与工作空间的行操作常显，并提供至少 44×44 px 点击区域。
- 删除图标统一使用用户指定的垃圾桶SVG路径，viewBox按可见轮廓收紧为 `3 2 22 24`，通过公共 `DeleteIcon` 组件复用，保持 `currentColor` 填充且不叠加描边；覆盖会话、工作空间、模型、配置覆盖项及附件移除。可用按钮悬停或键盘聚焦时图标变为灰玫瑰红 `#d99595`，禁用及 `aria-disabled` 状态保留中性灰色。

视觉验收覆盖：360×800、390×844、430×932、600×960、820×1180、1024×768、1366×768、1440×900、1920×1080。页面不得出现无意的横向溢出；代码块等内容可以在自身区域横向滚动。

### 2.3 工作台行为

- 侧栏顶部移除Logo、AXIOM 2字标及副标题，新建会话位于工作空间选择器上方，与右侧收起侧栏按钮同一行。新建入口仅图标与文字，无边框和常驻／交互底色；图标常态为灰色，悬停／键盘聚焦／按下时为原主题暖橙色 `#fcbc7c`，文字提亮，保留可见键盘焦点和至少44px点击高度。新建图标保留05号Phosphor `note-pencil` 的纸笔造型，改为圆角端点／连接与1.25px非缩放细描边，外框转角柔和；viewBox贴合路径边界为 `3 3 18 18`。新建和工作空间图标统一16px，文字14px／20px行高，图文间距10px，两行文字起点和图标中心对齐。工作空间恢复原设计带横线的文件夹，“打开文件夹…”使用同款后盖与倾斜前盖的展开图形（参考04号Tabler `folder-open`）；工作空间入口、菜单项及打开文件夹的图标常态为灰色 `--muted`，悬停或键盘聚焦时提亮为 `--fg`，禁用入口保持灰色；菜单内图标16px，打开文件夹文字13px／20px行高。右侧收起图标宽18px、下拉箭头宽12px，中心对齐，侧栏局部线性图标采用1.25px非缩放描边。新建、文件夹、搜索、收起和下拉图标的画布贴合路径边界，非正方形图标按原比例设置宽高，去除画布内额外留白；描边允许溢出以保留完整圆角与抗锯齿，不缩小点击区域。桌面收起后焦点回到展开入口，重新展开后回到侧栏收起按钮；手机抽屉、焦点恢复、新建会话和草稿保护沿用现有行为。

- 置顶会话跨工作空间统一显示，不按空间分组；普通会话列表限定当前工作空间。搜索覆盖全部置顶会话及当前空间的普通会话。点击置顶会话只切换当前打开的会话，保留侧栏选中的工作空间、普通会话列表和搜索内容；置顶条目下方显示所属工作空间路径，过长时省略并可悬停查看完整路径。会话标题栏路径、消息、输入、重命名、取消置顶和删除仍使用会话的实际归属；新建会话使用侧栏选中的工作空间。刷新分别恢复侧栏空间与打开的会话，跨空间查看不修改最近工作空间偏好；会话退出置顶区后仍保持打开，删除后回退到侧栏空间的可用会话。
- 运行中（主执行启动／运行／停止中或仍有活动子任务）和未读会话跨工作空间自动进入顶部“置顶”区，自动置顶排在空闲的手动置顶会话前；同级按最近更新时间倒序，每个会话只显示一次。运行中会话始终保留在置顶区，不参与冷却倒计时；启动、运行、停止中及仍有活动子任务均视为运行中，已有冷却取消，旧的已回队状态不阻止自动置顶。执行全部结束后，未读会话继续保留置顶；已查看且已读的空闲会话采用 5 分钟冷却回队，点击、输入或重新查看续期；当前会话在可见且聚焦的窗口中打开时持续视为正在查看，最后一个前台查看窗口切换会话、失焦、隐藏或断连后才开始完整的 5 分钟倒计时。到期后回到所属工作空间普通队列；新的执行、活动子任务或未读结果重新自动置顶。手动置顶标记独立且不受冷却影响。冷却状态保存在服务端，页面刷新／服务重启后恢复；查看状态按连接独立登记，不切换其他窗口；查看保护使用实际连接状态和连接代次，订阅错误提示不会解除前台保护，重连后只恢复当前查看目标，不重发 Agent 操作。普通区仅显示当前工作空间的其余会话。状态更新不切换当前会话；行内重命名、删除点击等待、确认或提交期间暂缓该行跨组移动，操作结束后应用最新分组。
- 会话列表的运行／待阅读状态图标放在会话标题前，使用 8px 图标框，进行中为绿色，待阅读为蓝色。当前打开的会话立即隐藏蓝色待阅读图标，运行中的绿色图标仍显示；已读回执仍在结果实际可见后确认。进行中为静态绿色实心点；待阅读为固定蓝色实心点加径向光晕，只有光晕透明度以 3 秒 ease-in-out 周期在 0.25–1 之间变化，圆点和光晕均不缩放、不收缩、不位移。保留 8px 图标框和 6px 标题间距，光晕可超出图标框但不改变布局；各实例使用独立渐变 ID。减少动态效果设置下停止光晕循环，保留透明度 0.65 的静态光晕。
- 主会话首次发送时以用户输入的前60个字符作为临时标题，折叠空白并去掉图片占位符；纯图片输入使用图片占位名称。会话标题改为独立无工具、无历史模型请求，使用当前主会话模型，以有效的 `MEMORY.md` 和其中编号关联的详情段作为数据输入；不读取原始对话，不执行材料中的指令。每3次主模型请求边界检查一次，成功结算时补查；只有标题pending、记忆有实际内容且没有在途标题请求才调用，空文件、注释和空占位模板不触发。完整捕获材料并校验修订，总预算128000字符，超过预算或缺失详情则安全跳过，不发送截断资料。结果必须为单行纯标题且≤13个Unicode字符（字母、标点、空格均计入），不完整结果不采纳；一次成功即持久化定案，手动命名由数据库CAS优先。每轮最多尝试3次，后续新运行恢复重试；请求含排队30秒上限，失败不阻塞主任务。停止、删除、退出供应商或关闭会取消相关在途标题任务，迟到结果不覆盖。标题费用独立标为“会话标题”，不混记为记忆查询或整理。不再向主历史追加命名指令、标题结果或结束提醒，也不采纳主代理回复中的标题标签；旧历史不重写，展示层保留既有标签投影。子会话不参与。标题变更通过会话局部订阅同步到列表、置顶区和当前标题，不打断输入或切换查看对象。
- 会话行通常为切换会话的按钮；双击或聚焦后按 F2 原位切换为标题输入框，不使用省略号管理入口或重命名弹窗。Enter／失焦保存，Escape／空白标题取消；输入法组合输入期间 Enter 不提交，组合输入期间失焦延后至组合结束再读取最终文字保存。粗指针设备上侧栏搜索和行内重命名输入使用至少 16px 字号。
- 删除按钮直接位于置顶按钮旁，操作区相对整行垂直居中。两者平时隐藏且不可指针点击，悬停会话行时显示灰色图标；悬停或键盘聚焦置顶按钮时提亮，删除图标变为灰玫瑰红 `#d99595`，键盘操作保留可见焦点。操作区绝对定位，桌面平时不预留文字宽度；显示时标题与状态文字收窄并省略长文本，避免遮挡且不改变行布局；触屏／粗指针下操作常显，并为扩大后的点击区域预留文字避让空间。
- 工作空间切换只改变查看对象，不停止后台 Agent。菜单展开后点击外部区域自动收起，点击菜单内部或删除确认弹窗不触发外部收起，也不阻止外部控件响应本次点击。工作空间列表沿用会话行的灰色悬停操作区及整行垂直居中布局，仅提供置顶／取消置顶和删除按钮，不显示铅笔重命名按钮；双击名称或聚焦后按 F2 在行内重命名，支持 Enter／失焦保存、Escape／空白取消及输入法组合输入保护。置顶空间优先显示，改名不改变目录路径。
- 删除工作空间支持单击确认或双击垃圾桶直接移除，语义是从列表移除，不删除项目目录或会话历史；隐藏空间的会话不再出现在跨空间置顶列表。存在活动执行、排队任务或后台压缩时拒绝移除并提示先停止。重新选择同一目录即可恢复原工作空间标识、名称、置顶和历史。
- 服务端在后台尽力保存最近使用的工作空间及最近主会话；偏好保存超时、断线或失败不显示全局错误条，不阻塞当前查看与会话操作，也不自动重发。仅已确认保存的位置承诺跨窗口恢复。新打开浏览器查看实例或 Pake 窗口时分别恢复侧栏空间和查看会话，不要求重新选择目录；同窗口刷新优先保留本窗口的有效会话位置。会话恢复作为现有工作空间偏好快照的可选字段交付；旧服务未提供时仍恢复工作空间并允许正常选择与新建，不能等待新增订阅而阻塞导航。其他窗口更新最近使用偏好不能切换当前窗口。当前空间已移除时选择剩余有效空间，无空间则展示空态；恢复只切换查看，不启动任务。
- 新建入口（按钮、快捷键、打开工作空间及空态模型选择）按侧栏工作空间复用唯一的未开始对话的新会话，重复点击跳转同一会话，连续点击和多个查看窗口同时新建不重复插入。可复用会话必须未删除、保留默认标题且未手动命名、没有执行记录、pi 文件绑定或子任务；草稿、附件和模型选择随原会话保留。已开始对话或手动命名后可再新建；旧数据已有多个空白会话时复用最近一个，不自动删除历史条目。新建入口通过 `session.create({reuseEmpty:true})` 在同一数据库事务内查找或创建。新建会话即写入 SQLite 并取得稳定标识，附件读取与草稿状态绑定工作空间／会话；新建、读取、保存或恢复草稿均不创建 pi 会话或启动 Agent，首次发送请求时才准备 pi 会话并启动执行。
- 标题前不再显示连接图标；浏览器仍保留辅助技术可读取的连接与业务诊断状态。桌面顶栏左侧仅显示后台连接状态，品牌保留在独立连接页；状态使用用户原先提供的心跳波形 SVG（24×24 viewBox、1.52单位圆角描边，显示为22px／窄窗20px及18px）；连接图标在已连接时为绿色 `#68bf7c`、实际断开时为红色 `#e08a8a`，证据不足时为灰色 `#989fa9`；后方状态文字始终为浅灰色 `#aeb6b0`，不随连接状态变色，分别显示已连接／已断开／确认中。右侧“服务与更新”与左侧连接状态垂直居中，使用44px热区和随文字字号等高的横向调节图标（宽高均为1em，桌面12px、650px及以下11px），采用用户选定的05号 Lucide `sliders-horizontal` 原始路径及1px非缩放细描边，常态为灰色，常态及点击均无底色和边框，仅悬停／聚焦时暖橙提亮。发现较新版本或业务连接状态发生明确变化时显示提示点，进入控制页后清除本次提示；未知状态和普通轮询不产生新提示。已连接不代表模型供应商调用已验证。
- 主会话空闲而子任务仍运行时，侧栏仍展示活跃任务状态。
- 子任务运行状态使用 Tabler `loader`（I12）原始路径配合 CSS 持续旋转，初始化、执行、总结及停止中沿用该运行标记；排队与终态静态。完成使用 Iconoir `badge-check`（C27）；取消、失败和中断使用 Tabler `alert-triangle`（F02），具体状态继续以文字、悬停和辅助描述区分。后台压缩入口与详情中的加载图标使用 Iconify `eos-icons:bubble-loading`：八个固定位置的气泡按官方 1 秒周期依次缩放，不旋转底色或状态文字；退出活动状态后移除加载动画。减少动态效果设置下仍播放该状态反馈。
- 未读状态与运行状态分开保存，不通过最后一句回复文本推测状态。侧栏使用活动优先规则：停止中、初始化、主执行（含重试／压缩恢复）、活动子任务优先于未读；有活动且未读时保留未读事实并在辅助说明中显示。主执行结束但子任务仍排队或运行，不显示整个会话已结束。连接中断保留上次已知状态，标记待同步。
- 结果使用 `resultVersion/readVersion`，`unread = resultVersion > readVersion`。主执行终态与子任务不可变结果分别按 runId/resultId 幂等计数；流式输出、重试倒计时不生成终态未读。`session.read({throughVersion})` 只单调确认已展示版本，旧窗口的确认不能清掉新结果。客户端须在可见、聚焦、消息区滚到底且未被遮挡、当前连接的消息及运行状态已同步、对应任务卡或通知已渲染时确认；恢复可见、聚焦和重连后重新判断。过程分段及最终回复的外层折叠均保留真实任务结果通知的挂载，普通思考与工具详情仍按展开挂载；满足原有阅读条件后，无需逐层展开过程即可确认已读。压缩移除旧子任务卡或通知时，消息展示层从同一会话当前分支补回仍未读结果的真实通知，保留原消息与结果标识，按原有阅读条件确认；不修改 pi 记录或模型上下文，不以压缩摘要代替结果通知。已确认的历史通知在下次消息缓存重建时不再补显；尚未实际送达的通知不能凭任务元数据推定为已读。打开会话只影响置顶冷却，新输入、后台通知唤醒及模型读取结果不代表用户已读。
- 删除会话支持单击确认或双击垃圾桶直接删除；先强制终止拥有的活动 Agent 执行，不增加 Agent 清理确认步骤，不因清理待核实记录阻塞删除。
- 删除会话采用逻辑删除，从普通列表及执行入口移除；保留原始 pi JSONL、实际文件绑定、会话记忆、子任务结果与托管附件及其授权，不删除项目目录或 Agent 已经产生的项目文件。记忆来源使用专门的归属读取边界，普通会话恢复／执行仍拒绝已删除记录。
- 主／子 Agent 系统提示词统一追加：`引用本地文件时，使用 Markdown 链接 [文件名](路径)`。

新增工作空间直接由本地服务打开系统文件夹选择器，不要求手动输入路径。选好目录后默认授予项目访问权限，直接登记／恢复工作空间并创建会话，不再展示路径确认或授权弹窗；取消选择不创建工作空间或会话。选择及打开期间避免重复提交，失败显示明确错误并允许重试；旧服务返回空白 404／405 时提示重启本地服务，不直接显示 JSON 解析异常。浏览器文件选择 API 不能可靠提供服务端项目绝对路径，不能用上传文件替代工作空间目录选择。所有系统文件／目录选择复用统一打开组件：`kind=file|folder|mixed`、`multiple`、标题与初始目录；工作空间用目录单选，主／子附件用混合多选。所有选择窗口打开时居中；Windows 以点击时前台应用所在显示器的可用区域为中心，使用原生 DPI 坐标并限制窗口不越出工作区，阻止 Explorer 初始化时的记忆位置覆盖，之后允许用户正常拖动／缩放；macOS／Linux 调用原生居中接口。Windows 使用 Explorer `IFileOpenDialog`，macOS 使用 `NSOpenPanel`，先完成独立 AppKit 宿主初始化，再将居中的面板设为键盘窗口，只在模态会话内请求激活宿主：会话开始前主线程阻塞于连接远程面板，此时激活会使宿主成为前台却无法读取事件，鼠标移动溢出事件缓冲后激活通知被丢弃，宿主保持未激活、远程面板忽略全部点击且后续请求无效；会话内重复请求，直到宿主激活且面板为键盘窗口，成功即停止、重试有上限，不持续抢占焦点；Linux 使用 GTK 3 文件选择器（Python 3／PyGObject）；无图形桌面或缺少依赖时明确说明。浏览器与 Pake 共用本地服务，不各建实现。各用途共用一个活动窗口，取消／超时／退出后等待拥有的宿主进程退出才释放位置；Windows 原生宿主编译以编译进程退出状态及生成文件为结果；确认编译进程退出后释放其标准输出／错误管道，继续等待真实 `close` 完成结算，避免继承的输出句柄阻塞服务启动；取消和超时同样等待拥有的编译进程退出与关闭。Windows 宿主被终止或服务关闭时，确认真实进程退出后释放其标准输入／输出管道，继续等待真实 `close` 完成清理，避免继承的输出句柄阻塞关闭；正常请求保留输出直到 EOF。服务端统一复核真实绝对路径、文件／目录类型、数量和重复项，工作空间授权及附件归属仍按各自用途校验。

标题栏“打开系统文件管理器”保留独立浏览语义。Windows 服务启动时另行预热单次使用的 Explorer 自动化宿主；请求只携带已登记工作空间的有效目录，经 JSON 管道传递。按完整文件目录、Explorer 窗口类型与当前标签标识匹配：仅在当前活动标签显示目标目录时复用、恢复并居中，核实浏览器标签 HWND 与当前标签相同，不能仅凭顶层 HWND 或标签可见标记判断。目标只在 Windows 11 后台标签页中时直接新开目标目录窗口，保留原窗口的当前目录与位置；标签显示名可能来自本地化或 `desktop.ini`，即使唯一也不能证明目录身份，不按显示名称选择标签。Shell 自动化准备在宿主就绪前完成，等待请求期间 STA 继续处理 Shell 消息。等待实际窗口可见、位于当前显示器工作区中心且 `GetForegroundWindow()` 确认为目标窗口后才返回成功。激活调用后以 200ms 为限轮询前台标识，期间处理 STA 消息；随后重新核对完整目录、当前标签与实际矩形，不能把定位或激活 API 调用成功当作最终状态。缺少可交互前台窗口时，在创建或移动 Explorer 前拒绝请求；系统拒绝激活时返回 503 和明确的桌面连接／解锁重试提示，不误报成功，不通过模拟输入或附加其他应用输入队列抢占焦点。最小化／最大化恢复同样核实前台标识及实际位置；不移动无关目录窗口。打开期间前后端阻止重复请求，断线／超时／退出清理拥有的辅助进程并等待退出；已打开的 Explorer 由用户继续使用，不随服务关闭。该入口的 Windows 成功验收须覆盖真实按钮、关闭后重开、已有窗口恢复、后台目录新开与显示名不等于文件夹名的多标签场景，每次到前台且居中低于 1,000ms，并验证原窗口当前目录与位置不变。计时前确认桌面已连接、解锁且存在前台窗口；无输入桌面的可见标志与矩形检查不能代替此验收。另覆盖拒绝激活后的错误提示、重试及输入保留；macOS／Linux 保持系统默认打开命令，其独立文件管理器居中尚未实现。

## 3. 系统结构

```text
浏览器 / Pake
       │ HTTP：页面、附件、资源
       │ WebSocket：命令、回执、状态、输出
       ▼
Axiom 服务
  ├─ 工作空间与会话归属校验
  ├─ Agent 进程管理、任务调度、结果通知
  ├─ pi 模型配置与认证管理
  ├─ SQLite、会话索引与附件
  └─ 独立 Agent 工作进程
        ├─ 一个 pi SDK 会话
        ├─ 对应工作目录与明确的会话文件
        ├─ pi 基础工具和默认授权加载的项目扩展
        └─ 主 Agent 的四个子任务工具
```

### 3.1 技术选型

- 前端：React、TypeScript、Vite。
- 服务：Node.js、TypeScript、WebSocket。
- Agent：独立 Node.js 子进程承载 pi SDK，会话通过公开 API 创建和操作。
- 存储：SQLite 管理应用数据，pi JSONL 保存对话上下文。
- 桌面：Pake 作为同一 Web 产品的外壳，不另建一套桌面业务代码。
- 依赖锁定到实际验证过的组合；升级依赖需要重新执行模型、会话、工具和取消验收。

不同时维护另一套 Agent 运行后端，不解析终端输出模拟事件，也不修改 pi 依赖源码。

### 3.2 职责边界

| 部分 | 负责 | 不负责 |
| --- | --- | --- |
| 前端 | 页面、交互、草稿、局部订阅与展示 | 直接读取凭据、调用供应商 API、决定任务归属 |
| Axiom 服务 | 管理数据、进程、命令校验、结果通知、配置发布 | 重写模型协议、推理循环和上下文压缩 |
| Agent 工作进程 | pi 会话、工具执行、事件转换 | 操作其他会话状态、直接管理应用数据库 |
| pi 模型运行时 | 模型目录、协议适配、认证与模型请求 | Axiom 页面和任务列表 |

会话与子代理是 pi 的薄封装：发送请求优先复用归属、配置与持久文件仍一致的保活 pi 工作进程，冷启动才按绑定 JSONL 打开已有会话或创建首次会话；同一真实会话同一时间只允许一个活动工作进程和一个执行者。pi 绑定的 JSONL 是唯一上下文恢复来源，不用 SQLite 请求记录、草稿或另一份对话副本重建上下文。后台压缩允许另一个只处理独立快照的进程，不成为原会话的第二个写入者。不同会话可以并行。同一应用数据目录只允许一个服务进程持有管理锁，进程退出时锁由系统释放。成功执行结束后，合法的同会话绑定归还服务级统一 pi 执行池，和记忆／压缩共用物理容量、空闲保留及预热预算；容量须经生产基准校准，见[执行池说明](pi-execution-pool.md)。15 分钟未使用或初始化满 15 分钟的实例在空闲边界释放；运行中实例不参与普通 LRU 淘汰。进程退出中仍占物理名额并保有会话文件所有权，只有真实 close 才完成交接。失败、停止、撤权、关闭与不兼容配置淘汰进程。恢复必须指定对应会话文件，不使用“最近会话”推断归属。

## 4. 标识、配置范围与隔离

### 4.1 标识定义

| 标识 | 含义 |
| --- | --- |
| `workspaceId` | 已确认项目目录的稳定标识 |
| `sessionId` | 一个主会话或子会话 |
| `parentSessionId` | 子会话所属的主会话 |
| `taskId` | 一条可持续追问的子任务链，关联固定子会话 |
| `runId` | 一次执行；继续追问创建新的执行标识 |
| `resultId` | 一次执行的最终结果标识，结果发布后不可变 |
| `requestId` | 一次用户操作的幂等标识，重传必须复用 |

工具调用中的父会话和工作空间从注册工具时绑定的运行环境获取，不允许模型通过参数冒充其他会话。

### 4.2 配置范围

- 应用级：模型供应商与认证、子代理默认模型及思考等级、子任务并发和工作时限、模型收藏、新主会话默认模型及思考等级、连接设置、内置工具接入配置。
- 工作空间级：规范化目录、显示名称、项目授权、置顶、移出列表状态、会话集合；最近使用的工作空间标识作为应用级持久化查看偏好。
- 会话级：模型选择、思考等级、会话文件、运行状态。
- 查看实例级：当前选中的工作空间和会话、菜单打开状态、焦点、滚动与折叠状态。
- 会话未发送输入：文本及所选附件在前端按工作空间／会话缓存，并在后台尽力保存到服务端 SQLite；切换保留，确认保存后跨刷新或关闭恢复。草稿是辅助能力，读取／保存延迟、失败、旧服务缺少接口或修订冲突均不得阻塞输入、附件、发送、停止和会话切换；不常驻展示加载、已保存、读取失败或重试提示。父／子会话独立，多窗口同时编辑同一会话时校验修订，仅真实冲突提供选择；迟到恢复不得覆盖已编辑或已提交的输入，冲突不阻止继续发送。草稿读取、保存和恢复不启动 pi；新窗口同时恢复最近主会话，窗口内已有查看位置优先。未确认保存的内容不承诺跨刷新恢复。模型配置草稿仍按自身契约处理。

应用级模型服务可以共享，但 Agent 上下文、当前模型选择和消息队列不能跨会话共享。不同标签页的导航不互相切换。

### 4.3 服务端约束

- 目录经规范化与实际路径解析后登记，处理符号链接及平台路径大小写规则。
- 请求执行前校验工作空间、会话、子任务和执行的完整关系。
- 配置、任务状态与事件更新校验当前执行标识，丢弃不匹配的迟到回调。
- 消息、附件读取和模型确认均使用操作发起时的归属，不在完成时读取当前 UI 选择。
- 进程管理器只停止自己创建并记录的进程，不按模糊进程名批量终止。

上下文隔离不是文件系统沙箱。用户选择目录打开工作空间时默认授予编码工具项目访问权限，不额外弹窗确认。不同工作空间不会由 Axiom 误路由，但任意命令仍可能访问授权用户能访问的其他路径。

同一工作空间的 Agent 共享文件；子代理负责调研及执行测试，代码修改由主代理执行。独立测试优先并行委派，明确工作目录、命令或范围、前置条件与交付要求，并隔离端口、临时目录和输出路径；依赖同一构建产物或争用共享资源的检查按前置关系执行。测试期间不修改其覆盖文件，相关文件在结果产生后变化时重跑受影响检查；已验证且依据未变的检查无需主代理重复执行。主代理应用子代理建议前应重新读取当前文件，避免调研期间文件变化导致建议过时。多个主会话仍可能并行修改；原文不匹配的编辑必须失败并重新读取，不能宣称存在完整文件事务或自动回滚。

## 5. 模型配置与认证

### 5.1 唯一运行配置来源

Axiom2 默认复用终端 pi 的模型配置、模型目录缓存和认证存储（通过 getAgentDir()，可用 AXIOM_PI_DIR 覆盖），显式向各运行时传入文件路径。保存和退出登录也会影响终端 pi；应用设置、资源和会话仍独立。旧独立模型／认证文件不自动覆盖共享配置。

- `models.json`：pi 模型、供应商及覆盖配置。
- `auth.json`：由 pi 原生认证接口管理，API 密钥的唯一保存位置。操作模型配置时，已有 auth 凭据优先（包括 OAuth），删除 `models.json` 中重复的 `apiKey`；只有 models 中有密钥时，经 pi 保存并核实落盘后再移除旧字段。保留密钥中的环境变量／命令表达式，解析与命令缓存遵循 pi 的 auth 存储规则。迁移与保存共用串行队列，迁移期间检查配置与认证变更，失败保留尚未移除的旧密钥，不回显凭据。
- `settings.json`：需要的 pi 原生设置。
- SQLite 不存第二套模型定义或明文凭据；模型收藏仅保存模型标识。

界面是这些能力的编辑入口，模型推理与认证继续使用 pi，不建立自己的供应商 SDK 或 OAuth 交换流程。模型列表发现按连接的 Base URL 发起只读 HTTP 请求，认证与请求头由 pi 解析。

### 5.2 模型服务页面

配置概览、模型服务和内置工具共用同一配置样式入口与标题导航组件，沿用现有深色视觉与紧凑侧栏。三页统一侧栏宽度、56px 顶栏、面包屑、控件高度及响应式断点；800px 及以下统一隐藏主侧栏并将二级列表放到详情上方。模型服务与工具页不另加重复页面标题，二级列表与详情从同一水平线开始；详情标题、连接／模型页签正文和底部保存区共用左右边距与 920px 内容宽度上限，模型配置读取与保存结果放在底部保存区附近，避免普通提示条推移整页列表与标题；错误仍在页首警报区显著展示。工具页正文独立滚动，保存／放弃操作固定在正文下方，短屏与窄屏随内容滚动可达。表单按详情区实际可用宽度折行，覆盖项按自身容器宽度切换为名称／值上下排列，长路径与说明允许换行；短窗口中详情可整体滚动，保存操作必须可达。触屏保留至少 44px 操作热区，输入字号至少 16px，不禁用用户缩放。协议、OAuth 供应商与请求体字段保留标准原生 `select` 的键盘和系统菜单行为，仅统一关闭状态的外观，不依赖 `base-select`、CSS 锚点或特定系统的选项高度。概览仅在配置读取完成后显示可用数量，读取失败使用警报；存储说明明确聊天草稿自动保存到 SQLite，重新打开可恢复已保存内容，首次发送时才启动代理。

保留供应商列表、搜索、连接配置与模型配置页签、行内编辑、覆盖项编辑、未保存标记及统一保存。统一操作区紧随当前配置内容和状态提示，仅含「保存」「取消」及图标式「重新读取」；连接表单和模型列表按内容自然高度排列，不撑满剩余视口或把按钮推到窗口底部，长内容随详情区整体滚动；重读采用共享 `rotate-cw` SVG，保留可访问名称与悬停提示，右上角不放配置操作按钮。沿用深色表面与暖色强调色，供应商与内置工具选中项采用浅色背景和完整细边框，不添加左侧强调条；页签和草稿标记使用细线／圆点；认证状态仅表示凭据配置，不表示远端调用验证。连接表单按标识／名称、协议／地址、密钥分组，密钥通过统一保存发布，不提供独立 API Key 登录入口；密钥旁提供即时「退出认证」，凭据路径位于「凭据存储位置」展开项。新建自定义接口聚焦供应商 ID。列表中的供应商长名称最多显示两行，完整名称保留在提示与详情；窄屏供应商区按内容高度排列，模型搜索独占一行；供应商及模型搜索无匹配时提供清除入口，清除后焦点回到搜索框。

- “完成编辑”仅暂存并结束行内编辑，配置下方“保存”才发布配置。统一保存必须包含尚未收起、或被连接页签隐藏的行内编辑；无效／重复 ID 保留输入、返回模型表单并聚焦 ID 字段，不能漏存。完成、保存、切换供应商复用同一草稿合并规则。
- 模型 ID 与显示名称使用两列布局，窄屏按设计折为单列。下方独立展示「输入能力」：文本为默认能力，图片以带简短说明的整行可点击开关卡片配置，键盘焦点清晰；两项宽屏并排，窄容器纵向排列。只提供当前支持的文本与图片输入，不把能力声明当作远端验证。思考等级多选占满行宽，使用与会话菜单一致的纯文字选项，选中为扁平橙底深色字，不显示方框勾选装饰或底部粗线／内阴影，悬停与按下轻微提亮；保留多选、再次点击取消、键盘焦点与可访问分组说明。至少保留一个等级，不使用思考时选择模型支持的 none。
- 模型列表在名称下展示「仅文本」或「文本 + 图片」能力摘要；列表与拉取目录中的思考等级使用逗号分隔，窄屏摘要自动换行。目录导入保留模型的原生输入能力。
- 模型名称与 ID 分别提供复制动作，复制完整原值而非截断文本；显示成功／失败反馈，窄屏与键盘操作可用。复制不修改配置。
- 切换供应商先合并有效行内编辑并保留其他供应商草稿；无效编辑阻止切换。离开模型服务页、刷新或关闭页面直接进行，不弹出页面离开确认或浏览器未保存提示；未保存草稿和临时密钥不自动保存，返回时读取已发布配置。主动放弃编辑仍明确确认。
- 密钥字段支持替换与显式清除；掩码和空白占位不能被误保存为新密钥。保存并重读成功后清空临时明文输入，以占位掩码和“已保存到本地”状态表达持久化结果；OAuth 凭据单独说明。页面状态区持续展示结果，错误不能只放在页尾；失败保留草稿。错误提示使用高对比度浅红色（`#fca5a5`）、加粗文字及红色边线／背景，并提供警报语义；普通状态和保存成功恢复各自样式。配置校验失败须说明供应商名称／ID、相关模型名称／ID、错误字段与可行的修正方式；请求头／请求体覆盖项标明行号，请求体数值错误标明字段名，不回显密钥、请求头值或含凭据的地址。连接页展示当前 `models.json` 与 `auth.json` 的实际路径，避免与旧独立目录混淆。
- 自定义 API 连接在 auth 与 models 中均无密钥，或已存密钥无法解析时，显示可编辑的配置错误并在拉取前拒绝请求；环境变量或单独请求头不能代替 auth 中的密钥记录。仍可保存未完成配置并补填密钥，显式退出认证保留配置并显示缺失状态。OAuth 连接按其登录状态处理，不要求补填 API 密钥。
- 保存成功不等于远端认证或模型请求成功；分别展示配置有效性、认证状态与运行错误。
- 供应商旁的「+」向右下方展开菜单，靠近窗口边缘时向内避让、下方空间不足时向上展开，菜单限高并独立滚动，选择「OAuth 登录」或「自定义接口」，不弹新增供应商对话框。菜单支持外部点击、Tab 离开和 Escape 收起，Escape 恢复加号焦点，方向键切换选项。OAuth 在页面内用应用内下拉框列出后台 pi 支持 OAuth 的供应商，选项只显示供应商名称、不拼接协议或 ID，内部仍使用原始 ID 发起认证；新增连接隐藏 `openai-codex` legacy 选项，OpenAI 只保留统一登录入口，已有 legacy 配置及重新登录能力保留；Kiro 名称统一为 `kiro`，仅认证的限制仍在连接详情说明，不通过名称拼接表达。Qoder 国际版和国内版默认列出为 `Qoder`、`Qoder 国内版`，不加实验性后缀，也不通过环境开关限制注册、认证、模型目录或推理；真实账号未验收作为文档验证边界保留。选择后点击「浏览器登录」。缺少能力时禁用下拉及登录并提示更新或重启后台、重新读取配置。授权状态、链接、回填、取消及完成提示均在页面内展示，不使用 OAuth 登录弹窗；失败和断线显示警报，终态隐藏已失效的链接与输入；认证期间禁止切换供应商、再次添加、手动重读或发布配置。不要求先保存供应商、填写 API Key、地址或协议；登录成功后从 pi 凭据存储导入并选中供应商。OAuth 连接面板只提供名称、认证状态、重新登录及退出移除；自定义接口保留地址、协议、密钥及覆盖项编辑。新 OAuth 连接保存模型时不生成 `api`、`baseUrl` 或 `apiKey` 覆盖；已有自定义覆盖保留并明确提示。默认应用目录与指定共享 pi 目录遵循相同导入规则。预置模板本身不自动变成可选模型，已登录账号按原生可用目录提供模型。内置模型保留 pi 原生能力与计费元数据。
- 模型配置页提供「拉取模型列表」：先保存或放弃连接草稿，自定义／API Key 连接根据已保存 Base URL 请求模型列表，保留代理路径和已有版本段；OpenAI Completions／Responses 请求 `<baseUrl>/models`，Anthropic 使用 `/v1/models`（在代理前缀后补缺少的 `/v1`），Google 使用版本地址下的 `/models`（根地址补 `/v1beta`）。密钥和供应商请求头由 pi 解析，按协议使用 Bearer、`x-api-key` 或 `x-goog-api-key`，已配置请求头优先；保留供应商 `authHeader` 与自定义请求头，不跟随携带凭据的重定向。模型 ID 与名称只取自接口响应，不向 pi 公共目录获取或补充 ID，不从目标 `models.json` 的 `models`／`modelOverrides` 补回模型或覆盖元数据；可对接口已返回的 ID 使用 pi 原生能力资料，未知能力显示待确认，加入草稿时默认仅文本、不启用思考，用户可编辑确认。不使用接口未返回的模型。没有自定义端点的 OAuth 连接与 Radius 网关继续通过 pi 原生发现，明确标注原生目录可能包含内置或缓存项，不宣称是 Base URL 的在线返回。Base URL 请求超时、鉴权失败、不支持列表接口或格式错误均明确报错，不回退到缓存、公共目录或目标配置，重新拉取先清空旧结果；读取失败与正常空列表互斥，不同时显示“0 个模型”或正常空态。列表读取限制为 15 秒网络时限、累计 2 MB、1,000 个模型和 20 页，校验分页游标，失败不返回半份列表；响应正文和认证值不进入错误提示。目录在工具栏下方就地展开，不使用弹窗，提供搜索、重新拉取、筛选内多选、收起及加入草稿；加入后统一保存才写入目标配置。收起或 Escape 恢复入口焦点；配置有草稿、行内编辑或等待对账时禁止继续加入，配置修订变化后重新加载目录。已添加项禁选；端点返回的模型使用当前连接协议，同名原生模型仅在协议一致时补充能力资料，新增同名异协议模型保存为自定义定义，不继承另一协议的能力或思考映射；已有模型的协议修改仍按原校验。OAuth 按模型原生协议选择。拉取前后均校验配置修订。
- 发起认证前须先保存或放弃已有配置草稿；没有草稿时可直接添加 OAuth 账号，不需要创建自定义接口占位。认证归发起连接所有，其他连接不能打开浏览器、回答或取消；断线、显式取消或超时终止流程，不自动重新登录。OAuth 收到授权链接后请求系统默认浏览器打开，并保留重开和复制入口；浏览器启动命令只接受当前流程 ID，从服务端取链接，不接受任意客户端 URL。自动回调、设备码轮询和手动回填由 pi provider 决定；前端按原生提示接收授权码或完整回调地址，文本提示允许留空以选择供应商默认值。登录完成后自动重读认证状态，失败保留待核实状态。仅展示完成步骤所需的授权链接、设备码与输入提示，不广播供应商任意进度／错误文本或保存认证输入。

### 5.3 UI 到 pi 的字段映射

| 界面内容 | 处理规则 |
| --- | --- |
| 供应商与模型 ID | 使用 pi 支持的 provider/model 标识；避免使用显示名称作为关联键 |
| 接口地址、协议 | 映射 pi 的 `baseUrl` 与支持的 API 类型 |
| 模型名称与能力 | 使用 pi 的 `name`、`input`、`reasoning` 等支持字段；输入能力保存为 `["text"]` 或 `["text", "image"]`，旧草稿省略时保留已有能力，未修改的原生能力继续继承目录；自定义定义与覆盖项重叠时按 pi 的覆盖优先级读取并更新，发布前校验实际加载能力与所选一致 |
| 思考等级 | 配置页可多选模型支持的等级，会话菜单单选本次使用的等级；通过 pi 支持的模型配置表达，不直接写入原型自定义字段 |
| 请求头覆盖 | 使用 pi 支持的 headers 配置，校验非法字符和重复键；敏感值脱敏 |
| 请求体覆盖 | 仅映射当前 pi 支持的覆盖字段和协议能力，例如受支持协议的 `samplingParams` |
| 供应商级通用请求体项 | 仅在 pi 能表达时保存；需要落实到各模型时使用 pi 支持的模型字段，不自建请求拦截层 |
| 模型级覆盖 | 在 pi 支持的规则内优先；不支持的字段应报错或禁用，不能保存后静默忽略 |

保留设计中的编辑布局，但不能为匹配示例文案伪造 pi 不支持的运行能力。等级配置以 pi 的 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max` 为边界；界面的 `none` 需要转换为适用的 pi 语义。使用受支持的 `thinkingLevelMap` 表达限制，不把多选结果直接作为一次请求的思考等级。空选或禁用思考须通过模型能力校验；不能让不允许关闭思考的模型产生虚假 off 选项。界面中的“自动”“开关”等选项也必须映射到实际能力，否则禁用并说明原因。

### 5.4 保存与生效

1. 前端提交配置草稿和读取时的配置修订标识。
2. 服务端检查修订标识、字段、重复 ID、URL、覆盖值与 pi 配置合法性。
3. 同一应用配置写入串行执行，避免多个页面互相覆盖。
4. 模型配置在同目录写入临时文件，验证后原子替换目标文件；保存前失败保留原文件。
5. 凭据保存调用 pi 原生认证能力，不自行拼接或覆盖凭据文件；API Key／OAuth 登录完成后，以新运行时重新读取本地凭据，确认对应供应商存在所选方式的凭据后才报告成功。
6. 刷新 pi 目录，计算可选模型，向会话和配置页发布更新。
7. 所有步骤完成才显示成功；分别报告配置写入、凭据变更或目录刷新失败。

配置文件与凭据文件不是跨文件事务。凭据已经改变但目录刷新失败时，应报告实际状态并重试同步，不盲目重做登录，也不假称全部回滚。配置发布／认证启动等外部操作先持久化请求哈希和受理状态，结果仅保存脱敏字段；重启时未确认完成的操作标为待核实，不自动重做。部分失败或回执不确定时暂停再次发布，显式重新读取并对账后才允许继续。读取到损坏配置时不得用空配置覆盖。

配置更新不得重建正在输入的表单。活动运行继续使用已经确认的模型配置；涉及认证撤销或删除的操作按删除流程处理。空闲时通过 pi 公开接口刷新、重设模型或重建同一持久化会话，不能仅刷新界面目录却继续使用过期运行对象。

### 5.5 会话模型菜单

```text
可选模型 =（明确配置的模型 + 未单列模型的供应商目录 + 已登录供应商目录）∩ pi 判定可用的模型
```

- 配置但没有所需认证的不显示；pi 已登录供应商可直接使用。
- 仅配置供应商时使用其 pi 原生目录，不要求重复逐个添加内置模型；收藏不能绕过认证。
- 删除模型后清除相关收藏，不自动选择其他模型替代。
- 列表为空时禁止发起模型请求，引导进入模型配置。
- 服务端执行同样的允许范围校验，不能通过直接请求绕过菜单限制。
- 能列出不代表远端密钥一定有效；实际调用失败如实展示。
- 菜单沿用工作台深色视觉变量，模型名称与供应商分行显示，长名称允许换行；选中标记和收藏操作保持独立。搜索无匹配时显示明确空态，模型服务入口固定在底部。
- 思考等级使用面板内平铺的单选项，不使用原生下拉菜单；选中项采用扁平橙色填充与深色文字，不使用底部粗线或内阴影，悬停／按下时轻微提亮，禁用时不触发悬停反馈；仅展示当前模型支持的等级，支持键盘焦点与方向键切换，窄屏自动换行。底部明确显示“取消／确认”，提交中显示“保存中…”并禁止重复确认；取消或 Escape 关闭后恢复入口焦点。

未打开工作空间时提供打开入口，不展示无法确认的模型菜单；已打开空间但未选会话时，确认模型先创建有稳定标识的会话，再保存选择。取消菜单不创建会话。

菜单选择为本地草稿，确认后等待服务端回执。主会话确认成功时，同时将供应商、模型 ID 与思考等级保存为应用级默认值，无需另行保存；新建主会话在创建时复制上次确认的选择，跨工作空间和服务重启后仍生效。默认值仅保存选择标识，不保存第二套模型定义，不覆盖已有会话。升级时若默认值为空，从现存主会话恢复最近确认的选择（优先按成功回执顺序，旧数据无回执时按选择记录顺序），排除子会话，不按消息或重命名更新的会话时间推断；已有默认值不覆盖。未保存过选择时保持未选模型。默认模型不可用时保留原选择，发送前要求重新选择，不自动替换。取消菜单或确认失败不改变默认值；子会话选择及默认子模型设置不改变应用级默认值。

运行期间允许选择下一次执行的模型和思考等级；当前执行不因菜单选择被中断或半途更换设置，同一次执行中的 Steering／追加消息仍沿用启动设置。显示当前执行的供应商、模型和思考等级，以及已确认的后续选择。切换后的首次实际模型请求开始输出时，在其对应用户请求上方显示紧凑通知，列出模型的供应商／ID 与思考等级的前后变化；只更改等级同样提示。首次选择、未发请求的菜单操作、未改变实际设置均不生成切换提示。无新用户消息的手动重试或系统唤醒，在其实际回复／执行过程上方提示。切换元数据随 pi 助手消息保存，实时与重载一致，不写入对话正文或供应商请求内容；压缩及原生重试排除历史时遵循当前消息投影，不单独恢复被隐藏正文。请求前的本地异常不触发切换提示或更新实际请求基准；切换后的失败／截断尝试被原生恢复移除时，后续保留的回复仍携带切换提示。

子代理默认模型与思考等级为应用级全局偏好；新会话首次发送前即可设置，不依赖 pi 会话初始化。设置可用性依据实际服务连接及全局设置读取结果，无关订阅诊断不禁用已就绪的设置；真实断线期间禁用保存，重连后恢复。未单设时在创建子代理时继承主会话选择。选择后自动保存，所有工作空间、会话及窗口共享，刷新和服务重启后保留；立即用于之后的新委派，不中断当前模型请求，不覆盖已有子会话的独立选择。升级时一次性迁移旧会话记录中最后存储的非空默认子模型；明确清除为继承后不会重新迁移。

全部子代理设置集中在输入框下方工具栏右侧的 Lucide `git-branch`（A01）分支图标内，删除原独立默认子模型块及配置概览的预算块。批注、子代理、压缩与全局记忆保留在右侧工具组，左侧保留用量入口；各入口44px，只收紧组内间距，容纳不下时仅工具条内部横向滚动。设置面板保持贴视口右边与顶边的非模态抽屉，最大520px、窄屏满宽，保留标题栏、正文独立滚动区、页脚与表单样式；两个面板底部均停在当前会话工具栏图标上方 8px，随窗口与工具栏布局变化更新，不覆盖图标或拦截其点击。再次点击当前图标收起，点击另一设置图标一次即可切换；主／子会话均适用。提供模型／思考等级，并以双列表单展示并发数和工作时限。点击面板外部、关闭按钮或 Escape 收起；关闭按钮与 Escape 恢复入口焦点，外部点击保留被点击控件的焦点和本次操作；面板内向外拖动不误关闭，模型菜单打开时 Escape 优先关闭菜单。数值输入完成后按 Enter 或失焦自动保存，错误明确显示且不写入无效值。通过 `task-preferences` 独立订阅同步全局设置，`task.preferences.get/save` 读取／局部更新 `{selection,budgets}`；局部更新不会覆盖其他窗口未修改的字段。

### 5.6 删除与退出登录

**删除模型或供应商必须执行 pi 的供应商级退出登录流程，不能只删除前端列表。**

- 自定义连接的「退出认证」立即调用供应商级清理，保留供应商和模型定义，清除受管理凭据、供应商及模型请求头覆盖、URL 内嵌凭据及参数；按钮附近说明影响。未保存草稿、行内编辑、认证进行中或待对账时禁用。复用完整已发布配置及页面修订执行，防止提交其他草稿或覆盖并发修改；活动执行须确认，部分失败或回执不确定后须重新读取，不能宣称已完整退出。
- 模型列表的垃圾桶单击确认、双击直接移出草稿；仍需统一保存并确认供应商级影响后正式执行。供应商删除使用独立确认操作。
- pi 的退出登录作用于供应商，不是单个模型。删除一个模型时，确认框必须说明同供应商其他模型也可能需要重新认证。
- 该供应商存在活动执行、排队子任务或后台压缩时，先说明影响，经用户确认后终止受影响的执行并取消排队任务；不能在拥有的执行仍活动时宣称删除完成，也不增加 Agent 清理确认步骤。所有类型先检查确认条件，不得先停止其中一种再要求确认其他类型。
- 先阻止受影响供应商的新请求，再调用 pi `ModelRuntime.logout()`，移除运行时认证覆盖及受管理的备用认证来源，移除目标模型／供应商配置并刷新目录。
- 删除单个模型可以保留同供应商其他模型的定义，但不能偷偷保留或重新注入刚退出的凭据。
- 外部环境变量等不由 Axiom 改写；如果它们仍能提供认证，应如实显示认证来源。已删除模型仍由明确配置范围排除，不能重新出现。
- 会话记录保留原模型标识用于查看，但发送前必须重新选择可用模型。
- 失败时保留错误和可重试入口，不将部分完成显示为完全成功。

### 5.7 凭据安全

- 密钥和 OAuth 令牌只进入服务端 pi 认证存储，不写浏览器持久存储、SQLite 消息、日志或附件。
- 前端仅展示是否已配置、认证方式和必要的脱敏信息；不回传已保存明文密钥。
- URL、请求头和配置错误信息均执行敏感数据脱敏。
- pi 支持的命令型密钥及请求头解析属于可执行配置，新增时须在发布入口明确授权；单独登录提示不直接接受命令型密钥。不能自动执行从不可信项目或页面导入的命令。
- 不承诺应用自带系统密钥库或磁盘加密；配置目录使用当前用户权限保护。

### 5.8 内置工具与 OpenCLI

「内置工具」是应用级配置入口，工具按条目呈现。首项 OpenCLI 提供本机环境检查、官方 npm 版本检查、安装／更新／重新安装、默认技能开关、Chrome 配置档案及窗口模式、扩展安装指引和主动连接诊断。使用现有配置页的侧栏、列表、表单与响应式行为，不改写 `ui/` 设计源。浏览器窗口模式使用与页面一致的不透明深色下拉浮层，避让视口底部且不受详情面板裁切；支持选中标记、方向键导航、Enter／空格确认、Escape 取消、Tab／外部点击收起及禁用状态。

- 使用 Node 绝对路径执行已定位的 `npm-cli.js`，参数数组不经 shell 拼接。安装仅接受官方 `@jackwener/opencli` 的已检查稳定版本，固定官方 npm registry，使用全局安装及 `--ignore-scripts`；不允许客户端传入可执行路径、包名或任意参数。npm 全局安装不提供事务回滚，失败后重读实际状态，不声称恢复旧版。
- OpenCLI 与其技能复用同一 npm 安装。主 Agent 通过 pi 的技能加载接口仅接入 `opencli-usage` 和 `opencli-browser`；不维护第二套命令 schema，也不注册原生 OpenCLI 工具。用同名管理条目替代运行时发现的旧技能链接，不覆盖、删除用户技能文件。开关只控制默认技能加载，不限制已有 shell 的能力。子 Agent 不加载这两个技能，并继续遵守调研与测试职责边界。
- `integrations/opencli.json` 保存应用内接入设置、npm 包与命令目录以及修订标识；更新校验 revision，并原子发布。Agent 在创建会话前应用 PATH、`OPENCLI_PROFILE`、`OPENCLI_WINDOW`，空 Profile 沿用 OpenCLI 自身默认选择。配置、包版本及两个指南内容参加 worker 复用身份计算，后续执行重新加载；可选接入损坏转为警告并跳过，不阻断基础 Agent。
- 命令 `opencli.get/refresh/check/install/save/doctor` 属于应用作用域，拒绝携带工作空间／会话。操作通过短幂等回执受理，单工具串行执行，独立 `builtin-tools:opencli` 订阅提供进度。`integrations/opencli-job.json` 保存最近操作状态；断线不重发，页面重开保留失败／中断原因，后台退出中止自有进程树，重启不自动重做。
- 安装前检查活动 Agent 和已准入但仍异步准备中的工作空间操作；安装期间阻止新的 prompt、resume 和子任务追加执行。全局安装可能被其他进程共用，页面明确告知影响，不假定本服务能控制所有外部使用者。
- Chrome 扩展提供「Chrome 应用商店安装」（推荐）和「手动下载压缩包」两种方式。商店版在 Chrome 中添加并由浏览器管理更新；手动版从官方发布页下载 `opencli-extension-v{version}.zip`、解压，并在 `chrome://extensions` 启用开发者模式后加载已解压的扩展程序，更新需另行下载。两个入口通过应用作用域命令 `opencli.openExtension` 请求本地后台调用系统默认浏览器，仅接受 `target: store | download`（省略默认 `store`），分别映射到固定的官方 Chrome 应用商店 HTTPS 地址及 GitHub 发布页，不接受客户端 URL 或其他参数；校验归属并使用幂等回执，重连不重发。无需安装 OpenCLI 即可使用，不占用安装／诊断作业；页面阻止提交中的重复点击，启动失败显示原因及手动访问地址。启动请求受理不代表网页加载成功。主动检测调用官方 `doctor`，可按需启动桥接服务；只展示有时间标记的限长脱敏报告，不将退出码 0 视为连接成功，不在后台轮询中调用浏览器操作。重试清除旧报告，安装状态和浏览器连接状态分别表达。
- 订阅更新不重建表单或覆盖未保存输入。多窗口 revision 冲突保留输入，用户可放弃草稿载入最新配置，或明确选择用当前输入覆盖最新设置；不静默重设草稿 revision。

#### REA 配套组件

REA 详情增加“分析引擎与配套组件”，分别呈现 JDK、Ghidra、Hopper、JADX Headless MCP、WABT 的路径、检测时间、状态与操作。刷新只读，不预热；显式检测只做无目标环境检查，环境通过不等同于实际分析成功。界面以后台 OS／Node 架构选择下载与路径规则，手机及远程客户端不参与平台判断；Windows 不套用 macOS 路径或 shell，缺发行包或 REA 不支持时明确提示。Ghidra 在 Windows/Linux x64 提供托管下载，macOS/Linux arm64 只接入已有完整安装；Hopper 只接入已有安装。所有受支持组件须确认后才下载。实现边界与平台矩阵见 [REA 配套组件说明](rea-engines.md)。

组件配置纳入 `integrations/rea/config.json` revision 与 REA 资源身份；`rea.engineSave` 保存绝对路径，`rea.engines-check` 显式检测，`rea.engine-install` 复用 REA 单作业、取消与中断记录。路径草稿遇到外部修订保留并提示重新载入，不隐式覆盖；保存后需检测，已有会话需重载技能与 MCP。仅向 REA 进程注入五个组件变量，不改全局环境或用户 MCP，不运行 `rea setup`。官方下载每跳白名单、SHA-256、受限安全解包后，在独立目录验证，成功且 revision 一致才切换；失败清理本次目录，旧目录供在途会话继续使用。

### 5.9 技能与 MCP 资源管理

「配置 → 技能与 MCP」（`/resources.html`）沿用配置页侧栏与设计变量。顶部按技能／MCP 切换，并独立选择全局或已授权项目；列表只显示当前类型及范围，支持搜索。详情按实际内容、来源与作用范围、资源维护排列，保存操作与更新安装来源分开。REA／OpenCLI 的内置项在列表名称、详情标题和详情“管理方式”显示 Lucide `package` 内置图标（`BuiltinMark`，列表13px／标题15px／管理方式14px、1.2px 非缩放描边、灰色），替代“内置”文字，悬停说明随安装包提供；列表副行不再显示“应用安装／本机配置”，详情管理方式写为“随 REA／OpenCLI 安装包提供”。窄屏改为纵向布局；未保存修改在切换资源、类型、范围及刷新前确认，断线保留编辑内容。

读取和修改通过应用作用域的 `resources.get/detail/install/update/save/remove` 命令执行，独立 `resources` 订阅显示真实作业状态。修改携带目录 revision，保存绑定详情读取时的 revision，卸载绑定打开确认框时的 revision；文件变化拒绝旧写入。MCP 详情返回实际配置结构，敏感字段、环境变量、请求头、全部命令参数及含认证信息的 URL 使用占位符；同一 JSON 路径保留占位符时恢复原值，输入新值替换，删除字段移除。单独保存配置不重新安装 npm 包。项目允许仅覆盖 enabled、exposure、toolExposure，校验继承后的有效配置但落盘保留局部字段。技能详情读取实际 Markdown（最多20份、合计256 KiB），可编辑的本机技能正文经 frontmatter 校验后原子替换；包内、链接与跨范围共享来源只读。

- 本机技能导入完整目录及附属文件，拒绝符号链接和超过 50 MiB／10000 项的来源；npm 技能与 MCP 安装在应用数据目录 `resources/<id>/`，分别拥有依赖和缓存，跳过生命周期脚本。技能导入后验证 `SKILL.md`；npm MCP 使用指定或唯一 bin，保留配置参数及环境变量。pi 资源包通过原生包管理器安装 `npm:`／`git:` 来源，按原作用域整体更新或卸载，不拆分包内技能；固定版本仍保持固定。原生 pi 包管理器的安装行为与独立 npm 安装分别说明。
- `resources/installed.json` 记录应用安装归属。卸载确认列出实际清理目录、配置及保留范围；应用独立安装删除整棵目录（含依赖和缓存），本机技能删除技能目录及附属文件，技能目录或 `SKILL.md` 自身为符号链接时只移除该链接，保留目标和同级文件；位于父目录链接下的技能拒绝直接删除，要求通过链接来源或原安装管理器处理。删除身份同时复核真实路径与链接类型。外部共享程序、外部资源包文件和公共缓存不因 MCP 的 command 字段被推断为归属目录。外部 npm 包提供的技能要求通过其原安装管理器卸载。
- 范围以安装记录、pi 解析元数据及配置来源为准，不能仅按文件是否位于项目目录分类。全局技能写入应用 pi 设置，项目技能写入该项目 `.pi/settings.json`；全局 MCP 写入共享 pi 配置，项目 MCP 写入该项目 `.pi/mcp.json`。项目撤销授权后保留安装文件并拒绝继续管理。跨范围共享或位于项目外的技能卸载只移除当前范围引用并添加排除规则，保留正文、脚本及其他范围引用。托管技能或资源包被其他范围引用时，所有者暂不能编辑、更新或卸载安装文件，需先从其他范围移除引用。
- MCP 按配置文件和名称分别管理，卸载只删除选中范围的定义与对应默认选择。通用配置中项目定义覆盖全局同名服务；删除项目定义后全局定义重新生效，页面明确提示，也可使用 `enabled:false` 保留项目禁用。清理 pi MCP 凭据时使用刷新锁与存储锁；同名同 URL 的其他范围仍存在时保留 namespaced 凭据，其他已发现服务共享 URL 时保留旧 URL-only 条目。同名同 URL 的连接沿用 pi 共享 OAuth 账户语义，配置独立不代表登录账户按项目隔离；详情明确提示。用户手工存放的外部文件、系统环境变量和共享认证供应商不推断为此连接的私有资源。
- 技能与 MCP 的保存、新增、更新、移动、卸载及 pi 资源包管理不要求 Agent、子任务或压缩空闲，不释放 worker，也不阻止新的执行或会话重载；正文与配置原子替换，新增安装在私有目录完成后发布。`resources.install` 拒绝携带已有资源 ID，替换已有资源必须使用更新接口。已有会话后续读取技能文件可获得新正文，已加载的目录、提示与 MCP 连接通过会话重载更新；并发准备阶段的文件变化仍可能触发版本冲突，需重试。确认卸载后按清理范围删除文件、配置和安装记录；共享引用以精确强制排除规则阻止重新发现，保留其他范围的文件与引用。操作结束前刷新目录，卸载还须核实原目标已消失；刷新失败或目标仍在则报告未完成，不误报成功。所有资源写入仍串行，保留版本检查及与 OpenCLI 安装的互斥。`resources/job.json` 保留最近作业，必须成功保存准入记录后才开始修改；最终记录保存失败时保留内存错误状态并提示核实实际资源，避免未处理异常和自动重做。重启将未完成操作标为中断。已结束作业的错误保留在默认折叠的“上次资源操作未完成（查看记录）”中，不以当前红色告警展开；当前页面提交操作产生的新失败、读取和提交错误仍即时显示为告警。资源页维护区只展示活动任务，历史结果从任务中心查看，避免同一旧失败在两处反复展开。关闭提示按作业 ID 与错误内容在同源浏览器 localStorage 中记录，并同步其他窗口；刷新、重新连接及服务重启恢复同一失败记录时不再弹出，新作业或同作业的新错误仍显示。存储不可用时退化为本页关闭，不删除服务端作业记录、不重试修改、不放宽忙碌检查。文件按原子替换写入，跨文件清理不承诺事务回滚；失败显示未完成并允许刷新核实。历史会话保留，项目操作只清除该项目未锁定会话的旧选择，全局操作影响所有未锁定会话；共享技能引用移除保留其他范围仍使用的默认选择。已锁定会话不自动改选能力，需显式重载或新建会话后重新选择。共享文件被移除后，终端 pi 后续读取同一路径也会反映文件变化。

## 6. 主 Agent

- 「技能与 MCP」面板按当前会话／全局默认分别维护待应用的 Skills 与 MCP 集合，按工作空间／会话保存于窗口内存及 `sessionStorage`，跨会话切换和刷新保留；成功仅清除本次目标范围，其他范围草稿继续保留，存储不可用时退化为内存保留；切换能力标签、搜索和关闭面板不发命令、不保存偏好、不触发重载。统一按钮通过 `agent.reload({capabilities:{target,revision,catalogRevision,skills,mcp}})` 提交批量目标，复用原生资源重载、安全等待、续接和页面刷新；空参数左下角重载继续采用准备时的全局默认。当前会话目标核验会话 revision，全局目标核验偏好 revision，均核验目录摘要和资源可用性；成功回报后在同步 SQLite 事务内复核会话 revision，全局目标额外复核偏好 revision，原子提交全局偏好及会话选择，完成后才发布。普通资源的全局偏好使用真实技能路径和 MCP 来源／名称区分物理来源；内置资源的偏好按类型与名称保存，并兼容读取原来源偏好。保留目录外的其他偏好，防止同名普通项目资源互相覆盖；成功的全局修改清除其他未启动会话的旧局部选择。任意准备、原生重载、取消或提交冲突均不发布新选择，实际运行时与数据库无法确认一致时停止执行。UI 保留失败草稿，外部更新不覆盖草稿，冲突时要求重置后重新选择；等待期间禁用重复提交，其他窗口在成功前仍显示已应用快照。空闲路径初始化原生重载 worker，不创建对话 run、不调用模型；运行中等待整批工具、旧 prompt 返回及 session idle，再重载设置、Skills、MCP、扩展、模板、主题与项目指令，并通过正常 prompt 生命周期继续原执行。成功后复用输入草稿持久化和未保存文件编辑保护，再刷新页面。旧 `agent.skills` 单项局部更新接口保留兼容，面板不再调用。`session_capabilities` 首次执行仍在同一事务内核验选择、偏好 revision 并锁定，准备失败不锁；旧会话在主动应用前保持兼容技能行为且不自动启用 MCP。连接状态依据实际 WebSocket 生命周期；资源摘要读取失败降级为脱敏警告，执行时严格校验所选资源。
- Skill 列表逐项显示名称与简述，简述最多两行并以省略号收起溢出内容；来源路径和待重新加载说明收入名称悬停提示，不另占列表文字行，勾选框辅助说明保留待重载状态；提供 `hand-click` 手形使用按钮，与勾选独立；将结构化引用加入当前草稿，同一技能去重，每条消息最多32个。撤回合并的草稿可保留最多2048个引用，超过发送上限时要求先移除多余项，不截断恢复内容；草稿加载或保存失败显示原因并提供重试。底部工具栏入口使用原手形图标；技能标签、卡片使用共享 S01 书本图标。有效技能无需勾选即可手动添加，全局勾选与当前会话自动选用状态不一致时在悬停与辅助说明中提示待重新加载；禁用按钮提示断连、加载、保存、资源不可用或重复添加的具体原因。输入区与待执行区采用紧凑单行技能标签，输入区与图片／文档附件共用可换行区域；已发送会话消息保留灰紫两行卡片，正文仅名称与描述，操作保留44px热区。标签名称及卡片编辑按钮打开通用文件预览并进入编辑，位置按钮通过宿主文件管理器打开所在目录；服务端只接受已发现技能身份并核验会话归属、实际路径及 Markdown 普通文件，不接受客户端任意路径。草稿保存、普通发送、Steering、撤回和修改重发保留引用，子会话沿用其实际可读技能和工具边界。worker 根据实际加载集合校验身份与原生命令按名称定位的一致性，复用 pi 1.1.0 `AgentSession._expandSkillCommand()`（与原生 `/skill:name` 相同的函数）读取正文、去掉 frontmatter 并生成相对路径说明；宿主不再读取或解析技能正文。SDK 未公开纯展开接口，内部适配集中在 `skill-input.ts`，接口或结果格式变化明确拒绝发送，不回退到自制展开。多个技能逐次原生展开后仍作为同一输入交付，不创建额外用户轮次、不碰运行队列；初始发送和 Steering 共用。读取行为遵循 pi，不再承诺旧自定义展开的128KiB／512KiB、严格UTF-8及读取一致性保证；编辑保存边界另行保留。无法加载时拒绝本次输入。发送时从已加载目录取得的名称、描述和原始显示文本保存到原生消息元数据；名称／描述变更需重新加载目录，正文由原生命令按调用时文件读取；历史卡片不随文件编辑回写，不把环境技能列表或添加引用等同于成功使用。

- 后续发送复用有效保活会话，或直接打开绑定的 pi JSONL 并处理新消息。失败、停止或中断后，在主／子会话消息列表末尾提供扁平文字问题提示（按状态显示“回复失败”“回复已停止”或“回复已中断”，后接“· 重试”），与正文左对齐、无图标和按钮底框，灰色常态，文字重试悬停加下划线并保留可见键盘焦点；桌面点击区域至少44×32px，触屏至少44×44px。提示随消息滚动，不占用发送按钮旁的位置。点击时同步移除入口，不等待受理、模型响应或退场动画；重试及未知回执核实在后台静默处理。按工作空间／会话和原 runId 保留提交状态，连点、切换会话及受理回执先于新运行快照均不恢复旧入口；明确受理失败时恢复入口并显示原因，新执行再次失败后可再次重试。键盘触发后将焦点交回对应输入框，草稿及附件保持不变。点击调用 `agent.resume({expectedRunId})`，创建新 runId 并关联 `resumedFromRunId`，不增加用户消息、不提交或改动草稿。使用 pi 公开 `sendCustomMessage({content:[],display:false},{triggerTurn:true})` 启动原生 Session 生命周期，`context` 钩子在请求前排除内部 `axiom-resume` 标记，并通过 `appendContextEdit`／`refreshContext` 持久排除以保证重载一致；不调用私有方法、不修改依赖、不绕过原生重试／队列／结算。仅排除末尾尚未完成的失败／截断回复，直接从原用户请求或已保存工具结果继续；工具结果缺失时补充明确的“中断、结果未知”错误结果完成协议配对，应用不重放工具、不伪造成功。缺少可续接上下文时明确拒绝，用户可正常输入新要求。服务端校验 expectedRunId、终态和无活动主／子任务，旧恢复意图遇到新执行时拒绝；子任务重试作为独立控制项进入现有并发队列，遵守停止／预算／调研与测试权限并生成新不可变结果。回执不确定只读取原请求 ID，不自动重发。
- 每次执行可使用只读配置快照，保活期间保留所绑定快照，进程退出清除；不在前端或 SQLite 复制模型定义及凭据。项目资源默认授权加载不替代工作空间访问授权或新增命令型密钥／请求头的授权。
- prompt、resume 与模型切换按会话串行；持久幂等登记和停止代次捕获在排队前完成。全局模型配置锁仅保护配置复核、快照及最终运行登记；锁内同步建立 pending 归属，锁外等待 Worker ACK 和旧进程退出。停止、关服和供应商撤权能识别 pending 执行，交接前再次校验停止代次。同一会话的追加等待不阻塞其他会话准入。
- 停止直接强制终止应用拥有的执行，不发起模型总结，不要求清理确认，也不承诺文件或外部副作用回滚。主会话停止时先冻结自动结果唤醒，再终止该会话及所属活动子任务、取消所属排队任务；只停止子任务时不影响父会话或兄弟任务。明确的新主会话消息或手动重试才恢复父会话自动处理；等待配置锁的旧提示和迟到受理不能越过停止边界、启动工作或解除冻结。
- 切换查看对象、关闭子会话弹窗或进入配置页不属于停止操作。

耗时由服务端记录每次执行的起止时间，并按当前会话汇总已结束执行；前端在此基础上展示正在进行的执行耗时。同一会话完成、失败或停止后重新发送、重试与续接均继续累计，不计入两次执行之间的空闲时间；切换会话、刷新与重连后从服务端记录恢复，各主／子会话独立统计，不叠加其他子会话的耗时。前端先更新而旧后台尚未提供累计字段时，保留最近一次执行的实时／终态耗时，悬停提示明确其口径及任务结束后需重启后台以启用累计计时，不将单次耗时标为累计值；终态缺少结束时间时仍显示未知。主／子会话输入框下方统计与操作图标常态使用系统灰色 `#8a8f98`（底栏局部 `--action-icon-fg`），仅真实进度填充及告警使用语义色。左侧统计与重载入口和右侧工具复用相同悬停／键盘聚焦高亮：中性图形随按钮提亮，背景使用前景色8%混合，保留进度与告警色，禁用入口不高亮。缓存数据库按实际轮廓收紧画布并垂直居中，未知标记保留在画布内。费用与耗时共用 Lucide `chart-column-increasing`（U04）纯图标入口，当前会话费用与运行耗时集中在详情中展示，费用保留四位小数。底栏普通线性图标与数据轮廓统一使用1.2px非缩放描边；上下文内部三行标记采用1px非缩放描边，灰色外环不透明度1、颜色与相邻图标轮廓一致，其他空轨道和未点亮任务行不透明度0.4。非品牌操作图标使用统一共享符号，底栏普通操作统一16px，任务、上下文、缓存与压缩阶段等底栏数据图形20px，不拉伸窄形符号。所有操作入口保留至少44×44px热区。所有视口的底栏入口均仅显示图标，数值在点击详情中展示；44px入口单排，保留左侧指标与右侧工具分组，只收紧组内间距，容纳不下时工具条内部横向滚动。缓存命中率为当前主／子会话最近一次模型响应的原生 `cacheRead/(input+cacheRead+cacheWrite)`，每次响应结束后更新，包括工具调用轮次；各项须为有限非负数且分母大于零，不含输出、摘要或工具内部模型调用，也不使用会话累计值。最新原生响应记录缺失／无效用量时显示“—”，有输入且缓存读取为零时显示0%；新请求尚未返回原生响应记录（包括被强制停止）时保留最近一次已返回的数据。单次数据以独立 `usage.lastRequest` 随快照保存，旧快照仅从绑定原生记录读取活动分支的最新助手消息，读取失败保持未知；保留最近失败／取消响应的真实有效用量，无有效用量则不回退旧读数；工作进程退出后按已持久化的原生记录校准单次用量，避免停止期间丢失的用量通知留下旧值。缓存详情为最大360px的锚定浮层，标注“最近一次请求”，20px命中率、4px本次输入构成条及三行右对齐Token明细；统计口径使用共享细线箭头，键盘可展开，未知占比显示“—”。缓存数据库填充只随真实比例变化；读取占比>90%时闪电绿色且整个图标保持静态，其他颜色仅在当前主／子会话运行时以1.8秒SVG透明度时间轴反馈活动，不另加右上角状态点，Windows关闭动画或系统减少动态效果时仍继续；结束后移除时间轴。上下文外环填充只表达占用比例，不循环变化。主／子会话底部累计运行时间按秒（s）、分钟（m）、小时（h）、天（d）逐级进位，最大单位为天；从实际达到的最大单位连续显示到秒，保留各级余数与零值，例如 110 秒显示 `1m50s`，3601 秒显示 `1h0m1s`，93784 秒显示 `1d2h3m4s`。仅舍去不足一秒的小数，不提前进位，未知显示“—”。Token、缓存、费用与上下文占用使用真实可得数据；估算明确标注，未知显示“—”，不能显示为零费用或零用量。统计口径区分当前执行、当前会话与包含子代理的汇总，不重复计费。

### 会话资源重载

- 主／子会话左下角费用统计图标右侧提供重载入口，采用共享 `settings-reload` 图标：齿轮右下角带顺时针刷新箭头，复合图形采用20px画布，齿轮主体放大、箭头靠近主体，与相邻数据图标保持接近的可见尺寸；使用1.2px非缩放圆角细线、灰色前景与44px点击区域，齿轮在箭头处留出间隔；入口及弹窗执行按钮同源。资源对比表的表头和数据行共用列宽，资源名称左对齐，前后数量与变化列统一右对齐。点击打开锚定弹窗，在弹窗中点击「重新加载会话」才执行；关闭、切换查看对象不取消操作。原生重载成功后，发起操作的窗口自动刷新页面一次，其他观察窗口只同步状态；刷新前确认全部聊天草稿保存及无未保存文件编辑，保存失败、冲突或文件仍在编辑时保留页面并提示处理。重载失败不刷新，历史完成状态不会再次触发刷新；刷新后由既有会话选择及草稿恢复机制恢复，前后对比结果可重新打开查看。
- 使用 pi 原生 `AgentSession.reload()` 重读设置、Skills、扩展、提示词模板、主题与项目指令，保留对话与当前模型选择。主会话重载应用「技能与 MCP」最新保存的全局选择，包括技能自动发现选择、MCP 成员增删及连接配置变化；子代理仍遵守原资源限制。模型认证由原入口管理。空闲重载独立占用执行租约，不创建聊天执行或请求模型；须已有可用模型配置以初始化原生 Session。
- 运行中先等待当前回合的整批工具及原生边界记录完成，再通过 Session 级取消标志阻止下一轮请求；钩子外等待原生结算后重载。仍有工具后续、排队输入或扩展明确要求继续时，通过新的 prompt 生命周期在同一业务 run 中续接，使首个后续请求使用新系统提示；进入底层 Agent 前移除唯一的合成空用户输入，保留原生系统差异及扩展消息顺序，不增加用户对话，不重放工具。原回合已经结束则仅重载。重载失败不继续使用未确认的运行时。
- 技能发现变化会修改系统提示。pi 1.1.0 使用结构化提示且模型支持 `supportsMidConvoSystemMessages` 时，在后部追加 skills section patch，可保留此前请求前缀；不支持此能力，或扩展／运行设置提供完整 forced system prompt 时，投影折叠为更新后的首条 system，首个差异之后的旧前缀不能按原样复用。扩展修改上下文消息数组时，pi 也可能将系统 sections 合并回首条消息；技能续接自身不通过 context hook 删除控制消息，以免造成这种额外重写。缓存实际命中仍取决于供应商、TTL、最小长度与分块等条件，不承诺零影响。取消发现不删除历史已读内容，也不撤销显式使用能力。
- `agent.reload` 立即返回持久受理状态，`reload:<workspaceId>:<sessionId>` 独立订阅真实阶段与时间。重复点击合并在途操作，断线只重读状态，不自动重发；重启后未确认操作记为失败。停止、撤权及删除遵守所属会话边界。等待工具完成不设强制中断期限，实际重载超过120秒停止拥有的工作进程。重载期间不并发启动压缩、模型切换或新提示；子任务结果保留待投递，释放重载锁后重新唤醒。
- 比较加载时保存的资源名称及内容指纹，展示数量和新增／移除／更新项；缺少前次快照时明确标记首次快照。设置只展示键名，不发送值；扩展只比较入口文件，不承诺追踪所有依赖。pi 主题不改变工作台外观。扩展重载可能重新连接服务，原生资源诊断作为警告展示。

### 费用明细与分类核算

- 主／子输入框下方用量图标是可经鼠标或键盘打开的统一按钮，在当前工作台显示费用浮窗；浮窗同时展示当前主／子会话的预计费用、运行耗时及统计口径。耗时按当前会话独立统计，不随费用汇总叠加子会话。原会话草稿与滚动保持。浮窗最大480px，沿用工作台深色表面与细边框，内容独立滚动，顶部固定纯图标刷新与关闭操作，不重复展示会话名称大标题；当前会话费用／耗时为14px，累计总额为18px。首次读取、手动刷新和重开校验显示加载反馈并禁用重复点击；已有报告的自动更新静默执行，状态文字保持稳定，错误明确展示。点击外部、关闭按钮或 Escape 收起；键盘关闭后焦点返回入口，子会话内只关闭费用浮窗。详情上方保留当前会话累计口径；分类明细始终归集所属主会话及其全部子任务，从子会话进入时标明当前子任务。
- 分类总额为主 Agent 对话请求、逐个子 Agent 对话请求、压缩、工具内部调用和其他模型调用之和。各分类互斥；子 Agent 按稳定会话／任务身份列出，包括同一子会话后续追问。模型行可展开输入、输出、缓存读取、缓存写入的已知 Token 与费用；主／子 Agent 优先以供应商记录的实际响应模型归集，缺失时使用请求模型；压缩关联任务只有所选模型时不推断实际响应模型。折算单价为已记录分项费用除以对应 Token 后换算为每百万 Token，多请求／阶梯价形成加权均价。
- `costs.get` 是校验工作空间／会话归属的只读查询，不创建持久命令回执，不启动模型。数据来自绑定 pi JSONL 的全部原始 Entries，保留压缩前、重试排除与历史分支的实际消费，不从当前消息展示投影计算，不用当前模型价格重算历史。缺失／不可读取的原始记录显示不完整，不能以缓存累计值猜拆分类。
- 原生 `compaction`／`branch_summary` 归入压缩；后台任务通过所属会话与 `details.axiomCompressionId` 对齐原生记录，应用前后只计一次。独立压缩工作进程在每个原生摘要请求前报告未知用量，结果返回后替换为真实分项；取消后到达的用量仍持久化到任务 `billing`。失败、取消、冲突与等待应用的摘要也按可得消费计入，尚在快照阶段且没有请求事实的任务不推算费用。历史任务只有总额时保留总额并标记分项缺失。
- 工具通过原生 `toolResult.usage` 上报自身模型调用的合计费用；需要模型维度或独立记录时，使用原生 `usage` Entry，`kind="tool:<工具名>"` 并带实际 `provider`、`model` 和 `usage`。同一消费只选一种上报方式，不同时写入工具结果与独立用量；生产者负责每次请求只记录一次。其他 `usage.kind` 归入“其他模型调用”，保留扩展来源。没有上报的工具消费无法自动计入，不将主 Agent 的模型选择冒充工具模型。
- 费用以请求时记录的美元值为准，先累计再显示四位小数，展开分项显示六位。零价格无法区分免费与缺失价格时按未知处理；混合已知／未知显示“$金额 + 未知”，不把部分金额标成完整总额；无记录显示“—”。记录条数不保证等于 HTTP 请求次数，旧摘要／工具用量可能已聚合。实时未返回、被强制中断且无用量回报的请求无法补算，以供应商账单为准。
- 服务端将状态通知在100ms固定窗口内合并，只对当前打开的费用订阅检查来源：主会话标题、子任务成员与状态、绑定JSONL的身份／大小／纳秒修改信息、压缩状态与费用、记忆费用完整行（含UPSERT更新）。同一主会话及其子会话共用来源检查；单个窗口的直接读取不得消耗其他窗口尚未收到的失效通知。来源未变不发费用失效通知，不解析JSONL；不同主会话互不刷新。文件元数据用于追加式记录的变化检测，手动刷新与重连仍权威读取，不承诺识别保留全部元数据的外部改写。
- 费用浮窗首次立即查询；费用订阅初帧以revision0表示建立订阅，不视为新增费用失效，挂载与重连仍各自执行权威读取。后续使用独立 `costs:<workspaceId>:<sessionId>` 失效通知订阅，以首条通知起150ms的固定窗口合并变化，同一连接与归属最多一个查询在途；查询期间的新变化在完成后合并补读，持续通知不推迟已有定时器或丢弃当前响应。关闭浮窗时无费用扫描；内存最多保留五份按连接代际、工作空间和请求会话隔离的报告，重开先显示上次记录并明确标示更新中，每次重新校验，不把缓存当最新数据。报告内容不随耗时秒表重复构造；更新不重建原聊天区域或重置已展开的模型明细。断线显示旧数据提示，重连重新查询；加载、错误与重试明确可见，旧响应不覆盖新归属。

### 6.1 后台压缩快照与安全点应用

- 入口使用折叠图形及三个阶段点，运行时保留SVG箭头往复与当前阶段呼吸，系统减少动态效果时仍继续；只有 `completed && done` 确认为成功并恢复初始静态灰色折叠图标，取消保持中性色并显示方块，失败或中断保留红色错误标记，不换算耗时百分比。点击切换压缩页面展开／收起，不直接启动模型请求。无任务显示准备状态；页内提供开始／再次压缩、运行中的取消及 `ModelPicker` 统一模型选择组件（搜索、收藏、供应商、模型、思考等级）。完成、取消、失败后仍可从页面再次开始；刚完成且没有新增消息时按 pi 原生限制明确提示暂无可再次压缩的内容，不重复模型请求。空会话允许打开和设置模型，但不能开始压缩。每个主／子会话的任务、详情、操作回执独立，更新不重建对话、输入或模型菜单。
- 压缩模型作为独立全局偏好保存在服务端，主／子会话及各窗口共享，刷新和重启后恢复；选择不修改聊天模型。尚未设置时使用当前会话模型，已保存选择失效时明确报错，不静默换回聊天模型。每次任务冻结其启动选择；运行中修改全局模型仅用于后续任务。
- 压缩页面提供全局自动压缩开关、Token 阈值与上下文百分比（整数 1–100）；默认开启，100,000 Token／80%。当当前上下文占用达到 `min(Token 阈值, ceil(当前会话模型上下文容量 × 百分比 / 100))` 时启动后台快照压缩；容量未知时仅用 Token 阈值，占用未知时不触发，不使用累计计费用量或摘要模型容量。主／子会话独立判断，启动与成功 `turn_end` 的新用量事件读取最新配置；页面打开、刷新、订阅、服务重启与保存配置本身不触发请求。数值按 Enter／失焦局部保存，跨窗口同步且保留正在编辑的字段。关闭自动开关不取消已开始的任务。
- 自动压缩复用同一原生快照任务、独立压缩模型、并发上限及安全点应用流程，详情标明自动触发。每次执行在持续超阈值期间只尝试一次；成功后观察到占用回落阈值以下才能再次触发，失败／取消不在同一执行中自动重试，新的执行可重新判断。达到并发上限时跳过本次检查，不建立自动重试计时器或隐式任务队列；后续用量事件可再判断。等待模型配置锁期间复核阈值、开关、执行归属与停止边界；停止或退出后不得复活旧启动。Axiom 接管 pi 的主动 `threshold` 压缩，并忽略被拦截检查的压缩进度事件，避免无实际压缩时显示压缩中／收尾；保留原生手动压缩及按 pi 设置启用的 `overflow` 恢复，不重写摘要协议。
- 启动时校验工作空间／会话、已保存消息、明确且可用的模型／思考等级及配置修订；不自动换模型。每次触发创建独立任务，以当前会话分支重新取快照；此前压缩失败、取消、中断不作为新任务的前置状态，迟到回执仅能作用于其所属任务。运行中的会话等待 pi `turn_end`／`agent_before_settle` 安全边界，再复制当前分支与会话头为临时快照；空闲会话先等待保活进程及关闭钩子释放所有权，重新检查是否出现新执行后同步保存快照。不在任意流式中间状态截取上下文，快照之后的消息不纳入摘要输入。历史失败、已中止请求及进程中断留下的未配对工具记录可被摘要，不以全历史工具配对判断当前安全点；应用仍禁止将原本成对的工具调用与结果切开。
- 独立进程调用 pi `AgentSession.compact(customInstructions)`，同次请求额外生成 `<axiom-summary>` 100 字内中文压缩短摘要，与会话标题的 `<title>` 提示词及生成流程独立；保留原生完整交接摘要结构，不增加短摘要生成请求，只写临时快照；针对 pi 1.1.0 分段压缩未传递 `customInstructions` 的路径，在专用压缩会话的 `streamFunction` 中向每个原生摘要请求附加相同指令，确保历史摘要与当前段摘要都收到要求，不追加会话消息。不对正在工作的原会话调用手动压缩、不打断当前请求。后台取得原生 compaction 结果后，等待原会话新的 `turn_end`／`agent_before_settle` 安全边界，由拥有该会话的工作进程校验并追加原生 compaction、更新内存上下文；空闲会话先释放保活进程，再在互斥保护下同步校验并追加；等待退出后重新检查会话是否已有执行，不另启模型请求，也不形成第二个会话写入者。快照或应用请求遇到执行结束时交接给协调器，在释放所有权后继续处理，不将正常结束视为失败，不重新生成已有摘要；启动期间尚无 IPC 所有者的请求在工作进程就绪后送达。
- 应用前校验真实会话绑定、快照前缀、分支及压缩边界仍兼容；只允许保留快照后的合法追加消息。分支切换、历史改写、其他压缩或缺失保留边界等冲突必须拒绝应用，不自动重新生成摘要或覆盖新内容。追加原生 compaction，不以临时快照替换整个原 JSONL；原始历史与快照后新增消息均保留。失败、取消、中断或冲突不应用摘要，不宣称回滚会话中的其他工作。
- 压缩进程关闭扩展、技能、提示模板、主题、上下文文件与全部编码工具；使用冻结的模型配置与 pi 认证，不建立第二套压缩协议或模型客户端。已有获准命令型认证仍可执行，独立进程不是操作系统沙箱。
- 每会话最多一项，全局最多四项，不隐式排队；不设置压缩等待或执行时限，取消调用原生中止，等待最多两秒后尝试强制结束拥有的工作进程。父会话整体停止覆盖其自身及所属子会话的压缩，等待配置锁的旧启动不得越过停止边界。供应商撤销和服务退出也处理在飞压缩。
- 状态为 `running / completed / cancelled / failed / interrupted`；阶段为 `snapshot / summarizing / applying / done`，分别呈现等待安全点快照、后台生成原生摘要、等待新的安全点应用和已应用，不用假进度定时器。处理阶段采用无底色、无外围圆框的线性图标与左对齐文字，统一图标占位和标题／说明间距；等待步骤分别使用 Lucide 官方 `copy`、`file-text`、`list-checks`，完成使用绿色 `check`，失败使用 `triangle-alert`，停止使用 `square`。仅当前运行步骤显示无外围边框的 24px `eos-icons:bubble-loading` 气泡动画与琥珀色高亮；失败标记停留在对应步骤，后续步骤仍为等待，终态移除加载动画。减少动态效果时仍保留气泡动画。压缩摘要卡片使用 Tabler `fold` 原始路径，图标无方块背景，桌面为 32px、窄屏为 28px，上下箭头以 1.8 秒周期向中间虚线靠拢再回位，减少动态效果时仍播放。等待应用时仍为 `running`；只有原生结果成功应用且压缩进程退出，才发布 `completed`／`done` 并记录应用时间（`appliedAt`）。其他终态也须释放压缩进程后发布，避免显示可重试却仍占用旧进程。
- 详情以独立提示区展示失败／中断原因；工作进程保留异常消息，经常见凭据模式脱敏与长度限制后传递、持久化并订阅更新，不传递完整异常对象或堆栈。模型配置、供应商请求、快照／应用及进程异常不得统一吞成笼统失败；无法取得具体原因时明确说明未知，不猜测。历史任务缺少原因时同样使用未知提示，失败后允许显式重试，不自动重发。
- 详情展示会话、服务端耗时、pi 压缩前后估算、Markdown 摘要及该次摘要用量／费用；摘要复用会话压缩卡片的安全渲染与排版，原始 HTML 不执行；未知数据不伪装为零。摘要展示上限 64,000 字符，超过明确标记截断；展示截断不影响完整原生结果的应用。摘要生成不代表已经应用，压缩后快照估算不包含后续新增消息，上下文外环图形优先取 pi 原生上下文统计；压缩后尚无有效模型用量时，以 pi `estimateTokens()` 对当前已提交的上下文投影逐消息估算，包含摘要、保留消息和快照后新增消息，不使用保留助手消息中的压缩前 usage 或详情快照数值。上下文 Token 数值直接显示，不加约等于符号；估算状态通过悬停提示说明待模型用量校准，有效原生统计恢复后更新提示。旧会话持久化的未知占用可从绑定 JSONL 只读补算，无容量仍显示未知。此当前上下文估算同时供 Axiom 自动阈值判断，不改变计费或 pi 的摘要算法；详情中的压缩快照估算不用于自动触发。摘要 usage 在应用后计入所属 pi 会话统计；详情只是该次明细，不再次与主／子会话统计相加。
- `compression.preferences.get/save` 管理全局 `{selection,auto:{enabled,tokens,percent}}`，模型选择和自动配置均支持局部更新，省略字段保留最新值；`compression-preferences` 独立订阅同步设置；`compression.get/start/cancel` 均绑定工作空间／会话，取消还校验压缩任务 ID；`compression:<workspaceId>:<sessionId>` 独立订阅。启动／取消先记录持久回执，前端发送前保存请求标识，重连只查询、不重发。
- 任务与结果持久化，临时快照／配置退出后删除；异常残留启动时清理。重启将未结束任务标为中断，不启动模型请求。关闭详情／子窗口不取消任务；点击详情面板外部收起详情，外部控件仍响应本次点击；面板内点击或从面板内拖动到外部不收起；Escape 只关闭最上层压缩详情并恢复入口焦点，子会话窗口保持打开。

## 7. 子 Agent 与独立工具

### 7.1 工具契约

四个工具直接注册到主 pi 会话，工具描述和参数一次可见。

| 工具 | 参数 | 行为与返回 |
| --- | --- | --- |
| `delegate` | `context`、`tasks: [{title, task}]` | 异步创建子任务，返回 `taskIds`、排队／启动状态与预算，不等待任务结果 |
| `append` | `taskId`、`summary`、`text` | 持久化新要求，返回 `taskId/inputId/runId/status`；异步接收、送达、失败可按输入回执追踪 |
| `cancel_task` | `taskId`、`reason?` | 强制停止指定子任务，不发起总结，返回停止回执；最终交付经完成通知读取 |
| `read_result` | `taskId`、`resultId` | 一次完整读取同一完成通知对应的不可变结果，可重复读取，不作为进度查询工具 |

- 工具描述仅说明能力和调用需求；schema 保留类型、必填项和未知字段约束，不附带长度、数量、正则或范围限制。字段提示词要求共同背景不超过200字、标题与追加简述不超过30字；运行时仍校验归属、类型和业务边界。`context`、任务内容、追问文本必须非空。每个新委派必须提供 `title`，每次模型工具追加必须提供 `summary`，均为1–30字符的单行核心目标，英文、数字、标点和空格也计数；拒绝空白、换行及 NUL，不通过截断掩盖不合法输入。任务短标题独立持久化，完整 `task` 和 `text` 继续用于执行；追加简述保存在对应工具调用中，追加、停止和读取均沿用原任务标题，不重命名任务。用户直接在子会话发送消息不要求额外填写简述。历史无标题／简述记录显示固定占位“子任务”（操作卡为“关联子任务”）／“补充任务”，不使用任务描述或追加正文替代，不补写历史。`title` 和 `summary` 由主模型在委派／追加的同一次工具调用中填写，卡片直接读取字段；不增加标题模型请求，也不要求子代理生成标题。
- 每个任务仅传入 `title` 和 `task`；职责、工作方式及额外约束直接写入 `task`，不另设职责提示字段。
- `append` 工具不再接受 `mode`，新追加统一经 `steer` 送达；历史 `followUp` 内容保持可读。`cancel_task` 不接受模式参数。
- 结果使用结构化字段与文本内容，错误必须标记为错误，不仅返回含“失败”的普通字符串。
- 委派幂等键包含父会话、执行和工具调用 ID，同一调用重传返回同一组任务标识。
- 取消与追加对同一个任务串行更新，其他任务不被无关操作阻塞。
- 子代理不注册委派工具，不递归派生子代理。

### 7.2 委派与上下文

- 每个子任务必须有明确目标、范围、必要资料和交付要求。
- 子代理不自动复制整个主会话；只接收明确传入的背景、任务及其获准的项目上下文。首次任务输入使用纯文本 `任务背景:\n…\n\n当前任务:\n…`，保留背景与任务内的换行、路径和命令，不将正文序列化为 JSON。任务表分别保存 `context`、任务正文与 `initialInputId`，初始委派和排队追加分开交付，供界面精确识别原始说明；职责限制与预算仍由独立系统指令和控制消息提供。
- 主代理按独立目标拆分任务，独立测试优先并行，协调前置依赖、端口和产物路径。测试期间不修改被测文件；收到完成通知后读取结果并核对实际证据，相关文件变化后重跑受影响检查。子代理最终交付不超过2000字，先结论，再给必要证据、建议和未完成／未验证项；此上限仅用于提示和任务拆分，程序不计数或限制正文。
- 子代理用于调研、分析、审查及执行测试、构建和静态检查。调研交付文件路径、相关位置、证据、修改建议和未验证项；测试交付工作目录、实际命令、退出码、通过／失败情况、关键错误、产物路径及未验证项，不能把未运行、超时或中断报告为通过。代码修改由主代理负责；子代理不得修改源码、测试代码、配置、锁文件或基准快照，不安装依赖。
- 工作进程以固定白名单启用 pi 内置 `read`、`grep`、`find`、`ls` 和当前平台命令工具（Windows 为 `powershell`，其他平台为 `bash`），并在工具调用边界再次检查。禁止 `edit`、`write`、非当前平台的命令工具、递归委派和其他未批准工具。命令工具用于委派范围内的验证，可产生必要临时文件、日志、截图、覆盖率和构建产物；使用独立路径与端口，缺少依赖或无法隔离共享资源时报告主代理协调。
- 子代理不加载用户、项目或资源包中的可执行扩展，防止同名工具覆盖、扩展命令或动态工具绕过；不加载提示模板，配置资源包从子代理的内存设置快照中移除，避免发现资源时安装依赖。保留项目上下文和可读技能，文本指令不能提高权限。主代理资源和修改能力不变。
- 首次委派、Steering 追加、用户直接追问、结束后恢复绑定 JSONL 均应用同一调研与测试策略，任务说明、历史消息和项目默认工具配置不能覆盖。工具白名单限制模型可调用的工具；命令只用于测试、不修改源码等要求由系统提示词约束，不能在允许通用 shell 后宣称文件系统只读或 OS 沙箱隔离。应用仍持久化会话／元数据，测试程序及已授权的命令型认证可能产生自身执行副作用。
- 任务记录先持久化再启动进程，卡片关联触发委派的消息或工具调用。
- 默认最多并行运行 4 个子代理，超出进入服务端 FIFO 队列；并发可配置为 1–16。一次委派 1–8 个，每个父会话最多 32 个活动／排队任务，每个子会话最多 32 条未交付输入；并发委派在异步校验后重新检查限额。
- 排队取消与启动前失败也产生不可变终态报告，不为获取报告而启动工作进程。
- 主代理可以继续独立工作或结束当前回复，子任务完成后由服务发送通知，不轮询等待。

### 7.3 追问行为

| 子任务状态 | 处理 |
| --- | --- |
| 排队／启动中 | 保存追加内容，在安全时机交给该子会话 |
| 执行中 | 新追加统一使用 `steer` 经 pi 安全边界送达，受理后从当前时间重新计算完整工作预算 |
| 总结中（仍属活动执行） | 先准备追加内容，真实提交成功后恢复工作工具并处理追加，保留同一 `runId`；受理时刷新工作时限 |
| 停止中 | 立即保存待续接新要求，旧执行退出并保存结果后自动入队；同一子会话不并行启动，再次停止撤销待续接要求 |
| 已完成／失败／已停止／中断 | 打开绑定的同一 pi JSONL，创建新 `runId`，只处理新要求，不经过人工恢复或清理确认 |

启动／运行期间的有效追加通过校验并持久化后，工作截止时间刷新为受理时刻加当前 `workMs`；校验失败不刷新。此边界与后续 worker 接收、实际送达分开，后续发送失败仍保留明确失败回执，不自动重放或回退时钟。总结中追加同时废弃旧总结截止时间；停止中追加仍等待旧执行退出。执行结束后的追问产生新执行与新结果，保留原结果可读。续接不依赖父代理读完旧结果或通知确认。输入持久化回执包含 `queued/accepted/unknown/delivered/failed/cancelled`、执行标识和错误；发送明确失败直接返回错误，worker 接收与 JSONL 落盘分别确认，未确认输入不自动重发。`unknown` 表示可能已经交接但送达证据不足，客户端显示「待核实」，查询映射为 `uncertain`，保持原请求身份而不恢复成可重复发送的草稿。运行期 IPC 同步异常与发送回调错误逐项生成不确定回执；SDK 提交抛错后核对原生队列、内存消息及会话记录，确认未保留才记失败，检查失败保持未知。通知同样保持 `unknown` 并先核对历史；`send()` 返回 false 仅表示背压，不作为失败依据。停止后输入使用独立等待状态，旧执行结算不能删除它们。停止检查之后才完成持久化的输入，允许在结算时凭同一 taskId/runId/inputId 的 JSONL 证据，将已删除队列正文的 failed/cancelled 回执修正为 delivered；任务停止来源与结果仍独立保留。

新委派、终态追加、停止后续接和显式重试共用事务内容量校验；按每次入队的持久化序号调度，老任务续接排在已有等待项之后。模型配置准备完成、分支修改和运行登记之前，再校验最新并发上限、活动执行及更早的 FIFO 启动候选；容量不足保留排队，不创建失败运行或结果，也不循环重试占用事件循环。已正式准入的执行不因降低上限而被强停。

输入回执更新校验 task/run/input 归属，迟到接受清理旧失败辅助标记，迟到传输错误不能降级已消费回执。未交接或确定未发送的可编辑输入可本地撤回；未知、已接受或正在提交的输入只按 Worker 确认的真实 ID 返回草稿，部分成功只恢复对应内容。撤回辅助接受回执不代表新要求已提交。结算和服务重启不重放输入；有可靠 JSONL 证据则对账为 delivered，缺少证据的已交接输入保留 unknown。输入送达、失败、撤回、取消和结算清理对应内存交接标识，不遗留已删除输入的引用。

用户整体停止主会话后，未消费的队列不会自行启动。用户明确向子会话发送新追问可以启动该子会话，但不解除父会话的自动通知冻结。

### 7.4 生命周期与预算

```text
queued → starting → running → completed
                       ├──→ failed
                       └──→ stopping → cancelled
```

- 配置仅包含工作时限 `workMs` 和并发上限 `concurrency`。工作到期进入同一执行内的无工具总结，总结固定最多 180000 毫秒，不提供独立配置；总结期间保留活动状态及并发占位，界面显示「正在总结」。没有 `cleanup` 阶段。
- `workMs` 默认 600000 毫秒，范围 1000–86400000 毫秒；`concurrency` 默认 4，范围 1–16。分支图标内统一设置且自动全局记忆。工作时限更新立即应用于排队及工作中的任务，按最近一次工作计时基点（首次启动或有效追加）重算截止，已超时则进入总结；修改偏好不延长已开始的总结。结束后追问的新执行使用最新时限。并发上限立即影响现有队列，提高时填补空位，降低时不强停已运行任务。
- 时间由服务端独立计时，排队时间不计入工作预算；刷新、重连和模型重试不重置预算。工作基点、工作截止、总结截止和递增预算版本持久化，定时器与控制消息校验当前 `runId` 和预算版本，旧回调不能覆盖追加后的新阶段。
- 首次请求按系统提示词、初始预算、任务正文的顺序发送，预算告知本次工作时限、截止时间、此前任务链累计耗时及到期后的总结阶段。后续预算变化、告警和总结通知仅追加到消息尾部，不因预算变化改写系统提示词或改写、删除、重排已发送的消息；新预算明确覆盖旧截止时间，旧提醒保留生成时的快照。工作进程按服务端时钟，在剩余总预算的20%（最多提前60秒）时注入一次预算提醒，通过 pi Steering 在下一安全边界交给模型，提示剩余秒数、尽快交付已有证据与未验证项，避免开始无法及时完成的新工作；同一执行的相同截止时间不重复注入。初始化跨过告警点但尚未到期时，在开始执行时补送；预算调整重算告警点，停止或结束时移除定时器。追加要求与当时预算在同一条消息提交，界面和可编辑正文只显示原要求。子代理在同一资源快照内保留首次请求的系统提示词，工具声明仍按阶段切换，避免 SDK 重建工具说明时改变请求历史前缀。告警不打断当前模型请求或工具调用，长时间生成／工具执行可能使模型在到期前无法读到提醒；不延长预算、不启动已结束的任务。总结阶段不注入工作告警，恢复工作时重新计算告警点。
- 工作到期先由服务端启动固定 3 分钟的总结硬截止，再通知 worker 中断当前模型请求／工具操作。等待原操作退出后，将未消费的预算提醒和追加要求按原生队列顺序追加到记录，再清空活动工具并在消息尾部发出总结指令；工具调用边界同时拒绝所有调用，总结只使用已有上下文，报告证据、实际测试结果、未完成／未验证项及已知副作用。等待中断、模型重试等均计入这 3 分钟。阶段切换不结算业务执行、不重放已执行工具。总结中追加先完成图片等内容准备，再中断总结并在串行安全边界提交；工具门禁在本次 transition 的真实提交确认后才开放。准备失败或准备期间撤回不恢复工作；已中断总结但本批输入全部明确拒绝时，以 `TASK_RESUME_FAILED` 失败收束一次并保留部分成果，不空跑新的工作／总结轮次。提交未知时维持工具关闭，等待同阶段后续成功追加或新的截止／停止；新预算版本和阶段可以中断等待。工作阶段的普通输入失败仅失败该输入。总结正常返回保存一次最终交付，依据实际 `BUDGET_SUMMARY` 原因或当前总结截止标记 `budgetSummary`，不因追加刷新预算而丢失真实总结事实，也不等于全部任务已验收。
- UI 停止、主代理取消及总结达到 3 分钟上限调用强制终止机制，记录 `user/agent/budget/parent/shutdown/provider` 来源、原因与时间；执行原因码区分来源。终止应用拥有的工作进程及可管理的子进程，不再发起模型请求；取消排队任务不启动 pi。
- 停止结果只基于已经保存的输出和可得执行事实，不为补齐报告调用模型，不将取消标成正常完成。
- 重复取消幂等，已结束任务保持原结果，不生成重复交付。
- Run 不含 `cleanup` 状态或字段，不提供 Agent 清理确认界面；强制终止不证明所有外部副作用结束，也不回滚项目文件。
- 服务重启时仍在执行的任务标记为 `interrupted`，不自动重放请求或工具操作；后续新消息直接使用绑定的 JSONL。

### 7.5 结果与通知

1. 执行结束后保存结果、执行状态和待通知信息。
2. 完成通知内部仅携带对应 `taskId`、`runId`、`resultId` 与结果状态。前端实时与历史投影统一为轻量系统状态条，不显示原始 JSON 或内部标识；连续独立通知按原顺序直接显示，不增加通知专用折叠入口；已有过程内的通知保留在过程内，展开所属过程后直接显示通知文字。压缩前尚未读的真实通知仅从当前分支补回，置于最新压缩摘要之后，不在会话顶部逐条铺开；折叠时保留通知记录供原有已读条件核对，不恢复已读或已舍弃分支的通知，不改变原生会话和模型上下文。完成为「子代理已完成」、取消为「子代理已取消」、失败为「子代理执行失败」、中断为「子代理执行中断」；未知／旧格式保留中性文案，不误报成功。所有此类通知仅显示灰色（`--muted`）文字和渐隐细线，不显示前置通知图标；显示时末尾统一为一个中文全角感叹号 `！`。文字为12px、行高18px，上下内边距2px、外边距4px／10px。200ms 淡入，减少动态效果时禁用动画；不使用用户气泡或弹窗，不改变原始上下文及投递确认。
3. 父会话运行中，最多合批 8 份通知使用 Steering 在安全边界送达，每份保持独立结果标识和展示；父会话空闲且未被冻结时，可以唤起一次结果处理。通知准备期间父会话变为运行中，仍按系统通知处理。
4. 父会话已停止时只更新任务卡片，通知保留待处理，不自动发起模型请求。
5. 消息进入可恢复的父会话记录后才确认投递，不能以写入内存队列作为送达依据。
6. 主 Agent 使用 `read_result` 获取结果；相同结果重复读取无副作用。

采用稳定 `resultId` 去重与独立投递尝试：每次重试使用新的 requestId，记录尝试所属父执行、时间、状态与错误；区分 `pending/inflight/delivered/failed/unknown`。明确失败不立即循环唤醒，新的主会话输入或模型选择操作触发受控恢复；未知结果先按父会话 JSONL 对账，当前执行仍拥有的尝试不重投。worker 按结果标识避免重复注入，按文件字节游标增量读取实际 JSONL 完整行后确认，不以文件存在或 SDK 内存索引证明落盘；部分尾行等待补齐，读取／解析失败不推进游标，文件重写时重新核对。批次逐项处理 SDK 提交失败：核对完整原生队列、内存消息和会话记录后，确认未入队才释放该项去重标记；已入队保留，无法核实则标记未知，其他项继续按自身状态处理。完整队列通过带版本校验的适配器读取，不能用仅返回下一安全边界消息的 peek 判定未入队。不宣称跨 SQLite 与 pi 会话文件存在天然的恰好一次事务，投递确认也不代表父代理已完成结果处理。

结果完整保存，`read_result` 和界面的 `task.result` 均按任务／结果归属一次返回全文，不接受分页参数，不返回续读字段。短报告、超过2000字报告和历史长报告使用相同读取路径；不截断、不拒绝、不转成文件引用或额外压缩总结。`reportKind` 区分最终回复、已落盘部分成果和系统执行记录。结果包含成功／失败／停止事实、已有产出、未完成或未验证项、已知副作用；未知项明确标注。停止报告仅整理已有记录，不另行请求模型总结，不意味着项目文件或外部副作用回滚。

### 7.6 子会话界面

同一次委派按父会话与调用锚点固定成员，成员状态图标显示当前执行状态，批次统计仅保留在标题身份图标的悬停和辅助描述中；仅 completed 计为成功，失败／中断、取消、排队与运行分别保留，全部结束不等于全部成功。没有任务记录时等待同步，不显示100%。追问可能使同一成员重新排队，因此这里表示成员最新执行状态，不是冻结的历史执行比例，也不是工作量或交付次数。

- 委派从工具调用出现时即显示「子代理协作」卡片，以调用 ID 稳定关联；任务记录尚未生成时，每项单行显示核心目标短标题，记录生成后原位接入真实任务，保留相同标题。同步提示、委派失败及停止原因通过既有图标颜色、悬停和辅助描述表达，不额外添加状态文字行，不推断成功。工具参数超过消息预览上限时，轻量投影单独保留任务标题、关联任务标识和追加简述，完整参数仍按需读取。委派组标题前使用 Lucide `bot` 身份图标，默认静止；悬停卡片或键盘聚焦子任务时提亮并播放一次600ms轻抬摆头动效，按下任务行时轻微回缩，失败／取消保留告警色，减少动态效果时只保留静态颜色反馈；运行状态仍由各成员的状态图标表达。右上角不显示完成数，完整状态统计保留在身份图标的悬停与辅助描述中；组标题最小36px高。子任务行仅显示现有状态图标、单行任务标题及打开图标，上下内边距6px、点击高度至少44px；长标题省略，完整标题和错误保留在悬停及辅助描述，完整任务正文与执行错误可在子会话读取。不重复状态文字、交付次数辅助行、通用工具卡、“独立 pi 会话”提示或详情下拉入口；点击任务行进入子会话。
- 子代理相关图标保留已选图形和系统线宽：设置分支在悬停、键盘焦点和打开时轻摆，打开子会话图标向右上微移，任务状态图标随任务行提亮并轻微缩放；读取结果的眼睛单次眨动，追加图标单次轻弹，停止图标轻收缩。按钮及摘要按下时回缩，失败／取消告警色优先。悬停动效仅在支持悬停的设备上启用；减少动态效果时保留静态颜色反馈，既有运行状态旋转不受装饰反馈影响。
- `read_result`、`append`、`cancel_task` 沿用紧凑操作卡的轻边框、圆角、图标、颜色和展开交互。读取卡片收起时仅一行「现有图标＋原任务短标题」；停止卡片已提供 `reason` 时在第二行显示原因，缺省或空白原因不留空行；追加／追问固定两行，第一行原任务短标题，第二行本次 `summary`，历史缺少简述时显示固定占位“补充任务”。长内容单行省略，完整追加正文、停止原因及错误可展开查看；错误和同步状态不替换任务标题或追加简述。上下内边距6px，点击高度至少44px，桌面和窄屏规则一致。卡片不新增「已停止」等可见状态文字、标签、详情／查看结果文字或下拉箭头；操作类型和回执状态保留在悬停与辅助描述，失败原因可从悬停和详情读取。读取成功为「已读取」，追加按回执区分排队、接收、待核实、送达、失败与撤销，旧回执保持「已受理」，停止区分受理、已停止和任务已结束；这些操作状态不等同于子任务成功或结果已核验。
- 主／子会话、原始会话与执行过程统一使用上述行数与标题规则。卡片左侧图标正常为灰色，失败／中断／取消使用系统告警红；运行保留既有旋转，排队保持静态，不将未知状态推断为成功。状态不使整行标题文字或边框变红。
- 读取详情只展示该次调用绑定的不可变结果，不切换到最新交付；按原始参数核对任务和结果 ID，以 Markdown 展示报告与未完成项。长返回在展开时经 `message.get` 按归属读取完整调用记录，再直接展示完整报告，不发起分页续读；标记最终回复／部分成果／系统执行记录。失败允许重新加载，不重放工具操作。追加正文与停止原因按需展开，原始工具名、ID、输入和输出收在二级详情；收起时不挂载完整结果。可从详情打开关联子会话。子任务通知收入过程卡片，其他通用系统通知保持独立。

- 点击任务卡片打开独立子会话窗口，保留父对话挂载与阅读位置。顶部显示子代理图标、实际任务标题、任务状态、任务说明入口与关闭按钮，历史无标题时显示「子任务」。任务说明卡分别展示背景和目标原文，短内容直显，长内容折叠预览并可展开；说明随会话滚动，入口定位时暂停自动跟随。初始输入按持久化 ID 精确替代为说明卡，后续追加保留在时间线；压缩后仍可回看原始说明。历史缺少结构化背景时保留原消息，不猜测分隔边界。「执行与交付」仅承载执行错误和结果，不重复显示任务全文。
- 不将主对话 DOM 移进弹窗，不复用全局 active 作为两个窗口的数据来源。
- 子窗口拥有独立消息订阅、草稿、附件、模型选择、滚动和工具折叠状态。
- 用户可在窗口中追问或停止；按钮与 Agent 工具调用同一任务服务，不经过模型转发。
- 关闭窗口只停止查看，不停止任务。
- 多次追问仍在同一任务卡片下展示，执行与结果分别可辨认。不增加暂存输入恢复、请求人工核实、停止总结或清理确认入口。

## 8. 持久化与故障恢复

### 8.1 存储职责

| 存储 | 内容 |
| --- | --- |
| pi JSONL | 主／子会话消息、工具结果、模型变更及 pi 管理的上下文状态 |
| SQLite | 工作空间、会话索引、未发送草稿、原生图片选择授权、最近主会话、任务关系、执行记录、结果交付、压缩状态与摘要预览、请求回执、界面偏好；不存另一份对话上下文 |
| pi 配置目录 | 模型定义、认证、原生设置与其自身缓存 |
| 应用资源目录 | 上传附件等受控文件 |
| 浏览器查看状态 | 窗口内查看位置、临时菜单与焦点；未发送内容使用内存缓存，持久化通过服务端 SQLite；浏览器持久存储不保存草稿正文、附件、凭据或运行事实 |

不把完整对话再复制进 SQLite。结果报告是任务交付对象，不是另一份全部消息记录。

会话草稿通过同源 `/api/draft` GET／POST 独立读写，不广播到消息订阅。保存包含原文、附件引用及兼容图片数据，按工作空间／会话验证归属，以 revision 和每窗口 writer／递增 sequence 防止旧请求覆盖新输入；冲突静默保留当前输入及服务端已有草稿，不展示提示或要求用户选择。草稿读写在后台尽力完成，不展示恢复、保存、错误或重试状态，连接恢复后重试未确认且无冲突的保存；仅已确认保存的内容承诺重启恢复，关闭页面时的小请求 keepalive 仅作补充。草稿首次读取期间仍可输入、添加附件及发送，迟到的已保存内容不覆盖本地新输入，读写失败或冲突不阻塞输入、发送及会话切换。草稿随逻辑删除保留在原归属下，但普通接口不再开放；工作空间归档保留。

发送前保存 submissionId，确认受理后仅清理匹配 writer／sequence／submissionId 的草稿，保留防止迟到保存复活旧内容的标记；等待期间的新输入不受影响。恢复时已提交回执对应的草稿清空；待确认提交恢复为原请求标识的待确认气泡，继续只读核实，不恢复为普通可重复发送草稿，不自动重发。页面内全部待确认消息仍由独立输入状态管理，草稿表不充当完整发送队列。服务端保存最近主会话与独立的侧栏工作空间，新的窗口恢复两者；同窗口自己的查看位置优先，其他窗口的偏好更新不强制导航当前查看实例。

### 8.2 最小数据关系

- `workspaces`：稳定 ID、规范化目录、显示名称、项目授权、置顶、移出列表状态；工作空间查看偏好单独保存最近使用的有效空间标识。
- `sessions`：工作空间、角色、父会话、pi 会话文件、标题及命名状态（待生成／已生成／手动）、模型选择、手动置顶、结果／已读版本与派生未读状态、自动置顶冷却期限（未开始／冷却中／已回队）。
- `session_results`：按会话和结果来源去重的版本事件，执行结算与结果版本在同一事务中写入；不保存第二份消息正文。旧未读迁移为结果版本 1／已读版本 0，已读迁移为相等版本。
- `tasks`：父会话、子会话、委派锚点、任务描述、当前执行标识、最近工作计时基点与截止、总结截止及预算版本。
- `runs`：所属会话／任务、状态、阶段、重试元数据、原因码、续接来源、工作预算、起止时间、停止信息；无 `cleanup` 字段。
- `task_results`：唯一结果 ID、唯一执行关联、完整最终报告或部分成果、停止事实、通知状态与确认消息标识。
- `task_input_receipts`：输入身份、执行关联、状态及错误，不保存另一份正文；待处理正文仍由 `task_inputs` 管理，重启不重放。
- `task_queue_order`：每次入队的持久化递增顺序；`task_stops` 保存当前任务停止来源、原因和时间。
- `task_notification_attempts`：每次独立通知请求及所属父执行、结果列表、时间、状态和错误。
- `compressions`：唯一任务 ID、所属会话、请求标识、状态／阶段、起止及应用时间、快照消息数、前后估算、模型标识与摘要展示；会话逻辑删除保留。
- `compression_preferences`：应用级单条压缩模型选择（供应商、模型、思考等级）及自动配置 JSON（开关、Token 数、百分比）；旧表新增 `auto` 列，缺失值使用默认自动配置；独立于聊天模型默认值，不随会话删除而清除。
- `task_settings`／`task_model_preferences`：应用级单条子代理预算和默认模型选择；独立于主会话模型及会话删除，修改通过独立订阅同步。
- `memory_sources`：按主会话保存来源修订、摘要、检索词、整理状态与实际读取依据；源文件、引用依据或纠正变化时旧摘要失效。
- `memory_organizations`：每工作空间最近一次手动整理的任务身份、来源范围、处理计数、状态及起止时间；重启标记中断，不重放模型工作。
- `memory_preferences`、`memory_corrections`、`memory_usage`：查询／整理模型与预算配置、明确原文的跨会话纠正目标、逐次模型请求真实用量（缺失保持未知）。
- `requests`：操作 ID、归属、输入摘要哈希、受理状态与响应，用于安全重传。
- 界面偏好：保存各自归属和修改序号；不建立会话 `drafts` 存储。

具体建表可合并不必要的实体，但必须保留外键约束、执行归属检查和结果去重约束。应用数据库由服务进程管理，Agent 不直接写管理表。

### 8.3 恢复规则

- 会话上下文只从绑定的 pi JSONL 读取；请求回执用于归属校验与去重，不作为输入恢复或上下文重建来源。断线、刷新或重启不自动重发用户请求，不提供会话请求人工核实恢复流程。当前页面中迟到回执只能清除与已提交内容仍一致的目标输入。
- 服务启动只恢复索引与状态，按需要加载 pi 会话；不为查看列表启动全部 Agent。
- 缺失或损坏的会话文件显示错误，保留任务记录，不创建空会话冒充恢复成功。
- 已保存的最终消息与任务结果不因浏览器断线丢失。
- 进程崩溃时尚未持久化的流式尾部不伪装成完整结果；对应执行明确标记中断。服务重启将活动执行原子结算为 interrupted 并生成一次结果版本，重复重启不重复通知，不自动恢复模型请求。
- SQLite 写入失败时停止确认新变更并显示错误，不能继续返回成功。

应用数据放在系统用户数据目录，不写入项目仓库。主／子执行的冻结模型配置保存在该数据根下的 `run-models/`，由同一数据目录的服务锁保护；启动清理只处理本目录的残留快照，不清理共享 pi 配置目录或其他数据根的运行文件。Windows 使用 `%APPDATA%/Axiom2`，macOS 使用 `~/Library/Application Support/Axiom2`，Linux 使用 `$XDG_DATA_HOME/Axiom2` 或 `~/.local/share/Axiom2`。允许通过明确启动配置指定数据根目录。

### 8.4 会话渐进式记忆

完整约束见 [会话记忆专项方案](session-memory.md)。默认安装在 `~/.axiom/memory/` 初始化共享 `RULES.md`，在 `<sessionId>/` 初始化主会话入口 `MEMORY.md`。启动时复制并校验旧应用数据目录下的 `memory/sessions/`，保留原件作恢复副本，完成后原子提交含数据根归属的位置绑定。迁移失败继续使用旧目录，非默认数据根保持内部存储，复制来的绑定不跨实例生效。模型用既有文件工具按需创建 `references/`、`scripts/`、`artifacts/`，记录目标、约束、状态、约 10% 步进的整体进度、关键过程、结论、验证及下一步。入口通常约 1,000 字、最多 2,000 字，由模型拆分详情，程序不截断。提示词说明维护责任、信息取舍与读写时机，目录与格式由共享规则承载。正文用文字描述，详细地址放在文末脚注链接中；引用支持跳转、返回与资料导航，定义不进入任务进度或摘要。

每次真实压缩应用后，主会话尝试读取入口；记忆是可选辅助资料，入口缺失、归属不匹配或读取失败时按空记忆继续，不阻断会话创建、消息发送或恢复，也不弹出读取错误。成功完整读取和已尝试但不可用分别绑定当前分支 compaction ID，失败不冒充恢复成功，同一次压缩不反复要求读取不可用入口。正文不自动注入每轮请求。记忆补充 JSONL 恢复，不构成另一份对话副本。

`memory_query` 为主会话同步工具，内部一个只读 pi Agent 先查看当前工作空间全部有效的30字以内工作标题，再按相关性读取对应摘要、原入口和必要详情。标题目录只含来源标识与标题，摘要通过同一读取工具的虚拟 `SUMMARY.md` 获取，正文及明确引用随后按需读取。目录为空或不可读时直接返回空，不启动模型。查询没有累计读取字符或模型轮数预算，不做关键词预筛、来源数量限制或全目录前后扫描；标题与摘要只用于定位，答案至少需要实际文档读取，返回实际读取的来源与文档修订。不读取原始对话、执行脚本、递归委派或写入项目。

后台默认每5分钟检查，只为连续30分钟未发生修订变化的来源生成不超过30字的单行工作标题和不超过200字的任务自然语言摘要，概括工作、所解决的问题、成果和当前状态，排除文件路径、代码名称、命令及实施步骤，关联原记忆及修订。旧规范版本、无效标题和超长摘要失效，在正常周期重新概括，未变来源保留稳定起点。稳定起点持久化，普通扫描与重启不重置，来源变化重新计时并使旧摘要失效；文件变化不即时启动模型，批次结束后不立即续排，不另设活动会话门槛。后台模型只读本来源，不核实当前项目或跨会话冲突，不修改原记忆。整理提示和正文共用累计读取预算，读取未完整完成则不发布摘要。用户通过现有文件工具纠正本会话，界面可按明确原文清理同一工作空间的重复条目。

用户可在来源 MEMORY.md 的操作栏“立即整理”，或在全局摘要视图“整理工作空间”。单来源重新生成当前已保存记忆的摘要，工作空间处理全部待整理来源并跳过有效摘要与空入口，筛选只影响显示；两者绕过周期、30分钟窗口和后台每批4项限制，沿用读取权限、预算、用量及修订复核。手动与后台整理互斥，短请求返回受理身份，独立状态订阅显示进度、成功／失败／跳过数量和终态；关闭面板或断线不取消，显式取消阻止晚到回写，服务重启标记中断而不重做。手动任务结算后后台等待完整配置间隔，避免取消后立即自动重试。编辑、草稿、读取或保存未完成时不允许单来源整理，不隐式保存内容。

`memory.summaries.clear` 在确认的工作空间范围内只清派生主题、摘要、版本、关键词、依赖与生成时间，保留原记忆、来源修订和稳定时间、配置、纠正与用量。清理前取消涉及该空间的整理并使扫描代次失效，晚到成功或失败均不能恢复结果；跨空间需分别调用。整理受理、取消和清摘要均保存幂等回执，重放不产生新副作用。此清理不通过原文纠正接口实现，应用数据库仍由服务管理。

主会话正常完成且没有错误或特殊结算原因后，程序定向扫描最新记忆，对明确未完成、无阻塞或等待用户条件的待办接续原会话。以隐藏宿主消息触发 pi，不新增用户消息、不消费草稿、不将记忆作为新授权。启动前、工作进程准备完成和模型执行许可前复核原执行或本次接续、最新记忆修订、归属、授权、删除与停止状态。首次新输入和手动停止取消旧检查及尚未请求模型的自动准备，重复请求重放不产生取消副作用；并发新输入共享一次停止操作，后续手动停止仍使此前等待的输入失效。父会话冻结、活动子任务及待处理通知阻止接续，运行中的压缩完成后重验。相同任务状态不重复启动，每轮最多自动接续3次，重启不重放历史执行。该机制与后台摘要周期分离。

查询与整理通过 `PooledMemoryRunner` 接入服务级统一池；经过验证的固定进程／ModelRuntime 可以跨任务复用，每个租约新建内存 session、loader、settings、订阅、只读工具与访问闭包。记忆业务许可与物理名额联合准入，总截止时间包括等待与准备，默认300秒；整理另有默认240,000字符累计读取和32轮模型交互限制，查询不继承这两项。真实父租约的同步查询可使用受全局限制的叶子预留。成功必须等待本租约清理确认，取消及清理失败退役，实际 close 前不释放物理名额。真实模型用量纳入所属主会话费用，取消后已知消费仍保留。

上下文与会话记忆合用输入框下左侧用量区起始入口：20px细实线灰环提供完整轮廓，橙色弧长只表示真实上下文占用；内部三条稀疏细横线按任务三等分进度点亮。入口不显示数字，百分比、Token和任务估计集中到详情；全局记忆SVG按钮位于既有工具组末尾，统一16px，点击热区至少44px；面板定位、外部点击判定与关闭焦点恢复绑定实际入口按钮，不依赖鼠标点击是否转移焦点。不新增独立底栏，保留左指标／右工具分组，容纳不下时内部横向滚动。上下文与记忆按当前查看主会话分别订阅，点击合并入口在左侧浮层查看上下文 Token／容量、估算来源，以及记忆目标、状态、任务整体估计、清单和下一步；“当前进展”“下一步”等短标签按内容宽度保持横排，说明列可收缩并正常换行，长路径不挤压标签或撑出面板；点击外部、关闭按钮或Escape收起。任务整体估计只在详情中显示，不按完成项比例推断；小于100显示“约”，100仅接受有效的整体已完成记录，任务完成点亮三条横线，不改变上下文外环或清单造型。上下文未知保留灰色完整轮廓，详情显示“—”；记忆读取失败按空态展示，不影响有效上下文数据；进度冲突在详情中说明。入口不叠加右上角活动状态点，外环始终只表达上下文填充量；任务状态在详情中显示，读取、保存、打开和设置操作保留SVG气泡动画，减少动态效果偏好下仍播放，操作结束后移除。主会话按信息保留价值主动维护记录，最终回复前核对实际状态与结果，任务及必要验证完成时同步写100%。全局记忆列表、计数、搜索及来源筛选只包含整理完成且标题与摘要均符合当前规范的会话；待整理、整理中、失败、无摘要或摘要已失效的来源不显示，也不以原文摘录填充。无可用摘要时显示“暂无已整理的摘要”，来源筛选中已失效的选择自动清除；条目保留入口字符数。未整理资料仍可从当前会话入口查看，显示过滤不影响后台整理。当前摘要来源为已保存会话记忆，不自动总结完整对话或建立跨会话主题层。浏览按搜索、双列来源筛选和紧凑资料列表组织；工作空间与来源会话筛选使用应用内深色菜单，选中项以暖橙文字和勾选标记区分，长标题换行、列表内部滚动，并在视口内定位避免侧页裁切。触屏入口及菜单选项至少44px；支持方向键、Home／End、文字前缀定位、Enter／空格确认、Tab及外部点击收起，Escape优先关闭已展开的筛选菜单，组合输入不误关。筛选不切换聊天会话，切换记忆工作空间后焦点返回对应筛选入口。摘要全文自然换行，不按行数截断。点击摘要展开关联记忆，再点击来源进入原文，摘要主题与来源标题分别显示，之后展开关联／引用文件阅读；返回按钮固定在展开面板左下角，沿用项目轻量按钮、左箭头与至少44px热区，和正文使用一致的水平内边距；逐层回退时保留筛选、摘要展开状态与阅读位置。文档显示字数，编辑时显示草稿字数；本地打开只允许校验归属、路径、引用和文档修订后的 Markdown／文本文件，打开磁盘版本，不自动保存草稿或执行脚本。浏览不调用模型。资料编辑绑定修订，后台刷新和切换不覆盖草稿，冲突时保留草稿并读取最新内容进行合并。记忆面板与压缩／子Agent设置共用右侧非模态抽屉：贴顶边与右边，最大520px、窄屏满宽，底部在入口工具栏上方8px，标题与返回区固定。左侧统计详情保持锚定浮层。正文链接提取和Unicode字数按正文缓存，无关状态变化不重复解析。点击外部、入口或 Escape 收起，面板内向外拖动不误关闭；未保存编辑保护覆盖关闭、返回、切换其他底栏详情和工作台内的会话／工作空间切换；切换底栏详情时先保留记忆面板显示确认，继续编辑不打开目标，明确放弃后才切换；新建会话也先确认离开，取消不创建空会话。不修改原始设计源。

## 9. 通信与局部刷新

### 9.1 命令和事件

命令至少包含 `requestId`、操作类型、目标标识与参数；非应用级操作携带 `workspaceId` 和 `sessionId`。服务从实际数据关系确认归属，不能将传入标签直接作为授权。

会话事件形状：

```json
{
  "type": "message.delta",
  "workspaceId": "workspace-id",
  "sessionId": "session-id",
  "runId": "run-id",
  "seq": 42,
  "data": { "messageId": "message-id", "delta": "text" }
}
```

- 子会话消息使用子 `sessionId`，同时携带 `parentSessionId` 与 `taskId`；父列表的任务摘要只更新父会话的任务区域。
- 应用级模型配置事件使用独立配置修订标识，不伪造会话归属。
- 消息和工具使用稳定 ID，不用数组索引或时间戳作为唯一身份。
- 命令回执区分“已受理”与“执行完成”，错误包含机器可判定类型和脱敏说明。
- 同一 `requestId` 的不同参数直接拒绝，不能将其视为新请求。回执查询校验原请求的工作空间／会话归属；旧数据缺少归属时拒绝返回内容，不泄露回执或允许自动重做，不据此增加会话请求核实界面。

### 9.2 断线重连

- 单连接承载多个按作用域订阅的事件；不同浏览器标签页各有自己的查看订阅。
- 连接事实不依赖业务诊断文案。当前 socket 的 hello、合法快照或回执才更新响应证据；业务错误回执也证明通道可达。空闲时通过同一 socket 执行无持久化副作用的 `ping`；15 秒无有效入站证据时显示确认中，真实 close 显示断开，新响应恢复已连接。HTTP 就绪探测有 10 秒超时；重复连接入口不会创建并行 socket，旧 socket 的消息、关闭及订阅失败回调不能覆盖新连接或处理新请求。焦点／可见性恢复重新探测，不自动重发业务操作。
- 事件序号在明确的流标识内递增；服务重启更换流标识，客户端不能混用重启前后的序号。
- 重连提交已确认序号，有缓存时补发；缓存不足时获取对应会话快照与游标，再接增量。
- 快照与增量有同一游标边界，防止快照覆盖较新的消息。同一服务、同一序号在新连接代际的重新交付可复用旧数据对象，但须更新同步证据；低序号不能确认新鲜度。完整消息集合先完成删除、写入、配对线程索引和同步标记，再通知订阅者；集合水位拒绝不晚于该集合的旧消息增量，避免已删除 ID 复活。
- 快照包含当前流式消息、最终消息索引、任务状态与配置修订标识。
- 切换会话后到达的快照只写原作用域；过期加载请求不抢占当前页面。
- 慢客户端允许合并文本增量，不能丢失最终消息、工具结束、取消结果或请求回执。发送预算计算实际 UTF-8 排队与在途字节，普通预算 4 MiB 加最多一份合法大帧；等待读取与延迟集合各最多16个描述符。大读取在正文物化前准入，完整集合在发送边界生成；已准入读取先交付并释放，再物化后续集合。关闭视图或读取超时可取消尚未开始的只读请求，退订使旧订阅意图失效，失败订阅不占用配额，待处理重订的失败或取消不作废已有订阅的排队交付；不重放任何 Agent 操作。
- 子任务队列按 run、输入顺序、模式及 pending/native 分区去重；相同投影不重复发送，接受／消费等业务回执仍逐项处理。调度器在当前事件循环合并必要 scope 的视图失效，发送时读取最新状态；纯队列变化不重建父聊天。任务列表批量读取结果、回执与耗时，避免逐任务查询及多结果、多回执 JOIN 放大。自动通知先确认存在待发结果，无待发结果不重读父会话历史；普通结算没有待发／在途／未知结果时同样跳过历史核实。有待发结果仍先按原生记录核实消费与回滚标记，在途／未知结果继续在结算时核实，显式恢复不省略回滚标记检查。发布继续保留置顶、费用与活动摘要副作用；没有正文观察者时跳过完整历史构造，重连仍取得权威快照。
- 断线后重新订阅会话消息和状态，不自动重发 prompt，也不恢复未发送输入或要求人工核实会话请求。模型配置和后台压缩的专用回执按各自契约处理。

### 9.3 渲染边界

| 区域 | 订阅内容 |
| --- | --- |
| 工作空间与会话侧栏 | 当前工作空间的会话摘要，以及独立订阅的跨空间置顶摘要；均包含运行／未读状态 |
| 消息列表 | 指定会话当前压缩上下文的完整消息 ID 与分组，无分页；原始会话模式按需读取当前分支的压缩前后消息，实时更新仍按消息 ID 订阅 |
| 单条消息 | 该消息的内容与工具增量 |
| 输入区 | 该查看实例、该会话的草稿及发送状态 |
| 模型菜单 | 可用目录、当前选择与本地选择草稿 |
| 子任务卡片 | 对应任务状态、进度与结果摘要 |
| 子会话窗口 | 对应子会话的数据 |
| 压缩入口与详情 | 对应会话的压缩任务及操作状态，不订阅其他会话 |

- 应用根布局不订阅流式正文。
- 增量按帧合并，仅更新受影响消息；已完成消息的 Markdown 和代码高亮通过有界纯解析缓存复用。普通缓存最多五会话，每个派生缓存最多 128 项、估算 2 MiB；RAW 缓存属于当前查看实例，关闭时释放，不缓存带归属的 React 节点或图片授权结果。
- 普通历史须在消息集合与索引实际到达后才判断空会话。RAW 区分最后成功快照与最新同步状态，刷新失败及重试保留成功视图；每实例只允许一个在途读取，期间只保留最新需求。权威历史重建推进独立 `contextRevision`，不依赖默认消息 ID 推测归档变化；已展开全文详情也按历史代际失效，包括同 ID 截断部分的编辑。过期快照可继续阅读，但不放宽已读门槛。
- 过程事实由消息与任务索引批量派生，隐藏正文与普通工具详情按展开挂载；模型选择菜单、会话环境与费用明细同样按展开构造正文。文件预览按首次访问的模式构造内容，已访问模式保留滚动位置；子任务交付区首次展开后保留阅读状态，选择报告时旧请求不能覆盖新的选择。记忆进度及目录使用订阅首帧，避免同时发起相同显式查询；直接打开会话记忆不加载全局目录，全局目录首次访问后保留筛选状态，记忆设置打开才读取偏好。实际任务卡、通知等已读证据继续渲染。后台未显示会话的 delta 不触发完整历史冷读；未落盘终态保留至完整 JSONL 记录确认，不能因显示 LRU 淘汰而丢弃。
- 会话中的用户消息与助手回复支持 Markdown；正文单次换行显示为换行，空行继续分段，列表和代码块保持各自语义，收起的单行摘要仍保持单行。显示层兼容中文引号、括号开头或中文收尾标点与相邻文字间无空格的双星号加粗（如 `简化为**“完成”**就够了`、`**验证：**43`）；不改写存储或复制原文，代码块、行内代码及转义继续按字面处理，原始 HTML 与危险链接仍不可执行。
- 助手正文中的本地 SVG 图片引用沿用消息归属、绝对路径、非链接文件及读取前后校验；上限 1 MiB，仅接受静态图形、文字及本地渐变的受限 SVG，通过图片数据 URL 显示，不插入 DOM。拒绝脚本、事件、样式、外部资源、实体声明与动画；上传附件和模型视觉输入仍沿用原有格式限制。
- 长历史按需加载，长工具结果按需展开，不一次性渲染全部内容。
- 复用组件不等于复用状态，父／子会话不能共享草稿、滚动或模型菜单状态。
- 切换主／子会话后，消息列表默认定位到最新消息，异步历史加载及后续内容尺寸变化继续吸底；自动滚动的迟到事件和布局收缩时浏览器对滚动位置的自动修正不得取消跟随；暂停跟随依据实际向上滚动操作，不能仅凭滚动坐标减小推断。每次提交新输入（包括运行中追加的 Steering）清除当前消息区内的文字选区，立即滚到当前会话底部并恢复跟随，待执行输入仍按队列规则展示；正式消息对账及后续流式内容继续吸底。仅新增提交触发恢复，回执状态变化、消费或撤回旧输入不打断之后的手动阅读。用户向上滚动、在消息区点击或切换原始会话时暂停跟随并保留阅读位置；思考、执行过程、工具、环境、压缩及子任务详情优先在原点击位置向下展开，运行中与已完成行为一致；仅底部空间不足时按展开规则有限上移，露出短内容或长内容开头，不跳到卡片顶部或内容末尾。键盘激活、重复展开及首次异步全文加载遵循相同规则，手动阅读立即取消待执行上移；消息区禁用浏览器滚动锚定，收起不恢复吸底，内容缩短后仅允许必要的滚动边界调整。吸顶标题只随用户滚动生效，嵌套偏移按实际标题高度计算，主／子会话独立；子会话顶部“执行与交付”区域的点击也暂停该子会话吸底，展开和异步加载导致消息区尺寸变化时保持阅读位置。当前消息区内的文字选区暂停自动跟随，其他区域的选区不阻止新会话吸底。
- 流式输出时保持输入法、焦点、选区、菜单打开状态与用户手动滚动位置。

## 10. 本地服务与桌面运行

- 第一阶段定位为本机单用户，服务默认仅监听回环地址，不默认暴露到局域网。
- 管理 HTTP 与 WebSocket 均需要本地访问校验和来源校验，防止其他网页借用本地服务执行命令。
- 工作空间访问在选择目录打开时默认授权；Agent 项目资源默认授权并按 pi 规则加载，不因非交互运行等待额外确认。新增命令型密钥／请求头的授权仍须显式处理。
- 服务进程集中管理工作进程、数据库连接和退出流程。
- 关闭浏览器标签页或 Pake 窗口只关闭客户端，后台服务和任务继续；用户明确退出服务时显示活动任务并进行停止与持久化。

的可用内容边界避开原生标题栏，并覆盖缩放、最大化和全屏切换。服务地址改变时重建工作台；控制检测超时、安装记录异常或尚未确认退出时保留原工作台，不据此推断业务连接断开。只有受管理入口打开的视图受服务管理结果影响；被动检测到停止时还需确认其工作台连接已关闭，显式停服成功或确认更新后可销毁该受管理视图。通过设备菜单直接连接的本机开发服务和远程视图均不被这些结果销毁。控制页图标定义由独立CSS隐藏，不依赖会被Tauri nonce策略拦截的内联样式，避免空SVG占据文档流并推移顶栏。原生层在连接建立期间保护当前视图，受管理状态轮询不能取消新的直接连接；打开请求从入口计算55秒总提交期限，晚到结果不得显示旧目标。管理结果在主线程事务中核对视图归属和请求修订，避免迟到结果关闭新连接。关闭窗口退出桌面客户端，退出后再次打开恢复控制入口并识别已有后台；再次启动已运行的客户端只聚焦现有窗口。关闭客户端不会停止服务。
- 桌面原生命令只接受固定动作，并验证实际调用 WebView 的标签、父窗口与内置来源，不以共享父窗口作为授权依据；通过安装记录找到 Node.js 与 CLI，以固定参数直接执行，不执行网页传入的 shell 命令、路径或 PID。CLI 使用独立回环控制端口及每次启动随机凭据，拒绝浏览器 Origin、错误 Host 和未授权请求；正常退出经现有服务关闭流程，不按残留 PID 强杀进程。安装记录和控制凭据保存在用户数据目录，后台日志写入 `service.log`。业务服务保留原有回环绑定、Host／Origin 校验和禁止 iframe；远程工作台没有原生服务控制权限。
- 顶栏连接状态通过独立只读桥接查询，不等待服务管理锁。只有内置控制页可发起查询，原生向当前工作台发送短期请求编号；上报只接受当前工作台 WebView、父窗口和实际 origin 匹配的当前请求，载荷限制为连接／断开／确认中三个状态。一次回应后消费编号，800ms 期限同时约束上报和读取；并发探测使用最多四个独立请求槽，不互相覆盖。超时、重载或销毁使旧请求失效；控制页查询另设 2 秒期限和 3 秒证据过期检查，无回应显示确认中，不复用旧绿色。只读上报不能调用管理操作或改变视图。旧后台页面不支持上报时显示确认中，需要更新后台以获得连接状态。
- 应用内更新从内置控制页发起，分别展示客户端、后台与发布版本。更新源固定为本仓库正式 GitHub Release，拒绝异常版本、外部附件地址及不匹配的 SHA-256／大小；不接受网页提供的下载 URL、路径或安装参数。嵌入客户端的 Node 内置模块更新器使用 SQLite 任务归属和独立后台进程，关闭客户端不取消更新，重新打开恢复进度。后台预备安装固定使用 `--install-strategy=shallow --ignore-scripts`，覆盖用户的默认依赖布局，将候选包及其自身完整依赖树一起移动，准备目录中的自身 bin shim 不进入安装目录；仅标准、可写的 `node_modules/@cosyeezz/axiom2` 包目录允许切换（拒绝包根符号链接）；仅针对受管理工作台，确认后销毁该视图并显示控制页更新进度，直接连接的视图保持；安装准备完成后才停止旧服务。后台更新与恢复仅支持单一数据目录独占服务安装。锁与服务探测按数据目录工作，不具备安装级实例登记；多个数据目录共用全局包不受支持，须使用独立安装目录，或停止全部相关服务后手动更新。目录切换期间持有现有启动协议的 reservation，并核实没有存活的服务描述符，防止并发启动穿过切换；界面及原生桥接阻止冲突管理动作。切换前写恢复记录，保留 CLI 路径和旧程序备份，启动新版并确认实际版本后完成；失败尝试恢复旧程序，更新进程异常退出后支持原 CLI 缺失时恢复；不保证系统崩溃或掉电后的自动恢复。恢复前核对备份版本，始终使用该备份中的控制代码确认服务退出，不能因候选 CLI 文件存在就依赖其控制模块；未确认退出时不得移动目录。清除恢复记录前核对安装目录的旧程序版本及服务报告的运行版本；备份已缺失且安装目录不是旧版本时保留记录并报错。旧后台协议不报告运行版本时，仅确认旧程序和服务运行状态。恢复仅针对程序，不回滚数据库或会话数据，发布须保证迁移兼容性。
- 「服务与更新」的 pi 引擎区域分别显示已安装后台包依赖的 pi 与后台 Node.js 所属 npm 全局终端 pi。应用内 pi 随经过验收的后台服务整包更新，不能以升级终端 CLI 代替 SDK 更新。终端支持查询安装路径、从官方 npm 仓库检查稳定版本及确认安装／升级；确认 token 绑定版本、Node/npm 真实路径及全局安装目录身份，加锁后再次复核。使用固定 prefix 与命名空间 registry、`--ignore-scripts --engine-strict`，拒绝降级和旧命名空间的同名命令覆盖。安装失败后重读实际状态，不承诺 npm 全局安装回滚；安装目录锁阻止应用更新器并发操作，异常残留时明确提示检查。配置及会话保留，终端现有进程需结束后重新打开。可选 pi 缓存损坏不阻断后台／客户端更新状态，需显式重新查询修复。
- 后台自动发布由 `master` push 触发，三平台、两组 Node.js 各自运行独立的完整测试任务和安装／升级／恢复验收任务，两类任务可并行，各自构建且保留独立的30分钟上限；十二个任务全部成功后才进入独立写权限的发布任务。PR、手动 CI、失败／取消验证不发布。按源码版本与已保留的正式格式 tag／Release 最大版本递增补丁号，在源 SHA 的直接子提交中仅同步五个分发版本文件，tag 绑定该快照，不回写开发分支。最终快照重新构建并以安装／升级／恢复验证实际上传的 tarball；先上传草稿，核对唯一附件、本仓库地址、大小与 API SHA-256 后再公开 Latest；草稿允许临时 `untagged-…` 地址，公开后要求对应版本 tag 的固定下载地址，并验证公开下载。新 push 取消旧 push 的 CI／发布流程，历史重跑隔离并发组，不取消当前流水线；后台仅修改草稿附件，macOS 附件发布仅操作正式版本并独立串行。同源重跑复用 tag／草稿，已公开版本只重新核验下载，不改写附件或重设 Latest，允许桌面校验清单追加。执行前和公开前检查远端 master，过时源跳过，禁止旧版本覆盖较新 Latest。源码与版本以发布 tag 为准；桌面原生改动仍独立从该 tag 构建，源码安装仍采用拉取、构建与重启方式。
- Windows 客户端附件下载和校验完成后仍需用户确认启动系统 MSI 向导；启动前重新校验文件，使用固定系统 `msiexec.exe` 和独立参数，随后退出客户端，后台服务继续。安装器启动不等于安装成功，完成向导后重新打开客户端验证版本。旧客户端首次手动安装带更新桥接的客户端；源码安装、Node.js 缺失及无写权限继续使用原安装方式。Windows 原生更新测试使用独立标识、数据、npm prefix 与缓存、本地发布 fixture；仅测试构建将安装器启动替换为原生程序路径和参数记录，覆盖篡改文件零次启动与有效文件的固定参数，不执行假 MSI。仅在最近请求的任务终态、worker 退出且后台停止后删除夹具，状态未知或超时保留现场。发布产物不含测试源覆盖入口或安装器替身。真实 MSI／UAC 升级需单独验收。
- OAuth 由本地服务打开系统默认浏览器，并提供复制授权链接及手动回填兜底，不在桌面壳内导航授权。Windows MSI／EXE、macOS 通用 DMG 与服务 tarball 通过 GitHub Releases 提供下载和 SHA-256 校验，源码不包含二进制与用户运行数据。桌面构建从固定 Pake 版本创建隔离模板，注入原生桥接，以根 `package.json` 版本统一设置 Pake、Tauri 和 Cargo，不修改全局安装的 Pake 源文件。macOS 通用包包含 arm64 与 x86_64，采用 ad-hoc 签名，未经过 Apple Developer ID 签名或公证；拖入 Applications 后使用，客户端自身更新通过退出并替换应用完成。手动构建工作流可选择平台和源码 tag／commit；macOS 发布前检查镜像、架构、版本／标识、签名及正式产物无测试入口，并在隔离数据目录启动复制出的正式应用、确认该进程拥有可见窗口。独立测试构建在真实 WKWebView 中操作打包控制页，检查单原生窗口双视图、管理权限拒绝、草稿／选区／滚动／焦点保留、原生缩放、服务启停、窗口关闭及重开复用后台，并用 CoreGraphics 核对工作台显示时只有一个可见应用窗口；测试入口不进入正式产物。诊断 artifact 不作为发布包，这些检查不替代完整业务、文件选择、模型交互或首次安装验收。
- 安装包构建、原生窗口交互、真实 OAuth 系统浏览器跳转及目标系统进程管理分别验收，不相互替代。Windows 原生 UI 自动检查需要已连接、解锁的桌面会话。
- Windows 的命令工具按实际环境选择并检查依赖；启动参数使用数组传递，不拼接未经校验的 shell 字符串。
- 跨平台验收在实际目标系统执行，不以路径判断单元测试代替桌面启动和进程停止验证。

### 10.1 Tailscale 内网与安卓端

- 内网直连是默认能力，网关随业务服务启动，只绑定操作系统当前可见的 Tailscale IPv4／IPv6 地址，端口与业务服务一致（默认 4317）；每 5 秒重新发现接口。回环业务服务保持独立，网络接口消失时关闭对应远程连接，接口恢复后自动接续。不得绑定所有网卡或自动配置公网转发。
- 不提供内网管理入口、页面或启停开关，不读取或保存 `remote.json`，旧配置不影响默认监听。Tailnet 可达设备直接进入完整工作台，无应用密钥、登录页面或授权 Cookie 交换。转发前校验 Host、Origin 与 Sec-Fetch-Site，清除客户端认证及转发头；本机 `/api/remote` 仅提供 GET 诊断，供开发桥接判断接管及电脑设置页读取当前连接地址，其他方法返回 405，远程访问及规范化路径别名返回 403。访问范围由 Tailscale 网络与 ACL 决定，业务遵循现有约束和操作系统权限。
- 桌面远程连接不要求本机 Node.js 或 Axiom 后台；原生层限时读取 `tailscale status --json` 的在线 Peer，显示设备名与 Tailscale IP。选择后填入地址与默认4317端口，由用户确认连接，也可手动输入 Tailnet IPv4／IPv6 和端口；端口框为最终端口。HTTP状态和工作台WebSocket分别确认，设备在线不等于服务就绪。仅内置控制页可安装、发现节点和切换视图；远程工作台无本机管理权限。本地停服不关闭远程视图，迟到连接请求按代际拒绝。最近成功连接地址在业务连接确认后保存。Windows Tailscale 可用 winget 安装；macOS 有 Homebrew 时通过其安装，否则提供官方下载入口。
- 安卓提供 `com.axiom2.android` 安装包及 `com.axiom.sdk.AxiomWebView` AAR，最低 Android 8.0，使用系统 Tailscale VPN 与系统 WebView。APK版本默认取根 `package.json`，仅交付客户端时允许PowerShell显式指定 `-ClientVersion` 或Gradle `-PclientVersion`，不改后台版本；正式交付固定源码提交并使用高于已安装版本的客户端版本。PowerShell及Gradle均按 `major × 1,000,000 + minor × 1,000 + patch` 编码versionCode，minor／patch限制为0—999，编码大于旧版404且不超过2,100,000,000；升级复用原签名，APK与AAR从同一源码构建并附校验和。启动展示扫码连接、地址输入、可选设备发现和最多8条最近成功连接记录，省略端口使用4317，不内置开发电脑地址；工作台连接无访问密钥或登录表单。SDK 为 `connect(address)`。安卓不跨应用读取 Tailscale 私有状态，不继承官方 App 登录态；工作台根页面返回操作提供切换连接。连接成功须确认后台状态和工作台 WebSocket 就绪，HTTP 错误或旧导航不得误报成功。取消、重试及销毁释放拥有的请求，旧回调不能影响新连接；渲染进程退出后重建 WebView。
- 电脑「配置」概览以内嵌「手机连接」分区展示二维码，沿用配置页标题、分隔线和按钮布局，不使用弹窗或地址输入框。进入配置页即通过本机 `GET /api/remote` 自动获取已监听地址，在浏览器本地生成二维码，IPv4优先并允许切换IPv6，不新增后台接口。桌面将二维码与说明、地址操作紧凑并排，窄屏上下排列；地址只展示一次，复制与刷新就近放置。多地址使用与配置页一致的自定义菜单，显示地址族、完整地址和选中标记，支持方向键、Home／End、Enter／空格选择、Escape／Tab及外部点击关闭，菜单限制在可见视口内。二维码仅包含显式端口的HTTP Tailnet字面IP根URL，禁止凭据、域名、其他路径、查询及片段；没有有效地址时显示等待或错误，不展示占位码。读取响应上限16KiB、8秒超时，页面内每次完成后5秒刷新，离开配置页中止，403停止自动刷新；复制反馈绑定当次地址。
- 安卓扫码使用固定SHA256的ZXing core 3.5.3，本地处理摄像头帧，无Google服务依赖，不保存或上传画面；浏览器编码依赖qrcode 1.5.4。进入扫码才申请权限，拒绝可重试或返回手动连接，相机硬件可选。相机打开、预览、解码和释放在独立线程串行，TextureView退役纹理在相机释放后销毁；暂停、取消和销毁使旧代际失效。有效扫码结果再次校验后进入现有SDK连接，只有WebSocket就绪才保存成功历史，重复或迟到结果不得重复连接。
- 安卓设备发现通过独立 OAuth client 的 `devices:core:read` 权限直接调用固定官方 HTTPS token 与设备列表端点，不新增后台接口。首次由管理员创建只读 client，配置 ID、secret、Tailnet（默认 `-`）及服务端口；普通 API key 不默认视为只读。凭据只在本机以 Android Keystore AES-GCM 加密保存，短期 token 不持久化；不发送到电脑、WebView、探测请求或日志。配置窗隐藏 secret、禁截屏和自动填充，关闭清除草稿；同 Client ID 的空 secret 可保留已有值。移除需确认，删除本机密文和密钥，保留手动连接历史，不代替管理端撤销授权。
- 设备清单最多1000台，支持名称／IP搜索、每页10台及取消刷新。云端状态只认 `connectedToControl` 的布尔值，缺失显示未知，管理清单不代表手机ACL可达性。当前页最多4路探测，仅使用合法 `100.64.0.0/10` 或 `fd7a:115c:a1e0::/48` 字面IP与配置端口，每台IPv4优先、IPv6回退；禁止DNS枚举、子网扫描和HTTP重定向，响应大小、请求与界面等待均有限制。`/api/status` 必须返回布尔 `connected=true` 才显示服务可达；点选只填地址，用户确认后仍由SDK核实实时连接并保存历史。请求代际隔离，后台暂停、切换连接及销毁取消读取和探测并关闭配置／移除确认窗；持久保存与删除跨Activity共享串行队列，防止旧保存覆盖新删除。
- 当前已运行的旧开发服务通过 `scripts/dev-tailnet.mjs` 透明转发，不重启业务进程；新版后台提供 `/api/remote` 后桥接释放监听，让默认网关接管。
- 手机文件上传的图形按本次选择文件总数与已确认成功回执计数，不显示字节进度。读取中、等待回执、确认成功分别说明；超时／断线标待核实，不自动重传，部分成功明确保留。上传期间禁用目录选择操作，关闭后不发送后续文件或更新已关闭选择器；关闭不撤回已经发送的上传。
- 手机工作台沿用原消息／命令协议和完整业务入口。安卓原生入口默认全屏阅读，隐藏系统栏（边缘滑动可临时显示），会话填满可用视口；手机及安卓不显示右侧滚动导航，也不预留其横向空白。阅读模式仅保留对话及展开按钮，不卸载消息、订阅或草稿；展开恢复原会话操作。手机输入框固定40px单行高度、字体14px，附件、模型选择与发送控件同排，外框高56px；模型名省略但菜单可打开，长行横向滚动不自动折行；统计与工具连续单排，普通图标16px、数据图形20px；数字按需点击查看，溢出时在工具条内横向滚动，不撑宽页面。抽屉管理背景 inert 与键盘焦点；Escape 优先关闭可见 Tooltip，其后处理输入或内部菜单取消，再关闭抽屉并恢复入口焦点。会话指针单击与双击重命名分开仲裁，双击仅重命名并保留当前查看会话与未读状态，键盘选择立即执行；阅读模式切换后焦点转移至可见的展开／收起入口。保留安全区与IME避让，分别适配横屏、短屏、长代码与弹层。
- 内网客户端选择项目或附件时浏览电脑目录，不在电脑弹出不可见的原生选择窗口；可翻页、进入目录及确认文件／文件夹。手机文件通过系统选择器上传至现有归属限定附件流程，遵循现有数量和大小约束。回环客户端继续使用原生文件选择器。
- 手机回到前台或网络恢复时检查业务连接并重新订阅；握手、无回应均有超时。重连不能重放 prompt 或其他有副作用操作，已确认保存的草稿按原恢复契约读取。
- 验证分别覆盖网关无凭据 HTTP／WS、来源校验与接口恢复、浏览器多尺寸交互、APK 构建签名与 AAR 消费、实体安卓和跨设备 Tailnet。浏览器视口模拟及同机 Tailnet 连接不能作为真机、软键盘或跨设备网络验收证据。安装与 SDK 运行说明以 `app/android/README.md` 为准。

## 11. 开发顺序与阶段门槛

### 步骤一：运行基础与设计落地

- 建立前后端构建、服务启动、WebSocket 和 SQLite。
- 提取设计样式，建立工作台、配置概览、模型服务三个独立页面。
- 建立工作空间／会话标识与局部订阅，不保留全局整体重绘入口。
- 验证 pi SDK 创建会话、注册独立工具、消息事件、停止和模型认证接口。

门槛：页面布局可对照，连接与空态真实；无模型时不能意外发起请求；设计源未改变。

### 步骤二：模型与主会话闭环

- 完成模型配置覆盖、pi 登录／退出登录、目录筛选、模型选择。
- 完成真实主 Agent、附件、工具输出、停止、持久化恢复。
- 完成会话列表交互、工作空间隔离和用量展示。

门槛：从打开目录到实际修改文件可完成；配置删除不会残留可选项；双会话同时运行不串数据。

### 步骤三：子 Agent 闭环

- 注册四个工具，完成任务队列、独立子会话、预算、取消与追问。
- 完成结果落库、通知、读取、去重与停止后的冻结。
- 完成子任务卡片及独立子会话窗口。

门槛：多个子任务并行、单独取消、结束后追问、父会话停止和故障恢复均符合契约。

### 步骤四：产品验收与交付

- 完成响应式、键盘操作、视觉对照、长对话与流式交互测试。
- 验证断线重连、服务重启、配置冲突、磁盘失败及拥有进程的终止；Agent 停止不要求人工清理确认。
- 完成浏览器与 Pake 运行验证及跨平台安装启动说明。

门槛：全部第一阶段验收项通过，无模拟数据冒充实际能力，无未说明的支持范围。

## 12. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| UI-01 | 页面复刻 | 三个页面与子会话窗口符合设计几何、样式和交互状态；规定视口无意外溢出 |
| UI-02 | 连续输出期间操作 | 输入、中文输入法、模型搜索、菜单、切换会话和滚动均不被流式刷新打断 |
| ISO-01 | 双工作空间、多会话并发 | 消息、附件、草稿、工具、模型回执和子任务全部回到发起时的目标 |
| ISO-02 | 多标签页与父子窗口 | 查看状态相互独立；关闭窗口不取消任务 |
| MOD-01 | 空配置和新增模型 | 空列表禁止发送；保存并完成所需认证后才出现在会话菜单 |
| MOD-02 | 删除模型／供应商 | 执行 pi 退出登录、提示供应商级影响、移除目标配置与收藏；环境变量不能使删除项重现 |
| MOD-03 | 配置冲突与失败 | 并发保存拒绝过期草稿；无效配置不覆盖有效文件；部分失败准确反馈 |
| MOD-04 | 行内编辑统一保存 | 完成／切换只暂存，统一保存包含隐藏编辑；无效项保留可修正，草稿不漏存 |
| AGT-01 | 主 Agent | 发送启动单 pi 工作进程，真实工具过程可见；强制停止后新消息使用绑定 JSONL，不经过恢复或清理确认 |
| CMP-01 | 后台压缩 | 安全点保存快照、后台真实 pi 摘要、新的安全点自动应用；主／子归属不串，原始历史与新增消息保留，冲突／失败不应用；取消、重试、停止与撤销有界，重启不重放 |
| CMP-02 | 压缩与用量界面 | 上下文容量边界／未知态准确；四阶段如实展示，completed 仅指已应用，摘要 usage 应用后计入会话且详情不重复相加；入口仅打开页面、完成／取消后可再次启动、统一模型选择与全局持久化、焦点恢复、减少动画及九视口布局符合设计 |
| SUB-01 | 委派与读取 | 多个调研或独立测试子任务立即返回标识，完成后通知并读取正确结果，无进度轮询；初次与恢复执行均可使用平台命令工具验证，非零退出码保留为失败；伪造写入／递归工具调用失败，配置与扩展不能改变白名单，主代理保留修改能力 |
| SUB-02 | 追问续接 | 运行中追加及结束后追问符合 pi 队列语义；新执行不覆盖原结果 |
| SUB-03 | 取消与预算 | 单独取消只停止自身；`workMs` 到期进入无工具总结，3 分钟后强停；有效追加刷新工作时限并可从总结恢复；仅配置 `workMs`／`concurrency`；重复取消无重复结果，不伪称回滚 |
| SUB-04 | 父会话停止 | 子任务终态可见，自动唤醒冻结；打开窗口和发送子会话消息不擅自恢复父代理 |
| REC-01 | 断线重连 | 快照与增量不重复、不回退，不重复发送用户请求或重复启动子代理 |
| REC-02 | 服务中断 | 从绑定 JSONL 读取消息并展示持久化结果；在飞执行标为中断，缺失文件不静默重做；未发送草稿在确认保存后可跨页面与服务重启恢复；恢复不启动 pi 或重放请求 |
| SEC-01 | 凭据与授权 | 浏览器存储、日志和事件不泄露凭据；工作空间访问在打开时默认授权，保留新增命令型密钥／请求头授权；Agent 项目资源默认授权加载 |
| PLAT-01 | 平台交付 | 目标系统可启动服务和桌面壳，目录路径正确，Agent 停止只作用于拥有的进程，无人工清理确认，不承诺外部副作用回滚 |

核心逻辑使用最小可运行自动检查覆盖；界面使用浏览器交互与截图对照。真实模型调用需使用获准的测试认证，不能以模拟单元测试代替供应商连接验收。

验收截图使用一致的视口、字体、页面状态与确定性内容；仅屏蔽时间等确实动态的信息，不屏蔽待验证布局或错误。测试产物写入开发或临时目录，不写入 `ui/`。
