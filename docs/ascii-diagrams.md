# 字符图本地美化

聊天 Markdown 可自动识别部分 ASCII / Unicode 字符图，将原有线框、转角、分支与箭头绘制为 SVG。模型不必输出 Mermaid，不增加模型请求、Token 或外部图表服务依赖。

## 展示与原文

- 默认显示识别成功的美化视图；点击「原文」显示原始字符图，点击「美化」切回。
- 复制按钮始终复制输入的原始字符文本；消息存储、整条回复复制和共享 Markdown 解析规则不变。普通段落中属于图块的结尾换行也保留。
- 描绘现有线条，不推测 AND / OR、节点归属或执行顺序，不把无框文本强制加成判断框。对几何证据唯一的开放分支，允许仅在美化视图对齐最多两格的缩进错误；不添加缺失的过程线。发生对齐时标题显示「已对齐」，悬停说明行数及最大偏移；原文视图和复制仍使用未经修改的输入。
- 生成中的回复保持原展示，结束后再识别；单行折叠摘要不绘图。
- 窄屏保持可读字号，图卡内部可横向滚动，不将整图缩成不可读的小字。主题颜色跟随界面。

## 识别范围

支持普通段落内的连续字符图，以及无语言标记或标记为 `text`、`txt`、`plaintext`、`plain`、`ascii` 的代码块。显式标记为编程语言的代码块、行内代码和 Markdown 表格不自动转换。普通段落图块之外的说明仍按 Markdown 展示。同段落包含行内代码、链接、强调或其他复杂内联结构时，保留原 AST 渲染，不切段美化，避免跨行格式或全局引用定义失效；将图单独成段或放进文本代码块即可识别。

识别依据为线框字符端口及相邻连接，不是关键字猜测。常见 `─│┌┐└┘├┤┬┴┼`、圆角 `╭╮╰╯`、ASCII `- | +` 和方向箭头可参与绘图；圆角会绘成曲线，不会变成直角。粗线、双线、虚线及其他未支持的线型、斜线分支暂保留原文，避免把有意义的线型统一成实细线。需有足够的连接结构；目录树、ASCII/Unicode 网格表格、孤立符号、单行箭头说明、明显错位的框与无法识别的图保留原展示。不承诺任意 ASCII 艺术或错位图均可转换。

轻微缩进容错不依赖关键词：三行 `┐ / ├ / ┘` 的上下端点原本同列时，可将偏移一至两格的中间分支对齐；相邻 `├ / └` 以下方分支对齐上方固定锚点。只移动以该分支起始的整段接点、横线/箭头和标签，不单独挪线导致穿字。全部提案基于原始显示列一次生成，修正后再次通过完整识别门禁；已正确对齐的坐标不变。闭框、Tab 缩进、跨空行、超过两格、多个候选锚点、含第二结构的移动行、会切断既有连接的修正均不采用。独立 `↓` 仍作为原符号展示，不因对齐而补上与动作之间的连线。

ASCII 笔画先组成候选连通图，再确认是否属于线框或外部箭头。框内不与结构相接的 `a + b`、`a -- b`、`x | y`、`a --> b` 等保留为文字；连续两行 `save` 不会把 `v` 吞成箭头，连续的 `++ i` / `++ j` 也不会变成小方框。纯 ASCII 嵌套框需要真实横边、竖边及内部区域；箭头的尾侧必须有最终确认的非箭头笔画，不能靠未绘制的候选字符互相背书。识别失败的文本代码图也保留不换行、卡内横向滚动，不因手机换行进一步破坏布局。

## 文本代码块中的页面线框

对于上述文本语言代码块，如果整块流程图识别失败，会额外逐块识别 Unicode 页面面板：上边为 `┌─┬─┐`（可单列），下边为严格对应的 `└─┴─┘`，中间仅有同列数的 `│` 分隔正文行，不含水平中线、嵌套 Unicode 框或外接竖向／斜向流程线。这样支持指标卡、左右面板等线框，但不将 Markdown 表格、ASCII 网格及带横向行分隔的表格强行转图。这一路径不用于普通 Markdown 段落。

- 原始上下边的缩进、列宽和接点必须完全对应；左边界不移动。每个边界相对该行原始显示列最多移动两格，超过就整面板回退。
- 只调整单元格尾部的 ASCII 空格，不删改标签、内部空格或全角空格。标签顶到边框时，允许将列宽扩展为“不小于原始列宽且能容纳完整文字”的最小值；上下边同样受累计两格预算约束。不补流程连线、不推断组件语义、不压缩字形。
- 多块面板分别转换；坏框和标题、筛选器、说明仍按原序以文本显示，不拖累别的可识别面板。整块「原文／美化」切换与复制始终对应未经改写的整个代码块。
- 面板内 ASCII 算式、箭头和示例小框均作为文字，不识别为新流程笔画。尺寸与控制字符预算按整个代码块累计，解析结果及失败结果均缓存。

## 无外框表单线框

文本语言代码块另支持“标签行 + 下一行空方括号框”的静态表单，覆盖五项一行、日期单独一行其余两列、全部单列等源布局。`[   ]`、`[────]` 和 `[----]` 会绘成轻底色的圆角输入框；按钮/操作说明仍按原文字展示，不生成真实输入控件，也不执行操作。

- 整块至少三个字段；每个字段必须在紧邻上一行有一一对应的标签，多列标签以至少两个 ASCII 空格分隔。按显示列匹配，标签起点与字段最多相差两格，不移动原文字或重新推测响应式布局。
- 框内仅支持至少三个 ASCII 空格，或至少三个连续 `─` / `-`；有值括号、`[]`、`[ ]`、Markdown 任务列表、链接、数组、含赋值等代码语法、混合流程线和不完整字段均不转换。包含右向左书写文字的表单保留原文，避免逐字源列定位破坏词序或连写。普通标签加多个空括号与表单可能语法同形，不能按语义保证零误识别；限制在文本代码块中，不用于普通段落或显式编程语言。
- 原文切换、复制、流式/摘要门禁、主题、自然字宽、移动端卡内横滚和整块资源预算沿用字符图规则。形状为本地 SVG，源消息保持不变。

## 宽度、安全与预算

使用字素簇建立显示网格：通常中日韩文字与 emoji 占两格，线框与箭头占一格；Tab 按四列展开。SVG 分别定位文字与线段，文字保持 14px 自然字形，不使用 `textLength` 强行拉伸或压缩；采用紧凑的 22px 行距。ASCII 字符与脚本转换处独立锚定源列，防止中文自然字宽导致后面的英文或标点累计错位；连续中日韩词组保持自然字距并在所属网格范围内居中，不逐字拉开。不依赖中文回退字体恰好等于两格宽，仅上述明确开放分支形状允许修正少量前导空格；流程图其他作者原有列错位不重排；文本代码块的面板纠偏规则见上节。原文视图及复制不展开或改写原始 Tab。

最多 24,000 个 UTF-16 单元、120 行、240 显示列、16,000 个网格单元；超限、控制字符及双向排版控制符降级原展示。SVG 仅通过 React 元素和转义文本生成，不插入原始 HTML，不使用 `foreignObject`、脚本或外部资源。解析异常保留原渲染，预览异常回退原文。

```sh
npx tsc --noEmit
AXIOM_TEST_BROWSER='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npx tsx tests/ascii-diagram.check.ts
AXIOM_TEST_BROWSER='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npx tsx tests/ascii-diagram-gallery.check.ts after
AXIOM_TEST_BROWSER='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npx tsx tests/code-block.check.ts
```
