## 状态与范围

这是用户讨论“先按目的整理成主题，再查询过程和结果”后形成的第一版方案，尚未实施。第一阶段原有的同源更新、相同合并、不同共存及其验收记录继续有效，不撤销已完成工作。此次补充改变的是整理的分类依据；第二阶段再处理按需读取和答案输出。

用户已明确：记忆包含目的，一个会话可以追加多个目的；需要的结果包含路径、方案、成功做法和失败经验；答案不需要说明记忆来源。

## 建议结构

优先复用现有四字段，不增加一套独立目录系统：

| 现有字段 | 建议含义 | 作用 |
| --- | --- | --- |
| Topic | 从任务目的提炼的具体主题 | 判断历史是否做过相关工作 |
| Section | 该目的下的子问题、操作环节或方案类别 | 判断需要读哪部分过程 |
| Item | 具体可复用事项 | 指明已定位入口、采用方案或失败尝试等 |
| Content | 该事项的过程要点与结果 | 保存必要步骤、路径、适用条件、成功/失败结论 |

目的决定主题，而不是看到某个技术词就单独建主题。一会话多目的可以形成多个主题；不同会话做相同目的时可复用同一主题，但仍保留各自条件和内部来源关联。不机械照抄“继续优化”等含糊目的，也不把所有操作都拆成Topic。

Section按实际任务需要形成，不强制每个主题都有“定位、实施、测试”三栏，不把每条命令和读取操作单列为事项。不强制固定类别枚举；命名必须让查询者看出对象和范围，例如“提示词接入位置”，而非孤立的“定位”。

### 示意（非新增事实）

```text
Topic：Axiom记忆维护指令
  Section：提示词接入位置
    Item：运行时文案入口
      Content：入口路径、函数及必要接入关系
  Section：完整替换方案
    Item：新版文案接入方式
      Content：采用方式、范围、验证结果
    Item：已排除的替换方式（若历史确有记录）
      Content：当时为什么不适用、适用条件、有依据的替代方式

Topic：Axiom记忆自动整理
  Section：整理触发条件
    Item：任务完成后触发
      Content：触发规则与限制
  Section：整理失败处理
    Item：单文件失败隔离
      Content：处理方式、失败边界与验证结论
```

问“系统提示词在哪里”，先命中相关主题，再找到“提示词接入位置”下的已记录路径，直接给路径及必要说明。问“怎样替换”，则取得对应方案；相关失败尝试应一起总结，避免重复走不通的路。不得把特定条件下失败扩大为永久不可用。

## 当前实现依据

- `app/src/shared/memory-tree.ts`已有Topic/Section/Item/Content四字段，不需要为这一分类含义立即新增数据库层级。
- `app/src/shared/memory-prompts.ts`当前按稳定主题、功能环节提取记录，尚未明确以任务目的统领归类；可以在现有规则上调整。
- `app/src/server/memory-pipeline.ts`的`organizeFiles`向整理模型提供当前文件、允许引用、`branchContext`和已有名称。`branchContext`目前主要用于分支状态约束，不能据此声称已建立“每项目的→所属详情”的结构化映射。
- 普通引用文件当前不一定自动获得主文档上下文；同源贡献按`sessionId + path`绑定，不是按任务绑定。多目的文件必须逐条判断归属，关联不足不能强猜，也不能把会话标题当唯一目的。
- `MemoryTreeStore.tree/publish`继续负责同源替换与同层相同内容聚合。仅名称相同不代表内容可合并；当前程序主要按字符串相等聚合，不具备自动语义等价证明。
- `queryTopic`目前在命中Section后读取其来源全文及直接引用。因此，分类改好不等于查询已按目的精确读取；后者仍是第二阶段的工作。

## 最小实施方向（待确认）

1. **明确整理输入中的目的归属。** 核对主文档目的、任务标题树和编号详情的关联，优先复用已有结构；必要时由程序补充所属任务路径及详情关联，不能只靠一行会话总体目标替代多个目的。尚不强制用户改写全部历史记忆或新增固定字段。
2. **调整提取与命名规则。** 按“目的主题→具体环节→事项结果”提取；保留成功和失败经验，计划、尝试和已验证结果不混淆。复用同义主题，不按会话编号建主题，不强求不同目的合并。
3. **保持第一阶段可靠性。** 同源更新、相同合并、不同条件共存、任务完成触发、取消边界和单文件失败隔离不回退；模型不得改变程序绑定的来源身份。
4. **隔离验证。** 覆盖一会话多目的、跨会话相同目的、同类操作属于不同目的、失败方案、无明确目的的旧记忆，以及原整理回归。真实模型分类质量另需授权评估。
5. **单独决定历史重整。** 当前按文件修订和依赖跳过已整理内容，只改提示词不会让全部旧记录自动重排。是否引入整理规则版本或进行受控重整，须明确成本与授权后决定，不清空正式索引、不悄悄重跑全库。

## 与第二阶段的分工

- 第一阶段补充：把目的、过程和结果整理到便于命中的结构里。
- 第二阶段：沿该结构读取相关内容并直接回答，不默认加载所有来源全文，不附来源引用。

内部来源和详情关联用于更新、导航与权限控制，仍应保留；省略的是答案中的来源说明。若必须改变来源定位粒度或存储契约，应另列兼容方案，不能声称只改提示词即可完成全部链路。
