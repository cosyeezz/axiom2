# 第一阶段：记忆整理

## 状态与授权

**实现及范围内隔离验收完成；尚未在正式后台启用新代码。** 本文替代此前未获批准的“索引有效性与失效闭环”草案，保留文件名以兼容现有链接。第一阶段不再建设“外部状态一变，历史记忆即失效”的系统。

用户明确的方向：

- 记忆是执行过程的总结、复盘和经验参考，不是当前事实标准。使用经验前核对实际条件；项目位置或实现后来变化，不意味着过去的定位经验没有参考价值。
- **同源更新、相同合并、不同共存。** 源文件自身修订，应更新它自己的整理副本；跨来源不同说法保留条件，不由整理模型裁定唯一真相。
- **任务完成后立即自动整理。** 仍依赖任务完成，不要求退出会话、执行空闲或静默30分钟，也不等待配置周期。
- 不需要人工触发：移除“立即整理”“整理工作空间”按钮及整理间隔设置。

## 行为契约

### 同源更新

文件贡献以 `(sessionId, path)` 为身份。成功整理的新结果整体替换自身贡献，而非向旧条目后追加；不会修改用户源文件，不覆盖其他文件或会话的独立贡献。

空提取是合法成功结果：清空该文件旧贡献，记录新修订，下次不重复提取。即使模型同时返回其他来源的重分类前缀，也只清空当前来源自己的记录。

实际读取的正文、引用及重分类依据都要通过发布前修订校验；贡献集合签名防止旧结果覆盖期间已经发布的新贡献。任务重新打开、权限撤销、关闭或取消后不发布旧响应。

### 相同合并、不同共存

当前确定性去重边界是 `topic / section / item / content` 四字段完全相同。合并展示保留全部 `(sessionId, path, revision)` 来源。一个来源修改或清空，只撤下它自己的支持，其他来源继续保留。

不同内容在同一事项下共存，保留各自条件及不确定性，不按时间先后裁定真假。措辞不同但语义近似的记录不增加全库模型调用强制合并；沿用现有名称复用和有界Topic/Section重分类。

### 自动调度与故障

- 扫描提交后以合并的 `setImmediate` 调度，不在扫描中等待模型。任务完成资格沿用 `memoryComplete()`：至少一个有效任务，所有未放弃任务完成且无继承等待；全部放弃不等于完成。
- 复用单执行槽，每批最多四来源，批次结束后立即续排剩余或新到来源。执行前再扫描，未变且成功的文件不重复请求。
- 会话主调用、子任务活动、切换面板、会话改名不再是整理失效条件。**实际源文件修订**仍是必要一致性边界。
- 某文件读取、预算、模型或解析失败，保留它之前的贡献并继续其他文件；成功文件立即保存。最终按失败报告，不把部分成功误标为整个来源ready。
- 取消（含供应商执行器内部取消）、授权/归属失效或任务不再完成，立即终止当前来源，不继续后续文件。纠正预处理也合并服务与本次整理取消信号，在写入前和文件间让出后检查，关闭或取消后不继续写下一文件。
- 自动失败按来源修订退避60秒重试，避免忙循环；新修订立即可重试。该退避不阻挡其他来源。退避状态在内存中，服务重启后允许重试，成功修订仍持久去重。当前不区分暂时与永久错误：持续失败仍会重试，涉及模型的失败可能重复产生费用；并非无限重试成本已被消除。
- 每1.5秒检查作为执行器就绪/失败重试兜底；一分钟安全扫描仍用于漏掉的文件事件及外部引用。两者不构成任务完成后的固定等待窗口。
- `intervalMs` 暂保留为旧配置兼容字段，不参与新的自动调度，界面不再暴露。
- 旧客户端整理协议暂保留兼容，但遵守同一完成判定及增量规则，不能绕过任务完成；当前界面无人工入口。旧显式取消/服务关闭/清除前abort保护继续有效。

## 边界与非目标

- 不改自动接续所用的完成判定；不以“运行结束”替代任务完成。
- 不实现此前草案的启动全库失效隔离、查询前强制索引与正文相同修订等机制。历史条目不能被提示词表述成已核验现状；具体应用由当前任务核对。
- 不新增外部项目实时事实核验，不调用模型做全库语义治理。
- 源文件物理删除及临时不可读的历史保留政策尚未重新定案。本阶段保留既有受控整理中的prune行为，不扩大删除语义；失败文件不等于合法空提取。
- 不改正式数据，不运行真实模型，不重启正式后台，不提交或部署；后续阶段没有自动执行授权。
