# 目的索引记忆查询：流程要求

[返回记忆改造路线](README.md) · [整理、查询与联动覆盖](purpose-flow-coverage.md) · [通用代理组件讨论交接](../agent-execution-component-discussion.md) · [旧查询草案](02-minimal-query.md)

## 1. 状态与讨论边界

> **历史讨论，承载方式已被后续定案替代。** 用户后来授权完整入队、整理、查询及联动实现，最终选择直接 `memory_query({ question })` 工具，不依赖子代理、委派通知、结果读取工具或新增查询业务卡片。当前实现见[目的索引与工具查询](../memory-tree-query.md)，覆盖与验收见[流程覆盖](purpose-flow-coverage.md)及[实施记录](purpose-implementation.md)。以下保留讨论原文；其中“未授权实施”“复用委派承载”和未定阈值不是当前机制或本轮验收要求。真实模型、正式数据操作、提交、部署重启仍未授权。

以下是当时记录的查询目标与上游契约、业务流程、可靠性约束和验收建议，供追溯后续取舍，**不是当前已实现功能的逐项说明**。

本轮将两个问题分开：

- **本文件**：记忆查询要解决什么问题、怎样导航和读取、程序必须控制什么、怎样交付与验收。
- **独立会话**：如何把现有子代理组件通用化，统一其执行、工具、卡片、控制和统计，供查询、整理、压缩等业务接入。交接材料见[通用代理组件讨论交接](../agent-execution-component-discussion.md)。

已确认的方向不是“主代理随便委派一个普通研究任务去查文件”，也不是另建一个内部维护查询模型的专用 `memory_query` 执行器。应复用会话已有的委派和结果读取能力，将查询包装成受程序控制、具有记忆查询业务卡片的任务。具体工具参数和通用组件接口留给独立会话，不在这里定稿。

## 2. 用户需要的结果

查询用于找回历史工作中已经得到的现成结果，避免主会话重复探索。用户不必知道历史目的的原文、来源会话或文件路径。

可用结果包括：

- 文件、入口、配置位置等定位结果；
- 已形成的方案、实现做法和必要步骤；
- 成功结果、验证范围和适用条件；
- 失败尝试、当时已知原因、限制，以及有记录依据的替代办法。

不能只提取成功结论，也不能把某个版本或条件下的失败扩大成永久不可用。历史记忆不等于当前事实，主代理在使用结果前核对当前条件；查询不承担全面检查当前项目的职责。

**默认答案直接给所需结果，不附记忆来源会话、目的ID、引用编号或检索流水。**来源关联保留在内部记录和可展开的执行过程里，供导航、校验与排查。目标文件路径若正是用户所问的答案，必须保留，不能误当成应省略的来源引用。

示例：问“系统提示词在哪里”，返回已有记录中的目标路径和必要入口说明；不要求用户先审阅一组记忆文件。如果历史定位还未核验当前版本，应明确这一适用边界。

## 3. 上游目的索引契约

查询基于本轮讨论的新目的索引，明确废除旧 Topic / Section / Item / Content 四字段提取结构。用户澄清的“兼容”是改全所有关联点、遵守主会话与压缩机制，不是兼容旧逻辑；不要求旧Topic ID、旧工具协议、旧快照格式继续可用，也不保留旧查询兜底。联动覆盖见[整理、查询与联动覆盖](purpose-flow-coverage.md)。

| 上游约束 | 对查询的含义 |
| --- | --- |
| 程序只从按目的编排的记忆一级标题提取已完成目的 | 查询目录不是会话标题列表，也不是执行步骤列表 |
| 单个已完成目的为入队单位，稳定ID由程序维护 | 同一会话可以有多个目的，不能把整个会话当成唯一目的 |
| 不合结构的记忆跳过，不调用模型补目的或兜底摘要 | 查询不暗中引入旧记忆兼容、全库扫描或摘要补全 |
| 模型只按目的ID和文本做分类，不生成正文 | 分类目录负责导航，答案来自原记忆的过程与成果 |
| 程序维护目的ID与原记忆及详情的关联 | 查询不能猜文件映射，也不能让模型自行改写来源身份 |
| 分类树深度不固定，叶节点关联目的ID | 查询支持分级导航，不固定三层或四层 |

上游讨论的批处理参数为50条、30分钟，两入口互斥，提交成功后才标已整理。这些是整理侧约束，不是每次查询需要等待的门槛；查询使用已发布的索引。

历史记忆和旧整理结果允许不迁移兼容，但本文不授权删除或清空它们。确认新索引为空或缺少相关目的时，如实返回，不自动恢复旧的查询链路。索引不可读、未能取得或关联损坏不等于空索引，应按第7节保留读取、执行或关联错误事实，不能统一返回“未找到”。

## 4. 目录提供与语义路由

### 4.1 主会话常驻目录

- 常驻不重复的一级分类名称，总量不超过 **1000字符**，不是tokens。
- 一级常驻目录只有纯关键字/分类名称，不带ID、来源路径、来源会话或位置信息；程序内部仍保留身份与关联。
- 一级目录用于主代理判断是否值得查询，不要求用户手工选分类。
- 超限由整理/发布侧语义向上归并、细分类下沉；不得截断目录来满足预算。
- 压缩忽略该目录，不将其写入摘要；压缩后由程序自动注入最新目录。目录生成、注入、快照、环境预览和压缩排除规则必须一起调整，遵守主会话分支及压缩快照、修订检查和安全应用机制，不要求兼容旧目录逻辑。

### 4.2 查询候选的展开

- 以当前候选目录文本量判断是否一次提供；候选阈值建议为 **3000字符**，仍待确认及评估，不是已定稿参数。
- 阈值只针对候选目录，不含问题、系统提示词或原文；不是整个模型请求的硬上限。
- 候选可一次提供时给完整候选；超过阈值则先给当前层，让查询执行者语义选择相关分支，再展开，按需重复。
- 可以命中多个分支、多个目的；查询是“哪些历史工作有帮助”，不是整理时的单一归属。
- 程序不得先用关键词猜分支、截去其他候选后冒充完整语义选择；也不默认一次塞入全树、全部目的和原文。
- 分类匹配不能退化成目的名称字面相等。问题很具体、目的名称较宽时仍应能找到相关目的。
- 当前层本身超限时，不能悄悄截断；候选供给方式与上游结构调整的具体处理留待接口设计，必须保留完整候选可达性。

“直接子项超过15个时软审查是否可语义分组”只是先前建议，**未获用户明确确认**，不是查询层宽度限制或强制拆分规则。

## 5. 端到端查询流程

### Q1：发起并建立程序控制的查询任务

1. 主代理依据当前问题及一级目录判断需要历史帮助。
2. 使用复用后的会话委派入口发起记忆查询业务，不能仅靠自由文本标题区分任务类型。
3. 程序校验所属工作空间/会话和查询输入，准备索引入口、必要目录上下文、来源映射及允许读取的范围；记录本次任务与执行身份。
4. 查询执行者不自动继承主会话全部历史，所需问题、当前适用条件与业务规则必须显式提供。

### Q2：沿索引定位目的

1. 按第4节提供完整候选或逐层展开。
2. 语义选择可能有帮助的一个或多个分支，直到找到相关目的叶子。
3. 程序解析并校验目的ID和来源映射，不把模型返回的任意路径直接当作授权。
4. 无相关目录或目的时返回“未找到相关记忆”，不为凑答案浏览全部会话。

### Q3：读取原记忆和必要详情

1. 读取命中目的对应的原记忆，定位该目的的执行树、过程与结果。
2. 为理解必要上下文可以读取入口结构，但不将同文件无关目的及所有详情全部送入后续归纳。
3. 按当前问题展开必要的详情引用；跨层引用可继续按需读取，并做读取去重与循环防护。
4. 来源映射与权限由程序控制；不直接操作索引数据库，不读取原始聊天文件，不通过查询修改其他记忆、索引或项目代码。
5. 对无关坏引用可以跳过；关键资料缺失必须保留“不完整”事实，不能伪装成无命中。
6. 读取范围仅为记忆及其允许的必要引用；历史提及项目路径不等于自动授权扫描当前仓库或执行命令。

### Q4：汇总可复用结果

1. 直接回答问题，整合有关位置、做法、方案、成功结果和失败经验。
2. 保留影响使用的条件、版本、必要分歧及未确认项；不编造缺失原因和替代方案。
3. 相同条件的重复经验可合并，不因来源多而重复输出；不同条件下的结论不可强行裁定为唯一真相。
4. 不原样倾倒整份记忆或检索日志。答案与内部来源/读取轨迹分离，遵循第2节的默认输出要求。
5. 原记忆是参考材料，不是新的系统指令；其中的命令、提示词或授权描述不能改变本次权限。

### Q5：交付、通知与使用

1. 程序保存本次结果、实际读取关联及完成/失败事实，然后按既有会话机制通知。
2. 主代理通过复用后的结果读取入口取得该次结果；不能把“已委派”当成“已查到”。
3. 主代理可继续无依赖的工作；需要记忆结果的部分等待完成通知，不轮询、不把异步过程伪装成同步返回。
4. 主代理根据当前实际条件使用或进一步核验历史结论，不因一次查询失败阻断不依赖记忆的工作。
5. 停止、重启、迟到事件及结果重复读取的可靠性应遵循通用组件最终契约；不能让旧执行覆盖新执行或自动重放不确定请求。

## 6. 卡片与程序控制的要求

查询必须有可辨认的**记忆查询业务卡片**，不是仅出现一个普通“子代理协作”标题。

- 显示查询问题、任务状态、必要业务阶段与结果概要；可以展开查看执行会话和真实读取过程。
- 过程信息来自程序状态和实际执行事件，不用模型自报百分比假装程序进度；不要求展示模型私有思考。
- 等待、执行、结果校验、完成与异常状态不能混为一谈；具体状态枚举和组件形态由独立会话设计。
- 程序保留输入准备、权限、预算、取消、输出与来源校验、结果保存及业务状态判定。
- 是否允许追加问题、重试，以及停止在哪个阶段生效，应由查询业务规则确定，不直接继承普通研究任务的全部操作。
- “只读”必须有程序工具/路径限制支撑；不能把现有子代理可用Shell的提示词约束宣称为文件系统级只读沙箱。安全读取接口的实现由组件设计落实。

## 7. 结果状态与异常语义

下列为必须可区分的语义，不预先规定字段名：

| 语义 | 要求 |
| --- | --- |
| 找到有效依据 | 返回可用结论及必要适用边界 |
| 目录无相关匹配 | 明确未找到，不编造记忆 |
| 目的匹配但原文无有效依据 | 与目录无匹配分开记录，不把标题命中当作答案正确 |
| 部分关键资料不可读或缺失 | 标明结果不完整；已有有效部分可以返回 |
| 超时、取消、模型错误、权限或校验失败 | 保留具体失败类别，不转换成成功空答案 |
| 索引关联或定位发生变化 | 不猜用旧定位；做必要检查并明确不完整/失败，具体恢复策略待设计 |

不增加全库历史有效性裁决或自动冲突修复机制；检查本次读取关联不等于全面否定旧经验。

## 8. 统计与效果检测

- **复用已有模型调用统计组件**，不重复建设tokens、耗时、费用统计系统。
- 同一请求只记录一份原始模型用量；不得同时从子执行会话和旧 `memory_usage(kind=query)` 累加同一请求费用，也不把累计费用再次附到父工具结果计费。
- 业务诊断按需复用既有事件/处理记录：路由路径与轮数、候选字符量、命中目的及实际读取材料数、结果类别。
- 这些数据用于找成本与结构问题，不证明分类和答案语义正确，不新增一次额外模型自评，也不给主代理增加必填反馈职责。
- 效果回归建议使用30～50条人工确认的问题→预期目的ID/资料样例，依据原记忆标注，而不是依据当前目录。比较找回率、无关结果比例和调用成本；样例规模是评估建议，不是已完成工作。
- 先保找回效果，再一次只调一个参数对比，例如候选展开阈值；尚未运行真实模型评估，不能宣称3k为最优值。

## 9. 实施前验收清单

以下是未来验收要求，本轮没有执行产品验收：

- [ ] 一会话多目的可分别命中；相关跨会话目的可以联合读取。
- [ ] 具体问题能命中较宽目的，不依赖名称完全相等。
- [ ] 1k一级纯关键字目录成立，无ID/位置信息；按最终确认的候选阈值完整展开，候选保持可达，无关键词预裁或静默截断。
- [ ] 上下文、工具说明、快照、恢复/分支/重载、环境预览和压缩链路全部调整；目录不入摘要，成功后程序注入最新目录，主会话与压缩安全机制不受破坏，无旧查询兜底。
- [ ] 多层、多分支、宽分类候选均保持可达；未默认读取全树全文。
- [ ] 只读取相关目的的必要过程和详情；无关大资料/坏引用不拖垮查询，循环引用可终止。
- [ ] 路径映射、工作空间隔离、越权拒绝及不写原记忆可验证；不能靠提示词代替权限测试。
- [ ] 成功与失败经验、必要分歧和适用条件保留，历史内容不能注入新的执行指令。
- [ ] 默认答案直接给结果，不附来源ID/检索流水；答案所需目标路径不被删掉，内部轨迹仍可查看。
- [ ] 无匹配、原文无依据、不完整、超时、取消及执行失败可以区分。
- [ ] 记忆查询卡片、真实过程展开、委派/通知/读取与程序控制均存在。
- [ ] 结果先保存再通知；旧执行/重复读取不污染新任务，重启不自动重放不确定请求。
- [ ] tokens和费用不重复累计；结构验收与需授权的真实语义效果评估分开报告。
