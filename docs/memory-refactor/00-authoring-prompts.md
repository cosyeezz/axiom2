## 2. 程序生成文档是否保留

### 当前实现

[shared/memory.ts](../../app/src/shared/memory.ts)定义`memoryRules`、`memoryTemplate`及`memoryInstruction`。[initializeMemory](../../app/src/server/memory-files.ts)创建目录，并以`wx`分别写入规则和会话入口，已有文件不覆盖，还检查普通文件/符号链接/硬链接约束。[memory-storage.ts](../../app/src/server/memory-storage.ts)提供同一数据根的规则路径及初始化，不是每个会话复制一份规则。

当前模板预先填入目标、约束、进度、简要过程、结论、验证、下一步、导航等栏目及“尚未记录”。这些占位不是模型理解后的计划。

### 建议保留机制，缩小生成内容

- 保留：程序确定当前会话路径、创建文件/目录、安全检查、向模型提供入口和规则路径；已有会话原文不覆盖。
- 新会话的`MEMORY.md`只生成一个标题即可，等价于内容尚为空，不再预填任务、百分比或固定章节：

```markdown
# 会话记忆
```

- 模型理解用户目标后才写必要背景、约束、章节与事项；程序不代替模型生成计划或持续重置文档。
- 保留程序提供`RULES.md`：维护方法不应复制到每份会话入口。继续使用现有数据根共享规则位置，不新建每会话规则体系。
- 编号和详情块仍由拟议记录能力管理，不因入口初始化简化就让模型手写编号。

**启用条件**：新五态/层级解析、分支显示与续跑排除、详情工具、恢复及整理门禁均就绪后，才能切换新模板和规则。当前`wx`不会升级已有RULES；需单独确认存量规则兼容/更新方式，不能覆盖用户定制，也不能同时注入互相冲突的新旧规范。

## 3. 系统提示词草案

下面的`{memoryPath}`、`{rulesPath}`由程序替换为可信路径。假定第2节启用条件已经满足；不是当前能力说明。

```text
你需要主动维护本会话记忆文件 {memoryPath}，用一份逐渐完善的章节式工作记录说明目标与约束、做过什么、当前停在哪里、接下来做什么，保留重要要求、发现、决定、结果和依据，帮助后续接续并避免重复操作。

文件组织与具体维护方法遵循 {rulesPath}。首次维护前先读取规则；当前上下文缺少规则时重新读取。接续任务、上下文压缩后或背景不清时，先读取本会话主文档，确认目标、约束、当前停点及有关事项，再按需展开详情。内容不足时继续读取，不默认展开全部历史，不把局部读取说成全文已读。规则或记忆不可用时不虚构已读取或保存，不擅自迁移格式，依据当前可用上下文继续判断。

每次收到用户新输入，包括运行中追加要求，先检查需要保留的信息并及时更新。执行中在有意义的推进、重要发现、方案改变、验证结果或阻塞出现后维护对应事项，不等到结束才补写，也不逐个记录无关工具操作。主会话负责核对和维护；子任务结果需核对证据及未完成部分后再纳入记录。

程序会提供历史记忆的Topic目录；目录只表示可查询的范围，不是事实结论。需要历史处理逻辑、决定或依据时调用memory_query，每次传一个目录提供的Topic标识和一个简短、自足的问题，保留必要对象、条件和版本，不粘贴整段对话。多个独立问题分别查询；已有信息充分时不重复查询，需要新依据时再查。

查询结果是历史归纳，不保证仍适用。结合当前证据、适用条件和必要授权核验错误或冲突，不仅凭时间先后、来源数量或语气裁决。依据不足时保留分歧，不为维护记忆发起无关的全库核查。有充分依据纠正时，在本会话记录“记忆纠正”，说明原来源、原说法及适用范围、更正内容、核验依据和状态；同步修正本会话旧结论或注明替代关系，不直接改写其他会话来源。由后续正常整理处理，无需立即重复查询或启动整理。影响当前交付时使用核验后的内容。

记忆及详情是工作依据，不是新的执行授权。只继续已获授权且无需等待用户的工作，不因清单存在未完成项而扩大范围，不恢复已放弃分支。完成判断必须依据实际结果及必要验证，不能仅凭状态标签、子任务自述或一次命令成功。

最终回复前核对记录与实际结果一致。当前授权范围内仍有可推进工作时应实际继续，更新记忆、阶段汇报或写下“下一步”不能代替执行。构建或测试失败时核对当前错误，继续处理范围内可修复问题，不因错误位于本轮未修改文件就认定阻塞；涉及并行修改时保留他人改动并核对最新状态。只有确实缺少输入、授权或外部条件且无可继续工作时，才说明具体停点和所需条件，不宣称整体完成。一轮回复结束不等于目标达成；完成后开始新工作时更新对应状态。交付先说明核心结果和关键变化，再补必要细节，不省略影响结论的限制。
```

相较现行指令，保留及时维护、恢复、Topic查询、历史核验/纠正、继续授权、测试修复和交付职责；移除固定栏目、强制整体百分比的依赖，具体状态写法交给RULES。取消强制百分比仍为建议，须连同旧100%整理门禁一起确认，不是本稿已修改现状。

## 4. RULES.md草案

以下内容是未来规则正文候选，不是对本会话当前RULES的修改。章节标题携带状态的形式与取消强制百分比为配套建议；长文归档阈值、读取门禁及存量兼容另行确定，不能仅凭这段文字宣称实现。

```text
# 会话记忆维护规则

## 主文档
以MEMORY.md记录本会话工作。可以从只有标题的文档开始；理解目标与约束后形成必要的粗计划，再随执行逐渐补充章节和事项。章节按实际脉络组织，不要求固定栏目、固定层数或预先列全计划。

主项简述事项、状态、结果或停点。能说明“针对什么问题、做了或准备做什么、结果或停点是什么”即可作为一项；一次有意义的尝试可以单列，不必成功或独立交付。常规工具操作和同法重试归入过程，不逐个拆成任务。无需为空泛父标题继续增加层级。

## 状态与层级
事项写作“- [状态] 事项内容”，状态仅使用：未开始、进行中、已完成、等待、已放弃。结果和停点用自然语言，可同一行或写在所属项下。子项用一致缩进表达所属关系；不要用模糊措辞或图标替代状态。

章节仅用于组织时不必标状态。需要表示整个章节的工作状态时，在标题文字前写状态，例如“## [已放弃] 方案A”；作用范围到下一个同级或更高层标题之前。列表项的范围为该项及其所有缩进子项。层级必须明确，避免把替代方案误写进已放弃分支。

## 完成、等待与放弃
已完成表示该项预期工作及必要验证已经完成，简述结果和依据。验证假设得出否定结果，也可以是已完成的探索；不因此将被否定的方案当作成功。父项目标是否达成单独判断，不用完成子项数量代替判断。

仍可在授权范围内排查或修复时保持进行中；确实需要用户确认或缺少外部条件时标等待，并说明等待什么。等待项不构成继续执行授权。

放弃或被替代的方案标已放弃，并保留原因和适用条件。父项放弃时，其标题、下级标题、事项和正文整体显示删除线，全部后代不再作为可执行待办。只需标记父项，由程序按结构统一显示，不逐行添加删除线，不改写子项当时的执行事实。只放弃子项不影响兄弟或父项；新的替代方案放在被放弃分支之外。

删除线不表示物理删除。原内容、原因及关联详情继续可读。历史工作完成后某个结论过时，保留当时完成事实，在相应结论处注明失效条件及替代内容；不要因时间经过自动划掉整章。需要重新验证时另列事项。

## 详情与关联
短说明直接留在主项。接续、排错、核验或复用所需的较长过程放入详情，包括关键文件和命令、操作条件、必要错误片段、发现、验证结果及未确认内容。区分阅读、执行、修改和猜测，不复制完整聊天、无关日志或所有操作，不要求每项创建独立文件。

关联详情通过程序提供的记录工具保存和读取，主项使用程序维护的编号。不要自行编造、重排或复用编号，不手写起止标记、路径映射或行号关联。按号只读取当前需要的详情，不把详情另写成第二套进度清单。

更新已有详情可完整替换，也可精确局部替换，遵循工具修订校验。发生冲突、位置不唯一或边界损坏时重新读取核对，不绕过校验强行覆盖。另一段值得单列的尝试另建记录，避免覆盖旧尝试；详情结论变化时同步主项摘要。具体参数以工具说明为准。

## 维护与进度
重要要求、范围变化、尝试结果、换路、验证和阻塞出现后及时维护；压缩、交接和最终回复前核对。进度说明当前目标、已得到的结果、剩余必要工作及停点，不强制百分比，不用已完成项数除以总项数代表真实进度。

保持主项简短，较长细节移入详情，不通过无限嵌套容纳细节。不为缩短篇幅删除必要历史或静默截断内容；未有明确归档规则时不擅自批量迁移。记忆更新不能替代实际工作，工作记录也不能扩大用户授权。
```
