# 第六阶段草案：整体验收与有授权的启用

[返回总路线](README.md) · [前一阶段](05-memory-ui.md)

## 状态与目标

**状态：草案，未批准。**

目标：在前五阶段各自已通过必要验证的基础上，证明整条链路协同有效，明确哪些效果经过验证、哪些仍受模型和环境影响，并由用户决定启用范围。

本阶段不代替各阶段单测，也不自动授权真实模型调用、正式数据迁移、全量重整或部署。

## 实施步骤草案

1. 整理跨阶段契约和决策记录，核对已实施行为与设计文档一致；清理不再适用的旧机制描述或明确替代关系。
2. 跑服务、存储、查询、整理、压缩恢复、进度/接续和浏览器整链回归，覆盖更新/删除/恢复/并发/取消/权限。
3. 执行类型检查与获准范围的构建；区分源码测试、构建产物验证和正式桌面效果，不互相替代。
4. 建立脱敏或合成的语义评估集：同义问题、多条件版本、相近主题、冲突来源、无命中、坏引用、巨大无关资料、嵌套证据和过期事实。
5. 先用假模型验证流程、边界和成本统计；若用户授权，再用选定真实模型和明确预算评估语义效果。
6. 对比改造前后结果，分析失败样本，回到对应阶段补修，而不是用平均数掩盖错误事实或越权读取。
7. 提供正式启用方案：版本、范围、备份、数据兼容、可观察指标、停止条件与恢复步骤。用户确认后才执行。
8. 启用后在授权范围内观察，记录真实结果与剩余限制，不自动触发全量模型重整。

## 质量指标

具体阈值在各相关阶段确认时确定，第六阶段汇总，不事后挑选有利标准。

| 维度 | 观察内容 |
| --- | --- |
| 有效性 | 旧条目进入归纳的次数；删除/依赖变化后的失效是否正确 |
| 召回 | 必要历史依据是否找到；语义不同但名称相近的资料是否误选 |
| 最小加载 | 实际读取文档/段落、累计字节与模型输入量、无关与重复证据比例 |
| 答案 | 是否直接有用、是否含无关背景、是否保留条件和分歧、是否无据断言 |
| 整理 | 主题重复/过细/错误合并、文件失败隔离、尾部治理覆盖 |
| 运行 | 调用次数、时延、真实用量、取消和超时、启动核验成本 |
| 展示 | 首屏负载、展开与搜索成本、分页可达性、草稿和修订保护 |

权限越界、已确认过期事实作为有效依据、取消后发布结果等是必须阻断的问题，不能用总体平均提升抵消。

## 验收与启用门槛

- 前五阶段文档均有真实实施记录和必要验证，不只打“完成”标记。
- 所有失败有定位和处理结论；仍有可修复的授权内问题应继续处理。
- 无真实模型授权时，可以报告工程契约通过，但必须写明语义质量尚未实测，不将整个质量评估宣称完成。
- 无正式启用授权时，交付候选版本与启用方案即停止，不宣称线上已生效。
- 旧数据兼容已用隔离副本验证；正式迁移另行确认范围与备份，不直接操作真实库试错。

## 风险与恢复

模型和供应商变化可能改变语义结果，需记录模型版本、配置与样本。恢复方案不允许重新启用已确认过期的索引作为事实；必要时关闭辅助查询，保持原始文件可读与主任务可执行。数据库与应用版本的回退必须成套验证。
