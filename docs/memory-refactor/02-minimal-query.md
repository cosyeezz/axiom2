# 第二阶段草案：最小加载与查询答案

[返回总路线](README.md) · [前一阶段](01-index-validity.md) · [下一阶段](03-memory-authoring.md)

## 状态与目标

**状态：草案，未批准；第一阶段完成后再讨论和细化。**

目标：查询只读取帮助当前问题的资料；主会话只收到可用结论、关键条件与必要不确定性，而不是内部检索过程。

前置条件：第一阶段的有效贡献、来源修订和失效返回契约已落实。

## 拟定范围

- Section定位之后增加事项/证据选择，避免自动带入整个分支。
- 以修订绑定的段落、章节或有界内容片段取证，而非默认来源全文。
- 引用变为按需可展开入口，支持必要的多层引用，防循环、重复加载和越权。
- 区分无关引用失败、关键证据缺失、执行失败与真正无命中。
- 统计读取量、重复量、模型调用次数和返回长度，保持内部数据与工具正文隔离。

不做主题重命名、原文自动迁移或全局UI改版；保留只读、工作空间隔离、无原始聊天回查等边界。

## 实施步骤草案

1. 固化三个对照夹具：小相关资料＋巨大无关资料；有效答案＋无关坏链接；答案依赖二级引用。
2. 明确候选信息粒度：Topic/Section提供导航，Item与必要简述供语义选择，原文按选择取证；不能仅因关键词不重合排除来源。
3. 设计修订绑定的段落定位与文本读取接口。源文件变更后定位失效，不将旧偏移应用于新内容。
4. 将全部引用自动展开改为“列出导航→选择→读取”；共享文件去重，同文件不同路径别名不重复读取。
5. 为读取和模型上下文设置可观察软预算。材料过大时分批或继续定向取证，不能静默截断关键条件，也不能无限补读。
6. 明确局部失败策略：无关引用不读，故不因其缺失失败；必要证据缺失只允许有依据的部分结果并标明缺口。
7. 调整归纳输入与输出契约。默认不附来源ID、修订、内部目录、读取流水；必要的项目路径、命令和版本条件可以保留。用户要求溯源时再提供定位。
8. 回归第一阶段的修订/权限校验，验证多轮取证不会放宽权限或混用版本。

## 进入阶段前必须讨论

- 查询采用固定多阶段请求，还是有界的按需读取循环？按总成本、延迟和证据质量比较，不预先认定“调用次数越少越好”。
- 段落定位信息实时生成还是随贡献持久化？涉及记录格式变更时明确兼容方式。
- 软预算与终止条件具体取值；不能只用字符数假定Token数量。
- 多来源分歧何时需要继续取证，何时将必要分歧返回主会话核验。
- 真实模型评估需要另行授权；在授权前只能证明读取和返回契约，不能证明语义质量达标。

## 验收

- 查询端口时不读取同源无关大报告，断言实际读取记录和模型请求内容。
- 无关坏链接不导致已有充分依据的查询失败。
- 必要二级引用可以按需读到；循环引用不会无限展开。
- 关键证据缺失明确不完整，不以成功空答案掩盖读取失败。
- 源修订变化时终止旧定位/旧证据，沿用第一阶段门禁。
- 同一条件的重复结论不因多来源重复输出；必要限制和冲突不丢失。
- 工具正文无自动附加审计元数据；details仍可追溯本次实际读取。
- 记录改造前后的读取字符/字节、请求输入量、模型调用次数、耗时与答案长度；数值目标在本阶段确认时填写，不伪造提升比例。

## 风险与恢复

过细筛选可能漏掉决定性上下文，应保留按需扩展和明确不确定性；不能以恢复“读取所有文件”作为默认降级。请求失败沿用可选记忆语义，不阻断主任务。旧存储格式需有明确适配；不修改原文实现定位。
