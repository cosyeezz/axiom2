# 第四阶段草案：主题治理与整理可靠性

[返回总路线](README.md) · [前一阶段](03-memory-authoring.md) · [下一阶段](05-memory-ui.md)

## 状态与目标

**状态：草案，未批准。**

目标：生成稳定、具体、可区分的Topic/Section；主题迁移不扩散召回范围；每份文档的普通整理失败相互隔离；有界治理能够覆盖全部待审查条目。

前置条件：有效性门禁和入口/详情职责已明确，整理引用沿用第二阶段的按需证据思路。

## 实施步骤草案

1. 名称规范化：处理首尾空白与明确格式错误，拒绝多行、明显路径/内部ID式主题；保留产品名、版本等有语义区分作用的信息。
2. 明确Topic与Section粒度规则，优先复用相同范围的名称，避免按一次操作拆主题；不能仅凭文字相似强行合并不同条件。
3. 对已有名称变化设计可追踪迁移；保留来源贡献，不用合并操作改写其他来源事实。
4. 迁移关系显式化。旧Item无法对应时，不再路由到同文件所有新主题；不确定关系标为待核验，旧目录只访问确认的有效后继。
5. 重分类使用可持久恢复的轮转/待审查队列，避免固定前缀反复占预算；超大单条单独处理，不永久静默跳过。
6. 将普通文件读取、预算、模型和解析错误隔离到文件，继续处理其他文档；取消、授权撤销和全局一致性失败仍终止相关执行。
7. 整理任务明确部分成功、失败文件与重试范围。已成功且未变化的文件不反复重提取；错误恢复不能复活第一阶段失效内容。
8. 检查入口与详情贡献的语义重复。引用提供理解条件，不将被引用文件的独立事实错误归属当前文件。
9. 评估Topic目录大小：统计序列化目录成本而不只计主题名称字数；目录层级优化另作可验证设计，不按关键词或固定前几项丢弃主题。

## 验收

- 前后空白不制造新Topic，路径/多行名称受到明确约束。
- 语义不同的事项不因压缩目录被误合并；分歧与适用条件保留。
- Item改名或来源新增无关主题时，旧Topic不扩散到无关Section。
- 连续多轮有界整理能覆盖尾部，重启后进度可继续；大条目有明确结果。
- 入口失败后独立详情仍可完成整理，任务显示部分成功并可定向重试。
- 用户取消和权限撤销阻止迟到发布；实际用量仍记账。
- 固定会话Topic快照与迁移路由测试不退化。
- 用隔离样本衡量重复主题、遗漏、错误合并和命名可辨识性；真实模型评估需另行授权。

## 风险与恢复

名称规范化会影响名称hash生成的标识，必须保留兼容路由并验证旧快照，不能直接批量改名。主题治理不是删除低频资料；模型不得修改原记忆。若引入重分类队列或新输出格式，需提供增量兼容与取消恢复方案。
