# 第五阶段草案：全局展示、详情浏览与编辑边界

[返回总路线](README.md) · [前一阶段](04-topic-organization.md) · [下一阶段](06-validation-rollout.md)

## 状态与目标

**状态：草案，未批准。**

目标：浏览所需内容逐层加载；来源能区分、有效状态清楚；大详情能读完；编辑范围与既定权限一致。

本阶段可拆为“编辑边界与阅读修复”“全局树渐进加载”两个实施批次。编辑路径策略缺口可经用户确认提前独立修复，不因排在第五阶段而视为低风险，也不自动塞进第一阶段。

## 实施步骤草案

1. 保存路径先解析并规范化为允许的相对路径，再判断入口/详细文档白名单；复用真实路径、归属、符号链接和修订保护。
2. 将浏览预算与编辑预算分开。只读采用分页替换或虚拟化，使服务允许范围内的大文本可读至文尾；编辑上限单独提示，不能误称资料读取失败。
3. 关联文件计数和导航统一口径，非标准目录下的可访问资料有清楚入口或位置说明。
4. 来源展示补充会话标题、资料用途和有效状态；多个MEMORY.md可区分。必要版本放在详情，不把UI溯源信息自动塞入模型答案。
5. 全局树改为目录、分支、条目内容按需加载。增量推送绑定工作空间和树修订，不因折叠仍传全量正文。
6. 搜索移到受授权范围约束的服务端，结果按需展开；不能为了搜索预先下载全库正文。
7. 展示第一阶段的核验中、待整理与不可用状态，不把旧条目当当前事实，也不因来源消失直接丢弃编辑草稿。
8. 在入口编辑页同时解释入口字数规范与180KB技术编辑上限；保留修订冲突、关闭确认和脚注导航。

## 验收

- `references/../scripts/notes.txt`不能绕过编辑白名单；链接、硬链接、跨会话和工作空间边界仍受保护。
- 超过180KB且在服务可读范围内的详情能完整浏览，未进入编辑不会报编辑预算错误；避免无限累计到浏览器内存。
- 文件计数与可导航项一致，多个同名入口有可辨识来源。
- 首屏请求不含所有Item正文；展开只加载目标分支；搜索不依赖预下载全库。
- 目录变化、切换工作空间、关闭重开时旧响应不串入新范围。
- 已失效条目不显示为有效内容，未保存草稿、阅读位置和输入焦点保持合理。
- 使用独立临时服务、随机端口和Chrome验证；窄屏、键盘、长标题和空/错误态都有用例。

## 风险与恢复

懒加载需要明确树版本/分页一致性，不得把不同修订的内容拼在一起。新增UI状态不能泄露内部路径或敏感错误。保留当前打开文件的独立读取能力；新全局树加载故障不应阻断主会话。
