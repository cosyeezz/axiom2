# 记忆机制分阶段改造

## 文档状态与执行约定

最新详情机制以[标题路径详情完整提示词](../memory-title-details-system-prompt.md)和[当前查询说明](../memory-tree-query.md)为准：纯状态标题树，`details/<祖先标题>/<当前标题>.md` 独立文件，原生工具写入前保护既有标题及父级，无编号详情工具、迁移或历史兼容。下文此前阶段的完成状态与验收仅对应各自历史版本，不代表本轮标题路径改造的验收结果。

**当前状态：第零阶段及此前第一阶段保留历史验收记录；用户已进一步授权完整目的索引、批量整理、直接工具查询及目录/界面/压缩联动，目前实现及范围内隔离验收完成。其余独立阶段草案不自动推进；真实模型、正式数据操作、提交及部署重启仍需另行授权。**

最新流程：[目的索引：整理、查询与联动覆盖](purpose-flow-coverage.md)；当前实现：[目的索引与工具查询](../memory-tree-query.md)；验收：[实施记录](purpose-implementation.md)。查询最终定案为直接 `memory_query({ question })` 工具，不依赖子代理或额外业务卡片。[查询流程要求](02-purpose-query-requirements.md)保留定案前的讨论历史，其中委派承载已被替代。四字段机制废除；用户所说的“兼容”指改全关联点、遵守主会话与压缩机制，不要求兼容旧逻辑。一级目录只注入纯关键字，压缩忽略目录后由程序注入最新目录。子代理组件通用化已拆至[独立讨论交接](../agent-execution-component-discussion.md)，不作为本轮依赖。此前[第一阶段补充：按任务目的整理](01-purpose-organization.md)是旧结构草案，其四字段映射已不代表当前机制。已完成实施记录：[第一阶段：记忆整理](01-index-validity.md)。已完成基础：[第零阶段：用一份可演进的todo记录会话工作](00-evolving-todo.md)。用户最新要求以简单、低维护成本为先，用同一份逐渐丰满的清单表达做过什么、接下来做什么；不引入多层复杂系统。具体联动范围、工具接口与提示词建议见[第零阶段补充：改动清单与提示词草案](00-implementation-and-prompts.md)，旧草案由第零阶段定稿替代。提示词演进见[系统指令与初始化讨论](00-authoring-prompts.md)：最新方向为维护方法统一放系统提示词，不再维护RULES，复用压缩前后提醒；保留程序建文件、缩小初始模板。前轮分拆稿已标记被替代；[最新统一系统提示词](00-system-prompt.md)已定稿并落地。

第零阶段的实际结果以其验收记录为准；第一阶段原“失效闭环”草案已被用户确认的“同源更新、相同合并、不同共存”方案替代，其余阶段仍待重新复核，不是已实现功能说明。现行机制参见[记忆树整理与查询](../memory-tree-query.md)与[会话记忆方案](../session-memory.md)。本计划基于代码审查和隔离复现，不将现有测试通过等同于缺陷不存在。

用户原要求逐阶段讨论、确认后实施；第零阶段和此前第一阶段已完成。后续又明确授权把目的索引所缺的入队、整理、查询及关联点全部实现，并补充最多4个同文件相邻目的语境。该授权覆盖本轮实施，不自动批准其他独立草案；原索引全面失效方案不视为获批。

每阶段执行顺序：

1. 读取当前阶段文档，复核最新代码与工作区并行修改。
2. 讨论目标、范围、取舍和验收；将用户意见写入该阶段决策记录。
3. 用户明确确认后，将状态改为“已批准，待实施”。
4. 主代理按步骤修改；适合独立验证的工作可委派，测试期间不修改其覆盖文件。
5. 完成测试与必要文档同步，记录真实结果、未验证项和偏离计划的原因。
6. 向用户交付阶段结果，再讨论下一阶段；不得自动开始下一阶段。

出现范围扩大、需要真实模型、操作真实数据或新增迁移风险时，先补充方案并确认。遇到本阶段授权范围内可修复的测试失败，应继续处理，不以写下“下一步”代替执行。

## 总体目标

以下为原审查路线的目标，需结合第零阶段重新评估。当前优先明确一份可演进todo如何承载计划和简要执行记录，不将原入口形式或阶段划分视为已定案。

- 主入口用自然语言简述目标、关键要求、过程、结果和当前停点；技术细节与证据进入详细文档。
- 全局记忆是历史经验参考库：同源修订更新、相同记录合并来源、不同条件或冲突共存；使用前核对实际，不把历史线索冒充当前事实。
- 查询只读取解决当前问题所需的内容，默认只向主会话返回可用结论、必要条件和不确定性。
- 浏览、编辑、整理和查询职责清楚，显示范围与授权范围一致。
- 不静默截断事实，不借“优化”删除历史资料，不覆盖其他会话原文或用户自定义规则。

## 已知问题的归属

- 同源修订需更新整理副本：阶段一；物理删除/不可读的历史保留政策待独立确认。
- 查询旧条目与新正文的关系：本阶段不实行全面失效门禁，提示明确历史参考语义；如需更强版本一致性另行讨论。
- 全部直接引用自动展开、无关坏引用导致整体失败：阶段二。
- 无关Item和大段背景进入归纳、答案质量缺少语义评估：阶段二与六。
- 入口长度仅软提示、具体路径过程容易堆积：阶段三。
- 纯自然语言与任务进度、自动接续、自动整理硬耦合：阶段三讨论后定案。
- 既有RULES不随内置规范更新：阶段三。
- 名称空白变体、路径式主题、旧路由过宽、重分类固定前缀：阶段四。
- 单文件失败阻断后续详情：已纳入第一阶段；重复引用正文的加载优化仍待后续讨论。
- 只读浏览受编辑预算限制、来源难区分、非标准目录文件无入口：阶段五。
- 保存路径在规范化前做目录白名单校验：阶段五中的独立边界修复，可经用户确认单独提前，不以本路线隐含授权。
- 固定Topic目录和全局树的规模开销：阶段四、五、六；不靠关键词硬截取目录掩盖召回损失。

## 全阶段约束

- 此前第一阶段实施及验收属于历史记录；本轮目的索引及直接工具查询已获代码实施、临时数据/假模型和隔离验证授权，不整理真实记忆；真实模型及正式启用另行确认。
- 未来实施保留并行修改，禁止整文件回退、替换或夹带无关改动。
- 默认使用临时数据、假模型、随机端口验证；不访问正式浏览器、不重启正式服务，不为测试修改真实模型配置。
- 安装依赖、提交推送、构建共享产物、真实模型调用、真实数据迁移和部署均不由本计划自动授权。
- 已保存原文和逻辑删除会话的记忆保留语义不变；读取失败不等于文件已删除。
- 每阶段完成后更新本阶段结果和必要机制文档；未实现草案不能写入产品文档成为现状。

## 阶段交付模板

每份阶段文档均保留：状态、目标、范围/非目标、实施步骤、验收、风险/恢复、确认记录、实际结果。

实际结果必须包括：修改文件、实际命令和退出码、关键行为证据、未验证项、是否迁移/提交/部署、下一阶段的建议调整。没有执行的命令只标为计划。
