# 第三阶段草案：自然语言主入口与详细资料

[返回总路线](README.md) · [前一阶段](02-minimal-query.md) · [下一阶段](04-topic-organization.md)

## 状态与目标

**状态：草案，未批准；进入本阶段前须确认进度数据如何存储。**

目标：主入口主要描述“为什么做、做了什么、重要转折、得到什么结果、停在哪里”；具体路径、命令、日志、实现和证据沉淀到详细文档。入口不是操作流水账，也不是大串文件导航。

前置条件：有效性和按需引用已完成，避免资料拆分后被查询再次全部加载。

## 必须先定的兼容方案

当前进度展示、自动接续、自动整理依赖正文中的栏目、状态、百分比和任务清单。只删这些结构会造成机制失效。

- **方案A：自然语言为主，保留最少机器字段。** 保留目标/任务进度，其余栏目合并为简短过程与结论。改动较小，兼容现状，但不是严格纯自然语言文件。
- **方案B：入口纯自然语言，机器进度独立保存。** 需明确权威来源、更新工具/接口、正文与状态的修订关联、失败恢复、旧格式兼容和自动接续授权。不允许出现两份相互矛盾的任务真相。

建议进入阶段时由用户选择；本草案不默认批准方案B，也不以小改提示词伪装完成解耦。

## 实施步骤草案

1. 确认入口的必需语义、软长度目标、进度兼容方案与详细文档职责。
2. 修改模板、系统维护说明和共享规则，删除鼓励重复填写的要求；继续要求依据事实更新，不降低维护频率与质量。
3. 详细资料按自然主题组织，说明背景、条件、决定、重要过程、实际验证与未知项；不逐轮抄录聊天或工具调用。
4. 明确路径策略：入口只放少量有用途说明的相对脚注；详细地址、命令、代码符号、来源身份放到专题。问题本身确实是路径/配置时不机械删掉理解所需内容。
5. 增加非阻断结构检查：超限、路径/日志堆积、断链、进度冲突等给出具体提醒，不自动删除或截断原文。
6. 更新流程先保存详情，再确认导航有效，最后收缩入口；失败时原事实仍可恢复，不能先删后补。
7. 引入内置规则版本与用户覆盖的区别。旧安装检测到规则变化时提供明确升级策略，不静默覆盖自定义RULES。
8. 验证旧入口、用户编辑、压缩后恢复、进度显示、自动接续与整理资格。

## 验收

- 入口可以独立说明当前任务与结果，不靠堆技术标识让读者猜。
- 具体实施和验证过程能从少量导航进入独立详情，不需回读原始聊天。
- 超限处理保留事实且可恢复；长路径和日志不再被默认写进入口。
- 正文与进度的一致性按批准方案校验，自动接续不会新增授权或重复操作。
- 旧规则升级保护用户定制，旧格式可读；不能仅更新代码常量就声称所有安装已升级。
- 模型维护效果由样本验证；不把提示词存在当作模型稳定服从的证据。

## 风险与恢复

纯自然语言与机器状态解耦可能明显扩大本阶段。若选择方案B，应在批准前拆成子阶段并补充迁移设计。禁止自动重写所有历史记忆；历史迁移必须另行确认范围、备份与验证。入口规范错误不应阻断主任务。
