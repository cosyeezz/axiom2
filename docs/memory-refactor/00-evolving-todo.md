> 本文保留第零阶段设计与验收历史。编号详情、固定标题、标题长度和旧 `memory_detail` 工具均已被后续[标题路径详情完整提示词](../memory-title-details-system-prompt.md)替代；现行主记忆仅状态嵌套标题，详情为按标题层级关联的独立文件，既有标题与父级受写入前保护。以下旧通过数不是本轮验证结果。

## 1. 状态与授权

用户已确认方案和精简提示词，授权更新第零阶段文档后执行，明确要求UI展示和记忆整理同步调整。没有待确认项，以下工程细节由实现与测试落实。原一至六阶段保留为历史审查路线，不自动扩大执行范围。不调用真实模型、不改正式数据、不提交部署。

## 2. 核心模型

同一份MEMORY.md既是计划也是简要执行记录，表达做过什么、接下来做什么。初始为空，理解任务后逐渐形成章节和事项，不强制固定栏目、完整预规划或百分比。一次有意义的尝试即可作为事项，不把每次工具调用列为任务。失败尝试保留原因和条件，具体过程放详情，不复制聊天或所有日志，不引入关系图、多层知识系统或第二套待办。

- 初始目标≤13字，作为固定记忆标题，生成后不再修改，与聊天标题独立。
- 正文一级标题≤10字、二级≤14字、三级及以下≤18字，事项正文≤40字，不计Markdown标记、状态和详情编号。
- 首个无状态H1是记忆标题，后续H1～H6是正文标题。先精简，独立内容才拆分，解释移入详情；不截断既有文本，不自动归档历史。
- 各级标题和事项均可关联详情，大标题详情可解释整个任务范围与方案。
- 开始或切换事项前更新记忆并标为进行中，再执行；事项及必要验证完成后立即更新为已完成及简短结果。

## 3. 状态与层级

事项格式为`- [状态] 内容`，标题可写`## [状态] 标题`。五态为未开始、进行中、已完成、等待、已放弃。普通标题只组织内容，不自动等同任务完成。标题范围直到下一个同级或更高标题；列表按缩进界定子树。

放弃父分支后，全部下级标题、事项及正文整体划线并退出可执行待办，保留原有状态事实与详情。兄弟分支不受影响；替代方案位于放弃分支之外。等待父分支也不自动启动其子项。已完成的探索不代表方案成功；父目标需要自身完成证据，不能按子项比例计算完成。

系统提示词只说明删除/放弃分支无需继续关注，不解释删除线等程序职责。程序统一解析层级，供恢复、整理及UI使用。兼容旧固定栏目、阻塞状态、checkbox和显式百分比，但新格式不要求这些字段。整理不再依赖100%字段。

## 4. 详情工具

新增薄本地工具`memory_detail`，单次只处理一个详情，支持写入和按编号读取，不调用模型、不扩展MCP或宿主RPC。仅主会话可用；子任务汇报结果，由主会话维护记忆。

- `write`无编号时新建，有编号时更新。`content`整条覆盖需该编号最新的`revision`；`read/write`返回`detail-v1:<编号>:<正文SHA-256>`，无关详情更新不会使该条修订失效。仅重新关联主项也需该条修订，可以省略`content`保持正文不变。
- `oldText/newText`局部替换在写锁内读取最新目标正文，按非空原文唯一精确匹配（包括拒绝重叠的多处匹配），按字面替换并保留其他内容。无需`revision`，传入旧`revision`也不参与局部匹配；不能同时传`content`。原文不存在或不唯一必须重新读取，不盲重试。
- `read`同时返回该条详情修订与当前入口`entryRevision`。入口仍使用整份`MEMORY.md`原始字节SHA-256。兼容旧工具的整文件修订仅限其恰好等于当前详情文件SHA时；过期旧修订不得用于整条覆盖，需重新读取。UI/整理使用的`memory.read`文件及分页修订仍保持原有整文件快照语义，不与工具单条修订混用。
- 新建关联用明确的主文档标题/事项原文及修订定位，必须唯一匹配；程序加编号，不凭语义猜位置。
- 编号为会话内递增正整数，稳定不回收。主文档为`〔18〕`，详情存放于`references/details.md`，用`<!-- detail:18:start -->`和同号end标记界定。文件内持久计数器不随块删除回退。
- 单次读取只返回目标块及修订，不返回整份详情文件。边界重复、缺失、嵌套、引用失效、修订冲突明确报错，不猜范围。
- 本地写入加锁、路径和会话归属校验。逻辑局部更新仍保存完整详情文件，底层以锁内最新整文件快照执行正文校验；写入前从实际写入fd复读字节，并核对路径、普通文件、设备号/inode及链接数。仅mtime/ctime变化但正文与身份不变不再阻止保存；正文变化、文件替换或链接变化仍拒绝。保留BOM、原有CRLF边界和读取大小预算。
- 写锁约束遵循该协议的详情写入者，不宣称能对任意外部进程提供操作系统级原子CAS。先保存详情再关联入口；若第二步失败，明确返回未关联详情编号，不报成功或留下悬空引用。先read已保存编号，再提交其详情修订及最新入口修订重试关联，不能重复新建或自动覆盖外部修改。
- 通用编辑不能改受管详情文件；主文档仍可常规编辑。标题更改与无效详情引用在受控写入口拒绝。bash等外部修改不能视为沙箱受控，后续读取仍须检测损坏。

工具schema说明参数、限制及错误恢复；系统提示词只说明何时使用。

## 5. 系统提示词与兼容

[定稿提示词](00-system-prompt.md)是唯一维护规范。停止生成、读取和注入RULES；不删除用户已有RULES文件。旧占位模板仍按空记录识别，新入口为空。保持现有压缩前维护、压缩后读取提醒，提醒送达不代表完成读取。长主文档按实际送达行累计覆盖，同次压缩且同一文件修订读全才确认；文件变化重新计数，子任务读取不替代主会话读取。

标题与长度规则用于新记录，旧文档可读取、不强制迁移或截断。固定标题优先用于记忆目录与来源展示，不随聊天改名。新格式整体完成要求至少一个明确任务、所有有效任务完成且无矛盾；仅放弃所有分支不能宣布目标完成。

## 6. 整理与UI联动

- 自动整理准入使用明确完成状态，而非100%门禁；保留活动会话、修订和删除等既有安全条件。手动整理沿用现有明确请求可整理当前已保存资料的能力，不将未完成/等待/放弃内容推断成现行完成方案。
- 整理读取编号引用的实际详情，携带来源与修订。保留失败原因、失效/放弃条件，不将废弃方案提取成现行建议；不把引用文件独立结论归给主文档。
- 会话面板展示多级标题、嵌套事项及五态，放弃分支整支划线，可打开详情。完整记忆预览同样继承分支状态，编辑仍展示原始Markdown。
- 不显示新格式的“进度待评估”或伪百分比。既有百分比仅作兼容展示；无全局2000字硬限制提示，长正文按现有分页加载，不静默丢弃。
