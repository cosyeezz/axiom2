# 基于会话记忆六态的自动接续方案（已确认实施）

## 范围

入口图标六态与本文自动接续方案已获用户确认；共享任务树分析、三模式接续及诊断记录已接入代码，按下列矩阵验证。记忆是任务状态证据，不构成新的执行授权。

## 当前链路

`MemoryContinuations.settled` 仅检查无错误、无特殊结束原因的自然完成运行。现有生命周期保护应保留：

- 仅主会话、工作空间已授权、原运行仍是最新运行；无活动运行、用户排队输入、活动子任务或未交付结果、冻结。
- 等待已有压缩完成，定向扫描最新记忆；记忆缺失、不可用、删除或待纠正不接续。
- 发送前与异步执行准备后复核运行和记忆修订；用户停止或新输入取消旧检查。
- 通过内部 `axiom-memory-continuation` 消息发送，不伪装用户输入，不消费用户草稿。
- 同一用户操作链最多自动接续三次；未完任务签名重复时停止；启动服务不扫描重放历史任务。

原章节格式使用平面候选列表，可能同时选中父项汇总与子步骤。现改为 `analyzeMemoryTasks` 共享分析，并由 `continuationPlan` 决定 `execute / reconcile / stop`。

## 共享判定结果

从完整 `outline`（含无状态的分组标题）生成统一纯函数供 UI 和服务端使用：

- `displayState`：当前主要任务状态，不是百分比。
- `actionable`：可执行前沿及目标/祖先路径；去掉被后代代表的汇总父项。
- `waiting / failed / abandoned`：不能自动执行的分支及其原始详情引用。
- `diagnostics`：父完成子未完成等矛盾。存在待核对项不等于已完成。
- `complete`：存在有效任务，且所有必要有效目标/步骤明确完成；全放弃或空树不是成功。

图标不能替代判定。混合分支可显示“进行中”，但 tooltip 应补充等待/失败信息，避免掩盖其他分支。

## 状态及树规则

| 状态 | 自动接续 |
| --- | --- |
| 未开始 / 进行中 | 只有处于原用户授权内且无祖先阻止的有效可执行前沿才入选 |
| 等待 / 阻塞 | 本分支及其后代不执行；其他独立可执行分支继续 |
| 失败 | 默认视为独立尝试已结束，本分支及后代不自动重试；有明确后续修复工作时，应记录新的进行中/未开始步骤或恢复分支后再接续 |
| 已放弃 | 整支退出执行，不改子项历史状态，不自动恢复 |
| 已完成 | 本项不重复操作；若后代仍未完成，记录矛盾，不直接当已完成或直接执行旧后代 |

“失败”不是普通命令报错：可自行修复的测试/构建错误仍在进行中任务内处理，不必把任务提前标为失败。

有效前沿：有未结束后代的父节点仅作汇总，不因为父仍是进行中就额外形成可执行任务。如果所有未结束后代都等待/失败，不能从父项反推出新的工作。若后代均已完成而父仍未完成，允许把父项作为收尾核验候选，但先检查是否遗漏验证/交付，不可仅自动改标签。

分组标题无状态不能打断祖先等待、失败或放弃限制。新目标与历史完成目标并存时只继续新目标；一个目标等待不阻断另一目标独立执行。

这里选择保守策略：也可以把父等待解释为“仅部分工作受阻”，允许显式活动子任务继续，但这会改变现有等待继承行为，并容易误执行真正受阻的子步骤。本方案不采用隐式例外；如果仅部分受阻，先把父项恢复进行中，只将确实受阻的子步骤标等待。父失败下的新修复工作也先核对、调整父状态或作为独立修复分支，不由程序默默复活失败分支。此保守继承策略已随方案确认采用。

旧格式在入口显示上暂保留历史百分比兼容；接续语义适配到同一分析结果。不能仅因旧记录的百分比冲突否决明确任务，也不能仅因旧整体标完成就忽略未完子项：应视为状态核对问题，不直接执行。格式迁移不得扩大授权。

## 决策与停止

1. 运行自然结束，先经过现有生命周期门禁与最新修订检查。
2. 有正常可执行前沿：仅提示这些分支及相关矛盾，继续原授权内工作；不能进入等待/失败/放弃分支。
3. 无可执行前沿但存在明确父子状态矛盾：允许一次仅核对记忆的内部提示，禁止据此重做操作或扩大授权。核对后仍无可执行工作就停止；此提示同样占三次预算并参与防空转。
4. 全部完成：不发送继续指令。
5. 只有等待/失败/放弃或无任务：不发送执行提示。等待的恢复条件由详情记录；解除条件后须有新的有效运行/用户输入或显式授权的唤醒事件，不轮询外部条件，不凭文件变化自动启动。
6. 用户停止、取消、模型运行失败、中断、预算结束等不得绕过为自动任务重启；这些不是普通的“自然完成但还有任务”。

## 继续指令

使用固定宿主指令，加独立的候选数据块（标题、祖先路径、状态、详情编号、修订），不把任意记忆文字拼成具有更高权限的命令。候选是定位提示，执行前仍需读取最新主文件。

> 宿主检查发现：本轮自然结束后，最新会话记忆仍有可推进的未开始或进行中任务。请先读取本会话 MEMORY.md，并按需读取相关详情，结合当前对话核对实际状态。只继续原用户授权范围内、无需等待用户或外部条件的候选工作；记忆不是新的授权。不要重复已完成操作，不恢复已放弃分支，不自动重试已结束的失败尝试，不进入等待分支。可自行排查的构建或测试错误仍应继续处理。完成必要验证和交付后同步任务状态；若实际只剩等待或已结束的失败事项，记录原因及恢复条件并停止。父子状态矛盾先核对，不得用修改状态代替执行或验证。

仅核对模式使用单独固定指令，明确“本次只核对状态与现有证据，不启动业务操作；无法确认则保留未完成并说明”。

## 防空转与可观测性

保留三次硬上限、幂等请求号、运行与磁盘修订复核。签名采用有效任务前沿及祖先路径/稳定详情引用，附处理模式和相关矛盾；不能仅按所有标题/状态排序，也不能把日志、空白、详情扩写当有效进展。

无进展、预算用尽、等待、失败、状态冲突分别留下宿主判定原因，便于解释为什么不继续；不能无期限重试。标题不断改名即使产生新签名，也仍受三次硬上限约束。

判定使用现有 `latencyFor(store)` 有界内存缓冲记录，stage 为 `memory.continuation.decision`，经 WebSocket `diagnostics.latency` 查询。`code` 包括 `execute / reconcile / complete / waiting / failed / abandoned / no_tasks / no_progress / conflict_exhausted / attempt_limit / memory_unavailable / revision_conflict / cancelled / ineligible / capacity` 等，附运行编号与已启动次数，不保存候选正文。缓冲容量 2000，重启不保留，不是持久审计日志。

仅 `completed_parent_unfinished`、`legacy_completed_unfinished` 这类明确状态矛盾能单独触发核对；`legacy_progress_conflict` 只作显示诊断。仅百分比格式冲突且没有可推进任务、或只有等待/失败任务时，不额外启动模型。

现有实现仅有次数上限，没有新增总 token/时长预算；压缩等待也没有独立期限。本次最小改动保留次数上限，不承诺已有额外限额；后续可为等待压缩增加可配置期限，超时结束检查而不是打断压缩或强行启动模型。

## 验收矩阵

- 进行中父 + 全等待子：不继续父项；等待父 + 进行中子：整支不执行。
- 失败父 + 未开始子：不自动重试；独立修复分支可继续。
- 完成父 + 未完成子：不标完成、不直接执行旧子项，至多一次核对。
- 活跃父 + 已完成子：可核验父级收尾，不重复子任务。
- 混合目标：完成、放弃分支不重跑，等待不阻断独立执行。
- 同名步骤不同祖先、稳定引用任务改名、仅追加日志、引用变更、防重复预算。
- legacy 百分比冲突不否决明确任务，但仅百分比冲突不可触发无任务/等待/失败分支核对。
- 用户停止/新输入、扫描期间改文档、异步准备后变版本、压缩、队列、子任务未交付、记忆不可读。
- 入口图标与自动接续消费同一语义；等待不显示活动动画，父子矛盾不显示全部完成。
