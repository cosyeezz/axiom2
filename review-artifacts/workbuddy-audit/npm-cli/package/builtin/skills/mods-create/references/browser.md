## Browser Extensions

### Native Style, Theme And Language

For ordinary controls and panels, inherit the native font and use semantic variables such as `--color-bg-card`, `--color-bg-input`, `--color-text-primary`, `--color-text-secondary`, `--color-border-default`, `--color-focus-ring` and `--skin-radius`. Inspect the live tokens/slot first when their exact names or dimensions matter. CSS variables update with the current user skin and light/dark mode; do not capture computed colors once, write a second root palette, or call `theme.setMode`, `theme.select` or `theme.overrideTokens` during ordinary setup. Use `theme.subscribe/getSnapshot` only when a non-CSS asset or chart needs the resolved scheme. Those subscriptions belong to the Mod lifecycle.

Register a plugin-local translation dictionary once during apply. Namespaces are isolated by Mod identity, so another installed Mod may use the same namespace without a conflict or shared translations. Candidate updates of the same Mod shadow and roll back their own dictionary. Components call `locale.useT` so language changes update mounted UI without recreating it; labels read outside components use `locale.t` at the time of use. Include zh/en text for empty/loading/error states and aria-label/title, not just the main button. User content is not translated. Source-free client bodies can use this pattern:

```js
return {slotContract:'strict',inject:['slots','locale'],apply(ctx){
    const ns='my-notes';
    ctx.locale.register(ns,{zh:{notes:'便签'},en:{notes:'Notes'}});
    styles.insert('.my-notes{font:inherit;color:var(--color-text-primary)}.my-notes textarea{font:inherit;width:100%;padding:8px;background:var(--color-bg-input);color:inherit;border:1px solid var(--color-border-default);border-radius:var(--skin-radius,6px)}.my-notes textarea:focus-visible{outline:2px solid var(--color-focus-ring)}');
    ctx.slots.register({name:'chat.view',id:'notes',label:()=>ctx.locale.t(ns,'notes')},function Notes(){
        const t=ctx.locale.useT(ns),[text,setText]=React.useState('');
        return React.createElement('section',{className:'my-notes'},React.createElement('textarea',{
            'aria-label':t('notes'),value:text,onChange:e=>setText(e.target.value)
        }));
    });
}};
```

Verify light/dark and zh/en changes on the same mounted controls with a non-empty draft. Verify the current skin, narrow placement, hover/focus/disabled/error states and native fallback after stop. A static translation table or successful syntax check alone does not establish synchronization. Scope specific artwork/style changes to the Mod; use the appearance reference only when the user asks for whole-application restyling.

For standard installed packages, declare `client.activationEvents` in the manifest when startup loading is unnecessary. Omitted means startup; `[]` means the user must Open the Mod or another active package must require it. Supported events are `startup`, `onView:<native mainView>`, `onFile:<lowercase extension without dot>` and `onTheme:<local theme id>`, at most 32 unique entries. A triggered package stays active until stop/update/page disposal, not just while a view is visible. `onTheme` restores a remembered exact Mod skin choice; an unregistered theme has no declaration-only preview and must first be opened from the Mod inventory. Do not invent onCommand/onService or claim dormant means loaded. Host-only hooks and package source approval are unchanged. Inspect exact dormant/waiting/failed diagnostics, activate required browser dependencies first and explicitly retry a failed version instead of reloading every Mod.

Advertise a lazy workbench entrance through `client.contributes:{dockTabs:[{id:'sheet',label:{zh:'表格',en:'Sheet'}}]}` in the same manifest. Up to 16 unique bounded local ids are accepted. The approved entrance appears in the native Dock plus menu before any client code executes; clicking it loads this Mod, then opens only its exact live `app.dock.tabs.item` panel. Register that panel with `id:'sheet'` during apply. Labels follow native language. Do not register a placeholder component or call dock.open during setup merely to advertise the entrance. Missing registrations or dependencies report a failure; closing the launcher cancels the open wait without unloading a package that already activated. Unregistered skin previews are not supplied.

Advertise lazy commands with `client.contributes:{commands:[{id:'openSheet',label:{zh:'打开表格',en:'Open Sheet'}}]}` and register the real handler through `ctx.commands.register({id:'openSheet',label:{zh:'打开表格',en:'Open Sheet'}},({signal})=>{ctx.dock.open('sheet');})`. Declare `commands` and `dock` in inject for that example. Up to 32 commands are namespaced by Mod identity. The native command palette activates only the selected package before invoking its exact registered handler. `commands.execute(id,{signal?})` calls only this version's own command; it cannot invoke native or foreign commands. Stop/update and the 30-second wait limit request cooperative cancellation; check signal during async work. Uncooperative work remains busy until it actually ends (64 total outstanding handlers), and failures are never automatically replayed. Commands do not override slash commands or install default shortcuts.

Declared or loaded commands appear in the native keyboard-shortcut editor without downloading dormant code. Users may explicitly bind, rebind, unbind or restore their `mod-command:<encoded-Mod-id>:<encoded-command-id>` action in the existing WebGlobal configuration. Restore means unbound because Mods have no default keys. User mappings persist through reload and Mod stop; handlers retract on stop/disconnect and reattach only for current approved entrances. The single native dispatcher still yields in text editors/composers, Monaco, terminals, IME and modals. Do not install a window keydown listener or write user shortcut preferences from apply. These are page shortcuts, not OS-global keys.

Inspect commands before diagnosing missing registrations: `Mods inspectQuery {platform:'client',provider:'Command',method:'listCommands',input:{plugin:'<exact-mod-id>',limit:20}}`. Optional command/query filters and a snapshot-bound cursor keep responses at most 50 entries and 48 KiB; long labels may shorten the page. Metadata includes exact owner hash/generation, zh/en labels, declared/registered/busy and runtime status; no code is downloaded or invoked by this read. `retained` marks a previous registered version kept after an unsuccessful update; `retired` marks withdrawn work still busy. A stale cursor requires restarting the read, not rerunning the business action.

For a standalone on-demand panel, start with `cbc plugin init <new-directory> --template workbench --name <npm-name>`. It declares an unloaded Notes entrance, registers the matching real panel on demand, follows native language and semantic CSS variables, and retains Mod-local notes through `slots.defineStore`. Keep its explicit Capture/Fill actions, or replace them with the panel's actual domain workflow; do not add startup activation solely to expose the menu entry.

For whole-client visual skins, use the trusted client CSS and real UI slots together. `contract {section:'browser',name:'styleSurfaces'}` and Client `Theme.listTokens` list stable `[data-mod-surface]` selectors and mounted status for app/navigation/sidebar/brand/chat/composer/messages/settings. `data-mod-page` and `data-mod-chat-state` are native-owned presentation flags. Insert owned styles for artwork frames, typography, animations and pseudo-elements; use actual image assets. Keep layout overlays within their Chat/sidebar region and non-interactive artwork pointer-transparent. Register controls in slots and read runtime/input/layout through services rather than polling DOM text. Stop must withdraw CSS, nodes and listeners. Data-only skin JSON supplies palette/background/tokens, not DOM behavior or arbitrary CSS.

Installed asset reads use mandatory HTTP revalidation: exact downloaded bytes are reused only after the authenticated host confirms current version approval and active identity. A valid conditional response is 304; revoked/inactive/changed selected versions reject even when cached. Pure-browser packages with verified materialized identity and complete snapshot approval use immutable index/code/assets; editing an installation cache does not select new bytes. Import/update and approve the intended version. Native/legacy/developer packages keep full-source checks. Use assets.read/url and owned cancellation, not CacheStorage or offline fallback. Cached bytes are not grants; do not claim native startup or every existing Mod has snapshot-owned loading.

Pass owned signals to asset reads. HTTP disconnect cancels the corresponding host scan between operations/chunks and closes its handles; it does not cancel peer Mod work or shared compilation. Already queued cancelled reads remain within the same outstanding budget until their queue entries exit, then skip filesystem work. Never treat cancellation as a partial successful asset read.

Activation is global to the CBC installation, while session-scope contributions are independent for every selected agent conversation, including worker agents. Register slots/styles/providers once in `apply`, not again on each Chat change. Use a session-scoped declared store for each conversation's data, global state only when sharing is intentional. Slot components receive `runtime`, `useRuntime(selector)`, `agentScope`, scoped `chat` and scoped `host`; retain these scoped props rather than global closure callbacks for a per-agent operation. Switching agents retires the old UI callbacks without deleting its declared store, and returning creates a fresh binding to the same session data. Module-local closures remain shared, not per-agent storage.

`ctx.runtime.getSnapshot/useRuntime/subscribe` reads native sessionId, agentId, jobId, attachment/readOnly, connection/binding, running, pendingApproval, phase/progress/stopReason and bounded Job state. `runtime.onSession(scope=>cleanup?)` owns effects for the current agent: register timers/listeners through `scope.effect`, pass `scope.signal` to cancellable requests and call `scope.check()` before publishing late results. Switching, disconnecting or stopping retires that scope; setup is synchronous. This is selection lifecycle, not cancellation of already committed Jobs. Read selected jobs through `sessions.detail` and attached child agents through `subagents`; the runtime projection is not the complete host engine or a second task cache. Never substitute the main agent when a worker is unavailable. A worker business call adopts only the same approved source hash with its own live runtimeId/generation. Different or inactive code returns a concrete error, not automatic trust or fallback execution.

For changing the actual Web UI beyond render-tree panels, a resident definition can include `client`: a plain JavaScript function body returning `{inject:[service names],provides?:[owned service names],apply(ctx){...}}`. Builtin services include slots/chat/input/theme/timer/sessions/inspect; plugins can provide more. Every direct `ctx.<service>` access must name an actual service in `inject`. `styles` is a supplied closure, not a built-in service: use `return {inject:[],apply(ctx){styles.insert('.my-mod{color:inherit}');}};`, not `ctx.styles` or `inject:['styles']`. The supplied `host` and `React` bindings likewise do not require injection. Plain `setTimeout`, `setInterval`, `requestAnimationFrame` and their clear/cancel functions are supplied closure symbols too: games and animations may use them, and the Mod owns every pending handle so stop, update or a page change cancels it (1024 pending at most; callbacks must be functions). Use `ctx.timer` when a delay must be abortable or a call must be debounced/throttled. `fetch` and `require` stay unavailable; use `host.call` for network or filesystem work. `apply` must be synchronous; start asynchronous work in event callbacks or React effects and report failures. Read `Mods contract` and live Service inspection for exact APIs. The complete installed source hash covers host files and client code; trusted browser code runs in the real page, not a sandbox against hostile code.

For cross-Mod services, publish `ctx.provide('records',value,{apiVersion:1,description:'...',signatures:[...]})` and consume with `inject:['records']` plus `serviceVersions:{records:1}` in the returned definition or exported module. Revisions are exact integers from 1 to 1000000, not package semver. A mismatch or unversioned provider keeps apply waiting and withdraws consumer slots, timers and outputs; compatible replacement or rollback restores them. Read Runtime.snapshot for expected/actual/owner and `MOD_SERVICE_API_INCOMPATIBLE`, and Service.listService for the live revision. Do not disable a foreign Mod or force a native service version to resolve incompatibility. Omitting requirements keeps legacy name-only behavior. Optional ctx.get does not negotiate a revision, and install-time ranges or parallel versions are not implemented.

For persistent client state, keep a stable `persist` key and opt into `persistence:{version,validate,migrate}` on `slots.defineStore`. From version 0, migrate the old raw JSON without rewriting it; return finite plain JSON synchronously and validate the whole resulting state. Callbacks must be pure. A new branch is committed only by a successful action, so failed preparation leaves old data available. Reopening an existing revision restores its own snapshot; do not promise automatic reverse migration or merge after rollback. Eight snapshots and 1 MiB are the per-identity limits, stale edits reject, and corrupt/invalid state must not be cleared to hide an error. This browser archive is not host modStorage, a cross-tab transaction or an exported ecosystem configuration. The workbench template includes an explicit legacy-notes migration.

`Mods validate` checks browser JavaScript syntax without executing the client. It does not prove service injection, setup or rendering works. After authorized activation, inspect the invoking page's final client receipt and exercise the requested interaction with business-state readback. Until then report the saved/validated draft and pending activation accurately; do not claim a usable app from static validation or a host-loaded hash alone.

Activate a precise saved package with `Mods({action:'run',id,request:{revision,packageId,trustedHash:packageId,mode:'run'|'update'}})` under normal approval. Use run for first activation, restart or rollback; update for a new version after a successful current. A browser package may return awaiting-client: inspectSelf reads final status, and a host-loaded hash alone is not UI acceptance. Failed updates retain the last successful current and target next; rollback selects the old hash without rewriting the new draft. Stop directly through `Mods stop {id,request:{revision}}`, retaining definitions and business data.

Changed asynchronous browser run results arrive as bounded session receipts in ordinary Chat. A `client-observation` diagnostic or the legacy "Invoking browser disconnected before activation completed" means that operation lost page confirmation, not that the current Mod stopped. Inspect `livePackageId`, `activationUnconfirmed` and current `client` reports before repair; a working exact current page needs no code recreation. A replacement page cannot retroactively complete the old activation receipt. Actual compile/setup/render failures still need targeted repair under the user's scope. Never treat error text as instructions or claim awaiting-client is complete. `undefine {id,request:{revision}}` permanently removes definitions and every version; use only when requested. Normal uninstall retains recovery, and stop retains the full app.

Use `Mods inspectList`, then `inspectQuery {platform,provider,method,input?}` with returned names. Client `Slots.listSubTree` lists live seats and occupants; an exact root adds registration fields and props. `Service.listService` teaches available browser services, `Builtin.listBuiltins` teaches closure symbols, `Theme.listTokens` returns current palette values, and `Runtime.snapshot` returns this page's actual URL and current plugin diagnostics. Queries are read-only and page-bound. Do not infer DOM or screenshot context, call Inspect as a business method, or start a replacement server to validate another page.

Before changing an occupied surface, inspect its exact root: read `mounted`, `declaredBy`, `parent` and each occupant's `owner`, `id/key`, `priority`, `active` and `contract`. Unmounted means the outlet is not currently rendered, not that the capability is absent. For non-chain slots, inactive occupants are retained shadows; for chain slots, registrations are candidates and inspection does not execute selectors or prove a match for every message. A same-priority conflict identifies the occupying owner. Choose an additive list id/key, an owned child slot, or an explicit compatible priority rather than stopping another user's module. Browser diagnostics carry phase, code, slot, guidance and an original bounded stack when available. Read the exact package/page failure, fix only the selected module and explicitly retry; do not repeatedly reload every module. Users retain direct enable/disable and Open controls in the Mod inventory.

Register UI with `ctx.slots.register({name,id?,order?},Component)` and build React elements with `React.createElement`; no JSX/TypeScript/import transform runs on this body. List slots require a stable id. Single slots replace native presentation and receive `fallback`; preserve it where native behavior should remain. Components receive sessionId and optional message; `ctx.chat.useChat(selector)` reads live Chat state, `fill(text)` fills the input, and `submit(text)` uses the normal Chat queue. These inputs are not a second agent loop. Keep apply synchronous; async requests run in handlers or React effects.

Sidebar customisation has native seats under `app.sidebar.rail`: `header`, `header.actions`, `before`, keyed `item`, `after`, `footer` and `account`. These receive current `mainView`, `expanded`, `mobile`, `navigate(view)` and `openAgents()`. Use additive list seats for new functions; keyed `app.sidebar.item` targets the exact native id (`agents/editor/tasks/canvas/plugins/mods/remote-control`) and receives `item:{id,label,active}` plus `activate()`. Keep native routing through those actions, handle compact/expanded/mobile forms and preserve account/settings access. Query the exact subtree for mounted state and occupants; conditional native entries exist only while their feature is available.

Brand content has separate `app.brand.mark`, `app.brand.name` and `app.brand.artwork` seats. Mark props contain `surface:'sidebar'`, `size`, `expanded` and `defaultSource`; return only image/icon content, not a nested button, so native click and accessible labels stay intact. Name props contain `defaultName` and `expanded`; use a short wordmark that fits the rail. Artwork props contain the current skin image, compact state and defaultName; its replacement keeps the native welcome path/caption/composer, and welcome:hidden still controls visibility. Whole-rail replacement removes its internal outlets unless fallback is rendered. Use the smallest matching seat rather than replacing the entire navigation for a logo or one action.

Native detail annotations use session-scoped keyed `task.detail` (exact background-terminal id) or `subagent.detail` (exact parent tool-call id). Read browser contract for exact props: task status projects the native terminal owner; subagent props contain identity/status, without transcripts. `surface` is `dock` or expanded `inline`; availability follows the native detail. `task.detail` does not cover scheduled jobs. Keep output, stop, navigation and history accessible, use scoped services for actions and never create a parallel task store. Stopping retracts the annotation while retaining native detail content.

For reusable groups, declare child seats in register options `children:{'my-app.actions':{kind:'list',description:'Actions'}}` and render them with the parent's `renderSlot(name,props)`. Use `slots.inject(name,()=>slots.register(...))` for independently loaded children; declaration unload retracts nested contributions. Preserve compatible child names/kinds during parent updates. `ctx.get(name)` is an optional known-service lookup; `ctx.on(event,callback)` owns subscriptions from client Event inspection. Create a new host-minted plugin through `Mods define {request:{definition}}`, or include the existing id and revision to append a version; neither activates it.

New client bodies return `{slotContract:'strict',inject,apply(ctx)}`. Standard installed modules use strict slots by default; existing bodies without this field retain legacy admission. `single/list/keyed` select one winner per slot/id/key: lower `priority` wins, equal-priority foreign conflicts fail; same-plugin candidate versions preserve rollback. Lists accept `label:'Title'` or a dynamic `()=>ctx.locale.t(...)`; `slots.list(name)` returns winning records. `keyed` registers `key` and renders with `{entryKey}`. Strict `chain` requires a synchronous pure `select(props)` returning `matched` or null; first non-null wins with owner `fallback`, never `next`. For native wrapping explicitly use `ctx.slots.wrap(options,Component)` and `next(props?)`, without select. Do not wrap `chat.composer`; its takeover preserves the original textarea.

Declare `store(sessionId?)` returning `{getSnapshot,subscribe,actions,dispose?}` or share a `ctx.slots.defineStore` handle at matching scope for framework-owned `useStore(selector)`/`actions`. An `inject(sessionId?,actions?)` props factory supplies plain data/callbacks and optional `hooks:{name:{getSnapshot,subscribe}}`; components receive `useName(selector)`. Stable snapshots must retain identity until data changes. Native auxiliary pages use `app.view` keyed by mainView; preserve recovery controls. Store sharing coordinates explicit business state, not another native Chat/task/connection cache.

Session components also receive `useInput(selector)` and `inputActions` for the native composer. Read immutable text/selection/attachment metadata and running/canSend/preparing/readOnly; do not mirror them in another draft store. Use setText/insertText/setSelection/addFiles/removeAttachment/clear/focus/blur/submit/cancel. addFiles takes user-selected browser File objects, returns a promise, and must finish before submission. Snapshot metadata never includes file contents. Submission uses the existing composer admission, attachment upload and busy Chat queue; handle errors explicitly. Retained actions fail when the plugin or native composer lease stops or changes.

`chat.composer` is a takeover seat: register a pure select(owner) returning matched or null. It hides the original composer but keeps the textarea DOM mounted; stopping or crashing restores the original draft. Do not call next() or render another copy of the native fallback from that seat. Use standard inputActions for the draft and sending. Prefer additive chat.input.dock/left/right/after controls unless the user actually wants to replace input presentation.

`ctx.provide(name,value,{description,signatures})` makes a capability available to other plugins. Declare `provides:[name]` for output reservation and cycle detection; required `inject` dependencies wait on actual providers. Provider removal disposes consumer effects; return re-applies them. Keep every registration/style/subscription inside apply/effect. `ctx.registerEvent/emit/on` extends owned events. `ctx.inspect.register({manifest,query(method,input,{signal})})` publishes exact input/output schemas and read-only bounded JSON through ordinary inspectList/inspectQuery. Stop withdraws providers and cancels their pending reads; do not use inspection for mutations.

Use `ctx.sessions.create({prompt,cwd,agent?,model?,effort?,permissionMode?,bgIsolation?})` to dispatch a real independent CBC job. Read limited `list/history` pages then selected `detail/transcript`; `reply/stop/resume` operate jobs without a second agent loop. `open(sessionId,cwd?)` and `createForeground()` use native App handlers. A session change retires old browser callbacks; do not mistake a revoked old callback for an undone navigation. Removing the UI plugin does not cancel committed jobs. Do not infer OS windows/global shortcuts/screen capture from browser overlays.

`styles.insert(css)`, `ctx.theme.overrideTokens({light,dark,tokens?:{light,dark}})`, and declared timer services register resources owned by this client version. Custom override names must match across both modes; a second call replaces the version's whole layer. Stop/update/page disposal removes them; failed setup rolls them back. A React render crash retires the bad entry and falls back to native UI. Report and inspect actual failures rather than claiming that successful loading proves rendering. Use the native Interface Extensions control to stop a broken UI directly.

Browser `host.call(noun,method,args?)` routes JSON arrays to only this Mod's custom `engine.create` methods through the existing CBC runtime. Network/filesystem/model work belongs in the trusted host half. Browser code has no OS-global keyboard hook, native desktop window or whole-screen capture service; do not silently substitute a browser shortcut/overlay for a desktop feature or couple to another product's Electron implementation.
