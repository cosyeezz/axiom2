## Thinking

- translator/index.js:78-94、130-144 捕获源请求意图，再经 thinkingUnified.js:434 规范化；provider 指定 openai 形状优先于模型的原生 vendor 格式（thinkingUnified.js:130-148）。
- codebuddy-cn.js:49-63 与 intl:20-25：有非 none/off effort 才加 reasoning_summary="auto"；none/off 删除 reasoning_effort。普通请求不主动添加这两个字段。未主动清理客户端原有 reasoning_summary。
- canDisable=false 时统一层把关闭意图改为 minimal（thinkingUnified.js:262-272）；可关闭模型得到 none 后，executor 又将 none 删除。故“关闭”只是省略参数，不能证明上游真的关闭，尤其模型默认为思考时。
- thinkingLevels.js:69-92 声明 CN pro=low/high/xhigh，v4.1-flash与GLM5.3=low/high/max，GLM5.2=high/xhigh，Kimi2.8=low/medium/high，hy3=low/high，hy4=high。normalizeOpenAILevel:172 只归一化 max/ultra，不全面校验其余等级；auto 会原样发送。服务端接受程度未知。
- 国际版 deepseek-v4.1-flash 会先命中通用 dotted-version 模式（thinkingLevels.js:77），后面的 intl 覆盖:92 不生效；声明“同等级”不等于实际解析结果。
- response/openai-to-claude.js:138-156 将 reasoning_content/reasoning/reasoning_details 转 Claude thinking_delta；工具回合历史 Kimi/DeepSeek 缺 reasoning_content 时会注入单空格占位（utils/reasoningContentInjector.js:12、70），并非重建原始思考。Claude thinking/signature 块在 OpenAI 转换中被删（translator/formats/openai.js:8、38）。

## 图片和工具

- chatCore.js:183-193 在转换前按能力移除不支持的图片，替换占位文本（translator/concerns/modality.js:48-57）。CN 当前 11 型号均宣告 vision，因此常规图片不会因该门禁被剔除；Intl 部分型号会。
- Claude→OpenAI：request/claude-to-openai.js:177-185 仅识别 base64 图片并转 data URI。Claude source.type=url 无转换分支；prefetch.js:8-12、80 又对 OpenAI 目标不预取，因此这类 URL 图片会丢失。OpenAI 原生 image_url 可保留，但上游是否支持远程 URL 未实测。
- 工具结果中的 base64 图片被移到随后 user 消息（claude-to-openai.js:199-240）；工具 role 留文本。未发现 CodeBuddy 专用大小、数量、MIME 约束，不能推断无限制。
- 工具定义 input_schema→function.parameters；tool_use→assistant.tool_calls(JSON.stringify input)；tool_result→role:tool + tool_call_id（claude-to-openai.js:67-80、188-224）。tool_choice any→required，指定 tool→function；未知对象落到 auto（:273-281）。丢失 tool_result.is_error 专门标志，缺少结果可补 “[No response received]”（:97-126）。
- 回包 openai-to-claude.js:183-244 组装 tool_use，参数先缓冲、finish 时发 input_json_delta；另有 Read 参数清洗（:14-47）。9router 是转换代理，这些路径并不执行客户端工具；tools=true 不能证明模型选择、参数准确性或多轮工具成功率。
